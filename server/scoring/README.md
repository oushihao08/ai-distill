# 独立评分

## 项目规则兼容改造（实施中）

评分队列已冻结前后钩子并接入同步执行，钩子输入由实际评分文件白名单组成，遵守同样的思路／标答边界。主操作检查点不改变评分原文；钩子返回的 notes/data 不覆盖成绩。后置异步动作同事务登记；执行记录需 033 迁移。API 模式带钩子的主任务交由 local/all worker，续跑入口沿用原失败尝试，不创建新的评分主调用。

新增 `extractModelReport()` 收集唯一 `<model_report>` JSON 结果区，只检查结构、逐条 ID 及模型报告的 0—100 比较指标范围；允许负原始分和独立否决，不重算或改写模型成绩。默认 `extractTextScore()` 的旧行为不变。新题派发冻结评分规则，评分上下文、Codex/API 调用和评分队列已接通新契约；按冻结的 none/calibration 政策决定是否提供标答，始终排除作答思路。新模式报告将 raw_score、full_score、evaluation_percent 和 veto_triggered 分开保存；无比较指标时达标等待。下文未特别标明的正分和排除标答说明描述默认 legacy 模式。页面和钩子接入已完成，Work独立验收题已实际使用新契约完成评分；验收结束后Work评分步骤已正式启用同版规则，钩子保持为空；旧项目默认不变。实施进度见 Work 项目《系统兼容改造计划》。

逐个成功答案建立匿名独立评分任务。默认使用隔离 Codex Agent，也可在评分步骤选择独立大模型 API。两种方式都接收同版题面、rubric、实际发送给作答模型的数据库脱敏附件、匿名完整答案及评分步骤提示词；不提供作答思路或标准答案，不读取项目 skill、出题和难度设计资料，不接收目标分数或作答模型身份。作答思路和标准答案仍在内部上下文中校验题目包完整性与版本绑定，但不会进入评分模型输入。

评分步骤提示词原样执行，仅未设置时使用默认正文；与旧内置默认正文完全相同的设置映射到新版默认正文，自定义提示词原样保留。新版默认要求每个 rubric 考点给出分数、判断理由和答案原文证据，并说明未找到证据的情况；不追加评分开发者指令。直接发送完整正文，不添加固定任务指令或输出 schema。记忆和外部资料访问由 CLI 隔离参数控制。

评分方式、模型与执行参数在任务创建时冻结。Codex 模式保留当前Agent隔离参数；API模式复用 `server/llm-api/` 客户端并进入独立API并发池，不占用Codex Agent名额。API评分配置只保存供应商、端点、模型、思考／输出参数，不保存密钥；调用时读取服务端凭证。两种模式复用同一总分提取、rubric ID、分项分值、合计和版本绑定校验。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `context.ts` | 从持久化成功任务读取题目包、附件和完整答案，核对版本与指纹；仅旧任务绑定校验兼容项目文件及旧规则快照。 |
| `executor.ts` | 组装题面、rubric、附件、匿名答案及原样提示词，发送到新会话并保留文本回复。 |
| `jobs.ts` | 逐答案冻结输入及步骤配置、去重、执行、复核绑定并汇总。 |
| `validate.ts` | 新回复仅在返回后提取总分；保留旧结构化报告校验兼容。 |

## 数据流与维护边界

context.ts 读取并校验同版题目包和答案 → jobs.ts 冻结评分提示词及模型配置 → executor.ts 将题面、rubric、附件、匿名答案和提示词交给 Agent → validate.ts 在回复后提取总分 → 汇总当前模型集合。作答思路和标准答案仅用于内部题目包完整性及绑定校验，不发送给 Agent。

模型集合全部终结且至少有一个成功答案时，可对成功答案评分；没有成功答案或仍有答案运行时不得评分。本轮评分全部终结后自动执行达标判定；无待领取任务的中断恢复分支也会先提交并释放评分连接，再执行同一达标判定，避免判定期间占用连接池。

旧任务的项目文件元数据继续参与原摘要及绑定校验，但不发送给评分 Agent。新任务不以本地 skill 是否存在或变化作为评分输入条件。项目身份只用于队列绑定，不发送给评分 Agent。项目名称、题目身份、题面、附件、rubric、完整答案和步骤提示词仍参与输入摘要，结果提交前复核；旧报告不改写。

评分要求由本次冻结的步骤提示词决定。执行器在步骤提示词后追加本题实际 rubric ID 清单，要求评分原样复用每个 ID，避免静态示例与数字型或其他自定义 ID 冲突。程序保留每个模型的完整回复，不改写逐项理由；对纯文本评分校验所有 rubric ID 恰好出现一次、无外来 ID、逐项分值／满分与 rubric 相符，且分项合计等于最终总分。满分为1分的条目仍限定为0或1分。校验问题随评分详情显示，且无效评分不参与达标判断；旧结构化任务继续保留原校验结果。

默认评分指令不预设得分高低，以 rubric 的既定条件和满分判分；附件用于核对题目事实及 rubric 依据，是否得分只看待评答案原文，不能用附件中存在但答案未写出的事实代替答案证据。评分模型不接收思路或标答。新派发及设置界面将精确匹配的已知旧内置默认映射为当前默认，自定义正文与历史冻结任务保持原样，不改写已有评分。

本次输入格式升级会使升级前已排队但未执行的评分任务因冻结指纹不匹配而失败，需重新派发；已完成的历史评分及报告不改写。

本模块既有 `*.test.ts` 不代表本次执行验证；运行边界遵循 [项目规则](../../AGENTS.md)。

评分调用显式关闭记忆、宿主 skill 发现、项目指令发现、插件、应用、hooks、MCP、网页搜索和相关外部工具入口；不以 `--ephemeral` 代替记忆隔离。新任务冻结任务指令、隔离参数与空开发者指令标记，去重同时比较这些字段；执行前发生变化则要求重新派发。CLI 在模型不可读的私有输出目录保存 `request.json`（实际 argv、stdin、developer_instructions、schema，不含环境和凭证），成功返回后的评分结果携带 `execution_request`，由界面展示本次实际发送指令。旧记录没有快照时明确显示缺失，不用当前源码回填。


### 旧版独立评分直接文本调用（历史格式）

独立评分在新隔离会话中发送题面、rubric、脱敏附件、匿名完整答案和原样评分提示词；作答思路及标准答案仅保留在内部同版题目包校验上下文，不发送给评分模型，不写入供模型读取的 input.json，不追加评分开发者指令，不要求 JSON 输出。Codex 文本模式省略输出 schema，保存 result.txt；其他结构化任务保持原协议。禁用记忆、项目规则及外部工具读取。

评分原文与实际发送正文保存在执行记录中，界面可查看。程序在返回后提取明确总分用于展示及达标判断；不修改模型评分。无法明确提取时，执行仍记为成功，单独标记提取失败且暂不参与达标判断。旧结构化报告继续按旧协议读取；旧记录不会用当前指令补造快照。

旧独立评分正文按固定顺序分区：评分提示词 → 完整题目包（题面、rubric、作答思路、标准答案）→ 题目附件 → 待评分的模型答案。该旧格式不代表当前模型输入。当前分文件评分提供评分提示词、题面与 rubric、题目附件和待评答案，不提供作答思路或标准答案；每份附件保留正文与页码。输入格式标识参与执行指令绑定，避免复用旧格式评分。


### 当前 Codex Agent 评分：分文件阅读

评分消息仅列出文件用途、完整阅读要求和用户原样提示词。题面与 rubric、各份附件、待评答案分别通过 `input_files` 传入 Codex 客户端；作答思路与标准答案仅留在内部版本绑定上下文，不写入评分文件；客户端仅在系统临时目录 `ai-distill-codex-*/workspace/` 写入文件，执行后清理整个临时目录，成功、失败及取消均尝试清理，清理异常记录日志。持久化记录保留原有冻结上下文、发送消息、文件名/大小/SHA256、读取事件及评分原文，不保留临时输入文件副本。

评分允许文件读取所需的 shell 工具，文件系统仍限制为独立工作区及执行所需最小运行环境，网络、记忆、项目规则、skill 和其他外部入口继续关闭。每次派发创建新评分任务，不复用已完成结果；同一答案已有等待或运行任务时拒绝重复派发。纯文本总分只从明确标注的最终总分行提取；界面显示“总分提取成功”，不把提取成功表述为逐项评分内容已被程序核验。达标前还要匹配答案、题面、rubric 和附件指纹。

纯文本评分解析会去除行首 Markdown 标题标记和加粗标记，再核对实际 rubric ID；不会把 `### R01` 的展示前缀当作编号。未知编号、重复条目、分项与总分不一致仍判为无效，不改写模型原始报告。

评分状态汇总只读取当前成功答案各自最新评分的必要字段；完整上下文与逐项评分报告仍保存在原尝试及产物中，达标接续规则不变。

### API 评分

API请求将与Agent相同的评分消息和每个输入文件的完整正文放入单次文字请求，不使用摘要或截断；API不读取本机文件、记忆或项目资料。实际模型、返回模型、请求ID、输入指纹、用量及耗时随评分报告保存。API评分任务由独立API队列领取，与作答和脱敏共享API并发并轮转调度；Agent worker只领取Codex评分。评分方式和API模型配置冻结在每个评分attempt中，配置更改不覆盖已排队任务。当前API候选模型与Codex模型不能视为同一模型；分数差异同时包含模型和执行方式差异。
