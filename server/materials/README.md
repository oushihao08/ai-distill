# 材料提取与脱敏

支持本地 DOCX／TXT／MD、PDF provider、原文与页索引落库、指纹缓存，以及可选择 API 或本地 Agent 的独立脱敏。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `config.ts` | 提取配置读取：从 config/extraction.json 合并并校验文本识别、实体检查和脱敏兼容参数。 |
| `document.ts` | 统一文档提取：本地解析 DOCX/TXT/MD；PDF 必须注入 MinerU provider，不再回退到智谱。 |
| `state.ts` | 附件或脱敏配置变更的事务失效处理：取消活动任务、重置依赖步骤并使项目导出失效。 |
| `jobs.ts` | PDF 提取队列：冻结解析器配置、复用健康缓存并把当前附件的原文与页索引发布入库。 |
| `pdf.ts` | 页级 PDF 工具：封装 Poppler 命令、文字与 OCR 提取、页级并发及指纹缓存。 |
| `process.ts` | PDF 材料处理与产物落盘：校验来源和缓存指纹，生成私有逐页文本并保留识别问题。 |
| `redact.ts` | 规则脱敏辅助：合并实体及敏感格式匹配，统一替换文本并检查敏感模式残留。 |
| `redaction-jobs.ts` | 独立脱敏队列：冻结入库文本和模型配置，执行脱敏与检查并保存当前附件的脱敏文本。 |
| `redaction-config.ts` | 脱敏执行方式、默认 API 配置与显式 Codex 配置的合并及校验。 |
| `redaction.ts` | 逐字段脱敏执行器：按冻结配置选择 llm-api 或受限 Agent；所有输入统一转成结构化字段，模型返回敏感值、遮盖子串和类别，程序定位并生成遮罩。 |
| `redacted-docx.ts` | 使用 `docx` TypeScript 库将数据库脱敏结构转为 DOCX，保留标题、段落、列表、表格、脚注与分页；历史 Markdown 使用兼容渲染。只读取脱敏产物，不解析原件或嵌入图片。 |
| `redacted-docx-export.ts` | 全流程完成后手动生成附件归档：校验当前附件指纹并复制原件到 `assets/out/附件库/<项目>/<期数>/<题目>/原件/`，从脱敏结构生成同题 DOCX；按脱敏尝试、结构、渲染版本和文件摘要安全复用／下载。 |
| `vision.ts` | 智谱视觉客户端：调用页级识别及实体提取，保留 usage 并处理超时、取消和服务错误。 |

## 数据流与依赖

document.ts 分流文档；jobs.ts 冻结 PDF provider 配置并领取 → process.ts 校验来源／缓存并将逐页原文保存为数据库附件产物；redaction-jobs.ts 从数据库读取原始提取文本 → redaction.ts 独立脱敏，并将脱敏正文写回数据库附件产物。pdf.ts、vision.ts、redact.ts 提供页级工具与辅助。

## 维护边界

当前 PDF 工作流默认直连 MinerU v4 API：通过上传地址提交本地文件、轮询任务并解析 `content_list.json`；仅 API 网络、服务端5xx或超时失败时回退一次至本机 `mineru-open-api` CLI。设置 `PDF_EXTRACTION_PROVIDER=mineru-cli` 可显式使用 CLI。两种方式均要求 `MINERU_KEY`，不会回退到智谱。历史 GLM 结果和旧页级 vision 调查代码仍保留，但不作为当前 PDF 工作流解析路径。提取成功不是全文准确或已脱敏；保留 issues 与页来源。脱敏字段输出错误使用安全原因码记录，日志不带文本正文。配置冻结，附件变更或取消后旧结果不得发布。子模块见 [PDF provider](pdf-extraction/README.md)。

API 脱敏按附件及原页序拆成有界批次；模型只返回扁平 `fields`，程序根据本次唯一字段编号还原附件、页码和结构，不要求模型回传这些元数据。整卷附件顺序按题目来源目录清单排列，保持脱敏正文中的附件编号与成稿附件名称一致。结构或字段校验失败时只重试该批一次；可重试的网络错误也只对当前批次重试一次，不重跑已完成批次。其他供应商、额度和超时错误不自动重试。所有请求字段都有结果且敏感值可在对应原字段定位后才发布整份脱敏结果，重试后仍失败则整次失败，不把部分结果标记为成功。日志只保留安全原因码、调用 ID 和批次序号，不记录原文或供应商原始错误。脱敏不重新转写页面；空白原页由程序保留。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

当前附件按 `deleted_at IS NULL` 查询。已移除附件与原件、提取文本和执行历史继续保留。附件接收、目录同步在工作流行锁内调用 `state.ts`，不再创建或递增材料版本。页面并发增删通过接收前的附件 ID 集合核对，避免覆盖另一请求新增的附件。

可选附件归档经单独 API 手动触发，不注册步骤、不创建 `step_attempts`、不进 worker；只新增／更新 `redacted_docx` artifact，并在 `assets/out/附件库/<主项目>/<期数>/<题目>/` 保存当前原件副本与 `成果/<附件名>-脱敏-<材料ID前缀>.docx`（旧合并格式为 `成果/脱敏材料.docx`）。缺少期数的历史记录仍使用原来的 `<项目>/<题目>/` 层级；下载和重置同时接受两种路径。项目页点击“下载全部达标题目 Excel”时会逐题调用此入口，先补齐或复用当前脱敏 DOCX，再生成带附件地址的工作簿；新期次目录名取主项目名、期数和题目来源标识。每个原件写入前校验数据库 SHA-256 与大小；新格式 DOCX 从当前脱敏结构生成，历史文本产物走兼容渲染，不从原 PDF/OCR 再提取。内部附件序号、页码及结束标记不写入 DOCX，原页边界转成分页。输入必须是当前成功脱敏且绑定全部当前附件的结果，导出还要求可见流程成功且 ordinal 8 已归档。材料或脱敏变化后，下载按当前脱敏尝试和 DOCX SHA-256 拒绝旧文件；整条工作流重置会一起隔离清理此题附件库目录。导出错误不更改工作流步骤或尝试状态。PDF 原件作为单个原始附件复制，不生成页图；最终 DOCX 只含脱敏文字与文档样式，不包含图片。

工作流附件全文接口支持 `redacted_only=true`：只返回当前已脱敏正文及页索引，不返回原始提取页；供达标题目详情弹窗阅读附件时使用。普通附件全文接口保留原有原文／脱敏双视图行为。

脱敏默认为独立大模型 API，默认复用统一 API 的 OpenRouter GLM-5.3-Flash，可用 `LLM_API_*` 覆盖，步骤只选择统一目录中的模型；已有显式 Codex 配置保留。API 直接接收已入库原文，Agent 使用隔离文件目录。两者共用输出校验、产物格式、附件指纹和取消检查。模型/执行方式/提示词变更或恢复默认使脱敏及后续结果失效；API 脱敏与作答共享 `LLM_API_CONCURRENCY` 路 API worker（默认 8），不占用本地 Codex 通道。JSON 结构检查不证明敏感信息已全部处理或事实未改写。

诊断日志：提取队列按 workflow/attempt 关联附件提取的开始、返回和失败；脱敏校验失败记录安全原因码、调用 ID、附件 ID、页码及预期/实际数量，正文允许为空字符串，空白页不单独判失败。普通日志不记录正文。

MinerU 的正文转换、缓存标识及私有诊断目录见 [PDF provider 说明](pdf-extraction/README.md#mineru-转换与诊断)。重新提取入队会使该题下游结果失效；历史原文不会自动补齐，需显式重新派发。

新脱敏合并正文由程序插入附件序号、结束标识和原附件页序，保留不同来源之间的边界，不依赖模型生成分隔符。内部索引继续保留附件 ID 与逐材料正文。任务配置记录 text_layout，旧布局成功任务不会作为新布局任务复用；历史产物不自动重写，重新脱敏后下游获得新正文。

结构化提取把标题、段落、列表、表格单元格、图注、脚注及可识别的图片文字映射为带页序的块；无结构文本也转成段落块。模型只返回扁平字段编号与敏感值；类别、遮盖子串可选，不返回附件页元数据、替换文本或整字段正文；程序按字段映射确定性生成脱敏结构，非敏感文字沿用原文。API 将同一附件相邻页的未完成字段合并，每批最多 32 个字段、以 10,000 字符为打包目标；超长单字段独立提交。可重试的格式或字段错误最多重试当前批一次，仍失败时仅将超过 8 字段的批次逐级对半拆分。通过校验的字段映射保存在权限受限的本地断点文件中，绑定材料、提示词、模型配置和脱敏协议；同输入重派只提交未完成字段，全部成功入库后删除断点。结构化 DOCX 复用还核对结构摘要、渲染器版本和 DOCX 实际摘要。

手动 DOCX 导出按当前附件逐份生成：每份原附件对应一份脱敏 DOCX，正文来自同次脱敏索引的 material_id 对应内容；校验索引指纹、附件集合和当前输入绑定，缺少正文时整体失败。每份 DOCX artifact 保存 material_id，重试逐文件复用并清除旧合并文件的索引；历史合并文件可能仍在磁盘，但不再进入新 Excel 引用。页面提供逐文件下载。

附件库相对路径由下载与工作流重置共用校验，逐附件 DOCX 与旧合并文件均可安全重置；路径层级、目录归属及符号链接限制保留。

当前任务协议统一为 `attachment-field-redaction-v14`；无结构文本也适配为段落字段，不保留旧整页脱敏入口。只校验 JSON 可解析、请求字段覆盖完整；多余或无法对应的返回项忽略、敏感值可定位；附件 ID、页码、页数、顺序、结构、类别和遮盖子串不由模型回传或强制校验。敏感值匹配容忍标点、空白及 Unicode 兼容形式差异；可选遮盖子串重复且互不重叠时逐处遮盖；无法定位或位置重叠时回退遮盖整个敏感值，不会仅因它拼写不同、重复或缺失而失败；重复字段合并，重叠遮盖范围取并集；真实敏感值无法定位时仍拒绝发布。姓名和电话的遮盖由程序按类别生成，其他类别使用模型给出的可选遮盖范围或遮盖整个敏感值。MinerU 缓存保留识别 issues，不因警告重新上传；来源、摘要、页序及结构投影仍须通过验证。当前 MinerU 入队与执行不再读取旧 GLM 提取配置。

模型输出仅使用 `{fields:[{target_id,redactions:[{source_text,kind?,mask_text?}]}]}`。允许 JSON 代码围栏、字段乱序和重复字段；附件 ID、页码、页数、顺序及结构由程序恢复。v14 不复用 v13 断点，不自动重派历史失败任务。
