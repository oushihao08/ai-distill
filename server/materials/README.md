# 材料提取与脱敏

支持本地 TXT／MD、PDF provider 与 MinerU DOCX 结构化提取、原文与页索引落库、指纹缓存，以及可选择 API 或本地 Agent 的独立脱敏。

远程材料任务仍使用本目录原有 PDF/DOCX 提取和 API 脱敏处理器；领取查询按 `step_attempts.execution_target` 区分本机和服务器，派生的 PDF/DOCX 提取继承入库 attempt 的归属。原始提取文本和脱敏正文继续进入数据库，管理文件保留在执行机器的 `.storage`；本机 CLI 仅按授权操作清单与 SHA-256 下载需要的原件和脱敏文件。旧 attempt 默认归属本机。

## 材料包模式

旧项目仍按题目工作流入库／脱敏；新项目先对材料包工作流执行这两步。派生题目使用建题时复制的受管理整包快照，不能再次入库或脱敏。材料包后续补充、重新脱敏只产生供新题选择的版本，旧题的附件和结果不随之失效。`server/material-package-questions.ts` 承担建题复制与来源绑定；本目录仍承担提取与脱敏执行。

硅基流动（SiliconFlow）的新脱敏任务在入队时冻结批次并发为 1，减少单题多批同时请求造成的供应商限流；其他供应商沿用原执行预算。它不保证账户 RPM／TPM 配额一定足够，也不限制其他任务共享同一供应商的调用。历史任务的冻结预算、已完成字段及题目快照保持原样。

## 数据流与依赖

题目目录扫描遇到超过 200 页或超过单文件大小限制的 PDF 时，按页生成分片并缓存到 `.storage/pdf-splits/`；先按最多 200 页分段，再按单文件大小限制继续细分。来源目录和超限原件保持不变，来源清单指向管理存储中的分片。含拆分 PDF 的题目目录入库允许最多 200 MB，其他目录及手动上传仍为 100 MB。分片在数据库中作为独立附件和页序处理，原 PDF 与分片的对应关系由文件名页码段保留。此步骤只拆分，不压缩图片，也不做脱敏；若分片合计超过 200 MB 或单页仍超限，同步会报错。

document.ts 分流文档；jobs.ts 冻结 PDF provider 与 DOCX 转换版本并领取 → process.ts 校验来源／缓存并将逐页原文保存为数据库附件产物；redaction-jobs.ts 从数据库读取原始提取文本 → redaction.ts 独立脱敏，并将脱敏正文写回数据库附件产物。pdf.ts、vision.ts、redact.ts 提供页级工具与辅助。

## 维护边界

当前 PDF 工作流默认直连 MinerU v4 API：通过上传地址提交本地文件、轮询任务并解析 `content_list.json`；仅 API 网络、服务端5xx或超时失败时回退一次至本机 `mineru-open-api` CLI。设置 `PDF_EXTRACTION_PROVIDER=mineru-cli` 可显式使用 CLI。两种方式均要求 `MINERU_KEY`，不会回退到智谱。历史 GLM 结果和旧页级 vision 调查代码仍保留，但不作为当前 PDF 工作流解析路径。提取成功不是全文准确或已脱敏；保留 issues 与页来源。脱敏字段输出错误使用安全原因码记录，日志不带文本正文。配置冻结，附件变更或取消后旧结果不得发布。子模块见 [PDF provider](pdf-extraction/README.md)。

API 脱敏按附件及原页序，以字段数、原文字符数和保守输入 token 估算打包；默认上限为每批 256 字段、10,000 字符、12,000 估算输入 token。输出上限固定为 32,768 token，不参与切批。估算不是供应商 tokenizer 的精确计数；单字段超过输入预算时明确失败，不截断；完整输入仍在输入预算内时以输出上限尝试一次，并由完整性校验决定是否接受。每题默认并发 8 批；worker 同时处理的 API 脱敏题目数跟随持久化 `llmApi` 并发设置，所有脱敏批次及其他 API 调用共同受全局请求槽位限制。完成一批后立即补下一批，槽位可供等待中的 API 调用使用。单请求队列等待、外部请求、无进度停滞和整题执行均有独立上限；初始默认分别为 45 秒、60 秒、6 分钟和 20 分钟。单次模型请求超过 60 秒即停止并记为超时，不再继续等待，均为待真实供应商验收的运行边界，不代表已证明最快。校验有效的字段单独提交并立即写入断点；失败只补做未通过字段，无法解析时才在共享请求预算内拆分。并发结果经单一写入链原子保存，断点同一时刻仅允许一个执行者持有；同输入重派只处理未完成字段。任务取消、材料或模型绑定变化后旧结果不得发布。任务定期持久化只含字段计数、耗时和阶段的安全进度，详情页面手动刷新后可查看。模型只返回扁平 `fields`，程序根据本次唯一字段编号还原附件、页码和结构，不要求模型回传这些元数据。项目规则明确要求金额原样保留时，执行器提示模型保留普通金额，并在字段发布前核对金额未被遮盖。所有请求字段都有结果且敏感值可在对应原字段定位后才发布整份脱敏结果；重试耗尽时保留已完成断点但将整次标记为失败。日志只保留安全原因码、调用 ID 和批次序号，不记录原文或供应商原始错误。脱敏不重新转写页面；空白原页由程序保留。

执行约束（修改此流程时必须保留）：目标是“尽量快地完成准确脱敏”，不是只追求状态变成成功。可验证字段立即落盘；并发 worker 完成一批后立即领取下一批，既不逐批串行等待，也不无上限地同时派发。某字段缺失时只补做失败字段；有限补做仍缺失就失败并保留进度，禁止把缺失解释成“没有敏感内容”、跳过校验、发布部分结果或为了成功反复重跑整题。字段内容必须完整输入；禁止截断、静默缩短、删除结构或让模型重写非敏感原文。输出 token 估算是打包启发式，可能高估“返回映射会重复整段原文”的成本；若完整输入仍在输入预算内，应在 provider 输出上限内尝试，并受既有限次补做与整题时限约束；只有完整 JSON、字段覆盖和原文定位均通过才接受，截断/缺字段仍失败关闭。不要通过无限重试、调大超时或取消并发上限掩盖慢请求；提速须用真实同输入的总耗时和调用数验证，正确性须检查原文覆盖、字段归属及结构。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

当前附件按 `deleted_at IS NULL` 查询。已移除附件与原件、提取文本和执行历史继续保留。附件接收、目录同步在工作流行锁内调用 `state.ts`，不再创建或递增材料版本。页面并发增删通过接收前的附件 ID 集合核对，避免覆盖另一请求新增的附件。

可选附件归档经单独 API 手动触发，不注册步骤、不创建 `step_attempts`、不进 worker；只新增／更新 `redacted_docx` artifact，并在 `assets/out/附件库/<主项目>/<期数>/<题目>/` 保存当前原件副本与 `成果/<附件名>-脱敏-<材料ID前缀>.docx`（旧合并格式为 `成果/脱敏材料.docx`）。缺少期数的历史记录仍使用原来的 `<项目>/<题目>/` 层级；下载和重置同时接受两种路径。项目页点击“下载全部达标题目 Excel”时会逐题调用此入口，先补齐或复用当前脱敏 DOCX，再生成带附件地址的工作簿；新期次目录名取主项目名、期数和题目来源标识。每个原件写入前校验数据库 SHA-256 与大小；新格式 DOCX 从当前脱敏结构生成，历史文本产物走兼容渲染，不从原 PDF/OCR 再提取。内部附件序号、页码及结束标记不写入 DOCX，原页边界转成分页。输入必须是当前成功脱敏且绑定全部当前附件的结果，导出还要求可见流程成功且 ordinal 8 已归档。材料或脱敏变化后，下载按当前脱敏尝试和 DOCX SHA-256 拒绝旧文件；整条工作流重置会一起隔离清理此题附件库目录。导出错误不更改工作流步骤或尝试状态。PDF 原件作为单个原始附件复制，不生成页图；最终 DOCX 只含脱敏文字与文档样式，不包含图片。

工作流附件全文接口支持 `redacted_only=true`：只返回当前已脱敏正文及页索引，不返回原始提取页；供达标题目详情弹窗阅读附件时使用。普通附件全文接口保留原有原文／脱敏双视图行为。

脱敏默认为独立大模型 API，默认复用统一 API 的 OpenRouter DeepSeek V4.1 Flash（关闭思考），可用 `LLM_API_*` 覆盖，步骤只选择统一目录中的模型；已有显式 Codex 配置保留。API 直接接收已入库原文，Agent 使用隔离文件目录。两者共用输出校验、产物格式、附件指纹和取消检查。模型/执行方式/提示词变更或恢复默认使脱敏及后续结果失效；API 脱敏与作答共享 `LLM_API_CONCURRENCY` 路 API worker（默认 8），不占用本地 Codex 通道。JSON 结构检查不证明敏感信息已全部处理或事实未改写。

诊断日志：提取队列按 workflow/attempt 关联附件提取的开始、返回和失败；脱敏校验失败记录安全原因码、调用 ID、附件 ID、页码及预期/实际数量，正文允许为空字符串，空白页不单独判失败。PDF 的 OCR 页为空或带识别问题时，会用配置的提取器复识别一次，仅替换这些页；复识别后仍为空会留下 `empty_after_recheck`，其他未解决问题会留下 `ocr_recheck_unresolved`。页级问题随脱敏结构进入导出校验；普通日志不记录正文。

MinerU 的正文转换、缓存标识及私有诊断目录见 [PDF provider 说明](pdf-extraction/README.md#mineru-转换与诊断)。重新提取入队会使该题下游结果失效；历史原文不会自动补齐，需显式重新派发。

新脱敏合并正文由程序插入附件序号、结束标识和原附件页序，保留不同来源之间的边界，不依赖模型生成分隔符。内部索引继续保留附件 ID 与逐材料正文。任务配置记录 text_layout，旧布局成功任务不会作为新布局任务复用；历史产物不自动重写，重新脱敏后下游获得新正文。

脱敏前，程序统一调用 `filterRedactionFormatting()`，还原 Markdown 标点转义、删除方括号及其中内容、移除百分号格式包装；清理后移除因此变空的段落和列表项，保留原有空段、表格单元格及分页。模型清理后变空的段落和列表项也会移除。结构化提取把标题、段落、列表、表格单元格、图注、脚注及可识别的图片文字映射为带页序的块；无结构文本也转成段落块。模型返回扁平字段编号与需处理的原文片段；孤立数字字段附带同附件跨页候选序列供模型判断页码，程序不据此自动删除；垃圾项由模型判定、程序精确匹配后删除，固定格式残留由程序过滤，模型格式映射忽略，敏感项按原有类别和遮盖规则处理。模型不返回附件页元数据或整字段正文；其他文字沿用原文。API 同一附件按原页序合并未完成字段，按字段、字符和估算 token 输出预算打包，最多并发 8 批；字段错误只补做未通过的字段，无法解析的批次在共享预算内拆分。单批修复预算耗尽后仍继续处理其他批次并保存通过字段；任务最终仍失败且不发布不完整结果。整题超时、停滞、取消以及认证、额度、配置、限流或供应商级错误会停止整个并发池。通过校验的字段映射保存在权限受限的本地断点文件中，绑定材料、提示词、模型配置和协议；同输入重派只提交未完成字段，全部成功入库后删除断点。API 调度策略不进入断点身份；结构脱敏协议 v27 不复用旧协议断点，历史产物不自动重写。结构化 DOCX 复用还核对结构摘要、渲染器版本和 DOCX 实际摘要。

手动 DOCX 导出按当前附件逐份生成：每份原附件对应一份脱敏 DOCX，正文来自同次脱敏索引的 material_id 对应内容；校验索引指纹、附件集合和当前输入绑定，缺少正文时整体失败。每份 DOCX artifact 保存 material_id，重试逐文件复用并清除旧合并文件的索引；历史合并文件可能仍在磁盘，但不再进入新 Excel 引用。页面提供逐文件下载。

附件库相对路径由下载与工作流重置共用校验，逐附件 DOCX 与旧合并文件均可安全重置；路径层级、目录归属及符号链接限制保留。

当前任务协议为 `attachment-field-redaction-v31`；无结构文本也适配为段落字段，不保留旧整页脱敏入口。只校验 JSON 可解析、请求字段覆盖完整；多余或无法对应的返回项忽略、敏感值可定位；附件 ID、页码、页数、顺序、结构、类别和遮盖子串不由模型回传或强制校验。敏感值匹配先用精确原文；没有精确匹配时容忍空白、Unicode 兼容形式、中文逗号／顿号差异，以及两个汉字之间 OCR 混入的标点或符号串，数字中的横线和小数点仍保持区别；可选遮盖子串重复且互不重叠时逐处遮盖；无法定位或位置重叠时回退遮盖整个敏感值，不会仅因它拼写不同、重复或缺失而失败；重复字段合并，重叠遮盖范围取并集；真实敏感值无法定位时仍拒绝发布。姓名和电话的遮盖由程序按类别生成；编号／案号没有有效遮盖子串时按首2末2生成（过短或已全遮盖值整体遮盖），其他类别使用模型给出的可选遮盖范围或遮盖整个敏感值。需保留的普通金额由程序只遮数字并保留币种、单位和标点；组织名称末尾的明确公司／法院后缀保留。MinerU 缓存保留识别 issues，不因警告重新上传；来源、摘要、页序及结构投影仍须通过验证。当前 MinerU 入队与执行不再读取旧 GLM 提取配置。

### v18 执行与维护注意事项（2026-10-14）

- 打包估算只决定批次，实际请求使用配置允许的有界输出上限；不要把估算值当 `max_tokens`，密集敏感片段可能需要更多映射。`max_tokens` 是上限，不是要求生成这么长。
- 多字段响应不完整时立即缩批，即使流结束时没有提供 `finish_reason`；拆分共用原批次和整题额度，避免把同一大请求再等待一轮。缺字段只补未通过字段；单字段修复可明确返回 `{redactions:[...]}`，程序只绑定该唯一字段。缺数组绝不能补成空数组。
- 精确匹配优先，不能通过删除所有标点把 `12-34`、`1234` 和 `12.34` 当成同一个值。同页字段ID重复应在收费调用前失败；不同页相同ID仍支持。
- 每次接受返回、补位和保存之前检查整题／无进度期限；使用墙钟及单调计时较大值，避免系统休眠后接受过期响应。失败保留实际最后进度时间，排队与请求耗时分别累计；不要把失败耗时记0或把失败时间当新进度。
- 断点独占使用已有 SQLite 事务租约（每个断点的 `.ownership/.concurrency/`），替代读令牌后删除文件的锁恢复。保留这个目录作为运行元数据；模型、规则或协议变化不能复用旧映射。
- 写正文前即进入失败清理范围，第二个文件写失败也清理；提交前重新核对当前有效规则／模型。相同工作流存在未结束的不同输入任务时拒绝重复派发。
- 心跳SQL使用本地 pg 客户端支持的5秒查询时限；连接获取沿用池15秒上限，退出等待在途心跳收束。数据库持久化失败不等于模型失败。
- 禁止用截断来源、漏页、猜测空结果、放宽完整性校验、无限重试、延长超时或更换模型来制造成功。原文定位及结构完整不证明模型零漏识别，真实内容仍须审阅。
- v17 冷启动性能与续跑必须分别报告；真实题目4／8成功前不宣称本轮优化验收完成。详情与执行证据记入 `docs/reviews/2026-10-14-redaction-function-audit.md`。


脱敏v18补充：真实内容核对发现模型可把完整编号作为mask_text，覆盖首2末2规则；编号／案号现统一由程序生成该遮罩，与姓名／电话同样不受模型遮罩范围覆盖。新协议不复用v17映射。队列原文加载也计入整题预算，读取正文查询最多180秒且不得超过剩余整题时间；脱敏调用只获得剩余预算，发布前再次检查截止时间。真实耗时以attempt开始／结束时间为准，执行器progress仅表示执行器内耗时，不能省略加载与提交。


真实大批错位后的少量错误字段需要隔离：1—4个剩余字段各单独尝试一次，5—8个也允许缩批；所有请求仍共用原批次6次与整题预算，不能增加单字段无界重试。修复请求必须明确返回数组并逐项通过原文定位，不能因“大概率无敏感”填空。汉字间的OCR符号可容错，但该容错不能跨数字标点。错误对象可能作为AbortSignal.reason共享，并发取消不能改写原失败调用的call_id。


### 当前 API 契约与失败补做

API发送字段编号、完整原文、页序与块位置；表格字段共享一次原行上下文并记录列位置，首行只标记first_row而不猜测表头。上下文与动态Schema都计入输入估算，不截断待处理原文字段。API使用json_schema/strict:true，fields为字典且本批所有编号均为必填键；程序转换为内部字段映射并继续校验每个原文位置。兼容解析旧数组与单字段修复返回不代表放宽完整性，缺项仍失败。Agent原数组协议保留。

单请求超时直接有限缩批，子批共用原六次请求额度和整题时限；一个子批失败仍处理另一个，只有全局预算/认证/取消等停止全池。局部失败在批次内收束，消费者继续补位，成功字段保存断点；整个任务有失败就不发布。领取事务的锁等待最多5秒，争用回滚退回轮询。v22隔离此前缺少上下文或主体规范化的断点，旧任务协议不匹配会明确失败后重新派发。

单请求超时后直接缩批，不原样重发同一批；字段覆盖和定位校验保持原要求。

json_schema只约束格式和字段覆盖，不能证明敏感信息零漏识别或行业通称保留正确。供应商对Schema的执行仍须真实校验。

## DOCX 与已人工脱敏声明

DOCX 默认走 MinerU v4 API 异步提取，忽略图片，按文档顺序把标题、段落、列表和表格放进一个逻辑文本页；PDF 的原配置和健康缓存条件不变。材料行的 `redaction_mode` 默认为 `model`，只有 DOCX 可通过附件详情按当前 SHA-256 改为 `declared_redacted`。声明材料的文本与结构仍进入完整的脱敏正文和索引，但不调用模型；混合包只把未声明材料送到原脱敏执行器。声明变化使本材料包当前脱敏及后续结果失效；替换附件恢复默认。原始 DOCX 仍是受管理原件，人工声明不等于系统验证零敏感信息。

脱敏映射应用先合并并删除垃圾，再将敏感范围投影到剩余原文；金额和真实日期按项目保留要求优先保护。涉及金额／日期的垃圾清理只允许明确扫描水印或打印落款等场景，短片段无法确认时保留原文，包含正文的长范围则仅修复该字段。无法定位时容忍原有格式差异，修复请求包含当前失败字段与映射；权限受限的 redaction-checkpoints/diagnostics 保存失败字段、映射、页码和调用标识，普通日志不记录正文。

readCurrentRedactionForDocx由独立DOCX导出与Work归档共用，只返回已通过当前来源/索引/正文投影校验的脱敏结构；归档无需等步骤8完成才能在事务内读取结构，不调用导出入口来绕过完成条件。

材料库题目的DOCX完成门槛按统一步骤注册表仅检查4–8；旧题继续检查其适用步骤。不能因新题没有旧1/9步骤拒绝已达标归档后的导出；后续仍校验私有材料、来源摘要及manifest绑定。
