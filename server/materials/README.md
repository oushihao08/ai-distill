# 材料提取与脱敏

支持本地 DOCX／TXT／MD、PDF provider、原文与页索引落库、指纹缓存，以及可选择 API 或本地 Agent 的独立脱敏。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `config.ts` | 提取配置读取：从 config/extraction.json 合并并校验文本识别、实体检查和脱敏兼容参数。 |
| `document.ts` | 统一文档提取：本地解析 DOCX/TXT/MD，PDF 使用 GLM-OCR 或注入的提取供应商。 |
| `state.ts` | 附件或脱敏配置变更的事务失效处理：取消活动任务、重置依赖步骤、终止旧返修链并使项目导出失效。 |
| `jobs.ts` | PDF 提取队列：冻结解析器配置、复用健康缓存并把当前附件的原文与页索引发布入库。 |
| `pdf.ts` | 页级 PDF 工具：封装 Poppler 命令、文字与 OCR 提取、页级并发及指纹缓存。 |
| `process.ts` | PDF 材料处理与产物落盘：校验来源和缓存指纹，生成私有逐页文本并保留识别问题。 |
| `redact.ts` | 规则脱敏辅助：合并实体及敏感格式匹配，统一替换文本并检查敏感模式残留。 |
| `redaction-jobs.ts` | 独立脱敏队列：冻结入库文本和模型配置，执行脱敏与检查并保存当前附件的脱敏文本。 |
| `redaction-config.ts` | 脱敏执行方式、默认 API 配置与显式 Codex 配置的合并及校验。 |
| `redaction.ts` | 逐材料脱敏执行器：按冻结配置选择 llm-api 或受限 Agent；API 按每批最多12页／20,000字符切分，逐批校验后按附件合并；仅结构或页码错误允许单批重试一次，页码及空白页均保留。 |
| `redacted-docx.ts` | 使用 `docx` TypeScript 库将数据库中的脱敏附件／页码文本转为 DOCX，保留段落、标题、分页及 Markdown 表格，转换粗体／行内代码；隐藏内部附件与页码标记，不解析原件或渲染页图。 |
| `redacted-docx-export.ts` | 全流程完成后手动生成附件归档：校验当前附件原件指纹并复制到 `assets/out/附件库/<项目>/<题目>/原件/`，将数据库当前脱敏文本生成 DOCX 放入同题目的 `成果/`；安全下载时拒绝过期或被篡改文件。 |
| `vision.ts` | 智谱视觉客户端：调用页级识别及实体提取，保留 usage 并处理超时、取消和服务错误。 |

## 数据流与依赖

document.ts 分流文档；jobs.ts 冻结 PDF provider 配置并领取 → process.ts 校验来源／缓存并将逐页原文保存为数据库附件产物；redaction-jobs.ts 从数据库读取原始提取文本 → redaction.ts 独立脱敏，并将脱敏正文写回数据库附件产物。pdf.ts、vision.ts、redact.ts 提供页级工具与辅助。

## 维护边界

当前 PDF 默认路径支持 GLM OCR layout_parsing 与 MinerU CLI；显式 PDF_EXTRACTION_PROVIDER 优先，否则 MINERU_KEY 存在时选择 MinerU。旧页级 vision 调查能力仍保留。提取成功不是全文准确或已脱敏；保留 issues 与页来源。脱敏输出的材料数、页数和页内容类型错误使用安全原因码记录，日志不带文本正文。配置冻结，附件变更或取消后旧结果不得发布。子模块见 [PDF provider](pdf-extraction/README.md)。

API 脱敏按附件及原页序拆成有界批次，每次外部调用使用独立返修预算键；模型返回的同一附件批次按 `material_id` 合并回一个附件。整卷附件顺序按题目来源目录清单排列，保持脱敏正文中的附件编号与成稿附件名称一致。JSON、材料或页码结构校验失败时，只重试该批一次，并计入总用量；供应商、额度、网络和超时错误不自动重试。所有批次通过页数与页码校验后才发布整份脱敏结果，重试后仍不完整则整次失败，不把部分结果标记为成功。成功和失败结果保留安全调用 ID 与可用的用量／页数诊断。提示词要求跳过无法转写内容时，仍保留对应页对象并将正文置空。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

当前附件按 `deleted_at IS NULL` 查询。已移除附件与原件、提取文本和执行历史继续保留。附件接收、目录同步在工作流行锁内调用 `state.ts`，不再创建或递增材料版本。页面并发增删通过接收前的附件 ID 集合核对，避免覆盖另一请求新增的附件。

可选附件归档经单独 API 手动触发，不注册步骤、不创建 `step_attempts`、不进 worker；只新增／更新 `redacted_docx` artifact，并在可见目录 `assets/out/附件库/<项目名>--<项目ID>/<题目名>--<题目ID>/` 保存当前原件副本与 `成果/脱敏材料.docx`。每个原件写入前校验数据库 SHA-256 与大小；DOCX 只从数据库当前脱敏 Markdown 生成，不从原 PDF/OCR 再提取。内部附件序号、页码及结束标记不写入 DOCX，原页边界转成分页；基础粗体和行内代码转成 Word 格式。输入必须是当前成功脱敏且绑定全部当前附件的结果，导出还要求可见流程成功且 ordinal 8 已归档。材料或脱敏变化后，下载按当前脱敏尝试和 DOCX SHA-256 拒绝旧文件；整条工作流重置会一起隔离清理此题附件库目录。导出错误不更改工作流步骤或尝试状态。PDF 原件作为单个原始附件复制，不生成页图；扫描页的“转文本还是保留图片”处理不在此功能内。

工作流附件全文接口支持 `redacted_only=true`：只返回当前已脱敏正文及页索引，不返回原始提取页；供达标题目详情弹窗阅读附件时使用。普通附件全文接口保留原有原文／脱敏双视图行为。

脱敏默认为独立大模型 API，默认复用统一 API 的 OpenRouter GLM-5.3-Flash，可用 `LLM_API_*` 覆盖，步骤只选择统一目录中的模型；已有显式 Codex 配置保留。API 直接接收已入库原文，Agent 使用隔离文件目录。两者共用输出校验、产物格式、附件指纹/取消检查与返修预算。模型/执行方式/提示词变更或恢复默认使脱敏及后续结果失效；API 脱敏与作答共享 `LLM_API_CONCURRENCY` 路 API worker（默认 8），不占用本地 Codex 通道。JSON 结构检查不证明敏感信息已全部处理或事实未改写。

诊断日志：提取队列按 workflow/attempt 关联附件提取的开始、返回和失败；脱敏校验失败记录安全原因码、调用 ID、附件 ID、页码及预期/实际数量，正文允许为空字符串，空白页不单独判失败。普通日志不记录正文。

MinerU 的正文转换、缓存标识及私有诊断目录见 [PDF provider 说明](pdf-extraction/README.md#mineru-转换与诊断)。重新提取入队会使该题下游结果失效；历史原文不会自动补齐，需显式重新派发。

新脱敏合并正文由程序插入附件序号、结束标识和原附件页序，保留不同来源之间的边界，不依赖模型生成分隔符。内部索引继续保留附件 ID 与逐材料正文。任务配置记录 text_layout，旧布局成功任务不会作为新布局任务复用；历史产物不自动重写，重新脱敏后下游获得新正文。
