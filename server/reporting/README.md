# 成果与 Excel 导出

新 `model_report_v1` 结果在评分单元格分别标注原始分、模型报告指标和否决；考点保留完整 rule 与业务 metadata，不假设每条都有正数 max_score。旧题目格式保持不变。数据取自当前达标判定引用的结果，不由导出器重新计分。

本模块只提供当前有效达标题目的查询及按需 Excel 导出。费用、产量统计、价格管理接口与对应计算模块已删除；历史数据库用量记录和迁移保留，不进行数据删除。

| 文件 | 职责 |
| --- | --- |
| `export.ts` | 用户点击导出时读取当前题目包和达标状态；按题目引用追溯同次脱敏生成的 DOCX，写入本机 `file://` 超链接；缺少当前 DOCX 时阻止导出，不回退原件。 |
| `results.ts` | 为每道达标题目输出一行任务数据：题目、任务名称、题面、脱敏输入附件名称、逐模型评分、可读考点、作答思路和标准答案；标准答案附件列按现有数据契约留空；另生成附件清单保存逐文件路径和链接。 |
| `xlsx.ts` | 生成 OOXML／ZIP，处理表名、特殊字符与超长单元格；按字段设置列宽、行高和自动换行，正文顶端对齐；生成外部超链接关系。 |

路由保存导出记录和失效状态，生成文件暂存在系统存储目录，经下载接口交给浏览器。工作簿包含“题目数据”和“附件清单”页签，不附加答案评分或返修历史；导出失败只重试导出，不重做业务步骤。`file://` 地址指向已生成的脱敏 DOCX，适用于本机打开，不是可公开访问的网络链接。保留既有测试文件不代表本轮运行了测试。

主表一题一行，“输入附件”单元格仅换行显示该题文件名，不随附件数量增加列。“附件清单”一文件一行，保存题目、工作流 ID、附件序号、文件名、本机完整路径及可点击文件链接，供本机 AI 上传时定位；同名文件按工作流和完整路径区分。链接只指向当前脱敏 DOCX，文件路径须保持有效。每份当前附件对应一份脱敏 DOCX；Excel 校验 DOCX 对应的当前附件集合完整，旧合并 DOCX 不计入，缺失时要求重新生成。

## 导出完整性与中断恢复

Excel 导出逐份调用当前 DOCX 下载所用的安全读取与 SHA-256 校验，拒绝缺失、过期、越界或被改写文件。每个项目的导出在显式数据库事务内持有 transaction-level advisory lock，事务覆盖查询和工作簿写入，并与整条工作流重置使用相同锁键；同项目并发导出或重置返回409。事务提交／回滚自动释放锁，事务结果未知时销毁连接，避免带锁连接回池。该方式兼容 Neon transaction pooling。重新出题使当前项目导出失效；历史文件保留但不再作为成功成果下载。

重新导出或重置时，取得同一项目锁后才能把无执行者的遗留 running 导出置为失败；不依赖耗时猜测。进程中断后 PostgreSQL 会随事务回滚释放锁；数据库记录与本地文件仍不是一个原子事务，导出路由会在可判定的失败路径清理文件。

导出只包含当前成功出题 attempt 的题目。收集记录时校验 attempt 内冻结的项目 skill 路径、文件清单和内容指纹自洽；不要求历史题目匹配后来编辑的当前 skill。工作簿生成完成后、路由写入成功状态前及下载时仍复核当前题目、达标依据和 DOCX 文件指纹。API 修改 skill 绑定会将已有项目 Excel 标为过期，便于按当前项目元数据重新生成；历史 attempt 和已归档题目保持不变。历史记录缺少冻结指纹或快照内部不一致时拒绝导出，不回填当前 skill，也不改写历史评分。

锁冲突会写入仅含项目 ID、请求 ID 和安全原因码的失败日志；该拒绝发生在创建导出记录之前，因此不会出现在导出历史列表中。当前运行实例是否已加载新锁实现仍需重新加载服务后观察日志与实际导出结果。

项目“下载全部达标题目 Excel”操作会先逐题调用现有脱敏 DOCX 归档接口，复用已校验的附件并补齐缺失目录/文件，再生成工作簿；因此附件链接对应的 DOCX 在 Excel 完成前已准备好。主表不导出内部任务类型；“考点”按条目逐行显示编号、考点文本和分值，“评分”按模型逐行显示模型名称、得分／满分及百分比。评分值来自被达标判定引用的模型结果，名称来自对应答案 attempt 的冻结模型名。
