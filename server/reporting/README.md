# 成果与 Excel 导出

新 `model_report_v1` 结果在评分单元格分别标注原始分、模型报告指标和否决；考点保留完整 rule 与业务 metadata，不假设每条都有正数 max_score。旧题目格式保持不变。数据取自当前达标判定引用的结果，不由导出器重新计分。

本模块只提供当前有效达标题目的查询及按需 Excel 导出。费用、产量统计、价格管理接口与对应计算模块已删除；历史数据库用量记录和迁移保留，不进行数据删除。

| 文件 | 职责 |
| --- | --- |
| `export.ts` | 用户点击导出时读取当前题目包和达标状态；按题目冻结来源追溯脱敏或原文 DOCX，写入本机 `file://` 超链接；缺少当前 DOCX 时阻止导出，不回退原件。 |
| `results.ts` | 为每道达标题目输出一行任务数据：题目、任务名称、题面、当前来源输入附件名称、逐模型评分、可读考点、作答思路和标准答案；标准答案附件列按现有数据契约留空；另生成附件清单保存逐文件路径和链接。 |
| `archive-workbook.ts` | 单题归档时复用达标题目导出与附件校验，为该题自动生成 `题目归档数据.xlsx`；下载前校验归档步骤保存的路径与 SHA-256。 |
| `xlsx.ts` | 兼容导出公共`../document-generation/xlsx.ts`，生成 OOXML／ZIP，处理表名、特殊字符与超长单元格；按字段设置列宽、行高和自动换行，正文顶端对齐；生成外部超链接关系。 |

路由保存导出记录和失效状态，生成文件暂存在系统存储目录，经下载接口交给浏览器。工作簿包含“题目数据”和“附件清单”页签，不附加答案评分或返修历史；导出失败只重试导出，不重做业务步骤。`file://` 地址指向已生成的对应来源 DOCX，适用于本机打开，不是可公开访问的网络链接。保留既有测试文件不代表本轮运行了测试。

成功归档步骤会为当前单题自动生成 `assets/out/附件库/<项目>/<期数>/<题目>/成果/题目归档数据.xlsx`，内容仍是通用题目数据工作簿；该表不等于 Work 专用的“法规案例检索轨迹.xlsx”。题目详情页提供下载，归档步骤保存该文件的相对路径和 SHA-256。归档前按题目冻结的材料模式生成 DOCX（共享材料库题目可为脱敏或 MinerU 提取原文；旧题仍为脱敏），再生成该题工作簿；DOCX 和工作簿任何一步失败时，归档状态保留，重复归档可重试导出。

主表一题一行，“输入附件”单元格仅换行显示该题文件名，不随附件数量增加列。“附件清单”一文件一行，保存题目、工作流 ID、附件序号、文件名、本机完整路径及可点击文件链接，供本机 AI 上传时定位；同名文件按工作流和完整路径区分。链接只指向当前来源 DOCX，文件路径须保持有效。每份当前附件对应一份对应来源 DOCX；Excel 校验 DOCX 对应的当前附件集合完整，旧合并 DOCX 不计入，缺失时要求重新生成。

## 导出完整性与中断恢复

Excel 导出逐份调用当前 DOCX 下载所用的安全读取与 SHA-256 校验，拒绝缺失、过期、越界或被改写文件。每个项目的导出在显式数据库事务内持有 transaction-level advisory lock，事务覆盖查询和工作簿写入，并与整条工作流重置使用相同锁键；同项目并发导出或重置返回409。事务提交／回滚自动释放锁，事务结果未知时销毁连接，避免带锁连接回池。该方式兼容 Neon transaction pooling。重新出题使当前项目导出失效；历史文件保留但不再作为成功成果下载。

重新导出或重置时，取得同一项目锁后才能把无执行者的遗留 running 导出置为失败；不依赖耗时猜测。进程中断后 PostgreSQL 会随事务回滚释放锁；数据库记录与本地文件仍不是一个原子事务，导出路由会在可判定的失败路径清理文件。

导出只包含当前成功出题 attempt 的题目。收集记录时校验 attempt 内冻结的项目 skill 路径、文件清单和内容指纹自洽；不要求历史题目匹配后来编辑的当前 skill。工作簿生成完成后、路由写入成功状态前及下载时仍复核当前题目、达标依据和 DOCX 文件指纹。API 修改 skill 绑定会将已有项目 Excel 标为过期，便于按当前项目元数据重新生成；历史 attempt 和已归档题目保持不变。历史记录缺少冻结指纹或快照内部不一致时拒绝导出，不回填当前 skill，也不改写历史评分。

锁冲突会写入仅含项目 ID、请求 ID 和安全原因码的失败日志；该拒绝发生在创建导出记录之前，因此不会出现在导出历史列表中。当前运行实例是否已加载新锁实现仍需重新加载服务后观察日志与实际导出结果。

项目“下载全部达标题目 Excel”操作会先逐题调用现有材料 DOCX 归档接口，复用已校验的附件并补齐缺失目录/文件，再生成工作簿；因此附件链接对应的 DOCX 在 Excel 完成前已准备好。主表不导出内部任务类型；“考点”按条目逐行显示编号、考点文本和分值，“评分”按模型逐行显示模型名称、得分／满分及百分比。评分值来自被达标判定引用的模型结果，名称来自对应答案 attempt 的冻结模型名。

## 服务层与路由的分工

`collectProjectResults()`按步骤7及最新判断记录筛选accepted并读取其中的分数，校验冻结Skill自洽、共享库来源和逐文件DOCX；它不独立重跑达标算法。导出HTTP入口负责前后及下载时的当前依据复核，不能把纯工作簿构建函数当成独立发布授权。

`withProjectExportLock()`内回调失败会尝试提交回调已写入的失败记录，再抛原错误；调用方必须遵循此事务约定，不当作普通失败即全回滚的事务包装器。提交未知时销毁连接，不据本地文件存在宣称导出成功。

`readArchivedWorkflowWorkbook()`只按步骤8已保存路径、普通文件、大小及SHA读取，不重新运行当前达标算法；五件套下载的当前依据校验另见publishing模块。单题Excel是内部通用报表，包含思路/标答，不能当成模型作答或盲评输入。

`export.test.ts`以注入查询/临时附件检查筛选、锁、来源和文件完整性；`xlsx.test.ts`检查OOXML结构/超长文本/链接与渲染字段。源码/ZIP结构不证明Excel应用视觉效果或平台交付成功。

单题归档工作簿由publishing worker在最终归档提交前生成；内部preparingPublication只接受当前步骤running，不向普通下载开放未完成归档。下载仍只接受succeeded和已保存的文件摘要。

分册材料按冻结且非空的`prepared_documents`生成DOCX，工作簿逐一核对其数量和文件名，不拿原PDF数量作分册数量；非分册材料仍核对逐原件覆盖。一次导出对每题只读取一次已验证来源索引，并继续逐文件核验归属、来源模式、路径和SHA，不在多份分册之间复用其他题的来源。
