# 出题

作者本次`render_command`先调用与结果接收相同的`validateDraft()`，使用本次冻结附件和内容/评分契约，再同源渲染题目文档。字段、ID/维度、分档或引用等确定性错误会在作者会话内明确报错并允许修正；结束后仍重新校验。该行为不自动判断法律正确、原子性或难度，也不改变作者工具权限。

Work的ID／维度错配在同次校验中列出具体条目位置、合法格式的ID及维度一级号（显示前20项并说明剩余数量）；不自动改号、改Q、修研究关联或输出判据正文。作者修正实际结果后重跑同一渲染命令，不增加模型调用或语义硬拦截。

出题步骤可单独配置 `timeout_ms`（1—120 分钟，毫秒；未设置沿用 Codex 的 30 分钟默认值），派发时冻结并传给作者执行器。超时仍是失败，不因工作目录存在草稿而自动入库。作者提示词要求从本次输入清单复用附件路径，避免手抄工作流 ID；`result_missing`、`result_validation_failed`、`codex_timeout` 等安全原因码和阶段写入失败尝试，页面沿用步骤错误入口展示。项目 skill 和历史尝试不因这项执行提示改变。

## 项目规则兼容改造（实施中）

出题队列已冻结项目配置的 before/after 脚本清单并接入同步钩子；主操作检查点保存在 hook_runs，钩子附加结果不会修改题包。后置异步动作与主成功结果同事务登记。无钩子时不访问新表；真实使用须先应用 033 迁移。钩子失败明确记录 project_hook_failed，续跑 API 可恢复原尝试并核对检查点指纹；实际脚本测试及本轮真实 PostgreSQL／Codex 验收已验证原尝试续跑复用主结果，该尝试主请求文件只有一份；异步动作已验证进程停止后恢复与独立失败重试。证据范围见 Work 系统兼容改造计划。

`validateDraft()` 与 `runAuthoring()` 已增加显式 `model_report_v1` 契约，保留每条 criterion、完整 rule 和业务 metadata，不把扣分／否决转换成正向满分。执行器仅在收到显式冻结的 `scoring_policy` 时采用新格式，默认旧格式保持不变；本地交付渲染脚本同步支持两种格式。出题入队从评分步骤同一配置源读取规则并冻结；结果携带冻结政策，后续评分不受当前项目设置变化影响。新 Rubric 版本摘要包含完整规则与政策，兼容 JSONB 键顺序。下文固定正分描述适用于默认 legacy 模式。线上项目启用、页面及可执行钩子仍在实施，不能据此宣称完整 Work 流程已验收。实施清单见项目根目录的《系统兼容改造计划》。

Work 法律全场景出题额外要求冻结 `model_report_v1`，并在 Rubric metadata 中提供可归档的 `project_context.harbor`、完整 Harbor metadata 和按脱敏材料顺序排列的 `input_files`。专业 metadata 或输入映射缺失时在 ordinal 4 结果校验阶段失败；外部 task_id、org 可省略或为 null，不阻断出题，归档时必须提供并校验。其他项目沿用原契约。Harbor 导出仍会复核完整字段、成果清单及评分映射。

ordinal 4 的出题队列读取步骤设置、本地项目 skill，以及数据库中的当前脱敏附件，由同一次作者调用生成并自检修订题目草稿，成功后直接保存可供后续作答的题目包。系统不再创建或执行独立审查任务；数据库中 ordinal 10 的既有步骤与尝试只保留为历史数据，不进入接口、页面、评分或工作流门槛。

材料库派生题目的附件正文来自冻结的私有脱敏快照；来源清单中的路径只用于任务元数据，不能据此访问文件系统。来源路径可以是材料库内部相对路径，题包展示只使用来源文件名。

每题可单独设置可选出题方向；有值时随本次输入冻结并加入作者提示，空值时不增加方向指令。派生题目的场景、角色视角、项目出题标签及历史目标等级在入队时冻结到 `design_context`，作为作者设计输入；它们不修改模型作答或评分配置，也不是等级验收结论。修改方向会取消本题活动出题及后续任务、清除当前题目及下游结果，保留入库、脱敏和历史尝试。

相同输入的出题任务仍在排队或运行时，重复请求会复用该活动尝试；已有成功结果后再次派发会创建新尝试，并清除依赖旧题目的后续状态。

普通新出与重出每次新建会话，业务输入只有本次数据库脱敏正文、指定 skill 和步骤出题指令。不查询旧题、模型答案或评分，也不写 `evaluation-feedback.json`。普通任务冻结 `fresh-desktop-v1` 契约标记，worker 在调用模型前拒绝缺少标记或携带历史反馈的旧普通任务，要求重新派发；已完成历史结果和旧摘要仍保留兼容。

后续改动须保留作者 Codex 的桌面式工具能力：文件、shell／计算、网络检索和已配置 MCP。`answer_requirements` 属于被测作答器的输入／输出记录，题包结构校验只检查交付结果，不能拿它收紧作者的工具权限、强制固定工具调用顺序或减少出题研究。当前能力差距和验证方法见[能力对齐清单](../../docs/plans/2026-10-11-codex-manual-capability-alignment.md)。

普通出题通过 `fresh_authoring` 执行选择，在冻结并经 `realpath` 校验的项目根目录运行，正常加载用户配置、适用项目规则与工具，使用完整文件／网络权限，不追加应用通用开发者指令。每次调用 `--ephemeral` 新建会话并关闭记忆。完整权限下，历史文件的排除是任务指令边界，不是文件系统硬隔离。评分保持独立执行隔离。

设置接口保存新模型时仍按当前 CLI 广告目录校验；出题派发只校验已保存设置的结构，不把缓存目录当执行白名单。Codex CLI 才是模型调用时的能力裁定方，避免模型目录缓存遗漏已验证可运行的配置而在入队前阻断任务。

`input/input.json` 记录身份、步骤提示词、附件顺序及 skill 文件路径／大小／SHA-256。skill 使用已校验的本次副本，保留内部引用相对位置；后端按冻结 ID 从数据库读取并校验脱敏正文，在普通出题执行期间写入 `input/attachments/附件N.txt`。提示词逐份给出本次 skill 入口和附件的绝对路径，作者无需自行搜索 `.storage`。作者执行结束后，不论成功或失败均清理本次附件正文文件；数据库脱敏产物仍为权威正文，输入索引、指纹、事件和结果继续保留。未配置步骤提示词时默认“查看指定 skill，依据本次附件出题。”。自定义步骤提示词原样保留，不自动清洗历史要求，运行切换前仍须核对。

作者同一会话完成设计、检索、核算和自检，将完整 JSON 保存到本次 `output/result.json`，按 `input/delivery.json` 的确定性渲染命令生成完整 `output/题目.md`。JSON 是入库权威表示，Markdown不得手改，最后一次写文件必须重新运行渲染命令，表头按冻结的原附件显示名称保留；两份正文只允许换行差异；缺失、不一致、非法 JSON、越界附件或外部链接均不提交成功。末条聊天回复只存 `completion.txt`，不能冒充题包。输出及临时计算文件按题目／尝试存放在既有 `.storage/` 私有目录，不写共享项目根文件；不合格尝试保留历史，不自动进入成功案例库。

普通出题保存私有 `output/request.json`（实际 argv、stdin、cwd、模型、档位、配置目录、输入清单与指纹）和 `events.jsonl`，用于追溯实际调用，不记录凭证或整个进程环境。请求快照不列为输入，完整权限下不保证物理不可读。

普通日志只保存失败事件。出题、评分、skill 生成及 Codex 脱敏的 `attempt.failed` 会带安全的 `failure_phase`（输入校验、Agent 执行、结果校验或结果保存），可用工作流／尝试 ID 与底层 `call.failed` 关联；不把题面、附件、提示词或模型原始输出写入普通日志。

出题输出 Schema 的 `attachment_ids` 枚举按本次脱敏材料 ID 动态生成，出题提示同时列出允许 ID。`answer_requirements` 描述的是后续被测作答器，不是作者 Codex：当前作答 API 只接收文字、返回文字、不执行工具，因此字段固定为 `text/text/tools=[]`。作者 Codex 在全新出题会话中仍使用配置好的文件、shell/计算、网页搜索及已配置 MCP 能力；作者调用过什么工具不改变作答器字段，也不据此降低题目复杂度。未来若作答器加入工具循环，须先改作答执行能力和隔离契约，再更新该字段。`validateDraft()` 在写入前拒绝与当前作答器不兼容的要求，并校验缺失、重复及越界附件引用。附件校验失败时，尝试记录保存安全错误码和明确原因，不保存模型原始响应作为错误详情。

这里的“全新出题”包括首次出题和对既有成功题目的重出：每次都创建新会话，不读取旧题、答案、评分或个人记忆。它指任务类型，不是一个共用会话，也不是质量／难度等级。

内部 JSON 字段保持稳定；私有题包按表头、任务名称、任务类型、prompt、考点 rubric、作答思路、标准答案七章组织，公开题包排除后两章及内部附件记录 ID。公开表头只列附件名称，不输出本机绝对路径。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `executor.ts` | 独立出题调用：作者依据本地项目 skill 自检并生成完整题目包。 |
| `jobs.ts` | ordinal 4 的持久化队列：记录步骤设置、项目文件和数据库脱敏附件指纹，校验任务绑定并保存题目包。 |
| `validate.ts` | 出题产物契约：校验题面、附件、rubric 和标答的结构与完整性；旧质量报告校验不参与新工作流。 |

## 数据流与依赖

出题 jobs 记录步骤设置、当前 skill 文件清单、数据库脱敏附件指纹及普通出题契约标记 → executor.ts 作者调用、自检并生成私有草稿 → ordinal 4 成功并保存公开题目包。作答入口校验当前出题成功及题目、附件绑定。

## 维护边界

改题面、rubric 或附件后须重新作答和评分，不继承旧答案或评分。作者完整草稿（含标答与思路）保存在 steps.result 和 step_attempts.result 的 JSONB 中。模型作答输入不包含项目 skill、rubric、标答或评分提示词；独立评分只向模型提供步骤评分提示词、同版题面、rubric、数据库脱敏附件和匿名答案，不提供思路或项目 skill；标准答案默认不提供，显式 model_report_v1 的冻结 calibration 政策可提供校准参考。旧任务仍按各自输入清单校验；新任务不使用编号规则版本。真实卷宗出题质量与规则适用性尚需验收。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

项目规范输入仅含 skill/（包括 references、assets），不读取项目 materials/ 或 project.json；旧任务输入清单不匹配时重新派发。出题 Agent 可以使用本地工具读取指定输入、解析模板；无工具限制仅针对被测模型作答。作者按 skill 自检关键判断是否实际影响交付，结构成功不代表题目质量已经验收。普通重出不注入旧题或评分。skill明确引用的案例卡和模板可作为设计参考，案例事实与历史成绩不成为本题事实或目标。

出题说明允许使用实际可用的搜索／网页工具核对官方法律原文；普通出题的完整网络权限由执行选择提供，评分遵守其独立隔离环境。工具不可用时不得声称已检索，公开规则不能补造案件事实。

重新出题入队在重置下游状态的同一事务内使项目运行中及成功的 Excel 导出失效，防止旧导出继续显示为当前成功成果；不改变作者模型、提示词、权限或工具。

## Work 独立内容契约（2026-10-15）

出题步骤的 `workflow.content_contract=work_legal_v1` 显式选择内容结构，与 ordinal 6 的 `model_report_v1` 评分报告独立。配置随入队冻结，配置变更会拒绝旧尝试提交。新内容不按项目名称选择；历史 Work 的 Harbor metadata 校验只兼容未配置该契约的旧路径。

`work-contract.ts` 定义动态作者 schema、原始字段校验和同源投影；`work-contract.test.ts` 验证结构、能力边界、真实子进程渲染、评分隔离及后续读取。整题信息、成果清单、逐份完整标准内容、检索与任务能力保存到现有 steps.result / step_attempts.result JSONB，无表结构迁移。原始 rubric 的 metadata.statement 与分值字段为权威；criterion/rule 为确定性派生。reference_answer 从 reference_outputs 派生；JSONB 往返后可再次校验。完整新内容参与 question_version，避免仅改标答后继承旧结果。

结构校验检查引用、分档、维度覆盖与比例，不证明事实、原子性、法源、工时或难度。草稿与文件/工具/视觉任务可以保存，当前纯文字作答器在派发时给出具体拒绝原因，不静默删减任务要求。评分只投影原始判据白名单，不把整题研究与等级输入夹进 rubric。

未提供正式分类表二级标签时，`task_metadata.domain_l2` 可保留 null，后续登记再补齐；不能强迫作者自拟案由冒充分类标签。知识点格式中的“法律域”是说明文字，校验拒绝将其作为实际领域名称。以上属于字段真实性与结构边界，不证明分类或法律判断正确。

真实检索未命中或未采用时，允许`research_records.supports=[]`并保留未核验原因；不要求把所有查询强行关联到成果/判据。后续转换仍拒绝实际支撑成果或判据的未核验法源，不能用空关联掩盖已有引用的核验缺失。

Work出题的`delivery.json.input_files`列出本次附件关联ID与可见名称，作者原样复制这两项并填写用途；原文件名仅用于显示。Skill规则按入口导航读取，模板仅在Skill实际提供时读取。此清单不包含旧题或答案，也不放宽最终内容校验。

Work内容校验要求每份必交成果的精确路径出现在候选可见题面中，禁止仅在内部deliverables里增加必交文件；可选成果不因此强制列明。该检查不自动补写题面或改变专业评分。
