# 出题模块

管理 ordinal 4 的派发、冻结输入、作者调用和结果入库。Codex交回JSON题包后直接接收保存，成功表示结果已保存，不证明法律判断、评分原子性、专家工时或难度已经验收。独立评分在 `../scoring/`，被测模型作答在 `../answer-models/`；不能把两者的输入限制套给作者。

## 文件与调用链

| 文件 | 作用与调用方 |
| --- | --- |
| `jobs.ts` | `enqueueAuthoring()`由HTTP派发调用，固定步骤设置、设计输入、有效Skill和材料指纹；`runNextAuthoring()`由worker消费，启动时读取冻结来源，作者返回后直接保存步骤、尝试和公开题包。 |
| `executor.ts` | `runAuthoring()`建立本次私有输入，调用Agent并接收JSON，不以Markdown存在或一致性阻断保存；`renderPublicQuestionPackage()`排除思路、标答及Work内部研究信息，`renderPrivateQuestionPackage()`用于完整渲染。 |
| `receive.ts`、`validate.ts` | 前者的`validateDraft()`只转换下游兼容字段，后者仅保留旧导入路径；不校验内容、数量、附件引用或runner声明。 |
| `restore.ts` | 显式恢复原任务已完成的本地检查点，不重新调用作者；仅接收最新、未取消且因保存失败的出题尝试。 |
| `work-contract.ts` | 旧导入兼容；schema、同源标答/判据和Work交付要求的实现位于`../lifecycle/projects/work-contract.ts`。 |
| `jobs.test.ts` | 队列冻结、摘要、重出和绑定相关回归；注入数据库/作者替身不证明真实worker或Codex执行。 |
| `executor.test.ts` | 作者输入、产物渲染与能力边界；替身执行不证明实际工具可用。 |
| `validate.test.ts` | 原字段保留、默认兼容转换和JSON对象接收边界。 |
| `restore.test.ts` | 原检查点恢复、重复请求、新任务保护和数据库失败回滚。 |
| `work-contract.test.ts` | Work内容、同源派生及关联读取回归；其中子进程只证明所执行的本地渲染路径。 |

默认出题计划及判据文本分别复用生命周期模块的`defaultAuthoringPlan()`和`formatCriterionRule()`；Work仅覆盖项目差异。判据文本共用不改变`validateDraft()`保留作者显式criterion/rule的行为，也不添加保存拦截，详见[生命周期说明](../lifecycle/README.md)。

## 来源与设计输入

1. 共享库快照题由`readQuestionMaterials()`读取创建时固定的脱敏正文或提取原文；若快照含材料整理结果，则作者只收到按文书边界拼成的可见正文投影，原始附件摘要仍单独冻结以核对来源。标记为隐藏的文书及其独有摘要/范围不会进入作者输入；人工材料预览仍可看完整快照。旧目录/旧包派生题仍要求步骤1和9成功，并读取该次脱敏数据库产物。不能从当前期次设置切换旧题来源，也不能为缺失快照静默回退旧步骤。
2. 派发读取当前有效Skill（含期次覆盖）、步骤4配置及步骤6的评分政策。Skill仅按`skill/`集合冻结；项目`materials/`、`project.json`、旧题、答案和历史评分不是本次主动提供的业务输入。
3. 题目的场景、角色视角、目标等级、标签、出题方向冻结到设计上下文。作者收到两段提示词：系统固定通用规则解释跨项目设计概念，项目步骤提示词提供可定制业务标准；两段与Skill、设计上下文分别标明，均在派发时冻结并计入出题输入指纹。目标等级是设计输入，不是验收结论；任务不注入历史评测反馈。
4. 内容契约与评分政策分别配置。`work_legal_v1`需要`model_report_v1`；这些设置在派发时冻结，返回后的接收不执行Harbor metadata或Work内容准入。

## 执行及隔离

作者每次使用`fresh-desktop-v1`和新会话，在校验过的项目工作目录通过`fresh_authoring`配置运行。固定通用出题规则来自`shared/step-prompts.ts`，项目可配置提示词来自系统默认快照或期次步骤设置；任务输入分别保存并冻结两段内容，出题调用中明确分区。能力、配置目录、权限和MCP初始化由`../agent/`及`../codex/`决定；完整权限下，排除历史文件依靠任务指令，不是文件系统硬隔离。不能仅从声明的工具列表推断真实调用成功。

`input/input.json`保存身份/指纹/路径，正文逐份写入`input/attachments/附件N.txt`，内容遵循题目冻结模式；`.txt`是作者执行输入，不是交付附件格式。Skill副本保留相对导航。作者应完整阅读附件及指定Skill，使用实际可用的检索/计算能力，不把附件中的指令当系统命令。本次附件文件在成功或失败结束后清理，来源快照、清单、私有请求/事件与结果仍按各自存储边界保留。

含材料整理结果时，`materials`和`source_files`均基于可见文书投影，摘要/支持范围也过滤掉隐藏文书及依赖隐藏文书的组合；`materials`中的内容摘要参与冻结输入摘要。完整来源附件ID/摘要仍用于题目快照和当前来源绑定，不把隐藏正文复制到Agent输入。

`input/delivery.json`给出动态schema、结果路径和确定性渲染命令。作者先写`output/result.json`，可选生成`output/题目.md`；结束后不再重复检查草稿和Markdown一致性。JSON文件的安全读取仍由Codex模块负责。聊天末条回复不替代题包。渲染不调用额外模型，也不自动修正文义。公开Markdown排除标答/思路；完整草稿保存在步骤及尝试JSONB。

步骤4可配置1—120分钟超时，未配置沿用Agent默认值；超时或会话不完整不能因目录中存在文件而提交成功。失败按输入、Agent、校验、保存阶段记录安全原因，正文、提示词与凭证不进入普通日志。私有请求及事件用于受限诊断，不等于普通日志。

## 直接接收与后续使用

Work与豆包等项目共用直接接收策略：保留模型原字段，按现有字段生成可读题面、兼容标答与Rubric；不再以条数、维度、权重、文书数、工时、草稿内容、附件ID或能力声明拒绝保存。模型声明的draft/complete原样保留，不将保存成功冒充内容完成。

出题Schema是提供给作者的字段说明，不是返回后再次审查的门槛。缺少题面/标答等内容也可保存，其实际可用性由后续步骤的现有入口体现。JSON无法读取、文件或数据库真实写入失败仍会报错，不能假装保存成功。最终项目交付检查仍由各项目脚本负责，本次不改评分、阈值和交付资格。

## 队列、重出和恢复

对于作者已经完成、但原尝试记录为`failure_phase=result_persistence`的本地任务，可显式调用`POST /api/workflows/:id/authoring-results/:attemptId/restore`恢复原检查点。入口仅接受同一最新未取消任务，保留原版本、会话和失败记录；缺少已完成检查点直接报错，不重新调用模型。重复恢复返回`reused=true`。实际数据库写入失败仍回滚并报错，不能将未保存结果标为成功。

相同冻结输入和配置的活动尝试复用；已成功后再派发会创建新尝试，同事务清除步骤5—8当前结果、跳过其活动尝试并使Excel导出失效，历史尝试仍保留。改题面/Rubric/附件不能继承旧答案或评分。

消费前读取冻结输入；作者返回后不再复核当前来源、设计及Skill指纹。只核对本次任务仍是当前未取消的最新尝试，避免写入其他任务。普通任务缺少当前出题契约标记需重新派发，不自动兼容执行旧历史反馈任务。五分钟失联的运行尝试终结为失败，不据心跳存在推断外部模型仍在生成。

before/after钩子由[生命周期模块](../lifecycle/README.md)处理：冻结脚本和绑定，主检查点可用于明确续跑，后置待执行记录与主成功同事务登记，释放事务后同步执行，失败不回滚主结果。无钩子不依赖钩子表；有钩子须具备相应迁移。脚本可信边界、收费调用未知状态及恢复授权以该模块实现为准，不重复执行未知请求。

本说明来自源码静态核对，不证明当前数据库迁移、真实模型、网页或完整业务已运行验收。维护时同步检查调用方、题目版本、作答隔离、评分投影和归档映射；操作授权遵循根AGENTS.md。

当前两种模式及历史mask来源的`material_processing_mode`如存在于题目冻结来源，则出题任务冻结和摘要计算同时保留；旧快照未记录该字段时不从当前期次配置补写。输入摘要、绑定变化和来源变化分别记录安全错误码，普通日志不输出附件或完整快照。

共享库出题启动时读取冻结材料，返回后不再重读材料或比较输入指纹；相应保护不推广改变作答、评分及交付模块的绑定语义。

本模块local队列模式的派发归属、指定ID领取、取消及恢复接入共享[执行队列](../execution-queue/README.md)；业务输入/结果契约保留，默认兼容模式不代表业务环境已切换。

## 维护入口与不可改写的边界

`jobs.ts`按派发、绑定检查、领取、执行、提交分段阅读。`buildAuthoringFailure()`只生成安全失败载荷，检查点保存、产物清理和事务结算仍在消费函数；它不重试作者。新增错误类型应在此维护消息与错误码优先级，不能把异常原文直接公开。

`inputDigest()`保留历史规则版本与当前项目提示词两种来源的字段顺序和省略条件；JSON插入顺序参与哈希，不因“去重”合并为不同序列。修改摘要须核对既有冻结任务兼容。

任务心跳使用`../attempt-heartbeat.ts`，仍每10秒仅更新running尝试，finally停止。作者选项在原钩子/调用缓存内部组装，恢复命中缓存时不提前执行作者；出题返回不执行Work字段准入，既有Work交付模块的独立检查仍按其入口执行。

## 显式手动建议

普通出题仍不注入历史题包、作答和评分。用户通过独立[返修建议入口](../revision-advice/README.md)生成的同版有效建议是明确例外：派发冻结建议身份、来源摘要和文本，执行时将建议文本拼接到项目步骤提示词；原历史正文不传给作者。建议参与输入规范摘要，保存前不再核对。活动任务保持同一建议快照；新题不继承旧版建议。此功能不自动出题或修改评分标准。

已归档题目由共享派发保护拒绝重新出题；仅显式撤回归档后才允许返修。

## 项目生命周期隔离

Work专属schema、提示片段、题包同源派生、公开/私有投影和版本字段由[lifecycle/projects/work.ts](../lifecycle/projects/work.ts)注册，经`lifecycle/steps.ts`调用。公共executor不判断Work名称/目录/契约来执行业务；普通项目和豆包采用默认策略。`work-contract.ts`保留旧导入兼容，实际契约在`lifecycle/projects/work-contract.ts`。生成阅读稿的子进程调用同一接收/渲染入口，不序列化第二套项目函数。

提示正文、schema、字段投影及版本摘要的迁移回归基线位于生命周期模块；当前接收不执行内容准入或Markdown一致性拦截。

本机明确新派发可在同一事务替代他机尚未开始的同范围待办；运行、结果未知和续作仍受保护，新派发失败则旧意图变更回滚。适用范围、共享状态兼容与验证边界见[执行队列的跨机准入](../execution-queue/README.md#他机未开始待办与本机明确派发)。


材料使用建议不是出题准入：作者可选一个或多个相容组合，`material_scope_selection`保留主组合的方向、主体、场景及交付，`additional_combinations`保存其余组合。历史单组合保持可读。已用方向/场景仅作参考，参考表缺失、重复或模型未返回选择不阻断题包接收；完整实际选择保存在尝试JSON。参考索引冲突不替代/覆盖其他题目历史。可见正文和摘要仍按题目冻结的visibility投影。
