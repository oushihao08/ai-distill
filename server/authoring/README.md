# 出题模块

管理 ordinal 4 的派发、冻结输入、作者调用和题包校验。成功表示产物通过当前结构及版本校验，不证明法律判断、评分原子性、专家工时或难度已经验收。独立评分在 `../scoring/`，被测模型作答在 `../answer-models/`；不能把两者的输入限制套给作者。

## 文件与调用链

| 文件 | 作用与调用方 |
| --- | --- |
| `jobs.ts` | `enqueueAuthoring()`由HTTP派发调用，固定步骤设置、设计输入、有效Skill和材料指纹；`runNextAuthoring()`由worker消费，复核绑定后保存步骤、尝试和公开题包。 |
| `executor.ts` | `runAuthoring()`建立本次私有输入，调用Agent并复核JSON/Markdown；`renderPublicQuestionPackage()`排除思路、标答及Work内部研究信息，`renderPrivateQuestionPackage()`用于完整渲染。 |
| `validate.ts` | `validateDraft()`共用于会话内渲染及结束后接收，支持默认legacy和显式model_report_v1；校验字段、附件及runner声明。 |
| `work-contract.ts` | `workQuestionSchema()`和`normalizeWorkQuestion()`提供显式work_legal_v1内容结构及校验；`projectReference()`/`projectRule()`从原始字段派生兼容标答和判据。 |
| `jobs.test.ts` | 队列冻结、摘要、重出和绑定相关回归；注入数据库/作者替身不证明真实worker或Codex执行。 |
| `executor.test.ts` | 作者输入、产物渲染与能力边界；替身执行不证明实际工具可用。 |
| `validate.test.ts` | 默认题包结构、附件及作答能力校验。 |
| `work-contract.test.ts` | Work内容、同源派生及关联读取回归；其中子进程只证明所执行的本地渲染路径。 |

## 来源与设计输入

1. 共享库快照题由`readQuestionMaterials()`读取创建时固定的脱敏正文或提取原文；旧目录/旧包派生题仍要求步骤1和9成功，并读取该次脱敏数据库产物。不能从当前期次设置切换旧题来源，也不能为缺失快照静默回退旧步骤。
2. 派发读取当前有效Skill（含期次覆盖）、步骤4配置及步骤6的评分政策。Skill仅按`skill/`集合冻结；项目`materials/`、`project.json`、旧题、答案和历史评分不是本次主动提供的业务输入。
3. 题目的场景、角色视角、目标等级、标签、出题方向冻结到设计上下文。作者收到两段提示词：系统固定通用规则解释跨项目设计概念，项目步骤提示词提供可定制业务标准；两段与Skill、设计上下文分别标明，均在派发时冻结并计入出题输入指纹。目标等级是设计输入，不是验收结论；任务不注入历史评测反馈。
4. 内容契约与评分政策分别配置。`work_legal_v1`需要`model_report_v1`；未显式选择内容契约的历史Work兼容路径仍可能按项目名称/工作目录触发Harbor metadata校验，不能据此声称所有路径都完全无项目名分支。

## 执行及隔离

作者每次使用`fresh-desktop-v1`和新会话，在校验过的项目工作目录通过`fresh_authoring`配置运行。固定通用出题规则来自`shared/step-prompts.ts`，项目可配置提示词来自系统默认快照或期次步骤设置；任务输入分别保存并冻结两段内容，出题调用中明确分区。能力、配置目录、权限和MCP初始化由`../agent/`及`../codex/`决定；完整权限下，排除历史文件依靠任务指令，不是文件系统硬隔离。不能仅从声明的工具列表推断真实调用成功。

`input/input.json`保存身份/指纹/路径，正文逐份写入`input/attachments/附件N.txt`，内容遵循题目冻结模式；`.txt`是作者执行输入，不是交付附件格式。Skill副本保留相对导航。作者应完整阅读附件及指定Skill，使用实际可用的检索/计算能力，不把附件中的指令当系统命令。本次附件文件在成功或失败结束后清理，来源快照、清单、私有请求/事件与结果仍按各自存储边界保留。

`input/delivery.json`给出动态schema、结果路径和确定性渲染命令。作者先写`output/result.json`，再用同一校验器生成`output/题目.md`；结束后再次校验草稿及文档一致性（允许CRLF差异），拒绝符号链接等非法产物。聊天末条回复不替代题包。渲染不调用额外模型，也不自动修正文义。公开Markdown排除标答/思路；完整草稿保存在步骤及尝试JSONB。

步骤4可配置1—120分钟超时，未配置沿用Agent默认值；超时或会话不完整不能因目录中存在文件而提交成功。失败按输入、Agent、校验、保存阶段记录安全原因，正文、提示词与凭证不进入普通日志。私有请求及事件用于受限诊断，不等于普通日志。

## Work内容校验的边界

Work保存独立整题metadata、输入映射、成果清单、逐成果完整标准内容、研究记录、真实任务能力及完成/草稿状态。`reference_answer`和criterion/rule由原始内容确定性派生，完整Work内容参与题目版本摘要；JSONB键序不改变规范摘要。

- 必交成果的精确路径须在候选可见题面列明，不能仅藏在作者清单或标答。
- 新Work生成schema使用`task_metadata.instruction`保存背景、诉求、基准日与硬约束，`question`由`renderWorkInstruction()`联合成果清单派生。保存、重复校验和归档核对同源正文；旧题未带该字段时仍按原`question`读取，不重写历史。新schema给出完整维度名称，历史缩写仍按既有维度身份兼容。
- 输入映射按本次附件ID和`附件N`顺序；原文件名用于表头显示。
- 完整状态还要求本批Work至少30项Rubric，业务成果为DOCX/XLSX；与本项目新交付共用数量、格式及文件引用准入，草稿不加此完整门槛。完整状态检查必设维度、Q/锚点、权重、主观比例及独立否决；草稿保存不等于通过后续作答/达标门槛。
- 研究未命中可以保持未核验且`supports=[]`；已核验必须有来源URL，关联必须指向实际成果或Rubric。不证明URL真实访问、法源正确或法律结论合理。
- 二级分类可为null；等级文书、必要步骤和估计工时是结构化依据，程序不替代专业难度审查。
- `workLevelWarnings()`仅报告作者登记的等级数量/人时疑点；Work五件套私有状态保存提示，不新增步骤、改变等级、计分或通过门槛。它不认证独立文书数量及真实必要步骤。
- `task_requirements`记录真实业务能力，可包含文件/图像/工具需求；`answer_requirements`是派生的当前文字runner声明。Work设计可保存，后续执行是否支持由作答入口判断。legacy题包则直接拒绝非text/text/tools=[]声明。
- 历史Work路径保留专业Harbor metadata及输入映射，外部task_id/org可省略。它们不是普通出题前置；Siriser五件套与可选Harbor转换的实际归档要求见`../publishing/README.md`，不要将外部平台身份当成所有归档都必填。

## 队列、重出和恢复

相同冻结输入和配置的活动尝试复用；已成功后再派发会创建新尝试，同事务清除步骤5—8当前结果、跳过其活动尝试并使Excel导出失效，历史尝试仍保留。改题面/Rubric/附件不能继承旧答案或评分。

消费前和提交前复核来源、设计及Skill绑定；新输入或取消使晚到结果不能覆盖当前状态。普通任务缺少当前出题契约标记需重新派发，不自动兼容执行旧历史反馈任务。五分钟失联的运行尝试终结为失败，不据心跳存在推断外部模型仍在生成。

before/after钩子由`../workflow-hook-*`处理：冻结脚本和绑定，主检查点可用于明确续跑，异步后置动作与主成功同事务登记。无钩子不依赖钩子表；有钩子须具备相应迁移。脚本可信边界、收费调用未知状态及恢复授权以该模块实现为准，不重复执行未知请求。

本说明来自源码静态核对，不证明当前数据库迁移、真实模型、网页或完整业务已运行验收。维护时同步检查调用方、题目版本、作答隔离、评分投影和归档映射；操作授权遵循根AGENTS.md。

当前两种模式及历史mask来源的`material_processing_mode`如存在于题目冻结来源，则出题任务冻结和摘要计算同时保留；旧快照未记录该字段时不从当前期次配置补写。输入摘要、绑定变化和来源变化分别记录安全错误码，普通日志不输出附件或完整快照。

共享库出题在启动、写文件前和提交事务内分别复核材料绑定。同一次复核取得的正文仅在该阶段复用，不跨任务缓存；保留后两个边界检查，防止晚到结果覆盖新来源。

本模块local队列模式的派发归属、指定ID领取、取消及恢复接入共享[执行队列](../execution-queue/README.md)；业务输入/结果契约保留，默认兼容模式不代表业务环境已切换。

## 维护入口与不可改写的边界

`jobs.ts`按派发、绑定检查、领取、执行、提交分段阅读。`buildAuthoringFailure()`只生成安全失败载荷，检查点保存、产物清理和事务结算仍在消费函数；它不重试作者。新增错误类型应在此维护消息与错误码优先级，不能把异常原文直接公开。

`inputDigest()`保留历史规则版本与当前项目提示词两种来源的字段顺序和省略条件；JSON插入顺序参与哈希，不因“去重”合并为不同序列。修改摘要须核对既有冻结任务兼容。

## 显式手动建议

普通出题仍不注入历史题包、作答和评分。用户通过独立[返修建议入口](../revision-advice/README.md)生成的同版有效建议是明确例外：派发冻结建议身份、来源摘要和文本，执行时将建议文本拼接到项目步骤提示词；原历史正文不传给作者。建议参与规范摘要并在保存前核对。活动任务保持同一建议快照；新题不继承旧版建议。此功能不自动出题或修改评分标准。

已归档题目由共享派发保护拒绝重新出题；仅显式撤回归档后才允许返修。
