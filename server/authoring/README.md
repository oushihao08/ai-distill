# 出题

ordinal 4 的出题队列读取步骤设置、本地项目 skill，以及数据库中的当前脱敏附件，由同一次作者调用生成并自检修订题目草稿，成功后直接保存可供后续作答的题目包。系统不再创建或执行独立审查任务；数据库中 ordinal 10 的既有步骤与尝试只保留为历史数据，不进入接口、页面、评分或工作流门槛。

相同输入的出题任务仍在排队或运行时，重复请求会复用该活动尝试；已有成功结果后再次派发会创建新尝试，并清除依赖旧题目的后续状态。

普通新出与重出每次新建会话，业务输入只有本次数据库脱敏正文、指定 skill 和步骤出题指令。不查询旧题、模型答案或评分，不写 `evaluation-feedback.json`；显式返修才读取冻结的 `revision.evidence`。普通任务冻结 `fresh-desktop-v1` 契约标记，worker 在调用模型前拒绝缺少标记或携带历史反馈的旧普通任务，要求重新派发；已完成历史结果和旧摘要仍保留兼容。

普通出题通过 `fresh_authoring` 执行选择，在冻结并经 `realpath` 校验的项目根目录运行，正常加载用户配置、适用项目规则与工具，使用完整文件／网络权限，不追加应用通用开发者指令。每次调用 `--ephemeral` 新建会话并关闭记忆。完整权限下，历史文件的排除是任务指令边界，不是文件系统硬隔离。显式返修和评分保持原有执行隔离。

`input/input.json` 记录身份、步骤提示词、附件顺序及 skill 文件路径／大小／SHA-256；正文分文件保存。skill 使用已校验的本次副本，保留内部引用相对路径；数据库脱敏正文写入 `input/attachments/附件N.txt`。普通提示词按步骤原文、身份、skill 入口绝对路径、附件绝对路径及交付说明组织。未配置时默认“查看指定 skill，依据本次附件出题。”。自定义步骤提示词原样保留，不自动清洗历史要求，运行切换前仍须核对。

作者同一会话完成设计、检索、核算和自检，将完整 JSON 保存到本次 `output/result.json`，按 `input/delivery.json` 的确定性渲染命令生成完整 `output/题目.md`。JSON 是入库权威表示，Markdown不得手改，最后一次写文件必须重新运行渲染命令，表头按冻结的原附件显示名称保留；两份正文只允许换行差异；缺失、不一致、非法 JSON、越界附件或外部链接均不提交成功。末条聊天回复只存 `completion.txt`，不能冒充题包。输出及临时计算文件按题目／尝试存放在既有 `.storage/` 私有目录，不写共享项目根文件；不合格尝试保留历史，不自动进入成功案例库。

普通出题保存私有 `output/request.json`（实际 argv、stdin、cwd、模型、档位、配置目录、输入清单与指纹）和 `events.jsonl`，用于追溯实际调用，不记录凭证或整个进程环境。请求快照不列为输入，完整权限下不保证物理不可读。

出题输出 Schema 的 `attachment_ids` 枚举按本次脱敏材料 ID 动态生成，出题提示同时列出允许 ID；被测作答模型当前仅支持 text 输入、text 输出且不执行工具，输出 Schema 将 `answer_requirements` 限定为该能力，执行器仍在提交前校验。`validateDraft()` 仍校验缺失、重复及越界附件引用。附件校验失败时，尝试记录保存安全错误码和明确原因，供步骤状态区展示，不保存模型原始响应作为错误详情。

内部 JSON 字段保持稳定；私有题包按表头、任务名称、任务类型、prompt、考点 rubric、作答思路、标准答案七章组织，公开题包排除后两章及内部附件记录 ID。公开表头只列附件名称，不输出本机绝对路径。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `executor.ts` | 独立出题调用：作者依据本地项目 skill 自检并生成完整题目包。 |
| `jobs.ts` | ordinal 4 的持久化队列：记录步骤设置、项目文件和数据库脱敏附件指纹，校验任务绑定，保存题目包并维护返修血缘。 |
| `private-draft.ts` | 返修私有草稿读取：限制工作区路径，恢复并校验当前尝试或旧目录格式的出题草稿。 |
| `validate.ts` | 出题产物契约：校验题面、附件、rubric 和标答的结构与完整性；旧质量报告校验不参与新工作流。 |

## 数据流与依赖

出题 jobs 记录步骤设置、当前 skill 文件清单、数据库脱敏附件指纹及普通出题契约标记 → executor.ts 作者调用、自检并生成私有草稿 → ordinal 4 成功并保存公开题目包。作答入口校验当前出题成功及题目、附件绑定。private-draft.ts 与 jobs.ts 的血缘逻辑读取返修草稿及答案继承来源。

## 维护边界

改题面或附件须重新作答；rubric-only 校验原输入一致性并记录 answer_source_attempt_ids。作者完整草稿（含标答与思路）保存在 steps.result 和 step_attempts.result 的 JSONB 中，返修优先读取数据库，历史缺少字段的任务兼容私有目录。模型作答输入不包含项目 skill、rubric、标答或评分提示词；独立评分只向模型提供步骤评分提示词、同版题面、rubric、数据库脱敏附件和匿名答案，不提供思路、标答或项目 skill。旧任务仍按各自输入清单校验；新任务不使用编号规则版本。真实卷宗出题质量与规则适用性尚需验收。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

项目规范输入仅含 skill/（包括 references、assets），不读取项目 materials/ 或 project.json；旧任务输入清单不匹配时重新派发。出题 Agent 可以使用本地工具读取指定输入、解析模板；无工具限制仅针对被测模型作答。作者按 skill 自检关键判断是否实际影响交付，结构成功不代表题目质量已经验收。普通重出不注入旧题或评分；显式返修的 `revision.evidence` 才携带经绑定校验的评测证据。skill明确引用的案例卡和模板可作为设计参考，案例事实与历史成绩不成为本题事实或目标。

出题说明允许使用实际可用的搜索／网页工具核对官方法律原文；普通出题的完整网络权限由执行选择提供，显式返修和评分仍遵守各自受限环境。工具不可用时不得声称已检索，公开规则不能补造案件事实。
