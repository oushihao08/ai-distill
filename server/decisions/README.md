# 达标判断

显式 `model_report_v1` 题目使用评分模型报告的 `evaluation_percent` 与同一门槛比较，不从原始加扣分重算。结果分别保留 raw_score、full_score、percentage 和独立否决意见；指标缺失时等待，否决不自动归零。完整 Rubric、业务字段及冻结政策参与绑定和发布依据摘要。下文“得分除以满分”的说明继续适用于默认 legacy 结果。

判定按项目策略读取百分制评分。未配置聚合时，普通项目继续要求每个必需模型严格低于各自阈值；项目可在数据库 `project_step_configs` 的 ordinal 7 配置聚合规则。模型数量、是否聚合及门槛来自项目当前配置；缺少策略要求的模型或有效评分时等待，不能用历史项目示例代替配置。模型身份仍由项目作答模型集合保存，不在达标配置中重复维护。普通工作流在本轮评分全部终结后自动保存判定结果；项目批量入口可对符合条件的待判定或失败题目再次执行相同程序判断，不调用模型。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `acceptance.ts` | 达标纯决策：保留通用逐模型门槛，并按已验证的 ordinal 7 项目配置计算均分。 |
| `config.ts` | 校验聚合策略及兼容的历史逐模型设置。 |
| `score-projection.ts` | 从已有评分结果或原文中的明确合计读取比较分数；兼容历史草稿说明与新契约汇总，不改写原报告或复评。 |
| `jobs.ts` | 达标事务服务：读取项目模型集合与 ordinal 7 策略、当前题目和评分，计算依据指纹并保存第七阶段决策；由普通评分完成后自动调用。 |

## 数据流与依赖

评分 jobs.ts 在普通工作流全部评分终结后调用 decisions/jobs.ts → acceptance.ts 判定。

达标结果同时保存本次评测中每个模型对应的答案尝试、评分尝试及题目／rubric 版本引用，不参与达标计算。判定前核对答案尝试、答案指纹、题面版本、rubric 版本及rubric摘要；不匹配的评分不参与通过判断。自动返修执行器和对应空表已移除。

## 维护边界

未配置 aggregation 的项目按必需模型逐一比较百分制得分与项目模型集合中的配置上限。均分策略要求模型数与 `model_count` 精确一致，并要求每个模型都提供有效评分；按未舍入数值计算均值，`mean_at_most` 使用小于或等于阈值。启用均分策略时，单模型状态标记“计入均分”，不单独判定通过／未通过；文档不固定任何项目的模型数量或阈值。历史报告校验标记不阻止已有明确分数参与比较；缺失分数或满分、满分不为正数或分数越界时等待。只有展示保留两位小数。判断attempt保存为succeeded表示程序已完成判断；步骤7遇到decision=waiting时仍为waiting，其余判断步骤为succeeded。业务结果必须看`result.decision`（accepted/repair/waiting/quarantine），不能只看步骤绿色。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

兼容字段 `minimum_score` / `minimum_score_by_model` 保留名称，当前值统一表示0—100的百分制上限。决策结果保留 `score`、`max_score` 并增加 `percentage`；不改历史原始评分。判定口径参与来源摘要，旧达标记录须重新执行判定后才能发布，不自动重算数据库历史。

项目模型集合或任一分数上限变化时，当前作答、评分、达标及归档状态失效；历史尝试保留，活动任务停止，需按新集合重新作答和评分。

## 当前性与记录边界

`readAcceptanceSnapshot()`按当前模型集合摘要选各模型最新答案，再选该答案的最新评分；`buildAcceptanceInput()`核对答案SHA及题面、Rubric、输入和答案attempt绑定，；legacy 原文按模型明确报告的总分或合计读取，旧逐项校验失败不再阻断，原始评分记录保持不变。model_report 仍按其显式契约读取。新报告直接使用evaluation_percent，raw_score/full_score仅留存，独立否决不会在本模块自动归零或阻止低分达标。项目若要求否决影响通过，必须明确设计对应政策，不能从字段存在推断。

主项目/期次身份不改变此计算；模型身份和顺序来自本期模型集合。存在旧完整达标配置时，其required_models须与当前集合逐项一致；没有模型集合时只允许完整历史配置回退。判定不补跑缺失答案/评分。

每次执行创建新的步骤7尝试，刷新当前结果并清空步骤8当前归档状态、使Excel导出失效；不自动重新归档或上传。`evaluation_records`用于追溯各模型答案/评分attempt，来源摘要用于发布再核对；本模块本身不重新提取附件全文或再做专业评分。

`acceptance.test.ts`覆盖边界比较/均分/缺失/无效/否决分离；`config.test.ts`覆盖配置形状；`jobs.test.ts`用注入查询核对快照/绑定/摘要。以上不等于真实数据库及完整归档验收。

legacy 达标直接按模型明确报告的总分/满分与当前项目门槛比较，不增加Python检查、逐项合计/ID唯一性/整数分门槛或额外AI判断。历史报告在读取快照时应用同一口径；原始记录不改写。缺少明确总分与评分执行失败仍不得当作有效零分。


## 按模型分数直接判定

达标判断只比较当前题目/答案对应的模型分数与本期配置的门槛；不再要求历史validation.valid、逐项合计检查、ID唯一性、整数分检查或争议标记通过，不调用额外AI审查。旧文本明确写出的“逐项合计为X/Y”“汇总为X/Y”等分数也可采用，不要求固定为独立末行；没有分数、多个不同总分、越界数值仍不能推测。model_report_v1直接读取模型报告的evaluation_percent，条目校验标记不作为第二道达标门槛。

多模型继续使用本期必需模型集合：配置mean_at_most时所有必需模型齐备后按未舍入均分与上限（含等号）比较；未配置聚合时沿用各模型严格上限，所有必需模型通过才accepted。缺失模型或仍运行的评分等待；评分终态即使带旧校验失败标记，只要提供了当前来源绑定的明确合法分数，也可比较。题目/答案/材料版本绑定仍用于避免采用旧题或其他答案分数。未达标保存repair，既有就绪规则允许重新出题，不自动重跑模型。

源码修改须在实际执行节点加载后才能影响该节点后续自动判定；本机API重载不代表其他Windows worker已更新。
