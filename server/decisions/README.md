# 达标与返修

按项目“作答模型”集合和每个模型已登记的百分制分数上限判定：原始得分除以满分乘100，所有必需模型的得分率严格低于各自阈值时题目达标，任一达到或超过则需要返修。普通工作流在本轮评分全部终结后自动保存判定结果；项目批量入口可对符合条件的待判定或失败题目再次执行相同程序判断，不调用模型；返修链按其冻结配置由返修调度器判定。分数上限只在项目模型集合中设置；第七步配置只保存返修预算。模块另为显式启动的返修维护链、轮次、冻结预算与调用账本。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `acceptance.ts` | 达标纯决策：等待必需模型作答和评分完成，然后将原始分数换算成百分制后与对应上限比较。 |
| `config.ts` | 达标及返修预算配置校验：限制模型评分门槛和内容、技术重试、耗时、调用预算。 |
| `jobs.ts` | 达标事务服务：读取当前题目、模型答案和评分分数，计算依据指纹并保存第七阶段决策；由普通评分完成后自动调用。 |
| `material-revision.ts` | 材料返修入队：依据已绑定轮次的问题材料重建提取任务，保留健康缓存与当前附件绑定。 |
| `revision-binding.ts` | 返修上下文绑定：核验有效链与轮次，读取冻结设置并将阶段尝试绑定至当前轮次。 |
| `revision-calls.ts` | 返修调用预算账本：预留外部调用与剩余时长，记录使用情况并恢复终态任务的不确定调用。 |
| `revision-jobs.ts` | 返修链入口：基于阶段尝试启动或恢复链，冻结步骤配置与模型集合。 |
| `revision-runner.ts` | 返修轮询推进：按持久化轮次接续提取、脱敏、出题、作答、评分和达标，维护停止状态。 |
| `revision-source.ts` | 返修问题归类：从材料、出题、rubric 或服务问题提取依据，并冻结有限预算。 |
| `revision.ts` | 返修纯策略：按问题类型和有限预算决定技术重试、等待、内容返修或隔离及返回阶段。 |

## 数据流与依赖

评分 jobs.ts 在普通工作流全部评分终结后调用 decisions/jobs.ts → acceptance.ts 判定；revision-source.ts 分类证据 → revision.ts 选择策略 → revision-jobs.ts 创建／恢复链 → revision-runner.ts 接续材料、脱敏、出题、作答、评分与判定。binding 和 calls 文件核验轮次与外部调用预算。

达标结果同时保存本次评测中每个模型对应的答案尝试、评分尝试及题目／rubric 版本引用，不参与达标计算。判定前核对答案尝试、答案指纹、题面版本、rubric 版本及rubric摘要；不匹配的评分不参与通过判断。启动 ordinal 7 未达标返修时，冻结最近最多三条未达标评测轮次；每轮保留全部模型（包括已通过模型）的结果引用，后续出题队列按绑定 ID 和指纹读取答案及评分原文。旧评测没有引用快照时只显示已保存摘要，不推断答案与分数的对应关系。

## 维护边界

达标按必需模型逐一比较百分制得分与项目模型集合中的配置上限，不做模型间平均；界面同时展示每个模型通过、未通过、待评分或评分无效，全部模型均通过才显示整体达标。评分报告无效时显示无效，评分任务执行失败则等待有效评分；缺失分数或满分、满分不为正数或分数越界时等待。判定使用未舍入值，只有展示保留两位小数。所有模型均严格低于上限才达标，等于或超过需要返修，不为压低分数修改评分尺度。第七步判定成功表示“判定已完成”，业务结果通过 `result.decision` 区分达标与返修。技术重试与内容返修分开计数，不确定调用保留预留。材料返修仅依照可核验的材料页证据。该接续已在 worker 挂接；真实业务自动返修与恢复验收仍是独立缺口。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

返修快照保存脱敏的 API/Agent 选择及具体模型配置，调用预算沿用同一账本。缺失的 API 配置不会在旧链后续执行时改用新的环境默认值；脱敏设置变更会使旧活动链失效。

兼容字段 `minimum_score` / `minimum_score_by_model` 保留名称，当前值统一表示0—100的百分制上限。决策结果保留 `score`、`max_score` 并增加 `percentage`；不改历史原始评分。判定口径参与来源摘要，旧达标记录须重新执行判定后才能发布，不自动重算数据库历史。

项目模型集合或任一分数上限变化时，当前作答、评分、达标及归档状态失效；历史尝试保留，活动任务停止，需按新集合重新作答和评分。
