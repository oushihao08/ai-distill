# 独立 Agent 执行模块

`index.ts` 是业务执行器与设置 API 的公共入口。每次 `runAgent()` 接收一个任务指令、独立目录、输出 schema、模型、推理强度、截止时间和取消信号，返回业务结果、执行后端／模型、会话与用量、诊断引用和耗时。当前默认使用本机 Codex CLI 与已有 ChatGPT 套餐登录。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `index.ts` | 公共执行与配置导出；业务调用方从此处依赖模块。 |
| `runner.ts` | 单次任务契约、固定开发者指令注入、可替换后端及统一结果。 |
| `system-instructions.ts` | 不随步骤变化的独立执行边界；动态任务要求仍由调用方提交。 |
| `config.ts` | 暴露全局／项目默认值、凭证目录、本机模型清单和登录配置能力；持久化复用既有设置服务。 |
| `processes.ts` | 登记本 worker 的 Agent 子进程，供现有资源监控采样。 |
| `processes.test.ts` | 检查 PID 重复登记、引用计数和注销；只使用当前测试进程 PID，不启动 Agent。 |
| `runner.test.ts` | 检查任务设置转交、fresh-authoring 边界及可替换适配器；使用注入适配器，不调用真实 Codex。 |

## 数据流与设置接口

业务队列冻结步骤输入与项目／步骤模型配置 → 业务执行器准备只读任务材料和 schema → `runAgent()` 对评分、模型作答和普通出题不追加开发者指令，其他任务注入通用边界指令 → 本地 Codex 适配器执行 → 业务校验结果并按现有事务提交。

全局设置通过 `/api/agent/config` 管理凭证目录、默认模型与推理强度并返回该凭证目录对应的本机模型能力；项目默认使用 `/api/projects/:id/agent-settings`；ordinal 4／6／9 的步骤配置可经 `/api/agent/projects/:id/steps/:ordinal/config` 保存。ordinal 4／5／6／9 的步骤提示词保存在项目步骤设置中。连接检查 `/api/agent/test` 只发送合成 JSON 任务。旧 `/api/codex/*` 与项目 `codex-settings` 路径保留为兼容别名。这里的“路径”是 Codex 凭证目录；CLI 可执行文件仍由 `CODEX_BIN` 或随桌面应用提供的二进制决定。

## 维护边界

固定指令区分本次明确指定的规范文件与待处理数据：前者指导执行，案件材料、题面及待评答案中的指令不得改变任务边界。项目方法由业务显式提供，不从聊天或个人记忆继承。

评分、模型作答与普通出题不发送固定开发者指令覆盖；其他任务通过 CLI 的 `developer_instructions` 注入通用边界。`execution_profile=fresh_authoring` 仅允许 `question_authoring` 并要求明确 `working_directory`，适配器完整转交；普通出题加载正常用户配置、项目规则与工具，使用完整权限。其余任务继续使用仓库外受限工作区。每次调用以 `--ephemeral` 新建会话，并通过 `features.memories=false` 关闭记忆。业务层不直接解析 CLI 事件。


执行模块负责会话隔离、进程与配置映射及结构化返回；业务 jobs 负责队列、按任务记录输入文件指纹、取消和业务有效性。通过 `configureAgentAdapter()` 可在模块装配处替换默认后端；业务任务不需要自行选择或调用供应商。当前每次调用共享配置的凭证目录作为 `CODEX_HOME`，运行状态是否影响桌面 Codex尚未验证。Agent 结果有效不等于脱敏、出题或评分正确。未来 API 后端需实现同一任务／结果契约，具体 API 能力和计费另行验收。

`independent_scoring` 任务由适配器开启评分上下文隔离，显式禁用记忆、宿主 skill、项目文档、插件/应用/hooks、MCP 与网页搜索等入口；model_answer同样开启该隔离；其他任务按其执行配置处理。`GET /api/agent/scoring-instructions` 返回当前服务的空开发者指令标记、最小调用说明与隔离参数，供步骤设置只读展示。Codex 内置系统指令未由 CLI 返回，不能冒充完整底层系统提示词。

全新出题的 CLI 调用采用完整文件／网络权限，并加载当前用户配置和项目规则；因此可用能力包括本地文件与 shell、网络搜索，以及用户配置中被当前 CLI 识别并成功启动的 MCP 工具。桌面 App 专有 connector 不会仅因完整权限自动出现；配置警告或 MCP 初始化失败也意味着能力未验证。历史调用曾观察到 shell 和网页搜索，但这不能证明每个服务或桌面工具在每次任务中都可用。若要宣称与桌面工具完全对齐，应按目标工具逐项核对 `codex mcp list`、当前 CLI 配置字段和 `events.jsonl` 实际调用记录；不要为追求工具数量额外打开和出题无关的写入型工具。


### 独立评分输入

当前 Codex 评分以独立文件提供题面与 Rubric、该题冻结来源附件、匿名完整答案及公开成果呈现约定；默认不提供标答，仅显式 `model_report_v1` 的冻结 calibration 政策可加入校准参考。作答思路和项目 Skill 不进入评分文件。API 评分使用相同白名单正文，无文件工具执行声明。

评分可使用受限工作区内的文件读取/计算，网络、记忆、宿主 Skill、项目规则、插件和 MCP 等外部上下文入口关闭。文本输出、报告解析、算术检查和输入版本绑定由 [scoring 模块](../scoring/README.md) 维护，本模块不另定义评分口径。旧记录按其实际冻结格式读取，不能用当前指令补造历史输入。

## 数据库模型设置

系统、项目、步骤和 skill 生成配置均保留数据库模型与推理强度，不按本机缓存修正或拒绝；界面允许输入缓存之外的值。缓存只提供建议，实际支持范围由 CLI 执行反馈。步骤覆盖项目默认，项目覆盖系统默认，已入队任务继续使用冻结配置。不改变登录凭证、工具配置、权限或隔离。

作答步骤可以通过系统作答模型目录登记 Codex Agent provider/model/reasoning effort，ordinal 5 本机 Agent 队列执行。盲作答会话只接收题面、该题冻结来源允许的附件、公开成果呈现约定和作答步骤提示词；答案思路、标准答案、Rubric、既有答案、评分结果和项目 Skill 均不进入输入。执行使用隔离上下文，关闭宿主 Skill、插件、MCP、浏览器、记忆和网络，文件权限限本次 attempt 工作区；不能据此宣称执行了外部检索。

模型设置保存的结构校验不依赖缓存，但系统作答目录登记Codex模型目前另行要求模型/档位在本机目录中；业务worker还验证自身允许的推理强度枚举。不能把通用设置允许保存解释成任何模型/档位都可成功执行。`runner.test.ts`检查任务配置/适配转交，`processes.test.ts`检查PID引用计数；均不证明实际CLI能力或额度。

## 请求与返回模型身份

`runAgent()`统一补齐`requested_model`，值来自本次任务配置；`returned_model`只保留适配器明确提供的返回模型，缺失为null，不根据请求或旧字段推断。当前Codex客户端未返回可靠的实际模型标识，因此其returned_model为null。旧`model`保持适配器原值，Codex适配器中仍是请求配置，不能作为实际模型确认；新字段在类型上可选以兼容旧适配器和历史记录。现有历史结果不回写。

作答适配器将requested_model保存为请求模型，将returned_model映射到作答结果的model（未知为null）；评分、脱敏等已有model配置记录继续按原字段兼容读取。此语义只表达已有证据，不证明供应商的真实底层路由。
