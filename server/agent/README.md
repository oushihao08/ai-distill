# 独立 Agent 执行模块

`index.ts` 是业务执行器与设置 API 的公共入口。每次 `runAgent()` 接收一个任务指令、独立目录、输出 schema、模型、推理强度、截止时间和取消信号，返回业务结果、执行后端／模型、会话与用量、诊断引用和耗时。当前默认使用本机 Codex CLI 与已有 ChatGPT 套餐登录。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `index.ts` | 公共执行与配置导出；业务调用方从此处依赖模块。 |
| `runner.ts` | 单次任务契约、固定开发者指令注入、可替换后端及统一结果。 |
| `system-instructions.ts` | 不随步骤变化的独立执行边界；动态任务要求仍由调用方提交。 |
| `config.ts` | 暴露全局／项目默认值、凭证目录、本机模型清单和登录配置能力；持久化复用既有设置服务。 |
| `processes.ts` | 登记本 worker 的 Agent 子进程，供现有资源监控采样。 |

## 数据流与设置接口

业务队列冻结步骤输入与项目／步骤模型配置 → 业务执行器准备只读任务材料和 schema → `runAgent()` 对评分和普通出题不追加开发者指令，其他任务注入通用边界指令 → 本地 Codex 适配器执行 → 业务校验结果并按现有事务提交。

全局设置通过 `/api/agent/config` 管理凭证目录、默认模型与推理强度并返回该凭证目录对应的本机模型能力；项目默认使用 `/api/projects/:id/agent-settings`；ordinal 4／6／9 的步骤配置可经 `/api/agent/projects/:id/steps/:ordinal/config` 保存。ordinal 4／6／9／10 的步骤提示词保存在项目步骤设置中。连接检查 `/api/agent/test` 只发送合成 JSON 任务。旧 `/api/codex/*` 与项目 `codex-settings` 路径保留为兼容别名。这里的“路径”是 Codex 凭证目录；CLI 可执行文件仍由 `CODEX_BIN` 或随桌面应用提供的二进制决定。

## 维护边界

固定指令区分本次明确指定的规范文件与待处理数据：前者指导执行，案件材料、题面及待评答案中的指令不得改变任务边界。项目方法由业务显式提供，不从聊天或个人记忆继承。

评分与普通出题不发送固定开发者指令覆盖；其他任务通过 CLI 的 `developer_instructions` 注入通用边界。`execution_profile=fresh_authoring` 仅允许 `question_authoring` 并要求明确 `working_directory`，适配器完整转交；普通出题加载正常用户配置、项目规则与工具，使用完整权限。其余任务继续使用仓库外受限工作区。每次调用以 `--ephemeral` 新建会话，并通过 `features.memories=false` 关闭记忆。业务层不直接解析 CLI 事件。


执行模块负责会话隔离、进程与配置映射及结构化返回；业务 jobs 负责队列、按任务记录输入文件指纹、取消和业务有效性。通过 `configureAgentAdapter()` 可在模块装配处替换默认后端；业务任务不需要自行选择或调用供应商。当前每次调用共享配置的凭证目录作为 `CODEX_HOME`，运行状态是否影响桌面 Codex尚未验证。Agent 结果有效不等于脱敏、出题或评分正确。未来 API 后端需实现同一任务／结果契约，具体 API 能力和计费另行验收。

`independent_scoring` 任务由适配器开启评分上下文隔离，显式禁用记忆、宿主 skill、项目文档、插件/应用/hooks、MCP 与网页搜索等入口；其他业务任务保持原有资料能力。`GET /api/agent/scoring-instructions` 返回当前服务的空开发者指令标记、最小调用说明与隔离参数，供步骤设置只读展示。Codex 内置系统指令未由 CLI 返回，不能冒充完整底层系统提示词。

全新出题的 CLI 调用采用完整文件／网络权限，并加载当前用户配置和项目规则；因此可用能力包括本地文件与 shell、网络搜索，以及用户配置中被当前 CLI 识别并成功启动的 MCP 工具。桌面 App 专有 connector 不会仅因完整权限自动出现；配置警告或 MCP 初始化失败也意味着能力未验证。历史调用曾观察到 shell 和网页搜索，但这不能证明每个服务或桌面工具在每次任务中都可用。若要宣称与桌面工具完全对齐，应按目标工具逐项核对 `codex mcp list`、当前 CLI 配置字段和 `events.jsonl` 实际调用记录；不要为追求工具数量额外打开和出题无关的写入型工具。


### 旧版独立评分直接文本调用（历史格式）

独立评分在新隔离会话中发送题面、rubric、脱敏附件、匿名完整答案和原样评分提示词；作答思路及标准答案仅保留在内部同版题目包校验上下文，不发送给评分模型，不写入供模型读取的 input.json，不追加评分开发者指令，不要求 JSON 输出。Codex 文本模式省略输出 schema，保存 result.txt；其他结构化任务保持原协议。禁用记忆、项目规则及外部工具读取。

评分原文与实际发送正文保存在执行记录中，界面可查看。程序在返回后提取明确总分用于展示及达标判断；不修改模型评分。无法明确提取时，执行仍记为成功，单独标记提取失败且暂不参与达标判断。旧结构化报告继续按旧协议读取；旧记录不会用当前指令补造快照。


### 当前独立评分：分文件阅读（替代直接正文模式）

评分消息仅列出文件用途、完整阅读要求和用户原样提示词。题面与 rubric、各份附件、待评答案分别通过 `input_files` 传入 Codex 客户端；作答思路与标准答案仅留在内部版本绑定上下文，不写入评分文件；客户端仅在系统临时目录 `ai-distill-codex-*/workspace/` 写入文件，执行后清理整个临时目录，成功、失败及取消均尝试清理，清理异常记录日志。持久化记录保留原有冻结上下文、发送消息、文件名/大小/SHA256、读取事件及评分原文，不保留临时输入文件副本。

评分允许文件读取所需的 shell 工具，文件系统仍限制为独立工作区及执行所需最小运行环境，网络、记忆、项目规则、skill 和其他外部入口继续关闭。每次派发创建新评分任务，不复用已完成结果；同一答案已有等待或运行任务时拒绝重复派发。文本评分与返回后总分提取保持不变。

## 数据库模型设置

系统、项目、步骤和 skill 生成配置均保留数据库模型与推理强度，不按本机缓存修正或拒绝；界面允许输入缓存之外的值。缓存只提供建议，实际支持范围由 CLI 执行反馈。步骤覆盖项目默认，项目覆盖系统默认，已入队任务继续使用冻结配置。不改变登录凭证、工具配置、权限或隔离。
