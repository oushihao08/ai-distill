# 达标题目归档

复核当前项目模型集合、达标来源和文件指纹，执行主项目的逐题交付脚本，再在数据库记录归档状态与版本摘要。归档后题目从“题目记录”移出，仍保留在“达标题目”中查看。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `jobs.ts` | 归档事务：重新验证当前达标依据与产物指纹；Work 项目释放数据库事务后，在 Agent 并发槽位中生成模拟专家成果，再重开事务复核版本、执行项目交付脚本并更新状态。 |
| `project-delivery.ts` | 优先解析 `projects/<主项目>/scripts/delivery.ts`，兼容旧根目录 `delivery.ts`；把已校验题目快照与系统管理的持久输出目录送入独立进程；无脚本时执行内置空函数。 |
| `work-simulation.ts` | 使用项目 Agent 模型配置、交付规则和脱敏附件生成 AI 模拟成果；校验本次网页搜索词与打开 URL 的事件证据并缓存结果。 |

## 数据流与依赖

 jobs.ts 读取当前题目／答案／评分／达标快照 → 校验来源摘要及文件 → 对 Work 暂停数据库事务并在 Agent 并发槽位中生成模拟专家成果及检索证据 → 重开事务复核达标版本 → 调用项目交付入口 → 记录 ordinal 8 归档状态及脚本摘要。Work 发布请求还须从归档页面传入外部 `task_id` 与 `org`；服务端只保存其摘要用于归档去重，不把它们写回题目或普通日志。项目脚本失败时不提交归档状态。HTTP 步骤入口随后自动调用脱敏 DOCX 导出和单题归档 Excel 生成，并把成果路径随归档响应返回；失败时重复归档可重试导出。reporting 模块也保留项目级完整 Excel 导出。

## 维护边界

系统归档标记不改变题目内容；项目脚本可执行该项目自己的交付操作。附件、题面、rubric 或达标依据改变后必须重新检查当前版本。归档成功后 HTTP 步骤入口为所有项目自动导出当前脱敏附件 DOCX，并将单题 Excel 写入 `assets/out/附件库/<项目>/<期数>/<题目>/成果/`。项目级完整 Excel 仍由 reporting 模块单独导出到系统存储目录。DOCX 或单题 Excel 导出失败不撤销已提交的归档事务，接口返回错误；重复归档可重试。单题 Excel 只包含通用题目和评分数据，不构成 Work 专用专家交付物或法规检索轨迹。

项目脚本是主项目级可选覆盖，统一入口名为 `scripts/delivery.ts`，放在 `projects/<主项目>/scripts/`；Harbor、Siriser 等专项工具继续按 `scripts/<用途>/` 分组，不放入 `questions/`、`materials/` 或 `skill/`。服务端优先读取该规范路径，并暂时兼容旧根目录 `delivery.ts`。部署包须带上对应项目的 `scripts/`；项目名称和入口文件名必须与数据库主项目名一致。脚本从标准输入读取版本为 1 的 JSON，包含项目／题目 ID、标题、达标来源摘要、题目／rubric 版本和当前题目的私有题包字段、达标结果及脱敏附件身份／指纹。有项目脚本时，`AI_DISTILL_DELIVERY_PARENT_DIR` 指向 `assets/out/附件库/<主项目>/<期数>/<题目>/成果`，与脱敏 DOCX 同一目录；没有期数时仍用项目名和题目名，不另造期数。Work 专用模拟生成配置使用项目 Agent 模型和当前并发槽位；发布 HTTP 请求会等待模型生成，单次执行上限 15 分钟，尚未迁入持久化发布队列。无脚本时不创建该目录。项目 delivery 子进程最多等待 60 秒，不向其传数据库凭证；脚本是受信任项目代码，不是操作系统沙箱。脚本须以来源摘要保证重复执行安全，不调用重新出题、作答或评分。脚本缺失时执行内置空函数，仍完成交付步骤。脚本摘要随归档尝试保存，脚本内容更新后再次点击会建立新尝试；内容相同时重复点击会再次执行并复用归档记录。脚本可能产生的外部副作用不能随数据库事务自动回滚，项目脚本须自行采用确定性路径和幂等写入。

归档验证题目 attempt 中冻结的项目 skill 路径、文件清单和内容指纹彼此一致；不要求历史题目继续匹配后来编辑的当前 skill。这样保留题目实际出题时的规则来源，同时仍拒绝缺失或内部不一致的历史快照；当前答案、评分、达标依据和文件指纹照常复核。

项目 skill 绑定经 API 改变时，已完成的归档与历史 attempts 保留，项目 Excel 导出标记为过期以便使用当前项目元数据重新生成。项目文件编辑 API 只允许编辑 `materials/`，不提供 skill 文件编辑入口。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

题目等产物有数据库 `content` 时，查询须同时读取正文并校验其SHA256；没有正文的历史产物继续校验本地文件。数据库正文是现有存储来源，不要求额外生成本地副本，也不放宽指纹校验。

新契约归档继续校验同版题目、完整规则摘要、答案及模型报告指标绑定；负原始分和独立否决不在发布阶段重新解释。传给项目 delivery.ts 的私有题目快照额外保留 scoring_policy，旧格式没有该字段时维持原形状。

Work 的 work_legal_v1 新内容由 work-simulation.ts 直接投影作者冻结的逐份成果和检索记录，origin以model=author_snapshot标识；不另读模型配置或调用Agent、不补写标准答案。actual_search_queries/actually_opened_urls为空，避免把作者声明冒充归档新检索事件。旧题仍使用原模拟生成路径；新结构随 DeliveryInput 送入项目脚本。外部 task_id/org 由归档页录入并按 Harbor 格式校验；变更身份会产生新的归档键，不覆盖另一编号下的包。尚未取得平台编号时，归档会明确阻断，不猜造；这类输出仍是内部准备包，不代表外部验收。

未采用的真实查询可以保留空关联和未核验说明，转换轨迹时没有URL就明确显示未取得正文，不生成空链接；实际用于成果或判据的来源未核验仍拒绝转换。这不替代逐处引用关联的专业核对。

## Siriser初次提交适配（2026-10-16，覆盖上文Harbor必填口径）

Work归档不再强制Harbor task_id/org；该可选参数提供时仍校验格式。项目脚本先生成独立Siriser确认稿JSON五件套及ZIP，Harbor另记generated/pending，不能连带阻断五件套。新契约只投影作者冻结成果，generated_at明确未随作者投影提供，不把每次归档时间冒充新生成时间，保证同一输入重复归档稳定。

`readSiriserArchive`与`GET /api/workflows/:id/siriser-zip`只下载当前有效归档包：复核实时达标来源、冻结Skill、题面／Rubric版本、生成脚本摘要绑定、路径和ZIP摘要。题面更新或文件改变须重新归档。该下载不上传平台，不代表外部验收。Harbor转换接口未能承载的判据保留原样并标待处理。

每次新归档把项目、题目、材料来源（材料包/版本/脱敏结果）、来源原件摘要和题目脱敏附件摘要冻结到归档尝试及 `workflow_publication_events`。题目页展示归档/撤回历史；`POST /api/workflows/:id/withdraw-archive` 只撤回当前 ordinal 8 状态，不删除尝试、事件或交付文件。再次归档重新验证当前达标输入并记录新的 `archived` 事件。材料库包的跨项目加载与归档引用由 `/api/material-library/packages/:id/usage` 查询。

Work归档的附件载荷可含documents（脱敏结构），复用readCurrentRedactionForDocx校验当前索引、来源摘要和结构正文投影后传入项目脚本；不得把原始MinerU未脱敏结构传出。Siriser input_files输出DOCX，历史无结构输入保留Markdown兼容路径。此改动不改变候选作答附件、题面或评分输入。

本地API尚未重载时，独立delivery脚本可通过127.0.0.1:3700的现有只读workflow/artifact接口补齐同attempt脱敏索引；校验工作流、正文SHA、结构SHA和正文投影后使用，不直连数据库、不获取原件、不改变归档资格。读取失败或结构部分缺失即停止归档；新API已传结构时不再查询。
