# 达标题目归档

复核当前项目模型集合、达标来源和文件指纹，执行主项目的逐题交付脚本，再在数据库记录归档状态与版本摘要。归档后题目从“题目记录”移出，仍保留在“达标题目”中查看。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `jobs.ts` | 归档事务：重新验证当前达标依据与产物指纹，执行项目交付脚本后更新步骤和尝试记录。 |
| `project-delivery.ts` | 解析 `projects/<主项目>/delivery.ts`，把已校验题目快照与系统管理的持久输出目录送入独立进程；无脚本时执行内置空函数。 |

## 数据流与依赖

jobs.ts 读取当前题目／答案／评分／达标快照 → 校验来源摘要及文件 → 调用项目交付入口 → 在事务内记录 ordinal 8 归档状态及脚本摘要。reporting 模块导出项目内全部当前有效的达标题目。

## 维护边界

系统归档标记不改变题目内容；项目脚本可执行该项目自己的交付操作。附件、题面、rubric 或达标依据改变后必须重新检查当前版本。系统归档本身不生成发布文件，Excel 由 reporting 模块统一写入系统管理的存储目录并通过下载接口提供给浏览器。

项目脚本是主项目级可选覆盖，固定名为 `delivery.ts`，位于 `projects/<主项目>/` 根目录，不放入 `questions/`、`materials/` 或 `skill/`。Docker 发布只打包该入口文件，不打包项目资料；项目名称和入口文件名必须与数据库主项目名一致。脚本从标准输入读取版本为 1 的 JSON，包含项目／题目 ID、标题、达标来源摘要、题目／rubric 版本和当前题目的私有题包字段、达标结果和脱敏附件身份／指纹；`AI_DISTILL_DELIVERY_PARENT_DIR` 指向本题位于系统 `STORAGE_DIR/deliveries/` 下的持久父目录。成功时退出码为 0，失败时退出非零。服务端最多等待 60 秒，不向子进程传数据库凭证；脚本是受信任项目代码，不是操作系统沙箱，不得接收不可信脚本。脚本须以来源摘要保证重复执行安全，不调用重新出题、作答或评分。脚本缺失时执行内置空函数，仍完成交付步骤。脚本摘要随归档尝试保存，脚本内容更新后再次点击会建立新尝试；内容相同时重复点击会再次执行并复用归档记录。脚本可能产生的外部副作用不能随数据库事务自动回滚，项目脚本须自行采用确定性路径和幂等写入。

归档验证题目 attempt 中冻结的项目 skill 路径、文件清单和内容指纹彼此一致；不要求历史题目继续匹配后来编辑的当前 skill。这样保留题目实际出题时的规则来源，同时仍拒绝缺失或内部不一致的历史快照；当前答案、评分、达标依据和文件指纹照常复核。

项目 skill 绑定经 API 改变时，已完成的归档与历史 attempts 保留，项目 Excel 导出标记为过期以便使用当前项目元数据重新生成。项目文件编辑 API 只允许编辑 `materials/`，不提供 skill 文件编辑入口。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

题目等产物有数据库 `content` 时，查询须同时读取正文并校验其SHA256；没有正文的历史产物继续校验本地文件。数据库正文是现有存储来源，不要求额外生成本地副本，也不放宽指纹校验。

新契约归档继续校验同版题目、完整规则摘要、答案及模型报告指标绑定；负原始分和独立否决不在发布阶段重新解释。传给项目 delivery.ts 的私有题目快照额外保留 scoring_policy，旧格式没有该字段时维持原形状。
