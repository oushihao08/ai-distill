# Codex 执行与设置

本目录实现本机 Codex CLI 适配和底层模型／凭证设置存储。业务执行统一经[独立 Agent 模块](../agent/README.md)进入，不直接调用 `runCodex()`。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `client.ts` | Agent 本地适配器使用的低层 CLI 客户端：校验套餐登录、映射开发者指令、按普通出题／隔离任务选择工作目录和权限，保存独立产物、处理进程时限和结构化结果。 |
| `models.ts` | 本机 Codex 模型目录：读取缓存公开的模型和推理档位，作为界面输入建议；保存与派发仅校验字段结构。 |
| `system-config.ts` | Codex 设置服务：管理系统与项目默认值、步骤覆盖合并，以及经路径校验的凭证目录；按数据库原值读取模型和推理强度，不自动替换。 |
| `client.test.ts` | 用假 CLI 子进程和临时目录核对参数、会话、隔离、超时、取消、错误日志及结果文件安全边界；不调用真实 Codex。 |
| `system-config.test.ts` | 用临时模型缓存和替身查询核对模型建议、结构校验、系统/项目继承与设置保存；不连接真实数据库。 |

## 数据流与依赖

system-config.ts 解析步骤覆盖 → 项目默认 → 系统默认；models.ts 读取本机目录并校验档位；client.ts 检查登录；普通出题在已冻结的项目 cwd 执行并直接读取本次私有输出，其他任务仍复制到仓库外系统临时目录、启动受限子进程并回存产物；同时解析结构化结果／事件，区分缺失结果／非法 JSON／未完成轮次／业务校验原因，并处理超时取消。

## 维护边界

不向执行子进程传播数据库或供应商密钥；不把登录有效当成额度与业务完成证明。每个职责使用自己的输入、输出与会话。模型目录属于本机当前状态，不把历史缓存当官方永恒能力。配置更新、数据库应用、服务重启和真实调用分别核对。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

Windows 默认从 PATH 启动 `codex.exe`，避免 npm 命令脚本的子进程参数兼容问题；显式 `CODEX_BIN` 仍优先。子进程仅额外继承系统目录、用户目录、临时目录和命令解析所需的 Windows 环境变量，不传数据库或供应商密钥。受限任务在 Windows 显式选择 MXC 沙箱，以支持 `:root=deny` 的读取隔离；为宿主 Bun 与 PATH 中的 PowerShell、Node 运行时目录补充只读权限，材料与输出仍使用原隔离范围，不回退到全盘可读或无沙箱。机器不支持 MXC 时执行失败，须使用支持同等隔离的执行环境。普通出题的完整访问配置不受此选择影响。跨机器共用设置可将凭证目录留空，让各机器使用自己的默认登录目录；不复制凭证。

每次 Codex CLI 调用都通过 `features.memories=false` 关闭记忆；`--ephemeral` 另用于不持久化 CLI 会话。独立评分还通过 `isolate_context` 关闭宿主资料发现等其他外部上下文入口，并保留既有目录权限与网络限制。评分的实际 CLI 参数、stdin、开发者指令和输出 schema 保存到源私有输出目录的 `request.json`，不复制给模型，不记录环境变量或凭证。



### 普通出题：项目环境与文件交付

仅 `execution_profile=fresh_authoring` 采用项目 cwd，加载用户配置与项目规则，使用 CLI 的完整访问参数；不传 ignore-user-config、ignore-rules、受限网络、输出 schema 或应用开发者指令覆盖。模型与档位仍由上层冻结，不硬编码覆盖所有项目。每次新会话，关闭记忆；不透传数据库／供应商密钥。

维护普通出题时，以桌面端手动出题的可用能力为基线。调整调用参数、配置目录、环境传递或结果交付前，先核对是否会使作者失去文件读写、shell／计算、网络检索或已配置 MCP；功能边界应通过输入绑定与结果校验表达，不能用关闭作者工具代替。当前完整访问只证明 CLI 未被本客户端限制，不能证明每项桌面工具已初始化；需结合当前 `client.ts`、配置来源、启动诊断、调用参数和私有执行事件核对。历史计划不作为现行能力依据。

cwd 与 `directory/output` 分离，清理只处理本次临时资源，不删除项目目录。结果从专用 `result.json` 读取，聊天末条保存为 `completion.txt`；清除旧结果，要求完整轮次、合法 JSON、普通文件、非外部链接和32 MiB大小上限。调用快照记录 argv、stdin、cwd、配置目录、模型、档位及输入索引，不记录凭证。完整权限下快照不是不可访问，只是不列为任务输入。Markdown一致性由出题执行器检查。其余任务尤其评分不继承这个执行选择。

### 独立评分输入

当前 Codex 评分以独立文件提供题面与 Rubric、该题冻结来源附件、匿名完整答案及公开成果呈现约定；默认不提供标答，仅显式 `model_report_v1` 的冻结 calibration 政策可加入校准参考。作答思路和项目 Skill 不进入评分文件。API 评分使用相同白名单正文，无文件工具执行声明。

评分可使用受限工作区内的文件读取/计算，网络、记忆、宿主 Skill、项目规则、插件和 MCP 等外部上下文入口关闭。文本输出、报告解析、算术检查和输入版本绑定由 [scoring 模块](../scoring/README.md) 维护，本模块不另定义评分口径。旧记录按其实际冻结格式读取，不能用当前指令补造历史输入。

## 数据库模型设置

系统、项目、步骤和 skill 生成配置均保留数据库模型与推理强度，不按本机缓存修正或拒绝；界面允许输入缓存之外的值。缓存只提供建议，实际支持范围由 CLI 执行反馈。步骤覆盖项目默认，项目覆盖系统默认，已入队任务继续使用冻结配置。不改变登录凭证、工具配置、权限或隔离。

`client.test.ts`与`system-config.test.ts`是本目录现存的两份测试；模型缓存读取和字段校验也由`system-config.test.ts`核对。它们不证明当前真实Codex二进制支持所有隔离参数。`model_answer`与`independent_scoring`共享`isolate_context`；普通受限任务按客户端参数禁用网络并限制目录权限；`project_delivery`额外启用`live`网页搜索，不等于任意网络或宿主工具开放。

stdout/stderr使用连续UTF8解码，跨Buffer字符保持完整；stdout事件仍按原背压串行写入，字节上限不变。
