# Codex 执行与设置

本目录实现本机 Codex CLI 适配和底层模型／凭证设置存储。业务执行统一经[独立 Agent 模块](../agent/README.md)进入，不直接调用 `runCodex()`。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `client.ts` | Agent 本地适配器使用的低层 CLI 客户端：校验套餐登录、映射开发者指令、按普通出题／隔离任务选择工作目录和权限，保存独立产物、处理进程时限和结构化结果。 |
| `models.ts` | 本机 Codex 模型目录：读取缓存公开的模型和推理档位，并校验所选设置；过滤掉不可选的 `gpt-6-astra`。 |
| `system-config.ts` | Codex 设置服务：管理系统与项目默认值、步骤覆盖合并，以及经路径校验的凭证目录；旧配置中的 `gpt-6-astra` 会按 `gpt-6-luna` 解析。 |

## 数据流与依赖

system-config.ts 解析步骤覆盖 → 项目默认 → 系统默认；models.ts 读取本机目录并校验档位；client.ts 检查登录；普通出题在已冻结的项目 cwd 执行并直接读取本次私有输出，其他任务仍复制到仓库外系统临时目录、启动受限子进程并回存产物；同时解析结构化结果／事件，区分缺失结果／非法 JSON／未完成轮次／业务校验原因，并处理超时取消。

## 维护边界

不向执行子进程传播数据库或供应商密钥；不把登录有效当成额度与业务完成证明。每个职责使用自己的输入、输出与会话。模型目录属于本机当前状态，不把历史缓存当官方永恒能力。配置更新、数据库应用、服务重启和真实调用分别核对。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

每次 Codex CLI 调用都通过 `features.memories=false` 关闭记忆；`--ephemeral` 另用于不持久化 CLI 会话。独立评分还通过 `isolate_context` 关闭宿主资料发现等其他外部上下文入口，并保留既有目录权限与网络限制。评分的实际 CLI 参数、stdin、开发者指令和输出 schema 保存到源私有输出目录的 `request.json`，不复制给模型，不记录环境变量或凭证。



### 普通出题：项目环境与文件交付

仅 `execution_profile=fresh_authoring` 采用项目 cwd，加载用户配置与项目规则，使用 CLI 的完整访问参数；不传 ignore-user-config、ignore-rules、受限网络、输出 schema 或应用开发者指令覆盖。模型与档位仍由上层冻结，不硬编码覆盖所有项目。每次新会话，关闭记忆；不透传数据库／供应商密钥。

维护普通出题时，以桌面端手动出题的可用能力为基线。调整调用参数、配置目录、环境传递或结果交付前，先核对是否会使作者失去文件读写、shell／计算、网络检索或已配置 MCP；功能边界应通过输入绑定与结果校验表达，不能用关闭作者工具代替。当前完整访问只证明 CLI 未被本客户端限制，不能证明每项桌面工具已初始化；需结合配置来源、启动诊断和私有执行事件核对。待核对项见[能力对齐清单](../../docs/plans/2026-10-11-codex-manual-capability-alignment.md)。

2026-10-11 的独立只读探针以与普通出题相同的配置目录、环境白名单及 CLI 参数成功调用 CodeGraph MCP；另一次全新会话自行发现 AnySearch skill 并用其 CLI 完成公开词搜索。历史正式作者事件已确认 shell 和网页搜索实际调用。这些分别验证了具体工具路径，不代表所有桌面专有工具可用，也不保证每题会主动使用同一工具。

cwd 与 `directory/output` 分离，清理只处理本次临时资源，不删除项目目录。结果从专用 `result.json` 读取，聊天末条保存为 `completion.txt`；清除旧结果，要求完整轮次、合法 JSON、普通文件、非外部链接和32 MiB大小上限。调用快照记录 argv、stdin、cwd、配置目录、模型、档位及输入索引，不记录凭证。完整权限下快照不是不可访问，只是不列为任务输入。Markdown一致性由出题执行器检查。其余任务尤其评分不继承这个执行选择。

### 旧版独立评分直接文本调用（历史格式）

独立评分在新隔离会话中发送题面、rubric、脱敏附件、匿名完整答案和原样评分提示词；作答思路及标准答案仅保留在内部同版题目包校验上下文，不发送给评分模型，不写入供模型读取的 input.json，不追加评分开发者指令，不要求 JSON 输出。Codex 文本模式省略输出 schema，保存 result.txt；其他结构化任务保持原协议。禁用记忆、项目规则及外部工具读取。

评分原文与实际发送正文保存在执行记录中，界面可查看。程序在返回后提取明确总分用于展示及达标判断；不修改模型评分。无法明确提取时，执行仍记为成功，单独标记提取失败且暂不参与达标判断。旧结构化报告继续按旧协议读取；旧记录不会用当前指令补造快照。


### 当前独立评分：分文件阅读（替代直接正文模式）

评分消息仅列出文件用途、完整阅读要求和用户原样提示词。题面与 rubric、各份附件、待评答案分别通过 `input_files` 传入 Codex 客户端；作答思路与标准答案仅留在内部版本绑定上下文，不写入评分文件；客户端仅在系统临时目录 `ai-distill-codex-*/workspace/` 写入文件，执行后清理整个临时目录，成功、失败及取消均尝试清理，清理异常记录日志。持久化记录保留原有冻结上下文、发送消息、文件名/大小/SHA256、读取事件及评分原文，不保留临时输入文件副本。

评分允许文件读取所需的 shell 工具，文件系统仍限制为独立工作区及执行所需最小运行环境，网络、记忆、项目规则、skill 和其他外部入口继续关闭。每次派发创建新评分任务，不复用已完成结果；同一答案已有等待或运行任务时拒绝重复派发。文本评分与返回后总分提取保持不变。
