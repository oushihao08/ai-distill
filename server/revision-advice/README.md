# 手动返修建议

面向工作台、CLI和后端维护者。`jobs.ts`管理独立的建议任务，`jobs.test.ts`使用合成SQL/Agent替身验证输入与版本边界。实际持久化要求`050_manual_revision_advice.sql`；不存在该结构时读取返回`available:false`，原出题不因此要求迁移。新功能只支持local队列。

## 入口与数据流

- `GET /api/workflows/:id/revision-advice`返回最近20条建议任务，含状态、来源摘要、文本和当前版本有效标记；不代表所有历史已删除。
- `POST /api/workflows/:id/revision-advice`手动生成，冻结当前出题、作答、评分及未达标依据，沿用步骤4模型/强度；拒绝已达标、缺少当前输入或4—6已有活动尝试。相同依据的活动或成功任务复用。
- `runNextRevisionAdvice()`仅由本机Agent通道按明确ID消费，最多10分钟，不自动重试、不触发下一步骤。模型返回建议后在工作流锁内复核来源再提交。原题面、作答和分数不改变。
- 页面题目记录、出题记录和题目详情均可打开`RevisionAdvice.vue`查看。批量按钮按当前筛选结果逐题派发，跳过达标；容量不足或写入回执未知后停止后续派发并显示原因。

## 绑定与恢复

建议按当前题目版本和完整依据的规范JSON摘要绑定。下一出题派发仅取同版成功建议，冻结ID、来源摘要、文本和建议摘要并拼接到项目出题提示词；不会把历史题面、作答和评分全文再次注入作者。旧建议仍可查看，不能自动跟随新题。活动作者复用其已经冻结的建议，JSONB字段重排不改变输入摘要。

作者执行及保存仍核对材料、设计和Skill；对建议额外核对不可变记录及文本。重出使后续当前结果失效，保留历史尝试。建议不是降低评分标准的授权。Agent只读取本次私有依据，不读取其他题目或个人记忆；建议与独立评分的输入边界不同。

任务使用`advice`种类、`agent`通道，与现有出题/评分共用本机容量及槽位。返回值经本地外部调用检查点保存后可重交；未知调用进入待核实，禁止自动重放。私有依据在`<STORAGE_DIR>/<workflow_id>/<attempt_id>/revision-advice/`，不写入普通日志；工作流重置检查活动建议后删除相应记录及管理副本。其他机器只能看到业务记录及共享建议，不能接管本地队列。

源码、替身测试、隔离PG/HTTP、页面验收和真实模型质量分别报告；本说明不表示业务库已迁移或线上服务已加载新代码。

尚未完成、失败或来源已改变的建议不会被出题采用；需要使用建议时，先确认列表中的同版成功文本，再手动派发出题。建议与评分按model_id或answer_attempt_id关联匿名候选，不能按两份列表的行号配对。
