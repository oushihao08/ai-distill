# 项目 skill 候选生成

用主项目共享规则资料、项目默认 Skill 和期次登记信息生成候选，校验入口、引用和问题清单。分期候选采用为本期 Skill 覆盖；未建立本期 Skill 时出题回退主项目 Skill。非分期项目继续采用为项目当前 Skill。

## 文件职责

| 文件 | 说明 |
| --- | --- |
| `generate.ts` | 项目 skill 候选生成：复制固定资料和模板，应用受限文本修改并检查候选入口与引用。 |
| `jobs.ts` | 项目级 skill 队列：冻结生成来源和模型配置，保存候选结果并阻止过期来源发布。 |

## 数据流与依赖

jobs.ts 固定主项目共享规则资料、模板（分期以主项目 Skill 为模板）、期次 `project.json` 及模型配置 → generate.ts 在受限工作区调用 Codex并检查候选；server/rules.ts 将分期候选安全复制到 `<期次工作区>/skill/`，不更新同主项目其他期次的 `local_skill_path`。非分期项目保留原稳定目录采用行为。生成候选留在 `.storage/` 作为尝试历史。

## 维护边界

候选不覆盖当前 Skill；采用时先校验并暂存完整候选，再替换相应稳定目录中的内容，数据库提交失败时恢复旧目录。分期默认 Skill 仍由主项目路径提供；期次覆盖目录存在有效 `SKILL.md` 时出题与步骤钩子优先读取覆盖。内部资料完整性与正式资格不同；外部资格不确定必须保留问题，不能伪装已确认。生成成功和采用分别表述。与脱敏／出题／Codex作答和评分共享当前 Agent 并发池，由 worker 公平轮转领取，不在此模块固定并发数。

本模块的 `*.test.ts` 保留既有验证意图；存在测试文件不表示本次运行。执行与授权遵循 [项目规则](../../AGENTS.md)。

基础模板默认使用仓库 `templates/company-legal-task/`；`SKILL_BASE_TEMPLATE_DIR` 或显式 template 参数优先，相对地址按仓库根目录解析。已有任务继续读取冻结的 template_path 与 snapshot，不替换历史输入。

## 成功状态、指纹和恢复

生成attempt的`succeeded`表示执行产出了候选报告；仍须看`publishable`、`issues`及`unresolved[].blocking`，不能按绿色状态直接采用。只允许生成/替换md、txt、json，单文件30MiB、合计100MiB；未修改二进制模板随来源复制。模型返回的remove不能删除SKILL.md，必须显式生成新入口并修复内部引用。结构/引用检查不证明规则内容专业正确。

同来源和模型配置的waiting/running/succeeded尝试可以复用；其他活动生成阻止再次派发。worker对五分钟失联尝试记失败，不自动重跑；新attempt执行冻结快照，并在调用前与保存前重验当前来源摘要。列表最多100条，不代表更早尝试被删除。

分期模板从主项目`local_skill_path`取，不将已有本期覆盖反向当作共享模板；来源解析及采用的权威实现是`server/rule-files.ts`和`server/rules.ts`。采用不会重写历史题目冻结输入，也不把候选报告变成新规则编号体系。

`generate.test.ts`用替身Agent及临时文件验证输入/资产/路径/引用/未决和取消；`jobs.test.ts`用注入数据库验证冻结/去重/失效；`adopt.test.ts`覆盖稳定目录与本期覆盖、原件保留和拒绝不安全候选。均不证明真实Codex规则质量或生产数据库采用成功。
