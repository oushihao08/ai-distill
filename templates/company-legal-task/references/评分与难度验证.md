# 评分与难度验证

## 考点设计

本 skill 默认编写15—20条，每条0/1、等权，一条核对一个独立结果，正向通过标准加零分条件。可唯一确定的结果明确；半开放结果接受实质等价解法。不能只查最后否决结论，也不能靠格式项抬分；难点与考点对应。上游错误影响下游时，各条核对不同结果，并说明关系，避免重复处罚同一事项。

总分为通过条数／总条数 × 100；不使用权重、倒扣或整题一票否决。用户明确指定另一套评估规则时按本次规则执行，说明差异，不混算。

## 重点2：必要工作量与判断难度分别设计

对每个核心难点核对“材料依据 → 必要处理 → 决策影响 → 评分结果”。同一决定可串联证据采信、时间与状态、金额核算和交付物对数；是否采用由当前材料决定，不要求每题固定包含这些类型。

多份材料不一致时必须有裁决依据。精确金额和日期考点须有足够数据及明确规则；脱敏数据不考未提供的具体元数。新增模拟材料须标注，并重新核对既有依赖关系。每个新增难点同步匹配可核对考点，避免重复扣分。

工作量来自同一决定需要的原始资料读取、不同对象逐项处理、规则适用、计算、条件重算和交付核对。判断难度来自采信、口径、规则组合、例外、状态与真实瓶颈的恢复。两者分别核验：很多记录采用一条简单规则可能仍容易；一个复杂判断也可能很快完成。

先检查最顺手的做法能否直接得到正确结果，以及通用建议、逐份摘要、全部否决或全部待核能否绕过关键判断。能绕过时修正任务依赖及必要产物，不凭空增加限制。不得指定消息条数、重复打开文件、固定决策步数或强制子代理凑长度。

内部保留每个难点的“来源位置 → 正确判断及依据 → 常见错法 → 后续影响 → 对应考点”，用于求解和核对，不默认另存文件或披露到 prompt。计算或求解确需实际运行时才要求执行证据，并先确认任务环境支持；不为增加时长强行搭环境。

## 重点6：考点核对具体产物，标答解释判断依据

通过标准写成可在产物中定位的主体、范围、口径、状态、数值或动作；不用“考虑了”“识别了”代替结果。零分条件覆盖对应遗漏、错误结果及已观察到的常见错法，不只覆盖最极端的错误。

先确定本条究竟评最终结论还是评专业依据。若依据本身是要测的判断，正确结论但依据错误也不通过，并在标准中写清；不能评分时临时加上未要求的依据。只禁止某种错误的条目，未出现该错不等于已经满足另有规定的正向条件。

半开放结果按实质条件判分，不指定唯一措辞或标答路径；确定结果写明口径、单位和必要容差。将独立并列结果拆开，保留实际需要的基础能力覆盖，格式、结构、常识合计远小于一半；不能只挑难点人为低估实际完成情况。

连锁错误各条核对不同产物结果，标答解释传递关系。若两条仅重复核对同一句话、同一判断，合并或重新确定评估对象。新增难点在15—20条范围内调整覆盖，不无限新增条目。

检查四件事：不写该结果是否还能完成核心工作；只写半句是否被错误放过；结论对但错依据是否属于本条范围；上游错是否被同一要求重复处罚。发现漏洞改任务或条目，不将合理局部未知写成零分。

## 评分、版本和交付

用户要求评分时，先核对当前 prompt、实际发送给模型的全部附件、rubric 和完整待评作答是否为同一版本，再审每条 rubric 是否符合这些输入。评分者不看标答、预期分数或其他模型成绩；满足正向要求且不触发零分条件计1。记录作答原文、反证或未找到，不能只记总结性转述；争议先说明。人工自测与官方机标分别报告。

评分有效性先于逐条计分：每条正向条件和零分条件都须能在模型输入或题目明确允许的外部规则中找到依据。若考点写“附件没有某文书”，先查完整附件及其内嵌文件；若附件实际包含该文书，该条不能按缺失文书的前提评分，标为“rubric与材料冲突”，修订rubric后再评。关键考点失效时，报告有效条目数和争议，不能把原总分当成有效难度成绩。

按语义判定是否依赖材料：模型为区分案件、说明不适用范围而提及某份材料，不等于将该材料作为本案事实或请求依据。rubric 若要禁止“引用”，须界定禁止的是哪种实质用途；不可将“提到”与“采信/据以主张”混为一谈。零分理由应对应实际作答原句及 rubric 原文；正向标准未满足而得0，与触发明确零分条件，分别记清。

缺少完整模型作答时，只能审核已提供的引文或评分记录，不能声称已独立重评整份答卷。每条有争议的分数保留原文证据和附件出处；未能核对附件、版本或作答原文的，标为待复核，不纳入确定结论。

题目与rubric修订后更新版本信息；评分文件保留旧轮次及对应版本，不覆盖历史，不将不同版本直接横比。版本记录写入题目允许的位置和评分文件，不因此新建旁文件。

交付前核对必要内容是否完整、文件引用是否存在、各交付内容是否一致、结论是否超出证据。明确本次实际修改及未确认项。文件生成时核对实际内容及必要的显示效果，支持文件留在临时位置，不混入题目目录。

提交资格、专业用途、交付完整性和难度分别判断。难度需当前版本得分及执行证据；没有相应证据就标未验证，不保证达到不高于50分且不少于50步或超过40分钟的门槛。测评只在用户要求时进行，不自动运行模型、测试、提交平台或修改外部记录。

## 重点7：先确认测评有效，再按证据返修

记录题目及 rubric 版本、模型及版本、评分方式、每条得分与支持或反证原文、通过条数、总条数、百分比和争议。盲评时隐去模型身份、既往成绩和目标得分，完成后再附模型信息。

难度门槛的逻辑是：得分率 ≤ 50%，且（执行步数 ≥ 50，或运行时长 > 40 分钟）。记录本轮真实执行证据；人工估分和官方机分分开。缺失任一必要证据，不能写已通过。

先核对当前题目与 rubric 版本、实际输入附件、模型及模式、原始作答、输出文件与 trace。环境不支持文件产出、输入未成功传入或版本错配，属于测评条件问题；输入可用但模型自行漏读、漏交，仍可构成作答失误，不能一概作废低分。选用能接收附件并完成所要求产物的模式，不固定推荐某个模型型号。

作答者只收 prompt 和输入附件，评分者另按 rubric 留证；不使用作答者自报分。人工分反映该次评估，不能代替官方机分。统计真实 trace 和时长，不把消息数量或并行子任务时长直接相加冒充项目执行长度。

试跑复盘区分模型漏判、任务允许绕过难点、材料不足、rubric 含糊或过窄、交付遗漏。只有实际证据支持才改题；改后成绩须重新取得，不复用旧版达标结论。

返修按缺口选择动作：错了但考点未覆盖，补齐相应判断标准；活多但判断被绕过，调整必要依赖；材料不够，补齐有授权且合规的依据或保留局部未知；长度不足，核对是否缺少真实必要处理，不机械增文件。得分高本身不能证明题有缺陷，也不授权改变公平尺度。
