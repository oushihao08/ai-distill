# 共享契约与步骤注册表

供前后端使用的轻量类型与步骤身份定义，不执行数据库查询或模型调用。

| 文件 | 职责 |
| --- | --- |
| `score.ts` | 后端达标与前端评分展示共用百分制换算；无效分数或满分返回空值 |
| `types.ts` | 项目、题目工作流、材料、步骤、执行尝试与 API 返回类型，含跨项目成果库摘要 |
| `workflow-results.ts` | 当前答案、评分、达标汇总的共享类型与 JSON 读取边界；不改变历史存储格式 |
| `step-prompts.ts` | 出题和评分默认任务；评分按本题 rubric，不预设得分高低；未设置或精确匹配已知旧内置默认时使用当前默认，自定义正文原样使用 |
| `step-registry.ts` | 步骤 key、持久化 ordinal、可见 position、默认启用项和脱敏默认提示词 |

`web/src/types/api.ts` 转出共享类型；后端材料接收、项目步骤汇总和执行器使用注册表。新增步骤应定义独立持久化身份，不重编号历史尝试。ordinal 2（PDF 内部提取）、3（旧规则绑定）和 10（旧独立审查）仅用于历史兼容；ordinal 4 为出题，七个可见步骤的位置为 1 至 7。

`workflow-results.ts` 定义当前作答、评分和达标摘要，并提供读取未知 JSON 的运行时边界函数；旧记录缺少可选字段时继续可读，不据此推断为成功。它只约束前后端对已有结果的读取，不添加数据库字段或改变 Agent 可见输入。

类型声明不代替服务端运行时校验；修改字段须检查 Hono 返回值、前端消费者和已有任务快照。页面状态名、步骤顺序与数据库序号是不同概念。

`types.ts` 共用 `ModelApiProvider` / `ModelApiConfig`，脱敏步骤配置支持嵌套 `api` 配置；`Step.ready` 与 `Step.ready_reason` 由服务端统一计算并供逐题步骤表展示；项目 `Workflow` 的达标判定、逐模型分数及发布／导出状态用于达标题目表；密钥不得进入这些公开类型或配置。

WorkflowDetail 的 artifacts 可带 filename，供逐附件脱敏 DOCX 下载链接显示文件名；不返回存储绝对路径。
