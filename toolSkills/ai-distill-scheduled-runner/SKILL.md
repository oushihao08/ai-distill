# 定时 CLI 执行

目标：每次唤醒先对账，再执行当前可推进的任务，及时利用现有 Agent/API 席位，直到约定终点。调用本 Skill 的定时执行使用 CLI；业务规则与恢复边界遵循 [工作流 Skill](../../skill/SKILL.md)，命令语法以 [CLI README](../../cli/README.md) 和当前帮助为准，不直连数据库。

## 建立任务

1. 从本会话沿用项目、期次、来源/题目范围、终点、优先级、巡查间隔、返修上限和交接对象。读取目标项目规则；只询问真正缺失的关键选择。用户只给间隔时，使用会话已明确的任务，不能扩大到整个库。未授权返修时上限为0；“直到达标”也需设置有限执行预算，避免无限消耗。
2. 按[对账台契约](references/ledger.md)创建或接续 `.storage/automation-runs/<run-id>/state.json`，固定范围。已有台账复用，不复制历史、重建任务或另造队列。不同阶段允许不同执行池；容量和步骤身份从当前服务端读取。
3. 使用应用的自动化工具创建当前会话 heartbeat；间隔采用用户设置，不固定5分钟。先查已有同目标任务，优先更新，保存 automation ID。定时提示必须包含 Skill绝对路径、仓库、台账、固定范围、授权终点与授权边界；要求每轮读取本 Skill和台账、主动派发、无变化安静、终态停用。缺少自动化工具时明确报告尚未启动，不能用 Skill文件存在冒充定时运行。
4. 记录已获授权的服务维护动作及确切范围。执行业务不自动授权重启、启动worker、修改模型/并发/阈值、取消未知执行或删除数据。已有授权持续有效，不重复索要。

## 每轮：对账 → 补位 → 回读

- 先检查台账的单写者锁和相关runner身份；同一run正在执行则不再启动或并发写。锁须包含PID、启动时间和run ID；核实原进程结束才清理遗留锁。更新采用临时文件原子替换，结束释放自己的锁。
- 读取范围内的 `workflow status`、相关 `attempt show`、`queue show`、`monitor show`、`queue diagnose`；材料阶段补查对应包、版本和library job。批量查询独立对象，只在诊断时读取结果正文和窄时间窗日志。API状态是事实，台账是带核实时间的观察；查询失败保留旧观察并标明过期，不推断任务失败。
- 逐题核对输入版本、ready/reason和全部活动attempt。`waiting`不代表已排队；已成功的不重做，活动任务只跟踪，部分模型完成不代表整题完成。原请求unknown先核同一请求/attempt，禁止换key盲重派。
- 按优先级将每题下一授权且ready步骤分组派发；一题出题完成即可作答，一题作答完成即可评分，不等全批齐步走。步骤key/ordinal读取当前注册表；材料处理与题目步骤分别走现有CLI，不复用旧步骤编号。材料模式沿用用户要求与期次配置，不靠提示词切换。
- Agent/API分别计算容量，使用当前队列运行R、等待Q和上限C，扣除本轮已预留席位。遵守服务端等待上限和运行上限；若等待上限也是C，可补数量最多为 `max(0,min(C-Q,2*C-R-Q))`。实际契约变化以当前API为准，不能固定历史容量或增加并发。未找到可验证的空位则先核实，不猜测。
- 写前落盘命令、工作流、步骤、输入版本、本地操作ID及该命令支持的request-key；不假造CLI没有的参数。写后立即保存完整逐项响应和所有attempt ID，再继续下一写入。已明确 `dispatched=false` 的容量拒绝记“未派发待补位”，不记模型失败、不扣返修次数；批量部分成功逐项处理。
- 每次派发后回读状态并更新台账。还有独立ready任务与容量就继续补位；仅有在途任务时使用短等待或留待下次heartbeat，不用长等待阻塞其他题。每轮结束记录未补满的实际原因，而非笼统“运行中”。

## 阻塞与返修

- 有排队且空闲但未领取：本轮立即核消费者模式、执行节点、限定范围、心跳、领取日志和对应进程。monitor单个worker存活不能证明所有池有消费者。没有消费者是阻塞，不能反复空等。
- 出题或评分自入队超过15分钟（含排队）必须在本轮排查并记录具体阻塞及下一动作，不能仅刷新checked_at继续等。消费者缺位不必等15分钟。告警不能自动取消或重派；缺授权立即提出具体处置请求并保存pending_decision，不以曾报告问题代替寻求必要决定。
- 对长running核同一attempt的领取、调用开始/返回、输出校验、结果提交时间线。只有心跳或call.started不能证明供应商仍生成；区分模型失败、数据库提交等待、unknown和needs_review。
- 授权内可解决的对账、就绪派发及维护立即处理并回读。缺服务操作授权或未知结果处置决定时，只问一次具体动作和证据，台账保存pending_decision并继续其他任务；不得静默启动/取消、自动重试失败模型调用或通过修改状态制造成功。
- 仅有效判定未达标且返修已授权的题进入返修：读该版本评分理由，记录每轮分数、问题与证据，按当前CLI的advice流程生成并提供显式返修建议，再对原题身份出题→作答→评分。旧答案/评分全文不注入作者；输入边界依现有工作流契约。每次实际开始新题版本计一次返修，额度派发前预留，失败不反复白嫖额度；派发结果未知先对账。达到上限、草稿或调用失败先定位记录，不自动强推。

## 达标与结束

核对同版本题目、答案、有效评分及当前decision。执行成功、accepted、等级合格、归档、上传、正式提交、平台验收分开记录。达标立即停止返修；用户授权交接时，将题名、等级、workflow、版本、分数依据、attempt、归档/五件套状态及等级疑点交给指定会话，保存工具回执。回执unknown先核目标会话，不能重复交接。

正常运行及无变化保持安静；新实质阻塞、需要决定或完成时通知。全体到授权终点且必要交接完成后停用/删除本次heartbeat；全部剩余阻塞且无在途任务时也停止空转，报告未完成项与恢复条件。只停止本次明确授权的辅助进程，不能影响其他worker。保留对账台和回执，不能宣称Skill验证等于真实模型或平台验收。
