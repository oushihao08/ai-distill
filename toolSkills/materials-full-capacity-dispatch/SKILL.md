# 材料与出题任务持续补位

目标是缩短已授权批次完成材料处理并进入出题的时间。每轮以实际完成和合法候选为准，不以派发数、历史并发数字或旧账本判断是否满载。当前用户指定的范围、来源、阶段、目标期次、执行位置和质量门槛是动态条件；不得把某次批次的包数或槽位数写成通用配额。

## 单轮闭环

1. 读取适用的项目规则、工作流契约和当前批次账本。通过目标服务的实时 API 回读任务、正式包与版本、脱敏、整理、目标期次的加载关系、题目工作流、出题尝试和各执行 lane 的队列容量；必要时扫描来源及完整原件集合。实时结果优先于旧表。按包建立唯一下一阶段候选清单，并列出依赖、重复、活动、未知、失败和阻塞原因。不要只检查上轮的少数候选。
2. 对每条 lane 区分运行容量和等待容量，以本次 `queue show` 的 `limit`、`running`、`queued`、`reserved`、`waiting`、`available` 计算可提交量。优先将已就绪且符合当前授权的任务填入空槽；上游成功并取得正式业务 ID 后，立即把该包下游阶段加入本轮候选。不同包可并行，单包阶段依赖必须串行。
3. **持续循环，不设固定小批上限。** 选一个合法候选，写前持久化包身份、输入摘要、阶段、执行位置和 request key；提交后立即保存完整回执、任务及业务 ID，回读任务和队列，重算两条 lane 与候选。继续到所有可用层均满，或全量候选已穷尽。一个包的拒绝、失败或未知仅隔离该包；仅队列整体不可用或容量无法可靠读取时停止对应 lane 写入。
4. 对可在当前授权和现有工具内解除的阻塞，先核实原件完整性，再用可追溯预处理解除，例如在受管副本中消除上传名冲突并保存原路径、原 SHA256、输出摘要和映射；随后重新纳入候选。不改原件，不拆散逻辑包，不把格式不支持、签名异常或来源缺失伪装成就绪。
5. 空槽仍在时，对每条 lane 记录当前运行/等待占用与空位、全量候选数、可派数、各候选未派原因和下一步。只有全量核对后没有合法候选，或该 lane 整体不可用，才将空槽解释为合理闲置。更新既有逐包账本和回执，不另造平行台账。

## 空槽强制规划门

每轮结束前再次执行 `queue show`。任一 lane 的运行层或等待层未满时，本轮不得直接结束，必须重新遍历完整范围并形成该 lane 的补位计划：

1. 纳入当前即可派发的任务，以及能在本轮通过已有可追溯预处理解除阻塞的任务。
2. 立即衔接本轮新完成的上游任务：提取成功转脱敏，脱敏成功转整理，整理成功后加载到目标期次、创建唯一题目并派发出题；不得等下一轮才规划。加载和建题是出题前置写入，不占模型槽，但必须保存回执并防止重复加载或重复建题。
3. 按计划逐个派发、回读和重算，直到该 lane 实际满载，或计划中的候选均已派发、隔离或证实不合法。
4. 仍有空槽时，逐项写明候选身份、缺失依赖、活动/未知任务、格式或来源阻塞及可执行下一步。只写“已派若干”“运行中”或“没有 ready”不构成候选耗尽证据。

调度周期由调用该 Skill 的当前任务决定。周期变化不得削弱上述单轮闭环；每次触发都必须执行到满载或候选耗尽。

## 不变量与验收

- 仅派发当前任务已授权的阶段。提取须保持完整原件集合的原子发布；正式 `package_id/revision_id` 到手后才能脱敏，成功 `redaction_id` 到手后才能整理。实时成功状态与内容质量验收分开记，不把已派发当已完成。
- 用户已指定“整理完成后加载并出题”时，只有成功整理且未在目标期次加载的包才执行加载；加载成功后按项目规则创建该包唯一题目，取得 `workflow_id` 且工作流状态确认 `author_question` 就绪后才派发出题。已经加载、已经建题、已有活动/未知出题尝试或出题已成功的对象只跟踪，不重复写入。
- Agent lane 的合法候选由脱敏、整理和出题共同组成。某一类候选不足时必须继续检查另外两类；不得因为材料阶段暂时没有候选而让已有就绪出题空转，也不得为了填满 Agent 槽跳过加载、建题或服务端 `ready` 依赖。
- 活动、排队、未知回执或同一 request key 待核实任务不得重复提交。失败重试仅按当前用户授权、确认的终态和新 request key 执行；同轮失败不立即重试。为凑满不得越过依赖、改变模型/并发、扩大来源或制造重复任务。
- 以本轮结束时的队列回读和逐包候选清单验收：若有真实空位且仍有合法 ready 任务，本轮未完成补位；继续派发。报告分别给出发现、合法候选、已接受、终态成功和仍阻塞的数量，不混用计数单位。
- “满载”以结束时的实时队列为准；“候选耗尽”以完整范围的逐项决策记录为准。派发数量、开始时队列状态和历史并发上限均不能替代这两个验收条件。

本 Skill 指导已授权的操作，不创建定时任务或额外授权。具体 API、材料格式和账本写法以当前项目工作流与适用批次规则为准。
