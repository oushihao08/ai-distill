# 豆包网页作答复测

从已提交的题目开始。沿用本批题号、冻结题面及附件、同版 rubric、导出位置、评分模型和停止条件。复用本流程时，默认每 5 分钟查看一次、每题用一个新的 gpt-6.2-sol medium 评分会话、从开始监控起最多运行 2 小时。用户本次指定值优先。耗时目标、分数门槛和比较基线取本批约定。

## 接管与等待

1. 用 browser-skill 连接指定的已登录浏览器。在同一账号的后台工作窗口打开目标会话，对照用户消息的题面、附件及基准日确认题号。同案重出要核对本次版本，侧栏标题只能用于找候选。
2. 在本批私有目录记录每题的题号、会话地址、题面与评分版本、已收文件和评分会话 ID。记录开始时间与绝对截止时间。恢复时先回读本地文件、页面和已有评分会话，接着做缺的步骤。
3. 每个检查周期只读未完成项的最新消息及交付状态。以原始任务的最终答复和成果卡片识别交付。页面可能折叠消息或延迟更新，按钮数量、静止计时器、文件生成中的预告均不足以判定完成。状态相同无需向用户重复播报。

## 收齐答案及测量值

- 分开保存首次完整交付的答复和步长回复。读原始答复上的“共用时”，排除后续追问。只能用收发时刻估算时注明精度。
- Agent loop 统计从接单至首次最终答复的助手回合，包含交付说明；一个回合内并行多个工具只计一次。按来源标注“豆包据轨迹自报”或“已核原始轨迹”。阶段数、工具次数另记。已有待发追问就等其答复。已授权取步长且仍缺该口径时，只补问一次“请据轨迹报原始接单至首次最终答复的助手回合数，排除追问，并行工具计一轮；轨迹不完整请注明。”仍取不到就记缺失。
- 逐件下载该答复公开交付的原文件，保留原名，按“豆包作答与附件/题号-题名-短ID/作答附件/”存放。输入案卷和仅供预览的图片另行识别。对照卡片和答复清单核数，检查字节数、文件能否解析；重名异件分开保存。答复声称交付而页面无件、下载失败或文件损坏分别记录。下载操作结果不明确时先核对目录和页面，再处理缺件。勿把账户凭证或带签名下载地址写入清单。
- 每题答复、步长回复与可见附件收齐即可派评，其他题继续等待。能确认确未交付的文件按事实告知评分者；采集失败的文件先恢复，无法恢复须注明评分局限。

## 独立评分与收尾

每题创建独立的新会话，显式指定评分模型与推理档位。单独准备该题的冻结题面、允许的案卷、同版 rubric、匿名答复正文和作答附件。剥离界面计时、模型身份、过程追问和页面操作文字。标准答案仅在冻结评分契约明确要求校准时提供。将本批绝对截止时间告诉评分会话。

评分任务要求逐项对照冻结判据，实际打开对应附件，引用页码、文书段落或表格单元格。公式联动在副本上改变真实输入后重算，核对下游供签数值。按该题口径换算总分，说明是否触发整题归零。将评分报告写回本题目录，回读后计为完成。

汇总每题得分、原始耗时、助手回合和实际附件数，报告中位数及有效样本数。按同材料、同口径与基线比较。目标接近就结束；差距明显时，从实际错办、漏办和返工中找能改变下游办理的任务，提出可用案卷验证的 Skill 修改方案。区分实质判断与读页、排版、转换等工具工作。修改或重跑须在本次授权范围内。

批次完成立即关闭本任务的浏览器会话、终止轮询。每次等待、下载重试或派评前检查剩余时间，等待不得超过截止；到点停掉本批轮询与仍在执行的本批评分工作，保留成果并列出未完项。只操作本轮启动或获授权控制的任务。
