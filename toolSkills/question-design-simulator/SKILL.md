# 出题模拟盘

先确定要做的决定。点子筛选回答“这个改动值得拿去试吗”；整版评估回答“这批题实际交办了什么，预计豆包会做到多少”。用户给的业务目标和阈值只用于判读结果。默认在本地推演，不触发出题、豆包作答或独立评分，不改生产 Skill。

## 快速筛选一个点子

1. 选同一冻结材料、同一委托目标和一个已成题的基线。只在临时副本改变本次点子对应的题面片段，保留前后文。改变了代理方、材料或办理阶段时，列为换方向比较，不能把全部差异归给这个点子。还没有成题时，写明评的是规则设想。
2. 将两版随机编为 A、B。给独立读者每次只看一版公开题面和同一组允许附件，请它列出承办人会做的关键动作、对应案卷位置、接手人能使用的结果，以及它认为可省略的事项。不给点子、阈值、设计备忘录、考点、标答或豆包表现；回收两份判断后再揭示版本。无法隔离时可先自查，标明“单人推演”。
3. 拿旧成品试办新题。指出最先办不下去的具体环节及必须重做的内容。换措辞、拆文件、另存 PDF 或多列选项而办理结果相同，新增业务量记零。新增动作只有在委托范围内、有卷内依据、公开题面能让作答者识别、结果会影响后续使用时才计入。另记删掉的工作、题面是否泄露了本应由承办人作出的判断。
4. 用一个办理目的不同或关键条件缺失的材料包作反例。看同一原则能否自然产生不同动作，或让承办人有理由就此停办。两案都被迫写相同的主备方案、补证单或交付清单时，指出是哪句要求造成的。给“保留试测、修改后再试、淘汰”中的一个结论，附最有区分力的证据。明显无增量时就结束。

## 预判一版 Skill 和一批成题

按题目 ID 和本次出题尝试绑定规则、公开题面、实际交给豆包的案卷和比较基线。先让读者只看公开输入，再核对设计备忘录、考点、作答思路、标答。分别指出规则想让它做什么、题面能否引出、现有材料是否支持、成品怎样验收。只在内部字段出现的设计记为执行缺口。尚无成题时只评设计潜力。

- 每题找一件最可能迫使承办人继续办理的事，也找一条合理的短路径。区分必须等前一步取得结果的连续工作、可一次并行完成的工作，以及因授权或材料不足只能准备到某一步的工作。对照上轮标明新增、深化、沿用、撤去或替换。检验最强风险时可以换一个有卷内依据的条件，观察下游决定是否真的改变；假设与在卷事实分列。
- 用户要评分时，分开评价实务真实性、工作完整性、实质难度、连续办理和批内多样性。每项满分 100。50 表示关键环节只能靠推测或通用稿，80 表示主要要求已有可定位证据但仍有实质缺口，接近 100 需要在已检查范围内说明反例也成立。每个分数附一个理由。去模板要跨题看委托切入点、办理顺序、核心成果和考点怎样组织；单题不报批内多样性。预计首答覆盖率单列，沿用该项目预先确定的分母和判法。豆包高经济价值项目以备忘录最终采纳的独立业务结果为分母，做到结果的项数为分子，首要事项另核；只有草稿时保留区间或未知。实测须打开成品逐项核对，复合考点分数不能直接换算。
- 耗时与回合分别预判。有同材料、同模型环境的历史首答，先列实测锚点，再按工作替换、可并行性和自然停办点给方向或宽区间；缺乏可比样本就记未知。用户设“每题超过 N 回合”时逐题判断，恰好 N 计未过。工作量、附件数、工具次数、法官办案轮次都不能直接换算助手回合。预测分、实测分、预测信心分别标示。

## 锁定与回验

需要后续实测时，在仓库私有目录 `.storage/question-design-simulator/<本批唯一标识>/预测.md` 留下预测时间、题目 ID 与版本、基线、分项判断、阈值、依据、可能推翻判断的现象。先锁定再看本轮豆包成品或评分。重估另存并注明何时获得了什么新信息。预测后若改题，按新版本另作记录。

拿到同版实测再在同目录另写 `回验.md`。首次接单至首次完整交付为耗时区间；每次助手输出计一回合，包含首次最终答复，排除追问，并行工具算同一回合。注明页面计时、轨迹核验或模型自报。逐题对照实测、区间是否命中、过线判断是否正确及一条成品证据。累计命中以“命中数 / 有同口径实测且作过预测的题数”表示，同时列出未知与缺失；曾见过结果的样本只作回顾。跨版本多处同时变化时，只报告整版差异。复核结束即停。
