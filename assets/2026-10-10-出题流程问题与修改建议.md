## 发现的问题及处理

### 已处理：冻结的出题提示词产生不兼容作答工具要求

题目4、6、8的首次任务在项目步骤提示词修正前已冻结旧提示词。草稿将法律检索、计算等作者侧工具写进了答题模型的 `answer_requirements.tools`，但正式作答执行器只接受纯文本输入、纯文本输出和空工具列表，因此三次任务在作答前被拒绝。更新项目提示词不会回写已冻结任务，这是任务快照的预期行为。

随后明确区分“出题作者可以自行检索／计算”和“被测答题模型只使用纯文本、不得调用工具”，并为4、6、8创建新任务重派。最终六题题包均满足 `text / text / []`，完整流程完成。后续修改提示词后，需为已冻结的旧任务创建新尝试；不能把更新后的配置误认为旧尝试已自动采用。

### 已处理：评分项采用二元分值并校验总分

本轮加强了评分步骤对逐项二元分值及总分等于分项合计的要求，并对评分文本提取的 rubric ID、分值和总分执行校验。六题最终评分结果均通过程序校验。代码定向测试记录为 75 项通过、0 项失败；这不是全仓测试通过声明，具体边界见验收记录。

## 评分环节复盘

### 本轮实际评分输入和隔离

每题由独立评分会话使用 `gpt-6.1-sol / low` 评分。输入按同一版本绑定题面、rubric、数据库脱敏附件和匿名完整答案，并带评分步骤提示词；不提供作答思路、标准答案、作答模型身份或目标分数，也不读取项目 skill。六题评分提取均返回 `valid=true`、无结构问题，评分与对应题面、rubric、答案摘要绑定后用于达标判断。

### 发现并处理的评分问题

评分 rubric 是逐项 0/1 的单位分制，但纯文本评分若只提取末尾总分，可能掩盖分项漏评、重复评项、部分分或分项合计与总分不一致。仅靠提示词要求模型遵守格式，不能替代程序校验。

因此增加了纯文本评分校验：每个 rubric ID 必须恰好出现一次；每项满分必须为1、得分只能为0或1；最终总分必须可明确提取，且等于逐项得分合计。结构不合规时不将提取出的总分用于有效评分／达标判断。评分步骤提示词也要求逐项二元判分和合计。

本轮六份正式评分均通过校验。测试覆盖了部分分、漏项以及总分不等于分项合计等反例。程序校验的是评分结构、覆盖和算术；rubric 是否合理、答案证据是否支持某个判分及法律／业务判断是否正确，仍需审阅评分原文和依据，不能把 `valid=true` 当成实质结论正确的证明。

代码定向测试结果为 75 pass、0 fail（9个文件、311次断言），覆盖评分输入白名单和相关评分契约；此前一轮评分测试夹具仍期待旧的标答／skill／结构化报告输入，已改为当前盲评分文件与文本协议。另有一个与已撤销质量检查流程有关的旧 `revision-source.test.ts` 用例未纳入最终定向命令，故不宣称全仓测试通过。完整测试范围和历史失败说明见[验收记录](../docs/evidence/2026-10-10-fresh-authoring-alignment.md)。

### 未解决：Codex 用户配置存在旧 MCP 字段警告

六次作者会话均出现五项旧 MCP 配置字段不被当前 CLI 识别的警告。作者实际调用了 shell 和网页搜索，但这不能证明 AnySearch、桌面专有指令或全部 MCP／插件已正确加载。当前证据不足以宣称后端工具环境与桌面端完全相同。

建议先根据当前 Codex 配置格式核对这五项具体字段及预期工具，再决定是否迁移配置；不要在没有逐项映射证据时批量改写个人配置。改后应从实际会话事件确认每个所需工具已加载并可调用。

### 需改善：展示有效答案模型及其配置来源

题目作答步骤显示的配置为 `qwen/qwen-plus`，但本轮队列优先使用启用的项目模型集合，实际作答 attempt、模型字段与日志确认使用 `qwen/qwen3.8-27b`。这是配置来源展示容易造成的理解差异，不是本轮模型调用失败。

建议界面或任务快照清楚显示“最终生效模型”和其来源（步骤配置、项目模型集合或系统默认），检查运行结果时以 attempt 及调用日志为准，不只看步骤表单中的候选配置。

## 后续修改建议

1. **保持作者提示词与作答契约一致。** 作者可使用的研究工具和答题模型可使用的工具是两个不同边界；提示词和题包校验都应继续分别约束。任何不兼容值应在正式作答前清楚拒绝，并指向需要修正的生成环节。
2. **对配置差异做逐项实证。** 核对五项旧 MCP 字段、实际启用工具和桌面端对应配置；只在确认字段映射和影响后调整，不把“CLI 有搜索”扩大成“桌面工具已完全对齐”。
3. **让有效模型配置可见。** 把项目模型集合的优先级及最终模型写入用户可见的任务信息，避免步骤配置显示值被误认为实际调用值。
4. **用配对条件比较手动与自动出题。** 如要判断桌面端和后端出题质量是否一致，应固定附件正文、skill、作者模型与推理档位、作答模型及盲评分口径，保存各次实际输入快照；不要用不同题目的分数作因果结论，也不要为达阈值修改 rubric。
5. **区分流程成功、阈值达标和内容质量。** 记录系统的 `accepted` 状态及其阈值含义，同时单独做内容和业务审查。低分是难度目标的信号，不自动证明题目无歧义、依据完整或业务结论正确。
6. **保留失败尝试和重派关系。** 旧冻结任务的失败原因、新提示词下的重派及最终题包应继续可追溯；失败任务不覆盖成功成果，也不作为普通新题的隐式输入。
7. **继续让评分按证据判分。** 保持盲评输入边界和逐项结构校验；人工复核时重点看零分理由、答案原文证据、rubric 口径，以及评分结论是否被题面／附件事实支撑，不通过调整标准去追求某个目标分数。
