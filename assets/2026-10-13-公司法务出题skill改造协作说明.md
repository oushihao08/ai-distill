## 2. 项目方要求及其适用边界

用户本次提供的项目方要求：

1. 高经济价值任务是专业人士在真实工作中投入较多时间、调用多种材料或工具，成果实际用于决策、执行、正式交付、合规流程或持续运营的任务。
2. “是否愿意支付100元”是辅助判断问题；不能将其改写为必须存在付费记录，也不能以一句“有商业价值”证明用途。
3. 题目要素完备：提示词、附件、标答、考点等符合规范。
4. 难度要求同时满足：SOTA 得分率不高于50%，以及执行轮数不少于50步或运行时间超过40分钟。
5. 项目方会对进行中、已结束及其他项目任务查重；高相似任务作废，是否相似由项目组判断。不得重复提交其他项目的 Agent 题目。

本地资料另有“同一专家多题应在任务目标、工作流程、任务类型、最终产物中至少两个方面实质不同”的要求。此要求可以作为已知题目的比较依据，但不是项目方查重的通过保证。换公司、案号、数字、日期、角色名称或措辞不能单独证明新任务成立。

可核对来源：[任务说明](../projects/豆包高经济价值/materials/高经济价值五期任务说明文档.md)。其中旧收题日期和页面更新时间不能自动视为当前周期安排；本次用户提供的要求是本轮讨论依据。

本地规范允许明确标示的合成材料，外部要求强调真实工作用途。需要区分真实专业工作场景、仿真材料、模拟变化情景和实际使用证据；不能把允许本地模拟理解为平台已认可提交资格，也不能要求所有辅助材料必须是未经加工的真实公司记录。

## 3. 本次驳回提醒了什么

用户提供的驳回意见认为：任务主要是债权受让签批的模拟要求与部分卷宗，未明确体现专属商业交付用途；建议补公司交易背景、后续执行约束及可复用签批模板等材料。

据此需要检查：成果由谁使用、处理哪项工作、受到什么具体约束、完成后触发什么动作，以及错误结果会产生什么实际后果。只给专业角色和复杂卷宗，不能自动证明高价值。

当前 skill 已要求成果接收人、用途、具体条款与办理正文，但入口重点是“难倒 AI”，尚未将业务用途与题目差异作为独立职责组织。其现有难度设计并不因此被证明无效。

“标准化模板”“核查表”属于本次审核建议。任务确有后续复用需要时，可以成为正式成果；没有依据时，不把它们设为每题必交项，也不将“补模板即可通过”写成保证。

尚未独立核对本次被驳回任务的完整提交题面、附件和成果，因此不能断言审核意见中的每项事实判断都已证实。

## 6. 角色清单如何理解

用户提出的角色包括：原告、被告、第三人、案外人、法官、律师、证人、鉴定评估机构、法务、合规。

设计时区分三层：

- 作答者职业：由谁完成专业工作，具有何种权限、义务和交付能力。
- 委托或服务立场：工作为谁服务，解决什么目标，例如代表原告或被告进行专业处理。
- 材料中的主体角色：证人、第三人、案外人等在本案中提供何种事实、权利或证据。

三层可以同时存在。更换角色只有实质改变目标、信息范围、权限、工作流程或成果用途，才可能构成有效差异。

当前 skill 仍以公司法务任务为范围，模板默认 L2 为法务。是否允许法官、律师等作为独立作答职业、以及项目行业职业字段能否相应变化，尚未确认。不能擅自将全部角色解释为仅轮换卷内人物，也不能自动扩大职业范围。

| 工作方 | 分析职责 | 需要交接的内容 |

| 统一修改者 | 比较两边结论，处理重复与冲突，再修改同一份当前 skill | 最终采纳清单、具体差异、未解决事项和实际检查范围 |

低分或高分本身不能证明设计有效或失效。对方需区分：模型已掌握的专业工作、题面提示、可绕过的要求、rubric覆盖或重复处罚、合法替代答案、材料缺口以及执行截断等问题；结论必须指向具体依据。

交接前先确认对方是否已经修改文件。若已有修改，读取其实际差异再整合，保护已有内容；不得用整份替换覆盖另一边修改。若仍处于分析阶段，统一确定修改者后再落地。

本会话建议由本会话作为最终整合修改者，待对方分析交付后统一处理。这是协作建议，不代表已向另一位 Agent 下达指令或确认其同意。

## 8. 输入边界与后续检查

当前[架构约定](../docs/architecture.md)说明：普通新出题和重出题使用本次附件、指定 skill 和步骤指令，不查询或注入旧题、答案与评分。skill 专用扫描不自动读取项目 `materials/`、历史报告或 `assets/` 中的近期题目表。

因此，skill 外的跨题比较资料适合由独立检查者使用。若以后希望作者获得任务安排、避免重复的抽象要求或其他历史摘要，必须先明确其来源、范围和与现有输入契约的关系，不能声称仅添一个文件就已接通。

统一修改后的检查包括：

- 每条要求有明确职责、来源与适用范围；不把一次驳回、个案数值或某模型错误扩大为永久规则。
- 高价值检查与专业难度检查都成立；不靠减少独立争点、泄露解题线索、修改评分尺度或限制正常工具制造低分。
- 新题在已知范围内具有实质差异；常见法律概念重复、来源复用和任务重复分别判断。
- 引用路径、入口、索引及模板一致，搬动时保留原有有用约束。
- 实际难度按完整作答、逐项评分及可取得的执行轮数／运行时长证据判断；文本核对或关键词统计不能证明达标。

本文没有启动测试、服务、模型调用或评分重跑；未修改目标 skill、历史题目、分数或业务状态。后续具体修改和运行验证按用户届时授权及项目规则执行。

2. 本次被平台驳回的完整提交材料能否支撑真实用途；不能仅据驳回短文替代复核。

5. 实际模型执行模式与项目方轮数／时长要求是否可对应；本地自动达标状态不等于平台正式合格。

本文完成的是情况说明和协作交接，不宣称改造已实施、难度已验证或项目方查重已通过。

## 10. 本轮修改计划与验收

用户要求在现有 skill 上进一步保障出题质量。本轮只处理已确认的缺口：当前规则要求写使用人、约束和成果，但成稿检查尚未明确核对这些内容是否实际改变专业判断与交付。

任务清单：

1. 在 `references/出题设计方法.md` 的成稿检查中加入实质依赖核对，识别只有业务或角色外壳、没有可见材料支撑的泛化题。
2. 检查新增规则与现有角色、题面、评分规则的关系，保留专业工作强度，清理重复或冲突。

验收标准：新增规则能让作者核对“关键材料与约束→待作判断→可执行成果”的关系；不把角色、附件、金额、成果数量规定为配额；skill 内本地引用有效；修改范围不触及历史题目、评分、工作流或数据库。本轮只验收文本规则与引用，不验收模型分数、平台高价值筛选或查重结果。

本轮已在 `projects/豆包高经济价值/skill/references/出题设计方法.md` 的“成稿”段加入实质工作链核对。它要求材料或模拟条件支撑独立判断和可执行成果，同时保留即使最终建议不变也确有必要的核查、反驳、核算与交接工作。对照现有角色、题面和评分规则后，未增加角色、附件、金额或成果数量配额。静态检查覆盖 skill 内 32 个 Markdown 本地引用，未发现失效引用；未运行新题、模型作答或平台评审，因此出题质量的实际效果尚未验证。上文关于“未修改目标 skill”的表述记录的是本轮实施前的交接状态。
