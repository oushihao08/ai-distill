# 未达标题包导出

仅在明确要求导出时，使用 `bun cli/index.ts export failed --project <项目UUID> --all --json` 从本机 API 读取当前第七步判定为 `repair` 的题目。也可用 `--ids <题目工作流UUID,...>` 限定范围。命令不派发模型任务，不修改数据库。

用户明确指定一题用于分析低分作答时，用 `bun cli/index.ts export review --project <项目UUID> --ids <题目工作流UUID,...> --json` 导出同样的完整题包。它允许系统判定为 `accepted` 的题目，但清单保留真实判定与“指定题目作答质量复核”用途；不能把模型低分写成作答调用失败。`export review` 不支持 `--all`。

固定路径：`assets/未达标题目/<项目UUID>/<题目来源标识>-<工作流UUID>/<判定尝试UUID>/`。每个目录包含 `出题.txt`、`清单.json`，每个参与评分的模型另有 `模型-<模型UUID>/作答.txt`、`评分.txt`、`评分.json`。同一判定重跑只核对文件后返回 `already_exported`，不覆盖；新一轮判定写新目录。未达标以当前系统判定为准，执行失败但没有完整出题、作答、评分关联的题目会报告缺项，不伪造文件。

`清单.json` 记录项目、题目、判定、出题与模型尝试 ID、题目／rubric 版本、得分和各文件 SHA-256。文件可能包含脱敏卷宗事实、题目标准答案和模型答案，只在本机按需查看；不要提交到公开仓库、复制到普通日志或重新作为出题输入。这里是人工复核用导出，不是题目来源目录或运行队列。
