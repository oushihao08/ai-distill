# 本地 PDF 批量打码 CLI 方案备忘

记录目标：输入一个本机 PDF 或文件夹，处理其中所有 PDF，并把打码后的文件导出到本机目录。本文是方案与边界记录，不代表功能已经实现或通过真实文件验收。

## 已确认目标

- 输入和导出路径都由本机 CLI 接收；原 PDF 保留，不覆盖。
- 支持单个 PDF 和文件夹批处理；每个输入文件都应有明确结果状态，不能静默跳过。
- 打码结果仍为 PDF。视觉上可采用模糊效果，但必须先移除底层原始文字或图像内容；只叠加模糊/遮罩图层不算安全打码。
- 当前用户倾向本地文件处理；是否允许把 PDF 内容发送给云 OCR，必须由用户显式选择，不能默认联网。

## OCR 与打码不是同一个组件

- OCR 引擎识别文字并返回页面坐标；它不负责判断哪些文字属于隐私信息。
- 敏感字段识别规则根据 OCR 文字定位姓名、证件号、电话、地址等候选项；手写批注、印章、复杂扫描件可能需要人工核查。
- PyMuPDF 按坐标修改 PDF。正确应用 redaction 可以移除区域内的文本并处理相交图像像素；它不负责 OCR 或语义识别。
- Azure Read 是云端 OCR：本机 CLI 可以读取本机文件、将内容发送给 Azure、再把结果和打码 PDF 保存回本机，但这不属于全本地处理。不能把“无需长期存到云盘”表述成“文件没有离开本机”。

## 可选处理方式

| 方式 | OCR 位置 | 文件是否上传 | 本机算力 | 主要取舍 |
| --- | --- | --- | --- | --- |
| 本地 PaddleOCR PP-OCRv5 + PyMuPDF | 本机 | 否 | 较高 | 满足全本地和隐私要求；批量耗时受本机 CPU/GPU 影响。 |
| Azure Read + PyMuPDF | Azure 云端 OCR，PyMuPDF 本机处理 | 是，发送给 Azure 处理 | 较低 | 减少本机推理；按页计费，需核对具体账户、区域和配额。 |
| PaddleOCR 云 API + PyMuPDF | PaddleOCR 云端 OCR，PyMuPDF 本机处理 | 是，发送给 OCR 服务处理 | 较低 | 减少本机推理；需另行确认账户价格、服务条款和真实文件质量。 |

**建议**：CLI 提供本地 PaddleOCR 为默认路径，满足“不上传文件”的明确边界；云 OCR 可作为显式选项，不默认启用。若用户优先考虑速度且允许向供应商传输材料，再选 Azure 或 PaddleOCR API 做同文件对照。Azure 的免费层和单次页数限制、付费单价会随服务层级/区域/账户条件变化，运行前需查账户控制台和当前官方价格，不能据此文中的旧网页摘录估价。

## 推荐的 CLI 工作流

1. 接收 `--input <PDF或目录>`、`--output <目录>` 和显式的 OCR provider；本地模式不访问网络。
2. 预检 PDF：枚举文件、保留相对目录结构、识别加密/损坏/不支持文件；为每个文件建立成功、需复核或失败状态。
3. 对原生文字 PDF 优先读取原生文字及其坐标；对扫描页调用选定 OCR，并保存页码、文字、坐标和置信度。
4. 用确定性规则识别需遮盖字段，生成逐页区域；低置信度、手写/印章或无法定位的候选不得直接标记为“已安全完成”。
5. 用 PyMuPDF 对原 PDF 应用实际 redaction，再按需生成模糊外观；输出到新文件，不改原件。
6. 验证输出 PDF 可打开、页数与输入匹配、目标文字不能从输出文本层提取，遮罩区域的图像内容已被移除/替换；生成逐文件检查报告。需要目视检查的文件标记为“需复核”。

CLI 语法草案（不是已实现命令）：

```text
ai-distill pdf redact --input <file-or-folder> --output <folder> --ocr local-paddle
ai-distill pdf redact --input <file-or-folder> --output <folder> --ocr azure-read
```

该功能应作为 CLI 的本地文件处理子命令，不调用工作台数据库，也不绕过现有工作流 API；保留现有 `remote material` 等 API 客户端命令。由于现有 CLI 主要调用工作台 API，本命令属于明确的本机文件工具扩展，不应另建第二套项目任务/队列状态。

## 质量边界与验收口径

- 可以保证：每个输入 PDF 都被记录为完成、待人工复核或失败；没有静默漏文件；原件不被覆盖；输出接受结构和内容检查。
- 不能承诺：对任意来源、任意扫描质量的 PDF，自动识别全部敏感信息且零漏遮。OCR 坐标和字段规则存在边界，复杂手写、印章、重叠字迹需要人工复核。
- “任务运行成功”不等于“隐私信息完整遮盖”。批量任务结束后，只有通过机器检查且无待复核页面的文件才可标记为自动验收；其余保留复核状态。
- 模糊是显示样式，不是安全机制；验收还要确认原始文字/图像数据已被移除，不能仅检查黑块或模糊块是否可见。
- 云 OCR 路径还需明确数据传输和供应商处理条件；在账户区域、保留政策和合同条件未核实前，不用于敏感真实材料。

## 已有性能证据与未知项

- 先前本机 PP-OCRv5 测量：20 页 OCR 与 JSON 保存约 349.55 秒（约 5 分 50 秒，平均约 17.5 秒/页）。这不是完整打码耗时，不包含敏感字段定位、PDF 重写、输出检查和人工复核；按线性估算 200 页 OCR 约 58 分钟，仅作粗略容量估算。
- 尚无 Azure Read 与本机 PaddleOCR 在同一 PDF/同一页集上的质量和耗时对照，也没有本地 CLI 文件夹批处理的端到端实测。
- PyMuPDF redaction 行为及图片处理选项应按所用版本核实；该项目的许可选择（AGPL 或商业许可）也需在产品化前确认。
