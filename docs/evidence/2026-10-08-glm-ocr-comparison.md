# GLM-OCR 与逐页 GLM-5.3-Flash 对比

日期：2026-10-08

## 真实调用

使用题目3的 `(2024)渝0104执312号.pdf`，文件大小 5,069,151 字节、29页。通过智谱官方 `/paas/v4/layout_parsing` 接口，以 GLM-OCR 对整份 PDF 发起一次调用。

| 项目 | 结果 |
|---|---:|
| 接口耗时 | 16.554 秒 |
| 返回页数 | 29 / 29 |
| Markdown 长度 | 13,500 字符 |
| 布局页数 | 29 |
| API 总 token | 73,757 |

同一材料之前的逐页 GLM-5.3-Flash `max` 识别已有14页缓存；前14页从第一张到最后一张检查点耗时约18.0分钟，平均约83.1秒/页。两种模式的页处理粒度不同，该耗时用于评估吞吐量，不是严格控制变量的质量比较。

## 文本一致性

将 GLM-OCR 的前13页布局内容与逐页 `max` 缓存按页对齐，去除空白和 HTML 标签后计算字符编辑相似度：平均 67.22%，范围 19.16%–90.61%。13页中有若干页差异较大。

该指标只代表两种输出的一致程度，不代表准确率或完整率；没有逐页人工/金标准校对，不能判断差异由哪一方造成。因此，当前证据支持 GLM-OCR 在这份 PDF 上明显更快、页数识别完整，但不足以证明它的文字质量达到正式使用标准。

## 原图抽查

再将 GLM-OCR 前 6 页逐页与原图比较，由 GLM-5.3-Flash low 只返回结构化问题计数。检查发现 3 项关键错误、0 项遗漏、0 项可见脱敏残留，6 页均未标记不确定。该复核仍由模型完成，不是人工金标准；但关键错误足以说明目前不能把 GLM-OCR 输出直接作为正式材料。

逐页计数见 [质量抽查结果](2026-10-08-glm-ocr-quality.json)。完整原始响应仅在本地权限受限目录中用于本次核验，不作为项目产物。

四份真实题目附件的后续整卷试跑与12页具体差异核查见[题目文件夹试跑报告](2026-10-08-glm-ocr-question-folder-trial.md)。

## 隐私与使用边界

GLM-OCR 的布局解析接口没有本项目的原脱敏提示词参数。本次原始响应只写入本地权限受限目录 `.storage/.glm-ocr-sample/`，没有生成或发布为出题 Markdown。接入实际工作流前，仍须应用现有脱敏流程，并逐页抽样核对金额、日期、案号、主体及表格内容。

官方资料： [GLM-OCR 模型说明](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-ocr)、[文档解析 API](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E6%96%87%E6%A1%A3%E8%A7%A3%E6%9E%90)。官方说明单个 PDF 限50MB、100页；本次样本符合限制。官方公布的 1.86 页/秒为其测试条件下的吞吐，不作为本地实测结论。
