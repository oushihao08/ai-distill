# 目录工作流与输入版本验证

2026-10-08，实施位置：ai-distill当前工作区。

新增目录导入入口，每个项目下以题目子目录标识 `source_key` 保持工作流身份。材料包按文件名与SHA-256比较；不变时复用，变化时增加 `input_revision`。历史原件、接收尝试和提取尝试保留；当前材料与产物查询只使用当前版本，旧任务不得覆盖新版本。

后端单元测试62项通过；类型检查及前端生产构建通过。新增验证覆盖目录内容不变、内容变化、目录标识校验、提取版本绑定及晚到结果阻断。

`bun scripts/verify-input-versions.ts` 在真实Neon PostgreSQL的临时schema中验证：并发目录提交只创建一个工作流、领取源版本固定、同目录更新保持ID、当前材料查询、旧任务晚到阻断、历史保留、新版本重新排队、未变重导入保持队列、项目材料数排除旧版本。检查结果见 [input-version-results.json](input-version-results.json)。临时schema和合成文件已清理。

主数据库已应用 `003_input_versions.sql`，本项目API已重启到新版本；前端代理健康接口与项目详情接口均返回200，现有工作流具有当前版本字段。浏览器验证了目录导入入口、弹窗打开/关闭及无文件时提交禁用，截图见 [directory-import.png](directory-import.png)。原生文件夹选择与整批上传仍未做浏览器端验收。

该集成使用合成PDF及固定处理结果，仅验证数据库和调度，没有调用智谱或证明真实OCR完成。部分PDF发生变化时，当前会重新处理新材料版本的整个材料包；未变PDF逐份复用仍待实现。
