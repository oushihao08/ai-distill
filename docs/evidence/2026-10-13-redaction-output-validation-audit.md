# 脱敏输出校验审查与 v14 修改

日期：2026-10-13（Asia/Shanghai）

## 结论

此前脱敏协议要求模型回传附件、页码、页数和嵌套结构，随后程序再把这些信息与本地来源逐一比较。附件和页面本来由队列输入确定，这组往返元数据检查让格式偏差变成整批失败，属于重复校验。v14 将模型输出改为扁平字段映射，附件和页序由本地输入恢复。

## 最近一次失败的证据边界

题目6工作流 `b7e7b3c6-6a6d-41bd-905d-2ba07daa8f68`，尝试 `78b130e3-e6ac-4c30-a254-35565519b855`，材料123页。日志显示失败阶段为 `output_validation`。首次调用 `b7084364-5810-485a-8ade-4e6e8e1eb1ae` 记录 `result_shape_invalid`；一次有界重试 `af93529f-8080-462a-a804-e1fbea730201` 记录 `page_content_invalid`，涉及页28。系统没有保存该次模型原始返回正文，因而不能从日志确定具体是页码类型、字段缺失或其他形状差异。修复解决了已确认的冗余结构要求，但不能把这次日志推断成唯一根因。

## 校验取舍

| 检查 | 处理 | 理由 |
| --- | --- | --- |
| 模型正文完整、assistant 角色、未截断、无工具调用或拒答 | 保留 | 缺失或未完成正文不能形成可靠映射 |
| JSON 能解析 | 保留；接受完整 JSON 代码围栏 | 业务仍需结构化映射，代码围栏只是外层格式 |
| 模型重复返回附件 ID、页码、页数、嵌套页结构 | 删除 | 这些元数据由任务输入提供，往返检查重复且容易因格式差异失败 |
| 每个请求字段有唯一编号并返回映射 | 保留 | 缺字段无法区分“没有敏感信息”和“模型漏做” |
| 未知字段编号 | 忽略 | 不把额外字段应用到原文；真正缺少的本批字段仍由覆盖检查发现 |
| `redactions` 显式数组 | 保留 | 空数组表示明确无敏感项；缺失代表输出不完整 |
| `kind` 和 `mask_text` | 改为可选 | 缺少类别时按通用敏感值处理；缺少遮盖子串时遮盖整个敏感值 |
| 重复字段、乱序字段 | 合并接受 | 由本地编号定位，不依赖返回顺序；重复不会改变目标归属 |
| 重复或重叠遮盖范围 | 合并接受 | 对并集生成遮罩，不让同一敏感内容重复识别造成整批失败 |
| 敏感值必须可在对应原字段定位 | 保留拒绝 | 无法确认来源时若继续会漏脱敏或改错文本；匹配仍容忍标点、空格和 Unicode 兼容差异 |
| `usage`、实际模型名、completion ID 格式 | 删除阻断 | 这些是可选统计/追踪数据；异常时置空，不应使正文失败 |
| 提取原文页序、来源摘要、附件指纹、内部结构与断点绑定 | 保留 | 保护任务输入完整和防止过期结果覆盖，不是模型格式校验 |

## 新协议

协议标识为 `attachment-field-redaction-v14`。模型输入是本批 `{targets:[{target_id,text}]}`，输出为 `{fields:[{target_id,redactions:[{source_text,kind?,mask_text?}]}]}`。程序只检查可解析、编号有效且覆盖本批全部字段、敏感值能定位，然后按原附件页结构生成脱敏结果。API 与 Agent 使用同一结构校验。

协议版本变化使 v13 的断点不再复用；已完成历史产物不自动重写，也不自动重派失败任务。v14 的整卷真实模型验收尚未完成。
