## 中途问题与处理

### 1. 缓存模型目录错误阻断正式派发

题目3按后端接口首次派发出题时返回 HTTP 400，提示保存的 `gpt-6.1-sol` 不在当前 Codex 可用模型清单；这次拒绝未创建 attempt。检查确认题目步骤保存配置为 `gpt-6.1-sol / low`，且同一轮题目2以相同设置已成功运行；旧缓存目录不含该模型，却被派发路径当成执行白名单。

在已授权的小问题修复范围内，增加 `validateStepConfigForExecution()`：派发阶段验证已保存配置的结构，不再以广告缓存目录拒绝它；新保存设置的目录校验保持不变，实际模型可用性仍交由 Codex CLI 报告。作者和评分派发都接入此行为。随后通过正式 API 重派题目3并完成全流程。没有改题目提示词、skill、评分标准或阈值。

相关修改：`server/project-folders.ts`、`server/authoring/jobs.ts`、`server/scoring/jobs.ts`，以及相关测试、模块 README 和架构文档。

### 2. Codex 内部命令有失败，但业务步骤恢复完成

Q3、Q4、Q5、Q6、Q8 的作者事件中有前表所列命令失败；类别为远程网页内容提取或本地文件／生成结果核验。作者仍保存了完整 JSON/Markdown 交付物并以成功状态结束，后续作答、评分和判定全部完成。当前证据无法把这些工具失败直接归因到题目得分或后端队列；它们是流程观察到的工具可靠性问题。

### 3. 评分严格阈值产生两道返修

Q3 得分 50%，Q5 得分 55%，均高于或等于“低于 50%”的通过边界，因此结果为 `repair`。这是预期业务结果，不是评分失败。后端评分校验及本轮后验核对均未发现条目 ID 缺失、重复、未知或总分结构错误；六条 `validation` 均为有效且无 issue。

## 与手动桌面 Codex 的差异

历史手动任务会话 ID：`01a125d4-fb54-7252-b5fb-7b2bb6855d10`。该会话的留存内容显示：工作目录为仓库根目录；用户附加的是另一路径中的原始 DOCX；会话读取了个人记忆、指定 skill、其成功案例、AnySearch skill，并写出 Markdown 成果。当前后端 Q2 是从工作流读取数据库脱敏附件（该工作流当前材料为 PDF），cwd 是项目目录；CLI 调用禁用记忆，作者的 skill 快照包含当前项目 skill 及其内部案例／模板引用。

所以两次出题**不是相同输入和上下文的配对实验**：至少附件版本与格式、cwd、记忆设置和外部 skill 加载边界不同。历史手动结果与本轮 Q2 分数不能单独用于证明“后端 Codex 能力导致分数变化”。本轮可以确认后端有完整权限参数、项目 cwd、shell、网页检索的实际调用和记忆关闭；配置警告以及无 MCP 调用记录则是当前可见差异。桌面端同输入再跑一次、对两边逐项核对 MCP 初始化及调用，没有在本轮执行，因此工具完全对齐仍未验证。
