## 一起启动脚本修复（2026-10-07）

旧脚本在服务已经运行时再次启动，导致3100与5173报端口占用。确认原占用进程均来自本项目后，停止旧验收进程，并通过`npm run start:iterm`实际启动前后端。

脚本现检查监听进程的工作目录及命令：本项目服务复用，其他项目占用时拒绝启动，不按端口杀进程。

验证结果：

- 空闲端口实际启动成功；3100后端及5173前端代理的/api/health均返回database=connected。
- 前端HTML返回出题工作台页面。
- 再次运行npm run start:iterm成功，两个监听PID保持不变，无重复服务。
- 使用临时命令桩验证其他项目占用端口时退出1，未调用启动命令。该分支为模拟验证，未停止其他真实程序。
- bash语法检查通过；7项后端测试通过，0失败。

当前服务由iTerm2页签持有；复用提示页签不会持有现有进程，停止时须回到实际运行服务的原页签按Ctrl+C。
