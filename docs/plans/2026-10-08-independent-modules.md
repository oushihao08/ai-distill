# 四项独立模块基础实施规划

日期：2026-10-08。范围：达标判定、返修决策、Excel导出、API费用与产量统计。依据完整MVP计划、第四至六步产物契约及用户最新费用范围。本文记录实施路径、当前证据和剩余闭环。

## 目标与边界

交付四项可独立验证的模块及接入说明。优先复用已有评分校验、版本绑定、provider调用记录和八步状态；不新建工作流框架。纯模块接收固定数据；系统接入层负责数据库查询、步骤状态、导出和 API 记录。

我负责模块、针对性后端单元测试、实际Excel文件回读及证据记录；主智能体负责查询组装、数据库迁移、路由、worker、状态事务及页面。最终接入验收必须由双方核对，模块测试通过不等于系统闭环。

当前已存在逐项评分校验和绑定字段、作答原始usage与调用时间、项目规则manifest中的assessment及步骤尝试。多模型集合、项目达标配置和统一成果查询不是既有能力，实施时应采用显式配置与查询投影，不能把自由结构的assessment直接当成已验证门槛。

## 1. 先固定最小输入输出

与主智能体约定四项契约，沿用现有字段，不另造同义版本体系：

| 模块 | 输入 | 输出与调用位置 |
|---|---|---|
| 达标判定 | 当前题目/材料/rubric绑定、独立质检、必需模型集合、逐答案有效评分、项目判定配置及必要执行证据 | 判定、逐模型原因、缺失项；第七步调用 |
| 返修决策 | 上述问题、明确错误类别、当前步骤、技术/内容次数、版本关系、累计调用及有效执行耗时、预算配置 | 重试/内容返修/等待/隔离建议、返回步骤、原因；调度器消费 |
| API费用 | 唯一调用ID、API Key计费类别、provider/实际模型、原始usage、适用价格快照及币种 | 单次费用或未知原因、分类token、分币种汇总 |
| 产量与导出 | 当前成果及历史尝试的投影、项目/批次、版本、答案、评分、返修及API费用 | 分阶段统计；xlsx文件及文件摘要 |

配置缺失返回明确缺失项，不推断项目门槛。单价由配置或已核实的价格快照提供，记录计价单位及适用时间；不在模块运行时抓取网页。开始实施前先核对现有调用结果的完整形状，契约写入模块旁接入说明。

## 2. 实现达标判定与返修决策

先实现纯函数，再由主智能体接第七步。达标判定必须先检查题目/评分版本一致、质检有效、必需模型齐备和评分无争议，再执行显式项目规则。支持已确认的逐模型条件；不默认平均分，不把低分自动当作题目无效。未齐备与配置缺失输出等待/阻断原因，不误判达标或内容返修。

返修决策区分：暂时服务错误走技术重试；认证/额度问题等待恢复；有依据的题面或标答问题回第四步；仅rubric变化保留同版本原答案并回第六步重评；题面或附件变化使旧作答及评分失效。材料问题交回第二步；规则问题停止当前派发，由主智能体处理规则版本，模块不能自动替换已绑定版本。实际修改由对应执行器完成，本模块只返回决策，不假装已返修。

技术重试与内容返修分别计数。沿用完整计划的内容返修默认三轮，允许项目覆盖；技术重试、有效耗时和调用上限读取显式配置，不另加未经确认的默认值。到达上限不再安排一次调用。有效耗时不包含排队和暂停；累计调用不因重试或进程重启清零。

验收：门槛等值、模型缺失/失败、配置缺失、无效/争议评分、旧版本、零满分等输入均有测试；返修测试覆盖错误分类、回退步骤、rubric重评、各上限边界及不修改输入。主智能体另验收事务发布、重新入队与晚到保护。

## 3. 实现API费用与产量统计

只统计系统通过API Key调用且按token计费的请求，排除GPT/Codex套餐。按provider已有usage归一化输入、输出及缓存命中/写入token；按其计价定义计算，缓存不重复计入普通输入。无法区分缓存或识别usage结构时保留原始记录并标记未知，不猜token。

保留实际已计费的失败/返修调用，以唯一调用ID去重；失败且无usage时费用未知，不标零。价格缺失、usage缺失分开说明。费用采用明确精度的金额计算；不同币种分别汇总，不自行汇率转换。存在未知项时汇总显示已知金额和未知调用数，不称为完整总费用。

产量按当前版本的工作流唯一ID分别统计启动、处理成功、出题、质检通过、有效评测、合格、隔离及导出。历史重试不增加题目数；输入版本失效后不沿用旧成功；同题多模型评分单独统计评测条数，不增加合格题目数；重复导出不增加唯一导出题目数。

验收：固定usage样本核算、普通/缓存计价、缺usage/缺价格、套餐排除、失败调用、去重、多币种；产量验证重试、多模型、失效版本和重复导出。无需真实凭证即可验证算法，真实供应商账单一致性另列验收。

## 4. 实现Excel并完成模块交接

接收冻结成果投影，按项目或批次拆页签；导出题目与版本、模型答案、逐项评分、返修记录和API费用。完整长文本超过Excel单元格容量时分段并带关联ID，不静默截断；将题面、答案等外部文本写为字符串，避免公式执行。sheet名称需处理非法字符、长度和重名。

先检查现有运行依赖，优先复用可用xlsx库；若需要新增运行依赖，先明确告知并取得授权，不改package.json或安装来绕过约束。输出实际xlsx及SHA-256，主智能体保存文件索引与下载接口。导出失败只影响导出任务，不重跑模型或回退合格成果；相同成果重复导出不改业务状态。

验收：生成实际文件，使用读取器核对页签、关联ID、中文、多模型、多行文本、逐项评分、未知费用及长文本分段；覆盖非法sheet名称和公式样式文本。主智能体验收下载、失败重试、重复导出及项目隔离。

## 交付顺序与完成标准

顺序：契约核对 → 达标/返修 → 费用/产量 → Excel → 主智能体接入。每项包含实现、后端测试结果、接入说明和未验证项；不写前端测试。可用固定样本独立推进，不等待第四步真实模型调用完成。

本规划不承担第四步执行器、自动调度、公共页面、系统模型库或完整八步验收。当前 `server/authoring/` 只有 `validate.ts` 及其测试，没有执行器实现，也没有 `executor.test.ts`；因此第4步的实际生成与质检消费者仍是返修队列和真实业务闭环的依赖，不把不存在的测试文件记为失败或本轮通过。

四项完成以模块行为与真实文件证据为准，不以“10%～15%”工作量估算作为验收标准；完整MVP目标及未完成项继续保留。

## 基础实施顺序

1. **固定契约并实现纯模块**：定义达标输入、返修预算、API usage/价格、成果投影；实现达标与返修决策、费用计算、产量汇总和XLSX生成。先用固定样本验证边界，不在纯模块中访问数据库或调用模型。
2. **接入持久层和 API**：为项目达标配置、API 单价快照、导出记录增加迁移；达标入口读取当前版本的步骤产物，写回第七步结果；费用接口只接纳 API Key token 计费调用；统计与导出复用同一结果投影，导出记录保存文件路径、SHA-256 和版本快照。
3. **接入用户界面**：项目页展示阶段产量和已知费用/未知调用数，提供成果导出与下载；步骤设置页编辑达标条件。价格快照暂由 API 管理，后续如需人工维护页面再单独排期。
4. **做分层验收**：单测验证纯逻辑和边界；临时真实 PostgreSQL 记录验证迁移、版本绑定、达标、价格、导出、下载和失效；浏览器验收用户实际操作；最后用可用的供应商调用和账单核对费用。合成数据库夹具、真实模型调用和账单核对必须分开报告。

## 下一步基础规划

1. **关闭费用金额缺口**：目前已确认 7 笔智谱页级 usage 字段齐全，缺少适用价格快照；取得可靠价格来源后按生效时间登记并重算，随后与供应商账单核对。来源未确认前继续显示未知，不推测金额。GPT/Codex 套餐始终排除。
2. **把返修函数接入持久化队列**：待第四步内容修订和主调度契约确定后，分别保存技术重试次数、内容返修次数、调用数及有效耗时；领取任务前和发布结果前核对版本/预算。技术错误只重试，内容问题按分类回第2/4/6步；达到上限隔离。通过队列集成验证重启、重复领取、版本变化和晚到结果。
3. **再验完整业务闭环**：只有上游题目生成、质检、作答和评分能提供真实当前版本产物后，才用真实题目验收达标、返修、费用和导出；整卷脱敏、国产模型凭证、多模型聚合或自动推进不属于本四模块证据，分别按完整MVP台账验收。

完成标准是上述每项都有对应证据；目前后端集成夹具、导出失败独立重试、浏览器错误恢复及临时项目主路径已通过。真实账单一致性、真实题目闭环及返修队列仍未证明。

## 2026-10-08 执行进展

已实现的模块入口：

- `server/decisions/acceptance.ts`：`decideAcceptance(input)`。按显式必需模型及逐模型最低分判断；缺配置/未完成模型返回waiting，版本过期或越界分数隔离，无效评分或质检失败返回repair。评分绑定、有效性和disputes由调用方投影，不能传未校验报告。
- `server/decisions/revision.ts`：`decideRevision(kind,budget)`。认证/额度等待恢复；暂时服务错误只有显式技术重试上限才重试；材料、题目、rubric/评分分别返回步骤2/4/6；规则变化和未知问题隔离。内容返修默认三轮，调用、有效耗时预算按显式配置检查。函数只作建议，不更新任何workflow。
- `server/reporting/usage.ts`：`calculateApiCallCost`、`summarizeApiCosts`。只含`billing=api_key`请求；套餐排除。输入、输出、缓存读写token按提供的单价计算，不同币种分组；调用ID去重，missing usage/price、计价币种不符及套餐排除有明确原因。缓存写入有使用量但缺缓存单价时费用未知。
- `server/reporting/metrics.ts`：`summarizeProduction(rows)`。按工作流唯一计数，使用最新输入版本，阶段成果不跨失效版本沿用；有效评分条数独立统计，不与合格题目混算；重复导出以工作流已导出布尔值计一次。
- `server/reporting/xlsx.ts`：无新增运行依赖生成XLSX，长单元格拆列并保留完整文本，数据以字符串写入避免公式执行，清洗非法sheet名并处理重名。
- `server/reporting/results.ts`：`buildResultWorkbook(records)`组装成果汇总、按批次拆分的答案/逐项评分、返修/API费用工作表。供主智能体从数据库结果投影后调用。

新增针对性后端测试18项、52个断言全部通过；包含XLSX真实生成并由openpyxl读回检查结构和长文本。`bunx --no-install tsc --noEmit`通过。测试命令：`bun test server/decisions server/reporting/xlsx.test.ts server/reporting/usage.test.ts server/reporting/metrics.test.ts`。
