# 第五期法务出题 skill 后续优化清单

日期：2026-10-10。

状态：第1节普通重出反馈方案已被[从零出题方案](2026-10-10-fresh-authoring-desktop-alignment.md)取代，不再作为当前实现要求；skill 优化点仍是后续计划。本文没有修改 skill、评分记录或业务数据，也没有调用模型。清单以当前 skill、现有方法材料、系统调用边界及用户最新决定为依据。项目 `materials/` 不自动成为任何 Agent 的输入。

## 1. 重新出题时的评分记录规则（已被取代，仅留历史）

这是普通“重新生成题目”队列的输入选择规则，不属于出题 skill 的专业方法。显式启动的自动返修链继续沿用其冻结的 `revision.evidence`，本次未调整。用户确认的普通重出逻辑如下：

1. 当前题目版本没有有效的“不通过”评分时，重新出题走普通流程，不附评分历史。
2. 当前题目版本有有效评分且达标判定为不通过时，找出造成不通过的评分记录，最多附三条给出题 Agent。
3. 通过按用户设定的工作台口径判定：每个必需模型的百分制得分必须严格低于该模型阈值；等于或超过阈值即该模型不通过。多模型时任一模型不通过，整题进入返修。

实现时，“评分记录”应指独立评分任务，而不是第七步反复生成的达标判定记录。仅选评分有效、答案与评分均成功、且题目版本／rubric 版本／附件绑定一致的记录；按实际不通过的模型过滤，按评分任务去重，再取最近三条。每条携带对应完整答案、逐项评分报告、分数、阈值及版本引用。`pending`、无效或有争议的评分不能冒充不通过分数。若有效不通过记录不足三条，则全部附上。

原实现曾取最近三条第七步成功记录，没有按模型不通过状态筛选，也没有按独立评分任务去重。现已修正 [authoring/jobs.ts](../../server/authoring/jobs.ts) 的 `readAuthoringEvaluationFeedback()`：要求当前第七步结果为 `repair`，只选该题版本中状态为 `not_passed` 的模型记录，按评分尝试 ID 去重，最多三条；再校验完整答案和评分文本可用。第七步 `waiting`、`accepted`、评分无效或详情绑定失败时不附历史。第七步任务行 `status='succeeded'` 不足以说明业务结论通过或返修，具体结论读取 `result.decision`，见 [decisions/jobs.ts](../../server/decisions/jobs.ts)。

## 2. Skill 优化点清单

当前 skill 已经覆盖大量必要设计原则。下面的“优化”重点是收敛冲突、让已有原则在实际起题和返修时更可执行；不是把每条都变成硬性要求。

| 优化点 | 现状与证据 | 建议完善 | 优先级 |
| --- | --- | --- | --- |
| 1. 材料来源与适用性 | 入口规定 `materials/` 仅在用户明确要求时读取；其中历史准则将 15–20 条写成硬要求，而当前 skill 不设固定条数。历史评分整理稿也标明不是官方原文。 | 保留当前“只按 skill 出题”的默认边界。若以后吸收材料，逐份核对来源、日期、适用项目和是否与当前用户决定冲突；只把已确认仍有效的方法改写进 skill，不让整目录直接覆盖 skill。 | 高 |
| 2. 返修反馈的使用 | 评分规范要求按有效记录归因；作者反馈提示也要求核对版本并回到附件、skill 复核。系统筛选已按第1节收敛，skill 可进一步明确如何分析传入的失败证据。 | skill 说明如何分析已传入的失败证据：先核对版本和附件，再逐项区分模型漏做、题目可绕过、rubric 错误、输入异常；只修有证据支持的原因。明确记录筛选由系统完成，Agent 不自行把等待或无效记录当失败。 | 高 |
| 3. 高分原因与返修动作一一对应 | skill 已反对“分数高本身就是题目缺陷”，但作者可能仍把“降分”误解为唯一目标。 | 把归因写成紧凑的分支：作答正确则检查必要工作是否已充分；核心工作可被套话绕过则补结果要求或依赖；rubric 错误先修标准；版本／附件异常先修输入。没有证据时保留原设计。 | 高 |
| 4. 题目任务与工作台能力对齐 | 工作台作答只提供题面和允许的脱敏附件，要求答案为文字且不执行工具；skill 已禁止把纯文本任务写成文件交付或卷外操作。 | 每次构造任务前对照当前作答能力和输入内容，确认所有必需工作都能凭题面、附件和明确模拟条件完成；不要把真实查询、联系第三方、法院操作、文件生成或工具运行当作模型必须完成的步骤。 | 高 |
| 5. 题面把核心工作落实为可核对结果 | 设计方法已要求逐项处理、核算、条件变化、办理文本及成果间核对，并说明不固定凑齐。 | 继续保留按材料选用的原则；审稿时把“需要做什么”对应到答案里的具体结果。删去只增加篇幅、没有改变业务决定或后续办理的要求。 | 中 |
| 6. 难度链条与考点覆盖 | skill 已规定按独立必要结果定条数，不设配额；强调复合判断、任务依赖和简化答案覆盖检查。 | 对核心工作做一张短的内部映射：材料依据 → 必须判断 → 结果如何改变决定 → 对应考点。它用于发现漏项和重复项，不作为新产物，也不向作答模型泄露。 | 中 |
| 7. Rubric 独立性与重复计分 | 现有规则已要求一条一事、合并重复判断、拆分独立结果、接受实质等价表达。 | 再明确检查两个考点是否可能由同一句事实陈述同时拿分；若是，确认它们是否真在检查不同后果。上游错误只有在下游确有另一项独立判断时才再次扣分。 | 中 |
| 8. 作答思路与标准答案的职责 | 两者已纳入数据库题包，评分会读取；作答模型不读取它们。 | 明确作答思路负责解释推理路径，标准答案负责提供完整、可复核的示范成果；二者需与题面、附件和 rubric 同版一致。它们可以复杂完整，但复杂度本身不加分；不得把仅存在于标答的要求变成 rubric 隐含标准。 | 中 |
| 9. 示例与模板的迁移风险 | skill 使用案例集和固定字段模板；案例可能使 Agent 复制某类债权／执行题。 | 每个示例标明哪些结构可迁移、哪些事实和任务不能照搬；对模板做替换检查，确保换业务后不会继续强制特定主体、付款、和解或执行场景。案例不作为成绩证据。 | 中 |
| 10. 成题与实测边界 | skill 已将 skill 修改、成题落实、真实难度验证分开，也要求报告有效评分和版本。 | 每轮复盘都写清是静态自检、真实作答还是有效评分；题面或 rubric 变化后重新作答评分，不拿旧题答案宣称新版难度。没有实测就标记未验证。 | 中 |
| 11. 资料索引和重复规则 | 入口、方法、评分规范、自检表和案例集有相互引用；后续修改容易重复叠加说明。 | 每条强制规则只设一个正文归属，其余文件用短链接引用；修订后检查术语“通过／返修”“有效／无效评分”及输入边界一致。 | 低 |

### 应保留为边界、不应加入的规则

- 不把 18–20、20 条、目标 35 分或固定情景数写成通用硬指标；条数由独立必要结果决定。
- 不要求每题都含复杂计算、多个方案、履行变化、可执行条款或大量附件；资料不支持时不得制造。
- 不把模型分数当作唯一质量指标，不为压分收紧合理答案，也不把低分当作出题有效的证明。
- 不让作答 Agent 读取 skill、rubric、作答思路、标准答案或历史评分；不让独立评分 Agent 读取项目 skill、目标分数或作答模型身份。
- 不把全部 `materials/` 同时提供给各 Agent。出题侧只读取当前 skill 和本题实际绑定的脱敏附件；只有用户改变边界并明确指定时，才评估某份项目资料是否适用。

## 3. 实施顺序与验收

1. **已修出题历史选择逻辑。** 静态检查当前实现是否按第1节筛选，并保持普通流程不附无效或旧版本历史。
2. **后续按优先级完善 skill。** 优先处理材料适用边界、失败反馈归因、文本作答能力和考点映射；其余保持简洁，不重复现有规则。
3. **再用真实任务验证。** 用新题确认题面、rubric、作答思路、标准答案及附件版本一致；得到有效评分后才能判断难度是否变化。分别报告记录传递正确性、成题质量和模型分数，不相互替代。

本文件是优化清单；评分反馈筛选逻辑已改代码但未运行测试或实际出题验证，skill 尚未按本清单继续修改，也未通过真实模型测评。
