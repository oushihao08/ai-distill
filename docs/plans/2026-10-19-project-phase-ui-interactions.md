# 主项目与期次工作台交互收口计划

## 目标

让工作台页面准确表达当前的数据边界：主项目是跨期身份，期次是独立题目与评测工作区，全局材料库保存可复用材料包，期次材料表保存本期加载和使用关系。修正旧的“一个项目一切配置”页面语义，使模型、材料与 skill、项目编辑入口符合这套边界。

本轮确认的具体范围：材料包是全局资产，不属于任何项目或期次；本期表只表示加载了哪个全局包版本，使用/提交状态在主项目范围跨期累计。规则资料由主项目各期共享，不跨主项目共享。Skill 有主项目默认版本；期次可在本期工作区创建覆盖，未创建时使用主项目 Skill。题目、模型设置和评测结果仍属于各自期次。本轮用期次 `skill/` 目录表达覆盖，不新增数据库字段或迁移。

## 方案比较与选择

1. 全面重做主项目、期次、材料库和详情页：改动面大，现有材料关系表和材料详情入口已经可用，收益不足以抵消回归风险。
2. 保留现有页面与 API，只修正入口归属、错误文案和期次身份编辑路径：覆盖当前已证实的交互缺口，不改变业务执行契约。**选择此方案。**
3. 为共享 skill、模型或材料重建一套主项目 API：目前项目 API 已能读取共享规则目录，模型与评测策略也明确以期次为键；没有证据证明需要新增存储或 API。

## 实施步骤

1. 修正路由与两个列表页的层级表达、导航高亮、搜索及空状态；让主项目改名调用既有接口。
2. 拆清期次身份编辑与期次业务配置编辑：新增期次保留自动期号；修改期号/期名使用专用接口；常规项目编辑不修改期号或共享 skill 路径。
3. 收口期次详情设置区：标签和标题明确显示本期/主项目共享范围；材料库型期次只显示本期材料关系表及全局材料详情链接，不显示不可用的旧来源目录同步；legacy 期次保持兼容入口。规则资料与 Skill 弹窗分成“主项目共享规则资料”“本期 Skill”“历史来源”；清楚显示 Skill 当前来源。
4. 本期 Skill 通过期次工作区的 `skill/` 目录覆盖主项目默认 Skill；出题快照与阶段钩子读取同一个生效目录。候选采用仅使当前期次导出过期；共享 Skill 的修改仍影响该主项目所有期次的新任务。
4. 更新 web 页面/组件 README，按项目要求做类型与差异检查，并在现有本地服务可用时只读走查主项目→期次→本期材料→材料详情及设置入口。不重启服务、不迁移数据库、不发模型任务、不改题目或材料数据。

## 接口与数据边界

- 计划中预计只调用现有 API：`GET /api/project-groups`、`GET /api/project-groups/:id/phases`、`PATCH /api/project-groups/:id`、`PATCH /api/projects/:id/phase-identity`、既有项目设置与材料库读取/更新接口。
- 若发现前端无法正确使用现有 API，先定位契约差异；仅在此类差异被证实后修改 API，共享类型与调用方同次核对。
- 不改 project/phase ID，不复制或删除期次；不更新题目、工作流尝试、答案、评分、归档、材料版本或永久使用记录。
- 作答模型目录和本期模型集合的保存语义不变；本期 Skill 采用只写入当前期次目录，主项目默认 Skill 不被覆盖。
- 全局材料包表与本期加载表是不同实体，继续分别显示；不合并、不增加第二份全局材料表。
- 旧 `/projects/:id` 与 `/workflows/:id` 链接保持有效；legacy 目录流程不自动迁移。

## 验收标准

- 用户从主项目页可以打开、创建或编辑主项目；期次列表显示正确的期号与期名。
- 编辑期次身份走专用身份接口；存在排队/运行任务时，页面能显示服务端冲突而不误报保存成功。
- 分期编辑只保存业务说明和标签，不发送材料来源目录、材料后端、工作区或跨期共享 skill 字段；未分期旧项目仍可编辑和同步原目录。
- 本期作答模型及 Codex 设置明确显示范围；配置仍写入当前 `projectId`，没有更改模型值、阈值、历史结果或其他期次设置。
- 期次不出现 legacy 来源目录同步控件；保留的旧目录仅作为历史来源显示。本期材料表包名可进入材料详情，详情的材料文件、使用与提交、处理记录标签可达。
- 顶部导航在主项目、期次、项目详情和题目详情路由上状态正确；已有详情深链接仍可访问。
- 主项目和期次页面不重复展示第二份全局材料清单；每期隔离、跨期防重和永久使用状态语义不变。
- 材料库说明材料包不从属于项目/期次；本期材料表说明其保存加载关系；规则资料主项目跨期共享，Skill 按本期覆盖、主项目回退的规则显示。

## 自审

- **遗漏检查：**覆盖列表、编辑、详情、导航、材料加载/详情、作答模型、共享 skill、legacy 兼容与旧链接；不把页面上的项目称谓误当数据库项目级作用域。
- **反例检查：**主项目默认 Skill 与本期 Skill 覆盖不是本期模型设置；期次没有有效覆盖时须回退默认 Skill。全局材料清单与本期材料关系也不合并。

- **最小性检查：**方案 2 不需要迁移、服务重启或新数据库实体；若类型与差异检查发现契约不匹配，再只修相应前端/API边界。

## 第二轮：本期材料与题目链路修正

### 复查结论

上一轮的期次基础交互已完成，但继续走查代码后发现共享材料库的建题链路尚未完整迁移到新 UI：

- `ProjectLibraryMaterials.vue` 已经是本期材料表，但表内仍展示材料包/版本 UUID，建题只提交题目名称与空标签，未把已有的角色、场景、方向、等级和标签设置交给 API。
- 删除本期引用有现成恢复接口，但页面没有入口；移除后的记录无法从本期页面恢复。
- 题目列表只按 `source_workflow_id` 识别材料包来源。共享库建题使用 `question_library_sources`，不写该旧字段，因此会被显示为“旧题目目录”，并出现不适用的入库/脱敏操作。
- 分组期次保留 `legacy` 后端兼容值，项目页仍展示旧入库/脱敏卡片。旧数据需继续可追溯，但这些步骤不应作为新期次主流程入口。
- 打开本期材料时会等待候选材料列表；候选接口固定读取第一页100条。使用记录接口还会一次取回所有历史事件，即使用户没有展开历史。
- `/api/projects/:id` 列表使用 `w.*`，将本页未使用的 `source_manifest`（本次实测约46.5KB，含本机来源路径）一并返回。
- 建题重试重复风险复查后不成立：服务端按规范化输入摘要查找并复用已建题，摘要包含题目设置和材料版本；不改这段逻辑。

本机 HTTP 只读样本：项目详情首轮响应约6.37秒/218,895字节；材料候选首轮约5.82秒、再次约0.7秒；已加载材料约0.4秒；使用记录约1.04秒并包含56条历史事件。冷/热时延波动明显，不能把首轮耗时直接归因于某条SQL。本轮针对可证实的页面等待和无用数据做定向调整，并重测相同接口。

### 实施步骤

1. 分组且启用材料包模式的期次隐藏入库/脱敏主步骤卡片和旧的“从旧材料包建题”入口；旧材料记录留在折叠的历史区域供追溯。
2. 精简本期材料表；用“加载材料”弹窗支持服务端搜索/分页，候选列表按需加载。每行提供材料详情、版本管理、使用记录、建题和移除；移除历史支持恢复原引用。
3. 用建题弹窗收集题目名称、场景、角色视角、出题方向、目标等级和本期标签，并完整发送到既有 `CreateLibraryQuestionRequest`。
4. 列表 API 为共享库题目补齐材料包 ID/名称；题目与达标题目列表正确链接材料详情，且不为共享库题目展示旧入库/脱敏操作。
5. 使用记录列表只读状态摘要；打开单条记录时再读取该记录的事件，避免首次加载整期历史。
6. 项目列表投影不返回未被该页面使用的 `source_manifest`，保留题目详情页仍需的来源清单接口。
7. 先写并运行对应后端失败用例，再实现；运行定向服务端测试、前端类型检查、根级检查和差异检查。对已有本机 API 做只读时延/响应体复测；不迁移数据库、不调用模型、不写业务数据。

### 验收标准

- 分组期次的主步骤卡片只显示出题至归档；旧入库/脱敏记录仍可折叠查看，旧题目详情与未分组 legacy 项目行为不变。
- 新材料加载不阻塞期次首页的初始渲染；候选服务端分页/搜索生效，第一页之外的候选可继续读取。
- 材料表无长 UUID 和内嵌完整历史；详情链接、版本选择、状态查看、移除及恢复均使用本期原有关系 ID 和 If-Match 版本。
- 建题请求保留全部六类设计输入；API 返回的成功题在题目表显示真实材料包名称/详情链接，并使用4–8流程操作。
- 默认加载使用记录不查询事件明细；用户打开记录后只加载所选使用记录的事件，返修/提交状态仍保留原因、证据和乐观锁。
- 项目详情列表响应不含 `source_manifest`；题目详情仍可读取并展示原始来源清单。
- 定向后端测试通过；前端类型检查、根级检查及 `git diff --check` 通过。与本机 HTTP 样本同口径比较耗时与响应体；若远端数据库时延仍波动，区分代码收益与外部时延，不宣称未测得的提速。
