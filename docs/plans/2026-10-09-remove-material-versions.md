# 移除材料版本机制

用户要求从数据库、后端和前端全面删除材料版本号，题目出题输入仍为当前附件的数据库脱敏全文与冻结项目规则。

## 实现范围

1. 撤除工作流、材料、执行尝试、返修链的 `input_revision`，导出的 `workflow_revisions`，以及接口、快照、日志、报表和界面中的材料版本字段。
2. 当前附件按 `materials.deleted_at IS NULL` 读取。移除和替换保留历史附件记录及原件；同步来源目录后刷新附件，不合并已移除材料。
3. 附件更新在工作流行锁内取消活动任务、重置当前步骤并终止旧返修链，使相关导出失效。并发页面编辑核对已有附件 ID，提取／脱敏检查附件集合和指纹；出题、作答、评分继续校验原有任务 ID、题目与 rubric 绑定。
4. 追加 `027_remove_material_versions.sql`，保留原件、文本和执行历史，标记旧附件移除；取消活动任务，保留已完成入库／提取，重置脱敏及后续当前状态。历史迁移和证据不改写。

项目规则版本、题面／rubric 指纹、内容返修轮次与材料版本不是同一机制，继续保留。

## 核对与执行边界

- 静态核对运行源码不再依赖材料版本列；查询参数、共享类型和 Vue 消费者同步调整。
- 类型检查与修改前基线对比；既有测试和人工脚本同步适配契约，但未经本轮授权不执行测试、lint、开发服务或真实模型调用。
- 迁移需明确目标数据库；部署时停止旧 API／worker，再应用此迁移并切换代码。不运行顺序应用所有未登记迁移的通用入口。
- 实际数据库迁移、服务重启、API／浏览器业务验收须单独取得证据，代码改完不代表运行态已切换。
