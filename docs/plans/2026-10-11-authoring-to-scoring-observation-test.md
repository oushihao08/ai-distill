# 普通出题至评分的观察与桌面 Codex 对照测试计划

执行状态（2026-10-11）：按用户更正，本轮六题的出题、作答、评分和达标判定均通过正式后端 API／worker 完成，结果见[运行证据](../evidence/2026-10-11-backend-authoring-to-scoring-run.md)。历史桌面会话已作只读对比，但输入并非同一版本，故严格同输入桌面对照项未通过；不得据本轮分数差认定后端与桌面能力等价或不等价。

## 目标

用一题的正式工作流完整观察普通出题、模型作答、独立评分和达标判断。记录中途错误及恢复过程，并将后台 Codex CLI 的实际输入、配置和工具行为与同条件桌面 Codex 对照，判断差异具体发生在哪一层。分数用于比较结果，不单独证明执行方式或题目质量有问题。

本计划是测试方案，不代表已派发任务或已通过验收。执行真实模型流程会写入工作流尝试和业务结果；须由用户明确启动。数据库、worker 和模型服务只核对运行状态，不迁移、不重启、不改评分规则。

## 已知基线与待验证项

- 当前普通出题代码走 `fresh_authoring`：每次新会话，项目工作目录，读取正常用户配置和项目规则，完整文件／网络权限，不注入历史题目、答案、评分或个人记忆；任务明确给出本次数据库脱敏附件和 skill 路径。
- 普通作者调用会保存私有 `request.json`、`events.jsonl` 及输入指纹；配置参数、工具清单和工具探针不等于真实任务中工具已启动或实际使用。
- 当前数据库脱敏附件是权威输入；临时附件正文文件在作者调用完成后清理。输入索引及调用事件保留。
- 作答由独立模型 API 执行；评分是新会话，使用题面、rubric、数据库脱敏附件、匿名答案和评分提示词，不读取出题思路或标准答案。评分条目 ID 和分值等由程序校验，无效评分不进入达标判定。
- 桌面 Codex 与 CLI 的逐项工具等价、同一案件下出题质量差异、以及完整链路当前运行情况仍待本轮证据确认。

## 测试对象与对照条件

选择用户指定的一个当前可执行题目及其当前附件和 skill。正式跑之前冻结并记录：项目／题目 ID、附件数据库 ID 与 SHA-256、skill 文件指纹、步骤提示词原文及指纹、Codex 模型和推理档位、候选作答模型、评分配置、项目达标线、应用构建版本和服务进程状态。不得改提示词、skill、rubric、评分门槛或附件来迎合结果。

生成两个互相独立的新作者会话：后端正式流程一份、桌面手动 Codex 一份。两边使用同一版本的脱敏附件正文、同一 skill 文件、同一句出题命令、同一模型与推理档位，以及可核实的同一用户配置、项目规则和工具来源。桌面端同样使用新会话，不读取旧聊天或记忆；其任务输入只含指定附件与 skill。记录无法匹配的设置，标为对照限制，不假称完全同条件。

两份题包各自保存后，使用相同作答模型配置分别作答；再以匿名且盲化的方式，按各自题面及 rubric 进行独立评分。系统正式链路仍要完整走完其中指定的一题并触发达标判定；桌面生成的对照题包通过隔离副本进行同样的作答与评分，不覆盖正式工作流产物。不得让一个作者会话看到另一份题包、答案或分数。若模型 API 配置无法保持一致，暂停分数横向归因，但继续收集可完成的调用链诊断。

一次配对用于定位可观察差异。若发现明显差异但无法排除生成随机性，先复核输入和事件；只有用户确认需要时再增加配对次数，不预设大量重复。

## 执行步骤与每步观察项

| 阶段 | 执行动作 | 必须记录和检查 |
| --- | --- | --- |
| 0. 开始前核对 | 查看指定 workflow 当前版本、可见步骤状态、附件与模型设置；检查数据库／API／worker 是否可用及当前 build。确认题目没有活动尝试，附件和 skill 与本次目标一致。 | 运行环境、服务状态、workflow／project ID、输入指纹、现有活动任务、开始时间。数据库不可用或有并发活动尝试时暂停派发并记录阻断点。 |
| 1. 普通出题 | 通过正式第四步入口派发一次，等待作者结束。桌面端使用匹配输入创建独立会话。 | attempt_id、call_id、Codex session/thread ID、模型／档位、配置目录、cwd、实际 argv 与 stdin 摘要、记忆隔离参数、输入指纹、实际工具调用及退出／完成事件；记录耗时、重试、错误。确认没有历史反馈注入，并核对绝对路径确指本次附件与 skill。 |
| 2. 题包校验 | 读取两边完整私有题包和公开题面；核对题目、附件引用、rubric、私有标答与 Markdown/JSON 一致性。 | 输出完整性、附件绑定、是否引用未给事实、是否存在无法作答或答案泄漏；工具调用是否对题目判断产生可追溯作用。只记事实，不以调用次数作为质量分。 |
| 3. 模型作答 | 按正式流程派发同一候选作答模型；对桌面对照题包以相同模型设置运行对应作答。 | answer attempt/call ID、模型及参数、发送内容边界、原始完整答案、HTTP／供应商状态、结束原因、重试与时长；确认模型未拿到 rubric、标答或 skill。记录失败阶段及安全原因码。 |
| 4. 独立评分 | 正式流程为答案派发评分；对照答案用相同评分模型、提示词和匿名输入约束评分。 | scoring attempt/call ID、评分配置和输入指纹；rubric ID 是否逐项且恰好出现一次、逐项分值与满分、理由及答案原文证据、合计总分；评分上下文是否意外含思路／标答／模型身份。原文保存以便复核，不以预期分数纠正评分。 |
| 5. 达标判定 | 等所有必需答案和评分终结后，观察正式流程自动判定；对照结果只用同一项目规则离线比较，不写回正式 workflow。 | 每个模型分数、门槛、判定状态和理由；确认无效／缺失评分不能被当作通过，判定所用题目／答案／rubric 版本一致。 |
| 6. 收尾核查 | 按 workflow 与 attempt ID 拉取数据库状态、普通日志、Codex 私有执行记录和产物清单，交叉核对完整时间线。 | 入队→领取→调用→校验→提交的时间线；缺失事件、重复调用、状态悬挂、晚到结果覆盖、临时附件正文清理、旧数据混入、输出落点以及服务是否仍健康。收集内容限制在本机受限证据目录。 |

遇到问题按事实定位到输入构造、队列／worker、Codex CLI 启动、工具初始化／执行、输出校验、作答 API、评分校验、数据库提交或达标计算。能在已授权范围内明确复现且属于小型流程缺陷时，先保存失败证据，再最小修复并运行针对性测试；之后从新尝试重跑受影响阶段，记录新旧 attempt 关联，不覆盖失败记录。问题涉及数据绑定／隔离、服务或数据库环境、无法解释的模型内容差异，或需要改变规则／输入时，暂停依赖步骤并报告，不自行改业务标准。

## 与桌面 Codex 的差异判定

逐层比较，不把总分差直接归因给 CLI：

1. **任务状态与上下文**：是否新会话；是否出现历史任务／聊天／个人记忆；是否只主动提供当前数据库脱敏附件与指定 skill。
2. **启动配置**：二进制版本、模型、推理档位、配置来源、项目规则加载、cwd、权限、网络、MCP 配置与实际初始化结果。
3. **工具行为**：分别记录“配置可见”“工具初始化成功”“本任务实际调用成功”。比较文件读取、shell／计算、网页检索、MCP 或 skill/CLI 路径的真实调用及输出；不要求两边调用相同工具，只看两边是否能完成相同必要工作。
4. **提示与交付**：逐段比较用户命令、应用额外指令、skill/附件路径和交付契约；检查是否存在后端专属指令改变了出题目标、研究深度或表达方式。
5. **产物和评分**：按题包结构与实质判断对照；评分报告逐项对照相同答案证据及 rubric。区分作者生成差异、作答随机性、评分差异、规则门槛和系统故障。

证据优先级：私有 `request.json`／`events.jsonl`、数据库尝试与结果、普通日志、桌面会话中可见的配置和调用记录、最终产物。工具列表只证明声明或配置，不证明执行成功；一次工具调用成功不证明所有桌面工具都等价。

## 记录格式与问题台账

结果存为 `docs/evidence/` 下注明日期的 Markdown 记录；私有题包、答案、附件正文、Codex 私有事件及可还原用户材料不复制到该目录，保留在已有受限存储位置并只引用 ID／路径／哈希。记录至少包括：

- 环境、build、题目／workflow、输入与配置指纹；后端与桌面任务关联 ID。
- 各阶段开始／结束时间、状态、尝试／调用 ID、错误原文可公开部分和安全错误码。
- CLI 会话的实际配置和工具证据；桌面对照能取得的对应证据及无法观测项。
- 两份题包的差异、每个作答模型答案来源、逐项评分及原因、总分／分数率、达标结果。
- 每个问题的发现阶段、复现条件、根因证据、影响范围、临时恢复／永久修改、重测结果及尚未确认项。

问题类别固定按实际原因填写：阻断／技术失败、输入或版本错配、Codex 配置／工具差异、作者产物问题、作答模型差异、评分校验或评分质量问题、数据库／worker／状态问题、达标判定问题、证据缺失。类别帮助定位，不预设根因。

## 验收标准

| 目标 | 通过证据 |
| --- | --- |
| 正式链路完整 | 正式普通出题、答案、独立评分、达标步骤均有同版绑定的成功终态和数据库记录；任何失败均有准确阶段和原因，且不会被误报成功。 |
| 评分可复核 | 每条 rubric ID、分数、判分理由、答案原文证据、总分和计算均能对应；评分输入边界符合隔离契约。 |
| 出题调用可追溯 | CLI 实际模型／档位／cwd／配置、任务输入和 session ID 可证；工具的配置、初始化、调用成功三层分别报告。 |
| 只给本次业务输入 | 后端没有注入旧题、答案、评分或历史反馈；请求指向当前附件和指定 skill，且数据库哈希与本次快照一致。发现超出任务范围的文件读取则列为问题并追因。 |
| 桌面对照有效 | 至少一对运行的案件材料、skill、命令、模型／档位、候选模型和评分条件逐项核对；不等条件明确标注，因此分数结论不过度归因。 |
| 问题被完整登记 | 所有中途问题都有阶段、证据、影响、处置和重测状态；无问题也需以完整时间线和检查结果支持，不能只写“顺利”。 |
| 能力对齐结论准确 | 分开给出已一致、实测差异、无法比较／未观测三类结论；不以单次高低分宣称全部等价或不等价。 |

## 本次不验收

- 不能以一题配对推断所有题型或长期平均质量；只有差异无法排除随机性时才建议额外配对。
- 不验收所有桌面专有工具与 CLI 的永久等价，不测试未参与本任务的 MCP。
- 不改提示词、skill、评分标准、达标阈值或模型集合；发现可能需调整时先作为有证据的问题单独提出。
- 不验收发布、导出、远程部署、数据库迁移、worker 压力／故障注入和服务重启。
- 单元测试、日志探针、工具列表和静态源码均不能替代本计划的真实端到端证据。
