# 项目源码注释与目录说明计划

## 目标

让维护者和每次进入项目的 AI 都能快速理解源码职责、关键方法及其使用方式、目录边界和维护方式。源码注释与目录说明是两类内容：JS／TypeScript／Vue 文件的文件头注释要说明文件职责、主要公开入口／方法及调用场景；目录用途写在该目录的 `README.md`；根 `AGENTS.md` 约束后续 AI 每次改动时遵循这些规则。

Markdown 文档本身不要求逐文件添加 HTML 注释。项目资料、规则输入和已冻结快照不得为满足注释覆盖率而改写；若目录契约禁止新增 README，由最近的非输入父目录 README 说明该目录用途和边界。

## 执行步骤与验收

1. **已完成｜清点源码**：纳入项目自有 `.js`、`.ts`、`.vue` 等可维护源码，排除依赖、构建产物和缓存；识别自动生成文件。按实际文件清单逐项核对文件头注释。
2. **已完成｜补充文件级说明**：每个源码文件头须说明职责、主要公开入口／方法及调用场景。大型文件只列关键入口；Vue 文件说明主要 props／事件及所在页面用途；测试文件说明测试对象和主要验证边界。避免罗列私有辅助函数或逐行复述实现。
3. **已完成｜补齐目录说明**：所有可安全维护目录均有 `README.md`；题目来源、规则输入及不可变快照目录由最近的非输入父目录登记，未改变来源清单、文件指纹或快照校验。
4. **已完成｜固定 AI 规则**：根 `AGENTS.md` 说明源码文件头注释必须交代职责、关键入口和使用方式，目录 README 及每次修改前的必读文档要求。
5. **已完成｜差异复核**：核对文件头覆盖、目录索引和维护文档链接，`git diff --check` 通过。另有未跟踪用户资料中的 6 个缺失文件链接，作为既有资料问题记录并保留原文。按项目规则未运行测试、lint、服务、迁移或模型调用。
