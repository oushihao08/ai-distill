# 第五期公司法务出题 skill 修改与完善计划

日期：2026-10-10。

状态：M01—M09 已落实于现有八文件；P6 成题验证、P7 真实难度验证待后续执行。本文件给维护者阅读，位于 docs/plans，不放入 skill 或题目附件目录，不作为作答、评分 Agent 的输入。

## 1. 目标、依据与完成边界

本次要解决的问题是：现有 skill 已要求独立求解、规则联动、条件变化、具体成果和中立评分，但部分案例骨架仍比较抽象，简化答案能否绕过核心工作的检查也未落实到逐项结果。继续重复“充分思考、增加复杂度”难以说明作者究竟该怎样改题。

修改目标：使出题者能够从真实材料和明确题设中找出必要专业结果，将它们组织为可作答、可核验的业务任务，并让 rubric 区分“提到了原则”与“完成了工作”。专业结果包括证据采信、权利范围、程序路径、条款及办理条件，也包括有完整输入支持的计算；不将法务题统一改为计算题。

当次难度目标：争取指定作答模型在有效、中立评分下得分约35分。该数字只留在当次出题／返修任务及实验记录中，不写入通用 skill、题面、标答或评分提示词。20个0/1考点下，7项通过等于35分；18、19项分别按实际分母换算，不为凑35分增删考点。未约定“左右”的容差时，不自动把30—40分设为验收区间，也不改变工作台的严格低于配置上限规则。

已确认：现有方法中大部分加压原则已经存在；入口仍包含让评分任务读取本 skill 的引导，与当前系统的独立评分输入边界不一致。尚未确认：下面的改动是否会使指定模型降至约35分、是否增加有效作答时长。这两项必须分别取得实测证据。

本计划按三层交付，不能混报完成：

1. skill 完善：修改现有文本并通过语义、引用和覆盖检查。
2. 成题落实：使用一个具体题目及实际绑定附件，证明新方法落实到了题面、标答和 rubric。
3. 难度验证：在输入完整、同版、模型配置明确的条件下取得真实作答和独立评分。

不纳入本计划的改动：评分程序、模型配置、前端、数据库结构、原始附件、自动返修机制或新评分模型。文件阅读、附件拆分等程序问题若仍存在，应作为测评前置缺口单独处理，不能通过 skill 掩盖。

## 3. 修改项清单

每项“有效”指其有明确的任务构造或质量保障机制，不等于已经证明能降低模型分数。以下修改已落实于现有八文件；真实难度仍待测评。

### M01：纠正独立评分的适用边界

- 位置：SKILL.md 的 description、按任务读取表、输入边界；评分规范、自检清单、资料索引中的角色称谓和读取引导。
- 具体改法：删除“本 skill 用于独立模型评分”及让评分 Agent 读取 references 的入口；改为出题侧设计 rubric、审查评分有效性和复盘测评结果。独立评分输入明确包含用户设置的提示词，不含项目 skill、目标分数或作答模型身份。
- 为什么有效：消除额外规则进入评分的入口，避免出题目标成为判分方向，保证后续低分有解释价值。
- 方法：检索全部“评分／评分者／读取”相关段落，逐处判断是在约束题目质量，还是在要求评分 Agent 读 skill。只改后者及角色歧义，不删除中立评分、版本一致、合理等价解等质量要求。
- 验收：八文件无要求独立评分 Agent 读取 skill 的指令；出题侧 rubric 设计和测评复盘要求完整保留。该项不宣称降低分数。

### M02：将“先求解再出题”落实为专业结果记录

- 位置：SKILL.md 流程2、5；设计方法“按业务用途构成完整任务”。
- 具体改法：利用已有内部难点记录，为每个核心结果补齐“依据位置、需要作出的专业判断、正确结果或可接受分支、影响的业务动作、可核对产物”。先确定结果，再选择意见、条款、请求、底账等表达形式。
- 为什么有效：阻止先套文书标题，再用事实摘抄填充；让新增内容可以追溯到实际决定。
- 方法：在现有记录格式中补充缺失字段，不建新台账系统；正文只定义一次，入口引用。记录用于起草和核对，按现有规则临时保存或在任务上下文使用，不混入作答输入。
- 验收：每个核心考点能指向一个必要结果；“认真分析、充分考虑、注意风险”不能单独充当结果。非计算型判断同样适用。

### M03：把约束和条件变化变成实际求解要求

- 位置：设计方法“判断机制／更多必要思考”；交付规范“规则组合／条件重算”。
- 具体改法：约束进入题目前，说明它限制哪个动作或改变哪个候选方案；变化进入题目前，先独立求出变化前后受影响和不受影响的结果。已有规则足够时合并补强，不重复追加原则。
- 为什么有效：让权限、期限、履行、资源或费用真正参与选择；防止只多写一段“需要重新评估”。
- 方法：做删除或替换检查：拿掉该条件，是否改变可行范围、结论依据或后续动作？若没有，只能作为必要背景，不能当核心加压点。条件变化不必一定翻转最终推荐，但必须改变有业务意义的结果或必要判断。
- 验收：每个保留的核心约束／变化都有完整输入、合理依据及可核对后果；不固定情景数量，不强制连续付款、临界值或特定法律业务。

### M04：明确交付结果，同时撤去解法提示

- 位置：交付规范“将必要工作明确写入题面”；成稿模板 prompt 部分。
- 具体改法：题面写清需要决定的事项、处理范围、时点及交付结果；如实际需要办理文本，就要求提交具体请求或替换条款，而非只列文件名称。将“某文书日期有错、某权限有冲突、应采用某基数”等题目发现工作还给作答者。
- 为什么有效：既避免只交泛泛意见，也保留模型独立发现和裁决问题的必要性。
- 方法：逐句分类为业务目标、必要条件、交付要求、解法提示；删除或改写最后一类。真实业务方已经明确提出的问题不能为加难而伪装成未知，必须保留。
- 验收：只看题面就知道要完成什么，但不能直接读出问题位置和正确取舍；不依赖隐藏 rubric 才知道需交哪些核心成果。

### M05：细化“具体专业结果”的正向判分条件

- 位置：评分规范“考点核对具体产物”；成稿模板 rubric 部分。
- 具体改法：将含糊的“考虑了、识别了、分析充分”改为能在答案中核对的结果要求，明确该条是在评结论、专业依据还是办理条件。保持每项一个独立必要结果，接受合法且实质等价的路径。
- 为什么有效：防止模型仅提到关键词就取得尚未完成工作的分数，同时保护实质正确但表述不同的答案。
- 方法：先从完整正确成果提炼考点，再逐条验证题面是否布置或完成任务是否必需；两条若由同一句结论直接满足，检查重复计分；上下游只有新增独立判断才分别计分。
- 验收：无“3+5+4+4+4”等固定配额；不捆绑多个独立难点为一分；不因漏一个无关词归零；不因同一错误出现在多份成果而机械重复扣分。

### M06：把简化答案检查落实到逐项覆盖

- 位置：评分规范“必要工作量／考点覆盖”；入口核对强度；自检清单对应条目。
- 具体改法：按当前任务选择有代表性的简化答案，如只摘抄、全部待核、只讲原则、只有最终结论。逐项记录它实际满足了什么、缺少哪个必要结果、若能得分是否说明任务或 rubric 允许绕过。
- 为什么有效：把抽象的“不能靠套话”变成可观察的检查，直接发现评分与业务成果脱节的位置。
- 方法：简化答案必须是可信的捷径表达，不能故意写成明显错误来让检查通过。按当前标准诚实判定，不先规定它必须得多少分；若正确完成某项，保留其分数。只有核心工作可以被绕过时，才修任务或考点。
- 验收：给出具体条目及其未检验的专业工作；不能仅写“检查通过”。此检查仅证明结构性缺口是否存在，不是作答模型的实测成绩，也不进入独立评分提示词。

### M07：改写代表性案例，展示依据到成果的完整关系

- 位置：案例模板集，优先改善案例8（债权执行）和一个非计算主导案例，如案例4（效力／适用范围裁决）。
- 具体改法：复用原案例，在内部示范中展示任务输入、待决定事项、必要判断、专业结果、实际产物片段和对应考点；补充适用条件与不适用情形。使用明确标为模拟的条件，不把例子写成已经验证的真实试题。
- 为什么有效：一个债权案例加一个非计算案例能展示机制的迁移，降低作者把方法理解为固定付款计算题的风险。
- 方法：只扩写真正需要示范的复杂关系，替换原抽象骨架；在同例说明“去掉某条件后，不应再要求哪项工作”。不是每例都要求变化、计算、方案比较和条款同时出现。
- 验收：示范能够独立理解；引用的材料摘录和条件足以支撑示范中的结果。涉及具体法律结论时核对适用规则及官方依据；未核实的不写成唯一正确答案。不得复制到新题充当真实案情。

### M08：同步模板、索引和失败模式，消除规则重复

- 位置：题目模版、资料索引、失败模式与自检清单；必要时回删入口和参考文档中的重复段落。
- 具体改法：模板要求完整呈现“本题已选的必要结果”；索引按症状引向 M02—M07 的已有方法；自检加入“条件不影响决定、变化只改措辞、上游错误重复处罚、具体请求只给名称、题面泄露发现任务”等可识别失败模式。
- 为什么有效：解决规则正文严格、模板却引导摘要化交稿的问题，使作者在不同入口得到一致要求。
- 方法：一条规则只在一个主位置完整解释，其他文件简短引用；保留七章节结构及本期18—20个0/1独立考点约定。35分和任何暂拟覆盖配额不进入八文件。
- 验收：引用可达；同一概念无相反口径；替换行业、日期、金额或业务类型后，不会仍强制债权、付款或和解结构。

### M09：完善按证据返修与测评解释

- 位置：评分规范“先确认测评有效，再按证据返修”。
- 具体改法：分别记录模型真实完成、任务可被绕过、rubric缺陷、材料不足、输入／版本异常。每类对应一个修复选择；难度目标和作答时长分别观察。高分本身不作为任何一类缺陷的证据。
- 为什么有效：防止为了接近35分不断改变评价尺度，也防止同题名称掩盖题面、答案和 rubric 已换版。
- 方法：输入和规则先定版，再作答评分。比较发送方式时固定同一题目与答案；比较出题改动时承认题目已变，只固定模型配置和评估方式，报告新版本表现，不把旧答案直接套新题。同一版重复测评记录全部结果，不挑最低分。
- 验收：复盘能说明“改哪里、凭哪条证据、影响什么”；不承诺固定次数、时长或分数。若模型已正确完成且材料没有更多必要工作，转为报告材料上限或更换题材建议。

## 4. 推荐任务构造：按材料选择，不作为每题必选清单

此表是 M03、M04、M07 实施时可用的设计方向，不把任何一行固化为通用配额。

| 可选方向 | 成立前提 | 修改方法 | 为什么能增加必要判断 | 不适用时的处理 |
| --- | --- | --- | --- | --- |
| 跨材料裁决 | 不同记录之间存在需处理的效力、对象或时间关系，且依据充分 | 要求确定可采用范围及其办理后果，题面不先宣布哪份错误 | 必须辨别来源与适用性，不能逐份摘抄 | 无冲突或无裁决依据时，采用普通归纳或保留局部未知 |
| 多约束方案选择 | 多个条件共同影响同一决定 | 先判可行范围，再给推荐及必要条件，允许依据充分的多解 | 单看报价、时间或单项规则不足以形成方案 | 无必要冲突时不人为制造困难 |
| 履行后的结果更新 | 有完整、明确且有业务作用的变化条件 | 重新确定受影响的范围、状态、计算或请求 | 检验变化是否被传递到下游，而非重复原意见 | 不改变相关结果的变化不作为核心难点 |
| 程序或办理路径选择 | 材料支持不同条件下的动作范围 | 输出当前动作、不能办理的部分及恢复条件 | 泛泛“核实后处理”不能代替已可确定的路径 | 不强求唯一合法路径；必要条件缺失时保留分支 |
| 条款或请求拟定 | 业务确实需要可以使用的文本，输入足以起草 | 在答案中给出具体条款／请求及边界 | 必须把判断转为主体、条件和后果清楚的表达 | 不要求无关文书或虚构对外行为 |
| 条件或分段核算 | 日期、规则、口径及可用变量足够 | 求出具体期间、公式或数值，并与方案衔接 | 规则和采信必须落实到可复核结果 | 脱敏值只用符号或范围，不靠猜数增加难度 |

## 6. 验收标准及自我审核

### skill 修改完成的标准

### 具体题目与难度的后续验收

- 成题验收：每个核心结果有材料／题设依据；标答可独立复核；题面、标答、rubric与实际附件对应；没有为满足条数凑摘抄项或捆绑难点。
- 分数验收：使用已确定的作答模型及模式，原样保存答案；评分 Agent 不接收目标35分。报告逐模型原始分、满分、百分制和争议，不用跨模型平均掩盖某模型的高分。
- 稳定性：单次约35分只证明该次结果；若要声称稳定达到，需在获准预算内取得同版本重复记录并报告全部结果及范围，不选择最低轮次。
- 时长验收：只记录作答阶段的有效执行时长／可见步骤；不能把排队、评分或无意义重复阅读当必要工作量。
- 返修方式：先判断分数高的原因。若模型正确完成工作，只能在材料支持时增加必要专业任务；若任务被绕过，改依赖和交付；若 rubric 错误，先恢复正确评分；若输入异常，先修测评条件。
- 停止边界：在用户授权预算内迭代；材料不能支撑更多有效任务时，报告上限并建议更换材料，不无限加压，不承诺所有模型或所有轮次必达35分。

本计划的自审结论：修改项能够逐一对应现有缺口，实施后可以验证任务构造和评分覆盖是否改善。缺少实测，仍不能推导具体得分或时长。两者分别验收，避免将计划完成、skill修改完成和难度达标混为一件事。
