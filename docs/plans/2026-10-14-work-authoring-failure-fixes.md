## 目标与边界

让「Work法律全场景 - 首批筹备」的出题尝试在路径写错、产物缺失或超时时给出可定位的结果，并减少同类失败。沿用现有按项目配置的步骤提示词与阶段钩子，以及共用的 Codex 执行器；不把 Work 规则写进豆包等项目的默认路径。本计划不修改历史尝试、不自动重派题目，也不把内部文字题包认定为 Work 正式交付。

本计划只针对已经查明的出题执行故障；Work 的材料数量、正式等级、专家核定、文件交付、三模型作答和均分验收另按项目规范处理。

## 任务清单

1. **先核对最新状态和隔离边界。** 通过 API 读取这两道题的最新出题尝试、Work 出题与评分配置，以及豆包第五期对应配置。已有更新尝试时以最新尝试为准；不覆盖活动任务。核对当前项目步骤提示词、`workflow` 钩子和出题快照的实际来源，避免把旧失败重复当成当前失败。
2. **减少 Work 路径误用。** 在 Work 项目现有出题步骤提示词或其指定 skill 中，要求 Agent 只从本次交付清单读取实际附件与产物路径，复用路径原文或使用相对路径，不手抄 UUID；遇到 `ENOENT` 先对照本次清单核实再声称附件丢失。优先修改现有指引；仅在指引不足、且确有需计算或附加的项目专属输入时，才使用该项目的同步前置钩子。不得让钩子覆盖题面、Rubric、答案或步骤状态。
3. **改进共用执行器的失败定位。** 保留 `result.json` 缺失、无效、会话未完成各自的失败判定；把可公开的原因码和阶段写入尝试结果及界面已有错误入口，避免统一显示“出题执行失败”。不向普通日志或页面复制材料、题面、完整私有事件或凭证。检查路径错误是否来自 Agent 命令、输入文件准备还是程序文件读取，分别报对应阶段，不能一概归咎于附件丢失。
4. **处理超时但已有文件的情况。** 先量化本次会话在写出 `result.json` 后的耗时和必要操作，减少重复检查指令。超时仍保持失败；如要支持复用已落盘草稿，须走显式恢复流程：确认本次输入和配置指纹未变、文件来自该尝试、JSON 与附件引用合法、Rubric 符合冻结契约、渲染结果一致，并经过现有提交前绑定校验后才能入库。若确有正常题目仍因 30 分钟不足而失败，再增加有上限、按项目出题步骤设置并随尝试冻结的超时参数；不全局提高默认值，也不让文件存在代替会话完成或恢复校验。
5. **针对受影响题目处理重试。** 新代码和 Work 配置生效后，只对最新状态为失败、无活动出题尝试的题目按现有 API 单次重派；保留历史尝试。`L4-运输`、`L2-运输合同` 分别核对最终结果，不自动执行后续作答、评分或归档。

## 验收标准

| 事项 | 完成证据 | 本次不以什么代替 |
| --- | --- | --- |
| 项目隔离 | Work 新尝试冻结新契约与本项目出题指引；豆包仍冻结自身旧契约、旧步骤提示词和钩子配置。 | 只看配置页面或源码分支。 |
| 路径错误 | 模拟或实际出现错误路径时，执行记录能指出读取阶段与 `ENOENT`；Agent 不再因抄错 ID 把现有附件称为丢失。 | 仅修改提示词而未核对实际执行事件。 |
| 结果校验 | 缺失文件、无效 JSON／Rubric、未完成会话分别保留失败；成功题目必须有同尝试的有效结果、渲染文件和提交前绑定核对。 | 只看 `result.json` 存在，或只看 Agent 回复“完成”。 |
| 超时处理 | 30 分钟上限触发时仍明确记录超时；如实施恢复，必须展示逐项校验及同版绑定成功的证据；如实施项目超时配置，任务快照能读回实际值。 | 把未结束会话的草稿直接改为成功。 |
| 题目结果 | 两道失败题各有一次新尝试，并分别达到成功，或留下新的具体失败原因供处理；不重复创建派生题目。 | 将入队、运行、静态检查称为出题成功。 |

实施后按仓库规则核对相关后端行为的针对性验证、配置读回、实际执行记录及必要的文档变更；测试与真实模型重派须遵守届时的明确授权边界。本计划文档只定义修改范围和验收依据，不代表程序已修改或故障已消失。
