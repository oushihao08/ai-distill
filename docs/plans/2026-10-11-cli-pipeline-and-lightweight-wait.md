# CLI 流程重叠与轻量等待

## 目标与依据

当前操作 skill 要求同批所有题完成同一步后才进入下一步，使 Agent 与 API 通道交替等待。CLI 等待会返回并保留完整结果；后端长轮询每 250 毫秒查询一次。此次只减少阶段等待、状态数据量和轮询查询，不改变出题、作答、评分及达标规则。

## 任务清单

1. 操作 skill 改为同批逐题推进：读取当前批次全部题目的服务端状态，按各题下一授权且就绪步骤分组派发；其他题的活动尝试继续运行。保留固定范围、批次顺序、终点、失败跳过及不重试约束。
2. `/api/attempts/:id` 增加 `view=status`，SQL 不读取结果正文；默认接口保持完整返回。CLI `attempt wait` 默认使用轻量视图，只保留白名单元信息，`--full` 兼容完整等待，`attempt show` 继续按需读取。
3. 服务端等待查询间隔改为 1 秒，截止时间较近时缩短睡眠；请求取消及时唤醒，不取消持久任务。同步 CLI、Skill 和架构说明。
4. 定向单元测试覆盖投影、旧响应兼容、完整读取、轮询节奏、截止、取消、失败和多模型关联；检查差异。

## 验收标准

- 状态 SQL 不选择 `a.result`；轻量 CLI 输出不含题面、答案、评分正文，任务 ID、工作流 ID、步骤、状态及错误不丢失。
- 默认 HTTP 读取与 CLI `--full` 保留旧正文读取能力。
- 轮询最长睡眠 1 秒，不越过剩余等待预算，取消不等待睡眠结束。
- skill 明确逐题读取 `ready` 与活动任务后推进，未授权步骤、失败题、未知写结果及未完成任务不重派；本批全部终结后才进入下一批。
- Codex 配置、模型、工具、权限、会话、输入隔离、worker 并发及领取规则不修改。
- 本轮执行定向合成单测；不重启服务、不写业务数据库、不调用真实模型。不以单测或理论计算宣称百题实际提速、整机内存下降或 AI 编排已验收。
