## 目标与事实边界

目标是在已跑通的后端“出题 → 作答 → 独立评分 → 判定”上，修复确认的配置／交付问题，增加可核查的45分钟超时难度标记，不破坏普通流程，不削弱作者 Codex 的能力。

- 历史本轮六题均完成普通新出题、作答、评分及判定；题目3得50%、5得55%，判为需要返修，本轮未启动返修链。流程完成与题目达标分开。
- 最低分批次30/116，本轮44/120；两批题面、rubric及部分输入不同。尚无证据把分差归因于单一程序问题，本计划不承诺改程序就会降低分数。
- 六次作者出现配置字段忽略警告及共10次失败命令，但均有成功终态；警告不等于工具全失效，命令失败不等于最终题目错误。
- 历史 `project-folders.test.ts` 有5项失败；是否为旧基线未确认。实施前重新核对，不将历史结果冒充当前测试结果。
- 当前作者已有 `input/delivery.json` 渲染入口和JSON／Markdown一致性校验，不能重复造一套转换流程。
- 当前作答上限在 `answer-models/jobs.ts` 写为60分钟，并受显式返修剩余预算约束；llm-api使用 `stream:false`，不能仅靠请求耗时证明模型思考时间。
- 已核对供应商公开接口：OpenRouter 对支持的模型可在流式 delta 中返回 reasoning details，但部分模型不返回；DashScope 可在流式数据块中分开返回 `reasoning_content` 与答案 `content`，且依模型能力而异。文档证明存在可接入的信号，不证明当前项目选用的每个模型都会返回，也不提供通用的供应商内部耗时证明。[OpenRouter reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[DashScope Qwen streaming](https://help.aliyun.com/zh/model-studio/stream)。
- 资料来源写超过40分钟并另有得分要求；用户选择45分钟是稳健余量。本地“确认长时生成超时可免评分”规则与来源原文分别记录，不修改来源材料。

## 全程必须保留的行为

| 边界 | 保留内容 |
| --- | --- |
| 作者能力 | 指定项目cwd、正常用户配置、适用项目规则、完整文件读写／shell计算／网络搜索、已配置MCP。不通过关闭工具、忽略配置或收窄权限消除错误 |
| 普通出题 | 每次新会话、禁用个人记忆；只主动提供当前数据库脱敏附件、指定skill及步骤指令。不注入历史题面、答案、评分，不转成隐式返修 |
| 独立评分 | 保持匿名与同版绑定，不提供标答、思路、项目skill、目标分数；保留ID、分值及合计校验 |
| 既有正常流程 | 未启用新策略时，正常作答、评分、严格低于阈值判定及显式返修语义保持原样；普通步骤不自动推进 |
| 历史与输入 | 不改来源附件、脱敏正文、冻结题包、旧答案和分数；不批量重算或清空项目，不自动把失败补成通过 |
| 并发与存储 | 沿用既有API／worker／队列、任务ID及私有目录；不另建执行器、不提高并发、不扩大连接池掩盖问题 |

## 不破坏现有流程的发布约束

- **默认行为逐字节保持。** 未启用新策略时继续走现有非流式请求、现有60分钟上限、现有答案校验、评分、达标及返修路径；不改作者 Codex 的模型、档位、配置、工作目录、文件／网络／MCP权限或输入。
- **默认关闭且不自动写配置。** 页面读取缺省值不得创建数据库记录；新字段缺失的旧项目、旧 attempt 和旧评分按原规则解释。建议缺省请求上限为当前值60分钟、认定阈值45分钟、免评分关闭。
- **仅新 attempt 使用新设置。** 设置在提交/创建答案 attempt 时冻结；排队和运行中的任务不动态换配置，设置变化不追溯解释已完成记录，也不自动失效、重跑或清除历史题目。
- **错误识别失败时关闭免评分。** 只有有来源可核查、在阈值期间持续到达的模型推理增量才可认定；HTTP请求耗时、客户端等待、流连接存活、thinking开关、最终完成时间、聚合 reasoning token 数及机器负载都不能单独作证。标签准确表述为“观测到推理增量持续超过阈值”，不声称拿到了供应商内部计时。供应商／模型不能提供推理增量时显示“时长未确认”，保留原错误与评分路线。
- **先复用现有数据结构。** 先验证可否把独立命名的作答策略放入现有步骤配置及 attempt JSON；配置读取必须剥离策略字段后再交给原 provider 配置解析。只有现有结构无法无损表示且已证明需要时，才另提数据库迁移方案；本计划不执行迁移。
- **合格标记不是分数或发布许可。** 免评分结果不填0、不进入得分率，不自动 accepted、发布、返修或重跑。若既有状态机无法把它显示为终结且未评分的结果，就先不启用跳过分支，不能用 `completed`、`accepted` 或 `repair` 伪装。
- **历史样本只读。** 不改题目2–6、8的旧题面、答案、评分、达标状态或附件；回归和试验使用新建隔离数据。禁止为验收清空或重置现有流程。

### 3. 证据机制验证后，再接免评分分支

只为启用策略的新attempt增加分支，不改正常完整答案的评分路线。

| 条件 | 程序处理 |
| --- | --- |
| 支持的供应商／模型在本次 attempt 持续返回推理增量，增量观测区间严格超过冻结阈值，且当前 attempt 由本地请求时限终止 | 标记“已确认推理增量超时，可免评分”，保存非内容型时间证据、配置和绑定；不派发该模型评分 |
| 仅等待超过阈值，无法确认实际生成 | 保留请求超时，显示“思考时长未确认”，不能自动免评分 |
| 网络、认证、额度、HTTP错误、空正文、无效响应、取消或worker中断 | 按原技术错误处理，不通过时间门槛洗成难题 |
| 正常返回完整答案 | 仍按现有rubric评分，时长只作观测 |

- [ ] “超过”用严格比较，恰45分钟不成立；请求上限应允许越过阈值，不把生成上限直接降至45分钟。
- [ ] 保留技术终态，新标记独立存在；不能把超时任务写成成功完整答案，不能虚构answer.txt或score attempt。只有本地 deadline 到期且完整推理事件证据跨阈值时可进入资格标记；供应商 HTTP 408 即使总耗时很长也不得自动资格化。
- [ ] 每个模型独立认定，其他成功答案继续评分，其他失败继续显示；覆盖全部模型免评分时的汇总，不因没有成功答案永久卡在评分前置条件。
- [ ] 先逐项核实现有步骤状态机能否表达“终态、未评分、未通过、不可发布”。同步修改评分派发、服务端就绪判断、达标汇总和详情展示；只有现有导出会误报时才修改导出。已有 accepted／repair 分数路线不变；新增“免评分”原因与空分数，不填0、不参与合计得分率。若必须迁移状态枚举或改变 accepted／repair 语义，暂停该分支并另出兼容方案。
- [ ] 免评分不自动等同于正式合格或发布许可。首次实现将时长资格明确展示，未满足现有发布规则的结果仍不能发布；如需要以时长直接accepted，另明确其业务规则后再扩展判定。
- [ ] 不把时长资格输入给作者或评分Agent，不自动启动返修／重跑，不让同一个attempt产生重复分支。

**阶段验收：**默认关闭时行为与改前一致；启用后仅证据充分的模型免评分；正常答案必评分；混合模型及全部免评分有可辨认终态和证据。不可评分结果不被 accepted／发布，且 UI/API 不显示虚构分数、无串题、无自动推进。状态机无法安全表示全部免评分时，此阶段不得发布。

## 分步回退与停止条件

- 每项独立改动和验收，先记录本次改动前的相关内容；回退只撤销本次明确的改动块，不覆盖并行工作的文件。
- 不改用户级 Codex 配置；任何经批准的兼容性实验只能在隔离配置副本中进行，验证结束即清理副本，不触碰桌面日常配置。
- 新时长策略可关闭；关闭只影响后续新 attempt，正在运行的任务按创建时冻结策略收尾。已经免评分的记录保留原依据，不悄悄补分；需要恢复评分时经原有正式入口显式派发并沿用版本绑定。
- 失败证据和历史结果不删除。优先使用现有JSON字段；确需迁移时单独核对，不盲跑全量迁移。
- 若出现输入污染、正常答案被跳过、错误达标、版本串联、作者能力减少或取消／停止失效，停止扩大测试，保留失败证据并修复该项；其他已验收的独立改动不一起推翻。
