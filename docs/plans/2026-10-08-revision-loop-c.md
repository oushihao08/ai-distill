# C 自动返修闭环实施计划

日期：2026-10-08。本轮交付计划，尚未实施代码或运行验证。

## 目标与边界

一次显式启动返修后，系统依据真实问题证据执行有限修订或技术重试，自动完成必要的重新作答、评分和第七步判定，直到合格、等待恢复或超限隔离。保留每轮版本、原因、计数、调用、耗时和评分变化。

复用现有队列、worker、Codex 执行器和项目模型集合。C 负责返修链内接续；首次从第一步跑到底、项目批次控制、认证监控和正式成果自动发布属于 D/E，不在本包扩建。

依据：当前情况、MVP 剩余工作规划、第四至六步产物契约，以及 server/decisions、authoring、scoring、reporting 当前源码。

## 已确认的缺口

- decideRevision 是纯决策函数，计数和预算未持久化；runAcceptance 保存 repair 但不执行。
- 多模型 runAcceptance 构造配置时未带入第七步 revision_budget，需保留项目预算来源。
- 第四步输入没有旧题及返修问题；质检失败只向结果保存报告，返修须安全读取私有草稿和标答，不扩大公共暴露。
- 当前 rubric 问题指向第六步，但第六步只评分，无法修改 rubric。必须先修订并独立质检，再重评。
- 第四步重跑会使全部下游失效；rubric-only 修订需保留有效旧答案，并调整当前以第四步尝试 ID 判答案有效性的绑定规则。
- 报表返修行目前为占位记录，需要读取实际修订链。

## 问题处理规则

- 服务暂时失败：同输入、同配置有限重试；不增加内容轮次。仅明确可重试错误自动处理；调用结果不确定时保留未知，不能声称恰好调用一次。
- 认证/额度：停止该链新派发，等待显式恢复，不循环请求。监控自动恢复归 D。
- 题面问题：实际修题并独立质检，改变题面或附件后重新作答和评分。
- rubric 问题：修订 rubric 及必要的私有标答并独立质检；确认题面、附件与作答要求未变，才复用答案。
- 评分无效/争议：依据评分报告有限重评；不能仅为跨过达标线修改评分标准。
- 分数未达标：按冻结项目规则分析问题，再决定有依据的题目修订；不能自动降低门槛或教模型抄答案。
- 材料缺漏：已有原件中可恢复的处理失败返回第二步；无法恢复的事实、规则冲突或未知问题保留依据并等待处理/隔离，不编造修复。

内容轮次默认上限沿用三轮；技术次数、时间和调用上限沿用已有配置，不凭空设数字。启动前预算须能形成有限执行边界；缺必要配置显示具体缺项。调用额度按实际外部调用预留和核销，包括修订、质检、作答、评分及材料重处理；等待认证时间不计有效执行耗时，记录统计口径。重启后不能丢失已消耗额度；请求不确定保留已预留额度并记录原因。

## 验收标准

1. 从质检拒绝或第七步 repair 启动，有来源问题、预算快照和完整父子记录；并发启动不重复执行。
2. 题面/附件变化不复用旧答案；rubric-only 不重新付费作答，但所有必需模型按新 rubric 重新评分；旧发布状态失效。
3. 技术重试、内容轮次、调用与有效耗时分别累计，边界生效，超限不再派发；认证/额度等待不消耗内容轮次。
4. 任一阶段失败、worker 中断或输入变化后，历史保留，恢复不重复执行已完成任务，旧结果不能发布；隔离一题不阻塞其他题。
5. 一条返修链最终得到 accepted、等待恢复或隔离的可解释结果；接受结果仍遵守当前项目模型集合和门槛。
6. 页面和导出展示真实返修历史、前后分数、调用和费用；私有标答不进入作答/匿名评分输入或公共下载。

实施阶段按用户明确调用的 goal-work 要求，对新增后端行为编写并运行针对性单元测试；前端不新增测试。使用隔离 PostgreSQL 验证事务、去重、版本失效、重启及完整队列。真实 Codex/供应商修订链单独保存证据，真实材料未就绪时明确未验收，不用注入结果冒充。

本包不验收整个八步真实业务闭环、项目级自动推进、批次控制、生产部署、备份、压力或周产能；这些保留在 A/D/E/F。
