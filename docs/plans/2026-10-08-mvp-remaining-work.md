# MVP 剩余工作实施规划

日期：2026-10-08。范围：对照 [最初 MVP 计划](2026-10-07-workflow-mvp.md) 和 [当前情况](../当前情况.MD)，将剩余开发与验收归为六个任务包。本文件上半部分为规划基线；用户已授权执行，实际进展见文末执行记录。任务包不能因其中一项通过就标记整体完成。

## 目标与已有基础

让真实材料能按项目固定规则完成出题、独立质检、要求的模型作答、逐答案评分、达标／有限返修和成果发布；各步骤按需执行，保留版本、历史、实际产物和 API token 费用证据。

复用现有单步 API、数据库尝试与产物、Codex 执行器、国内模型适配器、worker、达标／返修决策函数、统计与 XLSX 导出。已有功能不重写；发现影响闭环的实际问题时，在对应模块修复。独立会话、私有标答、匿名评分、冻结配置和晚到结果保护必须保留。

## 六个任务包

| 包 | 当前基础 | 实施任务／交付 | 依赖及完成标准 |
|---|---|---|---|
| A 真实单题闭环验收 | 第一至七步入口、真实 Codex 接入、单模型作答、独立导出已有 | 核对服务／迁移与真实材料；确认推理凭证；复核 OCR 页数、issues、关键事实和脱敏；复核真实 skill 并冻结；运行出题→质检→作答→评分→判定，合格则导出；修复实际发现的问题，保存链路记录 | 用真实材料和真实模型答案完成当前单模型链路。题目无效须明确失败，不为通过而降低门槛；不达标结果真实保存，合格成果验收可在 C 完成后补齐。缺凭证时只阻断相应实际调用，不冒充成功 |
| B 模型管理与多模型评测 | 四家客户端、固定单模型配置、答案及评分队列、必需模型门槛已有 | 补系统模型登记及项目模型集合；固定模型配置快照；逐模型派发、保存明确成功／失败结果；逐答案评分；齐备后按项目规则判定；接页面设置及结果汇总 | A 的单模型契约明确。并发重复提交不重复调用；一个模型失败不丢失其他结果；评分绑定正确答案；模型配置改变不修改在途任务；无效或未完成结果不能合格 |
| C 自动返修闭环 | `decideRevision`、达标判定、输入版本保护已有 | 接问题证据与回退步骤；保存技术／内容计数、时间／调用预算和修订关系；执行实际材料修复／改题／rubric 修订／重新评分；重入现有队列；展示原因、变化和前后评分；超限隔离 | 复用 A 的真实链路及既有执行器；B 完成后补多模型返修回归。题面／附件变化重新作答，rubric-only 变化对同一答案重评；技术重试不计内容轮次；默认三轮内容上限及时间／调用上限实际生效；隔离不阻挡其他题 |
| D 自动推进与运行控制 | 曾接入项目级自动批次、暂停／取消／恢复入口 | 用户反馈难以理解，已按要求撤除；保留已有逐步执行、单步批量及 C 返修接续 | 不再作为待实现功能 |
| E 成果发布与费用完善 | 合格成果查询、XLSX、独立导出重试、API usage／价格／指标接口已有 | 增加第八步独立发布尝试、成果版本与文件索引；按真实项目要求补实际交付文件及核验；导出消费已发布成果；核对适用价格／账单、保留未知原因；接 C 的真实返修费用／耗时 | 可先用隔离夹具开发发布接线，真实验收依赖合格链路。发布仅接受当前有效合格结果；导出失败不撤销已发布成果，不重做题目；重复操作幂等；不计 GPT／Codex 套餐，缓存 token 不重复计费 |
| F 页面与交付收尾 | 工作台及部分基础／达标／导出浏览器记录已有 | 先修第四步 implemented 显示一致性；随功能补设置、控制、历史和下载；最后做完整浏览器、批量压力、部署与备份恢复验证 | 小修可立即做；最终交付依赖前五包。用真实操作覆盖创建、执行、失败、返修、恢复与下载；记录适用环境和未验证项；实际产能测量，不预先承诺每周 100 道合格题 |

项目要求图片、工具执行、Word 等实际交付时，A 先明确能力差距，B／E 补当前项目确实需要的能力及产物检查。不能让纯文字结果冒充文件或工具完成，也不预先实现所有可能工具。

## 实施顺序与挂靠

1. **先 A，同时修 F 的第四步显示问题**：先找出现有链路真正缺什么，不扩建调度器来掩盖材料、凭证或题目有效性问题。
2. **接 B 和 C，推进 E 的发布接线**：先对齐模型身份、答案尝试、题目／rubric 版本及修订关系；再补最小必要迁移和行为。C 可先按单模型工作，之后统一补多模型验收。
3. **完成 D 并接齐 B／C／E**：调度只调用已有入队／判定／发布能力，不重复业务规则。先验成功链路，再验失败、返修、暂停、取消与恢复。
4. **完成 F 的最终验收**：用不同规则的两个项目和一批实际材料检查隔离及自动流程，再核对备份恢复、费用和实际产能。

上面的并行是任务依赖允许的安排，不表示本次已经派发 agent。公共迁移、`server/app.ts`、`server/worker.ts` 和共享版本关系由同一个集成负责人统一修改，避免多人同时改接线。

- 最终验收包含：真实单题、项目隔离、多模型结果齐备、实际有依据的返修、上限隔离、技术重试、重启晚到保护、独立发布及导出、备份恢复。未通过项继续列明，不用百分比代替验收。
