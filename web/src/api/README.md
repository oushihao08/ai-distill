# API 请求

`client.ts` 的 `api<T>(path, init)` 调用 `/api` 前缀接口，读取 JSON 并将 HTTP、空响应、非 JSON 和网络异常转为可展示错误；204 允许无正文。

`apiPostIntent()`用于支持request_key的材料处理/建题POST：按路径和输入摘要保存同一次请求键，收到成功回执才清除；错误后相同输入恢复原请求，成功后的下一次操作使用新键。sessionStorage仅保存摘要与随机键，不保存正文；存储不可用时退回页面内Map，关闭页面后不保证恢复。该方法不对其他业务写入启用自动重试。

调用方提供请求体、请求头和可选 AbortSignal，自行管理加载与错误状态。泛型只是静态契约，不对返回值进行运行时结构校验。开发代理由 `web/vite.config.ts` 配置，服务端接口定义在根目录 `server/`。

JSON请求及响应正文读取共用35秒截止，调用方取消信号合并保留；写请求超时/网络错误明确提示回执未知，不能推断后台未执行。`ApiRequestError`保留HTTP/code及outcome_unknown供批量操作停发；不自动重试。

`batch-dispatch.ts`由项目步骤卡片与题目筛选列表共用：冻结本次题目ID后按每批2题顺序请求原批量接口，逐批展示回执进度；每批仍遵守35秒截止，不增加worker并发。任一批失败停止未提交部分，错误保留已收到任务ID，不自动重发结果未知的请求。

写请求自动生成并发送UUID格式的 `X-Operation-ID`，错误提示保留操作标识；批量中断同时列本批待核实题目ID。服务端日志按该operation_id关联，可查询原操作时间线；它不是幂等键，不保证重发安全，也不触发自动重试。
