# ai-distill

本地出题与评测工作台。主项目（`project_groups`）拥有多个隔离期次（`projects`）；全局材料库保存原件、文件集合版本、提取与脱敏结果，期次显式加载所需版本后建题。主项目永久材料使用记录独立于题目，跨期防重，提交后可退回原期返修。

归档按当前有效评分达标及版本绑定放行。项目独有的材料要求、交付规则和交付物由各自主项目目录的 `scripts/archive.ts`（可选准备）和 `scripts/delivery.ts` 负责；未配置项目要求时直接归档。材料 DOCX 和单题工作簿为辅助导出，失败不阻断归档。详见 [归档模块](server/publishing/README.md)。

## 当前材料与题目流程

1. 新界面创建主项目下的 `library_v1` 期次。在全局材料库提交独立提取入库任务（054原子导入契约）。上传只建立任务与暂存文件，全部提取通过后才在一个事务写入正式包、版本、文件与正文；失败不新增正式材料数据。脱敏仍由用户单独派发。部署和兼容边界见材料库模块README。
2. 每期的出题设置默认 `redacted`，也可显式使用 `original`。脱敏模式须选择成功可用的脱敏结果；原文模式须选择完整成功提取的版本。原文模式使用提取文字与结构，不把原始二进制直接交给模型。
3. 本期材料加载关系保存选版与顺序；建题时可填写角色、场景、方向和标签。新题冻结所选来源与正文摘要，后续更换期次设置或材料版本不切换旧题来源。
4. 题目按出题、作答、独立评分、达标判断、归档推进。出题使用本次附件和项目有效 Skill（期次覆盖优先，否则主项目路径）；作答只接收题面、允许附件、公开成果呈现约定和作答提示词。评分接收同版题面、Rubric、匿名答案、对应来源附件及评分提示词；不读取项目Skill或作答思路，普通评分不以思路/标答缺失阻断。标答仅在显式冻结的校准政策下要求并提供；API评分内联正文和计分数据，不发送本地脚本或其执行指令。
5. 普通步骤由用户单步或批量派发。评分完成后程序计算达标，判据来自项目当前配置和冻结评分契约；不在文档硬编码模型数量或阈值。相同完整依据及当前结果的达标判断复用原记录，不使导出或归档状态失效。归档核对当前题面、答案、评分和达标依据的版本绑定。
6. 归档、导出、上传平台与平台验收是不同状态。Work 五件套由项目交付脚本生成，可经 `siriser download` 下载；该命令不上传平台。Harbor 身份是可选的后续转换参数，缺失不阻止生成 Siriser 五件套。

旧 `question_folders` 与旧项目内材料包继续使用兼容路径。它们的入库/提取/脱敏步骤不能机械套到共享材料快照题；步骤身份与适用集合来自 [step-registry.ts](shared/step-registry.ts)，持久化 ordinal 不能按界面顺序重编号。旧目录建题仍要求自己的脱敏材料。历史同步到全局库不修改旧题来源，也不把旧脱敏结果冒记为新成功。

主项目材料占用以稳定项目身份和材料签名记录，移除引用或删除题目不释放跨期使用限制；原期恢复和提交返修按材料使用接口处理。期次题目与配置隔离，共用主项目 Skill 的期次仍可能共同受该本地文件后续修改影响，新任务以派发时的文件指纹为准。

## 运行与操作

技术栈：Vue 3、TypeScript、UnoCSS、Vuetify、Bun、Hono、PostgreSQL/pg。前端默认 `127.0.0.1:3800`，API 默认 `127.0.0.1:3700`；端口和执行位置以当前配置为准。

下列是操作入口，不是执行授权；安装、迁移、重启及真实调用遵守 [AGENTS.md](AGENTS.md)：

```sh
bun run ai-distill --help
bun run server
bun run worker
bun run dev
```

后台处理需要相应 worker。`WORKER_MODE` 决定领取队列，未配置时为 `all`；环境模板使用 `local`。Agent 与 API 并发逐项优先读取 `.env`／进程环境中的 `AGENT_CONCURRENCY`、`LLM_API_CONCURRENCY`，未配置或留空才读取持久配置，均缺失时默认 Agent 2、API 8；具体槽位、跨进程范围和重启要求见 [服务端说明](server/README.md)。不能用进程数量、`waiting` 或心跳单独判断任务正在执行。

远程材料/作答仅通过已有 [远程 CLI](skill/REMOTE.md) 及 SSH 隧道使用；当前共享材料库 job 与旧远程组合操作是不同接口，不能用同一种 ID 混发。发布入口和副作用见 [运行脚本](scripts/runtime/README.md)，不会因阅读本文自动获准部署。

PDF/DOCX/TXT/MD 的当前解析路径、供应商选择和异常保留见 [材料模块](server/materials/README.md)。API 供应商配置、服务端凭证引用及模型目录见 [llm-api](server/llm-api/README.md)；普通出题和盲作答/评分的工具边界见[Agent](server/agent/README.md)。模型调用分别记录请求与返回身份，返回标识未知时为null，不从请求配置推断。

## 根文件与存储

| 文件/目录 | 用途与编辑边界 |
| --- | --- |
| `package.json`、`bun.lock` | 命令与依赖声明、依赖锁；不因说明更新安装依赖或手工改锁 |
| `tsconfig.json` | 根 TypeScript 检查范围和共享路径别名 |
| `.env.example` | 不含真实凭证的配置模板；`.env`、凭证和连接串不得输出或入库为提示词 |
| `Dockerfile`、`docker-stack.yml`、`.dockerignore` | 构建、服务/挂载/回环端口及构建上下文边界，维护入口在运行脚本 README |
| `.gitignore` | 凭证、依赖、缓存和业务产物的版本控制排除规则 |
| `config/`、`migrations/` | 提取配置和有登记身份的数据库演进；SQL 文件不是自动运行指令 |
| `.agents/`、`skill/` | 本仓库操作 Skill 的发现链接和正文；不等于业务项目出题 Skill |
| `.storage/`、`assets/out/` | 受管理原件/快照/执行产物及导出物；不作为新题原始来源扫描 |
| `执行观察/` | 任务和证据追溯；不能把旧结果当作当前运行状态 |
| `templates/`、`unused/` | 生成器输入与停用资源；按各目录说明使用，不批量加说明污染业务输入 |

数据库状态及受管理文件应共同备份。更换 `STORAGE_DIR`、迁移本地路径或跨机器运行前须核对实际挂载和配置，不从文档中的历史绝对路径推断环境。删除、重置、材料移除与归档撤回有不同的数据边界，按对应接口实施。

## 项目生命周期扩展

1—7公共步骤通过[生命周期策略门面](server/lifecycle/README.md#1—7项目策略执行点)传入主项目key，各项目在[独立注册目录](server/lifecycle/projects/README.md)维护专属策略和交付接入。事务、模型调用、来源处理、评分执行和达标计算保留通用实现；默认项目无需注册空流程。

生命周期按顺序等待项目动作，必要实现失败沿原步骤报告，可选通知失败独立记录。新before/after脚本不另起后台任务；已登记的历史hook队列保留兼容消费。完整输入、失败及恢复边界以生命周期README为准。

项目工作区与Skill配置使用仓库相对路径，例如`projects/豆包高经济价值/skill`，每台机器按自己的仓库根解析；历史绝对路径兼容和文件同步边界见[项目目录契约](server/README.md#项目目录与多机路径)。

新材料先完成[原子提取入库](server/material-library/README.md#新材料处理顺序与可跳过步骤)。脱敏和Agent材料整理均可跳过：aliases来源需成功脱敏，原文来源直接使用提取结果；整理可基于任一来源生成摘要和支持范围，建题时有匹配结果才冻结给出题Agent参考。新加载、选版及恢复须通过[完整材料合并DOCX的快速估算门槛](server/material-library/README.md#拼接docx页数加载门槛)；估算10页及以下不得加载到任何项目期次。既有题目保持冻结来源。
