# ALE 专业工作任务包与环境/评分设计总控

从真实专业工作现场的输入资产、工具环境与待交付目标出发，设计符合《ALE 数据交付技术规范》的高价值任务包。把每道题当作该领域资深从业者（研发/算法工程师、生信与临床研究员、量化/财务/法律顾问、CAD/CAE 工程师、三维/音视频技术美术、计算物理学家）围绕一项具体业务委派完成的**完整专业工作闭环**：从原始脏输入与受限初始状态出发，到交付可独立重开、独立复算、直接供下游生产系统或决策者接手使用的**原生产物**为止。

**条件优先级：**
```text
ALE 技术规范固定边界 > 本次指定 domain/sub_domain 与运行模式 > 原始输入材料与环境真实状态 > 领域工程/学术标准 > 模型默认判断
```

---

## 一、八大固定系统边界（不可妥协）

1. **领域与去重净量**：严格按 ALE `domain/sub_domain` 均匀规划（`computing_math`、`life_science`、`health_medicine`、`business_finance`、`engineering`、`visual_media` 各 200 条，`physical_science` 100 条；`law_compliance` 等其他领域上限 **50 条**——商事/建工/借贷/尽调卷宗优先从财务尽调、资产估值、结算审计、现金流瀑布立意归入 `business_finance`）。合法复用软件环境不扣题数，但**只换名称、数字或随机种子的同构题归零不重复计数**；每题埋设数据集专属私有 `canary`。
2. **完整自包含任务包**：每题交付完整 `instruction.md`、输入材料与初始状态、可复现环境与 `reset.sh`、可执行评分入口（如 `tests/grade.py`）、结构化 `tests/rubric.json`、真实参考解（`solution/solve.sh` + `solution/artifacts/`）及推导依据，不依赖私有 harness。
3. **离线默认与严密真值隔离**：默认 `allow_internet: false`（确需联网须显式声明白名单服务、工具、凭据注入与合法快照）；确定性判分 100% 本地离线运行。Agent 执行期**绝对不可读**隐藏真值、`tests/reference/`、`solution/`、`tests/rubric.json`、`tests/grade.py` 及私有评分资产；业务状态仅经授权工具变更，Agent 自写日志或成功标记绝不作完成证据。
4. **原生产物实质检查**：CAD/三维、Blender/音视频、XLSX/Office、Web/应用、科学计算/代码及专业办公文档必须产出并检查**可编辑/可重跑的原生工程或活公式文件**；截图与导出件仅作辅助证据，绝不删减原生产物要求。
5. **零隐藏义务与等价解公平性**：目标、输入、权限、信息截点和交付契约在 `instruction.md` 清楚可查，必要材料可发现且足够；关键事实、单位、行列与口径一致，数值可重算、引用可定位。有意冲突须允许有据纠错；多种合理读法或等价工程实现须声明接受条件，严禁用单一隐藏答案误罚合法替代解。
6. **七要素 Rubric 与二值 `success` 双门控**：每条 `criterion` 写明题面依据、材料位置、交付物及观察位置、判断条件、权重、容差和关键门控（`is_key_gate`）。确定性参考必须拿满分 `1.00`；连续专业评分参考须 `≥ 0.90` 且全部关键项通过。模型二值 `success` 要求**同时达到冻结合格线且全部关键门控通过**，核心失败绝不能被次要分抵消。
7. **九类单因子反例与防投机封顶**：在正式环境实跑验证参考基线、`no-op = 0`、骨架/常量伪造/纯摘要归一化分 **`≤ 0.20` 且 `success = false`**，以及 9 类单因子错误反例精准失分、合法等价解零误罚。
8. **8 次黄金难度标定与真实轨迹防 hack**：最终冻结版用 `GPT-6.1-Sol` 或 `Opus-5.5`（`reasoning_effort = max`）干净状态独立跑满 8 次（`run_01`–`run_08` 全交），**仅保留成功 1–3 次（12.5% / 25% / 37.5%）的任务**；另交 ≥1 条 `opus-5` 或 `gpt-5.6-sol` 真实完整成功轨迹（禁拿 oracle 日志冒充）；每条成功轨迹均经防 hack 审核（`review/<run_id>.json`）且 Token/轮次可由原始调用逐笔复算。

## 二、跨模型非对称双赢校准（压 `6.1` 入 `1–3/8`，稳放 `5.6` 过 `+1`）

实测认知边界：`gpt-6.1-sol` 擅长全量脚本爬虫、4,000 公式大表、自写 XML `<v>` 缓存与无提示隐式惯例发散（但单轮推理轻、大表易自造耦合错误）；`gpt-5.6-sol` 单轮推理深度是 `6.1` 的 2.1 倍、建模紧凑（~250 公式），但呈**任务隧道视野**（未显式点名的核查维度默认不触发、不写 XML `<v>` 缓存、首版易带行号错移）。**必须彻底删除所有“拦住 `5.6` 却拦不住 `6.1`”的单边陷阱**，执行以下五条机制：

1. **紧凑异构多单元高耦合模型（打穿 `6.1` 单轮轻思考盲区，保 `5.6` 切片全读与深度推演优势）**
   - **最低结构复杂度硬门槛（禁 1–2 笔单线算术）**：实证显示 1–2 笔同构债权的线性滚算 `6.1` 通过率达 `24/24 (100%)`；每题必须包含 **≥ 3 个异构业务单元/债权档/担保顺位** × **≥ 3 处跨文书语义冲突或分段规则切换**（如本金桥已吸收还款 vs 执行阶段新增扣划、申请书与主文履行期/起息日冲突、最高额封顶含息与否及超限溢出归入普通池、双路径压力差额联动）× **逆向临界参数求解**。
   - **凭证紧凑禁机械爬虫（12–30 条高信息密度原件）**：禁止用 >50 行同质银行流水考全卷脚本搬运（`6.1` 全量爬虫速通而 `5.6` 局部切片吃亏）；同时选定破局真值后全文检索 `input/`，确保修正后真值**未在任何现成汇总表/裁判小计栏直接印出**，且**严禁在 `instruction.md` 把计算逻辑写成逐句伪代码或分摊公式**。
2. **「契约边界全消歧」与「破局机制零剧透」一刀两断（救 `5.6` 契约死锁，绝不给 `6.1` 喂答案）**
   - **必须写清契约边界（消歧）**：凡属“不声明就无唯一答案”的输出定义与任意性惯例——终点指标的**「对象 + 起止时间窗（判前/判后） + 含不含费/税/息/加倍」**、计息年基准（如 ACT/365）、差额正负方向、舍入精度及若涉清偿/履行期规则须“按有效法律与合同口径全表统一”——必须在 `instruction.md` 明确锁死。
   - **严禁点破案卷内部破局动作（防 `8/8` 泄底）**：**绝对禁止**在指标定义或正文中提示案卷事实结论与破局方向（严禁写“已按裁判吸收历史收付”“调节额按本金占比分配”“担保人只对其覆盖的某笔兑现”“剔除退货冲回/无效登记”“超限部分转入普通债权池”等喂题句！），也严禁把题面未提及的旁枝瑕疵（户名笔误、立案表错录）设为门控。只给中性终点名（如 `基准日未偿债权账面额`、`有效担保覆盖敞口`），让模型自行穿透凭证对账定性。
3. **评分器彻底清除单边偏见与脆词干误罚（零 `<v>` 缓存歧视、零未点名寻宝正则）**
   - **禁止要求无头 `.xlsx` 预填 `<v>` 缓存**：一律用 `ale_grader_lib.ExcelEvaluator` AST 重算估值；`cached is None` 完全合法，仅当非空缓存值与公式重算值矛盾时判错，**严禁使用 `openpyxl(..., data_only=True)` 单读缓存**。
   - **禁止 `.docx` 未点名实体/数字/脆词干寻宝正则**：`.docx` 仅核验题面明示的首表勾稽数值与受控决策枚举（自动兼容多列表格与 `☒/☐` 复选框）；**严禁在 `grade.py` 对题面未点名的具体调节数字（如 `347.95`、`14,000`）、专有人名或窄同义词干（如只认 `银行流水` 罚 `账户流水`、只认 `再次申请` 罚 `再申请`）做 `re.search` 扣分**。
   - **合法实务二义口径入白名单**：无卷内明文排除的期间顺延/算头算尾口径并列纳入 `ground_truth` 等价白名单；`C09` 动态探针避开 `MAX(0,...)` 截断拐点，下游判据代入被测工作簿自身上游值验算子，防一错多杀。
4. **关键门控分层（`is_key_gate` 总权重严控 `65%–75%`，≤80% 硬门禁防连坐）**
   - 仅将绑定核心主轴耦合链的 3–5 个主干判据（合计权重 `65%–75%`）设为 `is_key_gate: true`，旁支核对与说明项设为 `is_key_gate: false`（组内比例连续计分，`pass_threshold = 0.85`）。
5. **自然交办、真实 `.docx` 输入契约 ＋ 强制复用 `ale_grader_lib.py`（禁手搓解析器）**
   - 以真实业务交办函行文，禁用“模拟/假定/本题考察/无需生成文件”与 `(****)` 掩码裸露；
   - **在 `ai-distill` 工作台出题时，执行环境 `/workspace/input/`（即 `environment/input/`）的默认实体卷宗统一为确定性 Word 文件 `附件1.docx`**（含全部文书标题与原生 Word 表格，严禁在 `instruction.md`、`task_card.json`、`solve.sh`、`grade.py` 中写死 `附件1.txt`），且输入路径与二进制 SHA-256 必须严格采用前置关卡 `<前置关卡冻结输入锁定>`（`ale_pre_authoring_lock`）给出的 `locked_environment_inputs` 值；
   - `delivery.ts` 自动注入私有 `tests/ale_grader_lib.py`（沙盒内副本见 `skill/assets/ale_grader_lib.py`）与公开 `environment/tools/office_lint.py`。`grade.py` 直接导入 `ExcelEvaluator, DocxExtractor, GradeReporter, SubCheck, approx_equal, parse_grade_cli_args, verify_frozen_inputs`，控制在 60–120 行内。

## 四、封包前必过八条硬红线

1. **契约六处逐字节一致**：`instruction.md`、`task_card.json`、`environment/input/`、`solution/solve.sh & artifacts/`、`tests/rubric.json & grade.py` 中的输入名、产物相对路径、字段/Sheet/实体标识、单位与信息截点完全一致。
2. **真值物理隔离零泄漏**：构建与执行期挂载树中不含任何 `reference/`、`solution/`、`rubric.json`、`grade.py`、答案种子或测试脚本；搜索环境层与输入文件确认零参考真值残留。
3. **原生产物真实可重开复算**：`solution/artifacts/` 由真实求解流程生成并通过原生产物实质检查（CAD 拓扑尺寸、Blender 轨道材质重渲染、XLSX 活公式无 `#REF!/#VALUE!`、Web 持久状态、科学计算独立复算）。
4. **基线满分且反例精准拦截**：干净环境下参考解达确定性 `1.00`（或连续评审 `≥ 0.90` 且关键门控全过）；`no-op = 0`；骨架/常量伪造 `≤ 0.20` 且 `success = false`；各单因子反例精准扣减对应项且不误伤无关项；合法等价解零误罚。
5. **零隐藏义务与零剧透双达标**：遮住参考解仅凭 `instruction.md` 与 `environment/input/` 即可无歧义推导出全部必交规格；同时题面、文件名与目录结构未泄露待排查根因、隐蔽冲突位置或备选分支结论。
6. **去同构与受众纯净**：未沿用与同批其他题“仅换名称/数值/随机种子”的同构骨架；全套业务题面与参考产物零“模拟/假定/本题考察”话术、零内部产线术语、零 `(****)` 掩码裸露。
7. **标定与轨迹账实相符**：若进入正式批次交付，8 次标定预编号全留存且成功数严格为 `1`、`2` 或 `3`；至少 1 条 `opus-5` 或 `gpt-5.6-sol` 真实成功轨迹（非 oracle）；`run.json` 的 Token 与 `model_turns`/`tool_calls` 由原始记录精确复算，缺失填 `null` 不填 `0`，`review/<run_id>.json` 防 hack 核验与 `canary` 检查全过。
8. **诚实状态分级记录**：任何尚未实际运行的动态容器测试、单因子反例、8 次模型标定或外部评审，在质检记录中如实标记 `SKIP` 或待办缺口，严禁伪造运行日志、评分结果或 `PASS` 结论。
