# 专业交办表达与防同构组件库

**用途：**供作者在完成全部专业求解、环境构建与评分设计后，编写具有真实行业现场感、饱满详实、零模拟黑话且结构非同构的 `instruction.md`（及工作台 `task_name`、`question`）。

---

## 一、六种非同构宏观交办结构（打破全批四段式克隆）

严禁全批套用“首段我是谁和基准日 → 二段输入文件目录 → 三段任务 1/2/3 → 末段交付格式要求”的八股骨架。根据本任务的真实业务触发方式择一或自然融合：

1. **结构 A：线上故障/审计退件直入式**（适合系统排障、CAD 干涉返修、法院补正/审计异议）
   - 首句直接抛出刚发生的客观阻断事件（产线装配卡死、夜间批处理对账失衡、收到对方鉴定异议/退件通知），交代当前时间截点与手头原始工程/卷宗位置 → 展开需要核清的根因与不能破坏的既有约束 → 随各下游接收环节交代须落盘的原生产物路径与核验标准。
2. **结构 B：前手半成品接管纠偏式**（适合遗留代码/仿真配置/旧诉状/初版财务模型复核）
   - 从工作区已有的前手初稿或半截工程切入，说明原定用途及为何暂缓签发/上线 → 要求对照底层原始记录逐项核验哪些模块/条款/基数可保留、哪些必须推翻重算 → 明确最终替换产物的精确路径与跨件勾稽要求。
3. **结构 C：双下游接收方分流交办式**（适合既有底层计算模型又有高层决策/对外正式文本的任务）
   - 围绕两个不同下游角色的使用动作展开（例如：生产/财务系统需要可直接重跑续记的 `.xlsx`/`.step`/`.py`，而投委会/法院/临床主任需要结论明确、不含内部底牌外泄的正式 `.docx`/报告），自然导出内外分件、格式与一致性要求。
4. **结构 D：硬资源/预算/期限倒排式**（适合运筹调度、EDA 时序功耗、多标的执行分配、临床剂量安全窗）
   - 先摆明不可突破的物理包络、功耗预算、总资金池或法定除斥死线 → 交代待处理的候选对象与原始记录 → 要求在满足全部硬约束前提下求解最优可行配置并输出原生工程与验证数据。
5. **结构 E：跨版本/跨阶段状态对账式**（适合多组学批次整合、SPA 交割过渡期结算、历审与执行跨卷清算）
   - 沿业务演进的两个客观锚点（基准日 vs 交割日、初测批次 vs 补测批次、生效判决 vs 查控扣划记录）切入 → 交代需要穿透核销的状态变化与未决缺口（缺关键外部输入时要求同表算出极值边界或盈亏临界值，不留空白早退）→ 明确最终定稿产物。
6. **结构 F：技术规范/SOP 驱动验收式**（适合 Blender 播出技审、科学数据 CF 标准归档、医药 GxP 质控）
   - 直接给出交付目标与目标端工程接收规格（坐标基准、响度/色域、单位制、工作表契约、API 响应契约），将发现输入脏数据与修复中间管线的具体路径完全留给被测 Agent 自行探索。

## 三、`task_name` 命名规范（高辨识度、零剧透、防批产模板）

- **要求**：点明具体领域对象、核心工程/业务场景与目标交付动作，紧凑平实（通常 12–28 字）。
- **四禁**：
  1. 禁加“全链路/端到端/深度穿透/高难度闭环/专项评测”等浮夸包装词；
  2. 禁整批复制“`[主体/系统]`的`[动作A]`与`[动作B]`”对称模板；
  3. 禁把待排查的隐藏 Bug 根因或待裁决的唯一胜出方案直接写进标题（如把“排查因 UTC 时区未转换导致的日切差额”改为“跨境清分网关日切对账差额定位与账务修复”）；
  4. 禁带 `(****)` 脱敏掩码或内部编号残片。

## 四、成稿四步终检清单

1. **遮头盲读测试**：遮住首句与文件名，能否在 15 秒内看清这是哪个真实专业岗位在解决什么卡点、交付产物拿去干什么？
2. **契约完备无暗桩测试**：不看 `solution/` 和 `grade.py`，单凭 `instruction.md` 与 `environment/input/`，所有输出文件路径、文件名、必需的 Sheet/列名/函数入口/图层名/单位/舍入精度是否 100% 明确无歧义？（消除冤死 `0/8` 根源！）
3. **零泄底反查**：搜索 `instruction.md` 与全部文件名，确认未提前点破脏数据行号、隐藏冲突类型、跨版本规则切换年份、前手草稿错点或最优分支结论（守住防 `4–8/8` 防线！）。
4. **同族去同构核查**：与同 `sub_domain` 其他任务对比，确认并非仅替换实体名、数值或种子的换皮题，保证 100% 计入独立合格净量。
