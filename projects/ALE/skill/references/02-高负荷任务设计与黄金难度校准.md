# 高负荷任务设计与 `1–3/8` 黄金难度校准

**用途：**供作者在选定材料与领域后，挖掘真实专业工作的深层判断依赖，精准将任务难度控制在 ALE 第 4 节要求的 **`GPT-6.1-Sol` / `Opus-5.5`（`reasoning_effort = max`）8 次独立尝试仅成功 1–3 次（12.5% / 25% / 37.5%）** 黄金区间。

---

## 一、“完整专业工作日”双向试办与任务盘点

不要把题目写成教科书习题或单步工具调用说明。按资深专业人员承接真实工单的方式做**双向试办**：

1. **从交付终点倒推（Backward）**：
   - 下游谁会接手这份产物（生产流水线、制造车间、临床科室、投委会、合议庭/财务部、渲染农场）？
   - 他拿到产物后**第一件直接执行的操作**是什么？为了让他无需返工就能直接用，哪些边界条件、异常记录、单位换算、公式联动、拓扑闭合或权限限制必须在本次一并解决？
2. **从原始输入顺推（Forward）**：
   - 完整通读/解析全部输入文件（严禁只看前 50 行或摘要说明）。逐份核清：**谁在什么时间生成该数据、覆盖什么样本/期间、采用什么量纲/编码/基准、与其他文件哪里互相印证或冲突**。
   - 识别输入中真实存在的“半截工程”：前手留下的草稿、跑了一半的配置、带历史口径遗留的台账、有噪声的实验读数或未对齐的多源日志。把“核清前手做到哪一步、哪些可沿用、哪些必须纠偏重算”纳入本次任务。
3. **相容实质工作应选尽选，禁塞凑数垃圾步**：
   - 同一业务目标下互相关联、漏做会导致下游出错或失权的实质步骤全部纳入；
   - 严禁靠“要求手抄无争议大表”“强制写固定字数感想”“增加与核心目标无关的常规模板文档”虚增篇幅。

### 原始输入四层真伪穿透（跨领域通用）

| 穿透层级 | 表面现象（浅层模型易轻信） | 底层真实状态（必须核查的依据） |
| --- | --- | --- |
| **1. 描述层 vs 实体层** | README、注释、汇总邮件、主文书摘要声称的规格/总额 | 原始代码逻辑、CAD 实际几何体、原始测序/传感器数据、逐笔银行回单或合同原条款 |
| **2. 独立源 vs 同源转述** | 多份报表/转发记录/派生日志出现同一数字，看似交叉印证 | 追溯唯一原始事件 ID/时间戳/批次号，剔除同源重复计入或转发回单二次冲抵 |
| **3. 发起态 vs 终局生效态** | 订单已提交、查封已裁定、任务已入队、PR 已创建、补丁已生成 | 实际扣划到账、迁移已提交持久化、收敛残差达标、服务重启后健康检查仍通过 |
| **4. 标称工况 vs 边界失效态** | 常规均值、标准温压、现行通用规则下看似正常 | 跨时际规则切换点、单位制混用（mm vs inch, MeV vs GeV, 含税 vs 不含税）、空值/极值/闰年/时区截点 |

## 二、跨领域五类高判别力加压机制

根据当前材料的真实特性组合 **2–3 类**机制，形成多跳依赖链（前跳错则后跳连锁偏离，但每跳均有客观依据可查）：

1. **多源异构脏数据消歧与闭环重算**
   - 输入同时包含主台账、底层原始凭证/日志、修订补丁或退回记录；存在重复记录、冲销退回、ID 映射漂移、缺失批次或单位混用。必须全量清洗对齐后再进入核心建模或核算。
2. **隐式规范/版本/坐标/时际转换（零提示检索或环境内核查）**
   - 跨越不同软件/协议版本、行业标准、会计/税务/法律时际规则、地理坐标系或物理量纲体系；题面只给客观发生时间、地区或工程场景，**绝不点破**需要转换哪条规则或哪处存在单位陷阱。
3. **多目标与共同资源耦合约束**
   - 多个子模块、多笔债权/预算、多个零件特征或多个时间片共享同一总容量、功耗预算、几何包络、优先顺位或除斥期限；单看每项局部可行，合在一起却超限冲突，迫使模型求解全局自洽的最优合法解。
4. **直觉默认做法的反噬陷阱（Counterfactual Trap）**
   - 设计“调默认参数平推看似合理，实算后却导致精度崩塌、数据泄露、负收益或程序违法”的分支（例如：时间序列随机 shuffle 导致未来信息泄漏、直接删除含缺失值行导致高风险样本系统性丢失、按法定默认清偿顺序导致高息债权受损、CAD 直接布尔切除破坏非流形壁厚）。
5. **不完备信息下的极值边界与敏感性实算**
   - 当真实场景确有某项外部输入待定（如未到账回执、传感器标定不确定度、待确认交割日）时，严禁让模型写一句“待核实”早退；要求结合已知锚点与领域规则，在工作簿或工程输出中**实算出上下限区间或改变决策的盈亏/安全临界阈值**。

## 三、靶向 `1–3/8`（12.5%–37.5%）双边校准与“默认压难 + 高波动双峰”策略

> **核心战略基调**：不要试图做“8 次都考 80 分上下”的平稳型题目（只会在 `0/8` 和 `8/8` 之间跳崖）。出题基调必须定在**“默认让最强模型大概率掉进表层诱饵不通过（靶向单次通过率 $p \approx 15\%–20\%$），仅当某 1–3 次采样主动触发全卷脚本穿透证伪与跨期合规核查时直接冲上 92+ 分过关”的双峰分布（Bimodal Distribution）**。即使首轮偶发 `0/8`（或 `sample_3` 探出 `0/3`），也可根据 `repair_evaluation` JSON 对全盲锚点微调半句业务背景精准扶进 `1–3/8`；反之若首轮打出 `6–8/8` 则毫无返修信息。

在投入昂贵的 8 次正式标定前，作者必须对照以下双向标尺预判并调校任务：

### 1. 防止 `4–8/8`（过易失守）的五项高波动加压铁律

- **严禁中间过程行名指路（头号防泄底铁律）**：`instruction.md` **只准规定最终交付表中的 6–12 个中性业务终点指标**（如最终有效本金、应付利息、压力路径分配额、净敞口），**绝对禁止**规定任何暴露破局路径的中间过程行名（严禁要求填写 `服务费`、`紧接回款`、`转贷本金`、`重复回单冲销` 或直接列出分段起止日期）！模型中间如何拆表完全自由，`grade.py` 只检验终点结果数值及原始参数到终点结果的微扰动公式联动。
- **植入“表层自洽诱饵（Local Optimum Decoy）”制造探索分岔**：可在 `environment/input/` 中保留或提供前手经办人留下的初版 `.xlsx` 台账/汇总草稿（表面加总完全自洽，但漏剔除了卷尾原始回单中的同源重复收据、未实际到账的查控冻结额或无效转贷部分），让轻信前手摘要早停的 5–7 次运行掉入 `55–70` 分区间，唯有主动写脚本全卷逐笔核销的 1–3 次运行冲上 `92+` 分。
- **跨时际规则与直觉反噬零提示**：涉及跨新旧法/利率换档（如 `2020-08-20` 民间借贷利率上限切换）、法定 vs 约定抵充顺序反噬、生效前提未满足只能列“待核上界”不得混入确定余额时，题面只给客观业务日期与用途，**严禁点破修法年份、切换规则或异常性质**。
- **拒考在卷现成印出的数字**：严禁把卷宗判决书或汇总表已印出的小计当作核心考点；必须引入跨件核查差、未印答案的后续动态执行瀑布或特定回款额压力重算。
- **原生产物实态核验**：强制验收 `.xlsx` 活公式与跨文件勾稽，禁止纯文本摘要交差。

### 2. 防止 `0/8`（全军覆没废题）的四项可解性保护

> **铁律（规范第 2、4 节）**：不以隐藏义务增加难度；材料错误或题面歧义必须先修复，绝不能当作模型能力不足的证据！

- **六列双向追溯矩阵与盲读回查（彻底清零隐藏义务）**：
  定稿前在作者内部建立逐项对齐表：`采纳的实质义务 → 原始输入定位 → instruction.md 交办原句 → 产物观察路径 → criterion_id → 单因子反例编号`。
  随后**收起参考解与评分器，只读 `instruction.md` 与 `environment/input/`** 试接工单：
  1. 若某条 `criterion` 在 `instruction.md` 找不到明确交办原句或行业唯一必行常识，立即补清交办范围或删去该隐藏考点；
  2. 若拿走某项深层处理后，按 `instruction.md` 字面仍可交差，立即围绕下游接收用途补清约束（不泄露答案）；
  3. 每个被 `grade.py` 检查的文件路径、Sheet 名、列名、JSON 键名、坐标系、单位或舍入规则，必须 100% 无歧义可确定：
     - **差额与方向明示**：凡考查两数之差或变化率，必须在 `instruction.md` 明写被减数与减数顺序（如“按 `审定金额 - 送审金额` 计差，核减记负数”），严禁只写模糊的“A 到 B 的差”；
     - **引用定位给字面示例**：凡要求填写材料出处/页码索引，必须在 `instruction.md` 给出具体格式示例（如 `1/1/26` 或 `材料1/分卷1/原附件第26页`），并在 `grade.py` 同时兼容纯数字与带中文标签的等价写法；
     - **截点日期单值明确**：同时涉及“某日营业终了”与“次日零时排他右端”时，明确指定参数单元格填哪一天的日期值，或只要最终计息/统计结果与公式正确即予认可。
- **环境确定性与生产力基础库预置核验**：检查容器/VM 内所需编译器、字体、CAD/Blender Python API、科学计算包及常用办公读写库（如 `openpyxl`、`python-docx`，除非本题专门考察底层解析器实现）是否已在 `Dockerfile`/`requirements.lock` 完整锁定且离线可用；避免因缺常规库或工具障碍导致无谓 `0/8`。
- **中间可观测反馈设计**：真实专业工作允许从业者通过运行测试、查看编译器报错、检查几何属性或核对试算平衡表发现自身错误。保留合理的环境内工具可观测性（绝不暴露私有 `tests/grade.py`），让高水平推理模型在 8 次尝试中有 `1–3` 次能通过自我验证走通全链，而非盲猜黑盒。
- **等价实现白名单核验**：优化问题存在多个同等最优解、代码重构存在多种合法实现、冲突材料存在两种有据读法时，`grade.py` 必须检验**目标函数值/不变量/业务效果**，而非死锁作者参考解的唯一字节序列。

### 3. 标定偏离后的精准调校矩阵（首答实做覆盖诊断法）

当试跑或 8 次标定落在 `0/8` 或 `4–8/8` 时，严禁盲目改分或删失败记录；先检查模型轨迹中的**实做覆盖率**（模型实际动手处理过的采纳义务占比），按根因定向修复后**全量重跑 8 次**：

| 标定异常结果 | 轨迹诊断特征 | 真实根因判定 | 唯一允许的定向修复动作 |
| --- | --- | --- | --- |
| **`0/8` 且实做覆盖 `< 80%`** | 模型漏交某文件、未处理某模块或用错输出字段名 | **交办不清 / 隐藏义务 / 工具路径暗桩**（作者责任） | 修补 `instruction.md` 的交付契约或修复环境工具路径，**不降低核心专业推理难度** |
| **`0/8` 且实做覆盖 `≥ 80%`**（方法合理却全挂） | 模型识别了核心问题但卡在窄容差、唯一命名或 5+ 跳独立长链乘积暴死 | **评分器误杀等价解**，或旁支噪声跳数过多（$0.5^6 < 2\%$） | 放行合法等价实现与科学容差；收拢无关旁支，聚焦 **2–3 跳强耦合核心难关**（单跳成功率约 $0.6 \sim 0.7$ 时，$0.65^3 \approx 27\% \rightarrow 2/8$） |
| **`4–8/8` 且 `< 12` 轮速通** | 模型未读边缘文件、单脚本调默认库或靠宽容差一次过关 | **单跳平推 / 题面或文件名泄底 / 默认口径未设反噬** | 收回文件名与题面线索；引入一处有据的跨源脏数据消歧、单位/时际切换或共同约束冲突，并升级为原生产物实态核验 |

## 四、自然专业交办与五类防剧透禁令

### 1. 真实交办语体（去考题味与去模拟词）

- 按任务所属 `domain` 采用对应真实工作载体：工程研发用 Issue/架构重构单，数科/生信用分析委托与实验 QC 交接单，财税/金融/法律用业务部门或合伙人正式交办函，视觉媒体用制作总监 Brief 与返修单。
- **严禁出现模拟与评测产线词**：“本题”“考察”“模拟场景”“假定你是……”“假设截至某日无其他变化”“为测试你的能力”“评分脚本将检查……”“不得以提纲代替”。
- **严禁四段式八股同构**：不要全批套用“第一段我是谁 → 第二段输入文件列表 → 第三段请依次完成 1/2/3 → 第四段输出格式要求”；按真实业务紧迫事项、故障现象、下游接手用途自然组织段落（参见[专业交办表达与防同构组件库](../assets/专业交办表达与防同构组件库.md)）。

### 2. 五类防剧透禁令

1. **禁标题/文件名泄底**：待诊断故障、待选算法、待定救济路径不得出现在 `task_name`、输入文件名或必交产物文件名中（用中性功能名）。
2. **禁点破脏数据类型**：只交代数据来源与核对目标，严禁提示“注意第 3 张表有重复行/退回款/单位是英尺/存在时区偏移”。
3. **禁喂给跨版本/跨时际规则坐标**：严禁提示“注意某版本 API 废弃”“注意某年修法/新准则切换”或直接喂给公式/条文号。
4. **禁点破前手遗留稿错点**：提供前手代码、CAD 草图、财务模型或文书初稿时，只交代原件预期用途与复核要求，不提前指出哪一行/哪个特征写错了。
5. **禁注入人工测试假动作**：严禁在 `instruction.md` 写“请故意改一个参数试算后再恢复原状”之类的测试指令；动态扰动复算只留在 `tests/grade.py` 内部执行！
