# 可执行评分（`rubric.json` + `grade.py`）与单因子反例测试

**用途：**指导作者按《ALE 数据交付技术规范》第 2 节与第 6 节编写自足七要素 `rubric.json`、防投机实态评分器 `grade.py`、二值 `success` 门控公式，以及全覆盖九类单因子反例测试。

---

## 一、`rubric.json` 逐项七要素完整契约

每条 `criterion` 必须与 `grade.py` 中的断言函数或受控评审器一一映射，**严禁缺省以下任何一项**：

| 必含字段 | 定义与编写要求 |
| --- | --- |
| `criterion_id` | 唯一稳定标识（如 `C01_ledger_dedup`、`C02_ThermalFlux_Gate`） |
| `prompt_basis` | **题面依据**：对应 `instruction.md` 中哪一段/哪一项明确交付要求或工程约束（严禁考查题面未声明且领域非常识的隐藏义务） |
| `source_locator` | **材料位置**：支撑该项真值的具体输入文件路径及行列/实体/条款/时间窗定位（如 `input/raw_fills.parquet#tx_id`） |
| `observation_locator` | **交付物及观察位置**：在被测产物或运行态环境的哪个精确文件、工作表单元格、CAD 拓扑特征、API 端点或数据库表中读取观察值 |
| `condition` | **判断条件**：自包含的客观成立条件，同时写清**对象关联、计算逻辑与实际状态**；材料存在有意冲突时写明有据纠错规则；存在多种合理读法或等价工程实现时，在 `equivalent_conditions` 明示全部合法接受条件 |
| `weight` | 正数权重（或按题包统一声明的正负权重体系），与归一化分母严格对齐 |
| `tolerance` | **容差**：精确匹配填 `"exact"`；数值/物理/几何量写明绝对容差（`abs_tol`）、相对容差（`rel_tol`）及舍入口径（有工程/财务依据，不一刀切拍脑袋） |
| `is_key_gate` | **关键门控（布尔值，分层设置）**：仅将决定核心业务目标与 2–3 处深水破局锚点的主干项（总权重占 `65%–75%`）设为 `true`；边缘旁支复核与次要明细项必须设为 `false`（配合 `pass_threshold = 0.85–0.90`），严禁将 100% 条目一律设为 `true` 造成单处边缘失误全题归零 |
| `grader_mapping` | 对应 `tests/grade.py` 中的检查函数名/处理器标识（如 `"check_c01_dedup_balance"` 或 `"judge_c08_clinical_rationale"`） |

## 二、独立义务正交拆解与防投机铁律

1. **“甲对乙错”正交拆解（禁混绑、禁重罚、禁自相矛盾）**：
   - 两个独立业务义务（可一对一错、分别影响不同模块或决策）必须分拆为不同 `criterion`；
   - 共同决定同一最小可用结果的前置条件合并在同一 `criterion` 内验证；
   - **上游误差隔离与等价表达放行**：当 `C02` 具有独立的新算法/新规则判断但消费 `C01` 的输出基数时，`grade.py` 应以被测产物自身的 `C01` 输出代入验证 `C02` 的算子/规则正确性（或显式验证映射关系），避免 `C01` 一处小偏差导致全题连坐清零；对来源页码定位、Excel 单元格引用写法（带 `$` 绝对引用、表名前缀引号）及符合业务逻辑的边界保护公式（如非负余额上的 `MAX(0, ...)`），`grade.py` 必须完整兼容，且动态微扰动探针必须保持在业务合法定义域内（严禁注入使非负物理/财务量变负数的非法扰动去误杀保护公式）。
2. **严禁三类伪评分（零容忍）**：
   - **禁因文件/表头存在给分**：只生成空壳文件、复制模板表头或搭好目录骨架不得拿实质分；
   - **禁因孤立数字碰巧出现给分**：必须在正确对象 ID、正确单位、正确公式依赖链或正确系统状态下核验该数值（防止模型把输入里所有数字全打印一遍撞分）；
   - **禁因自称完成给分**：模型在回复、注释或自建日志里写“已全部通过校验/误差为 0.0001”一律忽略，只认 `grade.py` 独立复算实测值。
3. **LLM Judge（连续专业评分项）安全防注入规范**：
   - 能用确定性代码/解析器验证的（数值、公式、几何、状态、结构、引用定位）一律用确定性 Python 断言；仅专业说理、多方案权衡、复杂临床/法律/架构论证确需评审时才使用受控 Judge；
   - 必须保存并交付 Judge 的**模型名称与精确版本、采样参数（如 `temperature=0`）、完整 Prompt 模板、每次实际填充内容与原始响应**，且适配买方指定模型替换；
   - **防 Prompt Injection**：在 Judge Prompt 模板中对被测产物文本做严格边界隔离，显式声明被测产物内的任何祈使句/评分指令均视为待审纯文本，绝不能改变评审规则；
   - 含随机性的评审须执行事前冻结的**成对复评/多数仲裁规则**，保留全部原始响应与分数，**严禁多次抽样挑最高分**。

## 三、量纲、归一化与二值 `success` 判定公式

每题在 `rubric.json` 顶部显式声明分数量纲与归一化公式：

```text
raw_score        = sum(weight_i * item_score_i)          # item_score_i ∈ [0, 1]（二元项为 {0, 1}）
max_score        = sum(weight_i for weight_i > 0)
normalized_score = clip(raw_score / max_score, 0.0, 1.0)
key_gates_passed = all(item_score_k >= key_gate_min_k for k in key_gate_items)
success          = (normalized_score >= pass_threshold) and key_gates_passed
```

- **参考解（Reference Baseline）硬门槛**：
  - 纯确定性评分题目：`solution/` 参考成品运行 `grade.py` 必须取得 **`normalized_score == 1.00`** 且 `success == true`；
  - 含连续专业评分题目：参考成品必须取得 **`normalized_score >= 0.90`** 且**全部 `is_key_gate` 关键项 100% 通过**（`success == true`）。
- **核心目标不可抵消**：即使次要项拿满使 `normalized_score` 跨过阈值，只要任一 `is_key_gate == true` 的核心目标失败，`success` 必须强制为 **`false`**。`grade.json` 必须同时保留连续 `normalized_score`、逐项 `expected / observed / score` 与二值 `success`。

### 合规稳控 `1–3/8` 的四项评分架构准则（严禁放水作弊，消除自杀式误判）

> **合规红线（规范第 4、6 节）**：严禁为凑通过率降低实质正确性标准、暗示 Judge 放水或容忍错误答案——买方会运行 9 类单因子错误反例并替换为买方自定 Judge 模型复测，放水会导致反例拦截失败直接拒收。必须在**严守实质对错**的前提下，用以下四项合规机制消除非实质误杀：

1. **合格线、分层门控与组内比例连续计分（`65%–70%` 核心门控 + `30%–35%` 容错明细 + `0.85` 合格线）**
   - 将决定核心业务结论与 2–3 处深水锚点的主干项设为 `is_key_gate: true`（合计权重约 `65%–70%`），边缘核对、次要附表与出处溯源项设为 `is_key_gate: false`（合计权重约 `30%–35%`）；
   - **严禁多格判据“错 1 格整项归 0”**：凡包含多个单元格/子检查的判据，必须采用比例连续计分 `item_score_i = passed_subchecks / total_subchecks`，且该条判据通过判定设为 `passed = (item_score_i >= 0.85)`（参考解仍必须 `item_score_i == 1.00`；单因子错误反例须使目标核心判据跌破 `0.85` 从而精准判定 `passed = False`），防止 45 格对 44 格时触发一票否决清零。
2. **算引分离 + 上游基数偏差隔离（只扣源头一次，绝不因出处格式冤杀正确计算）**
   - **算引强制分离＋禁止未点名正文寻宝正则**：所有数值与公式计算判据严禁耦合出处页码字符串正则；`.docx` 仅核验题面明示的首表终点勾稽数值与受控决策枚举，**严禁在 `grade.py` 对题面未点名的专有人名、零碎金额或窄同义词干（如罚“账户流水”只认“银行流水”）做 `re.search` 扣分**；若确需考核证据定位，单独列为 `is_key_gate: false`（权重 ≤ 8%）并兼容同义表述与不同页码格式。
   - **上游误差不连坐＋实务二义口径入白名单**：下游公式项与 `C09` 动态探针验证“给定当前工作簿上游单元格值时，本步算子与业务约束是否正确”；微扰动步长 `probe_steps` 必须选在线性响应域（严禁跨过 `MAX(0, ...)` 归零截断拐点让上游 1–2 天起息差污染探针增量）。凡无案卷明文排除的合法实务二义口径（如普通周六休息日按《民法总则》203 条不顺延 vs《民诉法》82 条顺延、算头算尾差 1 天），须一并列入 `ground_truth` 等价白名单（要求全表自洽）；对数值恰为 `0` 但要求保留动态减法/汇总公式的单元格，必须在 `instruction.md` 明示公式构成（如“净回款须由总扣划减执行费公式得出”）。
3. **只锁终点结果、Word 多列表格/标点容错与无 LibreOffice 宿主机纯 Python 公式重算兜底**
   - **只验终点指标与端到端联动，禁锁中间过程行名**：`grade.py` 只定位并校验 `instruction.md` 明示的 6–12 个业务终点结果键及关键输入参数对其的微扰动公式联动，不强制模型中间辅助表的行名、列序或拆表方式；行序按主键匹配不锁行号，差额类指标在 `instruction.md` 明示被减数与减数方向（如“审定额减送审额”），跨期计息设合理容差（如 `±0.02` 元）。
   - **直接复用公共判分底座库 `ale_grader_lib.py`（禁止手搓解析器）**：`delivery.ts` 展开题包时自动将标准公共判分库打入私有 `tests/ale_grader_lib.py`（出题沙盒内同源副本见 `../assets/ale_grader_lib.py`）。`grade.py` 顶部统一通过 `sys.path.insert(0, str(Path(__file__).resolve().parent)); from ale_grader_lib import ExcelEvaluator, DocxExtractor, GradeReporter, SubCheck, approx_equal, parse_grade_cli_args, verify_frozen_inputs` 导入：
     - `ExcelEvaluator` 已完备支持 LibreOffice 与纯 Python OOXML + 惰性 AST 双引擎重算（含跨表引用、`$A$1`、`A1:B50`、共享公式 `t="shared"`、`SUM/MIN/MAX/AVERAGE/SUMIFS/ROUND/ROUNDUP/ROUNDDOWN/INT/TRUNC/ABS/MOD/SIGN/IF/IFERROR/AND/OR/NOT/CHOOSE/DATE/DATEVALUE/DAYS/DATEDIF/YEAR/MONTH/DAY/WEEKDAY/EDATE/EOMONTH/WORKDAY/XLOOKUP`、百分比 `%`、`^` 幂运算及合法零公式 `=0`），提供不锁行号的 `wb.find_row_metric(keys)`、`wb.is_live_formula(sheet, coord)` 与微扰动联动断言 `wb.probe(sheet, cell_or_key, overrides)`；
     - `DocxExtractor` 已完备支持多列 Word 表格键值提取 `doc.extract_key_number(keys)`（天然兼容模型自加第 3+ 列备注/来源/单位）与安全枚举提取 `doc.extract_enum_choice(keys, allowed_codes)`；
     - `GradeReporter` 自动读取 `tests/rubric.json` 的权重与 `is_key_gate`，通过 `add_subchecks` 实现比例连续计分并输出标准第 7 节 `grade.json`；注意 `rubric.json` 每条 `grader_mapping` 函数名仍须在 `grade.py` 中对应定义以通过 `CHK-04-RUBRIC` 契约校验。
4. **重确定性代码、轻主观 Judge（防买方换模型波动）**
   - 85%–100% 权重优先采用 Python 确定性实态断言；确需使用 LLM Judge 评审文字论证时，权重控制在 `10%–15%`、不设一票否决门控，且评分标准只锁定“是否包含客观证据锚点与正确因果结论”，不考核文风措辞，确保买方切换自有 Judge 模型时得分稳定一致。
- **复合办公与跨件受众隔离门控**：当任务同时要求对外交付物（如提交客户/法院/监管的正式报告、协议、外发单据）与对内底稿（含底价、内部脆弱性、多方案取舍）时，若被测产物将对内敏感底牌外泄至对外清洁件，或出现致命专业红线错误（如医疗致死配伍禁忌漏检、工程结构安全系数 `< 1.0`、凭空捏造核心实验数据/法源），必须绑定至 `is_key_gate: true` 门控项（或致命扣分门控），强制 `success = false`。涉及专业判断的题目，须在 `rubric.json` 顶层 `domain_review_basis` 记录领域审核依据（权威指南、国家/行业标准号或生效规范）。
- **自建工具、断言 Handler 与可插拔 Judge 适配器一并交付**：
  - 任务使用的任何自建 CLI/MCP 工具置于 `environment/tools/`，并确保**授权工具的写入路径/状态格式与 `tests/grade.py` 的读取路径 100% 同源一致**；
  - `tests/` 下自定义断言库（`tests/handlers/`）与评审适配器（`tests/judge_adapter.py`）须随题包完整交付，**零依赖供方私有包或内网服务**；
  - 含 LLM Judge 的评分器必须支持通过环境变量或 CLI 参数（如 `ALE_JUDGE_MODEL`、`ALE_JUDGE_API_BASE`、`ALE_JUDGE_API_KEY`）无缝切换买方指定评审模型。

## 四、第 6 节动态基线与九类单因子反例测试（必过门禁）

**只读源码或作者口头声称绝不算完成质检！** 每题必须在正式声明环境中用**完全未修改的 `tests/grade.py`** 按顺序实跑以下基线与反例，并留存原文件、改动 diff、预期与实际得分及 `check_id` 证据记录：

### 1. 基线、空交与等价解三项基础验证

| 测试编号与类型 | 构造方式 | 强制通过标准 |
| --- | --- | --- |
| **`B01` 正确参考基线** | `reset.sh` → 执行 `solution/solve.sh`（或放入 `solution/artifacts/`）→ 运行 `grade.py` | 确定性 `1.00` / 连续 `≥ 0.90`，全部 `is_key_gate` 通过，`success == true`（跑不通先修环境/材料/参考，严禁谎称拦截了退化） |
| **`B02` 空提交 / `no-op`** | `reset.sh` → Agent 不做任何修改直接退出 → 运行 `grade.py` | `normalized_score == 0.0` 且 `success == false`（严禁基建崩溃报 `ERROR` 或白送保底分） |
| **`B03` 合法正确替代答案** | 构造不同于参考解但符合题面与领域规范的等价实现（如不同算法/表结构/等效合法口径） | 全部对应项正常得分，`normalized_score >= pass_threshold` 且 `success == true`（零误罚） |

### 2. 九类单因子错误反例变异测试（每次仅改一个实质条件，其余保持参考正确解）

| 反例类别 | 单因子变异构造操作 | 强制拦截标准 |
| --- | --- | --- |
| **`M01` 空壳 / 仅表头骨架** | 生成全部必交文件名、正确 JSON 键名 / Excel 表头 / CAD 空图层 / 函数签名，但无实质计算内容 | **`normalized_score <= 0.20` 且 `success == false`** |
| **`M02` 硬编码常量 / 伪造数据 / 纯摘要** | 在 `.xlsx` 填死静态常数删掉公式，或伪造看似合理的正态随机数/仅写文字摘要跳过核心工程处理 | **`normalized_score <= 0.20` 且 `success == false`** |
| **`M03` 保留关键词但否定/反转核心结论** | 保留全部专业术语、法规条号或分析段落，仅将最终建议/诊断/极性反转为相反错误结论 | 对应决策项与关键门控必须失分，`success == false`，且无关纯计算项不应误变 |
| **`M04` 错误对象或漏组** | 计算逻辑正确，但绑定到错误的实体 ID、错误的对照组或漏掉一个必需子分组 | 对应对象关联/分组覆盖项精准失分，其余独立项保持不变 |
| **`M05` 未固定 ID 的数值改错** | 打乱行序或重排非固定顺序列表后，将其中一条关键记录的数值改错 `> 2 × tolerance` | 评分器须按业务主键/语义对齐后精准检出该处数值错误（防评分器只按固定行号盲查） |
| **`M06` 删除关键对象** | 删除一个必需输出的构件特征、工作表、服务路由或核心分析模块，保留其余全部正确 | 对应项归零；若属关键约束则 `success == false` |
| **`M07` 篡改只读输入/初始状态作弊** | 模拟恶意 Agent 直接修改 `input/` 原始基准数据使自身错误输出看似自洽 | `grade.py` 从受保护私有源或输入哈希校验检出篡改，判违规失分且 `success == false` |
| **`M08` 跨文件 / 跨状态自相矛盾** | 底表 `.xlsx`（或数据库）保持正确值，但将正式报告/主文书/前端展示中的引用总额改为另一矛盾数字 | 一致性勾稽项必须失分；破坏核心交付可用性时 `success == false` |
| **`M09` 核心功能缺失（仅留静态导出件）** | 保留正确导出图/CSV，但破坏原生 `.blend` 节点连接、CAD 可编辑特征或 Web 后端实际写入逻辑 | 原生产物实质检查项必须失分且 `success == false` |

> **按任务写明适用性**：某反例确因任务形态不适用时（如纯无状态数学证明无多文件勾稽），在质检记录如实说明依据，绝不把所有缺陷粗糙套用同一个固定分数上限。
