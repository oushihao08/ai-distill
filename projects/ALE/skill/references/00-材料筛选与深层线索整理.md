# 材料筛选、整理与“深水证据锚点”设计规范

**用途：**解决 ALE 与单向压分项目（如豆包高经济价值、Work 法律全场景）在选材与整理逻辑上的根本差异，从源头确保输入材料既能 **100% 算出唯一闭环结果（防 `0/8` 废题）**，又天然具备 **2–3 处需要深度交叉核查才能发现的破局证据（防 `4–8/8` 速通，稳定落入 `1–3/8`）**。

---

## 一、ALE 材料整理逻辑与传统单向压分项目的本质区别

| 维度 | 传统单向压分项目（如 `<= 50` 分即过关） | ALE（必须精准卡进 `8 次成功 1–3 次`） |
| --- | --- | --- |
| **缺证与模糊容忍度** | 允许残缺案卷，模型写“证据不足暂列待核”即可得分 | **严禁残缺无解材料**：待求核心数值、状态或上下限必须能从给定材料唯一、确定地推出，否则代码评分器无法公平判分 |
| **难度控制方向** | 越难越好，哪怕 8 次全拿 0 分也算压分成功 | **双边窄窗**：既不能让偷懒平推拿 `4–8/8`，也不能靠缺条件或堆积 10 个独立盲区把顶尖模型打成 `0/8` |
| **输入文件组织** | 常将多份材料拼成单一超长文本或图像 PDF 强拉阅读时长 | **保留原生多文件结构**：优先提供贴合真实工程/业务的原始多文件（`.csv`/`.xlsx`/`.docx`/日志/代码/CAD），且 `task_card.inputs` 与实际挂载路径、SHA-256 逐字节一致 |
| **破局线索机制** | 常靠大量边缘琐碎细节全面扣分 | **“明规则敞亮 + 深水真凭据”**：题面规则与格式 100% 透明，决定成败的 2–3 个破局点藏在边缘但客观可查的真实记录中 |

---

## 二、ALE 材料包准入四条硬标准（整理阶段先筛后出）

在把一份材料包送入出题前，先按以下四项核查；不满足的材料包直接淘汰或补齐配套文件，不强行硬出：

1. **终值唯一闭环**：所有核心计算指标或工程状态在给定材料内有完整数据链支撑；若业务上确有一项外部待定条件，材料内必须提供足以算出确定上下限或临界阈值的锚点数据。
2. **存在“表层常规值 vs 深层更正/限制依据”双层结构**：
   - 表层（主报告、首页汇总表、主合同初稿、README）存在一个看似可直接取用的常规口径或初版数字；
   - 深层（补充协议、尾页银行冲销回单、校准漂移日志、附件修订说明、跨表主键核销记录）存在**明确、无歧义、唯一改变结果的真实依据**。
3. **非同构原始载体**：同批次不同题目的材料包在数据结构、业务机制与冲突链路上真实异构，禁止拿同一份底表只改公司名和金额倍率拆出多题。
4. **授权与洁净度**：无未脱敏真实隐私/密钥，无公开评测集原题直接搬运，无残缺乱码导致关键数字无法辨认。
5. **拒抄在卷现成答案（生死红线）**：若照抄卷内某份已生效判决书（如法官已印出的“民间借贷计算器”明细表与主文定额）、审计报告汇总表或结算书就能直接得到核心答案，**绝对禁止围绕该现成数字出题**！要么改考读完该文书后**尚未计算过的后续动态问题**（如判决后多笔执行扣划/退费/迟延加倍双轨计息瀑布、特定金额新增回款压力测试、前手粗略计算跳号缺行与全量原始回单独立复算的核查差、缺生效证明案件的待核上界隔离），要么直接改选**只有原始合同/对账单/银行流水、没有现成裁判总账的一审举证卷或工程结算卷**。

## 三、合法合规的“通关钥匙”设计法（严禁作弊小抄，用深水真凭据控 `1–3/8`）

> **红线边界（规范第 3、5 节）**：**绝对禁止**在隐藏文件、注释或元数据里塞“答案小抄 / 作弊提示”（买方防 Hack 审查直接判 0 拒收，且后续模型训练无法涨分）。真正合法且高效的做法，是在公开输入材料深处保留**真实业务中本来就存在的“破局关键锚点”**。

### 1. 为什么 `2–3` 个独立深水锚点最容易命中 `1–3/8`？

- **0 个深水锚点**（数据全摆在主表第一页）：顶尖模型单次通过率 `> 80%` → 跑 8 次必出 `6–8/8`（过易作废）。
- **6 个以上独立暗坑或上百个苛刻格式锁**：即使每个点单次做对率有 `60%`，乘在一起 $0.6^6 \approx 4.6\%$ → 跑 8 次大概率 `0/8`（过难作废）。
- **黄金配置（`2–3` 个独立深水锚点 + 零格式误杀）**：
  每个锚点在材料里有铁证、在题面里有合法业务目标支撑，模型只有全量交叉核查才能抓全（单点抓准率约 `50%–65%`），组合通过率约 $0.55^2 \sim 0.65^3 \approx 25\%–30\%$ —— **8 次独立运行期望正好成功 `2` 次（稳稳落在 `1–3/8` 区间中心）**。

### 2. 四种高区分度、100% 公平的深水证据锚点形态

| 锚点类型 | 表层易错假象（偷懒模型踩坑点） | 深层真实破局依据（细查模型得分点） |
| --- | --- | --- |
| **跨件冲销 / 重复计入锚点** | 主对账单或汇总日志列出表面总额 | 附件尾页回单备注、退票记录或同一流水号跨表二次出现，证明其中一笔为同源重复或已退回冲销 |
| **补充变更 / 版本覆盖锚点** | 主合同、初版设计图或默认配置给出基准参数 | 后签署的补充备忘录、工程变更单（ECO）或校准记录明确覆盖了某分项费率、公差基准或生效起算点 |
| **主体 / 样本合格性排除锚点** | 多组数据混在同一原始目录或合并笔录中 | 附件主体登记、质控（QC）失格标记或归属条款证明某旁支对象不属于合并归集范围，须单列剔除 |
| **生效前提 / 阈值触发锚点** | 某项优先权、高阶补偿或保护分支表面金额诱人 | 底层送达回证、时效起算锚点或安全裕度实测值显示尚未满足法定/工程触发前提，应归入留置或受限档 |

### 3. 整理输出给作者的核查清单与全卷强制扫描铁律（防作者自身漏页乌龙）

**强制前置动作（写标答前必做）**：面对长文本/多案合并卷宗，作者必须先运行 Python 脚本按页（如 `【原附件第 X 页】`）全量扫描关键法律/工程状态词（`证明书|生效|裁定|调解|撤诉|终本|收据|发票|对账|结算|补充协议|变更|保证|抵押`），输出完整《全卷关键文书与重复卷宗映射索引》，严禁仅凭判决书末尾印象漏看单独成页的《生效证明书》或执行回单导致标答真值反错！

在进入编写 `instruction.md` 前，先列清本包的 4 个关键数字与定位：
1. **核心深水锚点（限 2–3 个）**：每个锚点的表层假象在哪一页/哪张表、深层真凭据在哪一页/哪张表、抓到与漏掉分别算出什么具体数值；
2. **严控紧凑终点键（锁 6–8 个纯结果态终点键 + 3–5 个参数，禁止百行抄表）**：聚焦多主体/多担保/多阈值高概念耦合链，**严禁设置 60+ 核心键或百行同质流水机械搬运**（单边利好全量爬虫、误伤紧凑建模的 `+1` 示范模型）；
3. **输入文件精确清单（默认真实 `.docx` 交付）**：在 `ai-distill` 工作台出题时，即使作者侧阅读正文副本以便检索，交付进执行环境 `/workspace/input/`（即 `environment/input/`）的实体案卷默认由流水线自动封装为确定性 Word 文件 **`environment/input/附件1.docx`**（含全部文书标题与原生 Word 表格，严禁再声明 `附件1.txt`）；`task_card.json.inputs`、`instruction.md`、`solution/solve.sh` 及 `tests/grade.py` 的输入路径与 SHA-256 必须严格采用前置关卡 `<前置关卡冻结输入锁定>`（`ale_pre_authoring_lock`）给出的 `.docx` 路径与二进制 SHA-256；
4. **算引分离与非核心旁支边界**：计算判据只考核数值与活公式（不耦合页码字符串），哪些属于次要核对项（放入 `is_key_gate: false` 普通计分项，不作一票否决）。
