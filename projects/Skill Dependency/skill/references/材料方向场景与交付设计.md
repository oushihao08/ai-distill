# 材料方向、场景与交付设计

## 材料盘点

逐份记录原件或投影的名称、时点、主体、数据对象、证明范围、冲突、缺口及可见性。材料整理的候选组合只用于定位；附件全文决定任务。题面不能要求处理未传入的图像、公式或隐含版本，也不能把未知设成零或已完成。

## 真实任务选择

从接收人的下一项动作倒推任务：需要决定、计算、审签、更新、提交或留档什么？选择材料足以支持、在现实中有人愿意付费完成的工作。一个任务可有多项相容成果；每项成果有独立用途、输入和完成标准。材料只能支持简单摘录时说明不足并换方向，不靠堆文件和步骤加难。

领域、主体、权限、时点、场景和成果依当前材料确定。服务立场与可取得信息须一致；不能照搬豆包的诉讼、执行或法律文书分类。多场景或多阶段只在有真实共同目标与依赖关系时使用。后项必须消化前项的有效结果，交付可辨认的当前版本；互不关联的情景不冒充连续工作。

## Skill依赖

选择输入会触发的专门规则、SOP、阈值、映射、优先级或停止条件。检查它是否已从题面、附件、工具说明或常识直接得出。真实源文件恰好含完整规则时保留文件，调整拟测规则。每份 Skill 需能解释一个可观察的成果差异；多 Skill 分别检查。

## 交付

按“材料依据→专业处理→使用动作→实际文件→验收证据”反查。题面明确要交什么、给谁用、关键内容及格式；标答完成文件正文与必要计算；Rubric 检查成果中规则产生的效果。文件格式由用途决定，不能用文件名、计划或无法执行的脚本代替成果。作者声称打开、重算或渲染时记录实际工具和结果。
