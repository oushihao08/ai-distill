# 题目格式与交付

## 六类内容

每题交付 Instruction、Input Files、1—3份作答 Skill、Golden Answer、Rubric、Metadata。Instruction写真实场景、模型角色、可见材料、Skill使用要求、实际文件、成果用途和独立段落中的硬约束；不泄漏Skill的决定性规则。Input Files保留业务必要信息和边界，文字投影不能冒充原件。

逐题Skill是作答输入，须有规则、适用条件、例外、停止与恢复、输出和来源。Golden Answer完成题面所有工作；文件成果交完整正文或结构，名称与题面一致。Rubric评价规则如何改变可见结果，Metadata说明真实任务、领域、复杂度、能力、所需工具和依赖理由。

## 本地JSON映射

按 `input/delivery.json` schema填写，字段示例见[题目模板](../assets/题目模版.md)。`delivery_contract`声明输入、Skill、成果及依赖反事实和核验记录；`platform_metadata`与`platform_rubric`保存平台所需信息；公共`rubric`为本地兼容投影。不要因为本地作答器的`answer_requirements`受限，就把真实任务的文件和工具要求删掉；真实能力另填`task_requirements`。

作者提交JSON不等于六类内容可直接使用。交付入口检查字段、权重、文件引用、公式声明及核验记录；作者核验记录没有独立工具证据时只表示作者报告。程序写入XLSX公式不执行计算，重算需有实际结果。旧v1题包缺v2字段时须重出题，不补造历史验证。

## 反查

交卷前按“题面任务→可见输入→Skill触发→完整标答/文件→Rubric→核验记录”逐项核对。缺输入就补获准来源或缩小任务；缺结果就完成成果；评分点没有可见触发或不影响成果就修改。已声明需渲染的文件须有实际渲染记录。平台提交、模型对照及外部验收只凭对应回执报告。
