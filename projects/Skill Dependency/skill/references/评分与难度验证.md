# Skill Dependency 评分与难度验证

## Rubric设计

先完成 Golden Answer，再按独立使用的专业结果划分评分点。每项围绕一个结果，写清共同决定其成立与可用性的必要判断、可观察成果、判断锚点、条件和允许的等价答案；不因子条件可分别检查就拆成数条简单分，也不把无共同用途的结果捆成一条。每个必要条件都须说明缺失怎样实质改变本条结论、范围、条件或使用；说不清后果的背景信息不设为必答项。让评分者依据题目、可见输入及该条规则独立判断；不以“调用过Skill”给分。共同上游错误只按其影响范围处理，同一判断跨成果出现不重复奖惩。

冻结前逐条试判：完整正确成果和有依据的合法替代应通过；只漏一个必要判断、其余都对的近似成果，按该遗漏对结果的实际影响判定。若它仍可正确使用，就收回该条件；若通用模板已能通过主要结果，就回到任务设计深化专业工作，不靠合并无关条件或调权重压分。Binary按完整成立边界判，Gradient的中间档须对应明确的部分成果及其使用限制；不能把同一错误在多个档位或条目重复处罚。

本项目按平台归档要求使用 `platform_rubric`：每项含 id、description、dimension、criterion_type、criterion_necessity、type、weight、levels。`dimension` 按本条实质从平台允许值选择：指令遵循、内容质量-结论正确性、内容质量-数值与计算准确性、内容质量-专业规范、内容质量-分析与论证质量、内容质量-事实忠实性、结构与组织、操作与交付安全、安全合规、超预期贡献、视觉美感；不自造“交付物内容质量”等总称。权重仅为 +10、+7、+3、-3、-7、-10；至少两项 +10 和一项负分；负分绝对值总和小于正分总和的一半；`内容质量-`各项的正分至少占全部正分30%。-10只用于真正影响可信性或安全的重大错误，不能为压分滥用。Binary档位为0与1，Gradient写明确的中间档；格式细节以运行时schema及平台有效契约核对。

公共 `rubric` 是本地兼容投影，同一 id 的 criterion 与平台 description 一致。豆包复合R等权百分制及整体归零机制不适用。若本地字段容不下平台语义，记录缺口，不能宣称平台校验通过。

## Skill效果与难度

每份 Skill 的关键规则必须与某个评分点及实际成果变化对应。作者做无 Skill 与规则改写的具体推演，检查题面或输入是否泄漏规则；若规则改变不影响答案，重设计。Rubric仍评价专业结果，不能只检测提到规则名称。

复杂度C1—C5按本次平台依据填写，说明信息关系、必要判断、工具工作和成果用途；不按附件或文件数量机械定级。S1—S3是带／不带 Skill 实测增幅档，不从作者自评推定。归档门槛：三模型均分增益至少20%；无 Skill三模型均分低于0.6且至少一项非零；Golden Answer得分不低于0.85。超时、失败和缺测不得填零或计为通过。模型实测、专家背书和平台验收分别留回执。
