# Skill Dependency 题包模板

本模板供作者反查字段和关系，花括号说明不原样进入题目。实际保存严格遵循本次 `input/delivery.json` schema；不要把模板本身作为作答输入。

## 业务设计（作者私有）

- 材料依据与可见边界：{逐份位置、时点、证明范围、缺口}
- 真实委托：{角色、接收人、待解决工作、成果用途}
- 专业结果：{最简正确解、竞争解释、条件与可用正文}
- 复合判断：{每项可用专业结果、共同必要判断、缺一项的实质影响、与其他结果的使用边界}
- 规则依赖：{每份Skill的决定性规则、材料触发位置、忽略后的具体错误、规则改变时的结果差异}

## 结构化题包

- `task_name`、`task_type`、`header`：{任务身份与职业，按当前业务填写}
- `question`：{Instruction；场景、可见附件N.txt、Skill文件名、逐份参考成果文件名、用途、独立硬性要求；不揭示决定性规则}
- `attachment_ids`：{运行时给出的冻结附件ID，不自行发明}
- `skill_files`：`[{name,content}]`，1—3份；每份完整说明输入、触发、规则、例外、停止与恢复、输出及版本。
- `reference_answer`、`answer_approach`：{完整成果正文与作者求解依据，不用文件名代替内容}
- `golden_files`：`[{path,markdown,requires_formulas,requires_render,sheets}]`；实际文件内容与题面一一对应。XLSX工作表用`{name,columns,rows}`；公式单元格用`{formula,cached_value}`，不能填普通“=公式”字符串。非表格`sheets=[]`。
- `rubric`：`[{id,criterion,max_score}]`本地兼容项；与平台项同id，criterion逐字对应description。
- `platform_rubric`：`[{id,description,dimension,criterion_type,criterion_necessity,type,weight,levels}]`；dimension用平台允许的具体维度，Binary含0/1档，Gradient含适用中间档；权重及占比按评分规范。
- `metadata`：`{domain,complexity,capability_tags,skill_dependency}`本地摘要。
- `platform_metadata`：`{task_id,task_type,domain_l1,domain_l2,domain_l3,domain_l4,capabilities,requires_vl,task_description,required_tools,domain_knowledge,skill_dependency,complexity,complexity_basis}`；编号和C等级有来源，不伪造平台身份或S等级。
- `task_requirements`：`{input_mode,output_mode,tools}`真实业务能力；`answer_requirements`按本地执行器契约。
- `delivery_contract`：`{version,input_names,skill_names,golden_names,dependency_rules,verification}`。version=`skill_dependency_v2`。文件名与实际交付一致。每条dependency_rules写skill_name、rule_locator、input_name、trigger_locator、expected_effect、without_skill_result、changed_rule、changed_result、unchanged_result、rubric_ids。verification逐文件写file、check、status、method、evidence；没执行写not_performed，不伪造。

## 交卷反查

六类内容齐全；所有声明文件实际存在且在题面被引用；每份Skill有被材料触发的特殊规则及对应Rubric；两项反事实检查有具体结果；参考文件和标答口径一致；需要的打开、重算、渲染有真实记录。作者推演、本地结构检查、模型对照、平台验收分开报告。
