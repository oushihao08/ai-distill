# 题包表达与制作残留检查

本文件供作者检查题面、逐题Skill、Rubric、Golden Answer和Metadata的实际可用性；不鉴定作者来源，不迎合检测器，也不要求伪造人工经历。

- 题名说明真实业务事项和核心工作，不堆文件名、内部操作名或待求结论。
- 题面交办具体对象、目标和成果用途。删去泛泛的“全面、深入、专业”后，仍须知道做什么、给谁用、以什么判断完成；缺的补业务要求，不补修饰词。
- 作答Skill写可执行条件、动作、例外和停止范围；不要把当前题标准答案、批改提示或作者自查塞给作答者。
- Rubric写可观察结果、判断锚点和允许的等价分支，不写“正确使用Skill”“结构清晰”等空评价；平台权重按项目规范。
- Golden Answer完成成果，保留事实、来源、条件和未知。文件名、制作计划、虚构下载链接或脚本不能代替实际文件内容。
- Metadata如实说明任务真实性、专业难度和Skill独有增益；模型成绩、专家背书和平台状态只填有回执的事实。
- 删除模型自述、生产路径、内部字段和本机路径等不属于业务交付的残留；保留业务必要的术语、编号、表格和正式格式。
- 表达改写前后核对对象、数值、时点、条件、规则和成果范围。相似度与风格不作为题目难度或依赖性的证据。

业务写法按[表述方法](references/表述方法.md)与[组合库](assets/书面表达组合库.txt)选择；逐题字段以[模板](assets/题目模版.md)和运行时schema为准。
