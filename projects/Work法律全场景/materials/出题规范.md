# Work 法律全场景出题规范

核对日期：2026-10-14。本文用于选题、准备材料、撰写任务、形成专家标准交付物和设计原始 Rubric；Harbor 的字段转换、评分运行与打包要求见[交付规范](交付规范.md)。这是项目要求，不能据此认定本地系统已具备全部能力或某题已通过验收。

> **【本轮执行口径】** L1 不采用，本轮需要 L2–L5；认领后 **5 天内**在出题平台提交任务包，收到质检意见后 **2 天内**返修，预计无法按时须提前联系项目方协调。待测 SOTA 模型从 Claude Opus 5、GLM 5.3、Kimi K3、Qwen 3.8 Max 0902 中选 3 个，按本题三模型均分验收。项目通知写“≤55%”，交付规范 H 原文写严格“<55%”；为同时满足两种口径，实际目标按 **<55%** 控制，正好 55% 不作为稳妥通过值。该通知优先用于当前批次；批次或项目方更新时重新核对。

**标记含义：** **【结算／提交红线】**可能导致不予结算、退回或无法提交；**【正向分】**为 rubric 命中加分；**【扣分】**为具体负向 rubric 命中；**【否决】**单独影响交付物可用率、不进入总分；**【提质】**提升实务可用性，但不自动产生额外分值。

必须把握以下重点：

1. 题目衡量的是法律实务产物是否可用。任务必须来自或映射到真实用户会付费办理的工作，不能纯为攻击模型弱点而设题。
2. **【结算红线】**禁止再次提交、迁移或改写任何其他项目已经提交过的题目或数据包；还要避开 D 列明的存量业务方向。这是两项独立要求，重复提交明确不予结算。
3. 材料必须完整、真实、相关，足以支持正确判断；不能靠模型生成、摘录、拆分、重复或无关文件凑数。
4. 题面还原委托人的真实表达，明确目标、立场、交付物、基准日与硬约束；不得提示答案、考点或扣分点。
5. 标准答案由法律专家亲自撰写并核定；法规案例检索轨迹必须来自专家真实办理过程，不能模型生成或事后补造。
6. 正向 Rubric 从终稿标准答案拆出，负向条目对应本题具体错误；判据自包含、可独立核验、互不重复。
7. **【正向分／扣分／验收门槛】**必设维度、领域锚点、分值档位、字段和验收门槛必须同时满足；不能沿用其他项目的 20 条等权 0/1 或轮次要求。
8. 题面、材料、答案或 Rubric 改动后，同步修订关联内容并重新核验受影响结果；不得为降低模型分数而恶意加扣分或把错误固化成标准。

## 4. 任务说明：信息完整，表达真实（D 第3.1节；H 第2节）

**【出题质量】**任务描述要像真实委托，不提示答案、考点或评分；资料不足时只能设计真实且正确处理方式明确的缺口，不能通过缺关键材料制造多解或不公平难题。

### 4.1 必需信息

| 要素 | 必须说明 |
| --- | --- |
| 背景与事实 | 交易／纠纷来龙去脉、当事人关系、已发生事项；脱敏后仍能判断委托方和相对方 |
| 诉求或办案要求 | 委托人希望解决什么、得到什么结果；允许包含不专业、不可行或越界诉求，交由模型作专业判断 |
| 交付物 | 每份材料是什么、大致用于什么；转 Harbor 时补齐固定文件名、格式和输出路径 |
| 基准时间 | 交付物出具日、尽调日或评估日，作为法规版本和信息截止依据 |
| 硬约束 | 不可退让条件，如期限、金额上限、须保留条款、不得披露事项；独立编号列出 |

### 4.2 不得违反的写法

- 一般当事人以第一人称口述，讲亲历事实、感受和目标；可啰嗦、顺序颠倒、夹杂情绪。不要替当事人判断证据性质、法律关系，或提前教模型如何写专业文书。
- 委托方为律师、法官、检察官或监管专业人员时，使用相应行业行文，允许专业术语与体例要求；同样不得提示答案或考点。
- 不出现“本题”“考察”“请注意”“重点是”、任务类型编号、维度名称、标准答案、Rubric 条目或“评分将检查……”。
- 自包含不等于把答案放进题面。写全完成任务所需事实和交付约束；隐含的法律专业判断仍由模型完成。
- 真实委托人的不合理诉求，应由正确答案作合法、专业处置；不能因其被写成“底线”就把违法建议设为应得分答案。
- Harbor 任务书使用 `instruction.md`，逐个列出 `/app/input_files/` 的文件及字段／口径；逐个写明 `/app/output/` 中的固定输出文件。显式 Rubric 要求须在任务书找到出处，任务书硬要求须有 criterion 覆盖。六处文件名一致性见交付规范。

## 5. 源文件：真实性、完整性与可判断性（D 第3.2节、常见问题附录）

**【结算／质量红线】**真实、完整、相关、可读的原始材料是题目成立的前提。模型生成文件凑数量、摘录冒充全文、重复／无关附件、来源或时间线无法核实，均不能靠标准答案补救；先查原件与版本，无法修复就更换题源。

材料可以包含与任务相关但非核心结论直接依据的真实文件，不得混入与解答完全无关的资料。每种文书的结构、体例、措辞、签署和必要要素，应符合真实实务情况。

逐份检查：

- 原件可打开、非零字节、页数齐全；文件名声称“汇编／全文／共几份”时，与实际内容一致。
- 合同、章程、制度等为完整内容，不能用一两页摘录或概要冒充完整文件；不能大面积采用 AI 仿真模板、不同机构完全相同的格式或重复签名图。
- 送达、形成、起诉、判决、上诉、会议和统计数据的时间线一致。不能用未来资料支撑过去已作出的判断，也不能把起诉后形成的材料说成起诉时已提交。
- 签章、签字栏、受送达人签名、笔录时间地点及权利义务告知等法定／惯例要素不缺失、不张冠李戴。
- 案号、机构、主体身份、代码和金额符合来源事实及合理性。按 D 对引用案号逐一核验，不能编造存在但案情不符的案件，或混淆脱敏标识与可外部检索的原始案号。
- 脱敏保留主体对应关系和完成任务所需的关键事实。遮空姓名后无法区分当事人、代理人和义务人，应修复材料包的指代说明。
- 正确结论必要的材料齐备；可设计真实的材料缺口，但正确处置应是具体说明缺口、列补充清单，不能因缺关键材料造成无法判断或结论不唯一。
- 提取成功只说明技术处理完成；扫描件、图表、表格、计算式、印章文字和提取 issues 需要复核。扫描件／图片／图表的视觉依赖如实填入 metadata。

发现来源包自身矛盾，先核对和修复用于出题的材料版本，再重做受影响答案、Rubric 和评测；不能用答案补造事实，也不能静默篡改原件。

| F5 数据核算 | 完整字段的结构化台账／测算表；口径说明（基数、公式、来源、假设）；分析结论与预警清单；检索轨迹 | Q1、Q5 |

按主交付物确定类型；可自然包含邻近类型的能力，不能因此更换必选锚点或遗漏本题核心能力。

### 6.2 专家答案的五项质量底线

- **可直接使用**：完整度、体例、措辞和准确性符合真实对外法律文书；清除模板占位符，按题目要求核验正文长度，不能用标题或签署占位凑字数。
- **结论确定**：逐项回应问题。真实不确定性应写明法条空白、司法分歧或地方差异等具体原因、不同结果及条件、对本案的建议倾向；不以“咨询专业人士／待进一步核实”代替本应完成的判断。
- **说理可追溯**：结论有事实、规范及适用过程；事实能定位到 input 文件名和位置，规范能对应已核验检索记录。不存在依据的事实删除或明确待核实，不能编造送达过程、书面意见、当事人行为或案例。
- **立场一致**：律师维护委托方，法官中立，检察官客观公正；不同文书不出现角色倒置或程序结论冲突。
- **口径一致**：金额、日期、比例、主体称谓、法律关系和结论在所有文件中一致；公式和结果可复算；法定结构如法院称谓、此致、署名、页码等按具体文书要求处理。

### 6.3 法条、版本和案例引用

| 对象 | 必须保留的引用信息 |
| --- | --- |

| 案例 | 案号＋裁判要点＋正文来源；核验真实存在且案情、裁判观点对应 |
| 域外法 | 原文名称＋编号＋条次，首次出现附中文译名 |

交付物须写条文原文或可核验规定摘要，可以用注释／备注；不能只列条号。Rubric 涉法条时还要嵌入该项判定所需具体条文和本案对应关系，不能让裁判自己补找标准。

| 来源档位 | 使用边界 |

| 一档正文来源 | 中国政府网、中国人大网、国务院部委官网、国家法律法规数据库、最高法公报、中国裁判文书网、人民法院案例库、北大法宝／威科先行正文页、域外官方立法与判例库；须能定位原文 |

## 8. Rubric 设计：重点、必须项与不能做的事（R 第1–5节、H 第6.6–6.7节）

**【正向分】**按本题实务后果合理设置 +10／+7／+3，并满足至少两条 +10、锚点正分占全部正分至少 30%。**【扣分】**只对本题具体、可观察的错误设置 −3／−7／−10；不得为压低模型得分而加重扣分。**【否决】**另行判断，不等于再扣一次分。

### 8.1 内容来源和判定要求

1. 以专家终稿 golden 拆解正向条目，覆盖全部核心内容；不凭经验添加 golden 没有的“伪需求”。要求还必须能追溯任务书、输入材料或由职业语境必然推导的隐含要求。
2. 负向写“做了什么错事”，来源为本题埋点对应错误、高频实务错误和红线行为；每处预埋考察点至少有一条对应的具体错误判据，不能有埋点无判据。不把“没做到正向要求”再写成扣分，同一点跨维度也只计一次。
3. 一条只判一件事。事实簇、法定动作四要素只有整体才有意义时可联合判定；独立的效力、计算、解除问题应拆开，不能靠大量同义小项扩大分差。
4. 写清具体正确事实、金额、日期、基数、计算口径、法条内容、结论和容差；明确须满足全部还是任一条件、等效表述和有效替代方案、负向计一次还是可累计。
5. 不写“专业、深入、充分、准确”等无法核查的期望；不写“等、详见参考答案、参照上条、共 X 项、以此类推”省略判据。长清单逐项换行，编号连续。
6. 法律结论需有可追溯依据；不能只靠关键词命中。允许多条正确法源、不同有效方案和专业同义表达，不能把专家选的路径当唯一答案。
7. 同一事实错误归 Q1；两个位置互相矛盾才归 Q7。专业实质对错归维度 2；维度 1 只检查动作、交付、格式和硬约束。
8. 不接受恶意负分、为了压低模型分数改变权重或故意构造不合理难度。对不同 Judge 或多次评分波动大的项，应补充明确判定边界，不能直接挑最低分。

### 8.2 维度与数量硬要求

一级维度 1（指令遵循）、2（内容质量）、5（安全合规）必须覆盖；3（体例）、4（推理规划）、6（协作可编辑性）、7（反偷懒反模板）至少再选两个。Q1–Q7 至少选择三个，且必须含第 6.1 节对应的两个领域锚点。

**两个锚点维度的正向分之和 ÷ 全部正向分 ≥ 30%；每题至少两条 +10（Critically Important）。**这是关键项和覆盖要求，不是总 Rubric 条数固定为 20，也不是各条等权。

| 维度／能力 | 必须写清的检查重点 |
| --- | --- |
| 1 指令遵循 | 按交付齐备、硬约束、角色立场、基准日四类；齐备性 binary，缺任何必交物不给部分分；硬约束逐条写清违反情形；角色立场只设负向。条目数量措辞冲突见第 11 节 |
| Q1 事实证据 | 多文件核心事实、冲突材料采信、证据三性、材料缺口；事实簇列全要素 |
| Q2 风险识别 | 每项具体风险及其严重程度、依据；实质障碍 +10，监管／程序不利且可整改 +7，补材料或确认可解决 +3 |
| Q3 法源 | 每条必要核心法源单独设项，嵌入条号、具体内容及本案对应关系；案例含案号与要旨，不堆法规汇编 |
| Q4 适用定性 | 每项定性结论及规范要件对应，覆盖必要例外与抗辩 |
| Q5 量化判断 | 正确值、基数、口径与容差；期间、门槛和四舍五入边界可核验 |
| Q6 可执行性 | 动作＋执行主体＋时限＋所需材料，缺任一要素不得分；结论、替代路径、不确定性具体化 |
| Q7 一致性 | 默认只设负向；逐项列出本题可能出现的跨章节／跨文件矛盾 |
| 3 体例可读性 | 优先法定或惯例要素、风险清单字段、台账列头；通用层级、编号、长列表／表格排版合并一项 |
| 4 推理规划 | 前置判断在先；交叉核验明确哪两处材料、正确差异与采信结论；检索层级及版本核验 |
| 5 安全合规 | 违法建议按本题情形逐项列明，−10、可累计；编造法规、事实证据、检索来源按对象分开设 −7 或 −10、可累计，并作为否决计数来源；不设“没违法”普遍加分 |
| 6 协作体验 | 可直接粘贴条款、可导入清单、留痕可编辑；需委托人决定或补充的事项明确提示，不能擅自决定 |
| 7 反偷懒反模板 | 在选设该维度时至少一条具体负向，注明可核验阈值；检查回避结论、无关模板、空标题、“略／同上”、复制底稿冒充分析；与可选维度措辞的歧义见第 11 节 |

### 8.3 分值与判定类型

| priority | 原始 score | 设值依据 |
| --- | ---: | --- |
| Critically Important | +10 | 缺失使核心结论方向错误，需重做 |
| Important | +7 | 结论方向仍可用，但对外前需要明显补查或修改 |
| Slightly Important | +3 | 复核可顺手补齐，不影响整体使用 |
| Slightly Detrimental | −3 | 易发现且低成本修改的小错、跑题、矛盾或体例问题 |
| Detrimental | −7 | 重要法条、事实、口径等错误，需回查材料，容易误导后续 |
| Critically Detrimental | −10 | 重大专业错误、幻觉、立场倒置、业务安全／合规风险，破坏可信度 |
| Veto | null | 独立可用性否决，不进入数值分子、分母 |

只允许六档计分，同档同分，priority 与 score 一一对应；不使用 +5、−4 等自创档位。正向和负向都不能机械全部设同档。

- 默认 binary；只有程度差异可量化且对质量有意义时使用 likert。主观判断能明确 yes/no 的仍可用 binary。
- likert 固定 `points = 5`，判官输出 1–5 整数，每一档写可独立核验条件；正向 5 为完全满足、1 为不满足，不能写成 0–1 小数档。
- 负向优先 binary；确有次数／严重程度差异才用 likert。原始累计负分转 Harbor 会有上限差异，不能假装与无限累计等价，详见交付规范。
- 原始净分 = 正向命中分＋负向命中分，满分只计正向；可用率 = R0-V01 未触发的题目数 ÷ 总题目数，独立统计、不参与分数。Harbor 的裁剪归一化主分与该口径有差别，不能混用。

### 8.4 原始 Rubric 字段清单

| 字段 | 必须遵守 |
| --- | --- |
| `id` | 正向 `R{维度号}-P{序号}`，负向 `R{维度号}-N{序号}`，否决如 `R0-V01`；二级维度不进入 ID，通过 dimension 区分；题内唯一 |
| `statement` | 完整自包含判据、正确值或错误情形、全／任一命中、等效表达和计数方式；禁止依赖外部补标准 |
| `criterion_type` | `Objective` 或 `Subjective`；Subjective 条数不得超过总条数 10%，不是分值占比 |
| `criterion_necessity` | `Explicit` 或 `Implicit`；前者为任务明文要求，后者由职业语境必然推导；不能把所有实质法律判断塞进题面 |
| `dimension` | 一级为 `维度号-维度名`；维度 2 写到 Q 二级，如 `2-交付物内容质量/Q3法源定位与援引准确性` |
| `evaluated_files` | 字符串数组，列本条涉及的 golden 文件名；涉及多份逐一列；整份、全部跨文件或无法指定时用 `all`，示例 `["all"]`；实际按功能对应候选产物 |
| `knowledge_points` | 字符串数组，`法律域::具体知识点`，可含制度／条号；纯事实、格式或流程无对应知识点时为空 |
| `atomic_capabilities` | 依据[法律原子能力v2](https://alidocs.dingtalk.com/i/nodes/Y1OQX0akWmzdBowLFj4mYKMgVGlDd3mE)，0–3 个；首项为主导能力，只有它用于该项失分归因，其余用于覆盖分析；不考原子能力时为空，不编造枚举 |
| `priority` | 与上表分值／否决一一对应 |
| `score` | 六档之一；否决为 `null`；原文另有 weight 示例差异见第 11 节 |
| `type` | binary 或 likert；原文大小写不一致，正式 JSON schema 需核对；TOML 明确用小写 |
| `points` | likert 必填且为 5；binary 和否决按字段表为 null |
| `trigger_count` | 可累计负向填写计数规则并与 statement 一致；一次性扣分和正向为 null；否决按本题触发规则核对 |

`evaluated_files`、`knowledge_points`、`atomic_capabilities` 是分析型元数据，不塞进 statement 充当判断条件，不参与分数／否决计算。TOML 的 description 仍必须显式写实际待查产物路径，不能用分析元数据代替。

### 8.5 一票否决单独处理

R 以全题独立 `R0-V01`、`dimension = 0-一票否决`、`priority = Veto`、`score = null` 描述否决；各普通维度不另建计分否决项。

具体情形必须结合本题，覆盖适用的效力／安全红线、角色／立场红线及幻觉红线。R 的幻觉阈值原文为各类编造“累计超过 3 处”，不能擅改为“达到 3 处”或“出现一次即否决”。明确如何按本题情形计数，普通专业错误、遗漏、说理不足、体例缺陷不得滥用否决。

对应违规可以正常命中负向分，但否决本身不再次扣分，独立统计可用率。R 对“全题一条”与“每情形一条”的文字冲突、示例引用不一致及 Harbor 未给出否决专用实现，见第 11 节和交付规范；未确认前不能自行给 Veto 设置 3／7／10 权重混入主分。

| 分组 | 原文能力名称 |

| 文书与事务管理（7） | 法律文书格式化、单文书摘要、多文书综合摘要、法律术语规范、案件全流程规划、庭审排期与期限监控、计费与诉讼预算管理 |

能力原文给名称及定义，R 示例则含 S2、L1、D5 等前缀；当前引用页未同时列出完整前缀编码表。使用正式提交字段时核对当前模板的名称／编码要求，不根据本表顺序自行生成字母编号。各能力的适用定义以链接原文为准。

knowledge_points 的法律域在 R 中是参考列表，不是本文件新增的封闭枚举：民法总则、合同编、物权、侵权责任、公司法、证券与资本市场、破产、票据、建设工程、房地产、劳动与社会保障、民事诉讼、强制执行、证据法、刑事、行政、知识产权、税务、个人信息保护与数据、涉外与跨境、金融资管、竞争与反垄断、政府监管与合规、环境与 ESG；后接本条实际制度／知识点，不能只写宽泛领域。

## 9. 常见问题、后果与处理（D 常见问题；R 第2–5节、常见问题）

以下按“直接后果”标出风险类型。标签用于帮助拦截问题，不表示项目方必然按该项扣固定分；实际扣分必须由本题已核定的 Rubric 命中，提交／结算后果按项目方规则和质检决定。

| 问题 | 影响标记 | 检查与处理 |
| --- | --- | --- |
| 题面泄露答案、法条、扣分点或全部考点 | **【区分度下降／任务质检风险】** | 保留真实任务信息，移除出题痕迹；与 Explicit／Implicit 要求边界一起复核 |
| 无法规基准日、新旧法混用 | **【法律准确性风险／Golden 与 Rubric 返修】** | 明确日期，核对适用版本及条号，补版本检索记录，同步答案和 Rubric |
| 材料时间线自身矛盾或不存在的主体／案号 | **【真实性红线／结论不可判】** | 先核对材料版本及真实性，受影响输出不得直接采用；不能由答案猜补或以低模型分掩盖 |
| 缺签章、法定笔录要素、空文件、模板／摘录冒充全文 | **【材料完整性／提交验收风险】** | 核验原始来源与完整文书，补齐真实必要材料；不能模型仿造补数 |
| 脱敏后无法区分当事人 | **【任务不可判／材料返修】** | 补主体角色与对应关系，确保保留任务所需事实 |
| golden 编造事实／案例、用错法律概念或时点 | **【Golden 准确性不达标／Oracle 风险】** | 每项事实定位 input，每项引用定位原文；核实纠正，并检查是否已被 Rubric 固化 |
| golden 口径矛盾、未清占位、缺真实检索记录或必要文书 | **【内容质检退回／完整性交付风险】** | 跨文件逐项核对，按实际正文与完整交付要求修订；字数要求以适用原文为准，不把示例长度当统一门槛 |
| 同一要点多条同义、正负反面重复、跨维度重复 | **【重复计分／分数失真】** | 保留独立考点，删除重复摆动；不能让一个数值或法条形成不成比例分差 |
| Rubric 要求 input 没有、golden 没做到、或法律结论本身错误 | **【Rubric 失效／整包返修】** | 回查题面、材料、专家答案和法源；按事实修订，不让错误标准“考倒模型” |
| 全部 +3、负向只有笼统一两项、格式分占主体 | **【核心能力区分不足／质量下降】** | 回到实务重要性和本题具体埋点；如无核心能力应换题／深化，不人为堆低价值项 |
| 否决过宽、触发次数互相矛盾、一般错误当否决 | **【误否决／可用率统计失真】** | 限于本题红线，统一计数与触发条件，普通问题用正常分项 |
| Subjective 超 10%、likert 无五档、累计规则前后不一 | **【评分器规则不合规／验收失败风险】** | 转成外部可观察标准，补齐档位和字段，不给 Judge 临时自由裁量 |
| metadata 视觉依赖、人时、等级与材料不符 | **【标签／等级验收风险】** | 如实改标签和估时，删除待确认占位，不按期望等级虚报 |
| 为达难度门槛调高扣分、隐瞒材料缺陷 | **【人工质检／诚信风险】** | 按真实任务深化能力要求并同步整包，不恶意改分或沿用失效评测 |

## 10. 出题完成核对与验收边界

**【提交前阻断项】**真实性／唯一性、核心材料完整性、答案与法源准确性、Rubric 自包含及字段校验、题包六处文件名一致性、Harbor 运行和三模型结果分别核验；任一关键项缺证据，不以本地流程成功代替项目验收。

- [ ] 场景和等级有当前分配依据；分别核对未重复提交及未命中存量方向，来源真实。
- [ ] 材料数量、完整度、时点、主体关系和视觉依赖符合任务；必要缺口可解释，不能导致题目不可判断。
- [ ] 题面五项必要信息齐备，口吻与身份相符，无答案或评分泄露。
- [ ] 实际交付物已确定并精确命名；参考组合没有被误当所有题目的固定清单。
- [ ] 专家答案可直接用于对应实务，结论、事实—规范—适用、职业立场和跨文件口径一致。
- [ ] 检索轨迹真实、逐项覆盖答案和 Rubric，链接定位一档正文，法规基准日和版本已核验。
- [ ] Rubric 维度、Q 数量、两个必选锚点、≥30% 锚点正分、至少两条 +10、Subjective ≤10% 均符合。
- [ ] 每项自包含、原子、稳定，不重复、不冲突；原始字段齐全，计数与分值匹配。
- [ ] 一票否决独立于计分，红线、阈值与计数明确；未决口径已按项目方确认。
- [ ] metadata 与实物、人时和当前登记一致；全文无待填、虚构来源和不真实检索。
- [ ] 题面／材料／答案／Rubric 改动后同步关联内容、重新核验，未沿用失效结果。
- [ ] 按交付规范完成实际文件、Oracle、多模型和人工验收；没有用本地流程状态替代项目方验收。

D 要求任务描述、材料、标准答案及评分方案内容准确性均 ≥99%。D 对 golden 写 ≥90%、三模型均分不超过 55%；H 更明确要求 golden 主分 **>0.90**、三模型均分 **<0.55**，同事项按 H 执行。运行框架、模型、有效分数和失败处理详见交付规范。

## 11. 原文差异、未决事项与使用边界

| 事项 | 已看到的差异／必须注意 |
| --- | --- |
| 定级场景限制 | D 先把全部 L4／L5 安排于 22 个 ≥3 题场景，列表不含 TL09、PG06；后文 L5 推荐又包含 TL09、PG06。认领具体等级时须核对项目方，不自行用推荐列表覆盖限制 |
| 维度 1 条数 | R 第3.4节 写四类“每类不超过一条”，又要求角色倒置每种情形单列；硬约束例子还出现累计扣分。须确认条目与情形的组织方式，保持原子性、不重复计分 |
| 维度 7 是否全题必设 | R 把维度 7 列为可选，又在细化中写负向至少一条。本文保留两条原意；未确认前不能声称所有题绝对可省略或全部必须额外覆盖 |
| 否决数量／示例 | R 同节出现“每情形单设一条”与“一题只设一条”；违规例子引用的否决情形和 Veto 示例正文、trigger_count 也有不匹配。以明确的全题独立可用性原则核对实际 schema，数量细节需确认 |
| JSON 字段／语法 | R 字段表用 score，部分类型示例用 weight；type 枚举又混用大小写；示例还含全角冒号等不可直接解析写法。原文例子不能直接当已通过 schema 的 JSON |
