# Work 法律全场景作答规范

## 适用范围与来源

本文件整理题目 Agent 的运行边界，以及数据集构建规则对标准法律交付物明确提出的质量要求。这里描述的是题目设计和参考答案验收基线，不代表系统自动保证模型作答满足法律专业标准。

## 题目 Agent 的输入边界

- 任务内容由 `instruction.md` 作为 prompt 提供。
- 题目 Agent 可读取 `/app/input_files/` 中的源文件；该目录只读，不得修改源文件。
- 镜像中预装的工具和依赖可供完成任务使用；`environment/requirements.txt` 中依赖在构建期安装。具体可用工具以题包环境为准。
- `task.toml` 不进入题目容器，只有 `[environment].env` 的值可见。
- `solution/` 仅在 Oracle 阶段可见，题目 Agent 不可见；`tests/` 仅在评分阶段上传，题目 Agent 不可见。因此作答不能依赖参考答案、Rubric TOML 或评分器内容。
- `/logs/agent/` 是运行日志位置，不是交付目录。

## 作答产物边界

- 所有交付物写入 `/app/output/`；这是唯一交付目录，工作目录为 `/app`。
- 按任务书要求逐项生成交付物，文件名须精确一致。文件名在任务书、`task.toml` 的 deliverables、`artifacts`、两份 golden 目录和 criterion 描述中保持逐字节一致。
- 不把产物写到 `/app/output/` 以外的绝对路径，也不把日志、临时文件或其他材料冒充交付物。
- 任务书应自包含，不能要求 Agent 依赖外部链接或隐藏语境；题目具体要求和输入材料以本次 `instruction.md` 与 `/app/input_files/` 为边界。

## 法律交付物的专业基线

题目要求的具体交付物因任务类型而异；构建规则对专家标准答案和验收提出以下质量基线，出题时应将与本题有关的部分转成清楚、可执行的任务要求：

- 完整度、体例、措辞和内容准确性应符合对应真实法律实务文书的使用场景。对任务中的每项法律问题给出明确结论；如存在法律不确定性，应说明争议或不确定性的具体原因、不同结果的成立条件和对本案的建议倾向，不以“建议咨询专业人士”代替分析。
- 说明应能追溯“事实—规范—适用”：事实来自输入材料并可定位；法律依据来自核验过的法规、案例或适用的域外法；分析说明依据如何适用于本案事实。不得编造输入中不存在的事实、送达过程、证据内容或案例；不能定位来源的事实应删除或明确标记待核实。
- 保持任务书要求的职业立场：代理人维护委托方立场，法官保持中立，检察官客观公正。全篇以及同题不同文件的金额、日期、比例、主体称谓与结论保持一致；计算结果应能复算。
- 法律法规引用应写明可定位的全称、条次和适用版本，并给出原文或可核验摘要；案例应能核验案号、裁判要旨和来源；域外法首次出现时给出原文名称、编号、条次及中文译名。不能只罗列条号，不能引用与分析问题无关或已失效的规范。
- 有明确长度、格式、文书惯例或文件要求时，应完整满足。不得用空标题、占位符、重复模板文字或“略／同上”代替实质内容；不得把摘录、检索清单或原始底稿冒充要求的分析交付物。
- 题目要求法规／案例检索轨迹时，轨迹应反映专家真实检索：检索词、命中原文或裁判要旨、可直接定位正文的 URL；覆盖 golden 与 Rubric 的全部援引，并记录相关版本核验。题目 Agent 只按 instruction 要求工作，不假定其能访问隐藏的专家检索记录。

## 任务书不得暴露的评分信息

出题方不得在 `instruction.md` 中放入 Rubric 条目、golden 内容或“评分会检查……”式提示。作答 Agent 应根据任务本身完成交付，不能通过泄露评分标准来迎合检查项。

## 适用边界

以上是跨任务质量基线，不取代某道题的 instruction、材料、任务类型要求或适用法律核验。检索轨迹是专家数据包的交付要求，并非题目 Agent 可见的隐藏附件；只有 instruction 明确要求模型提交某类研究说明或来源清单时，才把相应内容作为模型交付物。
