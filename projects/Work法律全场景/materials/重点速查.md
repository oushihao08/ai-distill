## 先守住的硬条件

- **L1 不做；L2、L3、L4、L5 都要覆盖。** 本专家具体数量、场景由认领登记和项目方分配确认。
- **必须是新数据。** 任何其他项目已提交题目或数据不得复用、迁移或换皮；尤其不得拿「豆包高经济价值」已有题目、案件附件、事实链、答案、计算、Rubric 或检索轨迹改编后提交。
- **模型测试：** Claude Code 下从 Claude Opus 5、GLM 5.3、Kimi-K3、Qwen 3.8-max0902 选三。用户通知为三模型平均分 ≤55%；交付规范写 <55%，实操以 <55% 为目标。参考答案 Oracle 主分须 >0.90。
- **时间：** 用户通知为认领后 5 天交包、收到质检后 2 天完成返修；主规则另有 1 个自然日内响应反馈的要求，认领前核实二者如何并行。
- **先准备真实新来源和专家标准答案。** 输入材料按 L2/L3/L4/L5 的参考下限分别为 3/10/50/100 份；完整、脱敏、相关，禁止凑数。Golden 答案和检索轨迹须由专家真实准备。
- **级别按真实必要工作量评定。** 分级表分别列“默认时程”和“专家人时”，metadata 又要求 3 年以上执业人员实际任务耗时（小时）；专家人时栏的数字口径与默认时程关系不清，不能直接互换，需确认后填。

## 题包与评分

- 单题 Harbor 目录必须含 instruction.md、task.toml、rubrics.json、environment、solution 和 tests 等规范内容；固定模板按交付规范原文逐字复制。
- Rubric 必设维度 1、2、5；另外 3/4/6/7 至少选两项；Q1–Q7 至少三项并覆盖任务类型两锚点，锚点正向分 ≥全部正向分的 30%。
- 一题至少两条 +10 关键项；负向严重度用标准档；每题一条独立 R0-V01 否决项。否决只统计可用率、不直接让整题归零。
- Harbor 中负向项用正 weight + `negate=true`，不能写负数 weight；golden 预检 >0.90；交付物文件名与路径逐处一致。
- 不得在任务题面泄漏评分规则或标准答案。裁判不得拿 golden 逐值对照；每条 criterion 自包含、可独立判定。
