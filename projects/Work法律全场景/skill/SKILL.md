# Work法律全场景出题总控

依据本次冻结案卷和真实法律执业场景，设计**有人会为此付费**、完全符合钉钉最新《Work法律全场景评测数据集构建规则》《Rubrics设计要求》《题包交付规范》且具有强专业区分度的法律实务题。

**核心方法：从委托目标与在卷原始记录双向穿透求解，用真实业务复杂性把平庸答卷挡在 55% 以下。** 作者先在执业立场与登记场景内完整读卷、检索一档权威法源原文并用脚本精确复算，确认哪份边缘凭证、哪项跨时际修法或哪条不合理诉求会改变结论，再定稿 `work_legal_v1` 完整题包（支撑自动导出 **Siriser 平台确认稿五件套** 与后续 **Harbor 六件套**）。材料确有空间时做深做透；材料不足以支撑高等级时如实记录差距，绝不靠虚构事实、单页摘录凑份数或恶意负分控分。

## 一、Work 六条铁律（无条件优先）

1. **一包一题与严禁重复**：一个材料包只对应一个题目身份，包内全部附件共同构成本题来源，严禁拆多题；返修重出沿用原题身份。严禁复用 `Work360`、`Work0-1`、`C项目` 历史题目，选题须避开 Work360 存量已覆盖案由／业务方向。
2. **`work_legal_v1` 同源契约**：按本次 `delivery.json` 的 schema 填写 `task_metadata`（含结构化 `instruction`）、`input_files`、`deliverables`、`reference_outputs`、`research_records`、`task_requirements`、`content_status`、`rubric`；公开 `question`、`reference_answer`、`answer_requirements` 与 `criterion/rule` 由程序同源派生，不另维护第二份。
3. **成果载体与必交检索轨迹**：业务成果仅允许 **`.docx` 和 `.xlsx`**（`format` 与扩展名一致，禁 `.pdf`/`.md`/`.tsv`）；每题须包含**至少 3 份不同用途的实质业务配套文书／测算表 ＋ 必交 1 份 `法规案例检索轨迹.xlsx`**（合计 `deliverables` **≥ 4 份**，至多 1 份检索轨迹）；所有 `.xlsx` 必须在 `reference_outputs` 提供完整结构化 `sheets` 与口径说明。
4. **最新官方六档 Rubric 体系**：完整题包至少 **30 项**独立判据；权重仅限六档 **`+10 / +7 / +3 / -3 / -7 / -10`**（**不设 `0-一票否决/Veto`、不设 `trigger_count` 累加文本**，`trigger_count` 统一填 `null`，确有违规处数或措施数量分档需求时用 `likert` + `points: 5` 写清 5/4/3/2/1 锚点）；必设维度 `1`、`2`、`5`，另从 `3`、`4`、`6` 至少选 2 个（`7` 按需选设反偷懒负向）；F1–F5 双锚点正分合计 ≥ 正向满分 **30%**，`+10` 至少 **2 条**，`Subjective ≤ 10%`，严禁“正话反说”双重扣分。
5. **官方双验收硬指标**：① 标准交付物（`reference_outputs`）内容准确率 ≥99%，按本题 Rubric 回测必须 **100% 满足全部正分项、零触发任何负分项**（确保 `golden` 预检得分率 **> 90%**）；② 题目设计须保证 `Claude opus5`、`GLM5.3`、`Kimi-K3`、`Qwen3.8-max0902` 中**三 SOTA 模型均分 ≤ 55%**（且至少一模型得分）。
6. **真实委托口吻与受众纯净**：普通委托人采用第一人称口语化口述（自然混入冗余、顺序颠倒、情绪干扰及不专业／越界诉求，不写文书体例与法律定性），专业委托方采用行内正式交办口吻；同时交代清楚脱敏后的委托方与相对方主体对应关系。`reference_outputs`（含 `sheets` 单元格）严禁残留任何 AI／模型身份、内部工具名、出题／评分视角词或未填净的模板占位符。

## 二、保证“三模型均分 ≤55%”的六大合规实务机制

禁止设计无人付费的纯 adversarial 脑筋急转弯，禁止靠恶意负分或绑定本地未验证的底层 OOXML 公式属性压分；难度必须来自以下真实实务工作负载（按本包真实材料选用）：

1. **全卷边缘凭证穿透消歧（Q1/Q5 核心失分点）**
   - 题面绝不替模型归纳时间线、资金账目或证据冲突；把改变诉讼时效／除斥期起算、实际欠款净额、担保上限或主体适格的关键事实锚定在**主文转述与底层原始凭证的差异处**（如汇总表／旧诉状 vs 银行回单、退票记录、送达回证、补充协议、工商内档、庭审笔录自认），只读主文摘要必错。
2. **当事人口语干扰与不合理／越界诉求纠偏（维度 1/Q2/Q4/维度 5 区分点）**
   - 普通委托人场景在 `instruction.requests` 中自然混入 1–2 项**表面有利本方但依法不成立、违反专属管辖／前置程序、会招致反噬失权或触碰合规底线的诉求**；平庸模型顺从当事人照写即丢失 `+10` 核心定性分，越过合规红线的还会触发负向扣分。
3. **跨时际权威法源核验与新旧条号对齐（Q3/Q4 核心失分点）**
   - 行为发生日与基准日跨越修法、司法解释更替、过渡期规则或多段 LPR 调整时，题面只给客观基准日，零年份／文号提示；作者打开一档官方正文核清条号、施行日与条文原文写入 `research_records` 与检索轨迹，封堵模型惯性套用现行条号审历史行为或引用已废止文件。
4. **多约束联动核算与可复算口径闭环（Q5 核心失分点）**
   - 涉及多笔往来去重、清偿抵充顺序（实现债权费用 → 利息 → 主债务）、分段计息、优先受偿顺位或赔偿篮子扣减时，用计算脚本精确跑通全链路；在测算表与文书中统一基数口径、计算公式、数据来源与核定数值，错取基数或漏扣一笔即连锁失分。
5. **法定动作四要素闭环与内外分件隔离（Q6/维度 3/维度 6 核心失分点）**
   - 方案与行动指令严格按**“具体动作 ＋ 执行主体 ＋ 精确时限（含起算依据与届满日）＋ 所需材料”**四要素落地，缺一不可执行；含己方败诉底牌、不合理诉求驳回说理或多路径利害权衡的内容独立成对内文件（如《委托诉求处理说明.docx》），严禁塞进对外提交法院或相对方的清洁正稿。
6. **Rubric 分值重心锁定硬核判断（结构性控分，不搞恶意扣分）**
   - 将 **75% 以上的正向满分**集中在需穿透底层凭证、核准有效法源原文、完成要件涵摄、精确复算数值及四要素可执行动作的 `+10` 与 `+7` 条目上；交付齐备、通用体例（合并为 1 条 `+3`）与底线守门仅占小头，使“格式工整＋堆砌通用法条＋复述主文”的答卷自然停留在 25%–45% 区间。

## 四、保存前必过八条硬红线（对标 11-17 官方质检退回清单）

1. **源文件与时间线零硬伤**：核对在卷文书无“送达早于出具、前文预知后判、诉后材料充诉前证据”等时间线矛盾；脱敏后委托方与相对方主体对应关系在 `instruction` 中清晰可辨，无空白失明主体。
2. **口吻真实、不喂答案、不泄底**：普通委托人保持第一人称口述（不写文书体例、不评价证据法律关系），专业委托方保持行内交办风格；零“本题／考察／请注意／模拟律师／假定……”痕迹；`instruction` 与 `deliverables` 文件名绝不泄露待裁决救济路径、修法年份、旧稿具体错点或账据重复异常。
3. **必交检索轨迹与 ≥4 份 `.docx`/`.xlsx` 逐字节对齐**：`deliverables` 含 **≥3 份实质业务成果 ＋ 1 份 `法规案例检索轨迹.xlsx`**，后缀与 `format` 仅限 `docx`/`xlsx`、无动态日期或版本号、≤200 字节；全部成果在 `reference_outputs` 有完整正文（`.xlsx` 必含非空 `sheets` 且行列合法）；`evaluated_files` 100% 精确匹配 `deliverables[].path` 或单独 `["all"]`。
4. **标准成果零编造、零错用、受众纯净**：`reference_outputs` 每一项事实均可定位到 `input_files`（无依据处写“待核实”，绝不编造双方意见或送达事实）；案号代字与法律概念准确（如区分“民撤/民初”、“行政罚款/罚金”）；具备法定文书首尾结构、无内部矛盾、无未填占位符、字数达标；全文及全部 `sheets` 单元格零 AI／模型身份、零内部工具名（`AnySearch`/`Codex`/`Harbor`/`JSON`/`research_records` 等）、零出题／评分视角词。
5. **一档法源原文与检索轨迹全覆盖**：主交付物与 Rubric 中每一条法规／案例援引均写出**规范全称＋准确条次（修订年份在书名号外）＋条文原文或规定摘要**（案例上网核验真实存在且案情相符，严禁编造案号或错背条文），并在 `research_records` 与 `法规案例检索轨迹.xlsx` 中有一档官方正文 URL 及版本核验记录，零引用公众号／百科等三档来源。
6. **Rubric 合规无 Veto、无重计、`golden` 满分通过**：`rubric.length >= 30`；仅用 `+10/+7/+3/-3/-7/-10` 六档（**零 `Veto`、零 `0-一票否决`、`trigger_count` 全为 `null`**）；必设维度 1/2/5＋另选 3/4/6 中 ≥2 个；双锚点正分 ≥30%，`+10` ≥2 条，`Subjective` ≤10%；零“正话反说”双扣、零同一法条／数值拆多条刷分、零要求 `input` 外事实或 `golden` 未做事项。
7. **难度稳压 ≤55%**：`+10/+7` 核心判断占正向满分 ≥75%；代入“只读主文摘要＋顺从当事人不当诉求＋套模板堆通用法条”的答卷试算，确认其得分稳压在 **35%–50%** 以下，而完整等效合法解可得 **> 90%**。
8. **元数据与对外交付口径纯净**：`input_files` 的 `attachment_id` 与 `name` 原样复制自 `delivery.json.input_files`；源文件含扫描件／图片／图表时 `vl_dependency` 如实填 `true`；`level_basis` 逐份登记真实独立文书与实际业务耗时（小时）。对外投影字段（`instruction`、`source_note`、`level_basis.explanation`、`reference_outputs`）一律保持“真人律师审阅原卷文件”的真实业务视角，**严禁出现“提取文本／提取原文／页标／未另行读取扫描PDF／历史题包／保留原姓名／不脱敏／不改写原件／不能据标签宣称已获LX认证／待专家确认”等内部流水线措辞**；内部审计或预处理边界说明一律仅写进包外私有的 `generation_note`。`instruction.hard_constraints` 数组元素不自带 `1. ` 等编号前缀；`法规案例检索轨迹.xlsx` 仅收录真实核验有效的法源／案例记录，超时未核实线索不写入对外表格。
