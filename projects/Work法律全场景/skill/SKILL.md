# Work 法律全场景高难度出题

## 本项目规则

先完整读取[出题规范](references/出题规范.md)和[交付规范](references/交付规范.md)，再使用下列出题方法与模板。两份规范是本 skill 内的项目规则依据，保留完整必选项、字段、验收要求和原文冲突；同事项按交付规范所列 H 优先级执行，未决事项不自行改成确定规则。

规则副本来源于本项目 materials 下同名文档，核对日期为 2026-10-13。项目配额不等于本题认领，历史计划日期不等于当前期限；按本次实际分配和已确认更新使用。执行时只需读取本 skill 内部文件，不依赖其他项目目录。

## 本地系统调用契约

普通出题调用明确采用 `model_report_v1` 且 `answer_requirements=text/text/tools=[]` 时，按本轮已确认的纯文字评测边界完成内部题包。保持本 skill 的实务深度、正负分和独立否决规则；被测模型仅接收题面及获准脱敏附件，不要求其访问互联网、调用工具或生成文件。正式 Work 文件题包及 Harbor 六件套仍按交付规范另行准备，不能把本次内部文字评测称为正式验收。

- 题面、Rubric、思路和完整标答使用本次调用的既有JSON字段；不要自行新增顶层字段。
- 新Rubric每项用 `id、criterion、rule`，rule完整保留计分或否决条件。Work原始字段全部保存在metadata对象；不要把负项伪装成正向max_score，也不要遗漏R0-V01。
- 本题计分口径以调用方冻结的评分规则为单一来源；不从历史成绩调整宽严。素材和结构检查不替代模型专业判断。
- 任务需要正式文件或工具而本次文字能力无法承载时，明确交付缺口；不假报文件已生成。无新契约的旧调用仍按既有契约处理，不强行塞入无法保存的负分字段。

## 唯一任务

出一道有真实付费办理价值、专业判断深入的 Work 法律实务题。难度来自必要的法律工作，不为攻击模型弱点牺牲真实性和可用性。按本次委托和材料确定主要作答者、其职业或诉讼身份、可取得的材料、权限及成果使用人。按 Work 六类主体确定岗位：诉讼律师、非诉律师、企业法务与合规、法官与法院辅助、检察官与检察辅助、立法与政策研究。原告、被告或被告人、第三人、案外人等是材料人物或服务对象的诉讼身份，不能代替认领的职业分类。再以严格的对抗审查视角逐层追问事实、证据、法律适用、金额、程序、权限、方案和文书中的漏洞，充分展开能考验专业能力的工作。

不要为照顾作答模型而删去真实委托所需的工作、解释待判断问题或给出解题路线。先确定完成委托的最少必要判断和成果；材料确实涉及多个决定、独立争点或连续变化时再充分展开，并让每项要求对应实际业务用途、可见依据和作答者权限。

## 出题视角

- 角色必须改变本题需要完成的专业判断、可用材料、行动边界或实际交付；不能只换称谓。公司内部法务题继续按公司业务、审批和执行需要设计，其他角色按各自职责设计，不要求其代行别人的职权。
- 从有利与不利立场分别审视材料，寻找看似成立但经不起追问的结论、请求、核算和安排。
- 追查不同来源、时间、主体及规则之间的关系。让作答者定位依据，判断记录是否同源、能否相互印证及各自的证明范围，再形成处理结论；将表面一致、隐藏差异、部分成立及例外纳入考查。
- 提高工作深度：从本题真实争点和交付用途选择必要的证据取舍、法律适用、反驳、核算、方案比较或后续处理；只有材料与委托确实需要时才布置临界条件求解、连续变化和对应文书。未用某种机制不必补另一种机制凑难度，但已可完成的专业判断不能删成泛泛意见。
- 让作答者自行发现问题。题面交代工作和条件，不替其指出证据错误、提示应采信的材料或预告正确结论。
- 按本题独立工作确定真实交付文件及数量；每份承担不同专业工作，核对主体、金额、时点和动作。F1–F5 的组合是参考，实际交付按任务确认。素材不足时记录必要材料缺口，不生成模拟材料、拆文件或重复改写意见凑数量。
- 深挖表面合理却应修正的主张，也保留看似可疑但依法可以成立或办理的事项。让作答者分别确定成立、附条件成立及应排除或阻断的范围，回应有依据的相反主张；涉及执行时落实可执行范围，不预设各种结论的数量，不让全批、全拒或全部待核成为捷径。
- 将法律定性、有效规则和事件时点落实为计算基数及办理条件。连续变化应迫使重新判断，并更新受影响的结果；不靠重复扣同一错误放大难度。具体构造见[出题设计方法](references/出题设计方法.md)。
- 充分利用可用阅读、检索和核算工具。本次提供的业务资料和评测记录、公开法律来源及按需选读的案例可辅助设计；案件事实与公开法律依据分清来源，模型推演不成为新事实。不自行引入旧题、旧答案或旧评分作为本次业务材料。

## 参考模板与设计迁移

先按当前附件与业务用途设计任务；需要参考构造机制时，通过[案例库索引](assets/成功案例索引.md)按需选读。案例并列，不固定套用。借鉴判断关系，自行设计本题任务；无匹配项时直接设计，不继承案例的事实、参数、成果组合或成绩。依据本次可见的已知题目检查实质差异，具体见[模板参考与迁移](references/模板参考与迁移.md)。

## 内容正确性

真实材料保持原意、完整性和脱敏对应关系；不以模型生成内容替代真实材料，不恢复被遮蔽信息。标答及考点有依据，支持多种正确处理时接受实质等价答案。加难落实在题目工作中，不用错误事实、错误计算或事后改判分尺度制造低分。

作者检索核实法律及相反解释，用于出题、考点和标答；题面不附作者的检索讲解、搜索链接或答案依据清单。保留原始资料中的法律内容、业务事实及有来源的必要条件，让作答者自行选择和说明依据。

按本次实际工具能力设计可读输入。复杂、少见的法律适用可以考，但不以未提供的个案事实或某网页观点指定唯一答案。隐藏批注、新增文件及需实时检索的特定资料必须实际可取得，不能只存在于作者工作区。具体边界见[出题设计方法](references/出题设计方法.md)。

## 交付

沿用题目包中任务信息、题面、Rubric、作答思路和完整标准答案的组织方法，具体文件、字段与阶段按 Work 规范，不把旧项目七项纯文本结构当成正式交付。题面明确基准日、真实诉求、硬约束和实际交付物；Harbor 必交文件使用固定路径，六处命名一致。

Rubric 不固定条数，不沿用旧项目等权分：原始计分仅 +3／+7／+10／−3／−7／−10，Veto 为 null、独立统计。维度 1／2／5 必设，3／4／6／7 至少另选两个；Q 至少三个且含任务类型的两个锚点，锚点正分占比 ≥30%，至少两条 +10，Subjective 条数 ≤10%。每条字段、五档 likert、计数与否决按[评分与难度验证](references/评分与难度验证.md)和完整规范。

模型可辅助形成供专家核定的完整草稿；未经专家亲自撰写并核定，不标为正式专家 golden。实际工具检索记录可以如实保存，但不能冒充专家本人办理轨迹，不能事后补造。正式交付必须有专家真实检索轨迹与实际可用文件。

本次调用若指定系统 JSON 或交付路径，先核对是否能完整承载 Work 的文件、负分、否决及元数据。不能承载的部分明确报告契约缺口，不擅自将负分改成正向分、丢弃否决、把文件任务改成纯文本，或称系统内部评分已经符合 Work 验收。完成不受缺口影响的内容；不修改调用方 schema 或业务数据来绕过。

题面和对外交付物不出现数据库编号、本机路径、模型成绩或 AI 出题过程；容器内业务路径按 Work 要求保留。Oracle >0.90 且 verifier_error=0、规定三模型均分 <0.55 与人工验收必须有实际证据，不能从草稿或本地归档状态推断。

交付前按[成稿检查](references/出题设计方法.md#成稿)核对题面是否代做待考判断，按[出题设计方法](references/出题设计方法.md#核对有依据的竞争解释)核对材料关系是否支撑具体判断与办理，按[评分与难度验证](references/评分与难度验证.md#考点)核对考点是否对应独立结果、同一错误是否重复处罚；再按[题目格式与交付](references/题目格式与交付.md)核对必要成果及变化范围。保留原件确定事实与必要条件，不以重复计算或隐含要求制造难度。
