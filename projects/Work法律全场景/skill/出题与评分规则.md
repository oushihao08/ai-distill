# Work法律全场景：出题与评分规则

本文规定任务描述、源文件、标准成果、评分方案及题目信息。首批筹备另读[LS场景出题规则](首批筹备-LS场景出题规则.md)，确定本题场景、方向及成果；两份文档共同使用。填写形式可参考[题目信息示例](题目信息填写示例.md)与[检索轨迹示例](检索轨迹填写示例.tsv)，示例内容不作为本题事实或通用要求。目录入口见[SKILL.md](SKILL.md)。

## 一、任务描述

用途：把真实委托事项完整交给模型，明确背景、诉求、交付物和不可退让的条件。

| 要素 | 原文要求 | 作用／结果 |
|---|---|---|
| 业务／案件背景 | 交代交易或纠纷经过、各方关系、已发生事实；允许冗余、矛盾和干扰信息 | 让模型自行梳理事实、识别法律关系，判断哪些信息可信或相关 |
| 委托方诉求或办案要求 | 逐项说明委托方想要什么；允许包含不专业、不可行、越界的诉求 | 检查模型能否识别不合理诉求并正确处理 |
| 交付物要求 | 明确交什么材料、每份大致包含什么；普通委托人口吻不直接规定文书体例 | 确定最终产物及其必要内容 |
| 基准时间点 | 写明交付物出具日、尽调基准日或评估基准日 | 确定适用法规版本、时效及信息截止范围 |
| 硬约束 | 提交期限、金额上限、必须保留条款、不得披露事项等；独立编号单列 | 评分时逐项检查遵守情况 |

口吻及内容要求：

- 以委托人第一人称口述为主体，只讲亲历事实、感受和期望结果；不预先解释证据性质、法律关系或指导文书如何写。
- 可以口语化、啰嗦、顺序颠倒、带情绪。
- 委托方为律师、法官、检察官、监管部门等专业人士时，使用对应专业行文，可以提出专业术语和体例要求，但不能提示考点。
- 不出现“本题”“考察”“请注意”“重点是”、任务类型编号、评测维度名称等出题痕迹。
- 基准日同时约束题面、标准成果和评分使用的事实范围。晚于基准日形成的材料，不得作为该时点已知事实；回溯复核确需使用后续材料时，明确区分原决策时点与本次复核时点及各自可用材料。

文件形式及对应关系：

| 阶段／字段 | 要求及作用 |
|---|---|
| 专家初稿 | `任务说明.docx` |
| 构建规则中的名称 | `instruction.json` |
| Harbor实际交付 | `instruction.md`，仅接受此文件名，≤1 MiB，作为模型的任务提示词 |
| 源文件说明 | 逐个列出 `/app/input_files/` 下的文件及相关字段、口径说明 |
| 交付路径 | 明确写入 `/app/output/`，逐个列出精确文件名 |
| 对齐要求 | 显式评分要求应在任务书中有出处；任务书硬性要求应有评分项覆盖 |
| 保密边界 | 不泄露评分条目、标准答案内容或“评分将检查……”式提示 |

## 二、源文件

用途：提供完成任务所需的真实材料，包括合同、证据、卷宗、尽调底稿和模板等。

| 项目 | 原文要求 | 作用／结果 |
|---|---|---|
| 数量 | L2≥3份；L3≥10份；L4≥50份；L5≥100份 | 满足对应任务长程性所需的材料规模 |
| L5材料构成 | 多项目、跨不同时期的不同材料 | 支撑跨项目、跨时期的综合任务 |
| 真实性 | 真实实务材料脱敏改写；不得由模型批量生成凑数 | 保持真实工作场景和有效难度 |
| 完整内容 | 不能用摘录、概要或节选冒充完整文件 | 让模型实际读取、筛选和交叉核验 |
| 格式与体例 | 行文结构、格式、表述细节应符合该类真实文件 | 避免简单模板或仿真材料失真 |
| 完备性 | 正确结论所必需的材料齐备 | 避免缺材料造成结论不唯一 |
| 可设置的缺口 | 只允许真实场景中确会缺失、且正确处理是明示缺口并列补充清单的情况 | 考察补充材料意识，不能以信息缺失制造无解题 |
| 文件形式 | 可含PDF、Word、Excel、扫描件、PNG等 | 对应识读、OCR、计算和核验能力 |

等级同时按成熟法律实务人员完成业务的必要工作核对，不计算设计题包、AI等待或人为增加的操作成本：

| 等级 | 专家业务人时 | 最短必要步骤 |
| --- | --- | --- |
| L2 | 0.5–2小时 | 10–30 |
| L3 | 2–8小时 | 30–100 |
| L4 | 8–40小时 | 100–500 |
| L5 | 40小时以上 | 500+ |

本系统的`level_basis.documents`按材料内可辨识、真实完整且相关的独立文书逐份登记，并填写附件和页段位置。一个合订附件不直接等于只有一份文书；也不能把分页、PDF分片、重复件或仅被提及但未提供的文书计为新增材料。未清点或完整性不足时如实说明，不以附件数量直接断定等级。实际人时与指定等级不符时保留真实工作及估算，说明等级未成立，不改数字或删除难点凑级。

存放及使用结果：

- 专家初稿放在 `input_files/`，目录名不能改成“源文件”。
- Harbor题包放在 `environment/input_files/`。
- 模型看到的路径是 `/app/input_files/`，只读，不得修改。
- 每份材料应在任务描述中列明；不能通过隐藏说明补足必要语境。

## 三、标准交付物

用途：由法律专家亲自撰写，提供可在真实实务中使用的标准答案，并作为评分细则的拆解来源。

以下组合是参考，具体交付物由出题专家按实际任务确定：

| 任务类型 | 标准交付物组合 |
|---|---|
| F1 咨询研究 | 法律研究报告／法律意见书／检索报告；法规案例检索轨迹 |
| F2 审查审核 | 审查意见书或尽调报告；风险清单；修订留痕版或300–500字审查意见邮件，覆盖全部高风险项；检索轨迹 |
| F3 文书起草 | 可直接提交、报送或对外出具的文书正稿；证据或附随材料清单；委托诉求处理说明；检索轨迹 |
| F4 方案设计 | 方案或预案正文；法定动作清单；支撑依据分析，含替代路径及成本／风险比较；检索轨迹 |
| F5 数据核算 | 结构化台账或测算表；口径说明；分析结论与预警清单；检索轨迹 |

其中明确要求的内容字段：

| 内容 | 字段／要素 | 作用／结果 |
|---|---|---|
| 风险清单 | 风险等级、风险描述、判定依据、修改或整改方案、是否必须修改 | 按风险从高到低排序，支持处置决策 |
| 证据／附随材料清单 | 编号、名称、形式、证明内容、证明目的 | 按证明对象或请求权路径分组，形成证据对应关系 |
| 法定动作清单 | 动作、执行主体、时限、所需材料 | 形成可以执行的步骤 |
| 测算口径说明 | 基数口径、计算公式、数据来源、假设条件 | 让公式和结果可复算 |
| 法律分析 | 事实、规范、适用 | 每项结论可追溯到源文件及核验过的法律依据 |

质量要求：

- **可直接使用**：完整度、体例、措辞、准确性符合真实对外文书要求。
- **结论明确**：每项问题有结论；确有不确定性时，写明原因、可能结果及条件、针对本案的建议倾向。
- **说理完整**：事实来自源文件，规范来自已核验的法规或类案。
- **立场一致**：代理律师保持委托方立场，法官中立，检察官客观公正。
- **口径统一**：不同交付物中的金额、日期、比例、主体名称一致。

法条与案例引用要求：

| 类型 | 必须包含 |
|---|---|
| 法律、行政法规 | 全称＋中文数字条次，款、项及“之一”“之二”不能省略 |
| 原文标为“部门规章”的一行 | 全称＋发布机关令号 |
| 司法解释 | 全称＋法释文号 |
| 修订版本 | 修订年份写在书名号外 |
| 案例 | 案号＋裁判要点＋来源 |
| 域外法 | 原文名称＋编号＋条次，首次附中文译名 |

**不能只写条号，必须给出条文原文或规定摘要**，便于裁判判断该规定是否支撑分析。

检索轨迹为所有任务类型的必交项，必须是专家办理过程中的真实记录，不能由模型生成或事后补写。

| 检索轨迹字段 | 要求／作用 |
|---|---|
| 检索词 | 记录实际检索入口 |
| 命中要点 | 法条原文或裁判要旨摘录 |
| 来源URL | 能定位到法规或裁判正文 |
| 版本核验记录 | 材料引用旧版、基准日应适用新版时，写明新旧条号对照 |

轨迹必须覆盖主交付物与评分细则中的每一条援引；没有轨迹的援引视为未核验。允许作为依据的是官方正文来源、国家法律法规数据库、法院正式案例来源、北大法宝／威科正文页、域外官方数据库。行业解读仅辅助理解；公众号、律所推文、百科、问答社区、聚合资讯不得作为依据，出现时按负向条目扣分。

交付物清单的结构化字段：

| 字段 | 要求 | 作用／结果 |
|---|---|---|
| `path` | 相对 `/app/output/` 的文件名；必交文件必须精确命名 | 定位交付物 |
| `required` | `true`必交，`false`可选 | 必交文件缺失即未完成交付 |
| `desc` | 一句话说明 | 说明文件用途 |
| `artifacts` | 必交文件路径加 `/app/output/` 前缀展开 | 登记产物路径 |

任务书、清单、`artifacts`、两份标准答案、评分描述引用的路径须逐字节一致。文件名不得含动态日期、时间戳或版本号；单个文件名≤200字节。

标准答案位于 `solution/golden_output/`，评分侧副本位于 `tests/__golden_output/`，两份内容一致、均不能为空。应满足全部正分项且不触发扣分项。

## 四、评分方案

用途：把专业人员对交付物实际可用性的判断，拆成裁判可以独立判断的具体评分点。

基本要求：

- 从最终标准交付物逐项拆解；核心内容全部覆盖，答案修改时同步修改评分细则。
- 先从标准成果提取独立业务结果，再写判据。对拟合并内容代入“甲正确、乙错误”的回答：两者各有独立业务意义则拆条；共同决定同一结果的必要要素保留整体判定。不同证据、金额或法源不能只因同主题就捆成一条；同一计算的口径、公式、结果不必机械拆开。判据客观、自包含，接受等效合法表达。
- 正向写“正确输出了什么”；负向写“实际做了什么错事”。
- 每个业务结果只设一个主计分位置。逐对核对共享同一事实、计算或结论的条目：若同一回答重复获得正分，或同一未满足点先漏正分再被其反面扣分，合并或划清独立评价对象。负项描述额外实际错误行为，不将核心正项的反面换名再扣；独立否决保持自身计数，不并入主分。共享材料但评价不同独立结果的条目可以保留。
- 判定所需事实、正确值、法规内容、接受范围和命中条件全部写入评分项。
- 不能写“详见参考答案”“参照上条”“等”等省略表达。
- 主观项不超过总条数的10%。

评分边界示例（仅演示判断方法，不继承案件内容、成果组合或权重）：

| 边界 | 应调整 | 可保留 |
| --- | --- | --- |
| 独立结果 | “正确计算欠款金额，并判断上诉是否可行”应拆；两项可一对一错，影响不同业务决策 | 同一次计算的基数、公式和结果可合并；同一法律结论成立的必要要素不机械拆开 |
| 重复计分 | Q5奖励欠款算式正确，维度4又奖励同一算式正确，应保留一个主计分位置 | Q1评价凭证证明范围，Q6评价取得缺失凭证的行动，使用同份材料仍可分别计分；负项须命中实际错误，不能只因正项未满足就触发 |
| 主维度 | “指出缺少付款凭证及其证明缺口”归Q1；“明确谁向谁取得凭证、何时完成”归Q6 | 评价跨文件核验的方法可归维度4，但不再次奖励Q5已计分的计算结果；具体空话替代分析的行为可归维度7，不因涉及建议就一律归Q6 |

原始评分文件字段：

| 字段 | 定义及要求 | 作用／结果 |
|---|---|---|
| `id` | 正向`R{维度}-P{序号}`；负向`R{维度}-N{序号}`；否决示例`R0-V01` | 唯一标识、追溯评分项 |
| `statement` | 完整判定标准；包含正确值或错误情形、全部／任一条件、等效表达范围 | 直接决定是否命中 |
| `criterion_type` | `Objective`可验证；`Subjective`需结合语境 | 标识判断性质，控制主观比例 |
| `criterion_necessity` | `Explicit`任务明文要求；`Implicit`由职业常识或语境必然推导 | 标识要求来源 |
| `dimension` | 一级维度；内容质量写到Q1–Q7 | 汇总维度表现 |
| `evaluated_files` | 字符串数组，填写标准答案文件名；跨全部文件写`all` | 按文件功能找到对应被测输出 |
| `knowledge_points` | `法律域::具体知识点`；无对应知识点填空 | 按知识点定位短板 |
| `atomic_capabilities` | 每条0–3个；首项主导，其余兼考 | 命中率及失分归主导能力，兼考只统计覆盖 |
| `priority` | 与六档分数或`Veto`一一对应 | 标识重要性／危害性 |
| `score` | `10、7、3、-3、-7、-10`；否决为`null` | 确定加减分 |
| `type` | `binary`默认；或`likert` | 二元判定或分档判定 |
| `points` | Likert固定5；Binary及否决为`null` | 确定五档标度 |
| `trigger_count` | 可累计扣分规则；一次性扣分和正向为`null` | 确定按处数累计还是只计一次 |

负向项先确定仅计一次还是按处累计；`statement`与`trigger_count`保持同一口径，不能同时出现两种算法。仅计一次时`trigger_count = null`；累计时填写每处定义、分值与封顶口径。

`statement`写业务判定标准、合法替代、必要的likert档位或累计条件；数值权重以`score`为唯一来源，不在每条正文另写“计+7，否则0”等重复分值，以免与字段冲突。本系统的`criterion/rule`由原始字段派生，不由作者另维护一套。

`evaluated_files`、`knowledge_points`、`atomic_capabilities`是分析型元数据，不进入判定正文、不直接参与计分、不改变净得分率或否决结果。

评分维度：

| 维度 | 检查内容 |
|---|---|
| 1 指令遵循与任务理解，必设 | 交付物齐备、硬约束、角色立场、基准日 |
| 2 交付物内容质量，必设 | 下列Q1–Q7 |
| 3 体例规范与可读性 | 法定／惯例要素、清单字段、层级编号 |
| 4 推理与规划 | 工作顺序、跨文件核验、检索及版本核验 |
| 5 安全合规，必设 | 违法建议、执业红线、编造 |
| 6 协作体验 | 可编辑、可接手、待确认事项明确 |
| 7 反偷懒与反模板 | 回避结论、通用模板、空标题、以“略”代答、大段复制 |

除必设的1、2、5外，3、4、6、7中至少再选两个。维度5可以只设负向；维度7选设时至少有一条具体、可量化的负向项。

先按statement实际判断的业务结果确定一个主维度；内容质量只填一个主Q，不用多Q拼接。查法源是否真实/版本正确归Q3，将事实代入法律要件归Q4；证据证明范围归Q1，风险判断归Q2，数量/金额/期间核算归Q5，落实行动归Q6。附带提及法条不改变主归属；兼考能力放atomic_capabilities。

维度1按交付物齐备、硬约束、角色立场、基准日分别组织，每类不超过一条；交付齐备按二元判断，角色立场只设负向。专业实质判断归维度2，不能靠换名称重复计分。维度5的普通负项分别明确编造法源、事实／证据、检索来源的具体行为及适用计数；不能只设集中编造的否决项而漏掉普通扣分。

| 内容质量子维度 | 检查内容 |
|---|---|
| Q1 事实与证据 | 事实准确完整、冲突采信、证据三性、材料缺口 |
| Q2 风险与问题 | 风险识别、等级及依据 |
| Q3 法源与援引 | 核心规范、条号内容、时间效力、案例可比性 |
| Q4 法律适用与定性 | 事实对应规范要件、例外及抗辩 |
| Q5 计算与门槛 | 金额、比例、期间、基数口径、法定门槛 |
| Q6 结论与执行 | 明确结论、主体、时限、材料、路径及替代方案 |
| Q7 内部一致性 | 同一事实、结论依据、风险处置、判项请求是否矛盾；默认仅负向 |

每题至少选三个Q维度，并包含任务类型的两个锚点；两个锚点正分合计须占正向满分30%以上：

每题至少两条`Critically Important`（+10）评分项。拆项后按各独立结果的真实后果重新定权重，不让所有子项机械继承原+10。合并重复项时保留实质覆盖，再核对锚点占比及其余结构要求，不删难点凑合规率。

| 类型 | 必选锚点 |
|---|---|
| F1 | Q3＋Q4 |
| F2 | Q2＋Q3 |
| F3 | Q1＋Q4 |
| F4 | Q4＋Q6 |
| F5 | Q1＋Q5 |

分值及结果：

| `priority` | 分值 | 含义 |
|---|---:|---|
| Critically Important | +10 | 缺失会使整体结论方向错误、需要重做 |
| Important | +7 | 需明显补充核查或修改才能使用 |
| Slightly Important | +3 | 细节完善，可由复核人员补齐 |
| Slightly Detrimental | −3 | 易发现、修改成本低的小错 |
| Detrimental | −7 | 需回查材料或法源的重要错误 |
| Critically Detrimental | −10 | 违法建议、立场倒置、编造或核心定性错误 |
| Veto | 不计分 | 判定实务不可用，单独统计 |

一票否决包括具体违法／舞弊建议、职业立场红线，以及编造法规或裁判依据、事实证据、URL或检索轨迹分别累计**超过3处**的情形。普通遗漏、说理不足、体例缺陷不应直接否决。三类编造分开计数，不将不同类别合计凑到阈值。否决不使分数归零，对应负向仍正常扣分。

Harbor转换后的字段：

| 字段 | 要求／结果 |
|---|---|
| `criterion.id` | 与原始评分项编号一致 |
| `criterion.name` | 必填且等于`id` |
| `criterion.description` | 完整标准＋`output/具体文件名`；Likert附五档锚点 |
| `criterion.type` | `binary`或`likert` |
| `criterion.points` | Likert固定5 |
| `criterion.weight` | 只允许正数`3.0、7.0、10.0` |
| `criterion.negate` | 负向设`true`，不能使用负权重 |
| `judge.mode` | `individual`，逐条独立会话、串行评分 |
| `judge.prompt_template` | `prompt.md`，保留`{criteria}`占位符 |
| `scoring.aggregation` | `weighted_mean`；最终主分按固定聚合脚本计算 |

计分结果定义：

- Binary：命中／未命中。
- Likert：输出1–5整数，归一化为`(raw−1)/4`。
- 满分：所有正向分值之和，负向不进分母。
- 净分：正向得分减去负向扣分。
- Harbor主分：`clip(净分÷满分, 0, 1)`。
- 可用率：未触发否决的题目数÷总题数，独立统计。
- `reward.json`、`reward.txt`：主分；`reward-details.json`：逐项明细；评分不可用时另写错误结果。

## 五、题目信息

用途：记录题目的归属、任务类型、能力、长程性、材料来源及完成任务所需资源。

| 字段 | 填写要求 | 作用／结果 |
|---|---|---|
| 题目编号 | `法律-{三级场景编号}-{提交日期}-{专家姓名}` | 标识题目及专家提交 |
| 所属领域 | 固定“法律” | 领域归属 |
| 一级／二级／三级场景 | 与认领登记表完全一致，不简写、不自行归并 | 场景分类 |
| 任务类型 | F1–F5，按主交付物形态 | 决定参考组合及评分锚点 |
| 评测的能力 | 从对应场景重要能力中结合实际选择2–4项 | 说明实际考察能力 |
| 任务长程性等级 | L2–L5，专家预判，负责人最终认定 | 标识任务规模与长程性 |
| 是否依赖多模态识读VL | 有扫描件、图片、图表截图填“是”，列文件 | 标识视觉识读依赖 |
| 任务说明 | 任务设计、交付要求、主要考察点 | 说明题目设计 |
| 专家耗时 | 3年以上经验从业者完成该实务任务的预计小时数 | 辅助判断长程性；不是制作题包耗时 |
| 数据来源 | 真实案卷卷宗匿名化改编 | 记录来源 |
| 需要哪些工具 | OCR、表格计算、法规／案例检索、企业查询等 | 记录完成任务的工具需求 |
| 需要哪些专业知识 | 完成本题所需具体制度或领域知识 | 记录专业知识依赖 |

## 原文中直接影响这五项的差异

| 项目 | 原文中的不同表述 |
|---|---|
