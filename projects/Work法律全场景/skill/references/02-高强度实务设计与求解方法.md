# 高强度实务设计与求解方法（目标：三 SOTA 模型均分 ≤55%）

**用途：**供出题 Agent 在确定执业角色与场景后，深度穿透真实案卷、设计符合官方规则的高区分度业务难点、完成一档法源原文核验与脚本实算，确保**真实付费可用、`golden` 预检 >90%、且三 SOTA 模型（Claude Opus 5 / GLM 5.3 / Kimi-K3 / Qwen 3.8 Max）均分稳压在 ≤55%**。本文件为作者内部方法，严禁将内部设计术语照搬进题面或标准成果。

---

## 一、读卷穿透：四项硬区分与双向试办

### 1. 读卷四项硬区分

分段通读全部冻结附件，逐份核清“谁制作、何时形成、证明什么、覆盖哪段期间、与其他文书如何印证或冲突”，严格区分：
- **提交者 vs 生成者**（谁交进卷里 ≠ 谁签署或背书）；
- **独立原始凭证 vs 同源转述**（银行回单／原始签收单／工商内档／庭审笔录原话 vs 汇总表／诉状单方陈述／微信转发截图的证明力层级）；
- **单方主张／草稿 vs 生效认定**（未签认结算草稿／退回旧稿／内部请示 vs 双方签章协议／生效裁判确认事实）；
- **程序控制状态 vs 实际受偿／生效状态**（查封冻结／轮候查封／受理通知／罚没告知 vs 实际扣划入账／已涤除优先权／生效决定）。

### 2. 从目标与原件两头试办

1. **从委托目标倒推要件**：委托方要达成的诉求或交易目标，在实体法与程序法上需要哪些前提同时成立？逐项回卷查证；卷内证据推翻当事人直觉印象时，锁定纠偏结论与替代方案。
2. **从边缘记录往前追后果**：某份不起眼的附件（如退汇回执、补充协议排他条款、电子送达签收记录、前案已执结裁定、历史章程修正案）使哪项期限起算、哪笔款项不得再催、哪份旧稿作废或带出哪项法定前置动作？将有实质后果的工作纳入本题交付链。
3. **按 62 项垂类场景库定点查漏**：查阅 [法律垂类场景与实务核查库](../assets/法律垂类场景与实务核查库.md) 对应领域条目与表末展开表。逐项检验：**少做这一步，接收人会不会因此多付／少收、超过法定期间失权、被法院／机关驳回，或必须自己推倒重算？** 会则纳入；无关的通用制度通则、脱离本案冲突的背景摘录一律舍弃。

## 二、按在卷真实文书展开的四类高价值工作

100% 立足在卷真实文书，严禁虚构卷外来函、严禁搞无人付费的纯 adversarial 文字游戏：

| 在卷真实文书结构 | 作者必须先穿透求解的核心判断 | 落地到 `deliverables` 的真实业务成果（另配必交检索轨迹） |
| --- | --- | --- |
| **1. 纠偏在卷遗留稿／待审模板**<br>（旧起诉状／申请书、对方合同模板、未签认结算表、初步方案） | 逐处比对底层回单、生效裁判、登记档案与现行强行法，定位管辖错误、主体错列、倒置付款节点、漏扣已付款或无效免责条款，测算纠偏对关联请求的连锁影响 | 可直接提交／签署的定稿正本或合同修订稿 ＋ 风险／纠偏清单（`.xlsx`/`.docx`）＋ 对委托人的诉求处理说明 |
| **2. 拆解并反驳对立主张**<br>（对方诉状／上诉状／再审申请、造价／审计鉴定意见、行政处罚告知书） | 还原对方证据链与计价／裁量逻辑，结合本方原始反证与证明责任规则，切分“应予认可、可凭铁证推翻、因缺原件不予认可及须申请调证”四类范围 | 答辩状／质证意见／代理词／陈述申辩书 ＋ 按证明对象分组的证据清单 ＋ 内部败诉／裁量风险评估报告 |
| **3. 共同约束下的多对象统筹**<br>（多笔混同流水、多处查封标的、多名担保／出资责任人、多项并存权利） | 逐笔去重并核扣前案已受偿／退费／垫付款，依法排定清偿抵充顺位（费用→利息→主债）或优先受偿顺位（建工→抵押→税款→普通债权），锁定各主体责任硬上限 | 结构化核算台账／分配测算表（`.xlsx`，含完整口径与分项数据）＋ 主张／异议主文书 ＋ 执行／追索操作预案 |
| **4. 复杂交易／合规体系审查与救济比选**<br>（多份并购／投融资协议、多制度底稿、跨阶段诉讼／执行衔接材料） | 穿透跨文件定义冲突、先决条件漏洞、监管申报门槛（如经营者集中／数据出境／减资前置）与多路径净损益差异，给出确定性结论与可执行落地步骤 | 法律尽调／合规审查报告 ＋ 按严重程度排序的风险整改清单（`.xlsx`）＋ 法定动作清单与替代路径损益比较 |

## 三、把三模型均分压到 ≤55% 的五项合规加压设计

SOTA 模型容易拿高分的根源是“主文直给结论＋委托人诉求全合理＋通用现行法条即够用＋分值散在体例套话”。出题时须结合本卷真实条件组合以下加压机制：

| 加压维度 | 针对模型的真实盲区 | 合规设计做法（严守官方规则，零恶意扣分） |
| --- | --- | --- |
| **1. 当事人口语干扰＋不合理／越界诉求埋点** | 模型倾向顺从用户指令、被当事人单方情绪化叙述带偏 | 按官方 3.1 要求：普通委托人用第一人称口语混入时间顺序颠倒、冗余抱怨及单方偏差认知，并在 `requests` 中自然放入 1–2 个**依法不成立、违反专属管辖／法定前置程序、超出责任上限或触碰合规底线的诉求**（如要求跳过目标公司减资径诉回购款、要求在申报中隐瞒处罚、要求把对方已退回款项忽略不计）。正确做法是依法纠偏并在《委托诉求处理说明》中讲明法律障碍与替代办法 |
| **2. 主文表面数字 vs 边缘凭证真相冲突** | 模型习惯只摘抄判决主文、合同总价或汇总表，漏读底层附件明细 | 让核心标的额、诉讼时效／上诉期／异议期起算日或担保范围取决于边缘凭证（如银行流水中一笔备注代付／同日冲正、补充协议对违约金上限的限缩、送达回证实际签收日与落款日差异、微信转发回单与银行入账实为同一笔交易） |
| **3. 跨时际修法与专门规范精准适用** | 模型常凭记忆混用修法前后条号、漏查专门司法解释或引用废止规定 | 当行为日与 `baseline_date` 跨越法律修订（如民法典／新旧公司法时间效力解释、新旧民事诉讼法条号顺延、建工／担保／执行异议专门解释、多段 LPR 改革衔接）时，题面只给客观基准日，绝不提示年份或文号；要求引用到准确条次并附条文原文，在检索轨迹专设“版本核验”对照 |
| **4. 多步依赖核算与阈值门槛判定** | 模型单步算术尚可，但跨表去重、抵充顺序切换、税费封顶或盈亏临界测算极易断链 | 将计算拆为“原始凭据去重筛选 → 法定／约定抵充顺位或计息基数切分 → 分段利率／折旧／比例核算 → 法定门槛或责任上限截断”的跨步依赖链；任何一步口径选错，最终主张金额与衍生文书请求即连锁偏离 |
| **5. 法定动作四要素与条件分支刚性落地** | 模型爱写“建议及时申请／尽快完善证据／咨询相关部门”等正确的废话 | 方案与行动类成果严格执行官方 Q6 标准：每项关键动作必须落实到**动作＋执行主体＋精确时限（写明起算事件与具体截止年月日）＋所需材料清单**；存在真实材料缺口或客观法律不确定性时，必须写清具体不确定原因、不同条件下的结果分支及明确建议倾向 |

## 四、作者完整求解核验四步闭环（写 Rubric 前必做）

1. **一档权威法源逐条核原文（零记忆背诵、零虚假案号）**
   - 凡主成果与 Rubric 拟援引的法律、行政法规、部门规章、司法解释、地方规范及生效案例，作者必须通过搜索／抓取工具核对**一档官方正文来源**（国家法律法规数据库、人大网、中国政府网、最高法及各部委官网、人民法院案例库、裁判文书网、北大法宝／威科正文页、域外官方库）。
   - 逐字核准：**规范全称、修订年份（置书名号外）、中文条次款项（“之一／之二”不省）、令号／法释文号、条文原文与施行状态**（严防 2023 年 7 月基准日错引 2023 年 9 月新修条号，严防引用已废止文件）。
   - **案例真伪铁律**：引用的每一个案号都必须经检索确有此案且裁判要旨相符，**严禁编造案号**；检索外部网络时只搜抽象法律争点与公开法规案号，不发送卷内未公开敏感原文。全部核验如实记入 `research_records` 并同步投影到 `法规案例检索轨迹.xlsx`。
2. **计算脚本精确复算闭环**
   - 用 Python 脚本把所有本金、已付款去重、抵充顺序、日历天数（含闰年与期间起算“次日”规则）、分段利率、滞纳金封顶、赔偿比例及临界值完整算一遍，做分项加总与反算一致性校验。
   - 明确四舍五入位置（逐笔舍入 vs 汇总舍入），确保所有 `reference_outputs`（含 `.xlsx` 工作表单元格与 `.docx` 正文）中的同一事项金额、日期、比例、主体名称 **100% 统一且可复算**。
3. **源件事实逐处回溯核查（零编造 `input` 外事实）**
   - 逐份检查 `reference_outputs`：正文中提到的每一份证据、每一次送达、每一笔款项、每一方观点，都必须能在 `input_files` 中指出具体文件与位置；**卷内没有的事实（如未附卷的双方书面意见、未发生的送达或外部报价）严禁编造**，确属实务必核缺口的，明示缺口并列入补充材料清单或标明“待核实”。
4. **“平庸 SOTA 答卷”对照压力检验（不落盘额外文件）**
   - **检验 A（防漏交办与防泄底）**：遮住内部思路，只读公开 `instruction`＋`deliverables`——委托方要办的事项、脱敏主体对应关系、基准日与硬约束是否交代完整？是否无意点破了待查矛盾、正确救济路径或修法线索？
   - **检验 B（接手直接可用）**：遮住内部说明，单看每份对外／经办 `reference_outputs`——收件人（法院、行政机关、交易对手、财务、业务负责人）拿到后能否直接使用，有无残留模板占位符、内部自相矛盾或缺“此致 XX 法院”／落款结构？
   - **检验 C（55% 难度预判）**：设想一个只读主判决／主合同、顺从委托人字面诉求、引用现行常见法条且排版工整的 SOTA 模型答卷——它在哪些 `+10` 和 `+7` 条目上必然失分？若它仍能拿到 55% 以上，立即回卷深挖尚未利用的底层凭证冲突、时际法源或跨步核算依赖（材料确无空间除外）。
