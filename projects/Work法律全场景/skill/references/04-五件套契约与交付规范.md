# 五件套契约与交付规范（`work_legal_v1` 对齐官方最新标准）

**用途：**确保作者输出的 JSON 题包 100% 通过 `work_legal_v1` 代码校验，无缝导出为 **Siriser 平台确认稿五件套**（`instruction.json`、`metadata.json`、`rubric.json`、`input_files/`、`golden_output/`）及 **Harbor 六件套**，并避开钉钉 11-17 通报的全部交付物退回红线。

> **载体与必交铁律**：
> 1. `deliverables` **仅允许 `.docx` 和 `.xlsx`**（严禁 `.pdf`、`.md`、`.tsv`、`.txt`）。
> 2. **`法规案例检索轨迹.xlsx` 为全部任务类型（F1–F5）的必交项**！由于平台确认稿生成器仅按 `deliverables` 清单输出 `golden_output/` 文件，每道题必须在 `deliverables` 中显式声明 **1 份（且最多 1 份）`法规案例检索轨迹.xlsx`**（`required: true`），**外加至少 3 份不同用途的实质业务文书／测算表**（合计 `deliverables` **≥ 4 份**）。

## 一、`work_legal_v1` 核心字段与五件套／Harbor 映射总览

按本次 `delivery.json` 提供的 schema 填写；**`question`、`reference_answer`、`answer_requirements` 及判据的 `criterion/rule` 均由程序同源派生，作者绝不另维护第二份**：

| 字段组 | 必填子字段与权威要求 | 下游投影去向 |
| --- | --- | --- |
| **任务识别** | `content_contract: "work_legal_v1"`；`task_name`（自然业务交办短句，禁标签拼串与剧透）；`task_type`（受控五选一：`F1 咨询研究`、`F2 审查审核`、`F3 文书起草`、`F4 方案设计`、`F5 数据核算`）；`header`（行业一二级填法律及细分业务，职业一二级填执业岗位如诉讼律师／企业法务／法官，不填原被告身份） | `metadata.json`、`rubric.json` 与双锚点映射 |
| **`task_metadata.instruction`** | `background`（案件／业务来龙去脉、各方关系、已发生事实，按真实委托人口吻行文并清晰交代脱敏主体对应关系）；`requests`（非空不重复诉求数组，鼓励含待纠偏的不专业／越界诉求）；`baseline_date`（`YYYY-MM-DD` 出具日／尽调或评估基准日，无适用时点才填 `null`）；`hard_constraints`（不重复的不可退让条件数组，独立单列供评分逐项核对；**数组元素不自带 `1. ` 等编号前缀，严禁把内部不脱敏指令如“保留原姓名、不改写原件”抄入题面**） | 合成公开 `question` 并投影为 `instruction.json` 及 Harbor `instruction.md` |
| **`task_metadata` 专业信息** | `occupation`、`scenario`（完整三级场景编号＋名称，与认领登记表逐字一致）、`role_perspective`（执业立场）、`domain_l2`（二级分类完整标签，如 `1.1 案件受理与策略`、`3.1 合同全生命周期管理`）、`capabilities`（从认领表该场景“重要能力”中结合本题选 **2–4 项**）、`professional_knowledge`、`vl_dependency`（源文件含扫描件／图片／图表截图时填 `true`）、`source_note`（**直接投影为对外 `metadata.json.dataSource`**，客观说明真实案卷／文件来源与卷宗形态，严禁写“本次提取原文／未另行读取扫描PDF／历史题包／事实来源仅为附件1”等内部流水线自白）、`generation_note`（内部审计说明、预处理边界与等级差距备注，留包外私有状态）、`tools`（OCR、表格计算、法规检索、判例检索、企查等）、`target_level`（`L2`–`L5`）、`level_basis`（`documents[]`、`necessary_steps[]`、`estimated_hours`［3 年经验从业者实际业务小时数］、`explanation`［**直接投影为对外 `metadata.json.taskDesc`**，只写客观业务工作量与复杂度，严禁写“不能据标签宣称已获LX认证／待专家确认”等内部自白］） | `metadata.json` 与 Harbor `task.toml` |
| **`input_files`** | `{ attachment_id, name, description }[]`：**`attachment_id` 与 `name` 按顺序原样复制自 `delivery.json.input_files`**；`description` 写清该份材料包含的具体文书、核心字段与口径说明 | `input_files/` 映射与 Harbor 源文件表 |
| **`deliverables`** | `{ id, path, format, description, required }[]`：**≥3 份实质业务成果 ＋ 1 份 `法规案例检索轨迹.xlsx`（共 ≥4 份）**；`path` 为安全相对文件名、UTF-8 ≤200 字节、大小写敏感、**禁止含动态日期／时间戳／版本号或通配符**；后缀与 `format` 仅限 `docx`/`xlsx` 且一致 | `instruction.json`、`golden_output/`、Harbor `artifacts`（`/app/output/<path>`）六处逐字节对齐 |
| **`reference_outputs`** | `{ deliverable_id, content, sheets }[]`：与 `deliverables` **一一对应且全部非空**；`content` 为可直接对外提交或内部交接的完整业务正稿；**凡 `format = "xlsx"` 必须提供非空 `sheets[]`**（`name` ≤31 字符不重复、`columns` 非空不重复、`rows` 每行长度等于列数且元素仅为 `string \| number \| boolean` 有限值） | 渲染为 `golden_output/` 下的真实法律样式 `.docx` 与 `.xlsx`（含结构化工作表＋“正文说明”表） |
| **`research_records`** | `{ id, query, source_url, source_title, version, findings, verification_status, supports }[]`：逐条如实记录本次一档权威来源实际检索与核验结果，覆盖主成果与 Rubric 的每一条援引 | 保存于包外私有状态，并与 `法规案例检索轨迹.xlsx` 的 `sheets` 内容完全同源 |
| **`task_requirements`** | `{ input_mode: "text"\|"image", output_mode: "text"\|"file", tools: string[] }`：如实声明真实业务所需能力（不因当前本地文字作答器删减必要法律工作） | 记录任务能力边界 |
| **`content_status`** | `{ status: "complete"\|"draft", issues: string[] }`：现有材料足以完成本次委托（含依法明示真实缺口与补证清单）即填 `"complete"` 且 `issues: []` | 五件套归档准入硬门槛 |
| **`rubric`** | 至少 **30 项** `{ id, metadata }` 六档加减分判据（无 `Veto`、`trigger_count: null`），详见 [Work 评分方案与加压验题](03-Work评分方案与加压验题.md) | `rubric.json`、`评分要点.xlsx` 与 Harbor `rubrics.toml` |

## 二、F1–F5 标准交付物组合与结构化要素规范

### 1. 五类任务类型参考组合（每类均必含 `法规案例检索轨迹.xlsx` 且业务文书 ≥3 份）

以主交付物形态确定 `task_type`（同一三级场景下不同题目可按实际主交付物落在不同 F 类，不为降重硬改分类）：

| 任务类型 | 必选双锚点 | 官方参考交付物组合（全部落地为独立 `.docx` / `.xlsx`，共 ≥4 份） |
| --- | --- | --- |
| **`F1 咨询研究`** | Q3 + Q4 | ① 法律研究报告／综合法律意见书（`.docx`）；② 专题法源与类案对比分析报告（`.docx`）；③ 实务处置建议或合规核查清单（`.docx`/`.xlsx`）；④ **`法规案例检索轨迹.xlsx`** |
| **`F2 审查审核`** | Q2 + Q3 | ① 审查意见书或法律尽职调查报告（`.docx`）；② 风险清单（`.xlsx`，按风险等级由高到低排序）；③ 合同修订稿／条款替换正本或 300–500 字核心审查意见函（`.docx`，覆盖全部高风险项）；④ **`法规案例检索轨迹.xlsx`** |
| **`F3 文书起草`** | Q1 + Q4 | ① 可直接提交法院／仲裁／机关或对外出具的文书正稿（`.docx`）；② 证据清单或附随材料清单（`.docx`/`.xlsx`，按证明对象或请求权分组）；③ 委托诉求处理说明（`.docx`，对内回应客户诉求与不合理诉求纠偏）；④ **`法规案例检索轨迹.xlsx`** |
| **`F4 方案设计`** | Q4 + Q6 | ① 整体处置方案或应对预案正文（`.docx`）；② 法定动作清单（`.xlsx`，含动作／主体／时限／所需材料四要素）；③ 支撑依据分析（`.docx`，含替代救济路径与成本／风险比较）；④ **`法规案例检索轨迹.xlsx`** |
| **`F5 数据核算`** | Q1 + Q5 | ① 结构化核算台账或测算表（`.xlsx`，含全部原始与核定字段）；② 测算口径说明（`.docx`，含基数口径、计算公式、数据来源、假设条件）；③ 分析结论与预警／主张文书（`.docx`）；④ **`法规案例检索轨迹.xlsx`** |

### 2. 核心清单与 `.xlsx` 工作表（`sheets`）落地规范

- **风险清单必含五要素**：`风险等级`（高／中／低，按由高至低排序）、`风险描述`、`判定依据`（合同条款／事实＋法规条号）、`修改或整改方案`（给出可直接替换的条款文本或具体动作）、`是否必须修改`。
- **证据／附随材料清单必含五要素**：`序号／编号`、`证据名称`、`证据形式`（原件／复印件／电子数据等及在卷状态）、`证明内容`、`证明目的`（按证明对象或请求权路径分组）。
- **法定动作清单必含四要素**：`具体动作`、`执行主体`、`法定时限`（写明起算依据与精确截止日）、`所需材料`。
- **测算类 `.xlsx` 填写规范**：`sheets` 中按业务拆分为清晰的明细表与汇总表，所有派生金额与比例均用脚本算准后填入有限数值（`number`）或清晰口径文本（`string`），**不在单元格填入未求值的 `=SUM(...)` 文本充当数值**；在对应 `content` 中完整写明基数口径、计算公式、数据来源凭证、假设条件与四舍五入规则（生成器会自动把 `content` 写入该工作簿的“正文说明”工作表，确保公式与结果 100% 可复算）。
- **`法规案例检索轨迹.xlsx` 的 `sheets` 六列规范**（对齐官方三要素、版本核验与 Siriser 导入列）：
  - `name`：`"检索轨迹"`；
  - `columns`：`["序号", "检索词", "检索数据库/平台", "命中要点", "正文来源URL", "来源档位与版本核验"]`（亦可将来源档位与版本核验分列，参考 [检索轨迹填写示例](../assets/检索轨迹填写示例.tsv)）；
  - **覆盖率铁律**：必须覆盖全部业务交付物与全部 Rubric 中的**每一条法规与案例援引**（无对应轨迹视为未核验）；源文件引旧版而基准日适用新版（或依时间效力解释适用行为时旧版）的，必须在版本核验栏写明**新旧条号与施行日对照关系**。

## 三、法源引用硬格式与来源三档分级（官方 3.3.3–3.3.4）

### 1. 六类法源标准引用格式

| 类型 | 强制格式要求 | 标准写法示例 |
| --- | --- | --- |
| **法律、行政法规** | 全称 ＋ 中文数字条次（款、项，“之一／之二”照写不省） | `《中华人民共和国民法典》第五百八十四条` |
| **部门规章／行政规范** | 全称 ＋ 发布机关令号 | `《网络数据安全管理条例》（国务院令第790号）` |
| **司法解释** | 全称 ＋ 法释文号 | `《最高人民法院关于适用〈中华人民共和国民法典〉合同编通则若干问题的解释》（法释〔2023〕13号）` |
| **修订版本** | **修订年份写在书名号外** | `《中华人民共和国公司法》（2023修订）第八十八条` |
| **生效案例** | 案号 ＋ 裁判要点 ＋ 官方来源（案号必须上网核验真实存在且案情相符） | `（2023）最高法民再××号，裁判要点为……，来源：人民法院案例库` |
| **域外法** | 原文名称 ＋ 编号 ＋ 条次，首次出现附中文译名 | 按域外官方数据库标准名称与条次引用 |

> **铁律**：正文中援引法条**必须写出条文原文或准确规定摘要**（可在正文引述或文内注释／备注写明），**严禁只列条号**，**严禁默写篡改法条原文**！

### 2. 法规案例来源三档边界

- **一档（正文来源，必须使用）**：中国政府网、中国人大网、国务院各部委官网、国家法律法规数据库、最高人民法院公报、中国裁判文书网、人民法院案例库、北大法宝／威科先行法条与判例正文页、域外官方立法与判例数据库。
- **二档（仅可辅助理解，不得单独作援引依据）**：行业协会解读、监管问答汇编、权威出版物。
- **三档（严禁使用，出现即在维度 5 扣分）**：微信公众号文章、律所推文、百科词条、问答社区、聚合类资讯。

## 四、标准交付物质量红线与代码级受众纯净拦截

### 1. 11-17 官方通报 `golden_output` 九大退回红线（成稿逐项清零）

1. **零编造 `input` 外事实**：卷内没有双方书面意见、送达回证或询价记录时，严禁编出“双方书面意见称……”或虚构送达日期；每一项事实均须能定位到 `input_files`，无依据处删去或写明“待核实”。
2. **零案号代字与法律概念错用**：严格区分“民撤／民初／执异”、“行政罚款／罚金”、“复议期届满／认定生效”；**严禁把基准日之后新修法律的条文编号倒用于旧时点文书**，严禁引用已废止文件。
3. **零内部自相矛盾**：同一文书前后（如上诉权利告知与审级）、不同文书之间的金额、日期、比例、主体称谓与请求结论 100% 一致，禁止以“建议咨询专业人士”收尾回避结论。
4. **字数与体例足额合规**：题面或文种有字数要求的必须足额达标（不拿标题、释义表、签署空行凑字数）；起诉状／答辩状／申请书／意见书具备完整法定首部、“此致 XX 人民法院／机构”、落款署名与日期等实务惯用结构。
5. **零模板占位符与内部流水线视角残留**：清空一切 `【请填写】`、`XX公司（待补）`、重复粘贴段落等模板痕迹；内外用途分件清晰（对内风险底牌与诉求纠偏放《委托诉求处理说明.docx》或内部报告，不塞进对外提交正本）；一律按真人律师审阅在卷扫描件／原件的视角行文（写“在卷扫描件／复印件”“卷宗第 X 页”），对模糊或字迹不清处写“扫描件字迹模糊，须调阅原件核对”；`法规案例检索轨迹.xlsx` 仅收录真实核验并支撑结论的有效法源与案例记录，超时／无法打开的无效线索不写入对外表格。

### 2. 代码级与人工质检受众纯净拦截

`reference_outputs`（全部 `content` 及 `sheets` 表名、列名、单元格）及对外元数据（`instruction`、`source_note`、`level_basis.explanation`）**严禁**出现以下四类字样：
- **AI 或真人身份制作说明**（移入 `generation_note`）：`AI作者`、`AI生成/编制/撰写`、`模型生成`、`作者为AI`、`非真人专家`、`真人专家确认/审核/认证`、`不能据标签宣称已获LX认证`；
- **内部工具与工程字段**（移入 `generation_note` 或 `research_records`）：`AnySearch`、`ChatGPT`、`Codex`、`research_records`、`reference_outputs`、`Harbor`、`JSON内容稿`、`历史题包`、`历史评分`、`本次会话`；
- **内部预处理与流水线视角词**（移入 `generation_note`）：`提取文本`、`提取原文`、`页标`、`仅复算提取数`、`未另行读取扫描PDF`、`当前所获文本不足以验证`、`保留原姓名`、`不脱敏`、`不改写原件`、`经授权使用本次`；
- **出题与评分视角词**（移入 `rubric`）：`不要求候选`、`候选人无需/不必`、`作者网址`、`作者检索记录/轨迹`、`唯一答案键`、`参考答案`、`标准答案`、`Rubric`、`评分项/细则`。
