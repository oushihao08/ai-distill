# Work 评分方案与加压验题（对齐钉钉最新规范＋双线达标）

**用途：**指导出题作者从定稿的 `reference_outputs`（`golden_output`）中拆解编写符合钉钉最新《Rubrics设计要求》（11-17 修订）、《题包交付规范》（10-28 修订）及本地 `work_legal_v1` 契约的评分细则，确保 **`golden` 正向预检 >90%（目标 100%）且三 SOTA 模型均分 ≤55%**。

> **规范衔接与冲突裁决（必读）**：
> 1. 依《题包交付规范》第 6.7 节冲突裁决条款及最新规范演进，新题统一采用 **≥30 项、六档加减分（`+10/+7/+3/-3/-7/-10`）、一级维度 `1`–`7`、二级维度 `Q1`–`Q7`、F1–F5 双锚点 ≥30%** 体系。
> 2. **严禁设置 `0-一票否决（R0-V01 / Veto）`，严禁在 `trigger_count` 填写“可累计／无封顶”文本（`trigger_count` 固定填 `null`）**——官方最新规范已取消独立否决，且 Harbor 导出器直接拒绝 `Veto` 与模糊累计规则；确需按违规处数或措施命中数分档时，统一使用 `type: "likert"` + `points: 5` 并逐档写清 `5/4/3/2/1` 客观锚点。
> 3. **严禁绑定底层 OOXML 公式标签**：不在 `statement` 中写“工作簿须由活公式驱动、手填静态常数不成立”或容器命令，一律考核可跨载体核验的事实依据、法源原文、要件涵摄、基数口径与精确计算结果。

## 一、官方五项核心准则与命中弹性

Rubric 评判的是**“模型交出来的文书，资深法律从业者敢不敢直接拿去用”**。裁判模型评分时默认只看被测交付物与 Rubric（Harbor 校准模式下标答仅作结构与量级参考，绝非答案键），因此每条判据必须遵守：

| 准则 | 硬性要求 | 严禁出现的反例 |
| --- | --- | --- |
| **1. 来源于 `golden_output`** | 正向条目是对本题 `reference_outputs` 的逐项拆解；**凡 `reference_outputs` 没写的内容严禁写入正向 Rubric**，凡 `reference_outputs` 的核心内容必须被覆盖。改标答必须同步改 Rubric | Rubric 要求“区分三法域侵权规则”，但标答正文根本没写（导致 `golden` 预检 <0.90 整题退回） |
| **2. 原子性** | 一条只判一件事。多个可独立对错的要点必须拆条，不得用“且／或”捆绑互不相关的判断（仅“要素齐备才有意义”的单一事实簇、同次计算口径与结果、单个法定动作四要素合并为一条） | “正确认定合同效力、正确计算违约金并提出解除建议”绑成一条 |
| **3. 客观性与可观察化** | 不同裁判读同一条得出同一结论；避免“论证充分／分析深入／格式规范”等空话，转化为可核查的具体要素（`Subjective` 条目不得超过总条数的 **10%**） | 写“应准确援引相关法律充分说理”，未写具体条号、原文与三层论证点 |
| **4. 完全自包含** | `statement` 必须内嵌判定所需的**全部正确值与情形清单**：法规全称＋准确条次＋**条文原文或规定摘要**、案例案号＋裁判要旨、精确数值与日期、比较基数与计算口径、容差范围，以及**“须全部满足”还是“命中其一即可”**；严禁写“等”“详见参考答案”“参照上条”“共 X 项” | 只写“援引《民法典》第 172 条分析表见代理”，漏写第 172 条法条原文与本案对应事实 |
| **5. 鲁棒性与命中弹性** | 不受措辞、章节顺序、同义表达影响；只有结论没有事实／规范依据支撑的不得分；同一目标有多条合法路径／等效法条／有效整改方案时，列全可接受范围并写明“命中其一或等效专业表述即得分” | 模型写“构成《民法典》第 172 条规定的情形”因未出现“表见代理”四字而扣分，或把作者搜到的单一参考案号设为隐藏唯一答案键 |

## 二、`work_legal_v1` Rubric 字段契约与受控词表

每条 Rubric 为 `{ id, metadata }`，`metadata` 的 12 个字段必须严格匹配代码 Schema（`criterion/rule` 由程序派生，不在 `statement` 内重复写“计 +7 分，否则 0 分”）：

| 字段 | 规范与填写要求 |
| --- | --- |
| `id` | 正向 `R{维度数字}-P{两位序号}`（如 `R2-P01`）；负向 `R{维度数字}-N{两位序号}`（如 `R5-N01`）；二级维度 Q 不进 `id` |
| `statement` | 完全自包含判定标准（长清单逐项编号换行）：写清原始文书名、法规全称＋条号＋条文原文、精确数值／日期／口径与容差、落点文件、全部／任一条件及等效接受范围；`likert` 项必含 `5/4/3/2/1` 五档具体锚点 |
| `criterion_type` | `Objective` 或 `Subjective`（**`Subjective` ≤ 总条数 10%**） |
| `criterion_necessity` | `Explicit`（题面明文要求）或 `Implicit`（由执业常识或语境必然推导；法律题多数实质判断为 `Implicit`） |
| `dimension` | 必须从下方 **13 项可用规范维度枚举**中逐字复制（禁止用历史 `0-一票否决`，维度 2 只填一个主 Q） |
| `evaluated_files` | 非空字符串数组，**逐字节匹配 `deliverables[].path`**（即 `golden_output` 文件名）；跨全部交付物或整包底线项写单独 `["all"]`（禁与其他文件名混写） |
| `knowledge_points` | `法律域::具体知识点` 字符串数组（如 `公司法::未届期股权转让出资补充责任（公司法第88条）`）；纯事实／格式／流程项填 `[]` |
| `atomic_capabilities` | 0–3 个字符串数组，必须从下方 **36 项受控原子能力枚举**中逐字复制（**严禁加 `S2 `、`L1 `、`D5 ` 等字母编号前缀**！首项为主导能力，其余兼考；纯格式／齐备项填 `[]`） |
| `priority` | 六档之一：`Critically Important`、`Important`、`Slightly Important`、`Slightly Detrimental`、`Detrimental`、`Critically Detrimental` |
| `score` | 与 `priority` 严格一一绑定：`10`、`7`、`3`、`-3`、`-7`、`-10` |
| `type` | `binary`（默认）或 `likert`（存在有意义的程度差异时使用；负向优先用 `binary`） |
| `points` | `type = "likert"` 时必填 `5`；`type = "binary"` 时必填 `null` |
| `trigger_count` | **统一填 `null`**（Harbor 无损映射要求；按处数分档的负向改用 `likert` 五档锚点写入 `statement`） |

## 三、维度细化规则、双锚点与六档权重配置

### 1. 各维度编写硬标准（严格对齐 11-17 & 10-28 规范）

- **必设与选设**：必设维度 **`1`、`2`、`5`**；从维度 **`3`、`4`、`6`** 中**至少再选 2 个**；维度 **`7`** 按需选设反偷懒负向项。另外注意：Harbor 约束 `prompt.md + 全部 criterion description < 100 KB`，单条 `statement` 应精炼自包含、不堆无用冗余，确保全套 ≥30 条总字节安全可控。
- **维度 1（指令遵循与任务理解）**：仅按“交付物齐备性、硬约束遵守、角色与立场、基准时间点采用”四类设条，**每类不超过 1 条**。
  - 交付物齐备性为**严格二元判定**：要求的必交业务文书与 `法规案例检索轨迹.xlsx` 全部齐备且均有实质正文方得分，缺一件或空标题即 0 分（不给部分分）；
  - 硬约束条须把 `instruction.hard_constraints` 单列的每项具体要求写进 `statement` 逐项核对；
  - 角色与立场：可设正向 `+3`（列明具体禁区，全程恪守指定委托方／中立／客观公正立场未倒置即得分）或针对严重立场倒置设负向，**绝不同时设一正一负两条**。
- **维度 2（交付物内容质量 Q1–Q7）**：至少选 **Q1–Q6 中的 3 个**，必含本题任务类型的 **2 个必选领域锚点**，且**两个锚点维度的正向分值之和 ≥ 全题正向满分的 30%**：
  - `F1 咨询研究` → **Q3 + Q4**｜`F2 审查审核` → **Q2 + Q3**｜`F3 文书起草` → **Q1 + Q4**｜`F4 方案设计` → **Q4 + Q6**｜`F5 数据核算` → **Q1 + Q5**
  - **Q1 事实与证据**：按核心事实簇、底层冲突材料采信顺序、证据三性判断、真实材料缺口明示设条（单一事实只归 Q1，不在其他维度重计）；
  - **Q2 风险与问题**：每项预设实质风险单设一条，按不处置后果定档（实质交易／程序障碍 `+10`，引发问询或程序不利需整改 `+7`，补材料即可解决 `+3`），须有判定依据；
  - **Q3 法源与援引**：每条支撑结论必需的核心法规／类案单设一条（不搞法规汇编凑数），必写**法规全称＋准确条次＋条文原文／要旨＋与本案具体问题的对应关系**；
  - **Q4 法律适用与定性**：每项核心定性结论、抗辩成立与否或对委托人不合理诉求的依法纠偏单设一条，写清要件对应关系；
  - **Q5 量化计算与门槛**：每项核心核算结果或法定门槛（时效、除斥期、申报线、罚款／违约金上限）单设一条，必写**基数口径、计算方式、正确值与合理容差**（如金额误差不超过 1 元）；
  - **Q6 结论与可执行性**：法定动作条必须按**“①具体动作＋②执行主体＋③精确时限（含起算日与截止日）＋④所需材料”**四要素二元判定，缺任一要素或时限算错不得分；多措施整改可用 `likert` 5/4/3/2/1 按命中实质措施数分档；
  - **Q7 内部逻辑一致性**：**仅设负向**，逐项列举本题跨章节或跨交付物可能出现的具体矛盾（如主诉状请求金额与计算表不一致、前文认解除后文仍按继续履行计费）。
- **维度 3（体例规范）**：考核法定／行业必备结构要素（诉状首部／请求／事实理由／此致法院／具状人，风险清单必备列头，检索轨迹必备列头）；**通用排版要求最多合并为 1 条 `+3`**，严禁拆多条刷分。
- **维度 4（推理与规划）**：考核前置程序顺序（如先核主体管辖再论实体）、具体两处材料的交叉核验结论（写明哪两份文件、差额多少、以何为准）及跨时际版本核验路径（不与 Q5 同一算术结果重复计分）。
- **维度 5（安全合规）**：重点对**编造法源／虚假案号、编造 `input` 外事实证据、引用三档非权威来源（公众号／百科／律所推文等）、顺从委托人给出具体违法舞弊／规避监管建议**设置客观可判的负向扣分（`-7` 或 `-10`）；若设正向合规底线守门项则统一取 `+3` 并逐行列明本题具体违规禁区，**同一违规行为严禁正负双设**。
- **维度 6（协作体验）**：考核是否给出可直接粘贴替换的合同条款修订文本、结构化清单，以及**是否把需委托人商业拍板／补充确认的事项明确标注而非擅自替委托人假设决定**。
- **维度 7（反偷懒与反模板）**：选设时须为具体可量化的负向项（如以“建议咨询专业人士／需进一步核实”回避现卷已可作出的结论、只列空标题无本案分析、未读底层底稿照抄模板）。

### 2. 六档权重与“压均分 ≤55%”结构配比

| `priority` | `score` | 设值标准与难度配比纪律 |
| --- | ---: | --- |
| `Critically Important` | `+10` | **缺失即整题结论方向错误、必须重做**（核心定性、决定胜败的边缘凭证消歧、关键请求权／管辖／时效门槛、对重大越界诉求的识别纠偏；**每题至少 2 条**） |
| `Important` | `+7` | **缺失需明显补充核查或实质返工**（关键事实簇、核心法源原文及时间效力适用、多步联动核算净额、四要素完整法定动作） |
| `Slightly Important` | `+3` | **复核人顺手可补的细节完善**（轻微风险、辅助法源、文书体例要素、通用排版合并项、可编辑性提示；**严禁堆砌 `+3` 稀释专业难度**） |
| `Slightly Detrimental` | `-3` | 易发现、修改成本低的小瑕疵或局部偏题 |
| `Detrimental` | `-7` | 需回查案卷或法源的重要错误（如错引已废止／未生效法条、引用三档自媒体来源、跨交付物关键金额矛盾、以“咨询专业人士”回避核心结论） |
| `Critically Detrimental` | `-10` | **毁掉交付物可信度的致命错误**（编造 `input` 外事实／虚假案号、给出违法舞弊建议、严重立场倒置；**不得滥用恶意扣分**） |

> **压住 ≤55% 的黄金配比**：让需穿透边缘凭证、跨时际核法源、纠偏不当诉求、精确多步复算及四要素落地的 **`+10` 与 `+7` 核心项占全题正向满分的 75% 以上**；纯格式、交付齐备与浅层摘录合计不超过正向满分的 15%–20%。

## 四、11-17 官方通报八大 Rubric 退回雷区自查（零容忍）

定稿前逐条对照排查，命中任一条立即修正：
1. **正话反说双重扣分**：负向条目是正向条目的反面重述（如正项奖“扣减 3 万已付款”，负项又扣“未扣减 3 万已付款”），导致同一缺失既丢正分又扣负分——**立即删去重复负项，负项只能针对独立有害错误行为**。
2. **同一考点拆多条刷分**：同一条法规（如《民法典》第 157 条）、同一组数值或同一检索截止日拆成多条重复计分——**合并至唯一主维度**。
3. **要求 `input` 里没有的事实**：要求模型写出案卷和题面均查不到的持股比例、交易细节或外部数据——**立即删除或改为考核明示证据缺口**。
4. **要求 `golden` 没做到的内容**：Rubric 写的要点在 `reference_outputs` 中找不到或口径不一致——**补齐 `reference_outputs` 或修正 Rubric，确保 `golden` 100% 命中全部正项、0 命中负项**。
5. **把错误法律观点固化进判据**：如违背专属管辖、违背自首或保证期间司法解释——**回查一档权威原文修正**。
6. **残留否决项或冲突阈值**：出现 `Veto` / `0-一票否决`，或同时写两套冲突的编造扣分门槛——**全部清理为清晰的六档条目**。
7. **分值倒挂或控分嫌疑**：表面直接可读的简单数字给高分，决定全案基点的核心判断反而给低分，或同类难度条目分值悬殊——**严格按返工代价重新定档（`+10/+7/+3`）**。
8. **Likert 缺五档锚点**：`type = "likert"` 未写 `points: 5`，或未在 `statement` 逐档写明 `5=...；4=...；3=...；2=...；1=...` 可独立核验情形——**补齐五档客观锚点**（正向 5=完全满足→1=完全不满足；负向按违规程度 5=最重违规→1=完全无违规）。

## 五、冻结前双线对抗试判（内部必做）

在会话内代入两类极端答卷验算净得分率 `clip((Σ正 − Σ负) / Σ正满分, 0, 1)`：
- **基准线 1（`golden_output` 与简洁等价合法解）**：逐条核对本题 `reference_outputs`——必须 **100% 命中全部正向项、0 触发负向项（得分率 = 1.00，稳超官方 `> 0.90` 预检线）**；采用同等合法替代法条或不同章节顺序的合格解同样可得 >0.90。
