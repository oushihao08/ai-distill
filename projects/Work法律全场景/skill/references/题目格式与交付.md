# 题目格式与交付

保留原 skill 的专业任务组织方法；Work 项目规则详见[出题规范](出题规范.md)与[交付规范](交付规范.md)，不沿用旧项目的纯文本限制。

## 题面

用成果使用者布置高强度专业工作的口吻写题。写清主要作答者、背景、对象、条件和成果要求，充分展开工作：

- 分别回应待评主张、方案及反驳理由，定位决定性材料，说明依据之间如何支持、限制或冲突，并给出具体处理结论。
- 全面处理案件、主体、款项、期间和条款，表达合并、区分、排除及适用情况。
- 涉及数值或期间时，给出分项计算、基数、公式、结果或条件表达式，并核对汇总关系。
- 角色须在多个处理路径间选择时，比较方案及其成立条件；后续事件改变判断时，重新形成相关成果。
- 写出本角色有权制作或提出的条款、请求、裁判、鉴定意见、通知或交接正文，保持主体、范围、条件和后果一致。

题目可以要求多项独立工作和多个成果，不限于单一决定或单一路径。题面可以限定核对领域、指定成果及要求说明依据；不要预先宣布材料存在某类错误、指定错误数量、采信方向或解决顺序。一个工作要求对应考点本身是正常设计，只有它透露待求结论或裁决线索时才构成提示。保留自行发现证据问题、选择规则和裁决争议的工作，不将详细任务缩减为泛泛意见。

| 工作布置 | 泄露判断线索 |
| --- | --- |
| 核对现有付款记录，确定已清偿范围，并在余额表及付款条款中落实 | 回单存在重复，必须去重；对账单余额错误，请以银行流水为准 |

区分原材料明确事实、必要业务条件和要求求出的结果。前两类完整保留；交易对应、授权效力、规则选择、推算日期及余额由作答者判断。原件已确定的日期和有效约定不删改；必要计算端点、精度和日历条件不得隐藏。不能新增模拟记录补事实，缺少关键材料先列明缺口。

题面按实际工作写明成果的使用人、接收人、专属约束、后续决策或执行动作，以及做错会影响什么；具体内容依本题材料和委托事项确定，不固定为签批或交易场景。各份成果承担不同用途，按本题确认的正式文件形态交付。要求给出可直接使用的口径、条件和文本，不以“另行制作”“待核后决定”代替已可完成的部分。模板或核查表仅在本题确有复用需要时交付，并写清适用边界；有数据时核算经济结果，不为证明价值补造金额。不要逐一提示附件中的矛盾、错误数字和正确法律口径。

区分主要作答者的 Work 职业岗位、服务对象及材料人物的诉讼身份。按已认领的六类主体和三级场景填写分类，不以原告、被告、证人等代替职业。律师维护委托方，法官中立，检察官客观公正；其他主体按其权限交付。角色必须实际影响判断和办理边界。

安排逐对象的处理结论与理由，让作答者自行区分成立、附条件成立、应排除或受阻的范围；涉及办理动作时进一步落实可执行边界，不预告哪些对象属于哪类。变化情景说明发生的事实和时点，要求修订受影响的成果及其依据、交代未受影响部分，不直接宣布原方案失效。完整修订稿或明确替换范围及正文均可；历史值可用于初稿及对比，核对的是当前有效文本之间的一致性。

保留估值时点、有效计算约定、有真实来源的业务政策和条件。事件时间、信息取得范围、计算端点及舍入按任务需要交代，不固定为每题栏位。内部测算确实采用不同口径时明示用途，分别处理对外权利；不能以内部约定当然替代法定口径。法律存在合理争议时列可成立分支，作者尚未核实不等于法律有分支。题面不附作者检索所得的法律讲解、搜索链接或答案依据清单。

## 题目包内容

沿用任务信息、任务名称、类型、题面、Rubric、作答思路和完整标准答案的组织关系，具体内容改为 Work 要求：

| 内容 | Work 要求 |
| --- | --- |
| 题目信息 metadata | 当前认领场景、F1–F5、L2–L5、2–4 项评测能力、视觉依赖及文件、专家业务人时、真实来源、必要工具和知识；不照搬旧项目职业／行业枚举 |
| 任务名称 | 与实际业务、委托和交付物一致 |
| 题面 instruction | 背景事实、诉求、交付物、基准日、编号硬约束；一般当事人第一人称自然表达，专业委托人按职业行文 |
| 原始 Rubric | 使用出题规范第 8 节完整字段及正负分、否决规则；不固定条数 |
| 作答思路 | 内部说明材料取舍、适用过程、计算口径、合法分支及可执行边界，不泄露给被测模型 |
| 标准交付物 | 按 F1–F5 和本题需要，形成可直接使用的实际文书、表格或方案；专家亲自撰写并核定 |
| 检索轨迹 | 专家真实办理过程的检索词、命中原文／要旨、正文 URL 和必要版本核验；不由模型伪造 |

成稿时对照标准交付物核查必要成果已由题面布置或由职业语境必然要求。明确成果使用人和内容，不把完整解题步骤逐项改写进题面。F1–F5 参考组合不是统一必交清单；专家检索轨迹必交，候选是否也要交必须在题面明示。

## Work 文件交付

- 专家初稿：任务说明.docx、题目信息表.docx、评分要点.xlsx、input_files/、golden_output/。
- 确认稿：instruction.json、metadata.json、rubric.json、input_files/、golden_output/。
- 最终 Harbor 包：instruction.md、task.toml、rubrics.json、environment/、solution/、tests/，各目录内部必交文件按交付规范完整制作。
- 输入只读 `/app/input_files/`，候选成果写入 `/app/output/`；任务书、deliverables、artifacts、两份 golden 和 criterion 六处必交文件名严格一致。
- 原始 Rubric 与 Harbor TOML 不能互换：负向用正 weight 加 negate，Veto 独立；累计负分转换差异和未决接口如实保留。
- 固定评分脚本取当前完整官方模板，不能用本地截断转录重写。未取得模板或未实际运行的检查不能标为完成。

题目包模板见[题目模版](../assets/题目模版.md)。当前调用方指定的输出格式不证明它能承载全部 Work 要求；格式冲突应报告，不用删负项、抹掉文件要求或伪造字段解决。

## 表达与引用

行业、职业、角色和任务背景相互一致；按当前 Work 登记分类填写，不把诉讼身份当职业，不因题目涉及法律就一律归法律服务。公司法务任务仍以公司实际主营业务为背景，不引用旧项目专属准则作为 Work 的新要求。

附件使用作答者可见名称或序号引用，序号对应实际正文。引用案号、日期、主体和金额时核对材料原文，脱敏保持原样。

题面不列出正确采信方向、陷阱位置、rubric 或解题步骤。标准答案用正式业务文书表达，完整呈现具体成果，不用“另拟申请”“制作明细”或文件名替代正文。

各项内容不出现数据库编号、本机路径、程序字段、模型成绩、AI 自述或出题流程。作者核验、考点必要依据和标答保留法律出处及争议说明；原附件的法条、条款和来源信息不因删除检索讲解而删改。题面保留完整事实边界、有来源的业务条件和适用时点，不自动附作者的来源清单。
