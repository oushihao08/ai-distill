# Work 题目包结构

沿用原 skill 的题目包组织关系，字段和交付改为 Work 规则。花括号是编写时的提示，不进入提交终稿；模型辅助稿如实标注待专家核定，不冒充正式专家答案或真实人工检索轨迹。正式文件结构按[交付规范](../references/交付规范.md)。

## 题目信息

内容包题号：{法律-当前认领三级场景编号-提交日期-实际专家姓名}
Harbor 题号：{正式分配的 LAW-序号；与内容题号建立对应}
一级主体：{六类主体中本题已认领类别}
二级／三级场景：{当前登记表原标签及编号}
任务类型：{F1–F5，按主交付物确定}
长程等级：{L2–L5；真实材料、人时和最短必要步骤支持}
评测能力：{本题真实考察的 2–4 项能力}
视觉依赖：{是／否；如是列实际文件；PDF 分类未确认则记录具体差异}
专家业务耗时：{成熟专家完成业务工作的小时数，不是出题耗时}
数据来源及真实性：{来源事实、匿名化边界、未重复提交和存量方向核对情况}
必要工具／专业知识：{完成本题实际需要的能力，不按作者调用次数虚填}

## 任务名称

{实际专业工作名称，与背景、场景和交付物一致。}

## 题面 instruction

{按真实委托表达背景事实、诉求和办理目标。一般当事人使用自然的第一人称，专业委托人按其行文习惯。明确服务对象、作答岗位及权限，不能以诉讼身份替代职业。}

{明确基准日、可见输入、实际交付物和编号硬约束。保留原材料必要事实、有效约定、计算口径，不泄露争点裁决、陷阱、Rubric 或答案。}

{Harbor 任务逐项列 input 文件及口径、/app/output/ 下必交固定文件名、格式与用途；必交无通配和动态名，六处名称一致。此模板不预设每题成果数量或强制使用 F 类型参考组合。}

## 考点 rubric

{根据专家终稿拆出正向项，根据本题具体错误设负向项；字段、维度、锚点、权重、计数和否决按[出题规范第 8 节](../references/出题规范.md)。不固定条数，不沿用等权分。}

每项逐一填全：

- id：{R维度号-P序号／N序号；独立否决 R0-V01，题内唯一}
- statement：{具体正确结果或错误行为，决定性事实、规则、计算口径、容差、全／任一条件、等效合法方案和计数方式；不依赖标答补标准}
- criterion_type：{Objective／Subjective；Subjective 条数 ≤10%}
- criterion_necessity：{Explicit／Implicit，具备任务或职业语境依据}
- dimension：{完整一级名；维度 2 带具体 Q 名}
- evaluated_files：{相关 golden 文件名字符串数组；全局时 ["all"]}
- knowledge_points：{法律域::具体知识点字符串数组；无对应则空数组}
- atomic_capabilities：{正式字典内 0–3 项字符串数组，首项主导；不编造编码}
- priority：{与分档一一对应，或 Veto}
- score：{+3／+7／+10／−3／−7／−10；Veto 为 null}
- type：{binary／likert；原始 schema 大小写按确认模板，TOML 用小写}
- points：{likert 为 5；binary／否决按字段表为 null}
- trigger_count：{可累计负向的明确计数规则；正向和一次扣分为 null；否决与本题阈值对应}

{likert 写全五档；Veto 不纳入主分。维度 1／2／5 必设，另选四选二；Q 至少三个且含对应两个锚点，锚点正分 ≥30%，至少两条 +10。冲突和未决接口不伪装成已确认。}

## 作答思路（内部）

{事实与材料定位、证据关系及采信、规范版本和适用、争议与有效替代路径、量化口径和具体结果、可执行边界及跨文件一致性。不能只摘抄事实或原则，也不把内部思路发送给被测模型。}

## 标准交付物 golden_output

{按本题实际文件名逐份形成完整可用内容：意见书、审查报告／风险清单／修订文书、起草文书及证据清单、方案与动作清单或台账测算表等。全文包含本应完成的实际分析和文本，不能用文件名、空标题、略、另拟或占位代替。}

{每项事实能定位真实 input，每项引用能核验，主体、金额、日期、程序和职业立场在各文件一致。满足全部正项，不触发负项；模型辅助稿与专家最终核定状态分清。}

## 专家真实检索轨迹

{由专家本人在真实办理过程中记录：检索词 → 命中条文／裁判要旨 → 一档正文 URL；逐一覆盖答案和 Rubric 引用，必要时记录新旧法版本核验。模型不得代填或事后补造。候选是否也须输出轨迹，须在 instruction 明示。}

## 内部完成核对

按[出题规范完成表](../references/出题规范.md#10-出题完成核对与验收边界)和[交付规范提交表](../references/交付规范.md#112-提交前检查表)逐项核对。只记录实际完成状态及证据；模型辅助稿、内容包、正式六件套和真实评测不是同一完成状态。尚未取得的信息不得以默认值冒充，内部待核事项不混入对外终稿。
