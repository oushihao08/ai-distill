# Work法律全场景出题总控（增强版）

从本次冻结案卷和委托方眼下要办成的事出发，设计符合 Work 标准、真实贴合实务、具有高专业区分度的法律实务题。把出题当作承办律师／法务围绕这一委托做一个**完整工作日**：从客户带来的现实难题出发，做到收工时客户能拍板、经办人拿着成品能直接推进获准的下一步。

**核心方法：从委托目标倒推成立条件，沿全卷原始记录追到办理后果。** 先在委托与登记场景允许的范围内完整求解，确认哪份材料会改变请求、抗辩、金额、期限或行动，再将有实质后果的工作落实为 `work_legal_v1` 完整题包（支撑后续自动生成 **Siriser 内容稿五件套**）。材料与场景确有空间时做深做难；无空间时如实保留实际任务与难度，绝不靠虚构事实、强拆文书或改严评分凑级。

---

## 一、Work 铁律（与其他经验冲突时无条件优先）

1. **一包一题身份**：一个材料包只对应一个题目身份，包内全部附件共同构成本题来源；不按附件、文书或子环节拆多题，返修重出沿用原题身份。
2. **`work_legal_v1` 同源契约**：按本次调用的 schema 填写 `task_metadata`（含结构化 `instruction`）、`input_files`、`deliverables`、`reference_outputs`、`research_records`、`task_requirements`、`content_status`、`rubric` 等字段；公开 `question` 与 `reference_answer` 由程序同源派生，不另维护冲突副本。
3. **成果载体与数量底线**：每题至少 **3 份**不同用途的实质配套文书；**业务成果只允许 `.docx` 和 `.xlsx`**（`format` 与后缀一致，禁止声明 `.pdf` 或技术格式）；`.xlsx` 必须在 `reference_outputs` 提供完整结构化 `sheets` 与业务口径说明。
4. **Work 评分体系**：完整题包至少 **30 项**独立判据（正项、负项、`R0-V01` 独立否决合计）；采用六档分值（`+10/+7/+3/-3/-7/-10`）与单条 `R0-V01` 否决（`score: null`，否决**不使净分归零**）；严格使用 14 项规范维度、F1–F5 双锚点（正分合计 ≥ 正向满分 30%）及 36 项受控原子能力。
5. **受众纯净与五件套就绪**：`reference_outputs`（含 `sheets` 单元格）只写真实收件人需要的业务正文与数据，严禁残留任何 AI／模型身份、内部工具名、出题／评分视角或题包制作说明；这些信息分别写入 `generation_note`、`research_records` 或 `rubric`。

## 二、五大高强度实务必建机制

以下机制仅在所附真实案卷有依据且会影响办理结果时落实，不强套模板：

1. **全卷穿透与相容工作应选尽选**
   - 逐份核清原始记录的生成者、证明对象与时点边界；严辨独立原件与同源转述、单方主张与生效认定、查封冻结与实际扣划入账。
   - 在单方代理立场与授权内，从委托目标和原始记录两头试办，用 62 项垂类场景库查漏；能改变客户决定或避免失权的相容实质工作应选尽选，严禁塞入脱离本案冲突的常规章程或同质短申请凑数。
2. **接手实务痛点、动态核算与利害比选**
   - 立足真实卷宗自然展开：纠偏在卷遗留稿、回应在卷对立主张、处理共同约束下的关联对象，或靶向改定交易／治理条款；涉及前手未办结事项或继续投入决策时，算清当下可办部分与改办代价。
   - 需逐笔勾稽、清偿抵充、分段计息或后续补录复算的，交办独立活公式 `.xlsx` 工作簿；关键起算日、估值或部分清偿在卷待核时，结合在卷锚点与法定费率同表实算上下限或盈亏临界条件，不交空白“待核”表早退。
   - 存在可量化损益或失权差异的方案选择时，核实直觉常规方案有无反噬风险；同一前提下明确占优的合法口径，直接锁定维护委托人最大合法利益的处理并写清次优选择的损失。
3. **跨时际权威法源核验与类案对读**
   - 行为与程序跨越新旧法、时间效力解释、多段利率或法定节假日顺延时，作者必须打开有权机关原文核对条号、版本与施行日，如实登记 `research_records`（须附条文原文或规定摘要）；禁止引用公众号、百科、聚合资讯。
   - 规范原文未决且会改变主张时，对读公开生效裁判原文的决定性事实与边界；接受同等可核实的合法依据，不把作者查到的单一案号设为隐藏答案键。
4. **饱满交办、零模拟、零剧透（连文件名都不泄底）**
   - 100% 立足所附真实案卷，严禁“模拟律师／本题模拟／假定截至某日无新增清偿／虚拟双窗口／编造卷外来函”。
   - 写足现实业务困局、基准时点、触发来件、各独立成果的接收人与用途；但**严禁**在 `instruction` 或 `deliverables` 文件名中泄露待裁决救济路径／案由、备选请求权、修法年份与顺延线索、旧稿具体错点或回单重复／倒挂异常。
5. **内外分件成稿与高区分度判据**
   - `reference_outputs` 按真实收件人独立分件、禁止不同用途混装合册；含官方出处核验、己方不利底牌、多路径损益取舍或签发启用条件的对内决策内容，独立成件，严禁塞进对外清洁文书附注。
   - 全部核心判断落实为自包含、独立计分的 Work Rubric：严格区分“提及／罗列”与“实质完成”，封堵仅凭主文摘要、常规套话或次优默认口径拿保底分，同时对同等合法替代路径公平给分。

## 四、保存前必过七条硬红线

1. **交办闭环不泄底**：只读公开 `instruction`＋`deliverables`，能否看出客户托办的全部独立事项与收件用途？若照字面做完却会漏办某独立事项，补清业务范围与用途；若提前泄出待求路径、修法年份、旧稿错点或账据异常，立即改回中性客观表述。
2. **接手人试走通过**：遮住内部思路与对内意见，只拿每份对外／经办 `reference_outputs` 试走：收件人拿到后第一件要办的事能否直接落地，无须自己再查法条、拆款项或补写关键条款？内外文件是否已严格隔离？
3. **五件套格式与路径逐字节锁死**：`deliverables` 至少 3 份且仅含 `.docx`/`.xlsx`（后缀与 `format` 一致、无动态日期或版本号、≤200 字节）；所有 `deliverables` 均在 `reference_outputs` 有完整正文（`.xlsx` 必含非空结构化 `sheets`）；`evaluated_files` 仅引用精确文件名或单独 `["all"]`；同一题 `deliverables` 至多声明一份检索轨迹。
4. **受众纯净零残留**：逐份全文及全部 `sheets` 单元格排查——零 AI／模型身份、零真人专家冒称、零内部工具名（`AnySearch`/`Codex`/`Harbor`/`JSON`/`research_records` 等）、零出题／评分视角词、零模拟词（`模拟律师`/`本题模拟`/`假定……`）、零 `(****)` 星号掩码、零将完整在卷文书误称“文字摘录”。
5. **Rubric 数量、结构与区分度达标**：完整题包 ≥30 项；维度 1/2/5 必设＋另选 ≥2 维度；维度 2 ≥3 个 Q 子维度且对应 F1–F5 双锚点正分 ≥ 正向满分 30%；至少 2 条 `+10`；主观项 ≤10%；仅 1 条 `R0-V01`（含完整三类编造 >3 处与本题具体红线）；维度 5 另有普通编造负项；逐对无重复计分，且表层照抄主文／次优默认口径答卷在核心项上明确失分。
6. **法源与计算真实可复核**：主成果与判据中每一条实际援引均对应 `research_records` 的真实权威原文核验（含条文原文或摘要）；全部金额、天数、利率、顺位与临界条件经脚本实算验证且跨件口径一致。
7. **等级依据与输入映射诚实准确**：`input_files` 的 `attachment_id` 与 `name` 原样复制自 `delivery.json.input_files`；`level_basis` 如实逐份登记真实独立文书、必要工作与专家人时，未达标等级缺口如实写入 `explanation`，不凑数、不冒充平台验收或真人签署。
