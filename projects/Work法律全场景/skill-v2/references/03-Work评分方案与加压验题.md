# Work 评分方案与加压验题

**用途：**指导出题作者从已核验的完整标准成果中编写符合 Work 契约（`work_legal_v1` + `model_report_v1`）且具备高专业区分度的 Rubric，并通过五类对抗答卷试判。

> **冲突裁决提示**：本文件严格采用 Work 的 **≥30 项、六档加减分、14 项规范维度、F1–F5 双锚点与单条独立否决 `R0-V01`（否决不归零）**体系，并吸收实务高区分度判据编写与试判方法。**严禁**套用“6–12 条等权 1 分”或“整题归零”。

---

## 一、设项原则：独立结果、严格区分与公平给分

### 1. 数量与提炼顺序

- 完整题包（`content_status.status = "complete"`）**至少 30 项**独立判据（正项、负项、`R0-V01` 独立否决合计）；草稿如实保留已完成部分。
- 严格**先逐份完成并交叉核验 `reference_outputs`，再从中提取独立业务结果**。先去重、再拆项，严禁拆句、按重复文件复制或增加无关形式项凑 30 条；不足 30 条时回查卷宗补足有依据的实质业务工作，或如实说明缺口。
- 作者的等级清点、人时估算与出题设计留在 `task_metadata.level_basis`，不单设得分项。

### 2. 独立拆合与防重复计分（“甲正确、乙错误”试判）

- **拆条检验**：代入“甲正确、乙错误”——两项各有独立业务后果（影响不同请求、不同抗辩、不同对象或不同动作）则拆条；共同决定同一结论的必要条件合在一条内整体判断。
  - 例：“核准本金与分段利息净额”与“判断上诉是否超期及可行”可一对一错 → 拆条；同一次计算的基数、公式与结果 → 合为一条主项，不机械拆开。
- **跨维度防重复奖励**：逐对比较两条实际奖励的结果，不看维度名。
  - 同一组数字的复算与算术结果只在 **Q5** 主项计分，**绝不**换成“Q1 事实冲突”或“维度 4 跨文件核验”再奖一次；
  - 同一份材料的证据证明范围归 **Q1**，据此取得缺失凭证的具体行动归 **Q6**（业务后果不同，可分设）；
  - 必要复用同一核定金额到多份文书，属于同一结果的一致性要求，不因重复出现而多次加分。
- **负项独立性**：负项必须命中**额外实际错误行为**（如违法建议、立场倒置、编造、内部自相矛盾、空话敷衍、错引自媒体等），**绝不**把正项“未做到 X”换个说法变成负项重复扣分。

### 3. 严格判断，满足即给分（封堵套话与次优放水）

- **把高标准事先锁死在 `statement` 中**（评分者独立判卷，不读本 Skill，默认不提供标答；每条 `statement` 必须完全自包含，严禁写“详见参考答案”“参照上条”“等”）。
- **提及 ≠ 完成**：
  - 列出双方说法 ≠ 评价证明范围与采信结论；
  - 罗列请求权名称 ≠ 论证本案构成要件与成立边界；
  - 写“若成立则支持、否则不支持” ≠ 依据现卷作出有理由的判断（仅在材料客观缺失时接受明确缺失前提、条件分支与补证动作的答案，现卷已能判断的不能推给未来核验）；
  - 仅在意见书提一句“应扣除某款”却未在对外文书／核算表落准数字或条款 ≠ 完成该项业务。
- **锁定最优合法利益口径**：在同一事实、授权与委托目标下，若不同代理口径存在可量化损益或失权差异（如约定优先抵充 vs 法定默认抵充、及时守期 vs 错选较晚起算点、前置减资 vs 径行起诉被驳回），正项须锁定维护委托人最大合法利益的占优口径，并写明采用次优默认口径造成少收、多付或失权的具体后果（即明确的不成立边界）。若取舍取决于客户尚未明示的商业偏好，则验收具体得失比较、保权动作与留待拍板事项，不暗设唯一偏好。
- **未决争点研判的判分边界**：题面要求研判未决争点时，验收决定性证据与最强反证的对读、证明规则适用、当前可支持的倾向及相反认定下受影响的具体文书／金额调整；只押中结论、两边罗列不权衡，或意见改了而请求仍照抄旧前提，均不成立。固定胜率百分比或事后真实裁判结果不作答案键。
- **合法替代必须给分**：内容满足本条实质条件即给分，不因措辞、段落顺序、等效表结构或同等合法路径不同于标答而扣分。类案只评价真实裁判规则、可比事实与适用边界，不把作者查到的单一案号设为隐藏答案键（除非业务确需指定并在题面明示）。
- **检索完成状态 vs 编造**：引文正确不单独证明已联网，缺可见轨迹也不直接证明编造；严格区分“未完成核验”“拿未核依据作确定结论”与“编造来源／虚称已检索”。明确标注“拟检索／待核”不按编造扣分，但也不算完成必须真实检索的正项。
- **共享前提与上游误差传递**：仅当下游项确有独立的新证据核查、新程序规则或新条款重构且引用上游数值时，在 `statement` 中预先写明条件式边界：纯粹沿用上游数值偏差但本条独立规则判断与文书落实均正确的，不重复扣分；若本条自身漏查、错选规则或未落实到具体条款，仍判不成立。
- **文件载体与活公式归属**：交办 `.xlsx` 活公式工作簿时，将“原始明细逐笔入表、派生值由活公式驱动非静态常数、默认待核留空无 `#VALUE!/#REF!/#NAME?` 报错、核定结果与对外文书一致”落实到对应的 Q5／Q6／维度 6 判据中，避免仅靠体例或表格框架拿走核心业务分。

## 二、Work Rubric 字段契约与受控词表

每条 Rubric 对象为 `{ id, metadata }`，**`metadata` 的 12 个字段必须严格匹配以下定义**（`criterion/rule` 由程序同源派生，作者不另维护；`score` 为唯一数值来源，`statement` 内不写“计+7分，否则0分”以免冲突）：

| 字段 | 规范与填写要求 |
| --- | --- |
| `id` | 正向 `R{维度数字}-P{两位序号}`（如 `R2-P01`）；负向 `R{维度数字}-N{两位序号}`（如 `R5-N01`）；独立否决固定 `R0-V01` |
| `statement` | 完全自包含的业务判定标准：写清具体原始文书名称（含案号／日期／主体）、正确值或规则要旨、精确落点文件、全部／任一命中条件、合法替代范围及明确不成立边界；计算项写明精度、舍入与有依据的接受范围；负向直接写明有害错误行为；Likert 项附完整五档锚点；累计扣分项与 `trigger_count` 同口径 |
| `criterion_type` | `Objective` 或 `Subjective`（**`Subjective` 不超过总条数的 10%**） |
| `criterion_necessity` | `Explicit`（题面明文要求）或 `Implicit`（职业常识或语境必然推导） |
| `dimension` | 必须从下方 **14 项规范维度枚举**中精确选取；内容质量每条只填**一个**主 Q，不得拼接 |
| `evaluated_files` | 非空字符串数组，逐字节匹配 `deliverables[].path`；跨全部文件时写单独 `["all"]`（不得与其他文件名混写） |
| `knowledge_points` | `法律域::具体知识点` 字符串数组；无对应知识点填 `[]` |
| `atomic_capabilities` | 0–3 个字符串数组，必须从下方 **36 项受控原子能力枚举**中精确选取；首项为主导能力，其余兼考 |
| `priority` | 与下方七档枚举一一对应 |
| `score` | 与 `priority` 严格绑定：`10`、`7`、`3`、`-3`、`-7`、`-10`、`null`（仅 Veto） |
| `type` | `binary`（默认）或 `likert`（确有质量分档意义时启用） |
| `points` | `likert` 固定填 `5`；`binary` 及 `Veto` 填 `null` |
| `trigger_count` | 一次性扣分与所有正向项填 `null`；按处累计的负向项写明每处定义、单次分值与封顶口径（不得因属编造类自动改为无封顶） |

## 三、维度配比、F1–F5 锚点、权重与单条否决 `R0-V01`

### 1. 维度选设与归属铁律

- **必设维度**：维度 1、维度 2、维度 5（`0-一票否决` 另设 `R0-V01`）。
- **选设维度**：从维度 3、4、6、7 中**至少再选 2 个**（选维度 7 时，至少设 1 条具体可量化的负向项）。
- **维度 1 约束**：仅按“交付物齐备（二元）、硬约束、角色立场（仅设负向）、基准日”组织，**每类不超过 1 条**；专业实质判断一律归维度 2。
- **维度 2（Q1–Q7）约束**：
  - 每题至少选 **3 个 Q 子维度**（Q7 内部逻辑一致性默认仅设负向）；
  - 必须包含本题任务类型对应的 **2 个必选锚点**，且**两个锚点正向分值之和 ≥ 全题正向满分总和的 30%**：
    - `F1 咨询研究` → **Q3 + Q4**
    - `F2 审查审核` → **Q2 + Q3**
    - `F3 文书起草` → **Q1 + Q4**
    - `F4 方案设计` → **Q4 + Q6**
    - `F5 数据核算` → **Q1 + Q5**
  - **主归属判别**：法源真实／版本正确 → Q3；事实代入法律要件定性 → Q4；证据证明范围与冲突采信 → Q1；风险识别与分级 → Q2；金额／比例／期间／法定门槛核算 → Q5；明确结论与可执行动作／替代路径 → Q6；跨文件自相矛盾 → Q7。附带提及法条不改变主归属。
- **维度 5 约束**：可只设负向；必须设**普通编造负项**（分别明确编造法源、事实／证据、检索来源的具体行为及计次口径），以及引用非权威来源（公众号、推文、百科、问答社区、聚合资讯）的负向扣分；**不能**只设 `R0-V01` 否决而漏掉普通扣分。

### 2. 七档权重与核心条目要求

| `priority` | `score` | 设定标准（拆项后按独立后果重定权，严禁机械继承 +10） |
| --- | ---: | --- |
| `Critically Important` | `+10` | 缺失会使整体结论方向错误、必须重做（**每题至少 2 条**） |
| `Important` | `+7` | 缺失需明显补充核查或实质修改才能使用 |
| `Slightly Important` | `+3` | 细节完善，可由复核人员补齐（严禁拿一堆形式小项堆高分） |
| `Slightly Detrimental` | `-3` | 易发现、修改成本低的小错 |
| `Detrimental` | `-7` | 需回查材料或法源的重要错误 |
| `Critically Detrimental` | `-10` | 违法建议、立场倒置、编造或核心定性错误 |
| `Veto` | `null` | 实务不可用一票否决（单独统计可用率，**不使净分归零**） |

### 3. 单条独立否决 `R0-V01` 规范

- 当前契约固定仅设 **1 条** `R0-V01`（`dimension: "0-一票否决"`，`priority: "Veto"`，`score: null`，`type: "binary"`，`points: null`，`trigger_count: null`）。
- 条内分开写全本题有事实依据的触发情形：
  1. 具体违法／舞弊／规避监管建议；
  2. 严重职业立场红线（如最终对外文书服务错误主体、越权放弃本方核心权利或泄露己方谈判底牌给对方）；
  3. 三类编造**分别累计超过 3 处**——① 编造法规或裁判依据；② 编造事实或证据；③ 编造 URL 或检索轨迹（**同一对象反复提及去重，三类分开计数，不跨类凑 3 处**）。
- 普通遗漏、说理不足、体例缺陷不触发否决；普通负项若引用 `R0-V01`，被引用条件必须在 `R0-V01` 正文写全。

### 4. Harbor 映射与计分口径（了解下游，不重复维护字段）

- Binary 命中／未命中；Likert 输出 1–5 整数，归一化为 `(raw - 1) / 4`。
- 满分 = 全部正向分值之和（负向不进分母）；净分 = 正向得分 − 负向扣分；Harbor 主分 = `clip(净分 ÷ 满分, 0, 1)`；可用率 = 未触发否决题数 ÷ 总题数。
- 下游导出 Harbor 时，自动映射 `criterion.id / name / description / type / points / weight(3.0|7.0|10.0) / negate(true|false)`，采用逐条独立会话评判（`judge.mode = individual`）。

## 四、冻结前五类对抗答卷试判（作者内部必做）

写完 Rubric 后，在作者会话内代入以下 5 类假设答卷逐条试判（不调用外部模型、不生成自审附件）：

| 对照答卷 | 必须通过的检验标准 |
| --- | --- |
| **1. 完整正确解 & 简洁等价合法解** | 两者均应满足全部正项、不触发任何负项或 `R0-V01`。若仅因措辞、结构顺序或等效表结构不同而失分，删除该呈现限制 |
| **2. 仅读主文摘要＋套话工整答卷** | 精准摘录表面事实与常规体例的部分正常得其对应合理小分，但在涉及底层凭证消歧、跨时际法源、精确复算或最优口径的核心正项（+10/+7）上必须明确失分；若靠套话就能拿到高分，回查是否遗漏实质判断或把核心项写得过宽 |
| **3. 成果齐备但漏办一项独立工作／填死常数答卷** | 抽掉一项独立成果的核心判断，或将 `.xlsx` 派生数改为静态常数，确认对应正项必不成立；且该缺失不会导致同一错误被两个正项或“正项失分＋同义负项”双重处罚 |
| **4. 沿用失效旧稿／采用次优亏损口径答卷** | 确认对应核心项能依据卷内原件与算清的损益差额明确判不成立；同时核查 `instruction` 和文件名是否无意中泄出了正确路径 |
| **5. 上游基数算错但下游独立判断正确答卷** | 确认上游错误仅在其所属主项扣分，下游独立规则／条款判断按事先写明的共享前提边界正常评价；若发现跨项重复计分或重复扣分，立即合并或重写分界 |

**收尾检查**：逐项核验 `rubric.length >= 30`、双锚点正分占比 ≥ 30%、`+10` 条数 ≥ 2、`Subjective` ≤ 10%、`R0-V01` 仅 1 条、维度与原子能力 100% 命中受控枚举、`evaluated_files` 100% 命中 `deliverables[].path` 或单独 `["all"]`。
