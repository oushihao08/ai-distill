# 高强度实务设计与求解方法

**用途：**供出题 Agent 在确定立场与场景后，深度穿透真实案卷、识别决定客户成败的高负荷实质工作、完成跨时际法源核验与脚本实算，并验证题目的真实工作量与区分度。本文件为作者内部方法，严禁将文中分类术语照搬进题面或标准成果。

---

## 一、读卷穿透：找茬与双向试办

### 1. 读卷四项硬区分

通读全部冻结附件（长文件分段全读），逐份核清“谁生成、因何事生成、证明谁的什么事项、覆盖何期间、与其他记录如何印证或冲突”，严格区分：
- **提交者 vs 生成者**（谁交到卷里 ≠ 谁制作／背书）；
- **独立原始证据 vs 同源转述**（判决摘要、微信转发截图、汇总表与银行回单／原始合同的证明层级）；
- **单方主张 vs 生效认定**（诉状／发函／内部单据 vs 双方签认／生效裁判）；
- **权利成立 vs 当前可执行状态**（查封冻结／受理通知／胜诉判项 vs 实际扣划入账／已涤除负担／可分配余值）。

### 2. 从目标与事实两头试办

1. **从本方目标倒推**：客户今天要拍板、签发、立案、付款或抗辩什么？哪些事实、证据、程序期限或授权前提必须同时成立？逐项回卷核实；证据改变可实现范围时同步收窄或调整交办。
2. **从原始记录往前追**：某份记录除证明表面事实外，还使哪项权利受限、哪项期限开始起算、哪份前手稿件失效，或带出同一委托下尚未处理的并行事项？把有实际后果的事项沿依赖链办到当前证据与授权允许的位置。
3. **按 62 项垂类场景库查漏**：查阅[法律垂类场景与实务核查库](../assets/法律垂类场景与实务核查库.md)对应领域条目与表末高负荷展开参考。对候选工作逐一检验：**少办这一项，哪位接收人会因此办错、失权、多付／少收或必须自己重做核心专业判断？** 会则纳入委托；超出授权、时点互斥、缺核心输入或用途重复则舍弃（“篇幅够了”“好套模板”不是排除理由）。
4. **相容实质工作应选尽选，严禁凑数**：同一委托方权限与时点相容、各有独立用途的实质工作均应纳入；通用合规手册、无冲突公司章程通则、无争议历史沿革摘录和仅改抬头的同质短件，一律不单列凑数。

## 二、按在卷真实文书展开的四类实质工作

严禁虚构卷外事件、来函或虚拟双窗口。根据卷内真实存在的文书结构，择一或组合展开：

| 实质工作与卷内触发输入 | 作者必须先求解的专业处理 | 落地到成果的真实交付（DOCX / XLSX） |
| --- | --- | --- |
| **1. 纠偏或重构在卷既有文书**<br>（卷内已有旧申请书、多版起诉状、财产表、合同草案、和解稿或结算单） | 对照裁判、回单、登记、送达回证逐处核查旧稿的主体、管辖、请求、范围与计算；区分可沿用、须纠偏及因缺证留白的边界，测算局部纠偏对关联请求与数额的连锁影响 | 可改的交付完整修订稿（需谈判审改又需送签时分别备修订说明／留痕与清洁稿）；不应再用的交付停用说明、受影响事项与替代正文 |
| **2. 回应在卷对立主张**<br>（卷内已有对方诉状、上诉状、异议书、造价鉴定／审计报告、结算主张或抗辩笔录） | 还原对方请求与证据链，核查证明范围、计价方法与法律要件；结合本方反证锁定应承认、可推翻及待调证范围，分清专业鉴定边界与法律质证边界 | 按主张所处环节交付对应正式文本：审理中落入答辩状／质证意见／代理词与证据目录；付款审批中落入核准放行与异议明细（`.xlsx`） |
| **3. 处理共同约束下的关联对象**<br>（多笔混同流水、多处查控财产、多名责任主体或多项权利受资金／顺位／权限／除斥期共同制约） | 逐对象核定成立依据、优先顺位、前案已执结／退费／垫付扣减与排斥关系，求出共同约束下维护委托人最大合法利益的可行组合，防止逐项可行但整体冲突 | 逐对象把准许与暂缓范围落实到收件人可直接使用的文书与指令；涉及多笔扣减、共同余额、分配顺位或动态复算的，配套交付联动 `.xlsx` |
| **4. 定制交易、治理或和解条款**<br>（卷内合同、章程、决议或履行基础明确，暴露冲突条款） | 测算现有条款对权利保留、违约触发、表决权限、出资期限、清偿抵充或担保脱保的实质后果，求出权限内最优安排与须请示授权的边界 | 优先靶向改定正在流转的合同／决议文本；另给批准人比较方案与风险说明；对外稿保留真实生效条件，不塞无冲突常规通则 |

## 三、深度实务推进的三项高价值方法

仅在卷内有对应事实时启用，不强套：

### 1. 从前手留下的工作接着办

- **接手已在办事项**：先辨清哪版仅是拟稿，哪版已递交、签署、退回或部分履行。未发稿直接改到可签；已递交须调整的，办到原收件人能识别哪项请求变动、依据与随件如何替换；已签署的先核变更权限与相对人同意要件。状态未明时，完成辨别版本与守住眼前期限的工作。
- **接手继续投入的决定**：客户需决定是否追加诉保、评估、另诉等支出时，比较现实可选做法（含只做已具备条件的部分），分清已有保障、新增收益、直接成本与等待代价。**关键估值、报价、送达节点或优先负担在卷待核时，严禁留空白“待核”或笼统写“暂不投入”，必须结合卷内已有时间／金额锚点与法定费率，在底稿与意见中实算出上下限区间或改变决定的盈亏平衡临界条件**（如覆盖诉保税费所需的最低可变现值或份额），不把主张总额当净收益，不虚构外部报价。
- **处理对方已提出的障碍**：将真实退件理由、拒付项目或返稿条件对回原件；现有材料能解决的办到可再次递交或回传的正文与凭据，一时不能解决的核定其余部分能否先行办理，重点排查接受一处修改是否变相放弃其他权利。

### 2. 客户原意与办理建议

- 先分清客户想保住的利益、原提办法、已明底线和本次授权，正面回答原办法能办到哪里、障碍何在。
- 再查卷内是否存在足以改变建议的事实或替代路径（更快实现、多保权利或少担义务）：区分**可并行、须择一、已包含原有利益、条件后手**。以原办法今天能得的结果为基准比较净得失。
- 有利方向仅有线索时，写清支持记录、反向制约、取证主体与代价，以及查实／查否分别改动哪项主张；等待会失权的，先在授权内守住期限。
- 标答将取舍落实到实际要用的意见、条款或请求，**不统一硬凑“高中低三档方案”或无必要比较表**；原路已最优或无替代线索时，直接把原委托办扎实。

### 3. 从未决争点形成办理决定

- 仅当客户眼下决定取决于在卷未决争点时启用。按办理基准日独立求解：将支持当前倾向的决定性记录与最强反证／相反解释对读，依证明责任、证明范围与适用规则说明各请求获支持、部分支持或受阻的理由（严禁拿基准日之后的裁判充作当时依据）。
- 沿最有影响的相反认定回查：若该证据只能证明较窄事实，哪项请求、抗辩、收付安排或签发条件须调整？写出可用替换措辞或可复算边界（条件分析，不虚构新来件）。若删去研判不影响任何决定或交付内容，直接并回常规分析。

## 四、五类高判别力加压机制与六类捷径反制

### 五类真实业务加压机制（按本包真实材料选用，不强求全覆盖）

| 卷内真实存在的冲突／关系 | 迫使作答者必须完成的专业工作 | 落实到成果的可核验差异 |
| --- | --- | --- |
| **1. 主文转述与底层原件冲突** | 穿透合同原条文、工商内档、原始回单或关联裁定，推翻汇总表／裁判摘要表面印象并回应最强相反解释 | 改变可采基数、责任上限、抗辩范围或请求标的 |
| **2. 跨时际修法与多层级特别规则** | 自行识别行为与程序跨越的新旧法、时间效力解释、过渡期政策、多段利率档次或法定节假日顺延（题面零年份／文号提示） | 决定适用旧法还是新法、是否脱保／加速到期、精确届满日与分段计息 |
| **3. 多笔流水／多标的／多主体共同约束** | 全量原始记录逐笔去重、核扣前案已执结／退费／垫付、排定清偿抵充或分配优先顺位 | 防止重复受偿、超上限追偿、漏扣费用或跨文书总额矛盾 |
| **4. 发起／冻结与实际履行／扣划半截并存** | 严辨查询、冻结、解冻、受理通知、审批单与实际扣划入账或签收生效状态 | 锁定真实未清偿净额与补证条件，不把冻结额或受理额当已受偿 |
| **5. 直觉常规方案存在反噬风险** | 对“顺势申请补正／按法定默认抵充／径行起诉”与“保守抗辩／约定优先抵充／前置减资或析产”做反事实净损益比选 | 核实额外代价后修订会造成可避免损失的方案；复算支持原路则坚守原路 |

### 针对作答模型六类捷径的反制检查

| 作答模型常见捷径 | 真实业务反制设计 | 作者成稿前可观测核验点 |
| --- | --- | --- |
| **1. 只读主文，跳过边缘凭证** | 让举证范围、金额基数、送达起算或授权边界真正依赖边缘凭证（回执、内档、签收单、批注等） | 仅靠主裁判／主合同摘要，即便猜中大方向仍会算错数、错配证据或漏掉关键限制 |
| **2. 只搜现行通用法条或靠题面提示填空** | 涉及跨时际法源、专门监管规则、多段利率或节假日顺延时，题面**绝不**透露年份、文号或顺延提示 | 不实际检索行为时旧法、时间效力解释原文、历次 LPR 或当年放假安排，必然选错条文或算错死线／利息 |
| **3. 计算填死常数或遇缺证交空白表早退** | 需逐笔勾稽或后续补录复算的，交办独立活公式 `.xlsx`；待核留空与已知为零分离；缺估值／送达日时结合在卷锚点与法定费率同表实算上下限／临界条件 | 改动一笔影响结果的卷内记录或参数，能追踪到哪些派生值和请求随之改变；且默认待核留空零公式报错 |
| **4. 批产同质短件或合册塞全文** | 按不同接收人与用途分别独立命名正式文书（≥3 份），诉讼／仲裁／执行主文书的举证目录或质证意见按需要独立成件，严禁不同用途混装合册 | 拿走任意一件都能指出哪位接收人的哪项动作无法完成；换抬头或拆同质短件不算有效扩展 |
| **5. 直觉平推，未做反事实损益核算** | 挖掘“表面合理但实算亏损或被驳回”的方案陷阱，要求在相同事实、授权与目标下比较净损益与失权风险 | 对照次优默认口径，能明确算出少收、多付或失权的具体后果并落实到最终正文 |
| **6. 核心错算却靠体例套话拿保底分** | 在 Work ≥30 项体系内合理配置核心判断权重，将“提及≠完成”与不成立边界写实到每条 `statement`（详见[评分方案](03-Work评分方案与加压验题.md)） | 顺着主文表面数字或次优口径走的工整答卷，核心正分项均无法得分 |

## 五、作者求解核验：法源原文、脚本实算与依赖检查

作者完成标准成果前必须亲自做到以下四项：

1. **权威法源逐条核原文**：实际检索并打开国家法律法规数据库、最高法／有权机关官网、法院正式案例来源或北大法宝／威科正文页，核清条号、款项、施行日期、修订版本与过渡条款，写入 `research_records`（须含条文原文或规定摘要）。严禁凭记忆顺延条号、编造 URL 或引用自媒体／百科。
   - **类案检索适用条件**：仅当规范原文不足以解决影响主张的关键分歧时启用；对读公开裁判原文的程序阶段、决定性事实与裁判理由，说明与本案的相似点及足以区分的差异；检索词使用抽象争点，**严禁将案件当事人的真实／脱敏隐私细节发往外部搜索**。
2. **脚本精确验算闭环**：使用计算脚本（如 Python）精确复算全部本金、分段利率、闰年／日历天数、清偿抵充顺序、优先受偿顺位、分配比例与临界值，并做分项汇总反算校验。如实区分分项舍入与汇总舍入的合法尾差，在 `rubric` 中写明舍入口径与有依据的接受范围（不机械一律给 1 元容差）。
3. **跨成果口径与依赖检查**：
   - 同一基准日与前提下，所有 `reference_outputs` 的主体、案号、金额、日期与行动指令完全自洽；跨阶段变化的明确标注时点与依据。
   - 内部做一次**依赖反查**：暂不使用某组拟作决定性依据的记录，检查能否从其他合法证据得出同一结论——能则保留合法替代路径，不能则明确不可或缺的判断前提。
4. **“最省力合规答法”压力检验（冻结前必做，不产出额外自审文件）**：
   - **检验 A（只读公开题面反查漏交办）**：遮起内部思路与标答，只读 `instruction`＋`deliverables`，设想一个“找对主路径、算对汇总数、会批量出文件但能省则省”的答卷——拿它的成品交给真实签发人／经办人／财务／代理律师，哪件事还办不成？若是题面字面允许省掉它，回到 `instruction` 或 `deliverables` 补清实际办理范围与收件用途（绝不泄出答案或证据矛盾）。
   - **检验 B（接手人试走标答）**：遮住作者内部思路和仅对内备忘录，只拿收件人有权拿到的 `reference_outputs` 试走：收件人第一件真正要办的事能否直接落地？若仍须自己补挑证据、拆分逐笔款项或补写关键条款，立即回到该份 `reference_outputs` 补足。
   - **检验 C（拿走一件检查）**：从 `deliverables` 逐一拿走任一份文书，若其余成果全对时接手人仍能完整办结且不失独立用途，合并重复件；若会导致无法举证、签发、复算或交接，保留并写准该件用途。
   - **检验 D（区分真实变化与批量换皮）**：若把两个收件人或两笔争议事项的处理意见互换后仍能照交，检查是否遗漏了各自不同的凭证、时点或权利限制；确可同办的合并，不机械重复。
