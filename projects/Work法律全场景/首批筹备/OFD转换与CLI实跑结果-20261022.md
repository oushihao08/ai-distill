# OFD转换与CLI实跑结果

日期：2026-10-22。范围：25、27、28号OFD材料及21号超限PDF；不脱敏。

## 实现

- 新增共享预处理`server/materials/prepare-library-files.ts`，CLI命令`library files prepare --manifest JSON --out 新目录`。
- OFDRW 2.4.0 IText本地整页转PDF，原件只读；Java/Maven依赖由显式安装入口准备，不改package.json。
- PDF切割优先qpdf按范围导出并清除未引用资源；不重编码图片。缺少qpdf时兼容Poppler。缓存键区分算法；新增分片页数校验。
- 不修改现有HTTP上传限制，不重启API/worker；不修改模型或数据库结构。
- 新目录保留原件路径/摘要、转换器版本、页数、上传件摘要和分片范围。

- CLI四次真实本机文件预处理及上传成功；类型检查`bunx tsc --noEmit`通过，差异空白检查通过；没有新增或运行单元测试。

- 抽查转换页文字、表格、扫描内容和印章，未见明显截断；这不是逐页视觉验收。
- 28号被拆分的大PDF抽查每个分片首尾，共6次，源PDF与分片同尺度渲染PNG完全一致。见`L5-OFD切割页面核对-20261022.json`。
- 最初PDFBox转换出现膨胀，未作为最终上传输入；换IText后复核。原OFD数字签名效力不能从PDF副本继承。
- 入库核验成功不等于OCR成功或加载项目完成；后续原文提取有独立任务，详见入库记录JSON。
- 初始100MB入口调整授权因最终产物均小于100MB而未使用；没有启动独立API。
