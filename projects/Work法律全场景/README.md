## 目录边界

- `materials/` 保存本项目规则原文转录和整理规范；案件来源附件位于 `首批筹备/questions/`，不视作已完成脱敏或参考答案。
- `skill/` 是主项目跨期共用的出题规则输入；内部 references/assets 也参与任务指纹，不添加目录说明文件。普通作者只扫描指定 skill，不自动读取外面的 materials，因此完整规则副本保留在 skill 内。
- 系统新增显式 model_report_v1，用于保留正负分／否决规则及模型报告指标；缺省旧流程不变。当前被测作答仍为纯文字，不提供工具或文件交付能力。新实现、配置示例及内部评测不等同正式 Harbor 验收。
- `首批筹备` 是本地临时分组，不代表项目方正式期数；题目目录及 `project.json` 已建立，数据库目录同步已完成，附件入库和题包制作另行执行。
- 点击“归档达标题目”会让 `delivery.ts` 将本次内部达标快照保存到系统管理的 `STORAGE_DIR/deliveries/`。该操作仅完成本地交付准备，不代表 Harbor 格式转换、外部上传或项目方验收；正式题包仍按 `materials/交付规范.md` 完成。旧 `outputs/交付准备/` 文件保留为历史产物，不再接收新结果。
- Harbor 整批组包单独运行 `bun projects/Work法律全场景/batch-package.ts <manifest.json>`；manifest 结构、限制和边界见 `materials/交付规范.md` 第 11.4 节。此工具只执行结构与固定脚本字节校验、目录复制和 ZIP，不替代 Docker／Oracle／judge／模型及人工验收。钉钉页面现可见 A.1/A.2 完整代码且已转录，但未提供可下载的原始脚本文件；取得正式文件并完成字节校验前，不能生成已验证的可交付批次。
- 题目认领登记表现可访问；具体认领状态和剩余名额以该表当前内容为准。
