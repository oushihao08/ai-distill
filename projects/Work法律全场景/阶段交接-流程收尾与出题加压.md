## 3. 当前从出题到评分的真实设计

### 3.1 两层工作流与输入版本

```text
来源目录 → 材料包：入库／提取 → 脱敏成功版本
                                  ↓ 同一版本可建多题
题目：私有整包快照 + 场景／角色／方向／标签
       → 4 出题 → 5 各模型作答 → 6 对各答案独立评分
       → 7 程序判断 → 8 项目交付脚本 → 文件／打包
```

材料包更新或重新脱敏，不修改既有题目的冻结材料。要用新材料另建题。重出同一道题会创建新尝试，使当前下游答案、评分、达标和归档依赖失效；历史尝试保留。要对比加压效果，优先从同一成功材料版本另建测试题，保留原题与现有 accepted。

页面顺序不能作为 API ordinal。当前七个可见步骤的稳定 ID 是 `1、9、4、5、6、7、8`。

### 3.4 评分计算与有效性

当前规则：正项 +10／+7／+3，负项 −3／−7／−10，独立否决不计入主分。正向满分为所有正项权重之和，净分为实际正分减实际扣分；当前政策使用 `clip(净分/正向满分,0,1)×100` 比较指标。Likert、累计扣分按本题冻结规则；不能另造算法或重复扣分。

`extractModelReport()` 主要校验唯一结果区、JSON结构、ID覆盖／唯一、字段类型、比较指标范围；**当前该解析函数不会复算 raw_score、full_score 或 evaluation_percent，也不判断法律结论。** 评分 Agent 获得只读 `复算评分.py` 和从同版 Rubric 投影的权重文件，可核算最终逐项结果；是否实际执行须看本次事件，API模式收到文件文本不等于能运行工具。

因此“评分 succeeded / valid”不能证明算术和法律判断均准确。算术疑点须对照 items 独立核对后记录，禁止替模型改写成绩制造 accepted。专业评分问题留在后续任务；真实缺分、绑定错误和结构错误先解决，否则第七步没有可靠输入。

## 5. A任务：出题加压的独立任务书

### 5.1 要解决的问题与不能推断的结论

已知：现有9题中7题双模型均分超过55%；4道多案组合L5全部为repair。**增加材料或合并案件本身没有保证低分。** 尚未知：各题具体是业务问题过直白、主要正分太容易、提示泄露、候选确实能力强，还是评分判断／算术存在问题。未逐项读题、答案与评分前，不指定根因，更不归咎于某一段Skill。

诊断者可读取历史评分定位模式；普通出题作者仍遵守新会话输入边界，不注入旧答案、旧分数或逐题评分反馈。诊断结果应先提炼为有证据的通用设计方法，再经用户要求更新Skill／设计方向；不能把某个旧题答案变成新作者暗示。

加压先用现有字段和结构。当前 `authoring_direction` 能承载具体业务判断目标；`scenario` 与 `role_perspective` 承载场景和立场；`reference_outputs` 和 `rubric` 承载完整求解及独立判据。没有证据表明仅为提高难度就需要新数据库字段或新工作流。

### 5.2 先做证据诊断，再选加压方法

1. 固定两道试验原型及对应作者／答案／评分attempt，优先包含高分的“L5交易借贷组合”和双模型分歧大的“L5用工运输组合”；这是试验建议，不自动重跑这两道。
2. 逐项表记录：Rubric ID、原权重、两模型得分与答案证据、业务结果、所需材料位置、是否只是复述／模板即可命中、是否确需跨材料推断。
3. 先排除评分错判、隐藏要求、输入未发送、技术故障、算术错误。能指出证据再认定设计缺陷。材料足够且模型答错属于有效失分，不返修题目来帮助模型。
4. 对真正容易的核心业务结果，说明增加哪一项材料支持的判断依赖、为什么影响法律选择、标准成果如何完整解出、Rubric如何独立评价。
5. 不仅按得分高低选改项。高分可能说明模型完成有效任务，低分也可能来自工具限制；是否值得加压看真实专业推理和判断量。

### 5.3 合法且可验证的加压方法

下表是设计建议，不能冒充项目方逐条强制要求。每项必须在本次真实脱敏材料中找到依据。

| 加压方法 | 怎样增加真实难度 | 成果与判据怎样接住 | 无效加压 |
| --- | --- | --- | --- |
| 非相邻材料交叉核验 | 结论必须结合不同文件、不同主体或不同期间的信息；识别证明范围和真实矛盾 | 正稿给出采信理由及出处，Rubric评价独立事实结论与证明链 | 仅增加页数、重复件或随机干扰 |
| 竞争解释与反驳 | 保留有材料支持的多种解释，要求选主路径并处理最强抗辩 | 给出主结论、对方最强论点、适用前提及替代路径；接受等效合法结论 | 强行规定唯一措辞或只认标答结论 |
| 法律要件与版本联动 | 基准日、合同／行为时间、法律生效时间共同决定适用版本及要件 | 标答完成时点和要件匹配，Q3评价法源、Q4评价事实代入 | 堆法条数量；用错误法条或事后材料陷阱压分 |
| 有意义的核算分支 | 不同请求权、证据采信或责任范围改变基数和结果，再影响程序／策略选择 | 同次计算的基数、公式、结果可整体评价，独立法律选择另设判据 | 把一条算式重复放进多个维度加扣分 |
| 约束下的方案选择 | 在实际预算、时限、权限、证明限制中比较合法方案并给出倾向 | 要求成本／风险／动作依赖和可执行条件，重视关键决策 | 增设材料没有的预算、期限、授权来制造无解 |
| 多案综合与差异判断 | 真正比较案件差异、优先级及共同政策；每案事实独立保持 | 标答有逐案判断和跨案决策；不得将一案事实移用另一案 | 多案分别摘要后简单拼接，假称已增加推理层数 |
| 不合理委托诉求处置 | 识别材料中真实的不可行或越界诉求，提供合法替代 | 按实际错误行为扣分，职业立场与安全底线分别正确处理 | 仅因没写某句话就触发违法或否决 |

### 5.4 本批场景如何具体落实

| 标签与场景 | 优先设计的复杂判断 | 可选成果（不是全部必交） |
| --- | --- | --- |
| L2 → LS02 | 冲突文书与证据证明范围、真实性／关联性／合法性、缺口对主张的具体影响 | 证据目录、阅卷笔录、质证意见或补强建议 |
| L3 → LS03 | 财产线索可信度、可保全范围、请求金额与标的／担保衔接、错误保全风险及行动顺序 | 调查报告、风险意见、保全申请、已有担保材料说明；不虚构已签发保函 |
| L4 → LS04 | 按真实可知时点形成争点、证据攻防、发问路径和突袭应对；反方回应如何改变下一步 | 庭审提纲、质证意见、关键证据摘要、攻防预案；历史庭审任务区分庭前与事后材料 |
| L5 → LS05 | 跨案／跨时期复盘，败诉风险分层、裁判规则可比性、代理意见与客户预期／资源安排的联动 | 复盘汇报、风险意见、代理意见、检索报告；多案组合须形成实际综合决策 |

等级材料量和必要业务人时按当前规则如实清点估算。合订PDF可能含多份独立文书；分页和PDF切片不新增文书。不能为证明L5编造100份材料、40小时或500步；同样不能把未核实的等级认证当作一切专业出题无法开展的理由。

### 5.5 不可牺牲的评分设计

- 必设维度1、2、5，从3／4／6／7至少选两个；维度2至少三个Q，保留主F的两个锚点、锚点正分≥30%、至少两条+10、Subjective条数≤10%。
- F1锚点Q3＋Q4；F2 Q2＋Q3；F3 Q1＋Q4；F4 Q4＋Q6；F5 Q1＋Q5。权重按实务影响分配，不把加长文字等同难度。
- 一条评价一个独立业务结果。同一计算的基数／公式／结果或同一法定动作的必要要素可整体判断；不得按句长机械拆条。
- 同一核心结果只有一个主计分位置；正项遗漏不能仅以反面措辞再扣分。独立否决与普通安全扣分分别处理，不自动归零。
- 本地代码当前要求一条 `R0-V01`；三类编造分别计数，“超过3处”的适用范围和普通错误区分。若需改变此实现，应先核验原文歧义，不将本地选择当作毫无歧义的官方规则。
- 每条判据自包含并接受等效合法方案。所有必交业务结果和评分义务在题面或必然职业要求中有依据；不泄露解题结论或评分清单。
- 按 [评分设计验收标准](评分设计验收标准.md) 给确认问题、优化建议和待核分别贴标签。不再使用已撤回的四题“不达标率”或80%本地放行线。

### 5.6 小规模验证与交付

建议先2道新测试题，问题定位并修正后再2道；保持同源材料、场景和所有模型／推理强度／超时／阈值可比。只改有证据支持的Skill设计方法或本题方向；改动前列出内容及传播范围，不悄悄同时改变评分宽严。新题必须产生新的作答、评分和判定绑定，旧分数不能继承。

每道记录：原型ID／新题ID、来源脱敏attempt／哈希、实际作者输入及Skill指纹、新增判断依赖、材料依据、标准求解可完成性、Rubric设计审查、双模型有效分数、技术与能力限制、最终decision。试验结束交付一张对比表，不能只报告“出题成功”。

完成标准：规范结构成立；核心业务任务没有减少；新增难点有材料依据、作者完整求解且判据独立；双模型真实有效结果能验证本地≤55%目标。若仍高于55%，记录未达标与根因，不再无上限自动重出。用户选双模型仅是当前本地回归口径，不能宣称项目方原三模型要求已完成。
