# Agent材料处理接入

适用于维护者。当前默认入口是材料库Agent任务，业务提示词从共用配置数据库读取，不要求人工逐页构造精确计划。

## 调用链

`POST /revisions/:id/jobs` → 每次读取数据库模板、系统Agent模型并冻结 → 既有agent消费池 → `agent-redaction.ts`整包限时生成语义计划 → `shared/agent-material-plan.ts`编译精确编辑/分册 → 原结构与覆盖校验 → 现有租约事务保存脱敏正文与prepared_documents。

原文来源、模板、模型和私有进度按摘要绑定。原始结构字段只在获准范围内变化；数值坐标由程序生成。工作流不新增可见步骤，不迁移表，不切换旧题来源。默认自然化名和法院保留；显式旧mask继续运行原API/字段映射协议。

每个任务最多10分钟，到限停止，不自动追加重试。原文和主体映射仅存私有目录；公开任务状态返回安全计数和错误码。`worker-once.ts <job-id>`用于受控验收，只消费指定的已入队本机Agent材料任务，并复用共享Agent槽位。

既有`prepared-redactions`与CLI手工计划导出/导入保留兼容，不再是默认自动流程的前置人工环节。各项目在建题时冻结成功结果；DOCX从同一prepared_documents生成，项目交付规范由对应交付模块管理。

## 验证边界

合成测试核对主体一致、同名范围、原文不变、法院/金额/日期保留、结构分册、来源防重、限时取消和配置重新读取。真实任务另检查全部正文覆盖、主体及材料分界、实际时长、存储结果及下游冻结来源。结构校验不证明所有未知身份已识别，只有真实执行后才能报告性能。
