# Siriser 内容稿生成

本目录管理 Work 项目内容稿五件套生成器与旧题目契约的成果提示词。旧契约由 `server/publishing/work-simulation.ts` 使用项目 Agent 配置生成带 AI 来源记录的内部成果；`work_legal_v1` 直接投影作者已冻结的成果与检索记录，不在归档时调用该 Agent。生成器由 `scripts/delivery.ts` 调用，固定提示词和模板只在旧契约生成路径中只读提供给 Agent。

| 文件 | 用途 | 维护边界 |
| --- | --- | --- |
| `模拟专家生成提示词.md` | 旧题目契约下，依据题面、Rubric 和冻结材料生成 AI 成果，并要求核验真实网页检索 | 仅旧契约使用；不虚构真人身份、检索行为或验收结果；修改后检查服务端输入文件清单与 `材料/交付规范.md` |
| `generate-five-piece.ts` | 旧兼容路径从归档成果组装初稿；新 `work_legal_v1` 路径把作者冻结成果与题目元数据投影为平台确认稿 | 新 Work 内容不重写作者成果，不把冻结检索记录描述为归档阶段新执行的检索 |
| `generate-five-piece.test.ts` | 验证新元数据完整投影和检索来源描述 | 单元测试不验证真实法律、文件排版或平台提交 |

归档生成的 Word、Excel、脱敏输入和 `golden_output/` 写在题目成果目录下的版本化内容包，不写回本目录。业务正本使用 `主成果.docx` 文件名，正文采用正常业务文书体例，不包含 AI 或模拟过程自述；AI 来源、模型和生成状态保存在独立的 `模拟生成记录.md` 及平台要求的来源字段中，不冒充真人专家成果。`golden_output/` 同时包含 Harbor 清单中的每一份实际交付文件和真实检索轨迹；Harbor 交付文件从同次生成的六件套 golden 原件复制，保持内容及文件格式一致。Harbor 六件套另由 `../harbor/` 管理。

## 平台确认稿生成契约

附件DOCX仅渲染文书内容，不再人为插入原附件页定位或识别提示段落；原页身份与issues仍保存在结构/私有索引中。此修改只影响重新生成的成果，不自动改写已归档ZIP。

新Work契约由`generateSiriserConfirmation`独立输出三JSON＋input_files＋golden_output的五件套及同名ZIP。Rubric平铺保留全部原始字段，包括Veto及累计规则；重新生成前要求完整Work题包至少30项，业务成果只接受DOCX/XLSX；复用出题模块的结构检查，核对题面必交名称、成果映射和evaluated_files。检查先于目录创建及缓存复用，失败不更新当前交付状态。历史包普通读取不重新校验。标准成果按作者声明格式生成，轨迹写`法规案例检索轨迹.xlsx`。不复制Harbor目录、不重写题面业务内容、不重新调用模型。旧`generateSiriserFivePiece`新生成同样检查数量、Office成果及评分引用；检索轨迹改为XLSX，新目录/状态后缀为office-v2，旧目录保留。它仍保留DOCX／XLSX初稿，支持直接生成成果，任务说明不混入Rubric。

ZIP生成后会验证本地与中央目录文件名一致，并将UTF-8标志写入两类ZIP头，避免接收端按CP437解码中文文件名。复用已有包时先校验冻结输入、目录清单和原ZIP摘要；只有摘要完全吻合才会原子修复文件名标志并同步ZIP摘要状态。

`document-boundaries.json`登记特定冻结脱敏文本SHA与人工整理的文书起止页；仅SHA匹配才分册，未知文本保持原附件。跨页连续文书保留完整，重复判决副本放同一分册，分册文件名带原附件／页码定位。生成器验证全部原页覆盖一次并保留字符范围，私有状态保存正文哈希与重建映射。该文件不含材料正文，不能用拆页、复制或新材料填充清单；分册数量只描述匹配该SHA的清单内容，不作为等级或实际工作量证明。

`Siriser五件套.json`位于成果目录外层，保存版本、ZIP及文件摘要和原文重建范围，不打入公开ZIP；`submission_ready=false`仅表示尚未外部验收。平台导入／导出实证见项目当前任务执行日志。目录命名中的署名默认采用用户已确认的杨政，日期采用上海当日；需要其他署名可通过生成函数options明确指定，不伪造名额认领码。

## input_files 原件与 DOCX

脱敏模式生成真正的 DOCX：发布模块传递经正文摘要和结构投影校验的脱敏结构，按冻结页段分册并保留标题、列表、表格、脚注样式和分页；历史无结构文本使用Markdown兼容渲染。它不读取或混入未脱敏原件。

新材料库原文模式走不同分支：服务端仅在冻结来源清单、题目内材料ID、原名及SHA一致且原件字节重新验SHA后，才把原始附件字节传入交付脚本。原始PDF直接写入 `input_files`，不转换成DOCX、不经AI。原件缺失、摘要不符、同名冲突或多逻辑附件关系不明确时归档失败关闭；不能回退成渲染文本并标成原件。交付脚本不直连数据库、不访问平台。每次渲染版本变更写入独立版本目录，保留旧ZIP供追溯；已归档ZIP不会被原地覆盖。

结构化确认稿的页段定位按结构投影时的实际字符偏移计算，不扫描正文中的同形“附件/原页”标记；防止合并卷内的引用文字被误当作外层页码。冻结正文与结构完整投影校验仍保留，不读取原件、不降级TXT、不改变分册覆盖规则。

底层deliverableBytes仍能读取历史TSV等格式；本项目新交付准入不允许将这些技术格式用作业务参考成果，不影响历史文件读取或脱敏输入DOCX格式。

Work业务DOCX通过现有渲染器的可选legal样式生成，正文宋体、标题黑色；附件默认样式不变。确认稿渲染身份为`siriser-confirmation-office-v7`，新目录隔离旧包，不覆盖历史ZIP。排版仍需渲染检查；Office结构校验不代替专业内容复核。

Work 的 Siriser 与 Harbor 业务成果共用 `deliverableBytes()`；XLSX 保留作者原有结构化工作表，并将完整正文逐行写入“正文说明”表，避免遗漏正文中的限定、计算依据和来源链接。
