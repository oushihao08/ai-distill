# 网页操作说明：题包上传与提交

核对依据：2026-10-17 本机工作台 API、Siriser“我的项目”回读及实际任务页操作。页面字段或项目状态更新时，以当前页面和该题回执为准；本说明不代表任何题目已通过平台验收。

## 先分清三个网页

| 页面 | 用途 | 完成标志 |
| --- | --- | --- |
| [Siriser 项目市场](https://www.siriser.com/siriser/market) | 选择正确等级项目、查看剩余名额、领取对应任务 | 项目进度中出现该题“进行中”记录及任务页入口。**领取不等于上传或提交。** |
| Siriser 标注任务页（通常从“我的项目 → 去回答”进入） | 上传五件套 ZIP、查看任务表单和 Agent 状态、正式提交 | 点“提交出题”后出现成功反馈，随后“我的项目”能回读该题为“验收中”并有题目 ID／提交时间。 |
| [题包编辑工具](https://www.siriser.com/siriser/projects/detail?id=640a9636-1875-4655-bd32-10d2cde61bee) | 导入、检查、导出题包 | 只表示编辑器处理完成；**不是**任务页上传或正式提交回执。 |

## 每道题照此操作

1. **先确认本地可提交。** 本机工作台中该题必须是当前版本 `accepted`，第 8 步归档成功；通过正常归档／下载入口取得这道题的五件套 ZIP。确认题目、L 等级和 LS 场景映射一致，`input_files/` 是本题脱敏 DOCX，ZIP 可正常打开，内容不串题。未达标、草稿、归档失败或版本不一致时不上传。
2. **领取匹配等级的任务。** 在市场选对应 L2/L4/L5 项目（本轮不做 L3），核对项目名称和剩余数后领取。不要把 L 等级当成 LS 场景编号；不要用其他题的进行中任务承载新题。除非明确需要，保持“提交后自动领取下一题”未选中。领取后记录平台题目 ID、subtask、等级及截止时间。
3. **打开实际任务页。** 从“我的项目 → 去回答”进入，确认标题、等级、状态和任务 ID 与本地待提交题匹配。不要只凭旧标签页或手工拼接的 URL 判断当前任务。
4. **上传五件套。** 在回答区的必填“五件套上传”控件选择 ZIP，等待文件名显示并出现已上传标记。只看见 ZIP 文件名说明附件已经挂到表单，仍不等于正式提交。
5. **检查 Agent 与页面提示。** 文件在本地已核验后，再按任务页入口运行“浏览”和“质检检查 agent”（如页面要求）。若 Agent 持续显示运行但无输出，不要无限等待；记录它仍在运行／已停止，按本地 ZIP 清单核对包。点击提交后若平台确认框说明警告不阻止提交，可在题包确已核对、且当前任务匹配时按已授权流程继续；警告及未执行状态必须照实留在回执里，不能写成 Agent 通过。若提示发现题包内容错误或任务不匹配，则返回处理，不提交。
6. **提交。** 核对当前任务、附件文件名和必填反馈后点击“提交出题”，完成页面确认。除非用户明确要求，不勾选自动领取下一题。等待成功提示，再打开“我的项目”回读状态、题目 ID 和提交时间。
7. **登记并留回执。** 确认平台已“验收中”后，生成单题回执，记本地 workflow ID、平台题目 ID、subtask、等级／场景、姓名、ZIP 文件名和 SHA-256、提交时间、平台状态；更新《场景领取码记录.md》。本轮已明确不做 L3；钉钉登记只写入当前允许登记的等级，L4 不冒填到 L3/L5 行。平台“验收中”不等于“验收通过”。

## 页面异常怎么判断

| 看到的现象 | 说明／动作 |
| --- | --- |
| ZIP 文件名和绿色勾 | 仅证明文件已附加到表单；继续检查题目和提交按钮状态。 |
| “浏览”Agent显示目录或文件列表 | 仅证明 Agent 执行并读取／生成了所示目录内容；不能代替上传包清单或提交成功回执。 |
| “质检检查agent：Agent模型配置有误” | 平台 Agent 配置异常；保存截图和错误，不写成题目失败或质检通过。检查页面是否另有真实阻断提示，再按任务页允许的流程处理。 |
| 题目仍为“进行中”或计数未变化 | 尚无可确认的正式提交记录。回到“我的项目”刷新并核对，不重复领取、不盲目二次提交。 |
| 状态为“验收中” | 正式提交已登记，等待平台验收；不能报告为验收通过。 |
| 输出目录只有 TXT／MD，或缺少题面、metadata、rubric、输入 DOCX、标准成果 | 五件套不完整；停止提交，回本地生成和归档链路检查。不能靠网页临时补文件掩盖生成问题。 |

### 调度优化（本轮实际执行）

1. 不按整批阶段等待；每题完成一个步骤，立即查该题当前版本 `workflow-status`，只派发下一个 `ready=true` 的步骤。
2. L4可运行步骤优先；L4暂时没有 ready 步骤时，用已有 `repair` 判定、且作者步骤允许重出的 L2 题填补空闲 Agent 槽。上游重出后旧答案／评分不复用。
3. 只在系统当前版本 `accepted` 且归档成功时生成／上传 ZIP。模型步骤未终结、草稿、repair、归档失败都不能通过页面操作绕过。
4. 不按理论并发数盲目重复派发；用 `/api/monitor` 的活动 attempt 明细加 `workflow-status` 校验。到17:07，原 L2 作答仍运行，新增3个 L2 作者 attempt 并行运行，活动明细4项。

### 网页实际操作顺序

1. 在 Siriser「项目市场」选正确 L 等级项目，核对项目名、等级和剩余名额；领取后记任务页身份。领取只占名额，不是上传。
2. 打开「我的项目」，进入对应项目的「去回答」；确认当前任务标题、L等级、任务 ID 与待上传题目相符。不要从旧标签页直接提交到别题任务。
3. 工作台第8步归档后取得本题 ZIP；本地确认 CRC、五件套结构、`input_files/*.docx` 和题目／等级／场景对应无误。
4. 在任务页必填「五件套上传」区上传 ZIP，等待文件名与绿色勾显示；这只证明表单已附加。
5. 查看右侧 Agent 状态。配置错误、未执行或输入不一致警告须如实记录；用本地 ZIP 清单核包。警告不阻止提交时，只能在任务匹配且本地包确认无误后继续，不能写成质检Agent通过。
6. 点击底部「提交出题」，按页面提示确认；提交后回「我的项目」刷新，核对新题目 ID、提交时间和“验收中”。若仍“进行中”或无新记录，视为未确认提交，不要重复点击或另占名额。
7. 将等级、场景、姓名、Siriser题目ID、subtask、ZIP文件名及 SHA-256、提交时间、平台状态与警告登记到《场景领取码记录.md》，并保存单题回执。钉钉登记按用户限定的等级范围填写。

页面及平台状态会变化；上述操作依据2026-10-17实际页面核对，后续以当前任务页提示和回读状态为准。
