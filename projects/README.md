# 出题项目目录与文件说明

每一期一个独立文件夹，统一位于 `/Users/jack/Documents/codes/lvgou/ai-distill/projects/`。项目规则、本地skill、案件附件和成果分别保存；九份规则资料不是九条题目工作流。

```text
projects/
├── README.md                         # 本文：各期通用的目录约定
└── 豆包高经济价值-第五期/             # 第一个项目；其他期次建立同级目录
    ├── README.md                     # 本期材料说明、标准摘要和未决问题
    ├── project.json                  # 项目登记清单、文件指纹和来源
    ├── materials/                    # 本项目出题、审查和评分使用的项目资料
    ├── updates/
    │   └── inbox/                    # 群消息原文及来源快照；未采纳，不进入出题规则包
    ├── skill/
    │   ├── SKILL.md                  # 本期出题/审查/返修/评分的入口
    │   ├── references/               # skill方法及评分、交付规则
    │   └── assets/                   # 原有Word模板等资源
    ├── questions/                    # 项目的案件材料根目录
    │   ├── 题目 1/                   # 一条工作流：项目ID＋题目目录标识
    │   │   ├── 附件-1.pdf
    │   │   └── 附件-2.pdf
    │   └── 题目 2/
    │       └── 卷宗.pdf
    ├── outputs/                      # 可选脱敏 DOCX 等项目成果，不作为题目输入
    │   └── README.md                 # 本期说明；生成文件默认不纳入 Git
    ├── snapshots/                    # 旧编号规则快照存档；新任务不读取
    └── reports/
        └── updates/                  # 群消息与当前规则的差异分析报告
```

树中的题目1/2是结构示例，本期没有凭空建立题目或案件附件。`questions/`中只放输入材料；成果放在其外，避免同步材料时把生成文件重新当成题目输入。全流程完成后可以手动导出当前脱敏 DOCX，详见项目 `outputs/README.md`。

## 本地文件与数据库的职责

| 内容 | 本地保存 | 数据库保存 |
| --- | --- | --- |
| 项目资料 | `materials/`原文 | 来源与适用说明；新任务按本次清单读取，不登记编号规则版本 |
| 群消息原文 | `updates/inbox/`本地来源快照 | 不写入任务输入，不自动作为出题依据；原文默认被 Git 忽略 |
| 更新分析报告 | `reports/updates/`逐次报告 | 与来源消息链接和发布时间对应；采纳后才修改`materials/`或`skill/` |
| 项目skill | `skill/`完整目录，含references/assets | 本地路径、关联项目；任务读取当前内容并记录本次文件指纹 |
| 案件附件 | `questions/题目 n/`来源文件，受管理副本单独存储 | 工作流、材料索引、数据库原文／脱敏文本及状态 |
| 产物与模型答案 | 产物文件；目标位置为本期`outputs/` | 文件索引、题目与 rubric 版本、答案及评分记录 |
| 执行过程 | 必要的执行日志/文件 | 排队、执行、返回结果、错误、尝试、返修历史及时间 |
| 模型设置与密钥 | 密钥只在受保护的凭证配置 | 模型设置及密钥引用；不在project.json、skill或文档写密钥 |

数据库仍是工作台状态的唯一依据。`project.json`是项目登记及来源清单，不承担运行调度，不和数据库同时维护两份任务状态。JSON中的评分标准摘要是草稿配置，发布前须核对相应原文。

`materials/`保存项目资料来源副本，但目录本身不证明每份材料仍然适用或具有同等权威性；按项目 README 中的来源性质、适用状态和未决事项使用。群消息先进入`updates/inbox/`，比对报告写入`reports/updates/`；只有负责人确认的更新才并入`materials/`或`skill/`。新任务扫描当前`materials/`和`skill/`并记录本次指纹；旧`rule_versions`和`snapshots/`仅作历史存档，不作为新任务输入。

## 第一个项目的实际状态

此前创建的`v1`、`v2`、`v3`规则快照保留在`snapshots/`供历史追溯；新任务不会读取它们或要求选择版本。正式提交资格等业务问题仍按项目 README 中的未决项判断。项目运行状态以工作台数据库为准，不依据本文件中的历史记录推定当前题目或任务状态。

当前执行器的受管理原件及工作流产物主要保存在`.storage/`。可选脱敏 DOCX 单独生成到本期`outputs/<题目目录标识>/`，不加入`questions/`扫描，也不改变步骤、尝试或发布状态。其他成果仍以各自接口和存储约定为准。

## 当前执行约定

1. **附件**：脱敏从数据库中的原始提取文本读取；出题、审查、模型作答和评分读取数据库中的脱敏附件，不以原始来源目录文件代替数据库正文。
2. **步骤提示词与项目skill**：出题、审查、评分读取对应步骤设置和当前项目本地资料／skill；每项任务记录输入文件指纹。模型作答只读取题面及允许的脱敏附件，不读取项目skill、rubric或标答。
3. **历史兼容**：旧编号规则快照和已保存的执行记录保留用于查看；新任务不创建、选择或校验 vN 规则绑定。

新增期次时建立同级目录，放入该期规则及独立skill，再在工作台创建项目，材料根目录填写该期`questions/`，本地skill填写该期`skill/`。不得直接继承第五期的50分门槛、8题上限、人工要求或交付格式；新一期以其实际规则为准。

## 清理边界
