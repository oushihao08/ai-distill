# 出题项目目录与文件说明

一个主项目可以包含多个期次；主项目级 `materials/` 和 `skill/` 跨期共用，每期单独保存题目来源、更新记录、成果和历史快照，并在数据库中保留独立工作流。推荐目录位于仓库 `projects/` 下。

```text
projects/
├── README.md                           # 本文：主项目与期次目录约定
└── 豆包高经济价值/                     # 主项目级共享资料与 skill
    ├── materials/                      # 跨期共用的项目规则资料
    ├── skill/                          # 跨期共用的出题 skill
    ├── 第五期/
    │   ├── project.json                # 本期登记与来源清单
    │   ├── outputs/                    # 本期本地成果
    │   ├── reports/updates/            # 本期规则更新分析
    │   ├── snapshots/                  # 本期历史规则快照
    │   ├── updates/inbox/              # 本期更新来源
    │   └── questions/                  # 本期案件材料根目录
    │       ├── 题目 1/                 # 一条独立工作流
    │       └── 题目 2/
    └── 第六期/
        └── questions/                  # 新期次自己的案件材料
```

树中的期次和题目仅为结构示例，不表示已创建目录或案件附件。`questions/`中只放输入材料；成果由工作台写入 `assets/out/附件库/<主项目>/<期数>/<题目>/`，不会进入题目扫描。当前工作流目录仍由数据库中的 `material_root` 指向实际来源位置。

## 豆包高经济价值当前状态

主项目共享规则资料和 skill 的规范路径分别为 `projects/豆包高经济价值/materials/` 与 `projects/豆包高经济价值/skill/`。第五期的题目、更新报告、成果和历史快照位于 `projects/豆包高经济价值/第五期/`。工作流 `material_root` 只指向 `第五期/questions/`；项目规则服务通过共享 skill 路径解析主项目 `materials/`，不会把规则资料当作案件附件扫描。迁移 `030_project_phase_skill_sharing.sql` 负责项目归组和共享 skill 绑定；`031_project_period_root.sql` 将第五期工作流来源路径切换到新题目目录，同时保留附件哈希和步骤状态。

## 本地文件与数据库的职责

| 内容 | 本地保存 | 数据库保存 |
| --- | --- | --- |
| 主项目规则资料 | `<主项目>/materials/`原文，跨期共用 | 当前项目适用说明；新任务按本次清单读取，不登记编号规则版本 |
| 群消息原文 | `<主项目>/<期数>/updates/inbox/`本地来源快照 | 不写入任务输入，不自动作为出题依据；原文默认被 Git 忽略 |
| 更新分析报告 | `<主项目>/<期数>/reports/updates/`逐次报告 | 与来源消息链接和发布时间对应；采纳后才修改主项目共享`materials/`或`skill/` |
| 主项目 skill | `<主项目>/skill/`完整目录，含 references/assets，跨期共用 | 期次工作流所属项目记录该共享路径；任务读取当前内容并记录本次文件指纹 |
| 案件附件 | `<主项目>/<期数>/questions/题目 n/`来源文件，受管理副本单独存储 | 每期独立工作流、材料索引、数据库原文／脱敏文本及状态 |
| 产物与模型答案 | `assets/out/附件库/<主项目>/<期数>/<题目>/`中的可选 DOCX；其他文件按各自接口约定 | 文件索引、题目与 rubric 版本、答案及评分记录 |
| 执行过程 | 必要的执行日志/文件 | 排队、执行、返回结果、错误、尝试、返修历史及时间 |
| 模型设置与密钥 | 密钥只在受保护的凭证配置 | 模型设置及密钥引用；不在project.json、skill或文档写密钥 |

数据库仍是工作台状态的唯一依据。`project.json`是项目登记及来源清单，不承担运行调度，不和数据库同时维护两份任务状态。JSON中的评分标准摘要是草稿配置，发布前须核对相应原文。

`<主项目>/materials/`保存跨期共享的规则资料来源副本，但目录本身不证明每份材料仍然适用或具有同等权威性；按主项目 README 中的来源性质、适用状态和未决事项使用。群消息先进入对应期次的`updates/inbox/`，比对报告写入该期的`reports/updates/`；只有负责人确认的更新才并入共享`materials/`或`skill/`。新任务扫描当前共享`materials/`和`skill/`并记录本次指纹；旧`rule_versions`和各期`snapshots/`仅作历史存档，不作为新任务输入。

## 第一个项目的实际状态

此前创建的`v1`、`v2`、`v3`规则快照保留在第五期目录的`snapshots/`供历史追溯；新任务不会读取它们或要求选择版本。正式提交资格等业务问题仍按项目 README 中的未决项判断。项目运行状态以工作台数据库为准，不依据本文件中的历史记录推定当前题目或任务状态。

当前执行器的受管理原件及工作流产物主要保存在`.storage/`。可选脱敏 DOCX 单独生成到 `assets/out/附件库/<主项目>/<期数>/<题目>/`，不加入 `questions/` 扫描，也不改变步骤、尝试或发布状态。旧目录中的文件和数据库路径由下载／重置兼容逻辑继续处理；代码不自动物理迁移历史文件。

## 当前执行约定

1. **附件**：脱敏从数据库中的原始提取文本读取；出题、审查、模型作答和评分读取数据库中的脱敏附件，不以原始来源目录文件代替数据库正文。
2. **步骤提示词与项目skill**：出题、审查、评分读取对应步骤设置和当前项目本地资料／skill；每项任务记录输入文件指纹。模型作答只读取题面及允许的脱敏附件，不读取项目skill、rubric或标答。
3. **历史兼容**：旧编号规则快照和已保存的执行记录保留用于查看；新任务不创建、选择或校验 vN 规则绑定。

新增期次时在主项目目录下建立 `<期数>/questions/`、`reports/updates/`、`updates/inbox/`、`outputs/` 和 `snapshots/`；在工作台创建期次工作流记录，主项目名称填写共享主项目名，期数填写当前期次。各期共用主项目 `materials/` 和 `skill/`；只有确属期次差异的记录放在期次目录。模型阈值、题目数量、人工要求和交付格式仍按每期实际规则设置，不因共享目录自动继承。

## 清理边界

此次按用户要求清空旧的`ai_distill`业务数据及`.storage/`管理副本，重建首个项目。保留数据库schema和迁移登记、源码、凭证配置与测试证据；不清理数据库其他schema，也不删除原始资料所在目录。工作台日常的“删除项目”仍是逻辑删除；本次明确要求的全量清空是一次性动作。
