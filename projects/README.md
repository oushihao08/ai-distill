# 出题项目目录与文件说明

一个主项目可以包含多个期次；主项目级 `materials/` 和 `skill/` 跨期共用，每期单独保存题目来源、更新记录、成果和历史快照，并在数据库中保留独立工作流。推荐目录位于仓库 `projects/` 下。

```text
projects/
├── README.md                           # 项目和期次目录约定
├── 豆包高经济价值-医疗/                # 医疗高经济价主项目；独立规则与出题 skill
│   ├── README.md                      # 项目边界、材料准入与验证状态
│   └── skill/                         # 医疗材料驱动的出题指引
├── 豆包高经济价值/                     # 主项目级共享资料与 skill
│   ├── materials/                      # 跨期共用规则资料
│   ├── skill/                          # 跨期共用出题 skill
│   ├── scripts/                        # 本项目脚本，按用途分组
│   │   ├── delivery.ts                 # 逐题归档入口
│   │   ├── ocr/                        # OCR 调查和核对
│   │   └── skill/                      # skill 候选验证
│   └── 第五期/
│       ├── questions/                  # 本期案件材料
│       ├── reports/updates/            # 规则更新分析
│       ├── snapshots/                  # 历史快照
│       └── updates/inbox/               # 更新来源
├── Skill Dependency/                   # 逐题 Skill 依赖项目，第一期使用全局材料库
│   ├── materials/                      # 项目规则输入；当前归档另存执行观察
│   ├── skill/                          # 作者出题 Skill
│   └── scripts/                        # 直交说明及项目转换边界
└── Work法律全场景/                     # Work 主项目
    ├── materials/                      # 共享项目规范
    ├── skill/                          # 共享出题 skill
    ├── scripts/                        # 本项目脚本，按交付用途分组
    │   ├── delivery.ts                 # 归档入口
    │   ├── harbor/                     # Harbor 导出和组包
    │   └── siriser/                    # Siriser 五件套生成
    └── 首批筹备/questions/             # 本批案件材料
```

树中的期次和题目仅为结构示例，不表示已创建目录或案件附件。`questions/`中只放输入材料；成果由工作台写入 `assets/out/附件库/<主项目>/<期数>/<题目>/`，不会进入题目扫描。`material_root` 指向实际来源位置。旧目录模式中子目录直接对应题目；旧项目内材料包模式先登记材料工作流再冻结脱敏结果建题。当前新期次使用全局材料库，通过本期加载关系选择脱敏结果或已提取原文版本建题，不依赖本期案件来源目录。题目快照位于工作台受管理存储，不回写本目录。

`豆包高经济价值-医疗/`是与法律项目隔离的主项目工作区，当前只维护医疗出题 Skill 与项目边界。患者原始材料只放在本地忽略的候选来源目录，不进入版本控制；经授权、去标识化并通过全局材料库入库的版本，由对应期次显式加载。

## 豆包高经济价值当前状态

主项目共享规则资料和 skill 的规范路径分别为 `projects/豆包高经济价值/materials/` 与 `projects/豆包高经济价值/skill/`。第五期的题目、更新报告、成果和历史快照位于 `projects/豆包高经济价值/第五期/`。工作流 `material_root` 只指向 `第五期/questions/`；项目规则服务通过共享 skill 路径解析主项目 `materials/`，不会把规则资料当作案件附件扫描。迁移 `030_project_phase_skill_sharing.sql` 负责项目归组和共享 skill 绑定；`031_project_period_root.sql` 将第五期工作流来源路径切换到新题目目录，同时保留附件哈希和步骤状态。

## 本地文件与数据库的职责

| 内容 | 本地保存 | 数据库保存 |
| --- | --- | --- |
| 主项目规则资料 | `<主项目>/materials/`原文，跨期共用 | 当前项目适用说明；新任务按本次清单读取，不登记编号规则版本 |
| 群消息原文 | `<主项目>/<期数>/updates/inbox/`本地来源快照 | 不写入任务输入，不自动作为出题依据；原文默认被 Git 忽略 |
| 更新分析报告 | `<主项目>/<期数>/reports/updates/`逐次报告 | 与来源消息链接和发布时间对应；采纳后才修改主项目共享`materials/`或`skill/` |
| 主项目 skill | `<主项目>/skill/`完整目录，含 references/assets，跨期共用 | 期次工作流所属项目记录该共享路径；任务读取当前内容并记录本次文件指纹 |
| 项目脚本 | `<主项目>/scripts/`，按用途分组；逐题归档入口固定为 `scripts/delivery.ts` | 归档尝试记录入口脚本摘要与执行结果；项目调查工具由主项目 `scripts/README.md` 索引，不放在题目附件或 skill 输入目录 |
| 案件附件 | `<主项目>/<期数>/questions/题目 n/`来源文件，受管理副本单独存储 | 每期独立工作流、材料索引、数据库原文／脱敏文本及状态 |
| 产物与模型答案 | `assets/out/附件库/<主项目>/<期数>/<题目>/`中的可选 DOCX；其他文件按各自接口约定 | 文件索引、题目与 rubric 版本、答案及评分记录 |
| 执行过程 | 必要的执行日志/文件 | 排队、执行、返回结果、错误、尝试、返修历史及时间 |
| 模型设置与密钥 | 密钥只在受保护的凭证配置 | 模型设置及密钥引用；不在project.json、skill或文档写密钥 |

数据库仍是工作台状态的唯一依据。`project.json`是项目登记及来源清单，不承担运行调度，不和数据库同时维护两份任务状态。JSON中的评分标准摘要是草稿配置，发布前须核对相应原文。

`<主项目>/materials/`保存跨期共享的规则资料来源副本，但目录本身不证明每份材料仍然适用或具有同等权威性；按主项目 README 中的来源性质、适用状态和未决事项使用。群消息先进入对应期次的`updates/inbox/`，比对报告写入该期的`reports/updates/`；只有负责人确认的更新才并入共享`materials/`或`skill/`。新任务扫描当前共享`materials/`和`skill/`并记录本次指纹；旧`rule_versions`和各期`snapshots/`仅作历史存档，不作为新任务输入。

## 第一个项目的实际状态

此前创建的`v1`、`v2`、`v3`规则快照保留在第五期目录的`snapshots/`供历史追溯；新任务不会读取它们或要求选择版本。正式提交资格等业务问题仍按项目 README 中的未决项判断。项目运行状态以工作台数据库为准，不依据本文件中的历史记录推定当前题目或任务状态。

当前执行器的受管理原件及工作流产物主要保存在`.storage/`。可选脱敏 DOCX 单独生成到 `assets/out/附件库/<主项目>/<期数>/<题目>/`，不加入 `questions/` 扫描，也不改变步骤、尝试或发布状态。旧目录中的文件和数据库路径由下载／重置兼容逻辑继续处理；代码不自动物理迁移历史文件。

## 当前执行约定

1. **附件**：脱敏读取已提取原文；共享材料题冻结建题时所选的脱敏或原文提取来源，后续出题、作答、评分和交付沿同一快照读取。旧目录题继续使用自己的脱敏附件；不拿当前来源目录替换题目冻结正文。
2. **步骤提示词与项目 Skill**：出题读取步骤设置和有效 Skill（期次覆盖优先，否则主项目路径），记录本次文件指纹。评分只接收同版题面、Rubric、匿名答案、对应来源附件和评分提示词，不读取项目 Skill 或作答思路；仅显式校准政策可提供标答。作答仅接收题面、允许附件、公开成果呈现约定和作答提示词，不读取项目 Skill、Rubric 或标答。
3. **历史兼容**：旧编号规则快照和已保存的执行记录保留用于查看；新任务不创建、选择或校验 vN 规则绑定。

新期次经主项目入口创建；共享材料库模式指定本期工作区并加载全局材料版本，不要求先建上述旧目录结构。旧目录模式按实际需要维护 `<期数>/questions/` 及更新/成果目录。主项目默认 `materials/` 与 `skill/` 共用；有效的期次工作区 `skill/SKILL.md` 可覆盖本期，采用本期候选不修改其他期次。模型阈值、题目数量、人工要求和交付格式仍按每期实际规则设置，不因共享目录自动继承。

## 材料库、使用记录与清理边界

全局材料包不属于某一期；`project_library_packages` 保存本期加载关系，`project_material_uses` 保存主项目跨期永久使用记录，`question_library_sources` 保存题目私有冻结来源。它们与 `project.json`、文件目录和旧材料工作流具有不同职责，不能互相替代。

本项目某期使用的材料不能在同一主项目后续期重复加载；其他主项目可按自己的使用记录加载。移除引用、删题或删期不释放材料占用。提交/退回返修需要真实依据，返修回原期，不通过新题 ID 绕过使用账。

日常删除项目、重置题目和材料引用移除分别遵守当前服务端接口，不从历史一次性清理记录推导日常权限。历史材料同步只导入入库/提取来源，不修改旧题、答案、评分或已提交成果。运行态以当前 API 为准。
