# 多案复盘与办案知识库出题

## 使用范围与输入

根据本次提供的裁判材料，设计一道供法律专业人员完成的知识库建设任务，让原始案件记录经过结构化复核，形成能用于后续办案的结论、审查动作及材料清单。你负责出题，不代替作答者完成任务。

先读取全部材料和本次要求，确定使用人、专项范围、材料集合、规则核验基准日及交付能力。案件数量、地区、法律领域、文件格式和篇幅由本次任务决定，不沿用示例中的固定值。材料不足以支持所要求的归纳时，说明缺口，不自行换案或编造案件。

## 设计任务

### 1. 明确材料全集与分析单位

在题面要求对范围内文件全量盘点，记录文件名、案号、法院、裁判日期、可读性和脱敏一致性。缺件和不能解析的文件仍登记并说明处理情况。

让作答者依据仲裁编号、双方分别起诉、并案、另案等原文建立程序关系和案件簇。分别保留文书、程序案件、实质纠纷、请求项的计数，不以文件数代替纠纷数。使用统一编号连接文件、案件、请求和成果。

### 2. 将案件记录拆成可复核数据

按材料所涉业务设置案件字段：主体身份、关键时间、法律关系、程序经过、主张与答辩、认定与裁判结果。明确区分当事人主张、答辩、证据记载、法院查明、法院说理和主文，不相互替代。

要求按最小可判断请求逐行记录提出方、请求内容、主张金额、处理方式和支持金额。将全部支持、部分支持、未支持、未作实体处理等分类的含义写入字段字典；按实际争议选择字段，不强塞无关请求类型。

涉及金额时，要求记录法院采用的基数、口径来源、期间、折算单位、公式与复算结果，逐项对照主文并列出差异。区分主张金额、认定基数、支持金额与实际履行金额；无履行资料时不得以裁判数额填作实付数额。

未知、未消除的记载冲突和计算差异分别标明，不能用零值、空白或自行补全掩盖。

### 3. 从逐案结果归纳条件与例外

围绕材料中的实质争点设置归纳任务。每项特点要求说明结论、支持案件、原文位置、成立条件及反例或例外。代表性案例应能说明裁判差异或审查细节，不能只列摘要。

要求形成“待证事实—举证责任方—所需材料—材料掌握方—缺失后果—审查动作”的对应关系，把证明责任转成可执行的取证和审查动作。

归纳对象限定为本次材料。不得仅凭选定样本推断整个地区、法院或所有同类案件的一般规律。此项是重建时增加的适用边界，不是对官方原题已有措施的认定。

### 4. 核验规范并转为办案工具

要求核验影响结论的规范原文，记录名称、条文、生效时间、版本和适用边界。规范范围根据本次材料确定。区分历史裁判所涉时点与面向今后办案的现行规则，不能用新法直接改写旧案结论。

根据实际流程设计材料准备清单，区分必需、可补及无法取得会承担风险的材料。落实取材顺序、程序节点、常见返工原因及适合复用的表格或文本。

网络和文件工具能力需按本次环境确认；不能联网时，所需规范应有可读来源，不能假设作答者拥有工具。时点分离与工具可用性是重建补充，不能据此倒推原作者做过检查。

### 5. 配套交付与一致性

按实际用途组织下列成果内容，可合并或拆分载体：

- 全量复盘台账：文件盘点、案件主表、请求明细、复算与差异、字段字典及统计。
- 审查与举证责任表：连接事实、责任、材料及具体审查动作。
- 特点分析报告：范围与方法、发现、依据、条件与例外、风险及办案建议。
- 材料准备与提效方案：清单、取材顺序、程序节点及返工处理。
- 代表性案例原文索引：关联案件、请求、原文位置与可复用动作。

各成果使用一致编号、事实分类和金额口径，使结论能回到具体请求及原文。仅使用获准的脱敏信息，不恢复身份。格式按用户要求和实际交付能力确定；文件数和字数不作为专业难度的证明。

## 出题交付与边界

交付任务名称、任务类型和完整题面；要求完整写明角色、材料范围、上述适用工作、成果及统一口径。行业和职业分类遵守本次提供的分类表。

若用户还要求 rubric、标答或系统七字段题包，按明确提供的独立规则完成，并标注为新增配套设计。来源案例没有展示这些内容，不能声称本 Skill 已复原官方计分标准，也不能仅凭任务清单保证低分、执行步数、耗时或平台通过。
