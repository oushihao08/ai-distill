# 官方法律服务优秀案例：可见出题模型拆解

适用范围：比较[法律服务优秀案例](https://bytedance.larkoffice.com/wiki/XzRuwLQ1sitJDWkYTrccayA7nWe)的可见题目包与本项目出题方法，提取可迁移的任务设计机制。读者是维护出题 Skill 的作者；本文不是新题附件、官方原始提示词或官方评分细则。

## 结论与证据边界

可见案例以15份劳动争议判决为输入，设计四组工作、五份文件成果、11个编号考点，另列严重错误及一票否决。题面还统一了文书、程序案件、实质纠纷和请求项等口径。这里能够还原的是**成品题包表现出的工作模型**，不能据此识别原作者使用的模型、提示词、生成流程或真实作答轨迹。未取得15份附件原件，亦未验证标准答案的全部事实与法律结论。

其核心不是文件数多，而是把原始记录逐层加工成后续办案可用的成果：每一层有明确分析单位、来源关系和下一步用途。该机制适合材料能够支撑多对象处理与成果复用的委托；单案题也可按实际业务单位设计较短的对应链，不强行改为判例知识库。

## 可见工作模型

| 层次 | 案例中的具体做法 | 真正增加的工作及下一步用途 |
| --- | --- | --- |
| 委托目的 | 为后续劳动案件准备建设知识库，减少律师反复取材和审查时间 | 先确定谁使用成果、用于什么决定，再选择需要沉淀的数据与审查动作 |
| 材料全集 | 15份判决逐份盘点，可读性、脱敏、缺件均登记 | 确定分析分母，防止只摘典型案例却声称全量复盘 |
| 分析单位 | 分开文书、程序案件、实质纠纷、诉讼请求项，识别互诉和并案关系 | 防止一案多文书重复计数；给统计、金额和案例索引同一身份依据 |
| 结构化底账 | 逐案提取主体、时间、诉辩、法院认定及结果；一项请求一行 | 把原文变成可回查、可比较、可复算的数据；保留主张、证据、认定、主文的层级 |
| 实质复核 | 对请求金额逐项确认基数、期间、公式和支持数，再与主文比对 | 差异和口径影响后面的规律判断，不能只抄判决汇总数 |
| 有条件归纳 | 裁判特点须说明案号与原文、成立条件、反例，另梳理举证责任 | 从个案抽取可复用判断，同时限制过度推广；把证明责任变为具体取材动作 |
| 规则校验与交付 | 核对现行规则及适用边界，交付台账、举证表、报告、材料清单、案例索引 | 旧案分析与今后办案分开；多个成果共享身份和金额口径，且服务不同使用动作 |

题面指定了工作对象、必要字段和成果格式，但没有直接告诉作答者每份材料应采信什么、复算差异是什么、哪些特点成立。其作答思路采用从盘点到成果复核的顺序，标准答案文字提供框架及核心结论；仅凭页面不能证明五份文件实际生成或可用。

## 难度来自哪里

1. **覆盖与身份关系**：先确定全集和业务单位，后面的分母、金额与归纳才有意义。读错案件簇会影响多处成果。
2. **中间结果被实际消费**：请求明细进入复算，复算差异影响分析，分析和法律核验进入材料清单与案例索引。跳过前项难以完整完成后项。
3. **判断与操作同时存在**：文件盘点、表格记录、计算、原文核验、跨成果核对均有可检查产物；但题面写了这些动作，不等于模型实际调用了工具或运行了更久。
4. **归纳须有适用边界**：结论需要支持样本、条件和反例，不允许把一份判决说成地区通例。

该题也有局限：大量指定字段、法律主题与五份固定文件可能使某些部分成为机械填表；报告篇幅和文件份数本身不证明专业难度。可见考点将若干用途不同的法律问题合列，另设一票否决；页面没有每项分值、部分分及总分公式，不能把这种计分方式移植为本项目规则。其标准答案文字是参考框架，不能代替对完整文件、材料原文和可执行性的独立核验。
