# 好题、判断难度与必要工作量

## 一、好题的判断标准

好题替代一项专业工作，成果能让具体使用者在截止时点作出决定。判断质量看四件事：依据是否充分、关键处理是否必经、结果是否影响行动、产物是否能核对。专业价值来自省下的必要工作和避免的实际损失；不能只靠专业词、篇幅或虚构工时证明。

难度发生在作答模型能看到的 prompt 和附件中。标答解释判断依据，rubric 检查结果；把标答写得复杂不会增加题目难度。材料必须足够让更强的专业承办人完成工作，不能把无法获得的关键输入当作难点。

真实业务用途和出题难度分别判断。公司名称、职位、审批会、预算或交易条件如是模拟题设，应清楚标注，不能作为真实采用的证明；这些条件仍可用于已获授权的内部题目设计。缺少真实采用证据时，照常完成用户要求的题面、标答与考点，并单独说明正式提交资格尚待核实。业务条件不足以支持具体决定时，只限制该决定，不否定卷内已确定的专业结论。

## 二、按业务用途构成完整任务

1. 确认使用者、截止时点、一个决定及触发动作，识别当前真正瓶颈。
2. 从决定倒推必要上下游：事实整理、证据采信、规则适用、核算、方案比较、办理及交接。只保留会改变决定或落地的环节。
3. 定义完整对象范围和交付用途。让必要对象逐项有结果，而不是只写总体意见。
4. 独立求解，记录关键依据、正确结果、常见错法、后续影响和考点。记录用于出题侧核对，不自动生成旁文件。
5. 将难点落进必须处理的原始记录，题面只布置业务工作及验收要求。
6. 同步成稿、标准成果和考点；检查不求解关键判断能否仍交出看似合格的答案。

这是一种出题侧组织方法，不要求作答模型按指定步骤执行。不把案例中的文件份数、难点数量或处理顺序当成所有题目的标准。

## 三、怎样考到 AI 的专业判断

| 判断机制 | 材料如何支持 | 错误怎样改变产物 |
| --- | --- | --- |
| 证据冲突 | 正式文件、草稿、豁免及撤销、原始记录、汇总表保留有效时间和权限依据 | 错采口径会改变金额、对象或办理决定 |
| 真正瓶颈 | 材料保留显眼指标，也给出决定实际受限条件及变化依据 | 选最高分却不能满足当前交付条件 |
| 同数不同口径 | 保留含税/未税、合同/实付、原币/折算、期间等原始定义 | 直接相加造成金额或边界错误 |
| 规则组合与例外 | 不同对象实际命中多项条件，规则给出覆盖和例外关系 | 单用一条规则或全局排序产生错误措施 |
| 时间与状态 | 截止时点、生效条件、批准与履行记录可定位 | 将待批、已开票或已裁判写成已批准、已到账 |
| 错误请求 | 业务方提出待评方案，材料能够逐项支持或推翻 | 顺从全部方案或全案否决都会遗漏有依据部分 |
| 正常安排被误判 | 有规则支持的空字段、引用条款或专用口径 | 模型为了保守将正常事项全部标风险 |
| 局部未知 | 明确缺失的是哪个必要输入，其他事项证据充分 | 为完成任务编造值，或把全案转为待核 |

选用当前业务真实需要的机制。冲突须有裁决依据；唯一结果须有完整输入。不要在 prompt 写“注意某记录重复”“不得直接平均”等解题提示，也不能隐去必需规则或数据使题无解。

## 四、怎样让 AI 完成更多必要思考

将复杂判断与实际工作量接在一起，而不是要求“多想一会儿”。长任务的每一部分应产生下一部分必需的结果。

| 增加必要工作的方法 | 题目必须提供的条件 | 可观察的完成证据 |
| --- | --- | --- |
| 保留不同来源的原始材料 | 数据、附注、版本及来源关系可读，不预整理成答案表 | 关键判断可指回原始记录 |
| 全对象处理 | 完整范围和合并排除规则可判断 | 明细覆盖全范围，汇总与明细一致 |
| 前后依赖 | 采信决定基数，基数进入核算，核算改变方案和办理 | 各阶段使用同一口径，无跳步猜数 |
| 条件变化后重算 | 改变条件确实影响规则或约束，输入齐全 | 受影响结果重新产生，不变项保持一致 |
| 不同用途交付 | 审批、底账、办理和交接各有必要用途 | 同一主体、金额、权限和状态跨产物一致 |
| 独立复核 | 有另一种可行算法或来源核对 | 差异回到源数据或规则纠正 |
| 实际求解或执行 | 任务确需，环境支持且作答任务有授权 | 实际命令、输出及可重复生成结果；未跑如实说明 |

必要处理可以由脚本高效完成，不能故意禁止合理工具、制造重复读取或让模型串行做本可并行的工作。工作量是否足够以实际 trace 和时长核验，不用文件数或预计轮次担保。

禁止靠消息条数、强制子代理、固定步骤、同内容多格式、百页报告或无关支线凑长度。材料扩大必须增加真实对象、规则分支或决策覆盖，而不只是复制记录。

## 五、从案例生成新题

按[案例模板集](../assets/案例模板集.docx)选择与当前业务相符的办理结构，替换角色、对象、实际规则、截止时点和产物。正例可迁移的是“材料可裁决、答案有条件分支、rubric 可逐项验”；不能复制案件事实、材料数量或历史得分。反例用于检查模拟买方的业务输入、审批用途和成果完整度，保留原卷可用的判断，不把模拟条件当成真实交易证明。先确认材料足够，再写 prompt。模板中“内部设计”“考点候选”不发给作答模型。

每道题另按[题目模板](../assets/题目模板.docx)形成完整成稿。模板集没有原始案例全卷、完整数据及可运行快照，不能直接作为已验证试题或标准答案。不得复制案例结论，再临时造材料证明它。

## 六、完成设计后的四项检查

- 可作答：每个确定结论有可定位依据，局部未知有边界，关键外部资料可在允许条件下取得。
- 必经判断：通用建议、摘要、全部拒绝或全部待核不能替代必要裁决；若能绕过，改任务依赖。
- 可评分：每个核心难点有独立结果考点，基础项比例合理，不重复处罚或限定唯一措辞。
- 可测评：输入、模式、版本及产物一致，按实际得分和执行证据分别核验正确率与长度。

逐项检查方式见[失败模式与自检清单](失败模式与自检清单.md)。出现题面、原件或rubric的来源范围冲突时，先修复题目有效性，不把无效考点算成模型错误。

本方法只依赖本 skill 内的规则、模板和案例复盘。个案法律结论须根据本次实际材料及适用规则求解；正反案例用于提炼判断机制，不作为当前任务的事实依据或资格证明。
