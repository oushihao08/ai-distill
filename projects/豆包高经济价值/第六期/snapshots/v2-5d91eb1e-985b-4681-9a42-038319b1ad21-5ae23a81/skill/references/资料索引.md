# 方法适用索引

本文件定位 skill 内已经提炼的执行方法。按当前题目的实际缺口选择，不要求每题凑齐全部类型。

设计完整任务及增加必要思考，先读[出题设计方法](出题设计方法.md)。需要具体办理结构时，按需选择[案例模板集](../assets/案例模板集.docx)中的多案卷、截止核算、多版本整改、证据裁决、决策瓶颈、规则交叉、局部未知或债权执行模板。

遇到事实或材料范围不一致、角色不属公司内部法务、评分根据摘要而非原件、rubric 要求与附件相反、模型原文缺失等情况，先用[失败模式与自检清单](失败模式与自检清单.md)确定是否可以继续成题或计分。

## 发现问题后如何处理

| 题目现象 | 应采用的方法与落点 | 修正后的可检查结果 |
| --- | --- | --- |
| 只让模型分析材料，说不清给谁用 | [题目格式与交付](题目格式与交付.md)重点1：业务决定与真正瓶颈 | 使用者、截止时点、待批准动作和下一步明确 |
| 材料很多，但都是摘要或重复计算 | [评分与难度验证](评分与难度验证.md)重点2：工作量与判断难度 | 必要对象分别处理，错误判断会改变后续结果 |
| 两份记录矛盾，只能猜或一律待核 | 题目格式与交付重点3：证据裁决 | 有材料支持采信，或将真实未知限制在对应步骤 |
| 模型沿用最新版本、把待批写成已批 | 题目格式与交付重点4：规则与状态联动 | 按权限、适用时点、条件和例外处理对象 |
| 报告方向正确，但漏对象或底账对不上 | 题目格式与交付重点5：对象覆盖与交付核对 | 每个范围内对象有结果，金额、主体、请求和状态可回对 |
| 模型一句“已考虑”就能拿分 | 评分与难度验证重点6：具体考点 | 通过与零分条件能定位到产物，合理替代仍能通过 |
| 分数低，却缺附件、输出或执行证据 | 评分与难度验证重点7：测评有效性与返修 | 分清环境问题、作答失误与题目缺陷，结论对应同版本证据 |

## 方法选用边界

- 材料外观不同不自动构成事实冲突；先核对内容、期间、对象和法律含义，再决定是否需要裁决。
- 时间轴可以部分确定；唯一结论必须有足够证据，不凭空认定某一日期是笔误。
- 合同名称、身份标签和付款通道不直接决定法律性质与义务；按条款、事实和适用依据判断。
- 原始债权、当前余额与预计受偿分别表达。履行先定抵充，再判断计息基数是否改变；不能把预计受偿写成确定承诺。
- 意见与待核事项按同一命题核对：已经确定的部分不能再次写成未知；同一事项的另一必要条件仍可待核。
- 看似异常但有规则支持的正常安排应保留；风险识别不能替代事实判断，全案否决不能替代局部裁决。
- 情景改变条件，从受影响节点重算；未受影响部分保留。情景不能直接给出采信或计算答案。
- 新增难点须同步调整考点覆盖；可核对结果有完整依据，脱敏缺口不靠猜数补齐。

## 默认要求与任务条件

本 skill 默认采用单轮任务、七章节成稿、15—20条0/1等权考点，以及得分率≤50%且满足执行步数≥50或运行时长>40分钟的难度目标。它们用于本工作流；用户明确改变目标时同步调整，不把默认值冒充全部外部项目的现行要求。

附件数量、记录规模、交付份数、情景数量与计算工具按真实必要工作确定。不要固定15份附件、三份交付物或某个难点数量，不要求模型按指定次数发消息。

用户授权的内部设计和返修可采用明确标注的模拟条件；模拟内容不能冒充附件事实或真实采用记录。正式提交资格依当次要求另核：完整标答、模拟公司和审批链、高工时估算或低模型得分不能替代实际用途与采用证据。外部项目对来源、制作方式和提交流程的限制，只在对应环节解释和适用，不自动阻止用户当前授权的本地返修。领取名额、平台状态、账号和提交动作属于当次操作条件，不构成出题方法，不自行推定或操作。
