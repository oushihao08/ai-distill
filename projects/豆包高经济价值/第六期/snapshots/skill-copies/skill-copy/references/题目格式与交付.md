# 题目格式与交付

## 题面

用业务使用者布置高强度专业工作的口吻写题。写清角色、背景、对象、条件和成果要求，充分展开工作：

- 分别回应待评主张、方案及反驳理由，定位决定性材料，说明依据之间如何支持、限制或冲突，并给出具体处理结论。
- 全面处理案件、主体、款项、期间和条款，表达合并、区分、排除及适用情况。
- 给出分项计算、期间、基数、公式、数值或条件表达式，并核对汇总关系。
- 比较方案并求解可接受条件；后续事件发生后，重新形成相关成果。
- 写出条款、请求、通知或办理交接的具体正文，保持主体、范围、条件和后果一致。

题目可以要求多项独立工作和多个成果，不限于单一决定或单一路径。题面可以限定核对领域、指定成果及要求说明依据；不要预先宣布材料存在某类错误、指定错误数量、采信方向或解决顺序。一个工作要求对应考点本身是正常设计，只有它透露待求结论或裁决线索时才构成提示。保留自行发现证据问题、选择规则和裁决争议的工作，不将详细任务缩减为泛泛意见。

| 工作布置 | 泄露判断线索 |
| --- | --- |
| 核对现有付款记录，确定已清偿范围，并在余额表及付款条款中落实 | 回单存在重复，必须去重；对账单余额错误，请以银行流水为准 |

区分原材料明确事实、必要业务条件和本题要求求出的结果。保留前两类，不把作者推算的日期、余额、责任范围或批准边界直接作为题设交给作答者。原文书明确记载的生效日、履行内容或其他事实不得为加难删改；是否需要计算或核对，按本题实际争点确定。

题面按实际使用者写明各份成果的用途与接收人，例如签批意见、可复核底账、付款或申请指令、替换条款及变化后的修订稿；这些都可在一份纯文本答案中分别呈现。要求给出可直接使用的金额口径、条件和文本，不以“另行制作”“待核后决定”代替已可完成的部分。不要逐一提示附件中的矛盾、错误数字和正确法律口径。

安排逐对象的办理决定与理由，让作答者自行区分可执行、附条件和受阻范围；不预告哪些对象属于哪类。变化情景说明发生的事实和时点，要求更新受影响的成果及其依据，不直接宣布原方案失效。

保留估值时点、有效计算约定、业务政策及模拟条件。事件时间、信息取得范围、计算端点及舍入按任务需要交代，不固定为每题栏位。内部测算确实采用不同口径时明示用途，分别处理对外权利；不能以模拟约定当然替代法定口径。法律存在合理争议时列可成立分支，作者尚未核实不等于法律有分支。题面不附作者检索所得的法律讲解、搜索链接或答案依据清单。

## 七项内容

| 内容 | 要求 |
| --- | --- |
| 表头 header | 题目 ID、一级行业、二级行业、任务形式、可见附件名称、L1 职业簇、L2 职业 |
| 任务名称 task_name | 具体专业工作名称 |
| 任务类型 task_type | 按实际工作填写，默认法务、合规与交易支持 |
| 题面 question | 完整角色、背景、条件、对象范围和具体工作要求 |
| 考点 rubric | 不同专业结果及其通过标准、对应错误或遗漏 |
| 作答思路 answer_approach | 依据取舍、规则适用、求解关系、争议及替代路径 |
| 标准答案 reference_answer | 完整回答全部要求，包括核算、比较、变化处理及实际文本 |

按当前任务指定的结构返回上述内容。内容为纯文本；表格、条款、请求和文书也在正文完整呈现，不要求生成 DOCX、XLSX 等文件。

## 表达与引用

行业、职业、角色和任务背景相互一致。公司法务任务以公司业务为背景；模拟公司、业务条件和履行情景明确标示为题设。

附件使用作答者可见名称或序号引用，序号对应实际正文。引用案号、日期、主体和金额时核对材料原文，脱敏保持原样。

题面不列出正确采信方向、陷阱位置、rubric 或解题步骤。标准答案用正式业务文书表达，完整呈现具体成果，不用“另拟申请”“制作明细”或文件名替代正文。

各项内容不出现数据库编号、本机路径、程序字段、模型成绩、AI 自述或出题流程。作者核验、考点必要依据和标答保留法律出处及争议说明；原附件的法条、条款和来源信息不因删除检索讲解而删改。题面保留完整事实边界、模拟假设和适用时点，不自动附作者的来源清单。
