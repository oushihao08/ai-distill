# 五字段表述方法

用于任务名称、prompt、rubric、作答思路、标准答案-文本的表达与保义核对。先完成题目设计和求解，再读[书面表达组合库](../assets/书面表达组合库.txt)选择组件；七项返回字段仍按[题目模版](../assets/题目模版.md)。本页规定选择与核对边界，具体写作资源统一放在组合库，不另维护一套重复菜单。

## 独立使用与组合规则

1. 先完成全部材料阅读、业务范围、任务、完整解及复合判据。按[语气与表达建议](../去%20ai%20化建议.md#写作前的表达定位)从已确定的内容识别委托关系、任务触发点、接收人、用途与信息关系。表达组件不能参与选题、决定难点或改变成果范围。
2. 以尚未作表达调整的内容为对照，根据委托触发点、信息关系、成果使用人和文种分别组织五个字段的起笔、展开、局部写法与收束。资源中的组件用于表达当前内容；已有关系决定合适写法，不根据题号、历史题目或组件顺序选择。
3. 同一字段可局部组合，但不要求每段都用多个方法。顺序、段落、语体和排版须改善该内容的理解；没有独立作用的标题不设。名称最后核定，不把全部文书拼成标题，不泄露待求结论。
4. 五字段各尽其责：名称辨识事项，题面布置工作，rubric明确判分，思路解释取舍，标答完整完成工作。它们可以对应同一专业事项，不复制同一目录和段落。内部工作链不强制变成“任务一至四”，法律文书必需体例保留。
5. 只使用本次输入完成表达设计。其他题目的正文不属于本题选择依据；有本次提供的同期白名单设计摘要时，必须核对业务目标、核心工作和成果用途的实质重复，只在材料支持的候选之间选择差异。该摘要不包含正文，不能据此宣称跨题文风已去重。

**表达、排版和文件格式均服务于题目。** 与材料真实性、单方服务、任务范围、难度、权限、精度、成果使用能力和评分标准冲突时，换表达组件，不调整专业工作来迁就写法。选择结果只供作者内部使用，不增加题包字段或作答者义务。

## 日常书面表达与载体

五字段的业务正文使用自然段、普通标题与编号、必要的业务表格和算式。按[组合库的书面规则](../assets/书面表达组合库.txt)去掉Markdown标记、代码块和程序教程；作答思路、标准答案采用日常工作意见、论证说明或适用的正式文书体例，不固定成一封信或“分析—清单—文书”目录。

需要文字文件时按既定用途选DOCX、TXT等办公载体；公式联动所需XLSX、固定版式所需PDF及实际读回检查继续按题目要求完成。不能用TXT替代必须可更新的表格，也不为表达差异改变已确定的文件能力或新增文件套餐。业务正文不交付.md或生成脚本；程序要求的结构化返回外壳按契约保存，不能因纯文本写法漏掉字段或破坏结构。

正文与内部说明明确分区。正式请求、条款、通知必须带齐限制其适用的条件，不能把条件移到说明区后留下无条件承诺。来源采用可核验的普通引注及网址，DOCX可使用正常超链接；不因去掉Markdown链接而删除依据。工具和编程可用于内部求解，业务交付呈现结果、必要公式及完整正文。

## 强度不变

- 题面的任务、对象、全部成果、权限、模拟标识、精度、检索、文件操作及检查义务逐项保留。“必须”不能改成“可以考虑”；专属条件紧邻对应成果写出，把可编辑文书、公式工作簿重算及业务联动试算、全套主报告＋对外文书＋横向适配附表的分页 PDF 导出与逐页转图版式校改、权威法规原文核对融入具体交付物段落中，严禁照抄 Skill 内部缩略术语，不在开头加“先详细规划”套话，不在首段堆砌“委托设定＋四连禁令”公式，不在结尾单挂统包式技术尾段，也不单独要求提交“交付回执”。不从思路或标答补入冲突位置、正确方向或解法。
- 按[交付规范](题目格式与交付.md#作答端检索依据与交叉核验)保留 100% 具体处理深度、文件可用性与逐页渲染核验要求；交接与受阻说明融入业务正文或呈批说明，表达调整绝不弱化任何文件生成、重算或版式检查义务。
- rubric的数量、边界、ID、分值、复合条件及其同时成立关系、例外、合法替代、验收证据和错误归属不因表达改变。子条件分行不产生部分分，不把必要条件改成示例，不把“且”改成“或”。严禁在 criterion 中出现“评分端”“轨迹未传”“评测条件不满足”“不作为有效专业难度成绩”“本条评价……”等内部评测流水线术语。
- 阅读稿用1、2、3等普通编号，结构化ID按契约保留；criterion不重复外层序号、分值标签或“全部满足”计分尾句。具体判据引导完整处理，区分决定性错误与非实质错漏。每题的整体失效条件只出现一次，融入最直接相关的那条 criterion 中（不固定放在末条末尾），按本案对象、行为及业务后果自然写出全题归零后果（如全题按零分计、整题不予计分等，不每题逐字复读同一固定句尾），不固定使用“一票否决”标题。XML只用于作者指令，不进入五字段业务正文。
- 思路保留决定性材料关系、证据取舍、规则及例外、必要计算理由和合法分支；写已完成的论证，不写通用操作计划。评分策略、批次比较、工具环境和作者自查不进入思路。
- 标答保留全部分析、核算、来源、分支、各阶段可用文书正文、工作簿表结构与活公式及争议异常项逐笔明细；首屏按本案主成果体例直接切入（正式对外文书前置、无信头直入结论、内部呈批签报或账表先行），严禁整批套用“意见书标题＋致／收件人＋办理基准日”三行信头。附件已有的大批量无争议原始记录按来源、笔数与小计归并引用，不逐行重抄。业务内容不能以生成脚本或未来制作指令代替；作答端运行能力缺口仅在会话收尾简短说明，不另写落盘说明文件，也不混入律师正文。未决事实要有具体影响及后续动作，已足够的部分直接完成。
- 连续续办的事件输入、时点边界、前后依赖、实际更新和有效版本属于实质工作。表达可按对象、来源、使用人或办理节点组合，不能压成一次改值测试、未来跟进建议或只有最终答案；组合库中的“已有阶段”包括题目已明确设计的模拟业务阶段，不限于原附件已发生的事件。
- 允许长短不齐、标题不对称和必要重复，不故意造错字、病句或口癖；事实、法律、计算及含义不得出现瑕疵。文风不另设评分条件，篇幅变短也不作为目标。

## 成稿复核

1. 对照设计方法中的内部任务盘点，核对表达前内容与最终五字段的职责、全部专业工作和任务强度。每项必要事实、成果、条件和判据都能双向定位，不因换结构丢失、扩大或降低。
2. 用完整正确解、表达凝练但内容充分的合法替代、缺少必要判断的近似答案及最终成果矛盾的答案，检查表达前后逐条判定一致；任一不同就恢复条件或重选写法。此项是作者静态核对，不冒充独立评分实测。
3. 核对五字段的组织是否由本案委托触发点、信息关系、论证推进和成果用途决定：检查 `task_name` 无对称“A与B”或“接管”扎堆，`question` 无首段四步套话与末尾统包技术段，`rubric` 无内部评测系统术语或同尾口号，`reference_answer` 无统一三行公文信头。能够脱离本案对象直接套用的段落，改为呈现决定性材料关系和具体使用动作；正式文书体例、法律术语和精确计分关系按业务要求保留。
4. 检查思路是否有本案的推导，标答是否有全部可用成果；去掉代码围栏、Markdown标题符号、生成脚本、模板选型和制作说明。保留正常编号、必要表格、业务公式、模拟披露和使用条件，不把业务内容误当机器痕迹删除。
5. 本次无法取得其他题的实际表达或文件执行证据时，如实限定核对范围。文字自然不证明人工原创、模型必然遵守、文件已生成或批次已经去重。

## 已有题目的保义改写

仅授权润色时，不启动重新选题或改变rubric。先列原有主体、事实、时点、金额、权限、材料范围、任务、成果、模拟条件、分支及每条判分关系；再据现有信息组合写法，保持必要性、否定、数量、精度和范围。

改写后逐项双向核对，新文须有原内容依据。不得把建议升级为义务，把不确定改成确定，把材料记载改成已认定事实，或将完整正文缩成待办清单。完整解、合法替代和各类缺失答案的判定必须保持一致。

原内容有歧义或矛盾、需要实质选择时，单列问题并按授权处理，不能借表达编辑自行裁决。只读字段时不声称已核验原附件；文字核对通过不等于新版本已完成作答、评分及交付。本文件不授权覆盖旧题、同步外部服务或复用旧评分。
