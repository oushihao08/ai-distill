## 一、任务与执行范围

- 根据本次附件，以律师或法务身份服务明确的一方，确定其眼下要办成的事，以及谁拿到成果才能继续办理。

- 本方也可以是委托专项复盘、尽调或知识库建设的律所、企业等单一服务对象；样本中的不同诉讼当事人只是分析对象，不因此变成同时代理多方。此类任务只在材料确能支持跨对象判断及后续使用时选用，不默认每题都是专项研究。

- 根据给定材料和已知委托确定服务对象与办理范围。场景有几项、相互如何关联，取决于当事人眼下需要办成什么。

- 随附摘要或目录可用来定位原件。涉及主体、权限、冲突或识别疑点，回到附件正文查证；仅凭摘要中的标签或缺失信息不能认定案件事实。

- 通读附件，寻找本方现实需要但摘要未列出的工作。按当前可查的证据确定服务立场、办理场景和必要成果。

## 二、先确认材料，再选择方向

按以下顺序决定任务，不从文书清单倒推或虚构案件：

- **附件正文 → 实际法律关系与当事人 → 所代表的一方 → 可成立的业务场景 → 具体专业问题 → 必要配套成果。**

| 要素 | 选择要求 |
| --- | --- |
| 材料 | 阅读正文，确认交易、争议、程序状态、证据和已有文书；文件名只辅助定位 |
| 作者设定的作答身份 | 律师／法务，服务本次明确的一方委托方；专项研究中区分委托方与样本案件当事人 |
| 非诉方向 | 按材料中的合同或业务关系确定一方身份，如出卖人／买受人、出租人／承租人；称谓不能跨关系随意替换 |
| 诉讼、仲裁、执行方向 | 根据实际程序和所代表主体确定原告／被告、申请人／被申请人、申请执行人／被执行人等身份 |
| 场景 | 必须有材料支持、真实服务目的及与阶段相符的办理条件 |
| 成果 | 由该方律师／法务制作或提出，具有该场景下的实际用途，内容与任务要求对应 |

- 同一主体可以随程序推进改变身份，例如从买受人、被告到被执行人；各身份必须指向同一服务主体，并有相应事实和时点依据。不能把不同阶段的称谓当作同时成立的当前身份。

- 诉讼、仲裁、执行方向可根据材料选择：原告、被告、第三人、案外人、申请人、被申请人、上诉人、被上诉人、申请执行人、被执行人、执行异议人、再审申请人，以及刑事被害人、刑事被告人、犯罪嫌疑人、自诉人、附带民事诉讼当事人等。律师担任辩护人时，明确被辩护的主体；不把律师职务误写成另一名委托方。

非诉方向按实际合同关系选择一方：

| 法律关系 | 材料可能支持的当事人身份 |
| --- | --- |
| 买卖 | 出卖人、买受人 |
| 供用电、水、气、热力 | 供应人、使用人 |
| 赠与 | 赠与人、受赠人 |
| 借款 | 贷款人或出借人、借款人 |
| 融资租赁 | 出租人（兼买受人）、承租人、出卖人 |
| 租赁 | 出租人、承租人 |
| 保理 | 保理人、应收账款债权人 |
| 承揽 | 承揽人、定作人 |
| 建设工程 | 发包人、承包人，以及有依据的总承包人、分包人、勘察人、设计人、施工人 |
| 技术开发、咨询、服务 | 委托人、受托人 |
| 技术转让、许可 | 让与人、受让人，或许可人、被许可人 |
| 运输 | 承运人、旅客，或托运人 |
| 保管 | 保管人、寄存人 |
| 仓储 | 保管人、存货人 |
| 委托、行纪、中介 | 按具体关系分别确定委托人及受托人、行纪人或中介人 |
| 物业服务 | 物业服务人、业主 |
| 合伙 | 合伙人 |
| 保证 | 保证人、债权人 |

- 以上是选择范围，不是指定本题存在这些关系；其他业务身份同样须由材料支持。

- “委托人”必须说明语境：律师服务的委托方不等于中介合同、委托合同中的当事人身份。同一称谓可以存在于不同关系，判断依据是正文中的法律关系和行为，不是关键词命中。

- 材料确有多个关联法律关系时可以分别处理；不得因为目录列有某类合同，就给材料新增该类合同关系。严禁用“模拟条件”“假定前提”把没有卷宗依据的材料改造成另一种业务或强加卷外事实。

## 三、五大类场景与成果候选

- 下表用于选择，不要求集齐所有场景或文书。场景内还须确定具体工作，不能只写大类名称。

| 大类 | 具体工作方向 | 配套成果候选 |
| --- | --- | --- |
| 律师接案 | 核实委托事项、评估接案风险与利益冲突、确定代理范围 | 接案笔录、诉讼或法律风险告知书、虚假诉讼风险告知、委托代理合同及风险告知书、案件分析报告、类案检索报告、利益冲突检索报告 |
| 诉讼／仲裁程序 | 起诉或应诉、举证质证、程序异议、庭审攻防、调解和上诉 | 起诉状、答辩状、反诉状、仲裁申请及答辩书、反请求申请书、保全申请书、调查取证申请书、管辖或仲裁协议效力异议书、证据目录及举证质证意见、代理词、庭审提纲、调解或和解协议、上诉状 |
| 审判监督程序 | 审查再审条件、提出再审申请、应对再审及审判监督 | 再审申请书、再审代理词、再审答辩意见或答辩状、审判监督申请书 |
| 执行程序 | 申请执行、调查财产、查封及解除、追加变更主体、分配、执行救济与和解履行 | 执行申请书、财产状况表或线索说明、追加或变更申请书、查封或解除查封申请书、参与分配申请书、分配方案异议书、执行行为或案外人异议申请书、执行异议之诉起诉状、以物抵债申请书、执行和解协议、恢复或撤回执行申请书、不予执行申请书 |
| 企业合规与风险防控（非诉） | 合同和交易审查、法律尽调、规章制度与专项合规建设 | 合同起草审查修订意见、律师函、法律意见书、规章制度审查意见、法律调研报告、新法速递、风险提示、尽调报告、交易文件及修订稿、权利义务梳理报告、合规识别与职责清单、合规手册、管理办法、专项指引 |

- 按材料和真实业务需要选择具体文书，候选不限于表中列举。某文书出现于一个大类，不表示其在其他有依据的场景中绝对禁用。

## 四、从当前委托选择办理场景

1. **识别有依据的委托方向。** 已明确客户、委托目的或办理时点的，先按这些条件界定范围。方向尚可选择时，按[律师材料—场景—交付物参考](../assets/法律垂类评测（材料-场景-交付物）参考.md)的领域索引对读相关实例。裁判和执行记录可能用于判后追索，也可能供他人评估自己将承担的责任，关键在于谁要据此作决定。
   - 同套诉讼/执行卷宗在真实执业中同样成立的委托形态包括：被告／被执行人／一般保证人／案外人应对与三性质证及错算反驳；一审败诉／不利判项上诉及改判调解区间测算；二审生效后再审事由审查、再审答辩或检察监督；历审／执行全流程程序瑕疵复盘与行为异议；针对拒执、虚假诉讼、合同诈骗或职务侵占线索的民刑交叉刑事控告与移送中止；基于原判未决权利提起的独立衍生新诉（债权人代位析产、股东出资责任、债权人撤销权、追偿权）；不良债权收购尽调或公司出资穿透＋章程决议多条款改定。
   - 选题必须由所附真实卷宗本身支撑，不强制按材料中最后发生的那一道文书推进，也不靠切换角色装作不同任务。
2. **选定可办工作。** 方向可选时，分别试办到本方能实际行动的位置。此刻还有哪项权利、义务或期限须独立处理？已办事项留下的凭据，又使哪项后续工作现在可以完成？选择能凭现有材料分别作出有实质后果的决定、且服务同一委托的方向。
   - 比较候选时，先把只能等外部回函、实收、立案或估值才会出现的结果划出。现在能发的核查请求、能定稿的条件条款保留；同一缺件衍生的多份预案只按当下能完成的判断衡量。对有竞争力的方向，拿卷内真实的一项难处理记录试办到可用结果，再看其余记录是否仍需不同取舍。选那些在今天已有材料上仍能查出、裁定或改成更多实事的方向。
   - 办理时点可选时，取卷内已有关键材料且尚有真实决定要作的节点。核清这个节点能办到哪里；遇到真实缺件，完成已具备前提的事项，写明其余工作等待何种凭据。
   - 识别相连的工作时，从具体行为追它的后果。同一付款可能进不同主体的账，同一事实在两种请求中可能只证明其中一项，等待一种处理结果时另一项权利可能到期。遇到这类关系，分别核清两端的前提，再决定本方应向谁采取什么行动。所列情形供识别关系；只有卷内一端成立的，按实际范围办。
   - 作者按接收人的正常职责，拿标答中的实际成果试办。律师接卷能否带齐材料提出已定请求，财务拿到核定结果能否辨认收款方与批准范围，客户拿到修改稿能否看出本次可以签哪一稿？按本案实际去向核对相应动作。若还需其自己作一遍核心法律判断、重拟关键条款或重新拼随件，补足相应成品。若尚缺送达或授权，交清今天能办的事项、下一步由谁凭什么启动，并由有权人保留决定。
   - 如已提供相近题目的业务摘要，盖住名称和数额，用其中的做法试办当前委托：哪份原件要另核，哪个决定会做错，哪位接收人无法照办？若仍可照用，比较现有材料是否支持另一项有独立后果的工作，把取舍简记在出题备忘录。只有原做法合适时按案办全。

- 组合不要求每个成果都串成单一依赖链，但不能把无关的接案、再审、执行或合规文书拼成全集。程序尚未发生时，不能把未来事件写成既成事实，也严禁通过设定“模拟律师”“模拟场景”“模拟于某日接办”“本题模拟”或虚构卷外来函强推无卷宗支撑的程序阶段。

- 组合场景须区分连续办理、条件触发和互斥备选。可以连续办理的，交代衔接关系；须满足前提才能办理的，按条件安排；不能同时采用的路径，要求比较、选择或分别形成备选方案，不要求同时实施。文书起草、备选准备与实际提交分别表述。

- 若一题采用多个场景，先确定各场景的必要专业工作，再确定共享与独立成果。同一文书确能服务多个场景时不重复生成，不按场景数量机械倍增文书；**同一委托下属于不同接收主体、不同法定程序文种或独立数据底稿的文件必须分件独立命名制作（严禁通过“合册或分册”把多份独立用途文书打包成一个 `.docx` 文件）**。

- 对卷宗横跨多个程序阶段、含在卷遗留文稿或存在前后记录冲突的场景，依[原卷跨阶段穿透与前手纠偏](出题设计方法.md#原卷跨阶段穿透与前手纠偏)组织深度核查与配套文书定稿。所有事实与凭证均须取自所附分件脱敏卷宗，不为增加阶段强行跨程序或编造卷外事件；履行、证据、送达、查控、分配、质证、刑事要件、公司出资及条款衔接均可作为穿透主线，不默认以金钱收付或判后追偿组织所有题。

## 五、材料、方向、场景与成果的匹配底线

必须同时满足：

- **法律关系相符**：买卖合同材料中的出卖人、买受人不得无依据地改为中介人、物业服务人等其他业务主体。相关合同确实并存时，分别说明依据与作用。
- **服务立场一致**：代表被告应诉，可以分析原告主张及其最强理由，但不能把代原告提出诉讼请求的起诉状作为本方交付成果。反诉等工作须按该方实际程序身份和条件判断。
- **程序与时点成立**：场景所需的裁判、送达、申请、执行等前提必须来自所附真实脱敏卷宗的原始文书记录，严禁为挑选文书虚构生效、败诉、履行事实或添加“模拟接办／模拟前提”。
- **逐场景的信息边界**：每个场景明确办理时点及当时可取得的信息。材料中的后续判决、执行结果等，不得自动作为较早场景的已知事实。事后复核可以使用后续材料，但须区分当时判断与事后评价，不向较早场景提前提供结果。
- **权限与文书用途相符**：只能制作或提出本方有权完成的法律服务成果；不得要求律师代法院作出裁判、代对方作出意思表示。
- **成果内容可完成**：缺少某项定稿的必要事实，说明由谁补取什么、取得后怎样办理，将现有凭据足以支持的判断和文稿先交齐。

## 六、配套交付与动态评分

- 按整体委托的独立业务用途确定必要成果，完整交付实质内容；不设文书数量下限，也不以份数证明难度。

- 每份成果必须有明确业务用途和实质正文；同一用途在不同办理节点产生的必要版本，应保留实际状态及修订，不能以用途相同删掉阶段成果。相同状态和内容仅换名、同一文书无用途拆成小文件、为凑数增添报告，不算有效扩展。

- 场景选定后，完整求解任务，再按[评分规范](评分与难度验证.md#考点)编写复合rubric：共同判断核心结论、决定性依据及成果可用性，次要错漏不自动否定结果；等权且不设固定条数，每题含案件化整体失效条件。简单核查纳入其支撑的结果，不按场景或文书数量拆合；同一判断跨成果不重复计分。难度落实于专业工作，合法替代正常成立。

## 七、形成实质差异

- 同一业务目标可以有不同办到底的办法。以收回余款为例，卷内若已有双方核定的结算及付款回单，争点可能是哪些款项已抵扣、剩余请求能否签发；若争议来自验收标准被改写，则要先核原约定和变更权限，落实到可援引的条款及验收异议。另一起案件若仍须核抵扣，就按那案的回单做完。不能只凭题名、案由或首份文书判断两道题是否雷同。

- 按接收人下一步要做的事组织正文。交法院的答辩请求可以与另一题同名；请求所指对象、承认范围和随件证据要在本案中成立。

- 选定核心考点后仍可调整它的落实方式。相同的签署权限问题，在草案待签时可能落实为改写授权条款，在对方已经据此索款时则可能落实为对具体请求的抗辩。两种做法各有前提，不能为制造差异假设合同已签或争议已起。

- 若只是调换文件顺序、改换抬头或另附一份重述同一结论的意见，沿原工作办理并据实描述。独立审批、递交或后续使用确有需要的正式文件仍须交齐。

## 八、Agent 的设计顺序与成稿核对

- 本节供作者操作，顺序只约束内部工作。使用[出题备忘录](出题设计方法.md#出题备忘录与灵感记录)保存和查回本题选择，沿用同一文件；题面的开头可随来件、交办方式和业务紧迫程度调整，标答按接收人会怎样使用成品组织。表达选项见[表述组合](../assets/题目模版.md#独立使用与组合规则)。

设计时在内部完成：

1. 从材料确定法律关系、当事人、阶段和可用信息。
2. 确定本次所服务的一方，参照律师场景表的相关方向，按[任务盘点](出题设计方法.md#任务盘点与范围确定)查全用户范围内有依据的可办工作，再比较场景并确定相容组合；不先用文书数量或单一资产类别限制任务。
3. 确定每个场景的具体问题、材料依据、权限、成果用途及后续使用动作；据此确定实际业务文件和验收证据。
4. 选择必要配套文书并完整求解，再编写题面、完整标准答案及逐项评分标准。
5. 核对方向、阶段、场景和每份成果是否一致；去掉不匹配、重复或无实际用途的工作，并检查材料中的待解决争议、所需计算和文书正文是否遗漏。

- 内部设计不作为作答者新增交付物，也不把法律结论、证据错误或正确路径提前写进题面。

- 成稿至少能回答：材料为什么支持这个身份？为什么现在能办理这个场景？每份文书替谁解决什么问题？组合场景为何相容？材料中的哪个差异会实际改变接手人的动作？
