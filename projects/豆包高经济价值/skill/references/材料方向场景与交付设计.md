## 一、任务与执行范围

- 根据本次附件，以律师／法务身份代表一方，设计单场景或多个关联场景的法律工作，并形成必要配套文书，测试模型在不同法律场景中的专业能力。

- 本方也可以是委托专项复盘、尽调或知识库建设的律所、企业等单一服务对象；样本中的不同诉讼当事人只是分析对象，不因此变成同时代理多方。此类任务只在材料确能支持跨对象判断及后续使用时选用，不默认每题都是专项研究。

- 一个材料包可以支持多种不同方向和场景。材料、代理主体、场景、交付成果必须相互匹配。按实际工作选择场景数量，不要求每题跨场景，也不固定场景组合。

- 本文件负责场景与成果设计。按所属项目规范执行出题深度、输入充分性、真实材料保护、公平评分、输出结构和交付格式；逐项根据本题要求编写评分标准。

- 出题输入若附带`material-scope.json`，用整包摘要、逐份摘要、类型和标签定位材料关系，用候选组合探索方向。实际提供的`notes`、未归类状态和技术提示用于定位需回正文核实的缺口、冲突或识别疑点；摘要缺失、未归类或技术警告本身不证明案件事实，也不自动成为考点。缺失字段不推断，整理记录数不等于案件数。完整阅读附件后，只有影响本题专业判断或成果的事项才纳入任务，不把内部字段或作者判断直接写进题面。

- 结合正文与辅助描述，检查候选组合之外是否还有本方委托需要、材料支持但尚未展开的独立工作，不只围绕摘要中的醒目争议或已标注疑点设计。整理数据不用于跳过或过滤附件，也不预选方向、场景或成果；材料数量和类型不直接决定题型。最终按附件正文核定方向、单方代理主体、场景及交付之间的匹配关系，材料不支持的组合不采用；无整理结果仍按正文完成设计。

## 二、先确认材料，再选择方向

按以下顺序决定任务，不从文书清单倒推或虚构案件：

- **附件正文 → 实际法律关系与当事人 → 所代表的一方 → 可成立的业务场景 → 具体专业问题 → 必要配套成果。**

| 要素 | 选择要求 |
| --- | --- |
| 材料 | 阅读正文，确认交易、争议、程序状态、证据和已有文书；文件名只辅助定位 |
| 作者设定的作答身份 | 律师／法务，服务本次明确的一方委托方；专项研究中区分委托方与样本案件当事人 |
| 非诉方向 | 按材料中的合同或业务关系确定一方身份，如出卖人／买受人、出租人／承租人；称谓不能跨关系随意替换 |
| 诉讼、仲裁、执行方向 | 根据实际程序和所代表主体确定原告／被告、申请人／被申请人、申请执行人／被执行人等身份 |
| 场景 | 必须有材料支持、真实服务目的及与阶段相符的办理条件 |
| 成果 | 由该方律师／法务制作或提出，具有该场景下的实际用途，内容与任务要求对应 |

- 同一主体可以随程序推进改变身份，例如从买受人、被告到被执行人；各身份必须指向同一服务主体，并有相应事实和时点依据。不能把不同阶段的称谓当作同时成立的当前身份。

- 诉讼、仲裁、执行方向可根据材料选择：原告、被告、第三人、案外人、申请人、被申请人、上诉人、被上诉人、申请执行人、被执行人、执行异议人、再审申请人，以及刑事被害人、刑事被告人、犯罪嫌疑人、自诉人、附带民事诉讼当事人等。律师担任辩护人时，明确被辩护的主体；不把律师职务误写成另一名委托方。

非诉方向按实际合同关系选择一方：

| 法律关系 | 材料可能支持的当事人身份 |
| --- | --- |
| 买卖 | 出卖人、买受人 |
| 供用电、水、气、热力 | 供应人、使用人 |
| 赠与 | 赠与人、受赠人 |
| 借款 | 贷款人或出借人、借款人 |
| 融资租赁 | 出租人（兼买受人）、承租人、出卖人 |
| 租赁 | 出租人、承租人 |
| 保理 | 保理人、应收账款债权人 |
| 承揽 | 承揽人、定作人 |
| 建设工程 | 发包人、承包人，以及有依据的总承包人、分包人、勘察人、设计人、施工人 |
| 技术开发、咨询、服务 | 委托人、受托人 |
| 技术转让、许可 | 让与人、受让人，或许可人、被许可人 |
| 运输 | 承运人、旅客，或托运人 |
| 保管 | 保管人、寄存人 |
| 仓储 | 保管人、存货人 |
| 委托、行纪、中介 | 按具体关系分别确定委托人及受托人、行纪人或中介人 |
| 物业服务 | 物业服务人、业主 |
| 合伙 | 合伙人 |
| 保证 | 保证人、债权人 |

- 以上是选择范围，不是指定本题存在这些关系；其他业务身份同样须由材料支持。

- “委托人”必须说明语境：律师服务的委托方不等于中介合同、委托合同中的当事人身份。同一称谓可以存在于不同关系，判断依据是正文中的法律关系和行为，不是关键词命中。

- 材料确有多个关联法律关系时可以分别处理；不得因为目录列有某类合同，就给材料新增该类合同关系。模拟条件仅在项目允许范围内明确披露，不能用来把没有依据的材料改造成另一种业务。

## 三、五大类场景与成果候选

- 需要具体方向时，按需查阅[专业律师的37项材料—场景—交付物参考](../assets/法律垂类评测（材料-场景-交付物）参考.md)。其中原表及补充建议均为可调整、非穷尽的参考；先依据本案确定适用条件，不按编号逐项办理。
- 下表用于选择，不要求集齐所有场景或文书。场景内还须确定具体工作，不能只写大类名称。

| 大类 | 具体工作方向 | 配套成果候选 |
| --- | --- | --- |
| 律师接案 | 核实委托事项、评估接案风险与利益冲突、确定代理范围 | 接案笔录、诉讼或法律风险告知书、虚假诉讼风险告知、委托代理合同及风险告知书、案件分析报告、类案检索报告、利益冲突检索报告 |
| 诉讼／仲裁程序 | 起诉或应诉、举证质证、程序异议、庭审攻防、调解和上诉 | 起诉状、答辩状、反诉状、仲裁申请及答辩书、反请求申请书、保全申请书、调查取证申请书、管辖或仲裁协议效力异议书、证据目录及举证质证意见、代理词、庭审提纲、调解或和解协议、上诉状 |
| 审判监督程序 | 审查再审条件、提出再审申请、应对再审及审判监督 | 再审申请书、再审代理词、再审答辩意见或答辩状、审判监督申请书 |
| 执行程序 | 申请执行、调查财产、查封及解除、追加变更主体、分配、执行救济与和解履行 | 执行申请书、财产状况表或线索说明、追加或变更申请书、查封或解除查封申请书、参与分配申请书、分配方案异议书、执行行为或案外人异议申请书、执行异议之诉起诉状、以物抵债申请书、执行和解协议、恢复或撤回执行申请书、不予执行申请书 |
| 企业合规与风险防控（非诉） | 合同和交易审查、法律尽调、规章制度与专项合规建设 | 合同起草审查修订意见、律师函、法律意见书、规章制度审查意见、法律调研报告、新法速递、风险提示、尽调报告、交易文件及修订稿、权利义务梳理报告、合规识别与职责清单、合规手册、管理办法、专项指引 |

- 按材料和真实业务需要选择具体文书，候选不限于表中列举。某文书出现于一个大类，不表示其在其他有依据的场景中绝对禁用。

非诉材料支持签署、交付、持续履行或整改时，按[实质工作选择](出题设计方法.md#按材料展开实质工作)展开条件落实与实施配套；有报告或合同并不自动触发全部后续流程。各项具体工作仍须有材料、单方职责和实际成果支持，不以本表的分类粒度限制材料可支持的工作。

## 四、一个材料包如何支持多种场景

区分三种情况：

1. **选题候选**：同一材料可支持多个不同方向和场景。Agent 先比较真实可办的工作，再按本次任务选择，不自动固定为材料中最后发生的程序。
2. **单题组合**：一次出题可以选择单场景或多个关联场景。组合场景应服务同一方，分别有实际问题和成果，并说明必要的时点、已知信息及衔接条件。
3. **独立任务**：用户明确要求分别设计不同场景任务时，各任务可以选择不同的一方；每个任务内部始终只代表一方。能否另建题目、再次使用材料，仍须处理项目的题目身份和使用记录约束，不能通过复制材料包绕过。

- 组合不要求每个成果都串成单一依赖链，但不能把无关的接案、再审、执行或合规文书拼成全集。程序尚未发生时，不能把未来事件写成既成事实；只有在允许且公开的条件下，才能安排相应阶段的模拟工作。

- 组合场景须区分连续办理、条件触发和互斥备选。可以连续办理的，交代衔接关系；须满足前提才能办理的，按条件安排；不能同时采用的路径，要求比较、选择或分别形成备选方案，不要求同时实施。文书起草、备选准备与实际提交分别表述。

- 若一题采用多个场景，先确定各场景的必要专业工作，再确定共享与独立成果。同一文书确能服务多个场景时不重复生成，不按场景数量机械倍增文书。

- 对成果投入使用后需要承接反馈或继续处理的场景，依[连续续办设计](出题设计方法.md#已有成果的连续续办)安排后续业务。可在同一场景内推进，不为增加阶段强行跨程序。事件从本包已有业务、待决关系和成果用途确定；履行、证据、程序、协商及实施反馈均可作为变化来源，不默认以金钱收付组织所有题。

## 五、材料、方向、场景与成果的匹配底线

必须同时满足：

- **法律关系相符**：买卖合同材料中的出卖人、买受人不得无依据地改为中介人、物业服务人等其他业务主体。相关合同确实并存时，分别说明依据与作用。
- **服务立场一致**：代表被告应诉，可以分析原告主张及其最强理由，但不能把代原告提出诉讼请求的起诉状作为本方交付成果。反诉等工作须按该方实际程序身份和条件判断。
- **程序与时点成立**：场景所需的裁判、送达、申请、执行等前提须来自材料或合规明示条件，不能为挑选文书虚构生效、败诉或履行事实。
- **逐场景的信息边界**：每个场景明确办理时点及当时可取得的信息。同一材料包中的后续判决、执行结果等，不得自动作为较早场景的已知事实。事后复核可以使用后续材料，但须区分当时判断与事后评价，不向较早场景提前提供结果。
- **权限与文书用途相符**：只能制作或提出本方有权完成的法律服务成果；不得要求律师代法院作出裁判、代对方作出意思表示。
- **成果内容可完成**：材料不足以形成完整文书时，选择其他有依据的工作，或依项目规则处理真实缺口；不能写空文书、以未来核查计划替代本应完成的判断。

## 六、配套交付与动态评分

- 按整体委托的独立业务用途确定必要成果，完整交付实质内容；不设文书数量下限，也不以份数证明难度。

- 一道多场景组合题围绕整体委托形成配套成果，不因增加场景机械增加成果。若拆为独立任务，各任务分别满足所采用的交付要求。

- 每份成果必须有不同的业务用途和实质正文。相同分析换名、同一文书拆成数个小文件、为凑数增添无必要报告，都不算有效扩展。

- 场景选定后，完整求解任务，再按[评分规范](评分与难度验证.md#考点)编写复合rubric：共同判断核心结论、决定性依据及成果可用性，次要错漏不自动否定结果；等权且不设固定条数，每题含案件化整体失效条件。简单核查纳入其支撑的结果，不按场景或文书数量拆合；同一判断跨成果不重复计分。难度落实于专业工作，合法替代正常成立。

## 七、形成实质差异

- 依据本包材料确定最能影响实际办理的关系，从代理立场、分析单位、专业处理、成果用途和后续动作中选择相互支持的一组设计。材料支持多条成立路径时，选择能够形成完整专业工作和可用成果的路径；每条路径均由本包独立成立。

- 任务的辨识度落在本案具体对象、决定性关系和成果使用动作中。名称、金额、案号和文书标题只承载已经确定的业务内容；核心判断、中间结果的用途及最终成果共同构成题目结构。

- 材料支持多个专业工作、成果用途或核验路径时，根据本次委托选择其中相容的关系并完整展开。表达组件仅在业务设计完成后用于呈现这些关系。没有其他题目的可见信息时，只完成本题的独立设计，不作跨题相似性判断。

- 保持材料真实和工作深度；不为覆盖五大类强行跨合同、换立场、拼场景，也不让所有题都使用相同的多场景组合。

## 八、Agent 的设计顺序与成稿核对

- 以下为内部设计与核对流程，不限制任务名称、题面、思路或标答的正文组织顺序。完成业务设计、求解和判据后再选择[表述组合](../assets/题目模版.md#独立使用与组合规则)；材料、场景、权限及成果等业务规则始终优先，不以选定组合为由改变规则。

设计时在内部完成：

1. 从材料确定法律关系、当事人、阶段和可用信息。
2. 选择本次服务的一方，按[任务盘点](出题设计方法.md#任务盘点与范围确定)查全用户范围内有依据的可办工作，再比较场景并确定相容组合；不先用文书数量或单一资产类别限制任务。
3. 确定每个场景的具体问题、材料依据、权限、成果用途及后续使用动作；据此确定实际业务文件和验收证据。
4. 选择必要配套文书并完整求解，再编写题面、完整标准答案及逐项评分标准。
5. 核对方向、阶段、场景和每份成果是否一致；去掉不匹配、重复或无实际用途的工作，并检查材料中的待解决争议、所需计算和文书正文是否遗漏。

- 内部设计不作为作答者新增交付物，也不把法律结论、证据错误或正确路径提前写进题面。

- 成稿至少能回答：材料为什么支持这个身份？为什么现在能办理这个场景？每份文书替谁解决什么问题？组合场景为何相容？不同任务的实质工作区别在哪里？

## 九、与所属 Skill 的配合

- 在所属 Skill 声明采用本规范的范围内，按本文件选择方向、单场景或多场景及配套成果，不因旧的单场景写法而自行禁止关联场景组合。角色固定为律师／法务代表一方；持续使用场景执行连续续办要求，其他加压方式按实际需要组合，不要求集齐核算、阈值或固定成果。

- 正式场景登记与题目中的具体业务工作分别处理：按实际字段和获准分类填写，不虚构多选字段或认领结果。一个主场景标签不自动禁止有依据的关联工作；正式认领明确限定工作范围时，在该范围内设计，存在不可调和冲突则报告具体冲突。
