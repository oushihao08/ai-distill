# 复合判断与出题设计

**用途：**供出题 Agent 确定本包待解决的高负荷专业工作与各项工作的真实办理关系，并将判断落实到可实际接手使用的独立业务文件与动态底稿。场景与身份边界见[场景规范](材料方向场景与交付设计.md)，判据编制见[评分规范](评分与难度验证.md)。本文件是作者内部设计方法，严禁将文中分类标题或内部术语照搬进题面。

---

## 找茬的对象

先确认办理时点、单方职责与成果用途，再通读全部所附分件卷宗：
- 逐份核清：谁生成记录、依据哪个事件、证明谁的什么事项、覆盖哪个期间，以及与其他记录如何印证或冲突。
- 严格区分：**提交者与生成者、独立原始证据与同源转述、单方主张与生效认定、权利成立与当前可执行状态**。
- 从材料支持的待办事项选题。核清哪些已确定，哪些需辨认、取舍或进一步办理。既判结论在相应时点作为输入；较早场景不使用后取得的信息，事后复核须明确用途。

## 任务盘点与范围确定

完整阅读整包材料后再定委托范围和成果形态。先让原件说明这次委托可以解决什么，再决定需要多少工作。

1. **从目标和事实两头试办**
   - 从本方要实现的结果倒推：哪些条件必须成立，谁需要据此作决定或采取行动？逐项用当时可取得的材料核实。证据改变了可实现的范围，就相应调整交办。时点可选时，按[办理场景选择](材料方向场景与交付设计.md#四从当前委托选择办理场景)比较各节点尚待解决的工作。
   - 再从材料往前追：这项事实除了支持已有判断，还使什么工作成为可能、受到限制或失去必要？涉及已经办过的事，核对其实际结果有没有被后续处理承接。没有结果记录时，先判断查清它会不会改变本方行动；只有会改变时，才办当前可行的核实工作。每得到一个结论，就将它用于受影响的下一项决定；能独立办的事项照常完成。
   - 再按[场景库](../assets/法律垂类评测（材料-场景-交付物）参考.md)的领域索引查主营及相邻事项。对可能漏掉的工作，回到原件核准触发事实，把它试做到具体接手人手里。少办会改变其决定、耽误其行动或使其重做专业判断，就纳入委托。需要等待反馈时，办完眼下有用途的部分；其余候选若超出授权、缺少前提或仅重复现有结果，就结束扩展。
2. **相容实质工作应选尽选，严禁塞入低依赖凑数项**
   - 参考行及表外由本包证据支持、同一委托方权限与时点相容、且具有独立业务用途的实质工作，均应纳入整体委托（不能只挑最省事的一项；排除某项须有超授权、时点互斥、缺核心输入或用途重复的具体依据，“篇幅已够”“便于套模板”不是排除理由）。
   - 判断每项工作时问：卷内哪份材料使这件事现在要办，哪位接收人缺了它会办不成什么？难点可以是证明不同要件、赶在权利消失前行动、审核付款权限、处理共同资源或核改条款。通用制度、无争议摘录与重复件不单列；必要的随件和手续即使不单独计分，仍须交付。
3. **按事实安排连续办理、并行工作与条件备办**
   - 从客户眼下要拍板的事倒查。前项结果决定后项时，沿卷内实际发生的节点逐项办到底：用当时可见的记录核准原处理，再以真实回执、补正要求、履行或修订记录确定哪些继续有效、哪些请求或条款须改。确有不同使用人的阶段成果分别保留；仅需当前定稿时直接交定稿。
   - 并行事项各按自己的期限、接收人和证据办结，有共同的资金、标的或授权时再合并校核。已知要取得何种答复但尚未取得的，做完当前能发起的工作，交清下一手凭何结果续办。互斥选择交有依据的建议和必要条件稿，不替客户同时采取相反行动。
   - 无复杂流水时，检查卷中待证事实、可取证途径、签署权限、期限及条款能否分别落实。例如两份记录结论相同，可能一份能证实履行、另一份仅能说明授权。用适合接手人使用的证据目录、庭审提纲、修订稿或配套材料落实判断；涉及真实核算时仍逐笔建表复算。
### 从原件确定试办方法

从一项会影响客户的专业判断入手。找到当时可用的原件，先解出本方在这个时点能办到什么程度，再依交付用途选能检出实质错误的办法。自问：如果这处判断错了，实际使用时哪里会露出来？直接从那里回查原始依据。若换掉触发事实，原先的办法已经验不出对错，就随材料改换。没有相关事实的设计当场舍弃；卷中出现参考库没有的工作，照实际办理和核验。

有些卷宗里，每项安排单看都合理，却不能一起兑现。这才需要分别核准各自条件，再找出共同受限的那一处。原安排办不成时，把仍然可行的改法代回原条件：有唯一可算界限就实算，卡在条款或证明范围就给可采用的文字或范围。须第三方同意的，办到本方能提出的条件，保留未获接受时仍可做的事。缺少决定性依据时，可以作出暂缓或限缩的专业决定。

有真实的后续记录改变原先判断，才依时点找出哪些旧内容失效，修到当下仍须使用的正文。只需当前稿时保留有效内容，直接交可用版本。卷内没有变化时，就在现状上办深：例如同一份记录足以证明收件却不足以证明验收，意见应落实到客户可以承认的事实范围；这件事本身即可检验，无须比较报价、重演阶段或假设新来件。

### 从前手留下的工作接着办

把已有成果原样交还客户，他还有什么办不成？核清前手实际完成到哪一步、哪些后果有凭据，再决定哪些内容可沿用、哪些必须改办。证据或授权只够支持暂缓时，给出当下的决定和重新考虑的条件。已经满足使用需要的事项到此为止。

有正在流转的原稿、已办一半的事务或待批支出时，挑卷中真正卡住办理的对象试做。依案情选择入口：

- **接手已经在办的事项。** 找到哪份只是拟稿，哪份已经递交、签署、退回或部分履行。以仍在使用的版本为起点，处理其中各个有独立后果的请求、承诺或待批事项。未发稿直接改到可签；已经递交且确须调整的，办到原收件人能识别哪项请求变了、依据与随件如何替换；已经签署的，先核变更权限、既有履行和是否须取得对方同意。仅替换电脑里的文件，能消除已经发生的对外后果吗？状态未明时，完成辨别版本、守住眼前期限所需的工作。
- **接手继续投入的决定。** 客户确实要决定是否再花钱，比较现实可选的做法，包括只做已具备条件的部分。分清已经取得的保障、新增办理能多取得什么、相应成本和等待的代价。缺估值、报价或优先负担时，从已知范围推到改变决定的条件，交出当下可批准的行动和应暂缓的支出。能算临界值才算；不把主张总额当作净收益，也不虚构报价或胜率。
- **处理对方已经提出的障碍。** 将真实的退件理由、拒付项目或返稿条件对回原件。现有材料能解决的，办到可再次递交、可向对方回复或可在庭上使用的正文与凭据；一时解决不了的，核定其余部分能否先办。尤其要查接受一处修改是否一并放掉其他权利。卷中没有答复时，不代相对人表示接受。

回到客户一侧交代手头已有的东西、谁在等决定、决定之后要拿结果办什么。只选会改变本案动作的工作，不统一增交对照表、预算书或取证函。

### 出题备忘录与灵感记录

以本次题目 ID 保存并使用一份私有 JSON 备忘录。把题目提示给出的 `input/delivery.json` 绝对路径传给 [memo_path.py](../assets/memo_path.py) 的 `current <delivery.json路径>`，按返回路径写入，并在 `question_id` 中保留原样题号。重出时用本次备忘录。

1. **通读并试办后写第一稿。** JSON 沿用 `question_id`、`委托目标`、`设计想法`。目标写明此时谁要拿成品做什么、能办到哪一步。想法数组按案情记短条：点出原件及可查位置、由它引出的办理选择、办完后交给谁用。对决定选题的想法，用该条已有的原件位置和预期结果说明怎样看出办对或办错；可直接核实的到此即止。能从不同材料看出别的可办方向，也在此暂记。来源尚待核实的注明缺口。只记选择及依据。
2. **起草时确定真正采纳的工作。** 在原 JSON 的“设计想法”中区分采纳、并入或舍弃。对采纳项各记一件能独立办成的事：由哪处原件引出，谁等着用什么结果，交到什么程度才能接着办，以及在成品哪里能看出确实动了手。委托人首先要解决的事从“委托目标”中认定。同一判断的多份转写归在一起；写在同一文件里、却可分别办成或落空的事情分开。未取得的外部反馈只记当下能办到的程度。原件推翻设想时改记依据；舍弃项留在私有记录中。
3. **从公开成稿回查每一件交办。** 先单读最终题面，写下客户要律师办成哪些事，再按题目 ID 打开私有 JSON。在每个采纳项旁摘录能交代这项工作的题面原句，对照标答的实际结果。试着省掉这项独立结果：若仍可完整回应所引原句，或只能指出附件、考点、文件名，回到题面写清客户要处理的范围或等着用的结果，再回读原句。同一句能交办相连事项即可共引。支撑一个结果的隐蔽事实和中间推理留在卷内，无须逐项提示。用[加压检查](评分与难度验证.md#加压检查)核对复合考点。采纳项随本次成题定下，回查记录只留在私有备忘录。

备忘录供作者使用。交给作答者的题面和附件只包含委托所需内容；成题摘要概括实际采用的工作与用途。事后在仓库根目录用 `python3 projects/豆包高经济价值/skill/assets/memo_path.py find .storage '题目ID'` 查回。可用原样题号、完整工作流 UUID 或导出文件夹末尾的八位短 ID；同题多次出题会分别返回路径，短 ID 重名用完整 UUID 查询。

选定核心考点后，用[书面表达组合库](../assets/书面表达组合库.txt)第七节检查本卷支持怎样的办理形态。先按该形态求出客户需要的实际结果，再反写客户交办与考点。若换个文种仍可原封不动交同一份答案，应归入表达变化。

### 每项工作与各阶段材料完整交付

- **按真实接收主体与用途分件独立命名**：需要独立签署、递交立案、报审拍板或持续动态复算的成果，分别独立命名；题面按[交付规范](题目格式与交付.md#工作要求与答案提示的边界连标题都不泄底)区分已定文种与须由承办人决定的去向及配件，明确要求交付可编辑文稿（`.docx`）、动态活公式底表（`.xlsx`）或版式定稿（`.pdf`）。**严禁以“合册或分册”允许把不同用途文书塞进单一文档，严禁以“在回复中分件列出全文即可”或“无须上网、制作文件”放行纯聊天文本交卷，也严禁把必要明细或对外文书省并进一份笼统意见书**。
- **核对客户所求与证据能支持的范围。** 按本次委托中会改变行动的请求，找出必须成立的事实，核谁承担证明责任或由谁确认履行条件。核对支持记录、反向记录及其他已在卷的证明途径。能全办就办全；只能支持一部分，就把对象、金额或条款限到有据范围。确有事实缺口时，指明要证明哪一点、何人掌握哪项可取得的记录、怎样依法取得，以及取得或未取得时分别改动哪项主张。等待会耽误另一项权利的，先完成可独立办理的动作。若障碍在授权、约定或法律条件，说明可行的授权、改约或替代路径；无可行路径的，直接向客户说明原因。资料已经充足的不另列补证清单；不得把取得新证据写成已经满足实体条件或保证结果。
- **作者文本标答与作答端文件**：题面按用途交办实体文件。作者在 `reference_answer` 直接写可用的文书及必要随件，涉及工作簿，先逐项实算，再把凭据、核算过程、差额的处理及其对办理的影响写入正文。接手人需要逐项执行付款、提交证据或提出异议时，逐项给出能直接复制使用的数据和对应计算或认定。只有原明细可准确定位、原样沿用且接手人无需再筛选、分类或判断时，才可按来源、范围、笔数和小计归并引用。

### 按材料展开实质工作

对盘点出的未决问题，按下表匹配所附卷宗内的真实可见文书展开处理（四类可单独或组合成立，不作固定阶段目录）：

| 工作与触发输入（均须真实存在于所附脱敏卷宗） | 作者先求解的专业处理 | 题目应要求作答者实际完成的独立成果 |
| --- | --- | --- |
| **纠偏或重构在卷既有文书**：卷内已有原执行申请、多版拟议起诉状、财产控制表、合同草案、和解协议或结算单，需审查能否沿用或重拟 | 对照卷内裁判、回单、登记、送达回证等原始依据逐处核查既有文书的主张、范围、管辖、主体和计算；区分可保留、须纠偏及因缺证暂留空的边界，测算局部纠偏对关联请求与数额的连锁影响 | 依审查结果决定沿用、改定或停用。可改的交完整修订稿；不应再用的把停用版本、受影响事项和当前替代动作落实到经办人手中。当前无需替换稿时保留停用指令。需谈判审改又需送签时，就同一实质修改分别保留对方可核对的修订痕迹和供签署的清洁稿 |
| **回应在卷对立主张**：卷内已有对方起诉状、上诉状、异议书、造价鉴定/审计报告、结算主张或抗辩笔录，需本方正面攻防 | 还原对方实际请求与证据链，核查证明范围、鉴定计价方法与适用要件；结合本方在卷反证分别锁定应承认、可推翻及待补证调取的范围，识别专业机构鉴定边界与法律质证边界 | 先核该主张正在何处被使用。仅在付款审批中的，改准审批范围并标明可用凭据；须在审理中回应的，将相应认可、异议或请求写进实际递交或庭上使用的文书。计价须逐笔重算时交可复算的底账 |
| **处理共同约束下的关联对象**：卷内并存多项权利、多处查控财产、多名责任主体或多笔混同流水，受资金、顺位、权限、除斥期共同制约 | 逐对象核定成立依据、优先顺位、已执结扣减、部分履行状态与排斥关系，求出共同约束下维护委托人最大合法利益的可行组合 | 逐对象把准许与暂缓的范围落实到收件人能用的成果。财务要分批放行就改准付款指令；已到分配异议程序才形成相应请求。涉及多笔扣减、共同余额或分配顺位需随输入重算时，配套交付联动 `.xlsx` |
| **定制交易、治理或和解条款**：卷内现有合同、章程、决议或履行基础明确，需针对暴露冲突起草或靶向修订正式条款 | 测算现有条款对权利保留、违约触发、表决权限、出资期限、清偿抵充或担保脱保的实际后果，求出权限内的最优安排与待授权事项（严禁凭空捏造卷外谈判轮次或对方来函） | 优先改妥正在流转的文本；新决议或补充协议仅在现有文件无法完成该事项且具备权限时起草。若另有批准者需要比较方案，给他可据以决定的说明；对外稿保留真实生效条件 |

## 材料到成果的工作链

逐项核验办理关系：单独成立的工作验收到其接收人可以使用；前项改变后项的，核到具体请求、条款或金额；几个对象争用同一标的或授权的，核整体能否同时执行。
- **检查遗漏**：先把一项成果拿走。其余结论即使全对，谁会错过期限、缺少签发依据、不能举证或无法交接？有具体后果就把该项办足；移除后仍能完整办理、也未失去独立用途的，合并重复内容。
- **跨成果统一口径**：主体和案号回到同一原件，金额回到同一组成和截止日。引用另一份成果的结论时，核对它的适用条件。有逐笔取舍、参数变化或下游复算用途时，共用工作簿中的输入和公式；同一认定在不同程序下用法有别的，在各自成果中交清差别。

## 成果使用与办理交接

以接收人在授权范围内拿到文件即可直接审签、递交、复算或谈判为完成标准（融入对应审查意见、备忘录或底稿说明中，不统一单列“执行清单”文件）：
- 从递件、举证、签发或交割反推随件。原件由谁保管，哪些材料可调取、需签字或须随哪份正文提交？有独立用途的证据目录、异议对照、授权文本、交割指令等，按本卷内容做成可使用文件。卷内已有的凭据准确指向或按实际用途选编，不重制原件。
- 若用户要把证据实际带到庭上、递给窗口或用于主张合同权利，且作答者可取得相应文件副本，做到该收件人可直接核对。按主张选编现有材料，保留足以正确理解的上下文，并核对目录、正文引用与实际随件相符。遵守相应披露义务，区分应交材料、仅供内部审阅的资料和仍待取得的证明。保持来源文件完整，在副本上办理。只有文字摘录或目录时，准确标明能提供的内容及应调材料，不制作貌似原件的影像。
- 区分法定不变期间（上诉期、再审期、异议期、除斥期、优先受偿权行使期）、指定期间与工作安排节点；起算事实在卷未载明时写清向谁查何凭据、核实后怎样确定届满日；有持续复算用途时在工作簿中保留条件公式，绝不编造送达日或当地法院口径。
- 写清接手人需要留取的送达、收讫、付款或验收凭据。卷内已有反馈的，据此完成续办；等待中的说明谁核实、何种反馈改变哪项请求或条款、等待期间哪些事仍可办。签署、发出、递交和权利处分遵守实际授权。

## 原卷跨阶段穿透与前手纠偏

严格立足所附真实脱敏卷宗自身的原始文书结构设计深度，严禁人为切分虚拟取阅窗口或编造卷外补件：
- **跨程序阶段核对原卷**：沿影响委托的事项比较前后文书。例如执行反馈记载已冻结，后来的扣款回单只覆盖部分金额，先辨明冻结与实际受偿，再核该改哪项申请、保留多少债权。若后件只改变签发权限，就落实到落款和审批，不据此另造算表。确有多笔扣减、分配或期限需后续复算时，完成动态工作簿及受影响的正式文书。
- **同一阶段存在多源冲突**：对多版条款、主张、收付款或出资记录，核实原件的先后、效力与证明范围，逐项处理影响委托的差异。授权分歧落实到可签文字，计价分歧落到可复核金额。只有结果取决于法律变更时，另核相应行为的时际适用。

1. **输入 100% 源于在卷真实文书**：严禁将同一卷宗切分为“某日先收一批、某日再补一批”的虚拟双窗口，严禁要求保留虚拟“初办版＋补件更新版”，严禁编造卷外来函、登记回件、补充协议或待审草稿。
2. **严禁任何模拟包装**：题面严禁出现“模拟律师”“模拟场景”“模拟委托”“按模拟于某日接办”“本题模拟”“办理演练”“假定……”“题设前提”等字样。统一核算截止日直接指明具体年月日或锚定在卷客观文书节点；卷内未记载后续清偿或送达状态的，作为真实证据缺口按现有凭证核定并列明待核边界，严禁写“假定截至某日无新增清偿”。
3. **题面不预告尚待求解的结论（以下只约束作者另写的提示，原始业务文书完整保留）**：
   - ① **禁在书名号标题中泄露待裁决路径**：当采用何种救济程序、案由或请求权基础本身属于本题核心待决判断时（如应提代位析产、债权人撤销权、执行异议之诉还是追加被执行人），按客户目的交办，承办人求解后再确定收件人和文种。只有程序已定而待解事项更窄时，才点名已知文种；文件名同样保留待办判断；
   - ② **禁在题面括号或子项喂备选实体路径与结论**：严禁提前点名替代请求权、除斥期间类型或明示“不得直接启用某诉请”；
   - ③ **禁提示跨时际修法与顺延坐标**：严禁提示“跨某年修法前后规则变化”“某年新施行司法解释”“某法定节假日顺延”或直接点明清偿抵充等司法解释文号；
   - ④ **禁点破在卷旧稿的具体错误类型**：交办复核在卷旧申请书、起诉状或协议草稿时，只交代在卷文稿与使用目的，严禁提示其存在管辖错列、主体信息错位、机关名称有误或漏算某项利息；
   - ⑤ **禁预告账据与查控异常性质**：严禁在题面提示“多渠道回执重复需去重”“某日存在退回款”“面积/金额颠倒”或“查控时间晚于裁定”。

## 从结果反推必要判断与失效范围

对每个拟设考点，先求出接收人可独立使用的结果，再据卷核实它成立所必需的事实、法律与办理条件。无需为每项新增冲突、计算或专属文件。
- **必要性与关联性**：每个复合 R 必须由多项实质判断共同决定同一业务成果是否成立可用；摘一个日期、抄一个数字或套一段通用法条不能单设 R。
- **利害最优性与可求解性**：客观缺证保留条件分支；卷内足以比较的方案须算清实际损益和失权风险。给定本方目标与约束能确定优劣时，指出占优方案及选错的损失；取舍取决于尚未明确的客户优先事项时，交代选择代价、建议和授权边界。
- **局部失败与整题归零边界**：辨明哪些错误仅影响可分离的局部结果（归普通复合 R），哪一处严重错误会直接摧毁本次委托赖以成立的代理立场、核心事实基础、关键除斥期或使整套成果产生反向损害后果（在最直接相关的那条 criterion 中融入唯一一处案件化整题归零条件）。严禁成稿后强行凑判零理由，也绝不把否决清单写进题面。

### 客户原意与办理建议

先分清客户想保住的利益、他提出的办法、已经明确的底线和本次授权。按当时可用的材料正面回答原办法能否办、能办多少、障碍在哪里。然后从卷内找有没有一项事实足以改变建议：同一目的可能更快实现，也可能多保住一项权利、少承担一项义务。先核两种做法可并行、须择一，还是后者已包含原有利益。以原办法今天能取得的结果为基准，只比较另一做法实际多保住什么、还要付出什么和承担什么风险，再给建议。客户已经明确拒绝的代价按其底线处理。选择取决于客户尚未说明的偏好时，指出哪个取舍需要他决定，先办不妨碍选择且已有授权的事项。

有利方向只见线索时，说明哪项已有记录指向它，哪条反向记录或欠缺的条件会使它落空。判断谁能合法取得决定性的凭据或授权，取得的成本、时间是否值得，以及等待会不会妨碍原路。值得查才办当前的核实或准备，写清查实、查否分别影响哪项决定。委托若只限某项具体办理，先办好授权内的事；范围外的关联机会确实会改变客户利益时，只提示利害和是否值得另行委托。对方尚未同意的条件不作为现成选择。

不同路径可以服务同一目标，也可以分别处理不同争点，无须排成高低档。回到各自的事实、权限和阶段：可相容又各有独立作用的意见可以同时提出；一条只有在另一项认定未获采纳时才有用的，写明成立前提，措辞须保留对原争点的立场；采取其一会放弃权利、作出承认或妨碍另一项的，交代冲突和不可逆后果，留待有权者选择。依同一事实编造两种相反说法不能成立。

只有确实会改办才安排后手。标答在实际要使用的内容里写准当前怎么走，哪个可核的结果会让本方转向、恢复原路或停下，到时改动哪项请求、抗辩、条款或动作，什么仍应保留。分清提前准备或提出的期限与真正启用的条件。等前一路有结果可能失权时，在现有授权内先守住期限。转向前核实原有权利是否还在。没有卷内依据预定先后或唯一首选时，给客户说明各方向的取舍，不硬排顺序；确定的单一路径直接办结。

原目标难以实现时，分清哪些损失已经难以避免，哪些金额、责任、期限或承诺仍能控制。落实本方此时还能采取的保护行动，向客户说明代价与剩余风险。若追加投入也改变不了结果，说明理由并建议收住。原办法已足够或卷中没有可信替代线索，就直接完成原委托。

这些是作者求解时的判断。题面按客户所知交代要决定的事，发现机会和选择路径留给承办人。标答把差别落实到需要的意见、条款、金额或其他实际用件；不统一交三档方案、另附比较表或多份备稿。

### 从未决争点形成办理决定

只在卷内存在会改变客户选择的未决争点时启用。先按办理基准日独立求解：找到支持当前倾向的决定性记录，拿最有力的反方证据或解释与之对读，用证明责任、证据证明范围及适用规则说明哪项具体请求更可能获支持、部分获支持或受阻。客观不能排序时，分清已能判断的部分、仍待查明的事实与查明前应采取的行动。后来的裁判不能充作当时的证据。

再沿最有影响的相反认定回查：若这份证据只能证明较窄的事实，哪项请求、抗辩、收付安排或签发条件要改？据标答写出可用的对应措辞；涉及金额或期限时，用已有底稿求出变化前后的值或可确定的边界。相反认定只作条件分析，不能虚构新来件。若措施在不同认定下仍应维持，写明保住的权利、理由及真正需要调整之处。删去这段研判仍能完成同一个决定且成果没有实质差别时，将其并回原有分析，不另布置预测任务。

题面只交代客户正在权衡什么、要怎样使用内部判断。具体证据冲突、优劣方向和切换点留给作答者发现。研判写入能承载该决定的已有成果，所需行动落到实际使用它的文件；不统一另交胜率表、情景报告或多套备份稿。

## 加压机制与竞争解释核对

以下关系仅在卷内有依据且会改变某项可用成果时采用。独立事项依其自身的专业判断验收。

| 本包真实存在的关系 | 迫使作答者增加的专业工作 | 落实到成果的可核验差异 |
| --- | --- | --- |
| **主文转述与底层原件冲突** | 穿透合同原条文、工商内档、原始回单或关联裁定，推翻主文/汇总表表面印象，回应最强相反解释 | 改变可采基数、责任上限、抗辩成立范围或请求标的 |
| **跨时际修法与多层级特别规则** | 自行识别行为发生时点与程序节点跨越的新旧法、时间效力解释、过渡期政策、多段利率档次或节假日顺延 | 决定适用旧法还是新法、是否加速到期/脱保、准确届满日与分段计息公式 |
| **多笔流水、多标的或多主体共同约束** | 全量原始记录逐笔去重、核扣前案已执结/退费/垫付款、排定清偿抵充或分配优先顺位 | 避免重复受偿、超上限追偿、漏扣费用或各文书总额自相矛盾 |
| **发起/冻结与实际履行/扣划半截并存** | 严格区分查询、冻结、解冻、受理、审批与实际扣划入账或签收生效状态 | 锁定真实未清偿净额与尚待补证条件，不把冻结额或重复立案当已受偿 |
| **直觉常规方案存在反噬风险** | 对比“顺势申请补正/重算/按法定默认抵充/直接起诉”与“保守抗辩/约定优先抵充/前置减资或析产”的净损益 | 核实额外代价后，修订会造成可避免损失的初稿；原做法仍符合客户目标时，按原做法定稿 |

## 工具工作与有效步长

定稿前给最省力的答法一次有利条件：设它已读完全卷、找对主路径、算对汇总数，并能批量生成规格齐全的文件。拿这些结果实际走到客户签发或办理的位置，检查还有哪件事办不成。
- 若几笔表面相同的事项实际受不同凭据、时点或权利约束，试着把同一个处理意见套给它们。在标答里定位最先不能成立的一笔及理由，继续办到受影响的请求、交割条件、取证对象或付款安排。确可同办的事项合并，不机械逐项重写。
- 若一个对本方有利的选择会给另一项权利或义务带来代价，拿同一组已核事实比较可行安排，并在接收人真正会用的文书中解决该代价。证据缺口妨碍最后决定时，把现在必须做且有权做的工作办完，写出当下可用的内容。
- 对每件采纳的工作，试着交一份按题面字面也说得过去的简答：只做最顺手的一处、引用旧稿，或把“建议后续办理”写进意见。把这份答复交到真正用它的人手里。若他仍得替律师做实质工作，先找题面允许省掉它的那句话。在有歧义的位置写明他的具体需要：要处理到哪个对象或期间、眼下要据此签什么或决定什么。卷内足以让专业人员自行识别的疑点、证据、法条、算式及结论留给作答者。
- 特别检查看似任选的交办。要决定两件可以分别办错的事，却允许任选一例演示，就把两项实际用途交代清楚。例如账上有多笔待批款，只要总额就能回答“核对账款”；若客户当天要放行其中一批，得让承办人知道财务等着据此逐笔付款。哪些该付、凭什么、能付多少仍由承办人查清。客户确实只需一个总额，或简洁做法已能办妥全部事项，就接受该做法。卷中另有值得深办的事项时另行取材。
- 已经交代“审查”或“核实”，一句意见仍能交差时，查清客户本来要拿审查结果做什么。例如对方返稿正等回复，本方只授权变更交期，可以从这个授权写起，让承办人交回今天能发出的文字，把仍需决定的内容留给客户。具体哪一条越权、怎样修改，由承办人发现。仅需内部决策的事项就办到可拍板，不另造外发稿。
- 对看似任务很多的方向，再用已核事实试一次：先完成全题可共用的底数或结论，把可从它直接批量生成的文稿视作同一份工作。对余下事项找出还要独立处理的原始对象、规则判断和接收人可用的具体成品。若收件人名称互换后仍可照交同一套正文，或主要变化都要等材料之外的事情发生，回到当前委托，重查有依据但尚未办到的工作。错失时限等有实质代价的条件准备仍要交清。
- 严禁靠禁止脚本批处理、规定调用次数、故意等待或制造损坏文件凑复杂度；材料确实单薄不足以支撑复杂委托时如实报告并重选方向。

### 自检式深度与多跳工作链设计

以下六类捷径用于逐项查漏。有相应卷内问题的，按本案决定核验；没有相应事实的，不移植该行的场景、文种或办案顺序。总控对正式交付、动态底稿和证据依赖的要求照常落实。

| 作答模型常见捷径 | 必须落地的真实业务加压设计 | 作者成稿前可观测核验点（未满足须深化） |
| --- | --- | --- |
| **1. 只读主文，漏掉现行工作所需的依据** | 逐份核对不同记录的主体、时间、证明对象及可用范围。遇有冲突说明为何取舍；材料相符时仍须凭原件证明相应要件 | 仅靠摘要，即使猜中最终结论，仍无法编出可核查的举证材料、确定请求范围或完成相应手续 |
| **2. 只搜现行通用法条或靠题面年份提示填空** | 选取行为与程序跨越新旧法/司法解释过渡、过渡期特别规定、双轨送达节假日顺延或多期利率/费率切换的真实节点，题面严禁透露修法年份、解释文号或顺延线索，内部意见书要求核查有权机关原文并附官方链接 | 不实际检索核对行为时旧法、时间效力解释原文、历次利率调整日或当年节假日安排，就必然选错条文或算错死线/分段利息 |
| **3. 计算结果无法复算或直接填死常数** | 多笔收付需勾稽、方案要换输入比选、接手人会继续更新余额或到期日时，交独立 `.xlsx`。将影响结论的原始明细连到计算结果，待核输入留空且不产生虚假零值 | 选一笔影响结果的卷内记录或一个可变参数，核对改变后哪些派生值和处置动作会变。只涉及可由单份依据直接核准的确定金额或日期，就在实际使用的文书中列明依据和结果 |
| **4. 批量生成同质短申请或合册** | 按每个接收人实际要做的事补足必要正文、签发附项及底稿。短文书能独立保住权利时照常做全；案卷另有实质审查、修订或交接工作也要办到底 | 拿走这件，能指出哪项动作无法完成；补齐后，接手人可按权限使用。仅改抬头、转格式不算增加工作 |
| **5. 靠直觉惯性方案平推，未做反事实损益核算** | 优先挖掘卷内“看似顺理成章但实算后损害委托人利益”的反噬点（如申请补正/重算倒增本方负担、舍弃有利约定退守法定默认抵充、未先析产/减资径行起诉被驳回、错选较晚送达路径错过最早风险死线） | 思路核对原路与其他可行做法的实际得失，标答落实有依据的选择；复算支持原路时照原路办理 |
| **6. 核心事实与算账全错，仍靠文书格式、引注与交接套话拿保底分** | 文书体例、法源引注、通用交接及无独立判断的衍生文本一律并入其服务的核心争议 R；在同一事实、授权与目标下能够确定优劣的选择，判据唯一锁定委托人最大合法利益口径并写明明确二元不成立边界 | 逐条检查全部 R：顺着主文表面数字或次优默认口径走的表层工整答卷，在绝大多数 R 上均直接触发不成立边界 |

## 规则与载体落地

1. **权威法源必核原文**：定稿前实际打开有权机关发布原文核对条号、文号、利率档次、施行日期、过渡条款与适用例外；严禁凭记忆顺延条号或编造网址，未核实内容不得设为唯一判据。
   规范原文仍不能解决本案关键适用分歧、而选择会改变主张或客户授权时，先由作者查到办理时点已公开且可复核的裁判全文或主管机关办理依据。对读其程序阶段、决定性事实和处理理由，指出本案哪些事实相合、哪些差异足以改变选择，再落实到实际请求或条款。检索用抽象争点与公开规范，不发送案件个人信息。没有可核实的原文，或法条已足以确定结果，就不交办该项研究；不凑案例数、检索轮数或胜率。
   适合交办类案检索时，题面把查找和选案留给作答者。标答在争议判断处引法院公布的案例或生效裁判原文，留可定位的案号、入库编号或官方出处；说明决定结论的相似点、足以区分的事实及对本次办理的影响，区分规范依据、指导性案例和其他案例的参考作用。复合考点接受其他可核实且能说明同一争点的适切依据；按论证能否支持本案决定验收，不把作者找到的案号设成答案键。
2. **脚本实算验证精度与舍入**：所有本息、抵充、分摊、增值比例与期间天数均须用脚本实算验证端点、闰年/日历天数、调息节点及反算闭合；分项先舍入与汇总后舍入存在尾差且题面未限定单一财务口径时，在判据中明确兼容合理舍入尾差，不卡死无业务意义的几分钱尾数。
3. **部分状态与真实缺口不编造**：对现有卷宗已证事实给出确定结论与金额；对确属在卷缺失事实写清触发条件、分支结论与补证调取动作，绝不用“待核、依法处理”敷衍已可算清的部分，也不把待核事项强判为已发生或未发生。
4. **成稿六项终检**：
   - ① 仅读主文就能原样交出可用结果吗？若能，回查哪些原始凭据、相容事项或必要随件被漏掉；材料相互印证时不制造矛盾。
   - ② 各项工作能否说清遗漏的实际后果？补回过去只写成建议、现有证据足以完成的办理，并合并同质重复件。
   - ③ 待裁决救济路径是否在任务名称或文书标题书名号中提前泄底？若有，改为中性功能称谓；
   - ④ 逐个接收人核对独立实体文件：应签发的正文与随件齐备，应复算的明细和活公式可用，应报送的整套定稿可读，题面交办饱满且未放行纯文本或合册。
   - ⑤ 是否彻底清除了“模拟/假定/窗口”话术、`(****)` 星号掩码、以存储文件名代称证据及其他制作说明？
   - ⑥ 整篇行文顺序是否摆脱了“首段角色基准日→逐段点书名号→末段交卷说明”的四段同构骨架？成稿前结合[交付规范](题目格式与交付.md)、[表述方法](表述方法.md)与[书面表达组合库](../assets/书面表达组合库.txt)完成核对。
