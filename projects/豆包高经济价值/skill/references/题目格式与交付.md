## 题面

### 角色与职责边界

- 作答者为代表**单一委托方**的律师或企业法务；严格区分职业岗位（填入表头职业字段）与委托方的诉讼／交易身份（原告、被告、保证人、案外人、上诉人、再审申请人、管理人、收购方、标的公司等），不把当事人身份填成职业。
- 代理立场必须实质决定证据取舍、抗辩顺位、利害权衡与文书请求，不搞仅换称谓的伪换角。
- 不代签、不径行向法院递交或外联对手、不越权放弃实体权利等执业纪律，随文嵌入对应对外文书或交接要求处，不在首段末尾集中背诵负面禁令清单。
- 让委托人讲清希望自己、同事或获授权的人拿成果办成什么。内部风险判断、谈判底价和可交对方的文本分别给实际收件人。复核外发件时连同随件、批注和保留的修订记录一起读，办齐所需披露，同时避免外传仅供己方使用的信息。有现场行为时，卷内笔录可以复核；尚无答复则备好可照用的问题、相应凭据与收到不同答复时的处置，保留实际操作者的身份和权限。

### 饱满业务交办与整篇结构去同构

- **保持充足饱满的业务信息量（绝不压缩成简略几句话）**：题面必须像资深合伙人、法务总监或委托方在真实复杂案件中的正式工作交办，完整写清——① 现实业务困局与基于在卷文书的明确办理基准时点（利息或期间需统一核算截止日的直接写明具体年月日）；② 实际触发委托的来件或经过，以及确有的待审旧稿或对方诉求；③ 客户已知的接收对象及决策、立案、签约或复算用途；待承办人确定的办理去向和范围写成须解决的问题；④ 跨文件主体、金额、期限与附条件口径的互锁一致性要求及待核留白规则。**润色后须保留影响办理的对象、制约条件和交付用途，也不得在题面使用“简要说明”“只需概述”“不必展开”等压缩作答深度的字眼。**
- **从客户要办成的事写足交代。** 从试办结果中挑出会改变交付的限制，写进它实际影响的事项。已有在办事项，交代前手已办到哪里、现在交来什么、客户要沿用或重做什么。对象有别，交代须分别办到的范围，例如核对公司实际收款与个人代收、分别向两处接收人交什么。需协商时写清客户肯接受和须保留的条件，哪份文字将交对方，谈不成后还需要哪份可用稿。需续办时写清前件产生了什么可用结果、接手人靠它办哪一步、哪些授权或证据仍缺。只选卷内确有依据且会影响工作的内容；用当事人已知的业务对象和问题描述范围，决定性凭据、计算结果与路径仍由律师查明。
- 卷内确有两难时，把客户已经知道的约束放回它发生作用的地方。来件已有报价，就交代对方在等哪项回复以及本方不能轻易承诺什么；现有材料决定可报送范围，就写谁准备收件以及客户卡在哪里。让承办人自行找出能接受的界限和依据。直接起草、庭审应对或仅需内部决定的委托，沿用各自的交办方式，无须增写一轮比较。
- **从成题反查漏交办。** 暂时只读题面。律师若能逐字满足要求，却漏掉一类独立对象、沿用已经失效的稿件，或只交一段建议而缺少接手人所需的可签条款、报送明细或取证正文，补写具体办理范围和用途。例：“把这份协议改到我能签”仍可能只得到改字稿；客户确有代收授权问题时，可交代“钱进到谁的账户我才可以确认收到？请把公司能交给经办人的收款指示和本人届时签的确认稿一并备好”。何种支付算履行留给律师判断。案内没有这种安排，便从该卷真正容易漏办的工作检查。
- **打破四段同构骨架**：严禁整批沿用“首段介绍角色与基准日 → 中段逐段挂《文件名》一二三四 → 末段统一说明怎么交卷”的固定顺序；按[书面表达组合库](../assets/书面表达组合库.txt)核对各项成果如何服务于本案决定，共用格式一次交代清楚，不默认拿当事人姓名作全题首词，也不默认停在申请执行人判后追偿。

### 作答端检索、依据与交叉核验

将收件人要用的成品和事实依据写入 `question`，并与 `answer_requirements`、标答及 rubric 保持严格对齐：

1. **强制实体文件交办（严禁放行纯聊天文本交卷）**
   - 凡接收人需编辑审签、递交立案、持续调参复算或签章归档的成果，必须明确交办各自独立命名的实际办公文件：
     - 需签署、递交、修订或归档的正式文书 → 要求交付**独立可编辑文档（`.docx`）**，严禁允许将不同用途文书合并塞进单份合册。接收人必须使用的附页、证据目录、附件索引或签发指令，按卷内已有凭据和实际流向备齐。相同材料供多件使用时可共引；需独立签发或交给不同接收人的分别成件。
     - 收付、查控、期间、出资或分配等事项需逐笔勾稽、分段推算、切换口径或留供后续补录时，交付**独立的活公式工作簿（`.xlsx`）**。全量纳入影响结论的记录，把公式连到经办人实际要使用的数值，待核与已知为零分开。单个已核事实只供填入正文时，直接写入使用处；
     - 凡需递交、签章、报审或归档定版的正文及其随附明细，均提供对应 `.pdf`。实际打开核对定稿与可编辑源稿，逐页看附件是否齐全、表格能否读全、落款是否可签。发现问题改源件再导出；持续维护的内部底账保留活公式原件。题面只交代接收人要拿它办什么及所需格式。
   - **硬红线**：`answer_requirements` 必须如实声明 `output_mode: "file"` 及所需工具；**严禁在 `question` 中写“在本次回复／答复中分件列出全文即可”“无须另行上网、制作或提交文件”等放行纯文本交卷的语句**。
2. **跨时际权威法源核验**
   - 涉及新旧法衔接、时间效力司法解释、专门监管规则、多段利率费率切换或法定节假日顺延时，结合内部审查意见或备忘录复核需要，自然交代检索核对有权机关公开发布的正式原文、施行时间与过渡条款并注明官方公开出处（向法院提交的诉讼文书按司法体例援引条文文号，不在无关文种复读固定网址口令）。
   - 方案中关键建议就地给出支撑它的依据。事实、约定义务、程序要求及法律效果分别依其性质，选取可定位的记录、条款、正式办理依据、适用规范或裁判说理。决定取决于法律适用时，题面交代收件人需要解决的争点及引用用途，让作答者自行查找、核准办理时点可用的原文，并说明怎样用于本案。类案的取舍见[规则与载体落地](出题设计方法.md#规则与载体落地)。
3. **交叉证伪与受阻留白**
   - 核清影响结果的记录、矛盾或缺口；涉及账项的用可复算明细支撑请求，涉及权限、版本或证明范围的将取舍落实到相应条款、签发范围或举证动作。在卷可得的信息当场填妥；确须等补件或授权时，写明经办人找谁、取得什么凭据、此前可办到哪里，以及何种结果才能继续。

   - 核的是已经做出的请求、金额、期限或建议。两件成果沿用同一底数、两个网站转载同一裁判，均只能追到同一来源。能独立回查时，从另一条证据链或不同算法核到成品；按收件用途在原有文稿或底稿留下依据和处理结果。题面点明客户要确认的决定，不预告反证或指定核法。

### 工作要求与答案提示的边界（连标题都不泄底）

- **按客户知情范围交代来由。** 一份审批表若就是客户手中待签的原稿，可以点名并说明他要决定什么；同一张表若只是卷内发现授权矛盾的线索，由承办人自行找到。客户已提出的疑虑可按其陈述交代，证明力和处理结论仍须独立查明。其余材料不逐件报目录。
- **给办理方向，保留求解难点。** 在客户实际卡住的地方给出引子。已知对象可以直接点名并交办；只知道业务决定，就问到作决定所需的结果；已有专业分工，就从谁在等哪项成果写起。需要律师动手时，写到其成果实际要用在哪里。仅有“综合研判”“核查有关事项”或一个文件名，还辨不出该办哪件事的，补清该处。以下按案情选用。

| 允许的自然业务交办 | 应由承办人自己查明的内容 |
| --- | --- |
| 去向已定，直说收件人及已知要求。去向或证据组合待审，让律师就客户目标定出有权受理的对象、可签的正文和随件，各件独立具名。可以用中性功能称谓指明应交成果 | 连同收件机关、启动前提、文种和随件清单逐件给出，使律师只需按目录填正文就完成原本应由其判断的路径 |
| 要求核对现有全部收付、退费与查控记录，核定截至某年某月某日尚可主张或应承担的净额并在工作簿与文书中落实 | 提示“多渠道回执重复需去重”“某日存在退回款项”“查控时间晚于终本裁定”或“面积／金额记载颠倒” |
| 交代旧稿原准备用在哪里，委托律师决定能否沿用，并交给接手人当前可用的内容。须改稿的改妥，已失去用途的说明如何停用及当前还有哪些工作可办 | 提前点破在卷旧稿错在管辖、主体信息、协助机关名称、漏算某项利息，或明示“不得直接启用某项诉请” |
| 要求依据在卷裁判、送达及履行材料核定生效日、救济届满期限与分段利息费用 | 提示“跨某年修法前后规则变化”“适用某年时间效力司法解释”“注意某节假日顺延”或直接喂给清偿抵充条文号 |

## 七项内容

| 字段 | 权威要求 |
| --- | --- |
| **表头 `header`** | 题目 ID、按任务发生组织主营业务填写的一／二级行业、任务形式、按实际分件脱敏文书名填写的可见附件清单、按负责最终交付的律师／法务岗位填写的 L1／L2 职业（不填当事人诉讼身份） |
| **任务名称 `task_name`** | 聚焦本案最具区分度的标的对象、待决焦点或业务动作，用紧凑短语或交办短句；禁加“专项／全量／全套／闭环”包装词，禁整批套“[主体]的[A]与[B]”对称句式，禁带 `(****)` 星号掩码，禁提前写出待求结论 |
| **任务类型 `task_type`** | 依据材料实质内容、实际工作与最终交付用途选定准确业务类别（分散覆盖应诉、上诉、再审、执行救济、刑事控告、另诉、尽调、治理改章、合同修订、涉税行政或破产处置等），禁按文件夹名机械分类 |
| **题面 `question`** | 饱满详实的真实执业交办正文；明确单方立场、在卷事实基准时点、权限边界、必须实际交齐的独立成果及其用途（已定文种可点名，待决路径可用中性名交办）及按实际用途选定的载体与法源要求；严禁放行纯聊天文本交卷或合册打包，严禁剧透、模拟词、掩码星号与评测黑话 |
| **考点 `rubric`** | 按去重后的独立复合专业结果设项，等权二元计分；每条自足点明具体原始文书名称、规则要旨、可供核验的对应成果、同一前提下可确定的最优口径或有据的合理选择及明确二元不成立边界；无独立判断的体例、引注、交接或纯衍生短文并入核心争议 R；全题在最直接相关的一条 `criterion` 中自然融入唯一一处案件化整题归零条件 |
| **作答思路 `answer_approach`** | 解释本案最需专业判断的一处分界，由哪个事实、约定或规则决定，改变了哪次操作、哪项请求或哪句可签文字。其余独立工作各说明实际取舍；读者可以核查依据，经办人只看标答也能办 |
| **标准答案 `reference_answer`** | 按各收件人可用的形态交全文。正式文书保留法定首尾；给业务人员的交割指令、修订全文、现场问题或批准意见用其日常工作样式。涉及工作簿时，用文字交代逐笔认定、计算依据、已核数额及其对请求或决定的影响。数字不足以定案时，写明尚缺什么、当前能认定到哪里。读者应能凭这些内容复核结论，无须对照作者设想的格址或函数。仅在原始明细可无损沿用、接收人无需筛选或重判时才按可定位来源、笔数与小计引用；须分笔支付、提交或剔除的逐项交足 |

## 表达与引用

以下为全题包**反模拟与反评测黑话唯一权威清单**（其他文件直接引用本节，不重复抄录）：

1. **业务正文纯书面排版**：`task_name`、`question`、`rubric`、`answer_approach`、`reference_answer` 均采用自然段、普通中文编号（一、（一）、1、2）及必要的算式或制表分列。分件直接用文书名，业务正文用日常中文标点，不用方头括号给标题或文件名加框。**不使用 Markdown 井号标题、加粗星号、反引号、代码围栏、管道表格或 Python/终端脚本**。
2. **分件文书引用分层**：
   - `question` 可自然点明触发委托的已知来件，其他材料依上节的防剧透规则处理；当案号含 `(****)` 脱敏掩码时，改用不带星号的自然执业简称（如“某区法院第×××号民事判决／执行裁定”）；严禁声称随附材料为“调档扫描原件、手写原件、官网打印截图”或要求鉴定印章笔迹物理形态；
   - `rubric`、`answer_approach`、`reference_answer` 必须精确点明所附卷宗的具体原始文书名称及案号／日期／出具主体；
   - **全题包任何字段严禁出现**：“附件1”“附件 1”等内部序号、“合并卷宗”、`材料-xxxx.docx` 匿名哈希文件名、导出页码或本机路径。
3. **业务正文用语**：
   - **禁模拟设定词**：“模拟律师”“模拟场景”“模拟委托”“按模拟于某日接办”“本题模拟”“办理演练”“假定……”“题设前提”“材料取得窗口”；
   - **题面只交代业务用途**：避免“逐页转换为页面图像／页面图片”“实际执行公式重算并读回”“在与案件事实隔离的核验副本”“多表活公式XLSX”“定版分页PDF”“宽表横向截断成碎页”“不得以文件名／提纲／补证清单代替成果”；
   - **禁判据产线词与口号**：“本条评价……”“评分端”“轨迹未传”“评测条件不满足”“不作为有效专业难度成绩”、分数、步数或用时目标，以及每题逐字复读的固定归零尾句。
