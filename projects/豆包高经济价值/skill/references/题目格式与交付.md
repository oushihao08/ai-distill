# 题目格式与交付

**核心：**完整、准确地表达题目字段和业务交付要求。

**作用：**交付规范：确定角色、事实输入、成果及字段内容，保持题面与评分一致。

**阅读方式：**目录用于定位；正文中的适用条件、例外和引用共同构成要求。按需选择的机制不要求每题集齐。

## 题面

### 角色与职责

- 作答者为律师／法务，区分其职业岗位、所代表一方的诉讼或业务身份、服务对象与材料中的其他人物；当事人、被告人等诉讼身份不能直接填作职业，行业和职业按实际情况填写，不编造字段。
- 明确委托人与承办人的不同权限，只承担本方职责内的判断和交付，不代行其他角色职权。方向及场景按[材料方向场景与交付设计](材料方向场景与交付设计.md)执行。
- 代理立场须实际改变证据取舍、规则适用、行动边界或成果，不能只换称谓；分析对方主张不等于同时代理对方。

### 工作范围与强度

用适合本次委托的自然专业语体说明要办的事；口头交办、书面工作说明等均可。写清谁委托、当前要决定或办理什么、可用材料、权限及成果给谁使用，但严禁整批沿用“[当事人姓名]起手→委托与基准日→‘该委托关系及办理时点为本题设定’→‘不授权递交／外联／代签／和解’四连禁令”的首段四步公式：
- 首句切入须按本案真实触发点分散展开（从生效判决履行困局、前手遗留稿出入、程序或异议期限、查控／分配回执或接收人下一步动作进入，不默认拿当事人姓名做全题第一个词）；
- 模拟时点、委托或假定测算条件必须明确标示模拟／假定身份（严禁伪装成原卷既成事实），随时点或条件自然写出，不复读同一句设定套话；
- 不代签、不径行向法院递交或外联对方、不越权放弃实体权利等边界，随文放入具体对外文书起草或交接说明处限定，不在首段末尾集中背诵负面清单。
合并重复的答题指令，保留完整正文、必要依据、模拟披露及明确交付要求，不以口语化或精简为由删减任务。从以下工作中选择本题实际需要的内容：

- 分别回应待评主张、方案及反驳理由，定位决定性材料，说明依据之间如何支持、限制或冲突，并给出具体处理结论。
- 全面处理案件、主体、款项、期间和条款，表达合并、区分、排除及适用情况。
- 涉及数值或期间时，给出分项计算、基数、公式、结果或条件表达式，并核对汇总关系。
- 角色须在多个处理路径间选择时，比较方案及其成立条件；后续事件改变判断时，重新形成相关成果。
- 写出本方律师／法务有权制作或提出的条款、请求、代理意见、通知或交接正文，保持主体、范围、条件和后果一致。

### 作答端检索、依据与交叉核验

将以下要求转化为点名本案具体文书与底稿名称的自然交办要求写入题面，并在标答中实际完成；组织方式服从本题文体，严禁照抄本节内部缩略术语（如“多表活公式XLSX”“定版分页PDF”“宽表横向截断成单列碎页”“发现问题回改源文件后重导重验”“隔离核验副本”），严禁在题面末尾单挂统包式技术收尾段，也不另增一份检索报告：

- **深度表达**：需要深入处理的工作采用正向、可验收的措辞，要求完整梳理既定范围、全面核对关键关系、逐项列明依据与结果、细致区分对象和状态、展开论证竞争解释及适用规则。每个强化词都要对应本题明确的材料、对象、事项或成果，不机械叠加“详细、全面、细致”，不以篇幅代替专业工作。题面不得使用“简短回复”“简要说明”“无需详细”“不必展开”“只需概述”“不要过多说明”等会压缩实质作答的表达。

- **完整执行引导**：每题以明确的命令语气要求完成本次委托的全部可办工作，不得降为“可以考虑”或只交提纲。结合下列适用内容嵌入对应成果段落，不在开头套用“请先详细规划／安排……再全部完成”等流程话术；具体表达边界见书面表达组合库。
  - 存在竞争解释、复杂关系或方案取舍时，要求充分论证决定性依据、适用条件、例外及对手最强相反解释，交付可核查的专业理由；不要求披露内部思维过程，也不把延长思考时间作为完成标准。
  - 本题需要报告或办理意见时，要求直接交付可供接收人审签使用的完整报告或意见，覆盖该时点应完成的分析、核算、结论和办理安排；不以提纲或后续补写承诺充当成稿。其他文种按自身用途完整制作，不为使用该表述另加报告。
  - 题目要求文件、文稿、核算或更新能力时，随各份成果的具体名称与实际用途完整布置四项硬动作（拆散融入对应交付物段落与交接要求中，绝不减损动作量）：①制作可编辑正式文书（DOCX）及全由公式驱动的多分表工作簿（XLSX），并实际重算读回；②完成工作簿动态联动验证（跨节点题承接新增事件重算更新；单窗口静态题围绕本案真实存在的争议款项认定或关键时点分歧设置业务敏感性／备选情景测算栏验证公式自动联动并读回，与正式主表区分，严禁写“在与案件事实隔离的核验副本中改变一项关键输入”）；③将全套正式成果——包括主审查报告／法律意见书全文、全部正式对外文书，以及经横向排版或列宽适配后的多栏核算总表／附表——全部导出为分页 PDF（严禁只导短篇申请书或列文件名）；④将导出的全部 PDF 逐页转成页面图像检查是否存在宽表跨页横向劈裂、落款签章孤行跨页或正文与附表／对外文书的金额条款出入，如有错位必须修改原 DOCX/XLSX 文件后重新导出核准。
  - 确因缺证、权限或工具受阻的，完成不受影响部分，在主意见或呈批说明中写明具体阻碍、影响与启用条件；不单独要求制作独立的“文件交付回执”文件，也不得为声称全部完成而补造事实、隐瞒缺件或越权操作。

- **联网核验**：本题需要核验公开规则时，要求对影响处理结论的法律规则和争议问题检索权威公开来源，核对原文、适用版本、施行时间、对象及例外。优先官方发布机关的规范原文和有权机关公开资料；搜索摘要、转载和评论不能替代可取得的原始依据。历史场景按相关行为及决策时点判断适用规则，不直接采用当前最新规定。
- **结论与依据对应**：关键事实判断说明附件及对应的文书或记录内容，不按页码定位；公开规则说明来源名称、发布主体、相关条款或内容及可追溯链接，交代它怎样支持、限制或排除具体结论。只列链接、复制法条或笼统写“见附件”不足以完成必要论证；不要求所有句子逐句引用或使用统一引注格式。
- **交叉核验**：围绕影响结果的冲突、例外和相反解释，检查记录是否独立、时间与适用对象是否一致、证明范围是否相容，并说明采纳与排除理由。案件事实依据附件及明示条件判断，网络资料不能补造个案事实。同源转载不算独立印证；权威原文已足够时不为凑数寻找第二个来源，确实无法消除的分歧说明条件和影响。
- **结果复核与交接说明**：重要金额、期间及共同办理条件采用适用的分项汇总、反算、时间线或整体可行性核对。对象或计算较复杂时，呈现足以复核的分项结果及来源对应，不能只给汇总结论；核对各成果中的对象范围、条件、状态和处理结果，解释并修正冲突，区分合理的阶段或用途差异。回复随业务用途简要说明各实际文件及关键口径，不替代文件正文，也不单列通用审计回执尾段。

- **表达与任务对照**：先按本题已确定的工作和成果写清各自的完成、核验与使用条件；同一共同要求可集中交代一次，专属要求紧邻相应事项，结尾只承接尚未说明的实际交付或办理动作。成稿后逐项对照任务盘点、标答和 rubric：每项必要工作均有题面交办、完整成果和自足判据；每份文件的用途及必要核验可定位。改写不得删减权限、事实时点、模拟边界、实质工作、文件能力或核验义务；无需为换写法增加文件或重复段落。

- 作者出题前核对工具能力，不在题面用“无须／不得联网、调用工具或生成文件”等套话关闭工具。按[工具工作与有效步长](出题设计方法.md#工具工作与有效步长)设计适用工作，调用顺序由作答者决定。委托、保密或数据边界确有具体限制时明确对象和理由。必需工具尚未接通时记录执行缺口，不能擅自把已要求的联网核验或实际文件交付降为文字替代；关键资料本身不可取得时补齐必要正文和出处，不注入解法。运行失败如实记录，不虚构已完成操作，也不将环境失败当成专业难度。

### 工作要求与答案提示的边界

- 将[实质工作选择](出题设计方法.md#按材料展开实质工作)转成针对具体对象的交办：指出要审用或修订哪份成果、回应哪项实际意见、处理哪些对象或拟定哪些事项的条款，并交代使用目的和完成边界。提供包含常规有效内容与未标明缺陷（如隐蔽错算、越权处分、程序缺漏或不当结清）的自然完整待审文本及必要条件，让作答者自行识别应保留、接受、反驳或修改什么；严禁将有问题的一句话单独摘出点名反问，不直接复制工作分类表及作者求解步骤，也不只写“全面审查、深入分析”。
- 题目可以要求多项独立工作和多个成果，不限于单一决定或单一路径。题面可以限定核对领域、指定成果及要求说明依据；不要预先宣布材料存在某类错误、指定错误数量、采信方向或解决顺序。
- 可以说明要核对什么、计算什么、提交什么，并据此设置考点；不要直接告诉作答者该采信哪份材料或得出什么结论。保留自行发现证据问题、选择规则和裁决争议的工作，不将详细任务缩减为泛泛意见。

| 工作布置 | 泄露判断线索 |
| --- | --- |
| 核对现有付款记录，确定已清偿范围，并在余额表及付款条款中落实 | 回单存在重复，必须去重；对账单余额错误，请以银行流水为准 |
| 给出完整的内部会签草稿或对方协议全文，交办审定能否签署并形成本方定稿 | 只摘出草稿里越权免责或漏通知的一句话，专门提问该提议是否合法 |

### 事实输入与待求判断

- 区分原材料明确事实、必要业务条件和本题要求求出的结果。保留前两类；待考的交易对应、授权效力、适用规则、推算日期、法定起算端点、节假日顺延、折算基数、法定清偿抵充顺序及余额由作答者依据原卷与法律规定自行判断，不在题面提前确认或喂给实务常规。
- 原文书明确记载的生效日、履行内容和有效约定不得为加难删改；截止基准日与必要模拟时点仍须提供，不能删除事实发生日期让作答者盲猜。作者新增的模拟记录应提供可判断的主体、范围、时点及关联信息，不直接宣布其法律效果。

- 每个场景明确办理时点及当时可取得的信息；后续材料与事后复核按[场景设计规范](材料方向场景与交付设计.md#五材料方向场景与成果的匹配底线)区分。仅当委托方确有不同于法定规则的特殊内部考核或预算口径时才明示内部测算条件，并要求与对外法定请求分别处理；不能以模拟约定当然替代法定口径，也不把法定计息／顺延／抵充规则包装成委托人交办口径喂进题面。法律存在合理争议时列可成立分支，作者尚未核实不等于法律有分支。
- 题面不附作者检索所得的法律讲解、搜索链接或答案依据清单。

### 成果用途与变化处理

- 题面按实际工作写明成果的使用人、接收人、专属约束、后续决策或执行动作，以及做错会影响什么；不固定为签批或交易场景。按用途要求完整业务材料和实际文件，允许使用 PDF、DOCX、表格等成果；只有回复正文已能完整实现接收用途、不涉及编辑、签署、提交或持续更新时才使用纯文本。需要编辑、审阅或提交时明确文件用途与验收内容，并布置实际导出、读回或渲染核查；环境不足单独标明，不能自动将文件要求降为回复正文。
- 按业务用途确定有实质正文的必要配套成果；多场景围绕整体委托安排共享和独立成果，不按场景数量机械增加文书，不以重复分析、文件拆分或空文书凑数。
- 要求给出可直接使用的口径、条件和文本，不以“另行制作”“待核后决定”代替已可完成的部分。可复用的文书格式或核查清单仅在本题确有复用需要时交付，并写清适用边界；有数据时核算经济结果，不为证明价值补造金额。
- 不要逐一提示附件中的矛盾、错误数字和正确法律口径。

- 安排逐对象的处理结论与理由，让作答者自行区分成立、附条件成立、应排除或受阻的范围；涉及办理动作时进一步落实可执行边界，不预告哪些对象属于哪类。变化情景说明发生的事实和时点，要求修订受影响的成果及其依据、交代未受影响部分，不直接宣布原方案失效。
- 持续使用场景按[连续续办设计](出题设计方法.md#已有成果的连续续办)给定相互承接的事件；明示各阶段信息和模拟边界，要求实际更新成果。已知事件内容属于必要输入，事件的证明力、法律效果和处理路径留给作答者判断；不因避免泄题删掉必须提供的记录。
- 完整修订稿或明确替换范围及正文均可；连续办理须能回查各阶段实际处理，历史值可用于初稿及对比，核对的是同一阶段当前有效文本之间的一致性。文件数量服从使用需求，不要求逐阶段复制全部未变成果。

## 七项内容

- 成稿时对照标答核查必要专业成果是否已由题面布置，或为完成任务必然要求。缺失时补清交付对象与内容，不把多余展示细节升级为要求。
- 例如确需收益率时明确要求计算收益率，但不提前给出待考的公式、规则选择或应得结果；材料已有的有效约定、必要计算条件及测算定义仍须保留，不借此补写待考结论。不把标答求解步骤逐条改写为题面。任务可以充分具体，答案与裁决路线仍由作答者形成。

### 七项字段

| 内容 | 要求 |
| --- | --- |
| 表头 header | 题目 ID、一级行业、二级行业、任务形式、可见附件名称、按主要负责最终交付者填写的 L1 职业簇与 L2 职业 |
| 任务名称 task_name | 用最具区分度的单一核心业务事项、待决问题或关键文书用途命名，可用交办短句或专业短标题。严禁整批写成“[主体／案名]的[四字动作]与[四字动作]”对称句式，严禁滥用“接管、核校、全套、闭环、专项”等词，不机械堆齐所有元素或文书清单，不提前写出待求结论。 |
| 任务类型 task_type | 根据材料实质内容、题面要求的实际工作及最终交付用途，选择本期适用类型；不得按文件夹名、附件名或路径中的标签直接分类。材料只显示争议类型时，还须结合本题要完成的工作和交付来确定类型；法律实务题不固定为“法务、合规与交易支持”。 |
| 题面 question | 完整角色、背景、条件、对象范围和具体工作要求（首句切入错开，模拟条件用自然业务语言明确标示，硬性文件重算与全套分页 PDF 逐页转图校改要求点名融入具体文书段，禁挂通用技术尾段） |
| 考点 rubric | 按复合专业结果判断成立与否，等权换算百分制；条数按覆盖与去重确定，判据自足，禁用内部评测系统术语，每题融入一处案件化整体失效条件并自然写明全题归零后果 |
| 作答思路 answer_approach | 依据取舍、规则适用、求解关系、争议及替代路径 |
| 标准答案 reference_answer | 完整交付本题全部要求（首屏按主成果体例直接切入，禁用统一“意见书标题＋致XX＋办理基准日”三行信头）：写出各阶段正式可用文书全文、工作簿表结构与活公式写法、分项汇总与勾稽结果，以及争议、重复、异常或调整项的逐笔处理；附件无争议的大批量原始流水按来源范围、笔数与小计归并引用，不在文本标答逐行重抄 |

### 命名与分类检查

- 先读材料正文，题面和标答完成后核定名称与类型。文件名和路径只用于定位，不得照抄、拼接或仅替换其中主体、案号、日期来命名分类。名称与正文不一致时以正文为准；信息不足时采用不超出已知事实的概括表达，并明确必要模拟条件。名称可用交办句或专业短标题，类型提炼准确业务类别。

- 名称先回答“这一题与其他题最关键的区别是什么”。具体交付物已在题面说明时，不在名称中重复列全；不能只把同一骨架换人名、动词或标点，不批量套用“A与B”双并列四字名词。

- 交付前对照最终题面和标答，检查名称是否准确辨识本题工作、成果表述是否准确、类型是否为准确业务类别；不符合时在本次出题内改写名称或类型，不改变题目工作。

### 输出形式

- 按当前任务指定的结构返回上述内容。字段中的业务正文按[书面表达组合库](../assets/书面表达组合库.txt)使用普通书面文字、编号、必要业务明细与完整文书，不用Markdown标记、代码块或生成脚本。DOCX用正常表格和样式，TXT用分行明细或制表分列；保留全部核验内容和出处。结构化返回外壳仍按契约保存，不要求额外的Markdown业务交付。
- 作答者的文件交付要求按实际业务用途确定；环境能力另行核对，缺口不能降低交付要求。文字材料采用DOCX、TXT等适用办公载体，公式联动及固定版式按需使用XLSX、PDF。不为换写法改变原任务所需能力，不用格式转换或装饰增加无意义工作；内部可使用计算和编程工具，成果交付不变成编程教程。

## 表达与引用

- 四字段组织方式按[题目模版](../assets/题目模版.md#独立使用与组合规则)选择和组合。每项已选业务步骤及各节点的必要材料按[完整交付](出题设计方法.md#每项工作与各阶段材料完整交付)交办；明确正文、底稿、明细、修订和最终文件各自的实际用途与检查方式，不只写“完成全部工作”。

本文件的角色、条件与成果要求是内容契约，不是正文必须逐项照搬的标题或顺序。业务规则与任何表述方法冲突时，始终执行业务规则并调整表达。

- 行业、职业、角色和任务背景相互一致。行业按任务发生组织的主营业务填写，职业按主要负责最终交付的人及当前职业分类要求填写，不把诉讼身份当职业，也不因题目涉及法律就一律归法律服务。
- 公司法务任务仍以公司业务为背景；《公司法务出题准则》仅适用于此类任务。模拟主体、业务条件和履行情景明确标示为题设，不冒充已发生的真实交易或实际使用证据。

- 业务正文引用卷宗材料统一自然写为“附件”“所附材料”“所附卷宗”或直接点明附件内的具体文书名称（如民事判决书、执行裁定书、银行回单等）；`input/attachments/附件1.txt` 仅为出题端内部读取路径，严禁在任务名称、题面、rubric、作答思路或标准答案中出现“附件1”“附件 1”等序号或页码。表头元数据按实际登记原件名填写，不能替代正文阅读或决定任务名称、任务类型。
- 引用案号、日期、主体和金额时核对材料原文，脱敏保持原样。

- 题面不列出正确采信方向、陷阱位置、rubric 或解题步骤。标准答案用正式业务文书表达，完整呈现具体成果，不用“另拟申请”“制作明细”或文件名替代正文。

- **内部信息**：各项业务内容严禁出现数据库编号、本机路径、“附件1”内部输入序号、“评分端／轨迹未传／评测条件不满足／不作为有效专业难度成绩”等评测产线字段、模型成绩、AI 自述或出题流程。
- **出处与原附件**：作者核验、考点必要依据和标答保留法律出处及争议说明；原附件的法条、条款和来源信息不因删除检索讲解而删改。
- **题面事实边界**：题面保留完整事实边界、模拟假设和适用时点，不自动附作者的来源清单。
