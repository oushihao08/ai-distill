# 题目包字段与表达要求

> 本文件说明交付字段并提供可独立选用的表述组合。组合服从业务规则，不是固定题型。花括号内是作者说明，不原样写入；不照搬示例的主体、款项或成果。名称和类型待题面、标答定稿后按最终内容核定。字段对应：题面＝question，标准答案＝reference_answer。

## 表达要求

题面采用符合委托关系的自然专业表达，可用口头交办或书面工作说明等语体，说明律师／法务眼下要办的事。按本案信息组织叙述，不固定开头、句式、语序、段数、小标题或清单样式，不逐项套写“角色—背景—任务—要求”。业务信息复杂时可分段或列项，但以读者理解和办理需要为依据。不要为口语化加入寒暄、口头禅、虚构经历或含糊表达。

本文件各节只对应程序要求的七项字段，不要求题面内部沿用这些标题，也不要求各题采用相同写法。角色、时点、事实、模拟条件、权限和至少三份实质文书的要求仍须交代完整，不能以不固定格式为由省略。

作答思路自然说明判断与取舍，不固定以“先……再……最后……”开篇。标准答案中的沟通说明可自然表达；申请书、合同条款等正式文书按接收对象和实际用途采用合适文体，不强行口语化。考点仍须清楚、自足、可判分；下方R1示意仅说明内容，不要求正文逐字套用固定标签。

## 独立使用与组合规则

本节供没有历史聊天上下文的出题或改写 Agent 使用。目标是使任务名称、prompt、作答思路、标准答案在表达组织上有多种选择，同时完整执行本项目业务规则。四个字段分别选用下表中的方法，组成 N/P/A/S 四项组合；编号只供内部选择，不写入题包。

**业务规则与表述方法冲突时，始终以业务规则为准。** 材料真实性、单方服务、时点与权限、任务深度、成果数量及用途、模拟披露、公平评分、字段契约和正式文书必需格式均不因组合而改变。这里只决定如何表达，不决定哪些业务规则可以省略。设计流程是内部工作顺序，不是正文的固定顺序。

使用步骤：

1. 读取所属 Skill 和本次适用规则，明确是新题生成还是已有题保义改写。新题须按规则阅读材料并设计；已有题只在授权范围内改写，不另造任务。
2. 有本次指定组合时先采用；没有时从四张表分别选择，可在构思时先选，再按材料与规则检验。不默认取第一项，不要求同编号配对。选项不适配时替换该字段的方法，保留其他适配项；也允许采用表外方法。
3. 每项按表中的组织方式写成完整字段，不只是替换开头。方括号是待用本题真实内容填写的位置，不能原样输出；未出现的业务条件不为套方法补造。
4. 整题核对：名称准确指向任务；prompt 不泄露思路或答案；思路解释依据与取舍；标答完成全部任务。四字段可以采用不同顺序，但对象、时点、范围、条件和结论不能互相冲突。
5. 有获准的批次表达摘要时，优先更换已反复使用的整体组合和主导组织方式，不只换名称。无摘要时独立选用并如实保留“未做批次比较”的边界；不读取未授权历史题包，不声称每次必然不同。不新增数据库字段或要求另交报告，内部组合记录仅利用本次已有且支持的记录位置。

### 任务名称 N

准确点出本题的具体事项及核心办理工作，必要时补主体、阶段或成果；不要求把全部交付物塞入名称。可以是交办句或专业短标题，不泄露待求结论。

| 编号／方法 | 如何组织 | 局部结构示意 |
| --- | --- | --- |
| N1 动作起笔 | 先说核心工作，再限定对象及必要阶段 | 核定[对象]的[范围]，准备[关键成果] |
| N2 事项标题 | 以独有业务事项为中心，用处理工作限定 | [具体事项]的[审查／应对／处置] |
| N3 程序定位 | 程序阶段在前，具体对象与工作在后 | [程序阶段]：[对象]的[核心工作] |
| N4 成果用途 | 以主要成果及其服务事项命名 | [事项]的[文书／方案]准备 |
| N5 待决问题 | 以原任务真实待决问题统领，保留专业语气 | [对象]如何[待决动作]：办理意见与[成果] |
| N6 委托对象 | 主体确有辨识价值时先标主体，再说事项 | [本方主体]的[事项]办理 |
| N7 争议焦点 | 用已有争议的具体内容命名，不预判结果 | [争议事项]的回应与[必要工作] |
| N8 衔接工作 | 原任务存在前后衔接时体现两个环节 | 从[已有环节]到[后续环节]的[事项]处理 |
| N9 并列事项 | 两项独立工作同属委托时并列概括 | [事项甲]与[事项乙]的处理安排 |
| N10 条件变化 | 原题已有变化时点明需要更新的工作 | [既定变化]后的[事项]复核与修订 |

### 题面 prompt P

写清真实业务委托即可；可采用口头交办、书面委托、工作说明或专业任务简报的语体，不编造聊天记录、来函或个人经历。表中顺序是可选的正文组织，必要条件和全部成果始终保留。

| 编号／方法 | 适用内容与组织方法 |
| --- | --- |
| P1 当前事项进入 | 从眼下要办的事进入，补充主体、背景和材料，再交代成果及约束。 |
| P2 交付用途进入 | 先交代成果给谁、用于什么，再说明完成它所需的事实、范围和全部任务。 |
| P3 待回应事项进入 | 原题有对方主张时，以待回应事项引出委托，再说明本方权限、材料和成果。 |
| P4 办理节点进入 | 原题阶段明确时，先交代当前节点和可知信息，再展开工作及条件。 |
| P5 背景连贯叙述 | 按理解所必需的背景自然叙述，在相关位置嵌入工作要求，末尾集中补齐交付范围。 |
| P6 工作分组说明 | 复杂任务按实际事项分组，每组说明对象、用途和要求；共同条件集中说明。 |
| P7 委托范围进入 | 先明确为谁做什么及权限边界，再交代材料和具体任务，避免让身份说明占据长篇。 |
| P8 待决问题展开 | 原任务要求决策时，从待决问题展开所需工作；不在问题中暗示答案或指定求解路线。 |
| P9 时间层次组织 | 原题已有不同办理时点时，按时点组织已知信息和工作，保留模拟标识及信息隔离。 |
| P10 成果与条件对应 | 原任务有多个用途不同的成果时，围绕各成果组织专属条件，共用事实仅说明一次。 |
| P11 先总后分 | 简述整体委托，再展开各项实质工作和约束；不用统一的角色—背景—任务四栏填空。 |
| P12 变化前后对照 | 原题已有后续变化时，说明原任务、变化事实及需更新的范围；不提前宣布变化的法律效果。 |

### 作答思路 A

说明本题怎样求解及为何如此处理。可选择下列组织，不要求复刻 prompt 或标答目录；不得以“先、再、最后”替代真实依据关系。

| 编号／方法 | 组织方法与适用边界 |
| --- | --- |
| A1 决定性问题 | 从影响本题处理的核心问题展开，连接材料、规则与具体结果。 |
| A2 结论与依据 | 先概括已有处理结论，再解释成立依据、边界及保留分支；不得把有条件结论写成无条件。 |
| A3 证据关系 | 以材料如何支持、限制或相互对应组织论述，再连接规则及处理。 |
| A4 争议回应 | 按已有争议展开双方解释、采纳理由和可接受替代路径。 |
| A5 条件分支 | 原内容有分支时，分别解释条件与结果，最后指出共用依据；不新增假设。 |
| A6 时间与变化 | 按原有阶段解释依据和结论的变化，说明未受影响部分。 |
| A7 成果反推 | 从各项成果应解决的问题说明必要判断，保留推理依赖，不用文书清单代替分析。 |
| A8 路径比较 | 原内容有不同合法路径时，说明各自条件、后果及选择依据。 |
| A9 范围划分 | 按原有主体、款项或请求范围解释不同处理，合并共用依据但保留独立判断。 |
| A10 核算与法律关系 | 原内容涉及计算时，以组成及口径关系串联计算和法律处理，不只复述数字。 |
| A11 前提与后果 | 以真实判断依赖展开：哪些前提支撑哪些结果、前提不成立时如何处理。 |
| A12 关键取舍串讲 | 用连贯段落解释几项主要取舍及联系，可少用标题，但不能省去复杂条件和分支。 |

### 标准答案-文本 S

这里选择的是整份答案的编排及分析说明方式。申请书、合同条款等具体文书仍保留其适用的正式体例和必需内容；完整正文、依据、计算、分支与成果不能被摘要替代。不要求每题统一采用“分析—清单—文书”三段式。

| 编号／方法 | 组织方法与适用边界 |
| --- | --- |
| S1 逐项完成 | 按题面各项委托交付结果、理由和相应文书，避免遗漏。 |
| S2 成果在前 | 先呈现可使用的成果正文，随后解释依据与必要核算；明确哪些说明不属于文书正文。 |
| S3 处理意见在前 | 先给完整处理意见及条件，再展开论证和各份配套文书。 |
| S4 按成果用途 | 围绕不同接收人或用途编排已有成果，不新增接收人或改变代理立场。 |
| S5 按事项成组 | 各事项分别给出判断、计算及文书，共用依据集中交代且引用清楚。 |
| S6 按办理阶段 | 原题跨阶段时，每阶段呈现当时适用的完整结果，不能混用后续信息。 |
| S7 主文与说明分开 | 将正式文书正文与内部分析明确分区，保留各自用途和全部内容。 |
| S8 分支并列 | 原题确有互斥方案时，分别列条件、结果和可用文本，共用内容可准确引用。 |
| S9 核算后落实 | 原题有实质核算时，先给口径和明细，再落实请求、条款及其他成果。 |
| S10 基础稿与修订稿 | 原题已有变化时，保留初始成果，按原要求给完整修订或准确替换文本，并说明未变部分。 |
| S11 共用依据后分项 | 共用事实和规则只论述一次，再分别完成独立工作，避免共用说明掩盖例外。 |
| S12 连贯意见加文书 | 分析以自然连贯的专业意见呈现，文书另列完整正文，适用于无需密集分支的分析部分。 |

### 可直接选用的组合

以下是无需聊天上下文即可尝试的起点，不是唯一配对，也不是题型配额。原任务不具有适用条件时替换对应项，不为保留组合增造业务。可自由跨行组合。

| 组合 | 字段方法 | 使用说明 |
| --- | --- | --- |
| C1 | N1 / P1 / A1 / S1 | 从当前事项进入，按委托逐项交付。 |
| C2 | N2 / P5 / A12 / S12 | 背景自然叙述，思路连贯解释，正式文书独立呈现。 |
| C3 | N4 / P2 / A7 / S2 | 成果用途明确，分析解释其形成依据。 |
| C4 | N7 / P3 / A4 / S7 | 已有争议需要回应，区分对外文书与分析说明。 |
| C5 | N3 / P4 / A3 / S3 | 程序节点明确，以材料关系支撑处理意见。 |
| C6 | N6 / P7 / A9 / S5 | 委托范围和多个对象明确，按事项组织。 |
| C7 | N5 / P8 / A8 / S8 | 已有决策和替代路径，不把备选方案写成同时实施。 |
| C8 | N8 / P9 / A6 / S6 | 已有前后阶段，按时点隔离信息和成果。 |
| C9 | N9 / P6 / A11 / S11 | 多项工作有共用依据和独立判断，保留各项结果。 |
| C10 | N10 / P12 / A5 / S10 | 原题已有变化与条件，完整处理更新。 |

组合的数量不代表实际表达差异。生成后比较获准可见题目的开场、段落组织、分析推进和收尾；若只是替换主体或几个词，重新组织表达。相同的必要术语、事实边界、文书格式和业务要求可以一致。表达差异不替代项目要求的实质选题差异，也不证明人工原创。

## 已有题目的保义改写

用户只授权“换说法、内容不改”时，本节用于 prompt 与作答思路的表达编辑，不启动重新设计题目。

1. 先逐项列出原文的事实、主体与角色、金额日期、材料范围、办理时点、权限、成果及用途、约束、模拟条件和分支；作答思路另核依据、结论、因果、先后依赖、不确定性及合法替代路径。清单留在内部核对，不添加到交付正文。
2. 从上述四字段方法中选择原文已满足适用条件的组合，只调整句法、衔接、重复表述及不影响逻辑的段落安排。保持“必须／可以／不得／仅限”、数量、条件范围、否定和例外的强度；删去重复句前确认没有独立要求。
3. 改写后逐项双向核对：原有信息均能定位，新文每项事实、要求和判断均有原文对应。不能把建议升级为义务、把可能写成确定、把材料记载写成已认定事实，也不能把原文尚未解决的问题补成结论。
4. prompt 不从作答思路或标答补入提示；作答思路不因更换组织方式改变推理或删去争议分支。保持与现有 rubric、标答的对应关系，不借润色调整考点、难度或交付范围。
5. 原文含糊或自相矛盾，且必须作实质选择才能改写时，单列问题，不自行修正为新题。只读字段时仅评价字段间的一致性，不声称已复核附件事实。文字对照通过不等于新版本已完成作答、评分或交付验证。

本文件仅提供表达与核对依据，不授权覆盖已有题目、同步飞书或复用旧评分；实际写回范围遵守本次用户授权及系统版本规则。

角色：由律师／法务作答，明确代表哪一方、服务谁、有什么权限、能取得哪些材料。代理立场必须改变判断、可用材料、行动边界或交付，不能只换称谓；比较同一卷宗能支持的不同方向，不照搬已有题的角色和立场，一个任务只代表一方。律师写清委托人与承办人的权限；公司法务写清公司业务和审批执行链，本次提供《公司法务出题准则》时按其执行；不得代行其他角色职权。

场景：逐场景明确决策或办理时点、当时可知的信息（当时决策或事后回溯）、成果交给谁使用、做错会影响什么；不提前使用后续裁判和执行结果。组合中区分连续办理、条件触发和互斥备选，不要求同时实施互斥路径。

成果：整体任务至少三份有实质内容的配套文书，逐份说明服务本方的具体用途；不因附加场景机械增加三份，不交付对方立场文书、不重复拆分凑数。

事实边界：附件已确认的事实原样保留；另行设定的模拟条件单独成段并写明“模拟”，给足可判断的主体、范围、时点和关联信息，不宣布其法律效果；脱敏值不补；必要的日历条件、计算端点和精度要交代。

加压：读取并落实[加压机制](../references/出题设计方法.md#加压机制)和[工作范围与强度](../references/题目格式与交付.md#工作范围与强度)。在材料和角色职责能支撑的范围内，只选本题确有用途的机制，不为集齐而拼接。
