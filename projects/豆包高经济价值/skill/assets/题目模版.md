# 题目包字段

按本次返回 schema 填写七项内容；下列花括号、Markdown标题和列表只用于说明字段，不原样进入业务文字。题面＝question，标准答案＝reference_answer。字段契约不固定业务文体或作答工具，业务文字采用[书面表达组合库](书面表达组合库.txt)中的办公写法。

## 表头

题目 ID：{本次 ID，仅用于题包关联，不写入业务正文}
一级／二级行业：{任务发生组织的主营行业及细分行业，按当前分类}
任务形式：{本次契约允许且有真实业务依赖的形式，不机械拆轮}
输入附件：{作答者实际可见的名称或序号}
L1 职业簇／L2 职业：{负责交付的律师／法务岗位，不填当事人的诉讼身份}

## 任务名称

{具体事项及核心办理工作；按最终题面命名，不照抄路径，不提前给待求结论，不堆全部文书名称。}

## 任务类型

{按最终业务用途选本期适用的主要类型，不按附件名分类。}

先按设计方法完成任务盘点、[实质工作选择](../references/出题设计方法.md#按材料展开实质工作)、全部求解及复合判据，再为任务名称、prompt、rubric、作答思路、标准答案-文本分别组合表达。题名概括实际工作，prompt交办对象与可用成果，思路论证处理依据，标答完成正文，rubric验收具体结果。下列字段说明不是题面或答案的固定目录，不把内部盘点、工作分类、写法名称或自查清单作为新增返回字段；不得为采用某种组合反向调整题目内容、方向和难度。

## prompt

{按[场景规范](../references/材料方向场景与交付设计.md)、[设计方法](../references/出题设计方法.md)及[交付规范](../references/题目格式与交付.md)写真实委托：服务一方、办理时点与信息、权限、对象范围、成果用途及必要依据要求。将设计方法确定的全部工作、处理深度、实际文件及核验要求写入委托，不以概要或回复正文替代材料、文书等文件交付。模拟条件明示；不提前给冲突位置、判断结论、分支清单或解法。}

{按[交付规范](../references/题目格式与交付.md#作答端检索依据与交叉核验)明确完整执行与核验义务：深入论证竞争解释、交付完整可用正文，并按成果实际用途交代可编辑文件、活公式重算、版式渲染核对与受阻边界；共同要求集中一次，不加“先详细规划”起手式，不单列“文件交付回执”文种；改写后反查全部任务、文件能力与判据不变。}

{存在后续使用或外部冲击时，依[连续续办设计](../references/出题设计方法.md#已有成果的连续续办)按材料依赖选择单次关键变故、同日多方冲突输入或分阶段推进，交办对既有成果的实际修订与当前有效定稿。作者提供包含常规内容与隐蔽争议的自然事件或待审文本，作答者自行识别问题并决定处理；事件可穿插在相关委托中，不整批套用“基线＋两轮按日来件”结构，单轮内提供全部必要输入并标明模拟边界。}

## 考点 rubric

{整体失效规则依评分规范筛选本题适用风险，落到具体对象、错误行为、核验依据和核心委托后果；多个情形写清独立触发关系及不触发边界。五个风险方向仅供作者审查，不作为固定条款复制到题包。}

{按[评分规范](../references/评分与难度验证.md#考点)划分复合专业结果，完整覆盖且不重复。逐项依据核心结论、决定性依据和成果可用性判断成立或不成立，非实质错漏不否定本项。等权换算百分制，不设固定条数。每题必须写入一处案件化整体失效条件及整题归零后果；按评分规范放入现有字段，不另占得分项或分母。}

{每项写清具体必要判断及联系、决定性材料位置／规则要旨、正确结论及成果要求；计算写口径与关键结果。合法替代、关键失败及共享前提存在时，就近交代实际边界，不逐项套同名栏目。段落、分项或计算明细按内容选择。}

{先检查数据与依据、专业处理、成果使用的覆盖，再按独立用途设项；不固定这三类为三个考点。相关 criterion 写明验收证据和失败影响；共用文件或读回缺口不重复否定已可核验的内容结果，实际使用能力仍须有对应的复合验收。证据未传入、能力不足与明确漏做按评分规范区分。}

{有连续续办时，按[续办结果验收](../references/评分与难度验证.md#连续续办的结果验收)覆盖各节点的新增专业判断和实际修订；具体结果、允许分支、上游错误归属及有效版本边界进入对应criterion。不得仅追加“完成模拟”简单分或沿用未覆盖新任务的旧rubric。}

{评分者不读取 Skill、作答思路或默认标答；每条 criterion 须包含自足的完整判据。正文写具体成立要求及决定性失败影响，不重复“全部满足得分”之类尾句；整体失效条件写清具体行为、证据及全题后果，不固定标题或措辞，不增加schema未声明的字段。参考[复合示例](../references/评分与难度验证.md#关系型考点示例)，不继承示例事实。}

## 作答思路

{用日常专业书面说明完整展开本案决定性记录如何支持、限制或推翻主张，逐项说明规则与条件如何决定处理，细致区分对象、时点、证据效力和适用分支，并解释必要计算及竞争解释的取舍。写已完成的专业论证，不复述通用工作流程，不交Markdown正文、代码或生成脚本。}

{连续续办的论证解释前阶段成立基础如何受到新增信息影响、后续处理为何据此变化，保留未被解决的原有争议；不把事件摘要或工具步骤当作推导。}

## 标准答案-文本

{按日常办公材料或对应正式文书体例全面完成委托，逐项给出必要论证、核算、分支、办理动作和可直接使用的正文。结论、条件与实际条款前后一致；细致区分不同时点、原卷事实、模拟条件及剩余未知，并完整说明其对成果使用的影响。业务正文不带Markdown标记或编程内容，不能只列文件名、“另拟文书”或以代码代替文件交付。}

{采用实质工作选择中的任务时，逐项落实相应成果标准；受影响的正文、计算及关联成果一并更新，保留仍成立的内容。题面要求可使用的稿件时，不能以审查清单、回应提纲或修改建议替代；具体载体和组合依本题用途确定。}

{文件题的文本标答须写全内容及必要公式；实际文件按题面用途制作并读回，JSON字段只保存完整文本并不免除文件制作；按[标答校准](../references/评分与难度验证.md#标准答案)交付文件和核验结果。确因能力限制未生成或评分端未取得时，在完成说明报告具体校准缺口，不把未来操作指令、未执行脚本或虚构链接当执行证据，不新增 schema 字段。}

{连续续办按设计方法交付基线、各阶段材料及整合完成的最终有效文件，明确时点、依据与版本关系。阶段留痕可以记录局部修订，不能代替该阶段需实际使用的完整文件，也不能让接收人自行拼稿；不得只交最终总额而省略中间处理。}

## 独立使用与组合规则

业务设计完成后必读[表述方法](../references/表述方法.md#独立使用与组合规则)和[书面表达组合库](书面表达组合库.txt)。任务名称、prompt、rubric、作答思路、标准答案-文本分别依据本题的触发事实、信息关系、接收人和成果用途选择并组合表达组件。以改写前内容核对全部业务工作、难点与0/1判分关系不变；选型编号和内部组合过程不进入题包。

## 已有题目的保义改写

仅授权润色时按[保义改写规则](../references/表述方法.md#已有题目的保义改写)，不借改写改变题面工作、rubric 或标答结论。

成稿覆盖核对：按[完整阶段材料要求](../references/出题设计方法.md#每项工作与各阶段材料完整交付)逐项核对本题已选工作的输入、处理结果、实际文件与验收。回复正文不替代需要独立使用的文件；所有阶段均保留必要成果及明确有效关系。按[实测验收](../references/评分与难度验证.md#执行复杂度与实测证据)记录难度、轮次、耗时，未测不写已保证。
