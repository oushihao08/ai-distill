# 法律实务出题

从全部附件中选择尚未解决、会影响实际办理的单方法律服务任务，依据真实脱敏卷宗的原始文书形态展开跨源证据消歧、跨层级规则裁决、原始底账重建、在卷旧稿纠偏及配套正式文书定稿，同时提高专业判断难度、有效工具步长与成果交付深度；严禁任何模拟条件、虚拟取阅窗口、题面编造卷外材料或自撰审签结论综述，也不以篇幅、机械重复、隐藏输入或事后压分替代。

## 输入与阅读

- 按用户当前要求、本次任务及实际提供的适用规则确定范围；案例和历史数字不是永久要求。普通出题只读取本次 `input/` 下的清单、附件与本 Skill 目录，不执行仓库 `git` 检查或扫描仓库其他源码目录。
- 设计前读[场景规范](references/材料方向场景与交付设计.md)、[设计方法](references/出题设计方法.md)、[评分规范](references/评分与难度验证.md)，依设计方法完成内部任务盘点。完成求解和判据后，读[表述方法](references/表述方法.md)及[书面表达组合库](assets/书面表达组合库.txt)成稿，再对照同一任务盘点逐项核对最终题包；字段按[字段模板](assets/题目模版.md)。盘点与自检在会话内完成，不另行落盘编写设计核对记录或完成说明文件。这些是必读规则；其他参考按[资料索引](references/资料索引.md)选用。
- 每次选题必须查阅[律师材料—场景—交付物参考](assets/法律垂类评测（材料-场景-交付物）参考.md)；将相关行的工作及成果逐项与本包材料、权限、时点和用途核对，纳入任务盘点；适用者完整完成，不适用者说明具体原因。参考不是穷尽清单或固定套餐，表外有依据的必要工作同样纳入。
- 完整阅读附件；摘要只用于定位。仅使用本次所附真实脱敏卷宗的原始文书及公开法律依据出题；案件事实、程序节点、文书形成与送达时点全部严格取自卷宗原件，严禁添加任何模拟条件、假定前提、虚拟材料取得窗口或题面自编的卷外文书／事件。不读取历史题包、答案、成绩或个人记忆作为新题输入。
- 材料整理提供候选工作分析时，结合本包核实工作、成果用途、依赖及核验建议。依据接收人下一步需要实施的编辑、审签、核算、更新、提交或留档动作，确定必须实际制作并单独具体命名的业务文件及其核验方式；候选分析缺失时仍按正文完成同样判断。保持复合难度与完整交付。
- 以律师／法务身份代表卷宗中真实存在的一方；代理立场、卷宗客观程序节点、当时在卷信息、权限和成果用途相容。不默认执行、核账、和解或固定文书套餐。
- 仅当本次任务明确要求扩展已有题目，并给出须保留的委托方、时点、核心工作与成果范围时，按该范围扩展；否则按新题选题，不从历史题包推测保留范围。
- 显式跨期复用材料时，以本次冻结附件及给定的`authoring_direction`设计独立新题。该方向必须改变原题的核心工作或成果用途；仅换题名、措辞、角色称呼或增加文书数量不算不同方向。不要读取原期题面、答案、评分作为出题输入；若附件不足以支撑给定的新方向，说明缺口并按材料可支持的独立任务收窄，不复制原题。

完整交付覆盖每项已选业务步骤：必要来源对应、争议与异常对象逐笔处理明细、计算与修订底稿、各份独立命名的正式可用正文；题面对作答者逐份指定贴合本案的独立正式文件名称，布置实际文件制作与核验义务；作者在 `reference_answer` 按相同的独立正式文件名分件完整呈现正式法律文书全文、工作簿分表结构与活公式及汇总勾稽（严禁写成脱离具体文书载体的出题人自撰审签结论综述或判卷式说教），附件无争议原始长表按来源、笔数与分项小计归并引用，不逐行重抄。详细论证落实到具体依据、取舍与处理；概括总结、文件名、未来计划不能替代任何已可完成的成果。具体范围与载体按设计方法确定。

PDF 大小与分册要求按[输出形式](references/题目格式与交付.md#输出形式)执行：单份不超过18MB，超限按连续页、页数尽量平均完整拆分并核验，不能截断或降低清晰度。

## 出题标准

<question_standards>

1. 完整读取后，按文书核对来源、时点、证明范围与未决问题；依[任务盘点与范围确定](references/出题设计方法.md#任务盘点与范围确定)找出同一委托方可办的工作及未纳入理由，再定题目范围。涉及多份记录或多个对象时，依[材料到成果的工作链](references/出题设计方法.md#材料到成果的工作链)识别实际分析单位、可核验的中间结果及其后续用途；单案也按适用的业务单位处理，不固定为多案统计题。不得先限定资产类别、文书或单一争点而遗漏相容的实质任务；用户明确限定的范围仍须遵守。新增任务须有独立用途、材料依据及可完成成果，不靠换标题或增加文件份数扩量。
2. 从业务用途反推待解决的专业结果。按[实质工作选择](references/出题设计方法.md#按材料展开实质工作)核对触发输入，展开接管修订、对立回应、关联对象处理或协商条款等适用工作；完成该处的输入核对、缺口处理、求解及成果验收对应，不集齐类型。核清决定性记录的主体、来源、时间、证明范围及相互关系，求出权利、金额、条件、路径和所需文本。
3. 求最合法答案。若抄裁判、查日期、套通用原则或按已给公式代入即可完成主要工作，重新选择材料支持的未解决问题；保留必要输入和合法捷径。
4. 为每个拟计分结果明确共同决定其成立与可用性的多个必要判断，可以前后依赖或共同约束，不要求强行串联。按评分规范的用途与判断边界划分 R：每条独立 R 须含跨源消歧、证明状态缺口、规则时点／跨层级规范适用、多条款同步改定或共同约束取舍；无争议的基础梳理与常规法条套用并入其支撑的决策 R，不单列常规送分项，也不把具有独立证明逻辑与不同下游文书／办理用途的多项实质工作过度压成 2—3 条粗颗粒总包 R（避免单条偶发通过即大幅拉高总分占比）。同源债权、价款或费用的本金、一般利息、迟延履行加倍部分、诉讼／执行费勾稽及法定抵充顺序共同决定同一核定表或同一请求范围时，合并为一条复合结果 R，严禁拆成多条常规算式 R 让下游凭上游基数免责白拿算式分；审查、救济或治理类 R 须落到排他性裁决、具体重复／错列凭证剔除或多条款完整同步改定，使“可确认／仅证明申报／待核实＋附条件申请”的防御套话无法过关。
5. 推演有材料依据的竞争解释、剩余不确定性及适用分支；处理确定可办、附条件可办和受阻范围。所选方案必须同时满足共同约束，分析结论须落实到最终请求、安排或条款。
   按本包真实卷宗自身的文书构成选择任务结构：卷宗内同时包含多阶段真实文书（如原审合同及裁判＋执行立案／查控回执／终本裁定／分配方案／案外人异议，或主合同＋补充协议／催告函／在卷已交申请书）时，站在卷宗最新客观文书节点，按[原卷跨阶段穿透与前手纠偏](references/出题设计方法.md#原卷跨阶段穿透与前手纠偏)设计跨阶段核账重算、在卷旧申请／旧结算口径纠偏与现行救济文书联动定稿；卷宗集中于同一程序阶段的多源证据冲突（起诉或答辩主张、合同条款、银行回单流水、送达回证／笔录与裁判认定差异）时，围绕当前客观程序节点深挖全卷逐笔消歧、规则裁决与多成果同步定稿。严禁将同一套卷宗人为切分为前后两次“材料取得窗口／补交节点”，严禁在题面编造卷宗外的来函、补充协议、登记回件、对账单或待审草稿；待审查或待反驳的主张、条款、旧申请及流水必须全部来自所附真实卷宗文书，法律判断和缺陷发现留给作答者。
6. 先完成全部标准答案，再编写自足 rubric，最后逐项反查已选独立任务是否都在题面交办了独立具体命名的可使用成果及必要依据要求；核对材料、处理结果、结论与各成果之间的同一对象、口径和状态。只出现在 rubric 或标答中的工作不能计入题目任务。隐含的是解题时必须发现的问题，不是未告知的交付义务。

### 题面与成果

- 写清谁为哪一方办什么、权限与范围、成果给谁使用，起笔切入点须随本案卷宗真实触发点轮换（从生效裁判履行僵局、在卷旧申请与裁判矛盾、法定救济期限、法院查控／分配回执或接收人下一步动作进入，不默认以当事人姓名作首词，也不在首段堆砌“委托设定声明＋不递交／不外联／不代签／不和解四连禁令”固定四步式；越权边界随具体对外文书或办理动作就近限定）。输入按真实脱敏卷宗的原始文书分件组织，引用材料时直接点明所附卷宗中的具体原始文书名称（如《民事起诉状》、具体案号《民事判决书》《执行裁定书》《送达回证》、银行交易流水等，同名或同案多件时加注文号、日期或主体区分）或自然称“所附卷宗”“所附材料”，严禁在任何字段出现“附件1”“附件 1”（`附件1.txt`仅为出题目录内部文件名）、`材料-xxxx.docx`匿名哈希名、“合并卷宗”或导出页码。案件事实全部保留在卷宗原件中，不在题面单拎错误语句点名反问、指出冲突位置或把 rubric 改写为交办清单；不在题面喂给法定起算日、节假日顺延规则、折算基数或法定清偿抵充顺序。
- 真实缺口给出可判断的分支和行动边界；卷宗证据已足够的部分必须完成。严禁在题面或任何字段使用“模拟”“模拟委托”“按模拟于某日接办”“本题模拟”“办理演练”“假定”“假设”“题设”“材料取得窗口”等模拟化条件或双窗口切分。承办身份与委托目标直接按真实法律实务交办陈述，当前办理节点锚定所附卷宗最新客观文书已达到的程序阶段；利息、迟延履行加倍部分或法定期间确需统一核算截止日的，优先采用卷内相关程序文书载明的客观日期，或直接写明具体计息截止日期，对卷内未记载后续清偿或送达回执不全的事项要求按现有卷宗凭证核定并列明待核边界与条件分支，严禁用“假定截至某日无新增受偿”等虚拟假设替代证据核查，也不改写既判事实、脱敏值或原件。
- 允许并按任务需要要求联网检索权威法源原文、附件处理、计算、生成及导出 PDF、DOCX、XLSX 等成果，不设纯文本或禁止文件的统一限制。题面必须为每份应交付成果指定贴合本案主体、案由或程序动作的独立正式文件名称（要求作答者按独立文件名分别制作交付，严禁将全部工作笼统包成一份泛化的“初办意见／审签结论”）。需要编辑、审签、提交或交接留档的成果，必须完整落实四项硬性交付动作：①制作单独命名的可编辑正式文书（DOCX）及全部由公式驱动的多分表核算工作簿（XLSX），实际执行公式重算并读回结果；②围绕本案卷宗内真实存在的争议款项采信分歧、关键起止时点竞争或备选救济口径，在工作簿内设置公式驱动的备选口径／敏感性联动测算栏（或对比分表）验证公式自动联动并读回重算值，与正式报送主表明确区分（严禁构造虚拟补件窗口，也严禁使用“在与案件事实隔离的核验副本中改变一项关键输入”之类机械套话）；③将全套正式成果（包括专项法律审查意见／复盘报告全文、全部正式对外诉讼或执行文书，以及经横向排版或列宽适配后的多栏核算总表／附表）悉数导出为独立命名的分页 PDF，严禁只导短篇对外申请或列文件名；④将导出的全部 PDF 逐页转成页面图像检查版面与跨件数据一致性（排查宽表跨页横向劈裂、落款签章孤行跨页及正文与附表／对外文书的金额条款出入，发现瑕疵修改源 DOCX/XLSX 后重新导出核准）。
- 按[工具工作与有效步长](references/出题设计方法.md#工具工作与有效步长)选择适用环节。题目要求与环境是否支持分别记录；必要能力尚未接通时标明执行缺口，补齐后实测，不擅自把已确定的文件交付或检索工作降为纯文本替代，也不把环境失败计作专业失分。
- 标答（`reference_answer`）必须按题面指定的各份独立正式文件名称分件完整交付正式成稿：逐件标明独立正式文件名，内部严格采用对应法律文书（起诉状、上诉状、执行申请书、执行异议书、合同修订定稿、专项法律审查报告等）及多表核算工作簿在真实执业中的原生正式体例，逐项落回所附卷宗具体原始文书名称、文号、日期与金额依据；严禁写成脱离具体文书载体的“出题人自撰审签结论正文”或把判分禁令改写成散文式评卷说教，也不整批套用“意见书标题＋致／收件人＋办理基准日”同一三行信头（可按本案主交付物分件直接切入）。各独立命名成果口径一致，数量由独立用途决定，不用“另行起草”“待核后处理”代替已可完成的工作。
- 卷宗包含多阶段真实文书（如历审裁判与执行查控／终本／异议文书并存，或原协议与补充协议／往来函件／在卷旧申请并存）时，题面基于真实全卷交办跨阶段穿透核对与现行有效成果定稿，思路解释不同阶段在卷文书如何制约当前请求范围，标答交付现行正式成稿及跨阶段核定明细，rubric按[跨阶段原卷核改与联动试算的验收](references/评分与难度验证.md#跨阶段原卷核改与联动试算的验收)自足判定。单轮题一次基于真实在卷文书交办完毕，不切分虚拟收件窗口，也不要求等待新的用户回复。
- 成果须衔接本题实际业务的使用流程与后续程序。依[成果使用与办理交接](references/出题设计方法.md#成果使用与办理交接)，要求作答者在委托范围内详细、完整交代接收人如何使用各份独立命名的已完成成果、落实当前办理及处理证据缺口条件；按本案选择必要手续、配套原卷材料与交接内容，不套固定业务流程。题面交办、标答实际完成，rubric按相应专业结果验收。
- 题面的处理深度、完整交付及文件核验要求按[交付规范](references/题目格式与交付.md#作答端检索依据与交叉核验)点名本案具体独立命名的文书与底稿名称，拆散融入对应成果段落与交接要求中；Skill 中的概念缩略词（如“多表活公式XLSX”“定版分页PDF”“宽表横向截断成碎页”“发现问题回改源文件后重导重验”）仅供作者把握要求边界，严禁原词照抄进业务正文，也严禁在题面末尾单挂一段统包式技术收尾。不在开头要求“先详细规划”，不单交独立的“文件交付回执”。成稿后按任务盘点逐项核对题面、标答和 rubric 的工作、独立命名成果与判据，表达去同构绝不缩减任何任务强度、压分判据或文件渲染重算动作。

## 评分标准

<scoring_standards>
