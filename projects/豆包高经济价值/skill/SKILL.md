# 法律实务出题

从全部附件中选择尚未解决、会影响实际办理的单方法律服务任务，依据材料自身形态展开跨源证据消歧、跨层级规则裁决、原始底账重建、正式文稿定稿或确有依赖的跨节点修订，同时提高专业判断难度、有效工具步长与成果交付深度；不以篇幅、机械重复、隐藏输入或事后压分替代。

## 输入与阅读

- 按用户当前要求、本次任务及实际提供的适用规则确定范围；案例和历史数字不是永久要求。普通出题只读取本次 `input/` 下的清单、附件与本 Skill 目录，不执行仓库 `git` 检查或扫描仓库其他源码目录。
- 设计前读[场景规范](references/材料方向场景与交付设计.md)、[设计方法](references/出题设计方法.md)、[评分规范](references/评分与难度验证.md)，依设计方法完成内部任务盘点。完成求解和判据后，读[表述方法](references/表述方法.md)及[书面表达组合库](assets/书面表达组合库.txt)成稿，再对照同一任务盘点逐项核对最终题包；字段按[字段模板](assets/题目模版.md)。盘点与自检在会话内完成，不另行落盘编写设计核对记录或完成说明文件。这些是必读规则；其他参考按[资料索引](references/资料索引.md)选用。
- 每次选题必须查阅[律师材料—场景—交付物参考](assets/法律垂类评测（材料-场景-交付物）参考.md)；将相关行的工作及成果逐项与本包材料、权限、时点和用途核对，纳入任务盘点；适用者完整完成，不适用者说明具体原因。参考不是穷尽清单或固定套餐，表外有依据的必要工作同样纳入。
- 完整阅读附件；摘要只用于定位。仅使用本次案件材料、公开法律依据及明确披露且获准的模拟条件。不读取历史题包、答案、成绩或个人记忆作为新题输入。
- 材料整理提供候选工作分析时，结合本包核实工作、成果用途、依赖及核验建议。依据接收人下一步需要实施的编辑、审签、核算、更新、提交或留档动作，确定必须实际制作的业务文件及其核验方式；候选分析缺失时仍按正文完成同样判断。保持复合难度与完整交付。
- 以律师／法务身份代表一方；代理立场、办理时点、当时可得信息、权限和成果用途相容。不默认执行、核账、和解或固定文书套餐。
- 仅当本次任务明确要求扩展已有题目，并给出须保留的委托方、时点、核心工作与成果范围时，按该范围扩展；否则按新题选题，不从历史题包推测保留范围。
- 显式跨期复用材料时，以本次冻结附件及给定的`authoring_direction`设计独立新题。该方向必须改变原题的核心工作或成果用途；仅换题名、措辞、角色称呼或增加文书数量不算不同方向。不要读取原期题面、答案、评分作为出题输入；若附件不足以支撑给定的新方向，说明缺口并按材料可支持的独立任务收窄，不复制原题。

完整交付覆盖每项已选业务步骤：必要来源对应、争议与异常对象逐笔处理明细、计算与修订底稿、各节点可用正文；题面对作答者按业务用途布置实际文件制作与核验义务，作者在 `reference_answer` 完整呈现各阶段正式正文、工作簿表结构与活公式及汇总勾稽，附件无争议原始长表按来源、笔数与分项小计归并引用，不逐行重抄。详细论证落实到具体依据、取舍与处理；概括总结、文件名、未来计划不能替代任何已可完成的成果。具体范围与载体按设计方法确定。

## 出题标准

<question_standards>

1. 完整读取后，按文书核对来源、时点、证明范围与未决问题；依[任务盘点与范围确定](references/出题设计方法.md#任务盘点与范围确定)找出同一委托方可办的工作及未纳入理由，再定题目范围。涉及多份记录或多个对象时，依[材料到成果的工作链](references/出题设计方法.md#材料到成果的工作链)识别实际分析单位、可核验的中间结果及其后续用途；单案也按适用的业务单位处理，不固定为多案统计题。不得先限定资产类别、文书或单一争点而遗漏相容的实质任务；用户明确限定的范围仍须遵守。新增任务须有独立用途、材料依据及可完成成果，不靠换标题或增加文件份数扩量。
2. 从业务用途反推待解决的专业结果。按[实质工作选择](references/出题设计方法.md#按材料展开实质工作)核对触发输入，展开接管修订、对立回应、关联对象处理或协商条款等适用工作；完成该处的输入核对、缺口处理、求解及成果验收对应，不集齐类型。核清决定性记录的主体、来源、时间、证明范围及相互关系，求出权利、金额、条件、路径和所需文本。
3. 求最合法答案。若抄裁判、查日期、套通用原则或按已给公式代入即可完成主要工作，重新选择材料支持的未解决问题；保留必要输入和合法捷径。
4. 为每个拟计分结果明确共同决定其成立与可用性的多个必要判断，可以前后依赖或共同约束，不要求强行串联。按评分规范的用途与判断边界划分 R：每条独立 R 须含跨源消歧、证明状态缺口、规则时点／跨层级规范适用、多条款同步改定或共同约束取舍；无争议的基础梳理与常规法条套用并入其支撑的决策 R，不单列常规送分项，也不把证明逻辑各自独立的多组异质工作捆成一条。同源债权、价款或费用的本金、一般利息、迟延履行加倍部分、诉讼／执行费勾稽及法定抵充顺序共同决定同一核定表或同一请求范围时，合并为一条复合结果 R，严禁拆成多条常规算式 R 让下游凭上游基数免责白拿算式分；审查、救济或治理类 R 须落到排他性裁决、具体重复／错列凭证剔除或多条款完整同步改定，使“可确认／仅证明申报／待核实＋附条件申请”的防御套话无法过关。
5. 推演有材料依据的竞争解释、剩余不确定性及适用分支；处理确定可办、附条件可办和受阻范围。所选方案必须同时满足共同约束，分析结论须落实到最终请求、安排或条款。
   按本包材料形态选择真实任务结构（如前手遗留文稿对照原始卷宗与后台回执直接纠偏定稿、多表原始流水去重核账与反提案定稿、公司章程／决议多条款冲突同步改定，或确有后续状态依赖时按[已有成果的连续续办](references/出题设计方法.md#已有成果的连续续办)展开跨节点修订），结合同期白名单摘要避开整批重复同一业务切口或固定“首次基线全套文书＋次日两三封引号来函＋保留双版本”套路。严禁构造对方或当事人在一段话内集中暴露多处常识性违法主张的“稻草人自爆来函”；待审或模拟材料须采用混有常规有效内容与隐蔽瑕疵的客观文书、留白审批表、中性回执或条款改稿，法律判断和缺陷发现留给作答者。
6. 先完成全部标准答案，再编写自足 rubric，最后逐项反查已选独立任务是否都在题面交办了可使用成果及必要依据要求；核对材料、处理结果、结论与各成果之间的同一对象、口径和状态。只出现在 rubric 或标答中的工作不能计入题目任务。隐含的是解题时必须发现的问题，不是未告知的交付义务。

### 题面与成果

- 写清谁在何时为哪一方办什么、权限与范围、成果给谁使用。事实尽量保留在附件，待审原稿、提案或客观回执提供混有常规内容与未标明缺陷的自然全文，不在题面单拎错误语句点名反问、指出冲突位置或把 rubric 改写为交办清单；不在题面喂给法定起算日、节假日顺延规则、折算基数或法定清偿抵充顺序（仅委托方确有特殊内部考核口径时明示内部测算条件）。
- 真实缺口给出可判断的分支和行动边界；附件已足够的部分必须完成。模拟记录明确标注，不改写既判事实、脱敏值或原件，不用模拟假设消除主要争议。
- 允许并按任务需要要求联网检索、附件处理、计算、生成及导出 PDF、DOCX、表格等成果，不设纯文本或禁止文件的统一限制。优先设计前一工具结果决定后续判断或操作的任务；需要编辑、审签、提交或交接留档的成果，除可编辑 DOCX 与多表活公式 XLSX 外，要求将全套正式签批与报送成果——含主审查报告／法律意见书、全部正式对外文书，以及经横向或缩印适配的多栏核账总表／活公式计算附表——导出为定版分页 PDF，并对全套 PDF 逐页渲染目检版式与跨件一致性（消除宽表横向截断成单列碎页、签章孤行跨页及主报告与附表／对外文书的数额条款错位，发现问题回改源 DOCX/XLSX 重导重验），不只导出短篇对外申请或在回答中写文件名。
- 按[工具工作与有效步长](references/出题设计方法.md#工具工作与有效步长)选择适用环节。题目要求与环境是否支持分别记录；必要能力尚未接通时标明执行缺口，补齐后实测，不擅自把已确定的文件交付或检索工作降为纯文本替代，也不把环境失败计作专业失分。
- 标答交付完整分析、必要核算和可使用的正文；各成果口径一致。数量由独立用途决定，不用“另行起草”“待核后处理”代替已可完成的工作。
- 含动态输入或续办的题面须交代各事件可见信息及处理交付，思路解释状态变化如何改变处理，标答完成实际修订结果，rubric按[续办结果验收](references/评分与难度验证.md#连续续办的结果验收)自足判定。业务阶段不等于交互轮次；单轮题一次提供全部事件，不要求等待新的用户回复。
- 成果须衔接本题实际业务的使用流程与后续程序。依[成果使用与办理交接](references/出题设计方法.md#成果使用与办理交接)，要求作答者在委托范围内详细、完整交代接收人如何使用已完成成果、落实当前办理及处理后续条件；按本案选择必要手续、配套材料与交接内容，不套固定业务流程。题面交办、标答实际完成，rubric按相应专业结果验收。
- 题面的处理深度、完整交付及文件核验要求按[交付规范](references/题目格式与交付.md#作答端检索依据与交叉核验)随具体成果用途自然落实：明确要求办结全部可办事项、深入论证竞争解释并交付完整可用正文，将文件制作、活公式重算、版式渲染核对与未决限制融入对应成果的使用要求中；不在开头要求“先详细规划”，不单交独立的“文件交付回执”，也不贴通用技术收尾。成稿后按任务盘点逐项核对题面、标答和 rubric 的工作、成果与判据，改写不得缩减任务或文件能力。

</question_standards>

## 评分标准

<scoring_standards>

- 每项评价一个复合专业结果，依据核心结论、决定性依据与成果可用性判断成立或不成立。要求完整处理，但不影响结论和使用的次要错漏不单独导致本项失败。各项等权，百分制按成立项占比换算；max_score仅按当前结构化契约填写，不在判据正文反复写分值或计分口号。

<whole_answer_validity required="every_question">
按评分规范，从服务立场、事实采信、核心依据可追溯性、有效成果一致性及决定性法律推导审查本题风险；将适用风险具体化为可判定的失效行为，不把五个方向照抄成每题固定条款。明确其损害的是本题哪项核心权利、决策或办理用途，以及为何足以使核心委托整体失效；依法确认不利事实、合理推论和有依据的不同法律解释不因不利于委托人而触发。
每道新题依设计方法，在确定核心成果及求解标答时同步识别其成立基础，再将已论证的整体失效条件写入 rubric 一处：明确具体触发行为、可核验证据、核心委托整体失效的原因及整题最终得分归零的后果。普通单项错误、次要遗漏和局部文件问题不自动升级；单一决定性错误足以破坏核心委托时可以触发。证据不足、合法替代、条件备选和交付前已经纠正的错误不推定触发。
按评分规范将该规则放入评分者实际收到的字段；不另增普通得分项或分母。每题必须具备该机制，触发情形和措辞依本案确定；不把“一票否决”作为固定标题，不复制同一结尾，XML仅用于作者指令，不进入业务正文。提交前核对规则已落入题包且完整正确解不会触发。
</whole_answer_validity>
- 先按[评价维度](references/评分与难度验证.md#从评价维度形成复合考点)检查数据与依据、专业处理、成果使用的覆盖，再按独立用途划分结果；不照搬案例的条数、主题分组或成果套餐。每个必要条件都须说明缺失将造成的实质后果，背景叙述和可替代证据不升级为逐项背诵要求。
- 判据写清必要条件、依据、具体结果、允许替代及关键失败；不能只写“分析充分”或“符合标答”。附件依据写“依据附件1”及决定性记录内容，不写页码；导出 DOCX 后页码可能变化。评分者不读取本 Skill、思路或默认标答，判分所需信息必须进入 rubric。
- 同一判断不因出现在多个成果中重复计分；共享前提的归属及下游独立条件在作答前写清。普通考点错误不连带否定全题，整体失效仅按本题预先写明的条件判断。不因看到答案或目标分数改变本题标准。
- 按[内容、文件和执行的归属](references/评分与难度验证.md#内容文件和执行的归属)设置验收证据：实际文件及读回用于检验相应的业务使用能力，不逐条复制共用文件门槛，不设只有文件名或调用次数的简单分。能力不足、证据未传入与作答明确漏做分开；边界写入相关 criterion，不能只留在 Skill。

提交前按评分规范检查：完整正确解满足内容判据；漏掉任一必要判断的近似答案不能通过对应 R；表达凝练但内容充分的合法替代正常通过；通用建议、局部正确但最终成果矛盾不能冒充完成。普通出题用计算脚本核验全部数据与公式闭环并联网核对法源原文，不在出题会话内制作 DOCX/XLSX/PDF 校准实物或渲染读图；仅在专门获准制作独立实物校准样本时才生成真实文件核验文件判据。条目覆盖完整、无重复，材料充分，题面未泄解法。

</scoring_standards>

## 多样性

<diversity_standards>

- 表达按真实委托组织。先从本包确定代理立场、核心工作、分析单位、成果用途及真实依赖，再据这些关系选择叙述入口、展开顺序和成果结构；题目之间的差异由各自材料与专业任务形成，若本次提供同期白名单设计摘要，用于比较业务目标、核心工作及成果用途，避免仅换名称的重复；不读取历史题包、答案或评分。未提供时仅按本包设计，不虚构跨题多样性已验证。
- 连续续办的事件来源、变化性质、先后关系及修订载体按本案组合；表达库呈现已确定的业务关系，不反向限定为收款、退费、固定阶段数或文件套餐。不同阶段可用完整稿或可直接采用的替换正文衔接，必须能辨认各阶段处理结果与最终有效成果。
- 任务名称、prompt、rubric、作答思路、标准答案-文本分别从组合库选择适用的起笔、展开、局部写法和收束，再跨字段组合；示范搭配可拆散，不作为整套模板轮换。先确定专业内容，再选表达；不得为适配写法更改题目方向、任务、难点、成果用途或判据。按表述方法核对表达前后的全部工作及逐条判定一致。
- 五字段业务文字采用日常书面表达，不用Markdown标记、代码块、生成脚本或编程教程。题面中的业务工作涉及编辑、审签、数据运算、持续更新、正式提交或固定留档时，要求作答者实际生成能完成相应动作的业务文件，并完成内容、数据、公式、版式或打开结果的核验。阅读稿考点用1、2、3普通编号，结构化评分ID与max_score不变。思路写本案论证，标答写完整可用成果；作者自查、计分过程、模板选型及模型实测不进入二者。
