# 法律实务出题

从全部附件中选择尚未解决、会影响实际办理的单方法律服务任务，依据材料自身形态展开跨源证据消歧、跨层级规则裁决、原始底账重建、正式文稿定稿或确有依赖的跨节点修订，同时提高专业判断难度、有效工具步长与成果交付深度；不以篇幅、机械重复、隐藏输入或事后压分替代。

## 输入与阅读

- 按用户当前要求、本次任务及实际提供的适用规则确定范围；案例和历史数字不是永久要求。普通出题只读取本次 `input/` 下的清单、附件与本 Skill 目录，不执行仓库 `git` 检查或扫描仓库其他源码目录。
- 设计前读[场景规范](references/材料方向场景与交付设计.md)、[设计方法](references/出题设计方法.md)、[评分规范](references/评分与难度验证.md)，依设计方法完成内部任务盘点。完成求解和判据后，读[表述方法](references/表述方法.md)及[书面表达组合库](assets/书面表达组合库.txt)成稿，再对照同一任务盘点逐项核对最终题包；字段按[字段模板](assets/题目模版.md)。盘点与自检在会话内完成，不另行落盘编写设计核对记录或完成说明文件。这些是必读规则；其他参考按[资料索引](references/资料索引.md)选用。
- 每次选题必须查阅[律师材料—场景—交付物参考](assets/法律垂类评测（材料-场景-交付物）参考.md)；将相关行的工作及成果逐项与本包材料、权限、时点和用途核对，纳入任务盘点；适用者完整完成，不适用者说明具体原因。参考不是穷尽清单或固定套餐，表外有依据的必要工作同样纳入。
- 完整阅读附件；摘要只用于定位。仅使用本次案件材料、公开法律依据及明确披露且获准的模拟条件。不读取历史题包、答案、成绩或个人记忆作为新题输入。
- 材料整理提供候选工作分析时，结合本包核实工作、成果用途、依赖及核验建议。依据接收人下一步需要实施的编辑、审签、核算、更新、提交或留档动作，确定必须实际制作的业务文件及其核验方式；候选分析缺失时仍按正文完成同样判断。保持复合难度与完整交付。
- 以律师／法务身份代表一方；代理立场、办理时点、当时可得信息、权限和成果用途相容。不默认执行、核账、和解或固定文书套餐。
- 仅当本次任务明确要求扩展已有题目，并给出须保留的委托方、时点、核心工作与成果范围时，按该范围扩展；否则按新题选题，不从历史题包推测保留范围。
- 显式跨期复用材料时，以本次冻结附件及给定的`authoring_direction`设计独立新题。该方向必须改变原题的核心工作或成果用途；仅换题名、措辞、角色称呼或增加文书数量不算不同方向。不要读取原期题面、答案、评分作为出题输入；若附件不足以支撑给定的新方向，说明缺口并按材料可支持的独立任务收窄，不复制原题。

完整交付覆盖每项已选业务步骤：必要来源对应、争议与异常对象逐笔处理明细、计算与修订底稿、各节点可用正文；题面对作答者按业务用途布置实际文件制作与核验义务，作者在 `reference_answer` 完整呈现各阶段正式正文、工作簿表结构与活公式及汇总勾稽，附件无争议原始长表按来源、笔数与分项小计归并引用，不逐行重抄。详细论证落实到具体依据、取舍与处理；概括总结、文件名、未来计划不能替代任何已可完成的成果。具体范围与载体按设计方法确定。

## 出题标准

<question_standards>

1. 完整读取后，按文书核对来源、时点、证明范围与未决问题；依[任务盘点与范围确定](references/出题设计方法.md#任务盘点与范围确定)找出同一委托方可办的工作及未纳入理由，再定题目范围。涉及多份记录或多个对象时，依[材料到成果的工作链](references/出题设计方法.md#材料到成果的工作链)识别实际分析单位、可核验的中间结果及其后续用途；单案也按适用的业务单位处理，不固定为多案统计题。不得先限定资产类别、文书或单一争点而遗漏相容的实质任务；用户明确限定的范围仍须遵守。新增任务须有独立用途、材料依据及可完成成果，不靠换标题或增加文件份数扩量。
2. 从业务用途反推待解决的专业结果。按[实质工作选择](references/出题设计方法.md#按材料展开实质工作)核对触发输入，展开接管修订、对立回应、关联对象处理或协商条款等适用工作；完成该处的输入核对、缺口处理、求解及成果验收对应，不集齐类型。核清决定性记录的主体、来源、时间、证明范围及相互关系，求出权利、金额、条件、路径和所需文本。
3. 求最合法答案。若抄裁判、查日期、套通用原则或按已给公式代入即可完成主要工作，重新选择材料支持的未解决问题；保留必要输入和合法捷径。
4. 为每个拟计分结果明确共同决定其成立与可用性的多个必要判断，可以前后依赖或共同约束，不要求强行串联。按评分规范的用途与判断边界划分 R：每条独立 R 须含跨源消歧、证明状态缺口、规则时点／跨层级规范适用、多条款同步改定或共同约束取舍；无争议的基础梳理与常规法条套用并入其支撑的决策 R，不单列常规送分项，也不把具有独立证明逻辑与不同下游文书／办理用途的多项实质工作过度压成 2—3 条粗颗粒总包 R（避免单条偶发通过即大幅拉高总分占比）。同源债权、价款或费用的本金、一般利息、迟延履行加倍部分、诉讼／执行费勾稽及法定抵充顺序共同决定同一核定表或同一请求范围时，合并为一条复合结果 R，严禁拆成多条常规算式 R 让下游凭上游基数免责白拿算式分；审查、救济或治理类 R 须落到排他性裁决、具体重复／错列凭证剔除或多条款完整同步改定，使“可确认／仅证明申报／待核实＋附条件申请”的防御套话无法过关。
5. 推演有材料依据的竞争解释、剩余不确定性及适用分支；处理确定可办、附条件可办和受阻范围。所选方案必须同时满足共同约束，分析结论须落实到最终请求、安排或条款。
   按本包材料形态选择真实任务结构：材料客观支持履行推进、程序衔接、查控分配回执、对手异议或条款往复且存在前后承接依赖时，优先按[已有成果的连续续办](references/出题设计方法.md#已有成果的连续续办)设计跨节点动态任务（单次关键变故连锁重算、同日多方客观冲突输入或先后阶段推进）；材料天然集中于遗留文稿对照原卷纠偏、多表原始流水去重核账或章程／决议多条款冲突同步改定时，采用单窗口深度定稿，避免整批倒向单一静态结构或套用“首次基线全套文书＋次日两三封引号来函＋保留双版本”套路。严禁构造对方或当事人在一段话内集中暴露多处常识性违法主张的“稻草人自爆来函”；待审或模拟材料须采用混有常规有效内容与隐蔽瑕疵的客观文书、留白审批表、中性回执或条款改稿，法律判断和缺陷发现留给作答者。
6. 先完成全部标准答案，再编写自足 rubric，最后逐项反查已选独立任务是否都在题面交办了可使用成果及必要依据要求；核对材料、处理结果、结论与各成果之间的同一对象、口径和状态。只出现在 rubric 或标答中的工作不能计入题目任务。隐含的是解题时必须发现的问题，不是未告知的交付义务。

### 题面与成果

- 写清谁在何时为哪一方办什么、权限与范围、成果给谁使用，但起笔切入点须随本案触发点轮换（从生效裁判履行僵局、待审稿矛盾、程序期限、监管／执行回执或接收人决策用途进入，不默认以当事人姓名作首词，也不在首段堆砌“委托设定声明＋不递交／不外联／不代签／不和解四连禁令”固定四步式；越权边界随具体对外文书或办理动作就近限定）。引用卷宗材料统一自然称为“附件”“所附材料”或直接点明具体文书名称，严禁在任何字段写“附件1”“附件 1”（`附件1.txt`仅为出题目录内部文件名）。事实尽量保留在附件，待审原稿、提案或客观回执提供混有常规内容与未标明缺陷的自然全文，不在题面单拎错误语句点名反问、指出冲突位置或把 rubric 改写为交办清单；不在题面喂给法定起算日、节假日顺延规则、折算基数或法定清偿抵充顺序（仅委托方确有特殊内部考核口径时明示内部测算条件）。
- 真实缺口给出可判断的分支和行动边界；附件已足够的部分必须完成。模拟时点、委托或假定测算前提必须明确标示模拟／假定身份（严禁伪装成原卷既成事实），采用贴合本案情境的自然业务措辞，不每题复读“该委托关系及办理时点为本题设定”同一句式；不改写既判事实、脱敏值或原件，不用模拟假设消除主要争议。
- 允许并按任务需要要求联网检索权威法源原文、附件处理、计算、生成及导出 PDF、DOCX、XLSX 等成果，不设纯文本或禁止文件的统一限制。优先设计前一工具结果决定后续判断或操作的任务；需要编辑、审签、提交或交接留档的成果，必须完整落实四项硬性交付动作：①制作可编辑正式文稿（DOCX）及全部由公式驱动的多分表核算工作簿（XLSX），实际执行公式重算并读回结果；②工作簿须完成动态联动核验（跨节点续办题以新增事件重算核验；单窗口静态题须结合本案争议款项认定或关键时点设置业务敏感性／备选情景试算栏验证公式自动联动并读回，与正式主表区分，严禁使用“在与案件事实隔离的核验副本中改变一项关键输入”之类机械套话）；③将全套正式成果（包括主审查报告／法律意见书全文、全部正式对外文书，以及经横向排版或列宽适配后的多栏核算总表／附表）悉数导出为分页 PDF，严禁只导短篇对外申请或列文件名；④将导出的全部 PDF 逐页转成页面图像检查版面与跨件数据一致性（排查宽表跨页横向劈裂、落款签章孤行跨页及正文与附表／对外文书的金额条款出入，发现瑕疵修改源 DOCX/XLSX 后重新导出核准）。
- 按[工具工作与有效步长](references/出题设计方法.md#工具工作与有效步长)选择适用环节。题目要求与环境是否支持分别记录；必要能力尚未接通时标明执行缺口，补齐后实测，不擅自把已确定的文件交付或检索工作降为纯文本替代，也不把环境失败计作专业失分。
- 标答交付完整分析、必要核算和可使用的正文；各成果口径一致，首屏直接按本案主成果体例切入（如正式对外文书前置、无信头直入争议结论、内部呈批签报或核心账表先行），严禁整批套用“意见书标题＋致／收件人＋办理基准日”三行公文信头。数量由独立用途决定，不用“另行起草”“待核后处理”代替已可完成的工作。
- 含动态输入或续办的题面须交代各事件可见信息及处理交付，思路解释状态变化如何改变处理，标答完成实际修订结果，rubric按[续办结果验收](references/评分与难度验证.md#连续续办的结果验收)自足判定。业务阶段不等于交互轮次；单轮题一次提供全部事件，不要求等待新的用户回复。
- 成果须衔接本题实际业务的使用流程与后续程序。依[成果使用与办理交接](references/出题设计方法.md#成果使用与办理交接)，要求作答者在委托范围内详细、完整交代接收人如何使用已完成成果、落实当前办理及处理后续条件；按本案选择必要手续、配套材料与交接内容，不套固定业务流程。题面交办、标答实际完成，rubric按相应专业结果验收。
- 题面的处理深度、完整交付及文件核验要求按[交付规范](references/题目格式与交付.md#作答端检索依据与交叉核验)点名本案具体文书与表册名称，拆散融入对应成果段落与审签归档要求中；Skill 中的概念缩略词（如“多表活公式XLSX”“定版分页PDF”“宽表横向截断成碎页”“发现问题回改源文件后重导重验”）仅供作者把握要求边界，严禁原词照抄进业务正文，也严禁在题面末尾单挂一段统包式技术收尾。不在开头要求“先详细规划”，不单交独立的“文件交付回执”。成稿后按任务盘点逐项核对题面、标答和 rubric 的工作、成果与判据，表达去同构绝不缩减任何任务强度、压分判据或文件渲染重算动作。

</question_standards>

## 评分标准

<scoring_standards>

- 每项评价一个复合专业结果，依据核心结论、决定性依据与成果可用性判断成立或不成立。要求完整处理，但不影响结论和使用的次要错漏不单独导致本项失败。各项等权，百分制按成立项占比换算；max_score仅按当前结构化契约填写，不在判据正文反复写分值或计分口号。

<whole_answer_validity required="every_question">
按评分规范，从服务立场、事实采信、核心依据可追溯性、有效成果一致性及决定性法律推导审查本题风险；将适用风险具体化为可判定的失效行为，不把五个方向照抄成每题固定条款。明确其损害的是本题哪项核心权利、决策或办理用途，以及为何足以使核心委托整体失效；依法确认不利事实、合理推论和有依据的不同法律解释不因不利于委托人而触发。
每道新题依设计方法，在确定核心成果及求解标答时同步识别其成立基础，再将已论证的整体失效条件写入最直接相关的那条 rubric 中（仅出现一次，不固定放在末条末尾）：明确具体触发行为、可核验证据、核心委托整体失效的原因，并以贴合本案语境的自然表述写明全题计零分的后果（如全题按零分处理、整题不予计分、整题计零分等明确归零语义，禁止每题逐字复读同一固定尾句）。普通单项错误、次要遗漏和局部文件问题不自动升级；单一决定性错误足以破坏核心委托时可以触发。证据不足、合法替代、条件备选和交付前已经纠正的错误不推定触发。
按评分规范将该规则放入评分者实际收到的字段；不另增普通得分项或分母。每题必须具备该机制，触发情形和措辞依本案确定；不把“一票否决”作为固定标题，XML仅用于作者指令，不进入业务正文。提交前核对规则已落入题包且完整正确解不会触发。
</whole_answer_validity>
- 先按[评价维度](references/评分与难度验证.md#从评价维度形成复合考点)检查数据与依据、专业处理、成果使用的覆盖，再按独立用途划分结果；不照搬案例的条数、主题分组或成果套餐。每个必要条件都须说明缺失将造成的实质后果，背景叙述和可替代证据不升级为逐项背诵要求。
- 判据写清必要条件、依据、具体结果、允许替代及关键失败；不能只写“分析充分”或“符合标答”。附件依据直接写“依据附件”并点明具体文书或决定性记录内容，严禁写“附件1”“附件 1”或页码（真实交付为合并卷宗且导出 DOCX 后页码会变化）。评分者不读取本 Skill、思路或默认标答，判分所需业务与产物核验信息必须进入 rubric，但严禁把“评分端”“轨迹未传”“评测条件不满足”“不作为有效专业难度成绩”“本条评价……”等内部评测流水线术语写进 criterion。
- 同一判断不因出现在多个成果中重复计分；共享前提的归属及下游独立条件在作答前写清。普通考点错误不连带否定全题，整体失效仅按本题预先写明的条件判断。不因看到答案或目标分数改变本题标准。
- 按[内容、文件和执行的归属](references/评分与难度验证.md#内容文件和执行的归属)设置验收证据：实际文件、公式重算及全套 PDF 版式用于检验相应的业务使用能力，明确仅列文件名、口头声称已完成或填静态常数不成立；不逐条复制共用文件门槛，不设只有文件名或调用次数的简单分，也严禁在 criterion 中夹带评测系统状态说明。

提交前按评分规范检查：完整正确解满足内容判据；漏掉任一必要判断的近似答案不能通过对应 R；表达凝练但内容充分的合法替代正常通过；通用建议、局部正确但最终成果矛盾不能冒充完成。普通出题用计算脚本核验全部数据与公式闭环并联网核对法源原文，不在出题会话内制作 DOCX/XLSX/PDF 校准实物或渲染读图；仅在专门获准制作独立实物校准样本时才生成真实文件核验文件判据。条目覆盖完整、无重复，材料充分，题面未泄解法。

## 多样性

<diversity_standards>

- 表达按真实委托组织。先从本包确定代理立场、核心工作、分析单位、成果用途及真实依赖，再据这些关系选择叙述入口、展开顺序和成果结构；题目之间的差异由各自材料与专业任务形成，若本次提供同期白名单设计摘要，用于比较业务目标、核心工作及成果用途，避免仅换名称的重复；不读取历史题包、答案或评分。未提供时仅按本包设计，不虚构跨题多样性已验证。
- 连续续办的事件来源、变化性质、先后关系及修订载体按本案组合；表达库呈现已确定的业务关系，不反向限定为收款、退费、固定阶段数或文件套餐。不同阶段可用完整稿或可直接采用的替换正文衔接，必须能辨认各阶段处理结果与最终有效成果。
- 任务名称、prompt、rubric、作答思路、标准答案-文本分别从组合库选择适用的起笔、展开、局部写法和收束，再跨字段组合；示范搭配可拆散，不作为整套模板轮换。`task_name` 用本案最具区分度的单一核心事项、待决问题或关键文书用途命名，禁止整批写成“[主体／案名]的[四字动作]与[四字动作]”对称并列句式，禁止滥用“接管、核校、专项、全套、闭环”等高频词。先确定专业内容，再选表达；不得为适配写法更改题目方向、任务、难点、成果用途或判据。按表述方法核对表达前后的全部工作及逐条判定一致。

## 交付

完成前对照内部任务盘点逐项检查参考工作覆盖、所有业务步骤及阶段材料、输入完整性、法源与计算自证、判据边界和多样性。发现缺项在本次出题内补齐；确受材料、权限或能力限制时写清具体影响及已完成部分。验证并写入合法 `result.json` 后即结束会话，普通出题不运行 `render_command` 生成可选 `题目.md`，也不另写落盘自检或说明文件。

按当前返回契约交付表头、任务名称、任务类型、题面、rubric、作答思路、完整标答；结构化字段以本次 schema 为准，业务正文不出现内部路径、“附件1”序号、评测目的或目标分数。

作者自查只证明设计已核对。实际难度由独立作答和既定评分验证；故障、截断、缺件及评分争议不能证明难度。设计完成与独立实测达标分别报告；未取得评分规范要求的有效成绩、轮次和耗时证据时，状态为待实测或未达标，不能写“已保证”。目标成绩只用于外部验收，不进入题面或评分输入，不承诺未经实测的结果。
