# 法律垂类评测：材料、场景与交付物参考

## 来源与使用方式

本文件依据用户提供的《副本法律垂类评测（材料-场景-交付物）对应表20261111.docx》转为 Markdown。按用户说明，原表由专业律师提供；下文保留其 37 项业务方向、执行思路和交付成果，补全原表合并单元格对应的材料类型。末尾“补充设计参考”为本次增补，与律师原表分开。

**这是专业律师提供的经验参考，不是要求 AI 按部就班执行的流程、固定题型或交付套餐。** 真实案件可能存在表中未列出的材料、关系、场景和办理方式。先完整理解本次材料、委托范围、代理立场、办理时点及成果用途，再决定参考哪些内容、怎样调整和补充；有依据的表外方案同样可以采用。不要为了匹配某一行而改变案情，也不要因为表中没有写就漏掉必要工作。

- 原表的编号步骤展示可能的工作思路，不规定操作顺序、工具调用次数或每题必须完成的环节；“按清单起草”仅表示该场景下的成果候选，实际选用取决于办理条件和独立用途。
- 每行不是一道完整题目，也不是一个考点。相关工作可以组合；是否组合、是否拆分评分，仍以真实业务关系和独立专业结果决定，不把一行全部内容绑成一个 R。
- 原表中的法律条号、期限、数额标准及程序结论属于来源内容，本次格式转换不构成有效性核验。具体出题时按[作者依据核验要求](../references/出题设计方法.md#规则与载体落地)核对适用版本、条件和例外，不能直接把参考文字写成唯一判据。
- 每次选题必须定位并阅读与本包相关的方向，将其中工作和成果逐项纳入设计盘点，说明采用、调整或排除的依据。适用的步骤须形成实际材料，不能只借用场景名、只挑一个概述报告。无需执行无关方向，也不以轮换题型制造差异。选题与材料匹配遵守[场景规范](../references/材料方向场景与交付设计.md)，本文件不另设出题和计分规则。

## 补充设计参考：怎样从材料中展开实质工作

下表补充原表未展开的材料关系和业务依赖，供作者识别可用方向。只有本次材料和委托支持时才采用；每行中的处理与成果也可按实际需要调整，不要求集齐，不自动追加续办。

| 材料中出现的具体情况 | 可以深入处理的工作 | 工作结果怎样进入实际成果 |
| --- | --- | --- |
| 起诉或应诉材料中，主张、履行记录和已有文书对同一事项的范围不同 | 逐请求核对证据能支持的范围，区分可承认、可反驳和须保留条件的部分；有具体对立意见时回应其最强依据 | 把取舍落实到本方请求、答辩或质证正文；相关核算和证据引用须与该范围一致，不能只列风险 |
| 历审卷宗中，同一证据在提交、质证、认定及裁判说理中呈现不同状态 | 沿具体争点重建记录关系，区分没有记载、没有处理与处理结果不利；判断该差异对本方可采用路径的影响 | 将有依据的争点写入适用救济文书或回应意见；成立的原裁判结论也须保留，不能预设一定存在可救济错误 |
| 执行卷宗中，多个财产、多个程序和收付记录互相影响 | 逐财产或履行事项识别主体、状态、覆盖范围及关联记录；处理重复记载、部分完成和权利冲突，再确定本方可办范围 | 形成可追溯明细，并把可用范围落实到申请、异议或履行安排；不能仅以总额正确代替逐对象处理 |
| 公司档案、章程、决议和出资凭证的时点或记载不一致 | 区分登记状态、内部约定和实际履行；围绕本次拟议事项判断权限、程序及关联影响，不从单一档案直接推定全部控制关系 | 将分析落实为本次可采用的章程条款、决议草稿或条件落实安排；材料不足时限定结论范围，不凭空补造治理结构 |
| 合规制度规定了控制要求，实际业务记录却体现不同做法 | 对照具体业务样本追踪执行及例外，识别缺陷发生在哪一环、影响哪些事项；没有运行记录时不能声称完成穿行测试 | 完成针对性制度修订及现有问题的处理安排，使职责、触发条件和完成证据对应实际业务；不复制通用合规手册 |
| 多份合同存在版本、附件、补充协议或关联交易条件 | 逐对象确认适用文本和条款关系，审查局部修改对定义、交叉引用、履行条件及其他合同的影响；统一条款与个别例外分别处理 | 实际交付相应修订正文及必要对照，核验签署版本与附件一致；有给定对方改稿时继续处理，不能只列修改建议 |
| 多份诉讼或执行卷宗需要供同一委托方复盘或复用 | 先识别同案不同来源与不同案件，再建立可比口径，解释程序、证据、对象和适用规则差异，保留反例与不可比较部分 | 将逐案判断用于本次策略或确有需求的复用工具；每个结论可回查来源，不能从少数结果推出胜诉概率或通用办理结论 |
| 破产材料中，申报、账簿、担保、往来款和已处理结果互相制约 | 从本方职责出发逐项核对债权或财产的性质、范围、状态及争议；区分不同主体有权采取的动作，不把各方职责合并 | 管理人侧落实审查或处置意见，债权人侧落实申报及异议，债务人侧落实本方说明和方案；具体成果随已具备的程序条件确定 |

### 延长有效工作链的条件

原表列出“解析—分析—起草—校验”，并不意味着模型实际需要同样数量的步骤。沿选定业务查明哪些中间结果会改变后项判断，再按[工具工作与有效步长](../references/出题设计方法.md#工具工作与有效步长)展开：例如逐对象证据取舍决定可请求范围，该范围决定文书内容，实际成果再接受来源、口径和使用能力核验。批处理能完成的同规则重复工作仍允许批处理。

材料及委托支持成果投入使用后的反馈时，按[连续续办要求](../references/出题设计方法.md#已有成果的连续续办)承接前项结果：给定新增记录后判断哪些条件改变、哪些仍成立，并实际处理受影响成果。反馈可以来自证据、程序、谈判、履行或实施，不统一追加付款事件，也不把彼此独立的假设题包装成连续办理。具体事件仍须遵守原件保护和模拟边界。

补充的工作必须增加必要判断或成果用途。只增加同类记录、文书份数、标题、导出次数或等待，不足以证明难度和步长提高。实际达标沿用[评分与难度验证](../references/评分与难度验证.md#执行复杂度与实测证据)的现行口径；本参考自身不是已达标样本，也不能保证特定模型的轮数、时长或成绩。

### 考点与表达怎样随业务变化

原表的一串步骤不直接转成一串得分点，也不整串合并为一个 R。以合同版本审查为例，确认适用版本、处理冲突条款及落实修订可能共同决定同一条款安排能否使用；另一合同的独立争议不会仅因放在同一材料包中就并入该考点。具体拆合按[评分规范](../references/评分与难度验证.md#考点)，判据围绕结果连贯表达，不在 R 内编号拼接多个独立考点。

题目的差异来自本案的委托触发点、决定性材料关系和成果用途。同为执行材料，可以形成恢复办理、异议回应或程序复盘等不同工作，但须由本案材料支持；同为合同材料，也可能以采用既有稿、处理关联冲突或回应改稿为重心。不要为了看起来不同而随机换角色、换程序或增加文件。完成业务设计后，再按[书面表达组合库](书面表达组合库.txt)选择自然的交办和成果写法，不把本表栏目、编号步骤或内部设计术语照搬到律师正文。
