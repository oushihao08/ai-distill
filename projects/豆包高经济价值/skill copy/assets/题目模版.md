# 题目包字段模版与契约

按当前返回 schema 填写结构化内容；下文花括号与标题仅供作者核对字段职责，不原样带入业务正文（`question`＝题面，`reference_answer`＝标准答案-文本）。具体禁止词清单与载体细则统一以[题目格式与交付](../references/题目格式与交付.md)为准，整篇布局与语体组件见[书面表达组合库](书面表达组合库.txt)。

## 表头 `header`

- **题目 ID**：{本次任务 ID，不写入业务正文}
- **一级／二级行业**：{任务发生组织的主营行业与细分行业}
- **任务形式**：{按当前 schema 如实填写；`answer_requirements` 须按题面真实文件与检索要求声明 `output_mode: "file"` 及所需工具}
- **输入附件**：{按实际分件脱敏文书文件名填写；严禁使用“附件1”“合并卷宗”或匿名哈希名}
- **L1 职业簇／L2 职业**：{负责最终交付的律师／企业法务岗位，严禁填当事人诉讼身份}

## 任务名称 `task_name`

{提炼本案最具辨识度的标的对象、待决焦点或核心动作；禁套“[主体]的[A]与[B]”对称句式，禁带 `(****)` 星号掩码，禁提前泄露待求救济路径或结论。}

## 任务类型 `task_type`

{依材料实质工作与交付用途选定准确的细分业务类型，不按目录名机械归类。}

## 题面 `prompt`（`question`）

{1. **饱满实务背景与基准节点**：从本案真实的死线、待审旧稿、商业拍板、双线分流或账目冲突切入（以下三项是字段内容核对项，段落随本案办理关系组织），完整写明单方代理立场、基于在卷客观文书的办理基准时点及现实处境，信息量饱满详实，绝不压缩成简略几句话。}

{此处用客户自己的业务语言交办。经办人能否照办留到标答自检。成稿时用[题面交办检查](../references/题目格式与交付.md#饱满业务交办与整篇结构去同构)反查一份照字面办完却漏办的答卷，补回缺失的对象、限制、应改的在卷旧稿或下游用件。有成批请求、返稿或办理反馈时，把客户要处理的整件事交代清楚。例如客户等着签旧稿，问清的是原稿各项如何处置、已递交的版本谁来接着办；若真实用途只是财务批准无争议批次，就按这次批准范围交办。选符合本卷的写法。成品分别由谁使用，据此交代卷中已触发的续办、相容的并行工作与必要配件。事实未发生时说明交到哪一步，把具体路径及证据取舍留给承办人。}

{2. **点明要办的工作，保留待决判断**：在客户已知范围内，把触发委托的事实和必须办成的事写进题面。涉及未决救济路径或案由时，直接交办客户要解决的问题；隐蔽证据关系、补证办法、规则选择和结论留给承办人。已确定须签发或改定的成果，说明谁要拿去做什么；去向和文种仍待核定时，用实际用途交办，文件名不提前揭底。}

{3. **实体交付**：把正式文书、必要随件和底稿交到实际用它的人手中。可编辑文稿用 `.docx`；需逐项动态核算的交可续记和复算的 `.xlsx`；正式递交、签章、报审或定版归档的正文及随件配可用 `.pdf`。按业务需要核对权威法源、实际重算与核版。不同用途独立分件，严禁改为在回复中贴正文；保持单方授权边界。}

## 考点 `rubric`

{按[评分规范](../references/评分与难度验证.md#设项与覆盖)划分去重后的独立复合专业结果（等权二元计分，内部 ID 保留 `R1`、`R2`……，`max_score` 填 `1`）：同源本息费与清偿抵充合并为单条复合资金 R，独立实质工作分别设 R，无独立判断的体例、引注、通用交接或衍生短文一律并入核心争议 R。}

{每项须自足写出能核实的卷内凭据、规则、正确结果或可辩护边界、成果落点及判错后果。把各项连成一页审读，逐项留下能让评分者辨认这项特有决定的依据和边界。各项从最能说明本案成败的地方写起，可用证据证明范围、相反解释、净额边界或接手动作组织，具体写法查组合库第二节。唯一的案件化整题归零条件并入最直接相关的一项，写清核验依据及整体失效后果。}

## 作答思路 `answer_approach`

{从一处会改变交付的实际取舍说明缘由。卷内事实支持谁做什么、排除了什么误办，签发正文或经办动作因此怎样变化？其余独立事项各给依据。涉及核算或时际争议时给出实际数值或适用根据。不写工具过程、操作计划或代码。}

## 标准答案-文本 `reference_answer`

{起草正文时打开本题备忘录，核对所采纳的办理决定实际改了哪一处文字、款项或权限。由客户或接手人当下首先要用的成果起笔。要拍板时，内部意见可先直答能否签、先办什么及决定依据；已确定须递交或磋商时，可从可用的请求、协议或修订稿开始。逐件交给实际使用者。对外件写足该文种正文和随件，内部件直接给已核决策或可照办的指令。涉及核算时写出凭据对应的明细、业务算法和已核结果。逐项付款、补正或披露的范围要标到对应记录；只有可直接沿用的来源明细才可按笔数、小计引用。遮住思路和内部件，只看各自允许收到的部分，确定经办人无需再选法条、挑证据、补写文稿或拆分款项。}

## 独立使用与组合规则

业务设计与实算求解全部完成后，按[表述方法](../references/表述方法.md#独立使用与组合规则)和[书面表达组合库](书面表达组合库.txt)为六个文本字段分别选择匹配本案触发点、接收人与信息关系的宏观结构与表达组件；核对改写前后全部实质任务、文件要求、最优利益口径与二元判分边界零折损。

## 已有题目的保义改写

仅获准润色既有题目时，执行[保义改写规则](../references/表述方法.md#已有题目的保义改写)，双向核对事实、时点、金额、独立文件清单及每条 R 的通过／不成立边界完全一致，不借润色增删实质工作或放松判据。
