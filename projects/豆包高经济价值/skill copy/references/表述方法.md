# 六字段表述方法

**用途：**指导 `task_name`、`task_type`、`question`、`rubric`、`answer_approach`、`reference_answer` 的表达重组与保义核对。具体整篇宏观结构与表达组件统一存放在[书面表达组合库](../assets/书面表达组合库.txt)，禁止词与载体红线统一维护在[题目格式与交付](题目格式与交付.md#表达与引用)，本文件不重复抄录长清单。

---

## 独立使用与组合规则

1. **先定实质工作与实算结论，再选表达结构**：完成全卷穿透、多跳求解与复合判据后，结合[语气与表达定位](../去%20ai%20化建议.md#写作前的表达定位)从本案委托关系、触发事件、接收人、成果用途与信息结构选择匹配的宏观行文顺序，严禁用表达偏好反向删减任务或降低难度。
2. **六字段各司其职、拒绝目录互抄**：名称辨识个案，类型标明可复用业务类别，题面饱满交办背景与独立文件要求，rubric 自足锁定二元判据，思路展示证据与法源推导，标答按实际文种完整交付正式成果；不在六个字段间复制同一套小标题顺序。
3. **结合同期摘要主动分化**：若输入含 `batch-context.json` 同期摘要，在材料支持范围内比较客户决定和工作用途，再分别选择题面、考点与标答的行文结构（避免整批落入同一种起手与收束骨架）。

## 日常书面表达与载体保真

- 六字段业务正文统一使用自然段、普通中文序号、必要算式与制表分列，去除 Markdown 标记、代码围栏与脚本说明（详见[题目格式与交付](题目格式与交付.md#表达与引用)）。
- **表达调整绝不降级实体文件载体**：题面确定的独立可编辑文档（`.docx`）、动态活公式工作簿（`.xlsx`）与版式定稿（`.pdf`）必须在自然交办语言中完整保留，**严禁因追求口语自然而把实体文件要求弱化成“在回复中分件给出即可”或“无须制作文件”**。

## 强度与饱满度不变

- **题面业务信息量饱满不缩水**：重写表达是为了消除机械套话与四段同构腔，**绝不是压缩题面篇幅**；现实处境、核心锚点文书、基准时点、各独立文件的实际用途及已知接收人（待判断的收件对象留给承办人确定）、本案确需的复算与跨件一致性、权限边界必须完整保留，“必须”不得弱化为“可考虑”，待决救济路径不得在书名号标题中泄露。
- **判据排他强度不变**：rubric 的复合绑定条件、前提相同且明确占优的口径或有据可行的替代、明确二元不成立边界及唯一一处案件化整题归零条件不得在润色中遗漏或软化；子条件分行不产生部分分，“且”不得改成“或”。
- **标答正式体例不变**：`reference_answer` 依真实收件人分别成件。需向机关或对手签发的保留正式体例，内部决定可直接写能否放行、该改哪段和谁可照办；按用途写足正文及必要明细。

## 成稿复核

1. **双向任务与强度核对**：对照内部任务盘点，确认每项实质工作、独立文件要求、法源核验与最优口径在题面、标答、rubric 中一一对应，未因换结构漏项或泄题。
2. **四类答卷判定一致性核对**：用完整正确解、凝练合法替代解、退守次优默认口径/漏查边缘凭证的表层解、纯聊天文本/静态常数解静态核对，确保改写前后逐条 0/1 判定结果完全一致。
3. **去同构与零残留核对**：确认 `question` 已摆脱“首段角色基准日→逐段挂书名号→末段统一说交付”四段式，且六字段零模拟话术、零 `(****)` 星号掩码、零内部编号/哈希名、零评测产线黑话、零 Markdown 符号与代码围栏。

## 已有题目的保义改写

仅获准对既有题目做表达润色时，不重选题、不改 rubric 实质条件：先锁定原题主体、事实、时点、金额、权限、独立文件清单及每条判分边界，重组表达后逐项反查必要性、否定边界、数值精度与文件要求完全一致；发现原题存在实质事实或法律歧义时单列报告，不借润色擅自改判。
