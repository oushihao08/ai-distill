# 法律实务出题总控与路由

从本次提供的卷宗和委托方要办成的事出发设计法律实务题。以该方授权和办理时点为界，找全现在能办、必须衔接以及不能耽误的工作。把它当作承办律师围绕这一委托做一个完整工作日：从客户带来的难题出发，做到收工时客户能作决定、经办人拿着成品能执行获准的下一步。依卷宗确定这一天值得做哪些调查、判断、核算、起草或修订，连同尚需谁答复或签署一并交清。实际工作量看这些动作及其后果，不按小时编排题面。

**从委托目标倒推必要条件，再沿卷内事实追到办理后果。** 哪些条件决定客户能办成什么？哪份材料会改变这个判断，或带出同一委托下原先没想到的工作？把有实际后果的事项办到当前证据与授权允许的位置，再用场景库查漏。定稿时拿掉一项拟交办的工作，核对谁会因此办不成、办错或错过时机。按[从原件确定试办方法](references/出题设计方法.md#从原件确定试办方法)选择本案需要的核验，把必要结果落实到题面、标答和相应复合考点。这是作者的检查方法，成题按本案的业务需要组织。

## 一、确定办理范围与交付深度

先从收件人的下一步反推成果。已有业务原稿就判定沿用、修订或停用，给经办人当前可用的版本或指令，需要内部拍板就交可执行的决定及其条件，已有授权且确需对外办理才确定相应文种。若是否起诉仍待判断，题面只交办客户要解决的问题。一个案由、一个场景库条目或一张材料清单均不能决定这题要交哪些文件。选题时核清本包在办理时点已有多少工作能办出确定结果。按[选择办理场景](references/材料方向场景与交付设计.md#四从当前委托选择办理场景)试办后，再决定哪些连续、并行及条件事项进入同一委托。

1. **核清全卷内影响办理的记录**
   - 回查主文、当事人陈述和原始记录各能证明到哪里。材料互相印证时辨清各自证明的要件；确有矛盾时裁决可采范围。不能只凭主裁判摘要完成整项委托。
   - 从同一方尚待处理的权利、义务、期限和文稿中查遗漏。漏办会使谁无法举证、签发、收款或交割？即使另一主张尚未核清，也要交办已经有独立依据和现实用途的事项。通用建议和重复摘录并入其服务的工作。
2. **逐笔核准需要复算的业务底数**
   - 收件人须逐笔核销、比较相互影响的口径、续记或补录后复算时，题面必须交办独立的活公式工作簿（`.xlsx`），办到能据重算结果更新当前请求或指令。仅需在通知中写准一个确定日期或在条款中沿用一个已核数值，直接在该件落实依据与结果。不能把本应逐笔复核的账款缩成一个结论。
   - 将影响结论的原始记录逐笔入表，已知为零与尚待核实分别处理。派生值用活公式，真实的采信分歧或补录需要进入复算。补录后追到签发人实际引用的值，再核对哪份请求须更新、哪份仍可沿用。
3. **依真实进度续办，保留可并行及须择一的事项**
   - 有回执、履行记录或修订稿已改变前项处理的，接着办到当前节点。不同事项各有期限、对象或用途的，可同时推进；共用证据、款项或授权的，合起来核对可执行范围。接手前人已办的事，按[接办试做](references/出题设计方法.md#从前手留下的工作接着办)核清哪一版已经对外发生作用、什么仍须本方处理。把有凭据且今天能办的后续工作交进题面。
   - 将取舍留给承办律师。确有多条路径时，核实其启动条件、时效风险、成本与本方目标；只准备有当前用途的方案。已具备条件的工作完成可用定稿，尚缺前提的写清由谁持何凭据接办及届时改动何处。
   - 客户眼下的决定取决于未决争点时，按[走向研判的设计方法](references/出题设计方法.md#从未决争点形成办理决定)先解出有依据的倾向及其对具体成果的影响，再在题面交办客户要决定的事。没有这项决策依赖时，照常完成本案工作，不附加胜败预测。
4. **保留全卷，题面写足已知事实，把未决判断交给律师**
   - 全部在卷业务文书随题保留，包括旧诉状、和解稿、裁判和后续回款。若照抄卷内某件就能交差，改选客户读完它之后仍需解决的事。按签发、送达或履行凭据确定可办阶段；核出的差异要落实到真正受影响的请求、付款或签发内容。
   - **写全客户知道的事**：交代现实处境、日期、已有主张、已知收件人、授权、所需结果及实际文件用途。若找出主管机关、确定请求或决定哪些材料能交正是委托内容，用客户要解决的问题交办，让律师决定去向和配件。在题面写明哪些对象、旧安排和相互牵制的要求要由律师办到哪一步。按[题面交办](references/题目格式与交付.md#饱满业务交办与整篇结构去同构)用“少办了什么仍可能照字面交差”检查完整性。
   - **把发现矛盾与选择路径留给作答者**：卷内有据、客户已知且关系到这次委托的来件、日期和经过可以直说。不得把作者从全卷推得的矛盾、证据缺口、法律效果或纠偏办法预告给作答者；**当采用何种救济路径或案由本身属于待裁决核心（如应走代位析产、债权人撤销权、执行异议还是另诉追偿）时，题面交代需要达成的结果。去向和文种也待判断时，连文件名一并留给承办人；确定要立案而仅案由待选时，才可点名起诉状**。
5. **强制可接手使用的实体文件交付＋委托人最优利益二元判据**
   - **严禁放行纯文本交卷**：凡接收人需编辑审签、提交立案、动态复算或盖章存档的成果，题面必须明确交办可实际使用的独立文件（可编辑文稿、活公式表格、版式定稿），并在 `answer_requirements` 如实声明 `output_mode: "file"` 及所需工具；**题面直接写明收件人要拿实际文件做什么**。
   - **据卷区分办妥与错办**：文书体例、法源引注、交接说明及无独立判断的衍生文本一律并入其服务的核心争议 R；**对卷内能够确定的金额、期限及在相同前提下明确占优的合法行动，锁定结果并写清选错的损失**。裁判倾向与本方应采取的行动分别依[评分规范](references/评分与难度验证.md#设项与覆盖)验收，用本案的具体错办与合法替代试判。只有会使本项请求、签发指令或处置决定办错的条件，才作为这项复合考点的必要条件。

## 三、成稿必过六条硬红线

1. **按收件用途交齐实体文件**：交给作答者的任务明确要求可用的独立文件。作者只在 `reference_answer` 写业务正文与必要明细。涉及核算，写清凭据、取舍、计算口径、已核结果及其办理后果；必要时列普通算式。工作表布局、单元格地址、Excel 函数和建表步骤不写进这个字段。标答定稿时轻查一句：接手人拿到这份答案后，第一件真正要办的事是什么？只用其有权拿到的内容试走，这句话留在作者自查。仍须专业补写、自己从总数拆出逐项指令或靠内部说明猜哪个版本能发，回到该件修正。作者交文本标答，作答端按题面生成办公文件。
2. **把要办的事点进题面，把怎么办留给律师。** 每项采纳的独立业务结果都必须在公开题面找到交办原句。客户同时等两个决定，就让读者看得出两件都要办；一句话可以自然带出相连的工作。发现问题本身是考点时，点明客户等着作哪项决定、处理到什么范围。隐蔽证据关系、适用规则和待选救济路径由律师查明，文件名也不泄底。
3. **核实真实工作量**：去掉未来反馈、空白参数和重复结论，用[最省力的合规答法](references/出题设计方法.md#工具工作与有效步长)试接这单委托。若文件齐全、字面要求已满足，客户却仍有已交托的事办不下去，按其实际用途补清交办范围，保留需要读卷才能作出的判断。若只剩一次判断及其转述，回卷重选工作重心。取到真实答卷后，按[首答实做覆盖](references/评分与难度验证.md#首答实做覆盖)核对效果。
4. **零模拟与评测黑话**：依[表达与引用](references/题目格式与交付.md#表达与引用)使用自然文书名和案号简称。客户没有收到的反馈、尚未作出的决定，不能在题面、思路或答案中写成既成事实。
5. **整题归零与二元边界完备**：每条 `criterion` 均自足点明所附具体文书及判定依据。连读各项，能看出各自在判断哪件不同的事；删除重复计分套话后仍能判清对错，全题在最直接相关的一条 `criterion` 中自然融入唯一一处案件化整题归零条件（完整正确解不触发）。
6. **整篇行文结构去同构**：题面未沿用千篇一律的“起手点日期→逐段挂《文件名》→末段交代交付方式”四段式，遮去名称后仍能从段落关系辨认本案的待决事项及依赖。共用文件要求可一次交代，逐件实体交付、复算与核版仍逐件验收。连读题面、考点、标答：题面按委托事项组织，考点按独立判断组织，标答直接给接收人使用的正文。三者若能共用一份文件目录作提纲，按各自用途重写。同期摘要可用时，试把最相近一题的办法照搬过来：本题哪个收件人将因此做错哪件事？若说不出差异，重查本卷其他有依据的工作；唯一可行的方向据实保留。扩展名与配套版式只在交付要求中交代。
