# 法律实务出题

从全部附件中选择尚未解决、会影响实际办理的单方法律服务任务，同时提高专业判断难度和有效工具步长。用有依赖的检索、材料处理、计算、成果制作及检查修订展开工作，不以篇幅、机械重复、隐藏输入或压分替代。

## 输入与阅读

- 按用户当前要求、本次任务及实际提供的适用规则确定范围；案例和历史数字不是永久要求。不强制访问本次冻结输入外的项目文档或重新读取已接受的外部规则。
- 设计前读[场景规范](references/材料方向场景与交付设计.md)、[设计方法](references/出题设计方法.md)、[评分规范](references/评分与难度验证.md)。完成任务设计、求解和判据后，再读[表述方法](references/表述方法.md)及[书面表达组合库](assets/书面表达组合库.txt)，交付按[字段模板](assets/题目模版.md)。这些是必读规则；其他参考按[资料索引](references/资料索引.md)选用。
- 完整阅读附件；摘要只用于定位。仅使用本次案件材料、公开法律依据及明确披露且获准的模拟条件。不读取历史题包、答案、成绩或个人记忆作为新题输入。
- 材料整理提供候选工作分析时，结合本包核实工作、成果用途、依赖及核验建议。依据接收人下一步需要实施的编辑、审签、核算、更新、提交或留档动作，确定必须实际制作的业务文件及其核验方式；候选分析缺失时仍按正文完成同样判断。保持复合难度与完整交付。
- 以律师／法务身份代表一方；代理立场、办理时点、当时可得信息、权限和成果用途相容。不默认执行、核账、和解或固定文书套餐。
- 仅当本次任务明确要求扩展已有题目，并给出须保留的委托方、时点、核心工作与成果范围时，按该范围扩展；否则按新题选题，不从历史题包推测保留范围。
- 本次要求增加业务工作时，依据当前附件具体展开需要新增完成的专业处理，写清处理对象、待作决定及必须交付的实际内容。仅将已有审查要求换词、增加深度修饰或笼统要求据反馈更新，不算完成扩展。新增工作须落实到题面、完整标答和对应判据；合并表达不得省略不同事项各自需要完成的处理。无需读取历史题目；未提供比较依据时，不宣称比旧题增加。

## 出题标准

<question_standards>

1. 完整读取后，按文书核对来源、时点、证明范围与未决问题；依[任务盘点与范围确定](references/出题设计方法.md#任务盘点与范围确定)找出同一委托方可办的工作及未纳入理由，再定题目范围。涉及多份记录或多个对象时，依[材料到成果的工作链](references/出题设计方法.md#材料到成果的工作链)识别实际分析单位、可核验的中间结果及其后续用途；单案也按适用的业务单位处理，不固定为多案统计题。不得先限定资产类别、文书或单一争点而遗漏相容的实质任务；用户明确限定的范围仍须遵守。新增任务须有独立用途、材料依据及可完成成果，不靠换标题或增加文件份数扩量。
2. 从业务用途反推待解决的专业结果。核清决定性记录的主体、来源、时间、证明范围及相互关系，求出权利、金额、条件、路径和所需文本。只处理本案适用者，不集齐机制。
3. 求最简合法答案。若抄裁判、查日期、套通用原则或按已给公式代入即可完成主要工作，重新选择材料支持的未解决问题；保留必要输入和合法捷径。
4. 为每个拟计分结果明确共同决定其成立与可用性的多个必要判断，可以前后依赖或共同约束，不要求强行串联。按评分规范的用途与判断边界划分 R，不因同案、同文书就合并，也不因子条件可分别检查就拆分。简单事实与基础计算纳入其实际支撑的结果；只增加记录、步骤或文书数量不构成深化。
5. 围绕拟采取的关键行动，依设计方法审查证据能支持的主张范围、成立条件及有依据的竞争解释；关键未知或变化会改变办理决定时，设计相应[业务推演](references/出题设计方法.md#模拟与变化)，落实受影响成果。取证、办理取舍及备选路径按本案需要采用，不能为集齐流程新增无依据的任务。
6. 先完成全部标准答案，再编写自足 rubric，逐项核对题面已交办的业务决定、可见输入、成果及验收要求与二者一致；审查或推演不能只留在作者自查。核对材料、处理结果、结论与各成果之间的同一对象、口径和状态。只出现在 rubric 或标答中的工作不能计入题目任务。隐含的是解题时必须发现的问题，不是未告知的交付义务。

### 题面与成果

<business_work_guidance>
涉及多项工作、材料状态或成果依赖时，依[题面中的业务整理与复核](references/出题设计方法.md#题面中的业务整理与复核)交办本案适用的工作关系与使用要求，保留专业判断的发现难度。以真实业务加工增加有效执行，不指定思考时长、调用次数或固定任务清单。
</business_work_guidance>

- 写清谁在何时为哪一方办什么、权限与范围、成果给谁使用。事实尽量保留在附件，不提前指出冲突位置、法律效果、正确路径或把 rubric 改写为交办清单。
- 真实缺口给出可判断的分支和行动边界；附件已足够的部分必须完成。模拟记录明确标注，不改写既判事实、脱敏值或原件，不用模拟假设消除主要争议。
- 允许并按任务需要要求联网检索、附件处理、计算、生成及导出 PDF、DOCX、表格等成果，不设纯文本或禁止文件的统一限制。优先设计前一工具结果决定后续判断或操作的任务；需要编辑、提交或核验的文件，明确实际交付与读回检查要求，不只在回答中写文件名。
- 按[工具工作与有效步长](references/出题设计方法.md#工具工作与有效步长)选择适用环节。题目要求与环境是否支持分别记录；必要能力尚未接通时标明执行缺口，补齐后实测，不擅自把已确定的文件交付或检索工作降为纯文本替代，也不把环境失败计作专业失分。
- 标答交付完整分析、必要核算和可使用的正文；各成果口径一致。数量由独立用途决定，不用“另行起草”“待核后处理”代替已可完成的工作。
- 本轮可完成的成果、关键反馈后的具体处理及使用端复核按[成果使用与办理交接](references/出题设计方法.md#成果使用与办理交接)执行；题面交办、标答实际完成，rubric按相应专业结果验收。
- 题面采用正向、可验收的完成要求。不得出现“简短回复”“简要说明”“无需详细”“不必展开”“只需概述”“不要过多说明”等会诱导作答者压缩实质工作的措辞。需要深入处理时，结合本题对象明确要求完整梳理、全面核对、逐项列明、细致区分或展开论证，并写清应呈现的依据、结论、计算、条件、例外、成果落实和核查结果；不以空泛的“详细一些”代替具体工作。
- 文件题须区分业务成果与聊天交付回执。业务成果完整交付；回复按本题实际用途交代各文件、关键口径、实际核查结果、发现的问题及未完成限制。回复说明不得替代文件正文，也不得缩减题目要求的任何成果；交付说明的内容和位置由各项成果的实际用途决定。

</question_standards>

## 评分标准

<scoring_standards>

- 每项评价一个复合专业结果，依据核心结论、决定性依据与成果可用性判断成立或不成立。要求完整处理，但不影响结论和使用的次要错漏不单独导致本项失败。各项等权，百分制按成立项占比换算；max_score仅按当前结构化契约填写，不在判据正文反复写分值或计分口号。

<whole_answer_validity required="every_question">
按评分规范，从服务立场、事实采信、核心依据可追溯性、有效成果一致性及决定性法律推导审查本题风险；将适用风险具体化为可判定的失效行为，不把五个方向照抄成每题固定条款。明确其损害的是本题哪项核心权利、决策或办理用途，以及为何足以使核心委托整体失效；依法确认不利事实、合理推论和有依据的不同法律解释不因不利于委托人而触发。
每道新题依设计方法，在确定核心成果及求解标答时同步识别其成立基础，再将已论证的整体失效条件写入 rubric 一处：明确具体触发行为、可核验证据、核心委托整体失效的原因及整题最终得分归零的后果。普通单项错误、次要遗漏和局部文件问题不自动升级；单一决定性错误足以破坏核心委托时可以触发。证据不足、合法替代、条件备选和交付前已经纠正的错误不推定触发。
按评分规范将该规则放入评分者实际收到的字段；不另增普通得分项或分母。每题必须具备该机制，触发情形和措辞依本案确定；不把“一票否决”作为固定标题，不复制同一结尾，XML仅用于作者指令，不进入业务正文。提交前核对规则已落入题包且完整正确解不会触发。
</whole_answer_validity>
- 先按[评价维度](references/评分与难度验证.md#从评价维度形成复合考点)检查数据与依据、专业处理、成果使用的覆盖，再按独立用途划分结果；不照搬案例的条数、主题分组或成果套餐。每个必要条件都须说明缺失将造成的实质后果，背景叙述和可替代证据不升级为逐项背诵要求。
- 判据写清必要条件、依据、具体结果、允许替代及关键失败；不能只写“分析充分”或“符合标答”。附件依据写“依据附件1”及决定性记录内容，不写页码；导出 DOCX 后页码可能变化。评分者不读取本 Skill、思路或默认标答，判分所需信息必须进入 rubric。
- 同一判断不因出现在多个成果中重复计分；共享前提的归属及下游独立条件在作答前写清。普通考点错误不连带否定全题，整体失效仅按本题预先写明的条件判断。不因看到答案或目标分数改变本题标准。
- 按[内容、文件和执行的归属](references/评分与难度验证.md#内容文件和执行的归属)设置验收证据：实际文件及读回用于检验相应的业务使用能力，不逐条复制共用文件门槛，不设只有文件名或调用次数的简单分。能力不足、证据未传入与作答明确漏做分开；边界写入相关 criterion，不能只留在 Skill。

提交前按评分规范检查：完整正确解满足内容判据；漏掉任一必要判断的近似答案不能通过对应 R；表达凝练但内容充分的合法替代正常通过；通用建议、局部正确但最终成果矛盾不能冒充完成。文件要求须用实际产物及检查证据校准，文本标答不证明文件验收通过；未完成校准在完成说明报告，不虚构操作。条目覆盖完整、无重复，材料充分，题面未泄解法。

</scoring_standards>

## 多样性

<diversity_standards>

- 表达按真实委托组织。先从本包确定代理立场、核心工作、分析单位、成果用途及真实依赖，再据这些关系选择叙述入口、展开顺序和成果结构；题目之间的差异由各自材料与专业任务形成，不要求作者识别或复述历史题目。
- 任务名称、prompt、rubric、作答思路、标准答案-文本分别从组合库选择适用的起笔、展开、局部写法和收束，再跨字段组合；示范搭配可拆散，不作为整套模板轮换。先确定专业内容，再选表达；不得为适配写法更改题目方向、任务、难点、成果用途或判据。按表述方法核对表达前后的全部工作及逐条判定一致。
- 五字段业务文字采用日常书面表达，不用Markdown标记、代码块、生成脚本或编程教程。题面中的业务工作涉及编辑、审签、数据运算、持续更新、正式提交或固定留档时，要求作答者实际生成能完成相应动作的业务文件，并完成内容、数据、公式、版式或打开结果的核验。阅读稿考点用1、2、3普通编号，结构化评分ID与max_score不变。思路写本案论证，标答写完整可用成果；作者自查、计分过程、模板选型及模型实测不进入二者。
- 材料到成果的工作链只用于核对依据、专业处理、使用动作、实际成果及验收证据是否闭合。题面呈现当前委托和成果，五字段分别依其用途与信息关系组织；现有输入只支持独立设计当前题目，不据此评价其他题目的表达或相似度。

</diversity_standards>

## 交付

按当前返回契约交付表头、任务名称、任务类型、题面、rubric、作答思路、完整标答；结构化字段以本次 schema 为准，业务正文不出现内部路径、评测目的或目标分数。

作者自查只证明设计已核对。实际难度由独立作答和既定评分验证；故障、截断、缺件及评分争议不能证明难度。目标成绩只用于外部验收，不进入题面或评分输入，不承诺未经实测的结果。
