# 失败模式与自检清单

出题、审题、返修和评分时，用本清单拦截会使题目不可作答、考点无效或评分失真的问题。命中时修复根因；不能修复的考点标明无效，不硬判模型失分。

## 一、材料与证据边界

| 不好的做法 | 为什么会失败 | 应如何处理 |
| --- | --- | --- |
| 只读题面中的附件摘要，不读完整原件 | 摘要可能漏掉正文后页、附件包内的裁定、表格或脚注；模型却能看到完整文件 | 按模型实际收到的文件逐份读取；摘要只作导航。关键结论回指页、段、表格或记录 |
| 把题包内出现的文书误称为卷外材料 | 会把正确使用输入证据判成越界，污染rubric和得分 | 明确区分“附件内但摘要漏列”“附件根本未提供”“允许检索取得”；按实际输入判断 |
| 在rubric写“卷内没有X”，却没搜索全文及复合附件 | 负向事实可能是出题者漏读，不是模型应该发现的陷阱 | 逐条验证存在/不存在的断言。不能完整搜索时不得把“不存在”写成唯一考点 |
| 用附件标题、案由或目录名代替内容判断 | 同一卷宗可能混有他案、复印件、后续通知；标题不能证明主体、效力或范围 | 依文书内案号、当事人、内容、日期和关联判断，记录排除或采信理由 |
| 把模型提及材料等同于采信该材料 | 模型可能是在辨别并排除，评分却误判为据此主张 | 按句子实际功能区分识别、排除、背景说明与事实依据；只有题目禁止的实质用途才判错 |
| 多份材料冲突却没有裁决依据，仍要求唯一日期、金额或主体 | 题目无解，评分只是在猜出题者意图 | 补有权威性、有效时点或适用范围的依据；若仍无法唯一化，按半开放标准或局部待核设计 |
| 为了制造矛盾，把真实差异擅自说成笔误或伪造复印件优先级 | 产生材料漏洞或虚构证据规则 | 只按材料本身和适用规则判断；无法证实时维持不确定，不强求唯一结论 |
| 从星号数字、账户末尾或部分流水拼出完整脱敏金额 | 构成反推隐私，且计算结果无可靠依据 | 原样保留脱敏；只考可由已给数据支持的关系、范围或算法 |

## 二、业务真实性与任务资格

| 不好的做法 | 为什么会失败 | 应如何处理 |
| --- | --- | --- |
| 只给自然人案件加一家模拟公司、报价、预算或投委会，就宣称真实企业任务成立 | 模拟条件能用于内部题目，但不能证明实际企业关系或成果采用 | 保留可用的卷宗与考点，明确标示题设条件；若正式提交要求真实使用，再核对应的委托、授权和采用证据 |
| 对业务设定没有完整交付要求，最后只得一份泛泛法律意见 | 虽有专业分析，却难以支持具体签批、付款、交割和执行办理 | 让题设明确决策动作和约束，标答完整回应业务提案，并给可交接的条款、责任、条件和时点 |
| 将“有完整标准答案”“模型得分低”“题目很复杂”当作真实性或资格证据 | 这些分别说明可评审性、模型表现或工作量，不能证明真实采用或实际价值 | 单独记录任务资格、专业用途、交付完整性、难度测评，各用对应证据判定 |
| 把外部项目的制作或提交限制一概当作当前本地返修禁令 | 用户已经授权完善现有题目，过度扩大限制会使可完成工作停住 | 区分内部成稿、材料脱敏和正式外部提交；完成当前授权的返修，对尚缺的外部资格仅如实说明 |
| 把正例的分数、文件数或情景结构复制成固定门槛 | 历史成绩只反映特定版本和测评，固定数量会诱导凑量并削弱业务适配 | 迁移因果机制：材料有裁决依据、判断影响行动、考点能定位；每题按实际业务独立设计 |

## 三、题目范围与交付设置

| 不好的做法 | 为什么会失败 | 应如何处理 |
| --- | --- | --- |
| 表头写公司法务，prompt却让律所律师承办自然人客户案件，或行业写“法律服务” | 职业、行业、客户关系和实际用途互相冲突，偏离内部法务任务 | 逐项对齐公司主营行业、法务角色、公司业务关系、成果使用者和任务类型；模拟关系明确标注，正式资格另核 |
| prompt 日期、程序状态或对象名单与附件不符 | 题面直接给出错误事实，模型遵题面反而会被扣分 | 建立 prompt 事实与原件的双向核对；明确题面是当前指令、附件是证据，冲突须设计并有依据裁决 |
| 要求模型交多份文件，但出题文件夹没有完整标答，或引用不存在的标答附件 | 无法核对交付质量，也容易把评审材料误发作答模型 | 按用户目录约定将完整标答放在题目标准答案章节；只有明确提交要求时才另建附件，并核对文件确实存在 |
| 题面布置多个不相关法律问题，靠文件数量显得工作量大 | 不形成同一个真实决定，负荷增加却没有专业依赖 | 每项工作须影响同一决定或后续执行；删掉不影响决策的支线 |
| 强制程序时间轴、风险台账、三种情景、逐页摘要等固定产物 | 任务不需要时会变成形式负担，也可能把答案提示出来 | 只要求能支撑决策与交接的产物；不同题不继承固定数量和字段 |
| 把“至少要拒绝一项”或“要有可批可拒”写成出题规则 | 诱使模型或出题者硬造错误请求，形成套路化答案 | 只按当前业务事实决定放行、拒绝、附条件或待核；不为评分平衡制造虚假对立 |

## 四、rubric与标准答案

| 不好的做法 | 为什么会失败 | 应如何处理 |
| --- | --- | --- |
| rubric的事实前提与完整附件相反 | 有效考点不存在，低分不能说明模型失败 | 逐项用附件和prompt验证前提；冲突条目标无效，修订后重评分 |
| 标答、prompt、rubric对同一日期、金额或程序状态说法不同 | 无法判断模型应遵从哪一套，跨文件核对会惩罚正确作答 | 先独立求解；建立单一事实口径，再同步三处。若真实冲突保留，写清裁决依据和不确定边界 |
| 评分把“未写出”当成“写了相反事实” | 漏答与错误回答是不同错误，可能触发不同标准 | 只按正向条件判遗漏；只有产物确实作出相反断言且零分条件覆盖时，才按该条件判零 |
| 正向标准过宽，零分条件靠近义句或出题者意图判分 | 不同评分人会作不同判断，模型不能从文本预测边界 | 描述可定位的对象、范围、状态、数值、动作；说明合理等价表达及具体错误 |
| 将整份输出文件数、格式或文风作为主要难点 | 易完成事项抬高得分，核心专业判断未被测到 | 形式要求服务实际使用；核心考点查判断和结果，格式项从严限量 |
| 上游一个错在多条考点重复扣分，或为了凑20条拆同一结果 | 分数虚低、考点互相依赖，不能解释能力缺口 | 条目核对不同的独立产物结果；标明因果关系，合并纯重复条目 |
| 为压分临时加零分写法、要求标答原句或缩小等价解 | 破坏评分中立，修订版本不可与旧分比较 | 依据已观察作答判断原rubric是否漏测；合理等价解保持通过，修改后重新盲评 |
| 把任何异常都判风险，忽略附件支持的正常安排 | 鼓励“全案否决”式保守作答 | 核实异常对权利、责任或办理的实际影响；无不利影响则允许正确排除风险 |

## 五、评分与难度报告

- 没有同版完整作答、输入文件或rubric，不宣称已独立重评；仅报告实际看到的证据范围。
- 每条评分理由要有模型原句与rubric对应条件。二手评语不是作答原文；无法核对的结论标待复核。
- rubric事实前提与原附件冲突时，先暂停该条；若是关键条目，原总分不能作为有效的难度结论。修rubric后按同一作答重评，必要时再盲测。
- 记录区分有效条目数、无效/待复核条目数、原始得分与重评得分，不能把无效条目默认计零或直接从分母删除后不说明。
- 区分题目设计缺陷、评分口径缺陷、附件传输问题和模型作答问题。只有定位到对应原因，才提出相应返修。
- 题目角色或来源资格不符合当次范围时，分数只说明该材料组合下的作答表现，不能宣称验证了本 skill 的目标任务能力。
- 面向业务收件人的最终 Word 文书不得留有“我是AI”“作为语言模型”、提示词复述、生成流程、内部质检、自评分、模型局限套话或大段思维过程。不得以“去 AI 痕迹”为由删除有实质影响的法律依据、来源引注、事实边界、假设和风险披露。

## 六、出题交稿前的快速核对

1. 题设条件、卷内事实和真实采用证据各自标明，没有相互冒充；正式资格单独判断。
2. 退回意见指出的具体缺口已修补，原卷有效考点和专业判断得到保留。
3. 任务角色、行业、公司关系和最终使用者一致。
4. 实际附上的每个文件已读取；prompt摘要没有冒充附件全集。
5. 每个rubric事实前提均能在模型输入中定位，所有“材料不存在”已核验。
6. 题面、附件、作答思路、标答、rubric的日期、主体、金额和状态一致，或明确保留并裁决真实冲突。
7. 每个难点改变必经处理或决定，并有独立考点；没有强制清单、步骤和消息数凑量。
8. 用户题目目录只含约定类别；prompt所要文件与题目中的完整标答逐项对应。
9. 成稿中不含评审答案、考点提示或模型成绩；待测难度如实标未验证。
