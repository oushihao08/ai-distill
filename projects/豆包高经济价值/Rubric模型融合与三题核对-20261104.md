# Rubric 模型融合与三题核对

适用范围：维护豆包高经济价值出题 Skill，改进后续新题的复合评分可靠性。本文是分析与改动记录，不作为案件附件或新题事实输入，不追溯修改旧题成绩。

## 官方案例提供了什么

2026-11-04 通过登录浏览器读取[法律服务优秀案例](https://bytedance.larkoffice.com/wiki/XzRuwLQ1sitJDWkYTrccayA7nWe)的题面及完整考点区。页面有11个编号考点，另列严重错误、一票否决及常见错误；没有公开各条分值、部分分办法或总分公式。

| 可见考点 | 评价对象的简要归纳 |
| --- | --- |
| 1 | 材料全集、案件关联与计数 |
| 2 | 来源追溯及事实层级 |
| 3 | 案件字段和请求单位 |
| 4 | 金额计算及差异解释 |
| 5 | 法律关系与责任主体 |
| 6 | 双倍工资和工资证据口径 |
| 7 | 社保、补偿与赔偿 |
| 8 | 休假和加班报酬 |
| 9 | 工伤项目及制度证据 |
| 10 | 推定、程序及规则适用 |
| 11 | 案例应用、办案清单和成果对应 |

由此归纳的模型是：**可信的数据与依据→成立的专业处理→能用于后续工作的成果**。前面的身份、事实和金额支撑后面的判断，结论最终用于办案准备。每条可以包含多个共同决定结果的条件，任务步骤、文件数量与考点数量并不一一对应。

这只是从成品提取的方法，不是官方原始提示词或计分算法。案例也有合并较宽的条目，例如第7、9、10项覆盖多类事项；第3项使用准确率阈值，另有一票否决。因此不能将其每段原样改成“全部满足得1，否则0”：那会把未公开的计分方式擅自变成更严的全有全无规则。

## 本项目如何融合

先用上述维度检查工作是否覆盖，再以本案的独立专业结果决定考点。维度不是三个固定考点，也不要求所有案件建设台账或知识库。

1. 保留复合判断。构成同一结果的证据对应、规则条件、计算和成果落实仍须共同成立；不拆成查日期、报数值、列法条的简单分。
2. 条件要有实质后果。遗漏会改变权利、金额、程序、使用能力或使必要依据无法核验才进入通过条件；作者偏好的历史叙述、顺序和可替代引用不强制复述。
3. 划清内容与使用能力。专业结论、可更新核算工具、可办理文书有不同验收证据；同一文件未生成不自动否定所有已可核验的法律判断。真正需要可更新或可提交的成果仍须实际交付，不能靠文字预览通过。
4. 固定错误归属。保留纯上游误差不重复处罚规则，文件、检索及读回同样按业务用途归属；不同独立错误分别处理，严重错误也不改成全题否决。
5. 先校准再解释低分。完整正确内容只是内容参照，实际文件和检查证据进入评分端后才能检验完整任务是否可得满分；未执行的校准必须标明。

每条的内部对应为“任务依据→决定性记录→专业结果→验收证据→失败影响”。它用于作者检查，正文依本案组织，不强制把五个词写成栏目。各条仍 max_score=1、0/1等权；没有固定条数、部分分、权重或全题否决。修订分组会改变分母，不能把新旧总分直接用于证明难度升降。

## 三题逐项落点

本轮只读本机 API 的当前出题结果，未改写其冻结题面、rubric、答案或分数。以下是新版本应采用的边界，不是对旧答案临时换标准。

| 题目和旧条目 | 已确认的问题 | 新规则的处理 |
| --- | --- | --- |
| case77 第1项 | 一条同时含既判债权范围、诉讼费退付、迟延利息、LPR预算、XLSX生成及读回 | 区分债权及计息结果、费用结算结果、确有复用用途的核算成果；逐一保留其必要判断。费用办理有独立收款渠道和防重复要求，不因同在核账文件而并入全部债权判断 |
| case77 第7项 | 终本与救济、代理权限、整份DOCX生成读回共用一个通过条件 | 终本审查及路径保留为复合结果；审签申请的权限、请求和条件按可办理用途评价；共用读回按实际用途归属，不因缺文件反推终本分析错误 |
| case80 第3项 | 本息计算与实际XLSX、独立复核捆绑，工具缺口不能与规则算错区分 | 明确期间、公式、假设隔离属于核算判断；可更新成果的参数与公式联动另按用途验收或留在有明确业务必要性的同一结果，不机械拆出文件分 |
| case80 第12项 | 资格、渠道与调查改稿本身有共同用途，不能因条件多就一概拆散 | 保留复合关系；不同财产的证据范围仍由其原结果负责，不在此重复要求全部重判；改稿必须真正落实主体、证明目的和合法渠道 |
| case93 第2—4项 | 一般利息、迟延部分和300万元抵充分别有新判断，但重复把同一XLSX存在作为必要条件 | 保留这些独立判断及全部计算难点；可更新核算模型统一验收输入、分段、抵充、日增与改参联动。不能缺同一文件便将已有三个正确计算全部解释成专业误判 |
| case93 第9项 | 法院核账申请、受领/代理权限与DOCX/XLSX读回合列 | 法院申请和实际付款受领按真实用途确定边界；文件及读回不重复加入已评的计算或权限判断。原有授权、调查材料权限及收款核实不删除 |

## 以 case93 说明保留的强度

以下是边界示范，不是可直接替换旧9条的完整新 rubric；完整重出仍须核对全部附件和对应题面，不将本示例写入通用 Skill。

“300万元付款的分配与后续备款”继续要求：在题设费用另行处理前提下，先抵一般利息2441172.79元，再抵本金558827.21元；剩余本金346972.79元、一般利息0，加倍部分37568.06元；按旧题明确允许的另一日期口径可为37726.57元。费用以外余款384540.85元或384699.36元；付款次日起的计息本金相应下降，日增约178.60元；未付加倍部分不再复利，模拟不冒充实付，余款状态落实后续手续。上游数值误差按预定边界处理，本项新增的抵充、后续基数或结清条件错误仍判0。

“供财务更新的核算工具”只有在需要独立复用时设项：真实XLSX中的本金、期间、利率、付款额与各段利息、抵充、余款及日增建立可检查联动，区分实际账与模拟，限定适用期间；修改题面指定参数后结果随规则变化，不能只有静态值；DOCX用款安排与对应情景一致，读回证据覆盖关键公式、数值和引用。只有文件壳、未运行脚本或正确汇总数仍不通过。已归其他条的同一法律或算术错误不重复处罚，工具新增的引用错误、改参失效和场景错用独立判断。

这两项能分别失败：抵充判断正确但没有可更新成果；有可更新的表但采用错误抵充规则。其独立用途成立才分别计分，不能仅为增加条数而拆项。

## 静态对照及执行边界

| 对照情况 | 新规则要求的判断 |
| --- | --- |
| 完整正确内容、合法替代、实际成果及检查证据齐备 | 全部通过；独立评分尚待实际运行确认 |
| 内容正确，明确没做可更新成果 | 对应使用能力不通过，不能给文件分，也不能凭同一缺口重复否定已成立的内容结果 |
| 只有一个上游数值错误，下游按该值正确应用新规则 | 按冻结归属处理，不能以同一错误数值逐条判0；改变规则选择的独立错误另判 |
| 只漏不影响结果的背景描述或改用充分的等价证据 | 不应失分；若失分，应修正把背景当必要条件的判据 |
| 工具能力不满足或产物未传入评分端 | 报告具体运行/证据缺口，不能称为有效专业低分；模型自述无工具本身不足以证明环境状态 |

源码核查：`server/authoring/receive.ts` 将标答保存为文本字段；`server/scoring/context.ts` 从有效答案的 `model_answer_file` 读取受管产物，`server/scoring/executor.ts` 将其内容、结构核验范围及执行证据提供给评分模型，普通评分不读取项目 Skill。因此本次把关键边界写入作者编制 criterion 的要求，未假设评分器能自行读取 Skill；没有新增 schema 字段或改变程序状态。
