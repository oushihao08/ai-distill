## 1. 判断真正难度的标准

保留需要作答者依据可见材料作出证据取舍、法律定性、精确求解或办理决定，并影响具体成果的机制。只增加字数、文件数、付款次数、格式要求、计分条数或处罚力度的内容不作为独立难点。机制是否能难倒模型仍需实测，历史单题低分不证明因果。

原文明确列出12类主机制，下文另展开14项子机制。子机制与主机制存在包含和交叉关系，不能相加宣称有26个彼此独立难点，更不要求每题集齐。

| --- | --- | --- |
| 15–20条、0/1等权 | 否，豆包计分／组织规则 | **剔除。**Work采用其自身的正负档位、维度、锚点及否决要求。 |
| 七项纯文本题包、不要求生成文件 | 否，豆包交付及调用边界 | **替换。**按Work当前内部调用与正式文件阶段分别处理，不作为难度方法。 |
| 用明示模拟条件补足材料／新增报价、授权、履行事件 | 不是难点本身，是豆包材料构造许可 | **修改后保留机制，剔除许可迁移。**Work仅从其规则允许的真实材料与事实中寻找相应关系，不能模型造材料、事件或文书补数。内部AI模拟专家成果不等于允许模拟案件事实。 |
| 公司法务审批、交易、解押场景 | 示例语境 | **修改后保留。**按Work指定LS场景和职业权限重新设计，不能把所有题变成交易或执行任务。 |
| 案例比例、金额、付款次数、五份成果及历史分数 | 参数或历史证据 | **剔除固定值。**只迁移目的不同、门槛不同、变化范围不同的关系；不复制题目或提交数据。 |
| 个案中的清偿、保证、期间及效力结论 | 个案答案，不是通用规则 | **重新求解。**新题核对材料、法律版本和适用条件，不把卡片结论写成普遍提示词。 |
| 不照顾模型而删难点，充分展开独立工作 | 难度目标与创作原则，不是第27个机制 | **保留。**在Work真实性、场景、等级和可求解范围内最大化专业深度，不为合规而退回泛泛意见。 |
| 接受合法替代路径、不重复奖惩 | 公平性与有效测量边界 | **保留。**避免把正确回答判错；它不削弱专业难度。 |

## 7. 后续 Work Skill 的使用方式

以Work的出题规范、评分规范决定项目标准和字段；以本表提取的机制决定怎样从真实材料深化任务。作者提示词应按“当前场景／角色／等级 → 材料与法律研究 → 选适用机制并充分求解 → 题面与完整成果 → Work Rubric → 实际产物复核”组织。

不把本表全部原句拼接成新的长Skill。按当前材料选择适用机制，没有证据支持的不硬套；合规核对与难度设计分别落实，不能删困难判断解决格式问题。困难工作、正确答案及判据同步改写；已经生成的题目不会因文档生成自动更新。
