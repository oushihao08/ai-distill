# 高经济价值项目出题规则摘录

## 适用范围

本文基于 2026-11-02 读取的以下两份飞书文档整理：

1. [高经济价值【七期】任务说明文档](https://bytedance.larkoffice.com/wiki/MBUBwcfNUinZFJk8RqOc9ouQnch?renamingWikiNode=false)
2. [高经济价值任务：出题难度自测讲解文档](https://bytedance.larkoffice.com/docx/JiDJddtHHobs4dxIhHqcBzpjnfe)

这是项目出题与评分规则的依据；与共享 Skill 的方法或模板冲突时，以本文为准，并服从用户当前要求。期次、日期或平台要求变化时，以届时原文为准。外部实测门槛由评测环节核验；作者将其落实为真实工作复杂度、可核验成果和公平评分，不向作答者或评分者注入目标指标，也不承诺未经实测的成绩。

## 一、项目目标与题目边界

### 1. 项目目标

题目应来自专业人士真实工作中的高价值任务，用于测试 Agent 完成真实办公任务的能力上限。高经济价值不等于单纯“题很长”，而是任务通常具有以下特征：

- 专业人员在真实工作中需要投入较多时间；
- 需要阅读、核对和关联多份业务材料；
- 需要使用工具完成检索、清洗、计算、整理或生成交付物；
- 结果会直接用于决策、执行、正式交付、合规审查或持续运营。

### 2. 不适合纳入的任务

根据任务说明，以下方向不属于本项目支持的主要题型：

- 纯代码开发任务；
- 图片或视频生成任务；
- 选题策划、创意策划等以开放创意为主的任务；
- 与实际业务无关的纯计算；
- 只有简单文案撰写、改写或复制整理，缺少专业判断和真实业务用途的任务。

判断时应以最终业务用途和交付物为准，不能只靠增加材料数量或拉长题面把普通任务包装成高价值任务。

## 二、题目字段与分类

### 1. 任务名称

用一句简洁的话概括需要完成的真实工作，不把内部测试目的、难度要求或制作过程写进名称。

### 2. 任务类型

以最终用途和最终交付物为判断依据，只选择最主要的一类。不要因为任务中间包含检索、计算、写作等多个动作就并列多个主类型。

### 3. 任务形式

- 单轮：一次给出完整任务和材料即可完成。
- 多轮：后续轮次必须承接前一轮的真实业务结果，具有必要的上下文依赖；不能把一个完整任务机械拆成多轮来增加难度。

### 4. 行业分类

- 每道题只能归入一个 L1 行业，不能跨多个 L1；
- L2 从该 L1 下的细分行业中单选；
- 分类应按任务实际发生的行业和业务场景判断，而不是按附件来源或个别知识点判断。

## 三、题目组成与设计顺序

提交用于自测的完整题目至少应包括：

- 题面：真实角色、业务背景、明确任务和交付要求；
- 附件：完成任务所必需且可访问的材料；
- 参考答案：供专家校准，不提供给被测模型；
- 作答思路：说明正确处理路径和关键判断；
- 评分标准／考点：在看模型回答之前写好，并能够逐项判分。

推荐顺序是“先明确真实交付物和评分尺，再组织题面与附件，最后开启独立模型自测”。不能先看模型答错在哪里，再倒推只针对该回答的评分点。

## 四、难度硬门槛

难度自测文档给出的达标条件分为一项必选门槛和一组二选一门槛：

| 指标 | 门槛 | 判断口径 |
| --- | --- | --- |
| SOTA 模型得分率 | **不高于 50 分** | 专家按预先写好的评分标准逐项判分；若模型答错但评分点没有覆盖，会产生虚高分 |
| 执行轮数 | **至少 50 步** | 任务真实需要读材料、清洗、关联、计算、重算、生成交付物和自查等连续执行 |
| 运行时间 | **超过 40 分钟** | 可代替“至少 50 步”这一项，但时间必须来自真实工作量，而不是人为等待 |

因此完整公式是：

> SOTA 得分率 ≤ 50 分，且（执行轮数 ≥ 50 步，或实际运行时间 > 40 分钟）。

### “50 步”的证据边界

原文使用的是“执行轮数／执行步数”，强调模型为完成任务而实际进行的材料读取、工具操作、数据处理、核算、生成和自查等执行过程。原文没有给出按字数、思考时长或回答段落数换算步数的公式。因此：

- 不能把模型输出的 50 个段落直接当作 50 步；
- 不能把预先规定“必须做 50 步”当作难度证据；
- 应保存模型实际执行记录，按可识别的真实执行动作核验；
- 一个动作是否拆成多个技术事件，不能仅凭日志条数机械放大，最终以该轮自测平台展示和项目验收口径为准。

## 五、难度应来自真实任务结构

### 1. 把难点放进必须处理的明细

有效难度应来自任务本身，例如：

- 多份材料之间存在主体、时间、金额或规则关联；
- 原始数据需要清洗、去重、分类或重构；
- 需要逐项判断大量明细，而不是只总结全文；
- 计算存在前后依赖，需要复核或重算；
- 同一事实需要在不同交付物中保持一致；
- 最终结果必须经过完整性、准确性和格式自查。

### 2. 不得用伪难度凑门槛

不得依赖以下方式制造低分、长耗时或高步数：

- 强制模型输出固定数量的步骤；
- 塞入与任务无关的附件或重复材料；
- 提供无法访问、缺失或损坏的关键资源；
- 故意写含糊、互相冲突或无法完成的要求；
- 通过等待、重复抄写或无业务意义的机械操作拉长时间；
- 把参考答案、评分标准或目标门槛泄露给被测模型。

## 六、评分标准设计

评分点应当是可观察、可核验、可扣分的“尺”，而不是宽泛评价。建议做到：

- 每个关键业务判断都有对应评分点；
- 对事实提取、关系核对、计算结果、风险识别和交付完整性分别设点；
- 写清满足条件、分值和关键错误的扣分后果；
- 评分标准能够区分“提到”“判断正确”“计算正确”和“可直接使用”；
- 评分总分与各项分值一致，避免遗漏或重复计分；
- 先完成评分标准，再让模型作答，避免结果导向地修改评分尺。

如果模型明显答错但得分仍超过 50，首先检查评分标准是否漏掉了真正的专业考点，而不是直接认为题目太简单。

## 七、标准自测流程

1. **准备完整题目**：确认题面、附件、参考答案、作答思路和评分标准齐全，评分标准已在模型作答前冻结。
2. **确认测试模型与条件**：使用项目要求的 SOTA 模型和统一测试条件，记录模型、会话和材料版本。
3. **开启新会话独立作答**：只向被测模型提供题面和允许的附件，不提供参考答案、评分标准、作答思路、目标分数、目标步数或目标时间。
4. **保存原始结果**：保留未经人工润色的完整回答、生成的交付物、工具执行记录、实际执行轮数和运行时间。
5. **专家独立判分**：严格按预先写好的评分标准逐项给分，并记录扣分依据。
6. **核验步数或时间**：确认达到“至少 50 步”或“超过 40 分钟”，并排除固定步数、无关操作和人为等待。
7. **决定保留或修改**：同时达到得分门槛和步数／时间门槛才保留；否则定位是任务结构、材料、交付要求还是评分尺的问题。
8. **有针对性修改并复测**：只修改已识别的薄弱环节；最终版本必须重新开启新会话，从头独立测试，不能沿用旧会话结果。

## 八、提交前检查清单

- [ ] 任务来自真实专业工作，并有明确业务用途。
- [ ] 最终交付物清楚，可判断是否能直接用于后续业务。
- [ ] 任务不属于纯代码、图片／视频生成、开放创意策划或无业务背景的纯计算。
- [ ] 题面角色、背景、任务、输入和输出要求完整且不互相冲突。
- [ ] 所有关键附件完整、可打开、与任务有关，且没有把答案直接写在无关提示中。
- [ ] 多轮任务具有真实承接关系，不是机械拆轮。
- [ ] 参考答案、作答思路和评分标准齐全，但没有提供给被测模型。
- [ ] 评分标准在模型作答前完成，专业考点可逐项判定和计分。
- [ ] 使用新会话完成了最终版本自测，并保存原始回答和实际执行记录。
- [ ] SOTA 模型按评分标准计算后的得分不高于 50 分。
- [ ] 实际执行达到至少 50 步，或实际运行时间超过 40 分钟；证据来自真实任务过程。
- [ ] 难度不是靠固定步数、无关材料、不可访问资源、模糊要求或人为等待制造。

## 十、最简判定卡

一道题提交前，至少能对以下四个问题回答“是”：

1. 这是不是一个真实、专业且结果会被使用的业务任务？
2. 模型是否必须对材料做多步处理和专业判断，才能形成可用交付物？
3. 预先定义的评分标准是否能把关键错误真实扣出来，并使 SOTA 得分不高于 50？
4. 原始执行证据是否证明模型实际完成至少 50 步，或真实运行超过 40 分钟？

任一答案为“否”，都应先定位并修正题目、材料或评分尺，再用新会话复测，而不是直接提交。
