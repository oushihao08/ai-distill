# 历史评分口径整理稿（非官方原文）

本文件是本地历史整理稿，不是官方原文；适用性须回查当前官方材料。可核对的历史来源副本包括 `高经济价值五期任务说明文档.md` 和 `C端任务全流程操作指南.md`。会议、录播和群聊记录已移入 `../updates/inbox/`，仅作非正式参考，不作为本文件所列官方要求的依据。

不用：`图片提取-*`、`个人经验-用GPT代写并三家模型压分.md`（45 分、专家权重）、培训稿附录里的 4 分制、权重、一票否决（五期明确不参考）。

## 1. 官方在评什么

两套数，分开看。

**难度（题目合格线）**

- SOTA 得分率必须不高于 50（说明写 <=50，群通知写 ≤50，录播写低于 50，按不高于 50）。
- 执行轮数不少于 50 步，或运行时间超过 40 分钟，满足一项即可。

**判分（产物对不对）**

- 只按考点判。模型作答只看 prompt 和附件。作答思路、标答、考点都不进模型输入。
- 专家写的考点给字节，字节用 prompt + 附件 + 专家考点生成机标，机标按 0-1 打。专家自设权重、倒扣、一票否决、自标分值，流程里不参考。
- 半开放题：产物可以和标答不同；考点不要把标答那一种写法写成唯一解。收敛题：关键结论要能对上标答。
- 质检可能调优考点。不要过度拟合自己的标答。

自测：先让模型只拿 prompt 和附件做完；再把产物和考点交给另一个模型打，不要让做题模型自己报分。

## 2. 考点说明

历史 C 端指南要求提供关键评分点、通过标准和易错点；有唯一答案的写明正确答案。已查看到的官方正文副本未给出固定考点条数。其他条数建议或写法如果来自会议、录播，应先视为讨论意见；本地skill中的条数偏好属于本地设计约定，不得标为外部官方硬门槛。

突破指南：

以下内容用于设计和检查考点覆盖度，不表示具体受测模型应得高分或低分，也不能代替逐条评分证据。

- 一条只查一件事。并列结果分开写。
- 每个难点至少一条，重心在难点上。
- 对常犯的错写不得分条件。
- 上游错会连带下游时，每条仍查不同的东西，标答写清连带，避免重复扣分。
- 能唯一确定的写死；半开放的写必须写到哪些点、不能出现哪些错。
- 写粗了（「考虑了口径差异」）模型提一句就得分；要写成可核对的结果和不得分写法。
- 设计时检查格式、结构、常规计算、常识等基础项的占比。不要预设模型一定能拿到这些分；用盲测作答和逐项证据核验实际通过情况，再判断它们是否抬高总分。
- 题面点破难点，考点作废。

培训稿的「维度 × 优秀/良好/合格、权重、一票否决」是教学用，五期不用。

## 3. 官方评分规则（可执行）

1. 条目：15–20 条，优先约 20。
2. 计分：每条 0 或 1，等权。总分 = 得 1 的条数 / 总条数。得分率按百分理解（官方说不高于 50 分）。
3. 一条一事。正向通过标准 + 何种写法本条得 0。
4. 不设权重、倒扣、一票否决。
5. 格式、结构、常识合计远小于一半。
6. 难点每条都要能扣到：材料里有错点，考点去查那个错点。
7. 判分看产物是否命中该条正向、是否踩该条零分条件。不看文采，不拿标答当唯一答案（半开放时）。
8. 最终官方分以机标为准。专家自测只是估难度。

## 4. 单题审查与评分的中立流程

以下是将上述规则用于单题时的操作建议，不是新增官方门槛。

1. **先审 rubric，不看模型分数。** 检查条目数、0-1 等权、一条一事、正向标准和零分条件；标出重复考察、含糊词、复合要求及半开放题的替代表达。
2. **盲评作答。** 评分者先只看 prompt、附件、rubric 和待评作答；不提供标答、预期分数、模型名称、其他模型分数或“必须压到某分”的目标。
3. **逐条留证。** 每条记录作答中的支持原文、反证原文或“未找到”。仅按该条标准判 0/1：满足正向标准且未触发零分条件计 1，否则计 0；不得因总体印象、文风或预期难度调整单项分数。
4. **区分漏答与错误。** rubric 若要求明确写出某事实，未写按该条正向标准判 0；若条目只规定禁止某种错误，则未触发该错误不应被改判为触发。存在歧义时记录争议，先澄清 rubric，再汇总，不临时改变尺度。
5. **复核后报告分数性质。** 专家或第三方人工分只作自测参考；官方分数以项目机标为准。题目是否达到难度线，按规定的测评流程和官方结果判断，不由 rubric 作者预估或保证。

## 5. 结论边界

本文件概述官方评分与题目难度要求。它不预判任何具体模型或单题的得分，也不据此推断某题一定高分、低分或通过难度线。具体判断应基于题目当前版本、盲测作答、逐条评分证据及官方机标结果；如引用历史自测，应同时注明模型、题目版本、评分者和评分方式。
