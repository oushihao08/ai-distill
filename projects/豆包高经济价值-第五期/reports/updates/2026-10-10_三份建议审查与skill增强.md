# 三份模型建议审查与 skill 增强

核查日期：2026-10-10（Asia/Shanghai）。

本轮按用户要求阅读三份建议，筛选后修改第五期 `skill/`。建议是模型输出，不能直接当成法律依据、模型能力实验或平台规则。本文记录取舍，不进入出题 Agent 的 skill 输入。

## 结论与实际依据

当前 skill 已有连续事件、临界条件、竞争证据、具体文书和跨成果核对。三份建议重复这些机制的部分很多；继续增加口号、附件数量和成果份数，不构成新的能力要求。

本轮有价值的增量是：把适用规则与具体对象、时点绑定；先定给付性质再计算；同时检验应放行与应阻断事项；用会改变法律处理的事件检验原方案是否正确更新；让考点检出这些独立结果。

已核对 [作答输入契约](../../../../server/answer-models/input.ts) 和 [作答模块说明](../../../../server/answer-models/README.md)：当前要求文字输入、文字输出、无工具，只向作答者发送题面与允许的脱敏附件正文。作者可读取原件或检索，不代表作答者能看到批注、隐藏单元格或执行网页搜索。因此，文件载体及新规建议必须先转为实际可见的文本输入。

“会显著压分”“第三轮必定算错”“自然低于50分”在三份建议中没有对应实测。本文不据此承诺降分，也不采用关于注意力结构、RLHF 与法律错误之间的确定性推断。

## 建议1的取舍

来源：[建议 1.md](../../建议%201.md)。

| 内容 | 处理 | 理由与落点 |
| --- | --- | --- |
| 合同名称诱发模板化判断 | 采纳机制 | 按实际条款、主体和适用条件定性；建议内的具体法律示例未逐案核实，不直接转成标准答案。写入设计方法。 |
| 新旧法、版本和条号 | 调整后采纳 | 核验施行时间、过渡规则和对象范围；专门规则给作答者可见依据。主要考适用结果，不把条号记忆另拆大量得分项。 |
| 日期链、抵充与分段计算 | 调整后采纳 | 补充作者工具复核、起止日、精度与舍入口径；已有生效证明不能为拉长推算而弃用。 |
| 不显眼的决定性事实 | 采纳机制 | 保留来源、上下文与自然位置；未传入正文的字段不能当陷阱。 |
| DOCX批注、XLSX隐藏项、PDF版式 | 不直接采用 | 当前作答只有文本。相关差异实际进入文字输入后才可考；本轮不扩展作答工具或文件能力。 |
| 顺从高层业务提案 | 调整后采纳 | 职位高不证明模型会顺从。使用实质利益与法律条件的冲突，同时保留可以办理的事项，避免全拒捷径。 |
| 变化后仍沿用原结论 | 采纳 | 按事件后的权限、余额和状态重新决定；检查受影响与不受影响的部分，不只换金额。 |
| 编造出处、绑定具体条文 | 调整后采纳 | 必要依据要核对；支持等价法律论证，不将无关条号格式当作整体判断错误。 |
| 冷僻或近期规则迫使检索 | 不作为当前作答要求 | 作者负责核实；解题必需的专门规则应进入可见题面。不能用作答端没有联网能力制造失分。 |
| 恢复“一个拍板”及共同底账 | 部分采纳 | 增加真实业务关联，保留多个决定和并列工作；不把所有对象强塞进同一底账或一条依赖链。 |
| 新增弱点文档、更多行业案例 | 本轮不增加 | 现有设计方法和案例已覆盖多数机制，独立再写一份会重复。具体选题由实际材料决定，不因新题材名称就宣称更难。 |
| “可能、待核”一律零分 | 不采用一律规则 | 已知事项回避结论可失分；确实存在缺口时，正确的条件分析可以得分。 |

## 建议2的取舍

来源：[建议 2.md](../../建议%202.md)。

| 内容 | 处理 | 理由与落点 |
| --- | --- | --- |
| 最新或醒目文档未必有效 | 强化已有机制 | 具体核查出具权限、效力条件、对象及撤销范围，避免机械“主文/正式/最新永远优先”。 |
| 定性→基数→核算→办理 | 采纳适用依赖 | 在确有法律依赖的部分建立关系，不规定全部工作必须串成一条链。 |
| 多份成果核对 | 保留并具体化 | 更新所有受影响结果；不同成果可以有不同对象范围，不能为了表面一致消除合法差异。 |
| 正常但看似异常、异常但看似正常 | 采纳 | 同时要求正确放行与阻断，结果按依据产生，不预设两类各几项。 |
| 连续变化与对抗性提案 | 合并到既有方法 | 增加“替换关键条件，哪些结果应变/不变”的作者检查；不重复创建流程。 |
| 期间只给原始日期，不给现成日期 | 部分采用 | 模拟题可以保留待推算工作；真实附件已有有权认定时不能隐去，以现有材料和适用规则裁决。 |
| 冲突可裁决、接受等价表达 | 采纳并明确分支 | 该建议要求有裁决依据；有充分依据且法律上存在多个解时，评分接受对应分支，不扩张成所有问题只有唯一解。 |

## 建议3的取舍

来源：[建议 3.md](../../建议%203.md)。

| 内容 | 处理 | 理由与落点 |
| --- | --- | --- |
| “局部注意力”“天生讨好”推导必然错误 | 不采用 | 未提供所测模型、推理设置及对照记录。作为错误假设探索可以，不能写成已证实的底层规律。 |
| “第三轮迭代必定漂移”“自然低于50分” | 拒绝保证 | 计算次数不证明会错。保留多事件定性和求解，效果须同版实测。 |
| 诱人的商业提案 | 采纳可用部分 | 已融入设计方法；真实法律条件决定处理，不靠夸张措辞或高层口吻制造所谓难度。 |
| 固定5–10份矛盾附件、绝不给干净表格 | 不采用 | 不能为凑量制造无关冲突或破坏可读性。保留真实明细、汇总和修订关系，考它们的效力与一致性。 |
| 连续履行与例外交叉 | 合并采纳 | 每个事件有独立性质，新增判断对应独立考点；同一错误的机械传递不重复扣分。 |
| 禁止任何原则性分析 | 拒绝 | 法律依据与理由是必要工作。禁止用原则代替结果，不禁止解释结果为什么成立。 |
| 强制唯一日期、金额和不可替代措辞 | 调整后采纳 | 可唯一求解的给明确结果；有合理分支、精度约定或等价条款时不能只认一套措辞。 |
| 低于50分即“无法通过” | 不沿用其表述 | 本项目以作答模型低于配置阈值作为题目难度达标。实际阈值由项目设置决定，不写入评分倾向。 |
