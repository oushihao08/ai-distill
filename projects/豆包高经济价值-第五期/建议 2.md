**已阅读并理解全部出题 skill 与配套材料。** 以下从「AI 实际运作原理 + 法律专业难点」交叉视角，分析现有加压机制的空间，并给出可继续加压的方向。目标是让模型更难一次性给出准确、自洽、可核对的答案，同时保持题目可判、材料自洽、不靠制造事实错误或事后改尺度来压分。

### 1. AI 在此类任务上的典型薄弱点（结合现有材料与寅鼎类案例）

- **多跳精确链容易断**：生效路径（宣判 → 公告 → 视为送达 → 上诉期 → 生效 → 履行期 → 申请执行期间）模型常简化为“2018年5月作出”，或写成“若已过再核实”。中间任一环错，后续利息、时效、能否立即申请执行全错。
- **文档优先级与权限判断易被“最新/最醒目”带偏**：模型偏好最新汇总表、业务提案、或文件名看起来像“正式”的版本，而忽略权限、生效条件、撤销记录、或更早但有效的裁判主文。
- **计算依赖前置法律定性**：抵充顺序、共同债务认定、一人公司责任、费用是否并入对价等，模型常先按业务方案算数，再找理由，而不是先定性质再定基数。
- **跨成果一致性差**：签批意见、底账、执行指令、替换条款之间数字/主体/条件容易漂移；模型写完一份后，后续文件容易“记忆漂移”或局部幻觉。
- **局部未知处理差**：模型要么全案待核（把卷内已能确定的事项也放进去），要么补造数值，很难做到“已确定部分必须给结论、真正缺失的单列并写明补齐前哪一步不能做”。
- **对抗论证弱**：面对有依据的反驳（例如“已有2024年回证所以时效中断”“业务方案省钱所以应批准”），模型容易笼统否定或顺着业务方写，而不是逐项拆解依据。
- **幻觉高发区**：具体期间推算日期、合议庭署名差异、授权撤回日期、主文未列入事项、费用性质区分。即使金额用星号，主体、程序、口径仍易错。

这些弱点与《出题设计方法》《案例模板集》已列机制高度重合，说明现有框架方向正确，但仍有继续加压空间。

### 2. 现有机制可继续加压的空间

| 现有机制 | 进一步加压方向（针对 AI 弱点） | 预期效果 |
|---------|-------------------------------|---------|
| 多案卷/多对象整理 | 增加“同一主体跨案不同地位 + 同一款项在不同文书口径不同 + 并案关系需从多份文书交叉确认” | 模型易漏并案或错把主张当确认事实 |
| 截止时点与多版本 | 设置“最新版待批且晚于审阅时点、早期正式文件仍有效、豁免已撤销但汇总表未更新”的多层冲突 | 模型易选最新或醒目版本 |
| 多版本整改/放行 | 区分“规则已改但历史数据未补、一条线完成另一条线未同步、已执行补丁不会重跑” | 模型易把“看到修复”当成“已完成” |
| 正式规则 vs 临时豁免 | 权限、对象范围、期间、撤销时间全部可判定，但汇总表用旧快照 | 模型易被汇总表带偏 |
| 显眼指标 vs 真正瓶颈 | 把质量/报价/综合分写得很完整，当前真正约束藏在有效变更记录 + 实际履约能力中 | 模型易选总分最高方案 |
| 同一对象命中多项规则 | 增加真实存在的交叉例外（不是全局排序），要求逐对象写具体措施 | 模型易套固定模板 |
| 局部未知持续到交付 | 强制“已可判断部分必须给结论并落地到成果，真正缺失的单列，补齐前明确哪一步不能做”；禁止全案待核或补造 | 模型易全案待核或幻觉数值 |
| 债权/履行/期间/执行联动 | 强化“先定抵充顺序与义务人范围 → 再分段余额 → 再计息 → 再判断执行路径”；期间按公告原文推算，不直接给推算结果 | 模型易跳过中间环节或把履行期/执行期搞混 |

### 3. 可叠加的更高强度加压手法（推荐优先考虑）

1. **强制“先定性再核算”的依赖链**  
   把法律定性（是否夫妻共同债务、是否进入主文、费用是否并入对价、授权是否有效）设为后续所有金额、主体、动作的硬前置条件。错定性则底账、指令、条款全部对不上。模型若按业务方案先算，后续成果必然不一致。

2. **跨成果硬对数要求写进题面（但不点破具体坑）**  
   明确要求签批意见、分项底账、执行/付款指令、替换条款、变化后修订稿之间，主体、口径、期间、条件必须完全一致；并要求模型自行做一次跨文件对数检查。模型在长文本中容易局部漂移。

3. **对抗性提案 + 有依据的反驳**  
   业务提案看起来能省钱/加快结案，但遗漏一个关键条件（授权范围、抵充顺序、执行衔接、期间届满）。同时材料中保留相对方最有力反驳的依据。要求逐项回应，并写出可落地的替代条款。模型易顺着提案写或笼统否定。

4. **连续变化情景（依赖前次结果）**  
   先处理第一笔履行/程序事件，更新余额、权限、时点后，再处理第二个报价或处置选择。后续结论必须基于前次正确结果，而不是独立重算。模型易把变化当成简单数字替换。

5. **“看似异常但实际正常” + “看似正常但实际有坑”双陷阱**  
   放一两处按规定本来就不填/按通用条款执行的正常安排（防止全案否决），同时放几处需要精确程序判断的坑。模型要么过度保守，要么漏掉真正坑。

6. **要求写出具体可执行文本（而非原则）**  
   签批意见、替换条款、执行申请要点、通知正文等必须完整呈现，且与分析、核算完全匹配。模型在生成长文本时更容易出现内部不一致或幻觉细节。

7. **期间推算必须按原文路径，不给现成日期**  
   只给公告刊登日、履行期起算规则等，要求模型自行推算上诉期满、生效日、履行期届满、申请执行期间是否届满。这是寅鼎案例中模型高频失分点。

### 4. 设计时需守住的边界（避免题目不可判或标准出错）

- 所有冲突必须有可裁决依据（权限、时间、法律规则、主文优先于请求等），不能靠材料缺失制造难度。
- 局部未知只留真正卷内无法闭环的事项；已能确定的不得放进待核实。
- 考点检查不同专业结果，不重复扣同一判断；接受实质等价表达。
- 题面只布置工作和条件，不点破坑、不提示采信方向、不预告正确结论。
- 模拟条件明确标示，不冒充卷宗事实；脱敏保持原样。

### 总结建议

现有 skill 与案例模板集的方向已经对准 AI 的核心弱点（多跳链、文档优先级、前置定性、跨成果一致性、局部未知处理）。继续加压的最高性价比方向是：

- 把“先定性再核算”做成硬依赖链；
- 增加跨成果硬对数 + 具体文本要求；
- 叠加连续变化情景与对抗性提案；
- 保留精确期间推算与“正常但看似异常”的双陷阱。

这些做法能在不破坏可判性的前提下，显著提高模型出错或产生局部幻觉的概率，同时让考点能直接检出这些错误。
