# 材料包与多题工作流改造：实施清单

状态：**本地代码、文档与针对性测试已完成；运行环境切换待另行授权**。035 迁移文件及新模式代码已写入工作区；尚未对真实数据库执行迁移、切换项目模式、清理旧题或做真实模型／归档验收。开工先读根 `AGENTS.md`、`docs/architecture.md` 及涉及模块 README；以实施时的源码、迁移登记和用户要求校正文件定位。

目标：显式启用新模式的项目把一个来源目录登记为**材料包**，完成一次入库和脱敏后，从某次成功脱敏结果创建多道独立题目。每题冻结自己的整包脱敏快照和可选设计输入，再沿用出题、作答、评分、达标、归档流程。未启用项目仍是一目录一题。

## 要解决的问题与设计决定

| 问题 | 决定 |
| --- | --- |
| 一个目录现在自动对应一道题 | 对启用新模式的项目，目录只登记**材料包**；题目由用户在材料包下创建。其他项目保留原目录行为。 |
| 一套材料要出多题 | 材料包完成一次入库、脱敏；每道题创建独立工作流，固定当时**整包脱敏结果**的题目私有快照，不重新调用提取或脱敏。 |
| 材料补充或重新脱敏 | 新成功结果供**后来创建**的题使用；已创建题继续使用自己的快照。运行中或失败的结果不可选。 |
| 题目删除 | 只删除／隐藏该题及其任务状态；材料包与其他题不变。材料包仍被题目引用时，不物理删除其管理文件。 |
| 场景、角色、等级 | 题目创建时可选填场景、角色视角、目标等级及已有出题方向；传给出题 Agent。它们是设计输入，不能代替正式认领或等级验收。 |

**首版使用整包材料。**当前脱敏产物是合并的 `redacted_markdown`，没有可靠的逐文件脱敏正文可供勾选，因此不在首版承诺“每题选部分文件”。[现有产物读取](/Users/jack/Documents/codes/lvgou/ai-distill/server/authoring/jobs.ts:101)

## 验收标准与边界

- 一次成功脱敏可创建两道题；创建第二题不再次调用脱敏。
- 新脱敏成功后，旧题所用快照和题目结果不变；新题取得新快照。新脱敏失败不影响上一成功版本。
- 删除一道题不影响材料包和另一道题；同步目录不会把被删题重新创建出来。
- 非新模式项目原有目录同步与单题流程不变。
- 项目模型集合、模型参数、答案生成策略、评分配置在改造前后逐项一致；作答与评分业务逻辑不改。
- 材料包不能派发出题、作答、评分或归档；派生题不能派发入库、提取、脱敏。所有入口一致拒绝，步骤历史 `ordinal` 不变。
- 场景、角色、目标等级和方向分别保存在题目，影响出题时纳入该尝试冻结输入；变更后不得复用旧出题结果。
- 归档与导出只读取题目自己的冻结快照，且能通过现有同工作流及版本校验；未做真实归档调用时标明此项仅为单元测试／静态核对。
- CLI 帮助、Skill 操作指引、AGENTS、架构文档和源码注释对材料包／题目身份、步骤边界及版本来源使用同一术语；历史文档明确标记历史，不再充当当前操作说明。
- 本次**不验收**逐文件选材、平台五件套／Harbor 六件套自动生成、Work 等级自动判定。这些不应被“材料包多题”改造误称为已完成。

## 修改与执行边界

- 不改答案模型集合、模型参数、模型选择、答案生成策略、评分配置或评分算法；不为制造达标调整评分。不改 Work 规则原文、案件来源、Work 出题 skill 和历史冻结产物。`ai-distill/skill` 是工作流操作指引，本目标要求随新能力修改。
- 不把材料包计入题量或导出；题目继承快照要标明真实来源，不能伪称题目自己跑过脱敏。删除／重同步不得破坏仍被题目引用的受管理文件。
- 不扩大到逐文件选材、通用自动推进、出题／评分引擎重写或额外插件层。保留已有工作区改动，不顺手清理无关代码。
- 用户当前目标要求测试，因此可运行针对性后端单元测试；但计划与测试本身不授权全量迁移、未知范围的数据删除、服务重启、远程数据库写入、真实模型调用或发布。执行前核对目标环境和影响，分别报告是否已做。
